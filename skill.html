什么是 Skill

一个装着指令、脚本和参考资料的文件夹。AI 遇到相关任务时自己翻出来用， 用完放回架上，不占地方。

可以理解为：给新同事写的入职手册

手册开头是目录，让你知道哪份文档管什么事；真动手做某项工作时才翻到对应章节； 只有碰到具体细节才去翻最后的附录。Skill 走的是同一条路子，Anthropic 管它叫 渐进式披露（Progressive Disclosure）。

三层按需加载

progressive disclosure
  1. 01

    元数据

    始终加载

    SKILL.md 顶部的 YAML 头，只有 name 和 description。启动时就常驻，让 AI 知道有这个东西、什么时候该用它。

    约 100 tokens / 个
  2. 02

    核心指令

    任务相关时才读

    SKILL.md 的正文：工作流程、最佳实践、注意事项。AI 判断这个 Skill 和当前任务对得上，才把它读进上下文。

    一般 5k tokens 以内
  3. 03

    脚本与资源

    需要时再取

    捆绑的 scripts/、references/、assets/。脚本由 AI 直接执行，代码本身不进上下文，只有运行结果回来。所以随附多少资料都不吃上下文。

    几乎不计成本

一个 Skill 里有什么

anatomy 
my-skill/
├── SKILL.md       必需  YAML 头 + 正文指令
├── scripts/       可选  可执行脚本（Python / Bash）
├── references/    可选  按需查阅的文档
└── assets/        可选  模板、字体、图标

只有 SKILL.md 是必需的。name 限 64 字符，只能小写字母、数字和连字符； description 限 1024 字符，得同时说清做什么、什么时候用，因为 AI 靠这句话决定要不要触发。

和 Prompt、MCP 有什么不一样

comparison
方式解决什么生命周期
Prompt 一次对话里的一次性指令 用完即弃，下次重说
Skill 一类任务的流程与经验 写一次，之后自动复用
MCP 连接外部服务的能力 常驻连接，提供工具

Anthropic 自己打的比方：MCP 是厨房，提供工具、食材和设备；Skill 是菜谱，写清楚先做什么后做什么。 前者决定能做什么，后者决定该怎么做。

三个特点

traits
可组合

多个 Skill 能同时加载、互相配合，不用假定自己是被单独使用的那个。

可移植

同一份文件夹，在 Claude 网页版、Claude Code 和 API 里都能用。2025 年底 Anthropic 已把它作为开放标准发布。

省上下文

没被触发的 Skill 只占一个名字和一句话描述，装上几十个也不心疼。

装之前先看一眼

Skill 里可能带可执行代码，等于给 AI 开了新的操作权限。只用你信得过的来源；别人的 Skill 用之前翻一遍里面的脚本，留意有没有奇怪的网络请求或文件操作。
