## 自动升级判定（根据用户描述自动触发，无需用户要求）

收到用户描述后，先做快速预检，命中任一条件即自动升级为头脑风暴分析流程：

| 预检项 | 自动升级条件 | 原因 |
|---|---|---|
| 信息完整度 | 五要素（谁/事/钱/链/急）≥3 项缺失或模糊 | 信息不足直接定级易误判 |
| 谓词冲突度 | 命中红/黄谓词≥3 条且线索相互矛盾 | 单一骗局类型无法解释，需多方案对比 |
| 知识库覆盖 | 无法匹配 scam-knowledge.md 36 类中任何一类 | 可能为新骗局，需深挖沉淀 |
| 套路复杂度 | 描述含≥3 个环节/角色（如加群→下载App→充值→提现失败） | 复合型骗局需逐环节拆解 |
| 用户诉求 | 用户要分析/深挖/评估风险/怎么办，而非简单"是不是骗局" | 分析性诉求需要方案级输出 |

未命中任何条件 → 直接走判定五步快速定级。

## 触发条件（显式触发）

1. 用户提出设计类需求：反诈培训方案、定制话术体系、防护策略、新骗局应对预案
2. 内容疑点多、线索冲突，快速判定五步可能误伤
3. 骗局类型知识库未收录，需要结构化深挖（沉淀后可入库）

**红色优先例外**：若已确认命中红色谓词，必须先出强提醒卡，不得以"先走分析流程"为由延迟或弱化提醒。本流程服务于分析深度，不豁免强提醒卡。

## 反模式："这个太简单了，不需要分析"

所有复杂案例和设计需求都要走流程。"一看就是骗局，直接说结论"恰恰是漏掉关键证据链的地方；"用户只是问问"本身就是风险暴露。分析可以简短，但必须展示并获得确认。

## 流程步骤

### 1. 探索上下文

先搞清楚基础信息，再提问：

- 用户画像：通用 / 老年人 / 学生 / 财务人员 / 新入职员工（决定话术深度，对照 response-scripts.md）
- 内容来源：短信 / 电话 / 聊天记录 / 邮件 / 链接 / App
- 当前状态：是否已转账 / 是否已泄露信息 / 是否已安装 App（决定紧急程度）

### 2. 逐项澄清（每次一个问题）

围绕三个维度，每次只问一个问题（最多 3 轮，仍不足则按现有信息定级并标 [待核实]），优先选择题：

- 目的：用户想要什么结果？（定级 / 科普 / 设计方案 / 应对预案）
- 约束：时间限制？渠道限制？人群范围？
- 成功标准：怎样算分析到位？（一句话结论 / 可执行清单 / 可培训的完整方案）

### 3. 提出 2-3 种方案（附权衡与推荐）

- 先展示推荐方案并解释原因
- 每种方案给出权衡（分析深度 / 输出成本 / 可操作性）
- 遵循 YAGNI：删掉用户不需要的部分

例：用户问"公司财务总收到冒充老板的邮件怎么办"

| 方案 | 内容 | 权衡 |
|---|---|---|
| A | 只做单封邮件判定 | 快，但治标 |
| B（推荐） | 判定 + 财务人员专属应对清单 | 兼顾效率与防护 |
| C | 判定 + 应对清单 + 邮件特征培训演练 | 最全，成本高 |

### 4. 分节展示分析结果（逐节确认）

按复杂度分节展示，每节询问是否正确：

- 骗局画像：类型、典型套路、命中谓词
- 风险定级：红 / 黄 / 绿 + 证据链（对照 risk-levels.md）
- 应对方案：按人群适配的行动建议（对照 response-scripts.md）
- 沉淀：若知识库未收录，输出结构化条目草稿

### 5. 用户批准后才收尾

- 用户确认后，输出最终行动建议 / 教育材料 / 演练脚本
- **沉淀入库 SOP**（仅当"未收录骗局经结构化深挖"且用户明确批准时执行，禁止擅自入库）：
  1. **确认门槛**：该骗局确为知识库 36 类之外，且有足够证据（用户原始素材 + 命中谓词 + 套路还原）
  2. **用户批准**：显式获得用户"同意入库"确认，不默认
  3. **格式追加**：按 scam-knowledge.md 条目 8 字段格式（典型话术 / 判定特征挂 R/Y 谓词 / 高发人群 / 正确应对 / 铁律 / 变异形态）追加为编号顺延的新类目
  4. **同步计数**：更新 README / SKILL 的类目计数文案，并在 workflows/anti-fraud-drill.yaml 的 `scam_type` 枚举追加对应项
  5. **一致性校验**：跑一遍类目数（知识库标题 / README / yaml 枚举）三处对齐校验，避免重演 v2.0.0 去类目时的漂移

## 规格自检（展示前内联执行）

0. **反向证伪**：检查“为什么可能不是骗局”——若存在合理解释（银行官方验证码短信、正常售后流程等），先排除再定级；
1. **猜测扫描**：有没有编造骗局类型、引用不存在的案例？命中谓词是否都可观察（对照 risk-levels.md）？
2. **内部一致性**：定级与证据链是否矛盾？应对建议与人群画像是否匹配？
3. **范围检查**：分析是否聚焦到一个可执行建议？是否超出当前问题的范围？
4. **模糊性检查**：有没有可被两种方式理解的地方？选择一种并明确写出来。

发现问题直接内联修复，无需重新走全流程。

## 与判定五步的关系

| 场景 | 用判定五步 | 用头脑风暴分析流程 |
|---|---|---|
| 常规骗局识别（短信 / 电话 / 链接） | 直接定级 | — |
| 信息不足 / 复合套路 / 分析性诉求 | 预检命中（自动升级条件成立） | 自动升级深挖 |
| 疑点多、线索冲突 | 先出初判 | 升级深挖 |
| 未收录骗局 | 如实说"未收录，按特征判定" | 深挖后沉淀 |
| 设计反诈方案 / 培训 / 话术 | — | 全程 |
| 红色风险已确认 | 立即强提醒卡 | 不得因分析延迟强提醒 |
