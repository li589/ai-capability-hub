# 防幻觉输出规则（证据分级与引用闸门）

目的：杜绝编造骗局类型、虚构案例、夸大置信度。所有输出按证据强度分级标注，让用户能区分"已确认"与"推断"。

## 一、证据标签（输出必带）

| 标签 | 含义 | 使用场景 |
|---|---|---|
| [已验证] | 与知识库（risk-levels.md / scam-knowledge.md）中的可观察谓词或条目直接命中 | 判定结论、命中证据 |
| [推断] | 基于用户描述与已知套路模式的合理推导，知识库无直接条目 | 骗局类型猜测、套路延伸分析 |
| [待核实] | 关键信息缺失或依赖外部验证，无法当前确认 | 涉及具体账户、机构、案例时 |

**规则**：每个结论至少挂一个标签。无法从用户描述或知识库支持的内容，一律标 [推断] 或 [待核实]，禁止默认标 [已验证]。

## 二、引用闸门

1. **知识库优先**：判定依据只引用 risk-levels.md 谓词与 scam-knowledge.md 条目，不引用记忆中的模糊印象
2. **官方渠道只来自冻结清单**：求助/核实渠道只使用 emergency-sop.md 求助渠道总表中的号码，不临时编造或给出网上搜来的陌生号码
3. **未收录骗局**：知识库 36 类均不匹配时，如实说"未收录，按特征判定"，标 [推断]；如需深挖走头脑风暴分析流程，沉淀后可入库
4. **真实案例**：引用案例必须是用户提供的、或可核验的近期公开报道；无来源案例一律不引用，改用套路拆解说明

## 三、置信度规则

- 红黄绿定级本身即置信度表达：红色=高置信，黄色=可疑，绿色=低风险
- 定级时多命中取最高级；红黄谓词≥3 条且线索相互冲突 → 升级走头脑风暴，不硬下结论
- 禁止使用"一定""绝对""百分之百"等绝对化表述；用"极大概率""很可能"
- 涉及具体机构是否正规（如某平台是否持牌）：标 [待核实]，给出官方核验渠道，不自行断言

## 五、外部证据核验（L3）

- 定级出现 [待核实] 项、命中红色谓词涉及具体主体、擦边球主体真实性、或用户要求"帮我查查真假"时，优先发起外部核验（web_search / web_fetch / RAG_search / 官方冻结清单）。
- 外部核验源必须可溯源（给出来源机构名，不写"网上说"）；单次搜索结果不得当权威定论，须经交叉印证或标 [待核实]。
- 工具不可用 → 显式标 [核验未达]，只给 emergency-sop.md 官方渠道，不自行断言。
- 核验结果分级：[已核验-假] 支撑红色升档 / [已核验-真] 可降级黄绿 / [核验未达] 维持待核实。完整规则见 references/verification-chain.md。

## 六、交叉印证（L4）

- 同一结论须 ≥2 个独立来源/方法支撑才升档；内部谓词命中（L1）+ 外部核验-假（L3）→ 红且高置信；反向证伪通过（L2）+ 核验-真（L3）→ 绿/黄。
- 内部判定与外部核验冲突 → 一律降级 [待核实] + 人工复核，禁止硬下定论。
- 仅单一来源（无 L3/L4）时置信度上限为"中"，且必须标 [推断]/[待核实]。

## 七、置信度标定与人工闸门（L5/L6）

- 强提醒卡与各级输出均按 verification-chain.md 的 L5 rubric 标 高/中/低 + 依据；禁止固定占位与绝对化表述。
- 高危结论经 L6 人工复核闸门：只作警示与建议，最终动作由用户本人确认，并标注"未经公检法/监管机构最终认定"。
- 涉及具体机构是否持牌/合法：永远 [待核实] + 官方核验渠道，合法性交由监管/司法，技能不代位定性。

## 四、输出前自检

1. 我的判定依据是否都能在 risk-levels.md / scam-knowledge.md 中找到？
2. 渠道号码是否来自 emergency-sop.md 总表？
3. 有没有引用我无法验证的案例或机构结论？
4. 关键结论是否都挂了证据标签？
5. 我是否做过“非骗局假设”检验？
