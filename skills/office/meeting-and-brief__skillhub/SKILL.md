## §1 四档路由（先判档再动手）

| 用户输入 | 档位 | 走法 |
|---|---|---|
| "这是什么会议类型 / 项目最近开过哪些会" | **A · Quick** | 直答，不落盘 |
| ≤2000 字文字稿 + "整理纪要" / 历史纪要小幅修订 | **B · Mini** | Context → Execute → 自查 → Deliver |
| ≥2000 字 / 多场会议 / 含付款/合规决议 / 要求"入库+后续调取" / 用户说"走 harness / 正式纪要" | **C · Full** | 10 步全链路（Plan/Dispatch/Research前/Research后/Judge） |
| "甲方 X 最近有什么问题需要我们配合" | **B** | 跨场问询 → 5 项优先级清单 |
| "甲方 X 在 Y 时段做了什么 / 交付了什么" | **B** | 交付物挖掘 → 3 桶交付清单 |
| **"出 X 月简报 / 给甲方 X 写月度简报 / 月底整理一下"** | **B'·简报档** | 聚合多份切片 → 正式信函 docx（**必须人审**）|
| **"做本周/本月例会纪要" + 存在上一期纪要或台账** | **B·周例档** | 待办周际联动 → 纪要 docx + 追踪事项 xlsx |
| "登记新客户 / 新建客户切片骨架" | **B** | 客户登记流程 |

模糊不清 → `AskUserQuestion` 一次问清 A/B/C/B'，**不偷偷换档**。

## §2.5 转录文字校对（预处理步骤 · v1.5 重写）

> 腾讯会议等语音转文字产出的文字稿，错别字 95% 是**中文同音字替换**，来源分三类：
> **专名错**（客户名/领导职务/项目名/行业术语）、**口音错**（方言导致的系统性声韵母混淆）、
> **通用同音/形似错**。本步骤在 Context 之前自动执行，按三类来源**定向纠**而非逐字凭感觉猜；
> 拿不准的一律**标记不静默改**——咬合反幻觉红线。配套词典：`references/asr-纠错对照表.md`。

### 触发条件（自动）

满足以下**任一条件**即自动执行校对：
- 文字稿包含时间戳标记（如 `[00:01:23]` / `00:01:23` / `（01:23）`）
- 文字稿包含说话人标注（如 `发言人1：` / `张三：` / `Speaker 1:` / `A：` 模式）
- 用户明确说"这是腾讯会议转写/语音转的文字/ASR 出来的"
- 用户说"先校对一下 / 修正错别字 / 转写有错字 / 转写稿纠错 / 同音字纠正 / 纪要前先纠错"

### 纠错纪律（三条红线 · 不可豁免）

1. **三档处置**：
   - 高置信（命中专名表 / 命中口音规则且拼音回推成立）→ 直接改。
   - 中置信（同音可疑但上下文不能确定）→ **不静默改**，标 `[?待核：原词→疑似]`。
   - **数字、金额、比例、日期、领导姓名职务** → 一律**只标不改**，回听音频人工定。
2. **优先级**：领域专名 ＞ 口音规则 ＞ 通用同音/形似。冲突时高优先级覆盖低。
3. **留痕可溯**：清洗稿不改原意、只纠错别字；每处改动在纠错对照清单留痕（`原词→正词｜归因`）；
   新确认的错→正**回写** `references/asr-纠错对照表.md` §5 自增长混淆集，越用越准。

> 纠错不得变脑补。拿不准就标，不替音频做主。专名/数字宁可标待核，不可猜改。

### 工作流（5 步）

#### 步骤 1 · Context

1. 识别**客户**、**会议/工作类型**、**与会者**。
2. 读 `memory/doc/facts/client-codename.md` 取该客户代号/专名；查不到 → 走 §6 客户登记。
3. 读该客户 `memory/projects/clients/{客户代号}/术语表.md`（若有）；读历史切片 frontmatter 的
   `说话人口音:` 字段（若有）建**口音画像**。

#### 步骤 2 · 专名锁定（最高优先级）

用对照表 §4 专名接口（client-codename.md + 客户术语表 + 咨询锚词），把转写稿里的真名 /
近音错名 / 错术语回贴为登记代号或正确专名。**专名先锁死，后续口音/通用规则不得再覆盖。**

管理咨询高频术语误识（种子示例，完整见对照表 §3）：

| 正确术语 | 常见误识为 |
|---|---|
| 经营分析会 | 精英分析会 / 经验分析会 |
| 组织架构 | 组织架够 / 组织架设 |
| 绩效考核 | 绩效考和 / 鸡校（重口音） |
| 薪酬体系 | 薪酬体细 / 新仇体系 |
| 尽职调查 | 禁止调查 / 进调 |
| 对标 | 对表 / 对彪 |
| 复盘 | 复判 / 富盘 |
| 合规 | 和规 / 和归 |
| 闭环 | 壁环 / 必还 |
| 颗粒度 | 颗粒都 / 科立度 |
| 交付物 | 交付五 / 交付无 |
| 并购 / 股权 | 病够 / 古权·股全 |

#### 步骤 3 · 口音定向扫

按口音画像启用对照表 §2 的规则行（R1 平翘舌 / R2 前后鼻音 / R3 l-n / R4 f-h / R5 鼻韵尾脱落）。
对可疑词用**拼音回推**检验：识别词与上下文应有词只差一个声韵母维度 → 判口音错、改；
差很远 → 转步骤 4。无籍贯线索时，用**语义断裂信号**兜底（整句突然不通 / 冒生僻字组合 /
量词搭配反常）→ 标 `[?待核]`。

#### 步骤 4 · 通用兜底

剩余可疑词查对照表 §3 通用同音种子 + §5 自增长混淆集，命中 §5 直接复用历史判定。高频组：
在/再、的/得/地、做/作、象/像、他/她/它、是/十/四、反映/反应、须/需——以句子语义和
上下文语法为准逐句判别。

#### 步骤 5 · 三档处置 + 输出 + 回写

- **三档处置**按纪律执行；**格式归一**（不改变数值/事实）允许高置信直接做：
  - 百分比口语 → `20%`；上下文明确的"一千二" → 1200
  - "下周三" → 按会议日期推算为 `YYYY-MM-DD`，附 `（原话：下周三）`
- **语义矛盾检测**：数字前后不一致 / 态度反转 / 时间线矛盾 → 标 `【待核实：前后矛盾】`，不自行修改。
- **去重合并**：同一句话被转写出两次（间隔 <30 秒）→ 保留一句；说话人自纠（"我是说……不对，
  我的意思是……"）→ 保留修正版、删冗余。
- **断句标点**：长句按语义断句补逗号句号；疑问语气补 `？`；直接引语补 `""`；列举补顿号；
  删除口语填充词（那个 / 就是说 / 然后呢 / 嗯 / 啊，除非影响语义）。
- 新确认的错→正**回写**对照表 §5（日期 / 客户 / 原错词 / 正确词 / 归因 / 来源 六列）。

### 校对输出（3 份 · 落盘 `outputs/{客户代号}/`）

1. **清洗稿** `{原名}_proofread.md` — 修正后全文，顶部保留水印：
   `[本文为 ASR 转写稿，已机器纠错；[?待核] 处与数字/专名以原音频为准]`
2. **纠错对照清单** `{原名}_diff.md` — 表头：`原词 | 改为 | 归因(专名/口音R#/同音/形似) | 处置(改/待核) | 位置`
3. **存疑清单** `{原名}_uncertain.md` — `[?待核]` 与 `【待核实】` 条目汇总，供人审 / 回听

回复用户给 `computer://` 链接 + 一句话报：改了 N 处、待核 M 处、回听建议清单。

### 上游预防 · 客户专名 → ASR 热词（源头少错）

错别字最划算的减法在**源头**：转写前把客户专名喂进 ASR，转写阶段就少错专名。

```
python scripts/gen_hint_words.py --client {客户代号}
# 读 memory/doc/facts/client-codename.md（公司/人员/项目真名）
#  + memory/projects/clients/{客户代号}/术语表.md（产品线/缩写/黑话/职务）
# → 去重、截到 ~200 字 → outputs/{客户代号}/hint-words.txt
```

把生成的热词串传给 `asr-transcribe` skill 的转写命令（`--hint-words`，即 whisper initial_prompt，
偏置识别专名）。**保密**：热词串含甲方真名，仅本地 whisperX 离线用、数据不出域；脚本默认只写
本地文件、不回显真名（除非 `--print`）。转写出的真名后续由本 skill 代号化。

### 政治校对红线

领导姓名 / 职务 / 排序遵循新华社最新表述；存疑**只标不改**，提醒人工核。

### 校对后衔接

校对完毕 → 将清洗稿作为 §3 步骤 1（Context）的输入，正常走 B 档/C 档纪要整理流程。
Context 阶段读文字稿时**优先使用 `_proofread.md`**。

**周期性例会/有台账可核的场景**：语言层校对后追加**项目实体核验**（客户名/项目号/人名/金额
三级匹配：别名表 → 基准台账 → roster，确证静默改、拿不准一次问用户），规则详见
`references/entity-verification.md` 与 §3.5 步骤 2。

### 校对不通过的情况

以下情况跳过校对或降级处理：
- 文字稿无明显 ASR 特征 → 跳过校对，直接进入 §3
- 文字稿过短（<200 字）→ 跳过校对
- 校对后存疑条目 >20 条 → 暂停，交用户审存疑清单后再继续

## §3 工作流 · B 档·会议纪要（默认大多数场景）

### 步骤 0 · 转录校对（如有必要 · 在 Context 之前）

检测文字稿是否为 ASR 转录来源 → 是则执行 §2.5 转录文字校对 → 产出校对后文字稿。

### 步骤 1 · Context（30 秒内完成）

读三类信息：
1. 文字稿内容（如经 §2.5 校对则读 `_proofread.md`）→ 识别**客户**、**会议/工作类型**、**日期**
2. `memory/doc/facts/client-codename.md` → 查客户代号；查不到 → AskUserQuestion 让用户登记
3. `memory/projects/clients/{客户代号}/` → 查最近 90 天有没有同客户的历史切片（供跨场对照）

工作类型八选一：`sales` / `ops-review` / `project-mgmt` / `research` / `site-visit` / `process-mapping` / `policy-design` / `other`。详见 `references/meeting-types.md`。

### 步骤 2 · Execute（先证据矩阵后正文 · 不允许颠倒）

对每个议题：
1. 先在 markdown 注释里写"证据矩阵"——`论点 / 证据类型 / 来源 quote / 来源位置` 四列
2. 矩阵下方扩写正文，每个事实句必带【实证】/【估算】/【常识】+ `[source: 文件名:位置]`
3. 议题标题用 **action title（结论句）**，不是主题词

按 §7 附件10 模板结构组织 markdown 草稿。

### 步骤 3 · 自查（post_write · Judge 前必过）

正文 ≥10 行必跑：

| 项 | 通过线 | 检查方法 |
|---|---|---|
| 句级三态覆盖率 | 事实句 100% 带【实证】/【估算】/【常识】 | grep `【实证】|【估算】|【常识】` |
| source token 实存 | 【实证】句必含 `[source:` + 路径文件存在 | 抽 5 条 grep 原文件 |
| 行动项四要素 | 内容 / 责任人 / 完成时限 / 交付物 缺一不可 | 看 §7 行动项表是否填满 |
| 客户脱敏 | 无真名 / 无精确金额（万元级以下数字） | 用代号 + 范围（千万级 / 百万级） |
| 措辞红线 | 0 命中"业内通行 / 据说 / 大概 / 综上所述 / 首先其次 / 作为 AI" | grep 禁用词清单 |

任一不过 → 退回步骤 2 自己改。

### 步骤 4 · Deliver（落盘三份）

1. **docx 正本**（按 §7 附件10 表格式）→ `outputs/{客户代号}/{客户代号}-{会议简称}-YYYY-MM-DD.docx`
2. **markdown 全文**（含证据矩阵 + 未核实清单 · 内部留档版）→ 同目录同名 .md
3. **记忆切片**（关键事项浓缩，供后续调取）→ `memory/projects/clients/{客户代号}/{会议类型}/YYYY-MM-DD-{slug}.md`

docx 生成：调 `scripts/meeting_docx.py` 的 `build_minutes(data, output_path)`。

回复用户给文件路径 + 一句话结论；**不要长 postamble**。

## §3.5 工作流 · 周期性例会档（B·周例档）

> 专治"周例会/月度例会"类周期性会议：**周际待办承接**——提取上一期待办 → 逐项复盘进展 →
> 开放项承接到本期 → 出正式纪要 docx + 本周追踪事项 xlsx。两类主体均可承载：
> ①在手项目验收/交付进度复盘与堵点对策；②应回未回款项/应收盘点。
> 完整规则见 `references/weekly-action-linking.md`；正文骨架与承接校验规则也在其中。
> 无上一期纪要（首次建档）时向用户确认，不静默省略上周复盘。

### 触发条件（双条件硬闸）

1. 用户**发来转写**：周期性例会（周例会/月度例会）的腾讯会议转写（`.txt`/`.docx`/`.md`，或直接粘贴正文）。
2. 用户**明确指令**："做本周例会纪要 / 周会纪要 / 月度例会纪要"或高度近似。

缺转写 → 提示"请把转写发我"，不编。缺指令 → 不主动触发。
是录音/视频 → "请先 ASR 转写后再发我"。**拿到转写无需用户另说"请校对"，自动进入步骤 1。**

### 步骤 1 · 定位四个输入

| 输入 | 来源 | 备注 |
|---|---|---|
| 原始转写正文 | 用户本次发来的 txt/docx/md/粘贴 | 事实内容源；只读保留，禁止覆盖 |
| 上一期纪要 | 归档目录内会议日前最近一期正式 docx | `scripts/extract_previous_actions.py --root <归档根> --before YYYYMMDD --json` 提取上周待办；不得把本期或临时文件当上期 |
| 基准台账/明细表 | 项目根下最新日期版（`*.xlsx`） | 客户名/项目号/金额核验基准，详见 `references/entity-verification.md` |
| 别名表 + roster | 客户 `术语表.md` + 固定与会名单 | 已确认的"误听→标准名"，先查这里再查台账 |

### 步骤 2 · 转录校对 + 项目实体核验（先清洗，再组稿）

1. 自动执行 §2.5 转录文字校对（错别字/同音词/断句/标点）→ 产出清洗稿与纠错对照清单；过程稿写 `work/weekly-minutes-YYYYMMDD/`，下游步骤只读清洗稿。
2. 对清洗稿中**所有**客户名、项目名、口语项目号、金额、人名职务执行**项目实体核验**（`references/entity-verification.md` 三级匹配）：
   - 确证（别名命中 / 台账唯一命中 / roster 唯一命中）→ **静默改**，纪要正文只出现标准名，不留〔注〕、不写"原文误"；
   - 拿不准（查无 / 多候选 / 疑似当周新签 / 金额对不上）→ 不擅改、不写进纪要，收集成"待确认清单"走步骤 5。
   - 通用语言模型判断**不能单独**作为专名修改依据。

### 步骤 3 · 上周待办提取 + 进展对照

1. `extract_previous_actions.py` 提取上一期待办 → 依次编号 `上周-01`、`上周-02`…，逐项在本周转写中查找进展同步。
2. 进展状态**只使用五态**：`已完成` / `进行中` / `未启动` / `阻塞` / `取消`。**不得把"会上未提及"推断为"未完成"。**
3. `已完成`、`取消`：保留在上周复盘表，不再进入本周待办；取消项写明会上确认的原因。
4. `进行中`、`未启动`、`阻塞`：必须承接到本周待办，分配 `本周-XX` 编号，注明 `承接上周-XX`，并填本周负责人、追踪人和新完成时限。
5. 原事项被调整/拆分：上周复盘表写明 `调整为本周-XX/XX`，本周各条分别注明来源。
6. 转写未同步状态、开放项未给新时限或承接关系不清 → 统一进步骤 5 待确认。

### 步骤 4 · 组稿（正文骨架固定）

按 `references/weekly-action-linking.md` §二 骨架组稿，只使用已清洗且无 `[?待核]` 标记的文本：

- **一、会议议程**（3–4 条，结论化）
- **二、会议小结与决议**——按主题切块，每个小结论用 **action title（结论句，带关键数字）**，下挂 2–4 条证据 bullet
- **三、待办事项跟踪**（**必须是最末实质段落**）：
  - （一）上周待办事项进展：六列 `编号 | 上周待办事项 | 负责人 | 原定时限 | 进展状态 | 进展说明及本周处理`
  - （二）本周待办事项：六列 `编号 | 会议安排事项 | 负责人 | 追踪人 | 完成时限 | 来源/备注`
  - 延续项用 `承接上周-XX` 建立关联；本周新增项标 `本周新增`；每条只填一个主负责人
- 会议基本信息表用固定 roster 兜底（转写常缺与会名单）
- 表后接 `整理人 | 咨询项目组 | 抄送 | 项目相关部门` 页脚

### 步骤 5 · 不确定项 → 直接问用户（AskUserQuestion）

把 ASR 中置信错字候选、拿不准的客户名/项目/金额，以及上周待办的进展状态、承接方式、新完成时限，
汇成 **1 次** `AskUserQuestion`（每项给候选 + "其他"）。**绝不**在纪要里用"待核实/疑误听/〔注〕"这类提示。
用户答完：能定的填进正文，仍定不了的按用户口径写或暂不写。

### 步骤 6 · 生成 docx + 本周追踪事项 xlsx（同源同构）

用同一份 content JSON（schema 见 `weekly_minutes_docx.py --sample`）：

```bash
python scripts/weekly_minutes_docx.py --content content.json --out {客户}-{例会}-会议纪要-YYYYMMDD.docx
python scripts/build_action_tracker.py --content content.json --out {客户}-本周追踪事项-YYYYMMDD.xlsx
```

- docx：附件10 博维格式（微软雅黑 / 标题18pt / 正文10.5pt / 表格全黑边框）；生成前内置
  `validate_action_links()` 强制校验承接关系（开放项必须承接、关闭项不得重复进入、引用须存在）。
- xlsx：工作表名"本周追踪事项"，表头开启筛选、冻结首行、状态列五值下拉、选"完成"整行浅绿；
  规格详见 `references/action-tracker-spec.md`；保存后自动复检结构。
- 两个文件落点同目录、同日期后缀。

### 步骤 7 · 交付 + 自查

- `present_files` 同时给出 docx 和 xlsx；**缺任一文件不得宣称交付完成**。
- 对话里附"本次纠错日志"（普通 ASR 错字 + 项目专名两类，格式见 `references/entity-verification.md`），
  报告高置信修改数、经用户确认数和未采用数。
- 自查（出文件前必过）：ASR 校对完成且有清洗稿/对照清单；正式纪要 0 处待核标记；正文 0 处误听名；
  上周待办逐项记录五态状态、无悬空项；开放项均承接有效的 `本周-XX`；已完成/取消项未重复进入本周；
  Excel 行数与 Word 本周待办数一致、关键字段逐行一致；措辞 0 命中红线词。
- 回写：新确认的"误听→标准名"追加客户 `术语表.md`；普通错字仅在用户确认后按 §2.5 回写混淆集。
- 一句话结论收尾，不长篇。

## §5 工作流 · 跨场问询（5 项优先级清单 / 3 桶交付清单）

### §5.1 优先级问询

用户问"甲方 X 最近有什么问题需要我们配合"时：

1. 扫描 `memory/projects/clients/{X}/{所有类型}/` 近 90 天切片

1. 调 `scripts/deliverable_mining.py · scan_deliverables()` 扫描 4 个数据源
2. 按 3 桶分类：主交付物 / 中间产出物 / 我方独立完成事项

## §10 红线（PERMISSIONS 摘要 · 触发即停手）

### 反幻觉（P1）
- 事实句必带【实证】/【估算】/【常识】
- 【实证】必含 `[source: 文件名:位置]`；查不到 → 停-问 / 停-降为【估算】/ 停-删
- 禁用模糊归因："业内通行 / 专家指出 / 据说 / 网传 / 相关数据显示"
- 禁用不可证伪量词："大概 / 大致 / 应该是 / 可能是 / 基本上"
- 禁用 AI 痕迹："首先 / 其次 / 综上所述 / 值得注意的是 / 作为 AI"

### 客户保密（P2）
- 真实公司全名 → 用代号（甲方A / 甲方B...）
- 精确金额 → 用范围（百万级 / 千万级 / 亿级）
- 未公开战略 → "战略方向 X" + 一句话脱敏描述
- 内部组织调整 → 用"部门 D1/D2"

### 原件保护（P3）
- 文字稿原件不动；只读不改

### 禁用清单（P4）
- 不写真名/真金额/跨客户内容/推测性惯例/个人隐私/无关闲聊

### 权限（P5）
- 不直接修改 `memory/doc/facts/client-codename.md`（脱敏映射最敏感）
- 已入库切片**不修改**——发现错误起 v2 文件

### 顶级（P6）
- 未在文字稿中出现的内容禁止编造（句级三态强制）
- 触发任一红线 → 立即停手，输出违规清单，等用户决策

## §12 升 C 档触发

- 文字稿 ≥2000 字
- 多场会议合并到一份纪要
- 含付款节点 / 合规风险
- 用户明示"正式纪要 / 走 harness"

C 档比 B 档多 5 步：Plan（出 plan.md + 证据卡占位）/ Dispatch / Research 前（切证据卡）/ Research 后（抽样 5 条 source 实存）/ Judge（独立新会话 5 维盲评 ≥75 且每维≥15）。

B 档大部分场景已够——别为了"走流程"而升档。
