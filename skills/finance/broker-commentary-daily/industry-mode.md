# Industry Mode (按行业总结版)

适用于：

- 用户要求只总结某一个行业，或一次点名多个行业
- 用户给出申万一级行业名，如 `银行`、`电力设备`、`医药生物`、`电子`
- 用户给出模糊行业名或二级方向，如 `化工`、`光伏`、`半导体`、`白酒`
- 用户希望减少全量点评噪音，只看某行业内的券商点评主线、个股和分歧

## 与全面版的关系

行业版与全面版**共用同一套终稿格式与写作规范**：

- 终稿骨架：`一、今日总览` → `二、热点话题详析` →（可选）`值得关注的独立线索 / 附录`
- 话题三件套：事件 / 投资观点与推演 / 核心个股
- 观点按机构分条；不输出原文点评摘录；不附生成说明或覆盖校验摘要
- 总览写成可读摘要，覆盖该行业所有重要讨论
- 写法必须遵守 [writing-standards.md](writing-standards.md)，并参考 [comprehensive-example.md](comprehensive-example.md) 的话题与总览表达

唯一差异是**数据范围**：只抓取用户指定的申万一级行业 `comment`。单行业时主 Agent 自行执行；**多行业时必须并行 Subagent**，不要串成一条流水线。

## MCP 能力确认

已确认 `user-comein-brm` 的 `research_query` 支持结构化行业筛选：

- `type=comment`：筛选券商点评
- `industryName`：筛选关联行业，支持 `宏观`、`策略`、`固收`、`中小市值`、`海外研究`、`北交所` 以及申万一级行业名称，如 `银行`、`电力设备`、`基础化工`

`searchAnalystComments` 只支持自然语言 `query` 和 `start_time`，不支持结构化行业筛选；只能作为补充交叉验证工具，不作为本模式主数据源。

## 目标

围绕指定行业生成一份与全面版同格式的 Markdown 日报。为了防止该行业当天点评数量过多导致遗漏，必须采用“分页处理账本 → 分页成文式底稿 → 总索引去重聚类 → 跨页二次总结 → 覆盖审计（仅内部）”流程：

1. 只抓取该行业下的 `comment` 数据，并建立分页处理账本
2. 逐页提炼并生成分页成文式底稿
3. 提取全行业总索引，梳理最重要的主题、催化、分歧和高频个股
4. 按全面版终稿格式输出结构化日报，并完成内部覆盖校验

## 输出目录与文件保留规则

行业版运行产物必须放在**独立运行目录**中，避免污染 skill 本身的项目文件。默认目录：

```markdown
outputs/YYYY-MM-DD-券商行业版日报-[行业]/
```

该目录下默认只保留以下文件，不额外落盘内部账本、索引和审计记录（除非用户明确要求调试）：

```markdown
outputs/YYYY-MM-DD-券商行业版日报-[行业]/分页底稿/page-001.md
outputs/YYYY-MM-DD-券商行业版日报-[行业]/分页底稿/page-002.md
outputs/YYYY-MM-DD-券商行业版日报-[行业]/YYYY-MM-DD-券商行业版日报-[行业].md
```

## 执行步骤

### 1. 确认行业

如果用户没有给出行业名，先这样询问：

> 按行业总结用的是申万一级行业口径。可以说一个，也可以一次说多个（如「电力设备和电子」）。确定的一级行业如 `基础化工`、`电力设备`，模糊说法如 `化工`、`光伏`、`半导体` 也可以，我会先帮你对到对应行业再查。

如果用户给出了行业名，先判断是否已经是明确的申万一级行业：

- 如果是明确申万一级行业，直接使用该名称作为 `industryName`
- 如果是简称、俗称、二级行业或主题方向，先映射到最接近的申万一级行业，再查询
- 如果一个模糊行业名可能对应多个申万一级行业，必须先向用户确认，不要擅自选择
- 若用户一次给出 **≥2 个** 可区分的行业目标，进入「多行业并行」；不要合并成一次模糊全库检索
- 若用户说的是大板块名（`科技` / `周期` / `消费` / `医药` / `制造` / `金融` / `其他`），**立即停止行业版流程**，改走 [comprehensive-mode.md](comprehensive-mode.md) 的「单板块 / 多板块精简跑」。`科技` ≠ 申万 `电子`。

### 1.1 多行业并行（强制）

当确认后的 `industryName` 列表长度 ≥ 2：

1. **一次并行**启动与行业数相同的 Subagent（每个只负责一个 `industryName`）。
2. 每个 Subagent 按本文后续步骤独立完成：分页抓取 → 分页底稿 → 该行业日报（写入各自目录 `outputs/YYYY-MM-DD-券商行业版日报-[行业]/`）。
3. 主 Agent **不得**等行业 A 全部写完再开行业 B。
4. 全部完成后，主 Agent 可再给用户一份极短的跨行业对照摘要（可选）；对各行业正文以分文件或分章节呈现，不要把多行业硬揉成一份含糊日报除非用户要求「合成一篇」。
5. 对用户说话用「我同时在看这几个行业」，不要提 Subagent / 并行管道等实现词。

常见映射示例：

```markdown
| 用户输入 | 查询用 industryName | 说明 |
|---|---|---|
| 化工 | 基础化工 | `基础化工` 是申万一级行业，优先用它查询 |
| 光伏 | 电力设备 | 光伏通常归入电力设备一级行业，正文再按光伏子方向筛选 |
| 半导体 | 电子 | 半导体通常归入电子一级行业，正文再按半导体子方向筛选 |
| 白酒 | 食品饮料 | 白酒通常归入食品饮料一级行业 |
| 银行 | 银行 | 已是申万一级行业，直接查询 |
```

在最终日报「一、今日总览」开头用一句话注明：用户原始输入、实际传入的 `industryName`、是否做过模糊映射；不要单独开「使用说明」章节。

### 2. 读取 schema

先读：

- `research_query`

如需补充语义检索，再读：

- `searchAnalystComments`

### 3. 按行业全量分页抓取并建立处理账本

固定参数：

- `type=comment`
- `industryName=[确认或映射后的申万一级行业]`
- 单日范围默认 `00:00:00 -> 23:59:59`
- `pageSize=100`
- 持续翻页到 `<100条` 或 `暂无数据`

必须建立分页处理账本，但默认不单独落盘。账本作为运行过程中的内部清单维护，用于确保每一页都被抓取、阅读并生成分页底稿。

如果指定行业当天返回较少，可向用户说明数据稀疏，并只基于已返回点评输出，不要跨行业补齐。

如果用户原始输入是二级方向或模糊行业名，抓取后需要在分页底稿和总索引中再次筛选该子方向。

### 4. 分页成文式底稿

不要把所有原文一次性塞进上下文后直接写正文。每一页必须先生成**分页成文式底稿**，写入独立运行目录：

```markdown
outputs/YYYY-MM-DD-券商行业版日报-[行业]/分页底稿/page-001.md
outputs/YYYY-MM-DD-券商行业版日报-[行业]/分页底稿/page-002.md
```

分页底稿必须包含：

- **本页总览**（按 [writing-standards.md](writing-standards.md) 总览规范写成可读摘要）
- **本页热点话题与独立线索**（格式对齐全面版：事件 / 投资观点与推演 / 核心个股；不要原文点评摘录；不要一级主线汇总层）
- **本页全量条目处理清单**（确保不重不漏）

`去向` 只能填：`热点话题` / `独立线索` / `附录线索` / `噪音/不保留`。

### 5. 建立行业内总索引与去重聚类

所有分页成文底稿完成后，先基于全部 `分页底稿/page-xxx.md` 生成行业总索引，内部维护不落盘。
提取字段建议：

```markdown
| 时间 | 机构 | 标题 | 热点话题 | 逻辑分支 | 个股 | 事件摘要 | 投资推演摘要 | 保留层级 | 正文去向 |
```

`热点话题` 应在行业内部进一步细分，例如电力设备下可区分锂电、光伏、风电、电网设备等；命名遵守 [writing-standards.md](writing-standards.md)（主体 + 具体进展/量级，一事一题）。

排序与合并优先级：
1. 多机构反复提及且有客观催化的话题
2. 单条频次不高但事件强度较高的独立线索
3. 高频个股及其产业链位置
4. 存在明显分歧的方向

### 6. 基于总索引输出日报与覆盖校验

依据内部总索引及所有分页底稿生成最终日报：

```markdown
outputs/YYYY-MM-DD-券商行业版日报-[行业]/YYYY-MM-DD-券商行业版日报-[行业].md
```

终稿结构必须与全面版对齐：

```markdown
# YYYY-MM-DD [行业]券商行业版日报

## 一、今日总览
（覆盖该行业所有重要讨论的可读摘要；写法遵守 writing-standards.md「今日总览」；开头一句注明 industryName 映射）

## 二、热点话题详析

### 热点话题1: [主体+具体进展的一句话标题]
- **事件**：[先用一句客观事实总起。只有一个事件时用完整段落；同一主题包含多个相关事件时，按下列格式分点，不要堆成一个长段落。]
  - **（1）[事件主体/简短事实标题]**：完整陈述该事件、关键数字和条件。
  - **（2）[事件主体/简短事实标题]**：完整陈述另一项相关事件、关键数字和条件。
  [每点只讲一个事件；无共同主逻辑的事件应拆成不同热点话题。]
- **投资观点与推演**：按机构分条：
  - **（1）[机构名]观点**：...
  - **（2）[机构名]观点**：...
- **核心个股**：
  - **[个股A]**：卡位 + 弹性 + 估值锚（如有）

### 热点话题2: ...

### 值得关注的独立线索
...

## 附录：未纳入主线但值得关注的线索
（可选；无则省略）
```

覆盖审计只做内部质检，**不要**写入终稿。终稿不要附「使用说明 / 生成说明 / 覆盖校验摘要 / 原文点评摘录」。

## 质量红线

- 不要把行业外点评混入正文，除非原文明确说明对指定行业有传导影响
- 不要把用户输入的二级方向直接传给 `industryName`，必须先映射为申万一级行业
- 不要用全市场热点替代行业内事实
- 不要把“券商发布点评”当成客观产业事件
- 不要只按标题总结，必须阅读返回内容中的正文信息
- 如果 `industryName` 返回为空或明显过窄，先说明 MCP 返回情况，再询问用户是否改用标题/自然语言检索补充
- 终稿格式、话题三件套、总览写法必须与全面版一致；写作遵守 [writing-standards.md](writing-standards.md)
