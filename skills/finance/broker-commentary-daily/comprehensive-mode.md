# Comprehensive Mode (全面版)

适用于：
- 用户明确要求 `全面版`、`最全面版`、`全覆盖版`、`全集版`
- 用户强调 `不重不漏`、`不能有任何遗漏`、`非常细致`
- 用户要求按 `科技、周期、消费、医药、制造、金融、其他` 分类总结

## 核心目标

通过“**七大板块映射 → 按一级行业并行 Subagent 抓取 → 主 Agent 按板块合并、全量补漏、跨板块去重并拼接**”的流程，将当日点评（comment）**极其细致、尽量不重不漏**地提炼归类。不仅要提取主线，还要提取冷门线索。

**并行粒度是 `industryName`（一级行业）**：大板块只是归类与合并单位；同一板块下的多个行业必须并行，禁止板块内串行扫行业。

最终正文必须对齐 `@comprehensive-example.md` 的骨架与行文风格：流畅、专业、带具体数字，禁止碎片化电报体。

**绝对禁止**：
- 依赖外部脚本粗糙拼接最终日报。主 Agent 必须亲自阅读七份板块文档、执行跨板块去重与补漏后再输出最终内容。
- 以“条目过多”为借口遗漏信息。所有公司、涨价、订单、业绩变化等客观事实必须保留。
- 跳过行业映射表，凭感觉给七大板块随便塞行业。
- 七个板块任务各自全量抓取当日全部 comment 再自行分类；必须按映射表的 `industryName` 分别查询。
- **大板块下串行扫行业**（如科技任务里依次查电子→通信→计算机→传媒）。
- 随意改变规定的七大板块分类名称与顺序。
- **禁止使用碎片化、电报式短语拼凑**。必须使用完整、流畅的专业句子。

## 架构总览

```text
主 Agent
  ① 确认日期、创建运行目录
  ② 展开映射表全部 industryName，按一级行业并行 Subagent
       ↓
行业 Subagent × N（电子 / 通信 / 计算机 / 传媒 / 基础化工 / …）
  各自：只查本 industryName → 翻页 → 成文行业底稿
  （同一大板块下的行业必须并行，禁止串行）
       ↓
主 Agent
  ③ 按七大板块归属合并为板块底稿
  ④ 全量无行业过滤抓取做覆盖审计与补漏
  ⑤ 跨板块去重、统一文风与标题层级
  ⑥ 写今日总览 + 拼接最终日报（覆盖审计只做内部检查，不写入终稿）
```

## 单板块 / 多板块精简跑

当用户**没有**要求全面版，而是直接点名大板块（如「科技」「周期」「制造和消费」）时，走本精简流程，**不要**误当成申万一级行业版，也**不要**默认跑满七块。

### 核心：大板块下的一级行业必须并行

用户说「科技」时，真正要跑的是映射表里的多个 `industryName`（电子 / 通信 / 计算机 / 传媒）。**并行粒度是一级行业，不是「整个科技块串着查完再写」。**

错误示例（禁止）：
- ❌ 一个 Agent 里依次：先查电子 → 再查通信 → 再查计算机 → 再查传媒
- ❌ 只开一个「科技 Subagent」，内部串行扫完行业列表

正确示例：
- ✅ 科技 → **一次并行**拉起 4 个行业 Subagent：`电子`、`通信`、`计算机`、`传媒`
- ✅ 周期 → **一次并行**拉起该板块全部一级行业 Subagent（基础化工、有色金属……）
- ✅ 科技 + 周期 → 把两个板块下属全部 `industryName` **摊平后一次并行**（或按板块两波并行，但每一波内部行业仍必须并行）
- ✅ 各行业 Subagent 写完行业底稿后，主 Agent 再聚合成「科技/周期」板块文档与最终日报

### 精简跑步骤

1. 识别板块名：`科技` / `周期` / `消费` / `医药` / `制造` / `金融` / `其他`（及同义）。
2. 取出对应 `industryName` 列表（见下表）。
3. **按列表长度并行启动行业 Subagent**（每个 Subagent 只负责一个 `industryName`：分页 `research_query` → 该行业成文底稿）。列表只有 1 个（如医药=`医药生物`）时不必强行拆分。
4. 主 Agent 汇总各行业底稿 → 去重聚类 → 写成板块级终稿（骨架同全面版：总览 + 热点话题详析）。
5. 输出目录：
   - 单板块：`outputs/YYYY-MM-DD-券商板块日报-[板块名]/`
   - 其下可保留 `行业底稿/电子.md` 等中间文件与最终 `...板块日报.md`
6. 精简跑不做未点名板块、不跑满七块全量补漏；终稿禁止工程化去重话术。
7. 对用户只说「按科技板块梳理」，不要提 Subagent / 并行管道。

若用户随后说「改成全面版」，再升级为完整全面模式（七大板块；**每个板块内部同样按行业并行**，见「板块内行业并行」）。

## 七大板块 ← 申万一级 / 特色行业映射（强制）

查询时传入 `research_query.industryName`，**不要带「行业」后缀**。以下为全面版与大板块精简跑共用的固定映射；Subagent 不得擅自增删板块，但某个 `industryName` 返回空数据时可以跳过并在账本备注。

| 七大板块 | 查询用 industryName 列表 |
|---|---|
| **科技** | `电子`、`通信`、`计算机`、`传媒` |
| **周期** | `基础化工`、`石油石化`、`有色金属`、`钢铁`、`煤炭`、`建筑材料`、`农林牧渔`、`交通运输`、`公用事业` |
| **消费** | `食品饮料`、`家用电器`、`纺织服饰`、`轻工制造`、`商贸零售`、`社会服务`、`美容护理`、`房地产` |
| **医药** | `医药生物` |
| **制造** | `电力设备`、`机械设备`、`国防军工`、`汽车`、`建筑装饰`、`环保` |
| **金融** | `银行`、`非银金融` |
| **其他** | `宏观`、`策略`、`固收`、`中小市值`、`海外研究`、`北交所`、`综合` |

说明：
- 主题词（AI、光伏、半导体、白酒等）**不要**直接当 `industryName`；应落在上表对应一级行业内，再在正文按子主题聚类。
- 若 MCP 对个别名称报错或空结果，在板块底稿「板块抓取说明」中记录，并尝试最接近的合法申万一级名；仍失败则交给主 Agent 全量补漏。
- 「其他」不是垃圾桶：优先承接宏观/策略/固收等特色口径；跨板块都放不下、但有信息量的内容，由主 Agent 补漏阶段写入「其他」或附录。

主题语义对照（仅用于正文聚类，**不用于查询**）：
1. **科技**：AI、半导体、算力、光模块、软件、互联网、数据要素、消费电子等
2. **周期**：化工涨价、有色、能源、煤炭、钢铁、建材、农业、交运、公用、海运、贵金属等
3. **消费**：食品饮料、轻工、家电、纺服、社服、免税、电商、零售、地产后周期等
4. **医药**：创新药、疫苗、器械、检测、中药、CXO、医疗服务等
5. **制造**：机械、军工、航天、汽车、低空、锂电、光伏、风电、电力设备、出海制造等
6. **金融**：银行、券商、保险、转债、流动性等
7. **其他**：纯宏观地缘、纯市场情绪、无法验证传闻，以及补漏得到的未归类高价值线索

## 最终输出格式规范

输出的 Markdown 日报必须**严格对齐** `@comprehensive-example.md` 的骨架和行文风格，且事件与投资观点的表达必须遵守 [writing-standards.md](writing-standards.md)（事件段只写事实、观点段只总结券商、逻辑链完整有出处）。

板块内**不要**再套「一级主线 / 次主线」汇总层，直接按话题展开；每个话题只保留三件套：**事件 / 投资观点与推演 / 核心个股**，**不要**输出「原文点评摘录」。终稿**不要**附「生成说明 / 覆盖校验摘要 / 使用说明」。

板块内结构：

```markdown
## [板块名称，如：科技]

### 热点话题1: [主体+具体进展的一句话标题，如：InP 衬底紧缺持续至 2028 年，26 年缺口率达 81%]
- **事件**：[先用一句客观事实概括本话题。若只有一个事件，直接用完整段落展开；若同一主题包含多个相关事件，必须按以下格式分点，不得堆在一个长段落里：]
  - **（1）[事件主体/简短事实标题]**：完整陈述该事件、关键数字与条件。
  - **（2）[事件主体/简短事实标题]**：完整陈述另一项相关事件、关键数字与条件。
  [每点只讲一个事件，但必须使用完整、流畅的专业句子，禁止碎片化、电报式短语。无共同主逻辑的事件应拆成不同热点话题。]
- **投资观点与推演**：按机构分条总结券商观点，每条为该机构观点的消化提炼（一句结论 + 支撑逻辑），格式：
  - **（1）[机构名]观点**：...
  - **（2）[机构名]观点**：...
  **要求文笔流畅、逻辑连贯，禁止原话机械搬运；目标价、盈利预测等信息跟随对应机构条目。**
- **核心个股**：
  - **[个股A名称]**：结合原文提炼出该个股的具体逻辑，切忌只写名字不写逻辑。
  - **[个股B名称]**：...

### 热点话题2: [主体+具体进展的一句话标题；一个话题只讲一条主逻辑]
...
```

低频但有明确基本面变化的线索，在该板块下设 `### 值得关注的独立线索`，或由主 Agent 收入文末 `## 附录：未纳入主线但值得关注的线索`，绝对不能丢弃。

## 输出目录与文件保留规则

全面版运行产物必须放在**独立运行目录**：

```markdown

```

默认保留：

```markdown
outputs/YYYY-MM-DD-券商全面版日报/板块底稿/科技.md

outputs/YYYY-MM-DD-券商全面版日报/板块底稿/制造.md
```

除非用户明确要求调试，否则不要额外落盘原始抓取 JSON、全量 ID 清单等中间文件。行业抓取账本、去重清单、覆盖审计作为运行中内部检查，**结论不要写入最终日报**。

## 执行步骤

### 0. 主 Agent：初始化

1. 确认报告日期（用户指定或默认当天，时区按业务常用口径，通常 `Asia/Shanghai`）。
2. 创建运行目录、`板块底稿/`，以及可选的 `行业底稿/`。
3. 先读 `research_query` schema（及必要时 `searchAnalystComments`）。
4. 按映射表摊平全部 `industryName`，**并行**启动行业 Subagent（见下一步）。同一大板块下禁止串行扫行业。

### 1. 按一级行业并行抓取（板块内禁止串行）

**并行粒度 = `industryName`，不是「一个大板块一根绳子串完」。**

推荐实现（全面版）：

1. 主 Agent 把七大板块映射表里的全部 `industryName` **摊平**。
2. 使用 Task / subagent，**一次并行**拉起行业 Subagent（每个只负责一个 `industryName`）。数量多时可分批并行，但同一大板块下的行业不得改成串行队列。
3. 每个行业 Subagent 任务说明必须包含：日期、所属大板块、唯一 `industryName`、输出路径（如 `outputs/.../行业底稿/电子.md`）、本文件写作规范、`research_query(type=comment)`。
4. 全部（或该批）行业完成后，主 Agent **按大板块归属合并**为七份 `板块底稿/[板块].md`，再进入补漏与终稿拼接。

若仍采用「7 个板块协调任务」：每个板块协调任务拿到行业列表后，**必须再并行拉起其下属行业 Subagent**，禁止在一个板块任务里 `for` 循环串行查完电子再通信再计算机。

### 2. 行业 Subagent → 板块合并规范

#### 2.1 单个行业抓取（每个行业 Subagent）

只查自己的一个 `industryName`：

- `type=comment`
- `industryName=[该一级/特色行业名]`
- `startTime=YYYY-MM-DD 00:00:00`
- `endTime=YYYY-MM-DD 23:59:59`
- `pageSize=100`
- `page` 从 1 递增，直到返回 `<100` 条或暂无数据

写出该行业成文底稿（总览要点 + 话题三件套 + 条目处理清单）。维护内部抓取账本（默认不落盘）：

```markdown
| 板块 | industryName | 页码 | 返回条数 | 是否已提炼 | 备注 |
|---|---|---:|---:|---|---|
```

#### 2.2 板块内去重（主 Agent 合并时）

同一点评可能打多个行业标签，合并进同一大板块时先去重。优先级：

1. 数据 ID / 唯一键（若返回中有）
2. 否则 `标题 + 机构 + 发布时间`
3. 再否则内容前 80 字指纹

去重后进入提炼，不要同一条点评在同一板块重复展开。

#### 2.3 聚合成板块文档

- 不要把该板块所有原文一次性塞进上下文后直接写终稿。
- 以各行业底稿为输入，聚合成最终板块文档。
- 必须区分 **事件（客观事实）** 与 **投资观点与推演（卖方主观）**。
- 两者的具体写法必须遵守 [writing-standards.md](writing-standards.md)：事件只写可核实事实；同一主题有多个相关事件时按（1）（2）（3）分点，每点控制关键数字，只做同比/对照换算，不做解读。观点段忠实总结券商的因果链与分歧（结论→路径→前提，全部有原文出处），禁止原话串联，也禁止掺入券商没说过的判断。
- 主题聚类在板块内部完成；**一个热点话题只讲一条主逻辑**。同一主逻辑下的多个相关事件保留在一个话题内，但「事件」必须按（1）（2）（3）分点；没有共同主逻辑的事件必须拆成两个话题。
- 话题标题按 [writing-standards.md](writing-standards.md) 命名规则写成「主体 + 具体进展/量级」（如「InP 衬底紧缺持续至 2028 年，26 年缺口率达 81%」），禁止「行业景气」「XX 涨价」等言之无物的名词短语。

#### 2.4 写入板块底稿文件

主 Agent（或板块合并步骤）写出完整可读的板块文档，结构建议：

```markdown
# [板块名] 板块底稿（YYYY-MM-DD）

## 板块抓取说明
- 查询行业列表：...
- 各行业返回条数：...
- 去重前/后条数：...
- 空结果或报错行业：...

## 板块总览
（按 [writing-standards.md](writing-standards.md) 的总览规范写成有主次、有承接的内容摘要：覆盖本板块所有重要讨论，每个主要话题至少说清“发生了什么 + 券商怎么理解”；禁止只罗列话题名）

## 正文
### 热点话题1: ...
（事件 / 投资观点与推演 / 核心个股；不要原文点评摘录；不要一级主线汇总层）

### 值得关注的独立线索
...

## 本板块条目处理清单
| 序号 | 标题 | 来源 industryName | 去向 | 涉及个股 | 关键数字是否保留 | 备注 |
|---|---|---|---|---|---|---|
```

`去向` 只能填：`热点话题` / `独立线索` / `附录线索` / `噪音/不保留`。

**底稿正文也要干净**：若本板块只是次归属（如铜加工在周期侧出现、主线其实在科技），不要在热点话题标题或事件/观点段里写「主归属建议科技」「与科技交叉，周期侧保留映射」等话；应在处理清单「备注」列标注「建议主归科技，本板块可不展开」，正文要么不写该话题，要么只写本板块独有的产业事实（仍禁止工程话术）。主 Agent 拼接时按备注删除次归属副本。

质量红线与行业版/旧全面版相同：数字、订单、公司进展不得在压缩中丢失；禁止「有望受益」式空话。

### 3. 主 Agent：全量补漏（必须做）

仅按 `industryName` 并行抓取会漏掉**无行业标签**或标签异常的点评。主 Agent 在七份底稿完成后必须：

1. 再跑一遍**不带** `industryName` 的当日全量 `research_query`：
   - `type=comment`
   - 同日 `startTime` / `endTime`
   - `pageSize=100`，持续翻页
2. 建立内部「全量 ID/指纹集合」。
3. 与七份板块底稿已覆盖集合做差，得到「未覆盖列表」。
4. 对未覆盖列表逐条判断：
   - 有明确产业事实 → 补入最合适板块正文/独立线索，或写入「其他」
   - 纯噪音/重复转发 → 记入噪音并说明原因
5. 覆盖统计（全量条数、板块覆盖条数、补漏条数、噪音条数、仍存疑条数）仅作内部检查，**不要写入最终日报**。

可用 `searchAnalystComments` 做少量语义补充，但**不得**替代按行业结构化抓取与全量补漏。

### 4. 主 Agent：跨板块去重并拼接

1. **阅读**全部 `板块底稿/*.md`（必要时回看补漏原文），禁止只 `cat` 拼接。
2. **跨板块去重（内部操作，禁止写进终稿）**：
   - 同一事件/个股出现在多个板块时，选定**主归属板块**完整展开；
   - **次归属板块直接删除该话题**，不要在终稿里留占位标题、空话题，也不要写交叉说明；
   - 主归属优先：更贴近核心产业链的板块（如光伏主归制造而非周期；半导体主归科技；原奶主归消费；霍尔木兹/油价地缘叙事主归其他）。
   - **绝对禁止**把去重过程写成终稿文字。下列表达一律不得出现：
     - 「跨板块去重说明」「交叉引用」「主归属见××板块」「详见【科技】/【消费】…」
     - 「与科技交叉，周期侧保留××映射」「××侧不重复展开」「制造侧映射，主归属建议科技」
     - 「此处仅作交叉备注」「产业细节主归属××」「本板块仅保留总量层」
   - 去重决策只留在主 Agent 内部思考或底稿处理清单；读者看到的只能是干净的研究正文。
3. **写今日总览**：综合七板块，并严格执行 [writing-standards.md](writing-standards.md) 的「今日总览」规范：
   - 每个板块覆盖所有重要讨论，使读者只看总览也不会漏掉当天主要内容；低信息量边角线索不进入总览；
   - 每个板块通常写 3–5 句，采用「总起 → 按重要性展开 2–4 个话题 → 必要时归纳共识/分歧」的结构；
   - 每个主要话题至少说明「发生了什么 + 券商怎么理解」，禁止只把正文话题标题缩短后用分号串联；
   - 话题之间用验证、传导、对比、分歧或补充关系自然承接；关键数字与公司名只保留理解结论所必需的少数内容；
   - 所有判断必须来自当日券商点评，不得由主 Agent 自行添加；
   - 对齐 `comprehensive-example.md` 的「一、今日总览」风格。
4. **按固定顺序拼接板块详析**：科技 → 周期 → 制造 → 消费 → 医药 → 金融 → 其他。  
   （若示例为其他展示顺序，以示例骨架为准，但七块都必须出现；无内容的板块写「当日该板块映射行业下无足够信息量的点评」并保留标题。）
5. **汇总独立线索 / 附录**：各板块独立线索可保留在板块内；跨板块附录统一放到文末。
6. 使用 `Write` 写入：

```markdown
outputs/YYYY-MM-DD-券商全面版日报/YYYY-MM-DD-券商全面版日报.md
```

### 5. 覆盖校验（完成前必做，但不写入终稿）

默认不单独写 `coverage_audit.md`，也**不要**在最终日报末尾输出「生成说明 / 覆盖校验摘要 / 使用说明」。校验只作为主 Agent 内部质检。

| 序号 | 审计项目 | 检查方法 | 通过标准 |
|:---:|:---|:---|:---|
| 1 | 板块底稿完整性 | 检查 `板块底稿/` 七个文件 | 七个板块文件均存在且含抓取说明 |
| 2 | 行业映射执行 | 核对各底稿「查询行业列表」 | 映射表内行业均已查询或有空结果/报错备注 |
| 3 | 板块内去重 | 抽查同标题是否重复展开 | 同板块无重复正文 |
| 4 | 跨板块去重 | 抽查高频个股/事件 | 主归属清晰，无大段重复 |
| 5 | 全量补漏 | 全量集合 − 板块覆盖集合 | 未覆盖已处理或标明噪音原因 |
| 6 | 正文结构 | 对照示例三件套 | 事件/观点/个股齐全；无一级主线汇总层；无原文点评摘录；行文流畅 |
| 7 | 高频个股逻辑 | 出现多次的个股 | 有具体逻辑，非点名 |

校验失败则回到步骤 3/4 补充，直到通过。

## 质量红线

- **细致程度**：原文中的产量、提价幅度、订单金额等数字必须保留。
- **不遗漏**：只出现一次但有具体业务进展的公司，也要进热点或独立线索。
- **映射优先**：全面版的数据切分以申万/特色 `industryName` 为准，不以模型临场感觉重切全量池。
- **并行可合并**：七份底稿是中间产物；最终日报必须是主 Agent 审阅拼接后的单一完整文档。
- **补漏不可省**：没有全量补漏与覆盖审计，不视为全面模式完成。
- **文件不污染**：默认只在独立运行目录保留 `板块底稿/` 与最终日报。
- **格式一致**：事件、投资观点与推演、核心个股三件套；禁止输出原文点评摘录；禁止板块下再套一级主线/次主线汇总层。
- **终稿干净**：最终日报不要附生成说明、覆盖校验摘要或使用说明；不要出现跨板块去重说明、主归属提示、交叉映射备注等工程化元话语。
- **行文流畅度**：完整句子，专业研报体验；禁止电报体。

**错误类型6：把去重流程写进终稿**
- ❌ 留一个空话题，下面写「跨板块去重说明：详见【消费】…」
- ❌ 「与科技交叉，周期侧保留铜加工映射」
- ✅ 选定主归属后只在该板块展开；其他板块直接删除该话题，终稿里不留任何处理痕迹

## 常见错误警示

**错误类型1：把主题词直接当 industryName**
- ❌ `industryName=半导体` / `光伏` / `白酒`
- ✅ `电子` / `电力设备` / `食品饮料`，正文再按子主题展开

**错误类型2b：大板块下串行扫行业（严重）**
- ❌ 「科技」任务里依次查完电子→通信→计算机→传媒
- ✅ 电子 / 通信 / 计算机 / 传媒 **并行**行业 Subagent，再合并为科技板块底稿

**错误类型2：七个 Subagent 各自全量抓再分类**
- ❌ 每个 agent 都 `research_query` 不带行业，再只写自己板块
- ✅ 每个 agent 只查自己映射表里的行业列表

**错误类型3：机械 cat 拼接**
- ❌ 直接把七个 md 粘成终稿，不去重、不写总览、不做补漏
- ✅ 主 Agent 阅读后去重、补漏、写总览再输出

**错误类型4：跳过全量补漏**
- ❌ 认为「行业都查过了=不重不漏」
- ✅ 无标签点评必须用全量差集补漏

**错误类型5：遗漏低频线索**
- ❌ 只写高频主线
- ✅ 非噪音线索必须进独立线索或附录
