# Company Mode (按公司总结版)

适用于：

- 用户要求只看某一家公司，或一次点名几家特定公司的券商点评
- 用户给出了明确的公司名称（如 `宁德时代`）或股票代码（如 `300750`、`sz000001` 等）
- 用户希望了解某家公司在选定时间窗内的讨论焦点、个股逻辑与情绪分歧

## 与全面版的关系

公司版与全面版**共用同一套终稿格式与写作规范**：

- 终稿骨架：`一、今日总览` → `二、热点话题详析` →（可选）`值得关注的独立线索 / 附录`
- 话题三件套：事件 / 投资观点与推演 / 核心个股（或核心个股映射）
- 观点按机构分条；不输出原文点评摘录；不附生成说明或覆盖校验摘要
- 总览写成可读摘要，覆盖该公司所有重要讨论
- 写法必须遵守 [writing-standards.md](writing-standards.md)，并参考 [comprehensive-example.md](comprehensive-example.md) 的话题与总览表达

唯一差异是**数据范围**：只抓取指定公司相关的 `comment`。单家时主 Agent 自行执行；**多家时必须并行 Subagent**，共用同一日期范围。

## 目标

围绕指定公司、在用户选定的日期范围内，生成一份与全面版同格式的 Markdown 总结。为了防止相关点评数量过多导致遗漏，必须采用“确认日期范围 → 分页处理账本 → 分页成文式底稿 → 总索引去重聚类 → 跨页二次总结 → 覆盖审计（仅内部）”流程：

1. 确认公司标识，并**引导用户选择日期范围**（未指定则先问再抓）
2. 确认搜索策略并分页抓取，建立内部账本
3. 逐页提炼并生成分页成文式底稿
4. 提取公司维度的总索引，梳理最重要的事件、催化、分歧
5. 按全面版终稿格式输出结构化文档，并完成内部覆盖校验

## MCP 能力确认与工具选择

已确认 `user-comein-brm` 提供了两种相关搜索能力：

1. **结构化搜索工具 (`research_query`)**：
   - 适用于**已知具体股票代码**的精准搜索。
   - 参数：`type="comment"`，`stockCode=[股票代码]`。
   - 能非常精准地把带有该个股标签的所有点评、快评及相关新闻提取出来。
   
2. **自然语言搜索工具 (`searchAnalystComments`)**：
   - 适用于**只知道公司名称或事件模糊描述**时的语义搜索。
   - 参数：`query=[自然语言问题，如"宁德时代近期的分析师点评"]`。
   - 基于向量数据库，适合泛搜包含某个公司名字的讨论。

## 股票代码入参的标准化处理（核心要求）

**极其重要：用户提供的股票代码格式可能不规范，你必须具备极强的纠错和猜想能力！**

如果用户只给了一个疑似股票代码的输入，你必须基于以下规则尝试猜测和转换，切忌直接报错：

- **正常范例**：`300750` 或 `sz300750` 或 `sh600519`
- **常见的用户不规范输入及你的应对策略**：
  - 用户输入 `sz.007890` -> 你需要识别出关键的6位数字 `007890`，并转换为 `sz007890` 或直接传 `007890` 给工具。
  - 用户输入 `007890sz` -> 转换为 `sz007890` 或 `007890`。
  - 用户输入 `600519.SH` -> 转换为 `sh600519` 或 `600519`。
  - 用户输入 `007890.XSHE` -> 提取 `007890`。

**交互范例**：
如果用户输入了奇奇怪怪的格式，在回复总结前，你可以顺便提一句：
> “您提供的代码格式是 `sz.007890`，我已自动将其识别为标准的股票代码 `007890` 并为您检索到了以下点评内容。下次您也可以直接输入如 `007890` 这样的 6 位纯数字代码哦。”

## 日期范围确认（进入本模式后必做）

公司版点评量可能跨很多天，**不要默认 silently 只查今天**。在抓取前必须确认时间窗：

1. 用户已明确给出日期或区间（如「今天」「8 月 4 日」「近一周」「2026-07-01 到 2026-08-05」）→ 直接采用，并向用户复述将使用的起止日。
2. 用户未给日期 → **先询问再抓取**，话术示例：

> 已确认公司：`[公司名/代码，可多家]`。请选择点评日期范围：
> - 今天
> - 近 3 天
> - 近 7 天
> - 近 30 天
> - 自定义：请直接给起止日期（如 `2026-07-01` 至 `2026-08-05`）

3. 将选择换算为 `startTime` / `endTime`（单日用当天 `00:00:00`–`23:59:59`；多日用首日 00:00:00 至末日 23:59:59）。
4. `searchAnalystComments` 同步传入对应 `start_time`（起始日）。
5. 用户说「你定 / 默认」时，默认 **近 7 天**，并在开抓前用一句话告知。
6. **多家公司共用同一日期范围**；先定时间窗，再并行开抓，不要每家公司分别再问一遍日期（除非用户主动要求不同区间）。

## 多公司并行（强制）

当用户一次点名 **≥2 家** 公司/代码：

1. 先完成代码清洗与日期范围确认。
2. **一次并行**启动与公司数相同的 Subagent；每个只负责一家公司，按本文单公司流程写完该公司文档。
3. 主 Agent **不得**串行「先做宁德再做比亚迪」。
4. 产出分目录：`outputs/...-券商公司版日报-[公司A]/`、`...-[公司B]/`；全部完成后主 Agent 可用一小段对照摘要汇总（可选）。
5. 对用户不暴露 Subagent 实现细节。

## 输出目录与文件保留规则

按公司总结版运行产物必须放在**独立运行目录**中，避免污染 skill 本身的项目文件。

- 单日：`outputs/YYYY-MM-DD-券商公司版日报-[公司名或代码]/`
- 多日：`outputs/YYYY-MM-DD至YYYY-MM-DD-券商公司版日报-[公司名或代码]/`（起止日）

该目录下默认只保留以下文件，不额外落盘内部账本、索引和审计记录（除非用户明确要求调试）：

```markdown
.../分页底稿/page-001.md
.../分页底稿/page-002.md
.../[日期或区间]-券商公司版日报-[公司名或代码].md
```

## 执行步骤

### 1. 确认公司与日期范围后再全量分页抓取

- 先完成上一节的**日期范围确认**，未确认不得开抓。
- **如果用户提供了股票代码**（即使格式不规范）：优先清洗提取出 6 位数字代码（或带纯字母前缀的标准代码），调用 `research_query`，设置 `type="comment"`, `stockCode=[提取出的代码]`, 以及确认后的 `startTime` / `endTime`。
- **如果用户仅提供公司名称**：先尝试直接将名称包装在自然语言问题里，调用 `searchAnalystComments`，`query="[公司名]在指定期间的分析师点评"`，并传 `start_time`；如果有能力获取公司代码，再补充使用 `research_query`（同样带时间窗）交叉检索。

对于支持分页的工具（如 `research_query`），设置 `pageSize=100`，持续翻页到 `<100条` 或 `暂无数据`。

**必须建立分页处理账本**，但默认不单独落盘。账本作为运行过程中的内部清单维护，用于确保每一页都被抓取、阅读并生成分页底稿。

### 2. 分页成文式底稿

不要把所有原文一次性塞进上下文后直接写正文。每一页必须先生成**分页成文式底稿**，写入独立运行目录下的 `分页底稿/page-00x.md`。

分页底稿必须包含：

- **本页总览**（按 [writing-standards.md](writing-standards.md) 总览规范写成可读摘要）
- **本页热点话题**（格式对齐全面版：事件 / 投资观点与推演 / 核心个股映射；不要原文点评摘录；不要一级主线汇总层）
- **本页全量条目处理清单**（确保不重不漏）

`去向` 只能填：`热点话题` / `独立线索` / `附录线索` / `噪音/不保留`。

### 3. 建立公司内总索引与去重聚类

所有分页成文底稿完成后，先基于全部 `分页底稿/page-xxx.md` 生成总索引，内部维护不落盘。
将返回的 comment 按引发讨论的 **具体话题 / 事件** 聚类。
提取字段建议：

```markdown
| 时间 | 机构 | 标题 | 热点话题 | 核心事实 | 投资观点/分歧 | 核心个股映射 | 保留层级 | 正文去向 |
```

话题命名遵守 [writing-standards.md](writing-standards.md)（主体 + 具体进展/量级，一事一题）。

排序优先级：
1. 专门深度点评该公司的内容
2. 包含该公司重要催化/订单/涨价的行业报告
3. 宏观或行业总结中带了一笔该公司的名字（权重较低，可放入附录或简写）

### 4. 基于总索引输出日报与覆盖校验

依据内部总索引及所有分页底稿生成最终文档，路径遵循上文输出目录规则。

终稿结构必须与全面版对齐；标题与总览随日期范围微调：

```markdown
# [日期或起止日] [公司名/代码]券商公司版日报

## 一、今日总览
（单日可写「今日」；多日改为「期间总览」或在首句标明覆盖的起止日期。覆盖该时间窗内该公司所有重要讨论；写法遵守 writing-standards.md「今日总览」）

## 二、热点话题详析

### 热点话题1: [主体+具体进展的一句话标题，如：储能容量电价落地带来额外收益]
- **事件**：[先用一句客观事实总起。只有一个事件时用完整段落；若同一主题涉及多项相关事件、订单、涨价、政策或财务进展，按下列格式分点，不要堆成一个长段落。]
  - **（1）[事件主体/简短事实标题]**：完整陈述该事件、关键数字和条件。
  - **（2）[事件主体/简短事实标题]**：完整陈述另一项相关事件、关键数字和条件。
  [每点只讲一个事件；无共同主逻辑的事件应拆成不同热点话题。]
- **投资观点与推演**：按机构分条：
  - **（1）[机构名]观点**：...
  - **（2）[机构名]观点**：...
- **核心个股映射**：若点评中该公司与竞品、上下游被对比提及，写清该公司的业务卡位与比较优势；若仅讨论本公司，可写本公司逻辑。

### 热点话题2: ...

### 值得关注的独立线索
...

## 附录：未纳入主线但值得关注的线索
（可选；无则省略）
```

覆盖审计只做内部质检，**不要**写入终稿。终稿不要附「使用说明 / 生成说明 / 覆盖校验摘要 / 原文点评摘录」。

## 质量红线

- **必须具备极强的股票代码容错与清洗能力**，不要因为用户输入了 `sz.300750` 就直接判定为 MCP 工具调用报错。
- 如果选定时间窗内查不到任何点评，直接告知用户该区间暂无关于该公司的券商点评记录，不要生编硬造；可建议扩大日期范围再试。
- 终稿开头或总览中应能看出所用日期范围，避免读者误以为是「未说明的今天」。
- 区分哪些点评是“专门深度点评该公司”，哪些只是在“宏观或行业总结中带了一笔该公司的名字”，并体现在总结权重中。
- 终稿格式、话题三件套、总览写法必须与全面版一致；写作遵守 [writing-standards.md](writing-standards.md)
