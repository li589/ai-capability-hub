# Chat Mode（闲聊 / 点评问答模式）

适用于用户不想生成完整日报，而是**围绕券商点评持续提问、追问、澄清**的场景。

## 定位

- 这是一个**可多轮交互的问答模式**，不是日报生成模式。
- 每一轮都根据用户问题，在 `comment`（券商点评/快评/段子）里检索证据，再直接回答。
- 默认**不落盘 Markdown 日报**；只有用户明确说「整理成文档 / 导出 / 写成日报」时才写入工作空间。
- 会话中保持上下文：用户说「那目标价呢」「外资怎么看」「换成铜」时，应承接上一轮实体与时间范围继续查，不要每次重开冷场。

## 触发说法

- `闲聊模式` / `问答模式` / `点评问答`
- `随便问问` / `帮我查一下点评` / `根据点评回答`
- `最近券商怎么看××` / `点评里有没有提到××`
- 用户明确表示不要日报、只要对话式回答

若用户中途说「改成全面版/行业版/公司版」，立即切换到对应模式文档，结束闲聊流程。

## 与日报模式的差异

| 维度 | 日报三模式 | 闲聊模式 |
|---|---|---|
| 目标产物 | 结构化 Markdown 日报文件 | 对话回答（可连续追问） |
| 覆盖要求 | 尽量不重不漏、全量/分页账本 | 围绕当前问题检索够用即可 |
| 结构 | 今日总览 + 热点话题三件套 | 直接答问题；必要时短列表举证 |
| 落盘 | 必须写入 outputs | 默认不落盘 |
| 工程话术 | 禁止 | 同样禁止 |

写作底线仍遵守 [writing-standards.md](writing-standards.md) 中与本模式相关的部分：

- 事实与券商观点分开说
- 不替券商发明结论
- 不输出「跨板块去重说明」等工程化元话语
- 不把处理清单、检索策略原文甩给用户（除非用户要调试）

## MCP 工具策略

优先使用 `user-comein-brm`：

1. **`searchAnalystComments`（语义检索，闲聊首选）**
   - `query`：写成完整中文自然语言问题，明确公司/事件/观点焦点
   - `start_time`：按问题类型锚定（见下）
   - `topK`：一般 10–20；证据不足再加大或换关键词重查

2. **`research_query(type=comment, ...)`（结构化补查）**
   - 已知代码 → `stockCode`（可配 `market`）
   - 已知申万一级行业 → `industryName`（不要带「行业」后缀）
   - 可用 `keywords` 做关键词模糊匹配
   - 需要时间窗时传 `startTime` / `endTime`
   - 结果多时 `pageSize` 最大 100，必要时翻页，但闲聊不要为了「全覆盖」无限翻页

检索顺序建议：

1. 先用 `searchAnalystComments` 拿最相关点评
2. 若用户给了代码/行业，或语义结果偏弱，再用 `research_query` 补查
3. 仍不够时：换同义问法、放宽时间窗、或提高 `divergenceLevel`（仅在需要产业链联动时用 `medium/high`）

## 大板块问答

用户闲聊里直接问大板块（如「科技最近有啥」「周期怎么看」）：

1. 识别为七大板块之一后，按 [comprehensive-mode.md](comprehensive-mode.md) 映射表展开下属 `industryName` 列表，**不要**把「科技」当成单个 `industryName` 去查。
2. 列表 ≥2 个一级行业时：**必须并行**行业 Subagent 分头检索要点（科技 → 电子/通信/计算机/传媒同时跑），主 Agent 再合成回答；禁止一个对话回合里串行查完再答。
3. 回答按话题组织即可，默认不落盘；用户要「做成科技板块日报」再切换大板块精简跑。

## 多实体并行（强制）

一句话里出现 **≥2 家公司**、**≥2 个一级行业**，或 **≥2 个大板块**（如「对比宁德和比亚迪」「电力设备和电子今天怎么说」「科技和周期」）：

1. 先拆成实体列表（公司代码清洗 / 一级行业映射 / 大板块识别），时间窗统一。
2. **一次并行**启动多个 Subagent：每个实体一个，只负责检索并提炼该实体与问题相关的点评要点（短结论 + 证据，不要各自写成长日报）。大板块实体按其下属一级行业列表检索。
3. 主 Agent **禁止**串行「先查完 A 再查 B」。
4. 全部返回后，主 Agent 合并成一篇对话回答：可按实体分小节，并点出共识/分歧；对用户不提 Subagent。
5. 若实体过多（例如 >5），可先确认是否全部都要，或建议改板块/行业/公司版出文档；用户坚持则仍并行，可分批并行（每批并行若干个）。

单实体追问（「那目标价呢」）不必开 Subagent，主 Agent 直接补查即可。

## 时间范围默认

用户指定时间优先（今天 / 本周 / 8 月 4 日 / 最近三天等）→ 锚定到具体日期。

未指定时按问题类型默认：

| 问题类型 | 默认窗口 |
|---|---|
| 突发异动、为何涨跌、今日点评 | 近 7 天（可先查今天，不够再扩到 7 天） |
| 最新观点、还能买吗、目标价、评级 | 近 3 个月 |
| 业绩/财报/订单跟踪 | 近 1 年 |
| 行业格局、壁垒、长期叙事 | 近 1–3 年（先 1 年，不够再扩） |

回答开头用一句话点明检索窗口，例如：「以下基于近 7 天券商点评。」

## 多轮交互规则

1. **进入模式后保持会话态**，直到用户切换模式或明确结束。
2. 记住本轮已确认的：标的/行业、时间窗、关注焦点（价格、订单、分歧、外资等）。
3. 追问优先复用上下文；只有问题漂移到新主题时才重新定锚。
4. 用户问题含糊时，先用已有上下文给一版有用回答，再补 1 个澄清问（不要连续盘问）。
5. 可主动给 2–3 个自然追问入口，例如：「要不要看目标价分歧？」「要不要拉一下同业对比？」

## 回答写法（对话体，不是日报体）

每轮回答建议结构（可按问题裁剪）：

1. **直接结论**（1–3 句先答用户）
2. **证据要点**（2–5 条）：机构 + 关键事实/观点 + 关键数字
3. **共识 / 分歧**（若存在）
4. **边界**：点评未覆盖处明确说「检索范围内未见」，不要编造
5. （可选）**可继续问什么**

引用风格保持轻量，例如：

- 「中金（8/4）：……」
- 「高盛交易台提到……」

不要输出完整「事件 / 投资观点与推演 / 核心个股」三件套，除非用户要求「按日报话题格式展开」。

### 禁止

- 假装已经全市场穷尽（闲聊是抽样检索）
- 把内部检索计划写成「跨工具去重说明」
- 大段粘贴原文而不提炼
- 在没有点评依据时给出「我认为应该买/卖」的投资建议口吻；应表述为「卖方观点显示…」

## 执行步骤（每一轮）

1. 解析用户问题：实体（公司/行业/主题）、时间、想知道什么（事实 / 观点 / 分歧 / 个股映射）
2. 若 ≥2 个行业或 ≥2 家公司 → 走「多实体并行」；否则主 Agent 直接检索
3. 选定工具与参数并检索（或汇总各 Subagent 结果）
4. 阅读返回内容，筛出与问题直接相关的条目；丢掉噪音快讯
5. 用对话体作答；事实与观点分开
6. 若证据不足：说明不足并做一次补查或请用户收窄范围
7. 等待下一轮追问

## 何时建议切换日报模式

出现以下需求时，友善建议切换，不要硬在闲聊里写长篇日报：

- 「今天全市场/某行业做一份完整日报」→ 全面版 / 行业版
- 「把某某公司今天点评整理成日报」→ 公司版
- 「导出一份可存档的 Markdown」→ 对应日报模式，或在闲聊结论基础上按用户要求落盘

话术示例：

> 这个问题更适合做成完整日报。你要继续闲聊深挖，还是切换到【按公司总结版】/【按行业总结版】让我出一份结构化文档？

## 质量红线

- 每个关键判断尽量能指回至少一条点评来源（机构或标题级）
- 数字、目标价、评级、订单量不得张冠李戴到错误机构
- 多机构冲突时并列呈现，不要强行调和
- 用户问「有没有人看空」时，主动检索反面观点，不能只报看多
