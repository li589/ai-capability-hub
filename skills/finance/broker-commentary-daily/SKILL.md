# 券商点评总结

这个 skill 负责：

1. 判断用户要全面版、按行业总结版、按公司总结版，还是闲聊模式
2. 指向对应模式文档：日报模式完成日报；闲聊模式用点评检索持续问答

## 适用场景

- `券商段子日报`
- `段子日报`
- `卖方日报`
- `sellside晨会总结`
- `按行业热点梳理个股逻辑`
- `按某个行业总结券商点评`
- `按某家公司/股票代码追踪个股点评`
- `闲聊模式` / `点评问答` / `帮我查点评里怎么说`

## 最小通用规则

- 数据源以 `comment` 为主
- 需专业、客观地提炼产业事实（如政策落地、涨价传导、订单超预期等），并将其与券商的主观投资观点明确区分；日报模式再进行主题聚类
- **日报模式**的事件与投资观点表达必须遵守 [writing-standards.md](writing-standards.md)：一个话题只讲一条主逻辑、标题写清主体+具体进展；同一主题包含多个相关事件时，事件段必须按 **（1）（2）（3）** 分点，每点只讲一个事件，不得堆成一个长段落；无共同逻辑的事件拆成不同话题。板块/正文下直接列话题，不套一级主线汇总层；话题三件套为事件/投资观点与推演/核心个股，不输出原文点评摘录；事件只写可核实事实，观点按机构分条忠实总结券商逻辑
- 今日总览必须是正文的可读摘要：覆盖所有重要讨论，按主次和逻辑关系组织，每个话题至少说清「发生了什么 + 券商怎么理解」；禁止把话题名、数字和公司名机械堆砌
- **行业版与公司版的终稿格式必须与全面版对齐**：`一、今日总览` → `二、热点话题详析` →（可选）`值得关注的独立线索 / 附录`；话题写法、总览写法、禁止项均与全面版一致，只是数据范围不同
- **终稿禁止工程化元话语**：不得出现「跨板块去重说明」「详见【××】板块」「与科技交叉，周期侧保留映射」「主归属见××」「××侧不重复展开」等处理痕迹；跨板块去重后，次归属板块应直接删除该话题，只在主归属板块完整展开
- `comment` 里可能混有券商点评、快评、资讯、外资观点和段子，不要把它当成纯研报
- **日报模式**最终都要输出结构化 Markdown 日报，并写入本地 `.md` 文件（**输出文档保存到当前工作空间**）；**闲聊模式默认不落盘**，除非用户明确要求整理成文档
- **多实体必须并行**：用户一次问到 **≥2 个大板块**、**≥2 个一级行业** 或 **≥2 家公司** 时，主 Agent 必须按实体拆分，**并行启动多个 Subagent** 各自检索/总结，禁止串行一个个做完；全部返回后再由主 Agent 汇总。对用户只呈现合并结果，不要解释内部并行实现。细则见各模式文档。
- **已取消快速模式**。若用户要求快速版/先做一版/盘后梳理，应说明现仅支持全面版、按行业总结版、按公司总结版、闲聊模式，并请用户选择；不要再执行 `quick-mode.md`



## 脚本命令与运行环境规则

如果执行过程中需要给出或运行脚本命令，必须先区分当前环境是 `macOS`、`Windows` 还是 `Linux`：

- 实际运行命令时，只执行与当前操作系统匹配的命令。当前环境不明确时，先确认系统类型，不要盲目执行。
- 给用户提供命令示例时，按系统分别列出，至少区分：
  - `macOS / zsh`
  - `Windows / PowerShell`
  - `Linux / bash`
- 不要把 `mkdir -p`、`rm -rf`、`cp`、`mv` 等类 Unix 命令直接当作 Windows 命令；Windows 示例优先使用 PowerShell 写法，如 `New-Item`、`Remove-Item`、`Copy-Item`、`Move-Item`。
- 不要把 PowerShell 的 `$env:VAR`、反引号续行、`;` 管道习惯直接用于 macOS/Linux；macOS/Linux 示例优先使用 POSIX shell 写法，如 `export VAR=value`。
- 路径写法必须随系统调整：macOS/Linux 使用 `/`，Windows 示例使用 PowerShell 可识别的路径写法，并注意空格路径加引号。
- 如果只是写入 Markdown 日报，优先使用工具直接创建/编辑文件；只有确实需要批量目录、文件或辅助处理时，才使用脚本命令。



## 模式选择

如果用户没有明确指定模式，询问时**只介绍本技能能做什么**，用面向读者的白话，不要出现「终稿」「映射」「拼接补漏」「Subagent」等实现细节；也不要夹带「建议用某某大模型」：

> 你想用哪种方式看今天的券商点评？
>
> - **全面版**：把科技、周期、消费、医药、制造、金融等大板块尽量都梳理一遍，适合存档、想看全貌时用
> - **按大板块**：直接说「科技」「周期」「制造」等，只做你点名的大板块（可以说多个）
> - **按行业总结**：看申万一级行业（如电力设备、基础化工；说「光伏」「半导体」也可以）
> - **按公司总结**：看一家或多家公司/股票代码（如宁德时代、300750）；选好后会再问时间范围
> - **闲聊**：不用出完整日报，你直接问，我在点评里找答案，还可以接着追问

意图已很清楚时可直接进入对应模式，不必反复念菜单。

**口径区分（内部，勿对用户念实现词）：**

- **大板块**：`科技` / `周期` / `消费` / `医药` / `制造` / `金融` / `其他` → 走 [comprehensive-mode.md](comprehensive-mode.md) 的「单板块/多板块精简跑」
- **申万一级行业**：`电子` / `电力设备` / `基础化工` 等 → 走 [industry-mode.md](industry-mode.md)
- 不要把「科技」当成申万行业名去查；应按大板块展开其下属一级行业列表



### 全面模式

适用这些说法：

- `全面版`
- `最全面版`
- `全覆盖版`
- `全集版`
- `不重不漏`
- `不能有任何遗漏`
- 要求七大板块**全部**都做

执行参考：[comprehensive-mode.md](comprehensive-mode.md)。按映射表摊平全部一级行业并**并行**行业 Subagent → 主 Agent 按七大板块合并 → 全量补漏、跨板块去重 → 拼接最终日报。大板块内禁止串行扫行业。

### 大板块模式（科技 / 周期等）

适用这些说法：

- `科技板块` / `只看周期` / `做一下制造和消费`
- `今天科技怎么说`（且意图是出板块梳理，不是随口一问）
- 直接点名七大板块之一或多个：`科技`、`周期`、`消费`、`医药`、`制造`、`金融`、`其他`

执行参考：[comprehensive-mode.md](comprehensive-mode.md) 中的 **「单板块 / 多板块精简跑」**：先展开该板块下属申万一级行业列表，**按一级行业并行 Subagent**（例如科技 → 同时跑电子/通信/计算机/传媒），主 Agent 再合并成板块日报。禁止在一个任务里串行扫完行业列表。只输出用户点名的板块，不跑满七块。

若用户只是闲聊口吻问「科技最近有啥催化」且不要文档 → 走闲聊模式，但仍按大板块展开检索（见 [chat-mode.md](chat-mode.md)）。

### 按行业总结模式

适用这些说法：

- `按行业总结`
- `只看某个行业`
- `总结电力设备`
- `银行行业点评日报`
- `按申万行业筛选`

执行参考：[industry-mode.md](industry-mode.md)。先确认/映射为申万一级行业，再用 `industryName` 筛选。单个行业单线执行；**多个一级行业并行 Subagent**。若用户说的是「科技/周期」等大板块名，**不要**当行业版处理，改走大板块模式。

### 按公司总结模式

适用这些说法（意图是**出一份公司日报/总结文档**）：

- `按公司总结` / `个股点评日报`
- `把宁德时代今天的点评整理成日报`
- `搜一下300750做公司版`
- `关于某某股票的段子日报`

若只是随口问「宁德时代最近怎么看」「300750 目标价多少」且未要求日报，走闲聊模式。

执行参考：[company-mode.md](company-mode.md)。该模式必须先确认公司（代码清洗）与**日期范围**，再使用 `research_query` 的 `stockCode`（配合 `startTime`/`endTime`）或 `searchAnalystComments` 筛选总结。**终稿骨架、话题三件套、总览写法与全面版一致**。单家公司单线执行；**多家公司时并行启动多个公司 Subagent**（共用同一日期范围），主 Agent 汇总。

### 闲聊模式

适用这些说法：

- `闲聊模式` / `问答模式` / `点评问答`
- `随便问问` / `帮我查点评` / `根据点评回答`
- `最近券商怎么看××`（且未要求生成日报）
- 用户明确说不要日报、只要对话式回答或可连续追问

执行参考：[chat-mode.md](chat-mode.md)。该模式以用户问题为中心，用 `searchAnalystComments` / `research_query(type=comment)` 检索券商点评后直接作答；**保持多轮上下文**，默认不落盘；问题涉及多家公司或多个行业时**并行 Subagent 分头检索**，主 Agent 合并作答；需要完整存档日报时再引导切换全面/行业/公司模式。

### 默认规则

1. 用户明确说 `全面版`、`最全面版`、`全覆盖版`、`全集版`、`不重不漏`、`不能有任何遗漏`，或要求七大板块全部都做，直接走全面模式
2. 用户直接点名 `科技` / `周期` / `消费` / `医药` / `制造` / `金融` / `其他`（一个或多个）并要梳理/日报 → 走**大板块模式**（精简跑）；点名多个大板块则并行
3. 用户明确要求 `按行业总结`，或给出申万一级/可映射的一级行业名并要求点评日报 → 走按行业总结模式；多个一级行业则并行
4. 用户明确给出公司名或股票代码并要求做成日报/总结版 → 走按公司总结模式；未给日期范围先问；多家公司则并行
5. 用户明确要求 `闲聊`、`问答`、`查点评回答`，或提出具体问题且未要求生成日报 → 走闲聊模式；多公司/多行业/多大板块同样并行
6. 用户说 `快速版`、`快速模式`、`先来一版`、`盘后梳理`：说明快速模式已取消，请其选择模式，不要自行降级执行
7. 用户说 `你自己判断`、`你定`、`默认就行`：若像在提问查观点则走闲聊模式，否则默认走全面模式
8. 凡识别到 ≥2 个大板块、≥2 个一级行业或 ≥2 家公司，一律并行 Subagent，禁止串行轮询
9. 具体步骤见对应模式文档



## 输出目标

- **日报三模式**：最终产物是结构化日报，核心结构由模式文档定义；行业版与公司版对齐全面版终稿格式。**输出文档保存到当前工作空间。**
- **闲聊模式**：最终产物是对话回答；可连续交互；默认不落盘，除非用户要求导出。
