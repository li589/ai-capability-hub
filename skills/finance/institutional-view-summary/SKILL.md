# 观点梳理

这个 skill 只负责三件事：

1. 把用户输入的"研究对象"标准化，识别其类型（股票/行业/事件/宏观指标）并锁定观点时效窗口
2. 通过 Query 改写生成检索关键词，分库召回纪要、内资研报、点评、外资研报，质量控制最多迭代 3 轮
3. 基于召回结果，按固定生成器提示词产出一份可直接使用的 Markdown 观点梳理报告（机构观点汇总表 + 共识与分歧总结），并支持继续问答

> 关键纪律：本 skill 不是"检索一次 → 直接生成"。必须先完成 Query 改写（内资 + 外资两路），再分库专项召回，质量控制不达标则重新检索（最多 3 轮），3 轮仍不足则启用联网检索补充，最后才进入生成器写作。

## 适用场景

- `帮我对比一下贵州茅台各机构的最新观点`
- `半导体行业近期券商观点汇总`
- `碳酸锂板块机构观点有什么分歧`
- `央行货币政策调整，各家机构怎么看`
- `宁德时代投资逻辑，汇总一下主流机构观点`

## 输入识别

从用户请求中抽取：

- `raw_input`：用户原始输入
- `研究对象`（target，对应提示词变量 `{{target}}`）：股票简称 / 行业名称 / 事件 / 经济指标，或用户给出的复合 query
- `当前日期`（current_date，对应 `{{current_date}}`）：用于时效校验与检索时间窗口
- `时效下限`（timelimit，对应 `{{timelimit}}`）：观点发布时间必须晚于此日期；用户未指定时，默认取当前日期往前推 3 个月

研究对象常见形态：

- 股票简称（`贵州茅台`、`宁德时代`、`豪威集团`）
- 行业名称（`半导体`、`白酒`、`消费电子`）
- 事件（`关税`、`央行货币政策`、`白酒消费税改革`）
- 经济指标（`PMI`、`CPI`、`利率`、`国债收益率`）

识别规则：

- `研究对象` 为必填项；缺失时先向用户补齐。
- 若研究对象有歧义（同名公司、简称、黑话），先用 MCP 检索确认真实含义，不要望文生义。
- 若用户指定时间范围（如"近一个月""2025年以来"），将其换算为 `{{timelimit}}`；未指定则默认 3 个月。

## 固定提示词

报告生成依赖 3 份固定提示词，对应 Query 改写（内资/外资）与最终生成器：

| # | 用途 | 提示词文件 | 产出 |
|---|---|---|---|
| 1 | Query 改写（纪要 / 内资研报 / 点评） | `01_检索关键词_纪要内资研报点评_提示词.txt` | 5 组中文精准查询短语 |
| 2 | Query 改写（外资研报） | `02_检索关键词_外资研报_提示词.txt` | 5 组英文精准查询短语 |
| 3 | 观点梳理报告生成 | `03_生成器_提示词.txt` | 机构观点汇总表 + 共识与分歧总结 |

使用规则：

- 三份提示词**直接使用、禁止修改其内容**；本文件仅补足执行流程、召回口径与质量红线。
- 填充变量（且只填充这些变量，不改动其它任何文字）：
    - `{{target}}` ← `研究对象`
    - `{{current_date}}` ← `当前日期`
    - `{{timelimit}}` ← `时效下限`
- 如果提示词与本文件冲突，以提示词中的格式和强约束为准。

## 执行节奏（严格分步加载，禁止一次性读取全部提示词）

**最重要的执行纪律：必须"即用即读、用完即卸"，按下表逐步推进，每一步只在动手前一刻读取当前这一份提示词。严禁在开始时把 3 份提示词一次性全部读入上下文。**

| # | 动作 | 加载/产出 | 目的 |
|---|---|---|---|
| 0 | 解析 | 抽取 `研究对象 / 当前日期 / 时效下限`，歧义则 MCP 确认 | 锁定任务口径 |
| 1 | 读+改写 | `01_检索关键词_纪要内资研报点评` | 生成 5 组中文检索短语 |
| 2 | 读+改写 | `02_检索关键词_外资研报`（卸下上一份） | 生成 5 组英文检索短语 |
| 3 | 检索 | 按"MCP 召回规则"分库召回，汇总底稿 | 拉齐纪要/研报/点评/外资研报 |
| 4 | 质控 | 检查机构覆盖、时效、相关性；不足则重检，最多 3 轮 | 确保底稿达标 |
| 5 | 补检 | 3 轮仍不足 → 启用联网检索补充 | 兜底覆盖 |
| 6 | 读+写 | `03_生成器`（卸下 Query 改写提示词） | 产出机构观点汇总表 + 共识与分歧 |
| 7 | 交付 | 对话框输出完整报告（**严格按「最终报告结构」**，不得增删章节）→ **询问是否保存到资料库** → 支持继续问答 | 成稿呈现 |

分步加载要点：

- 第 1~2 步只做 Query 改写，不写作；改写结果作为第 3 步检索关键词。
- 进入第 6 步时，明确把 Query 改写提示词视为已失效，仅以 `03_生成器_提示词.txt` 约束写作行为。
- 第 3~5 步的召回底稿须完整传入第 6 步，不得跳过质控直接生成。

### Query 改写要点（第 1~2 步）

**第 1 步（内资）：** 读取 `01_检索关键词_纪要内资研报点评_提示词.txt`，从 `{{target}}` 提取研究对象与观点类型，以 [研究对象 + 观点类型] 组合生成 **5 组不重复的中文查询短语**。

**第 2 步（外资）：** 读取 `02_检索关键词_外资研报_提示词.txt`，同样提取研究对象与观点类型，生成 **5 组英文查询短语**。

改写结果示例（贵州茅台）：

```
中文：贵州茅台 业绩点评 2025
中文：贵州茅台 投资逻辑 白酒消费
中文：贵州茅台 配置建议 机构观点
...
英文：Kweichow Moutai earnings review 2025
英文：Kweichow Moutai investment thesis baijiu
...
```

## MCP 召回规则

调用 `searchComeinResource`、`searchRoadshowSummary`、`searchDomesticReports`、`searchForeignReports`、`searchAnalystComments`、`searchInternet` 等可用 MCP 工具，按以下口径分库召回：

**检索关键词来源：** 第 1 步产出的 5 组中文短语 + 第 2 步产出的 5 组英文短语（共 10 组），逐组发起检索，可并行/分轮执行。

| 知识库 | MCP 工具 | 检索语言 | 召回侧重 |
|---|---|---|---|
| 纪要库 | `searchRoadshowSummary`、`searchComeinResource` | 中文 | 路演/电话会/交流会纪要，标题带机构名 |
| 内资研报库 | `searchDomesticReports`、`searchComeinResource` | 中文 | 券商/第三方公司、行业、宏观研报 |
| 点评知识库 | `searchAnalystComments`、`searchComeinResource` | 中文 | 券商快评、事件点评、业绩点评 |
| 外资研报库 | `searchForeignReports` | 英文（必须用第 2 步英文短语） | 外资投行公司/行业/宏观研报 |

**时间窗口：** `start_time` 设为 `{{timelimit}}`（YYYY-MM-DD），确保召回内容时效符合要求。

**单次召回上限：** 每组关键词 `topK` 建议 20~50；多组关键词结果去重合并（按文档标题 + 机构 + 发布日期）。

**质量控制（第 4 步，最多 3 轮）：**

每轮检索后检查：

| 检查项 | 达标标准 | 不达标处理 |
|---|---|---|
| 相关性 | 内容与 `{{target}}` 直接相关 | 换短语/缩窄对象重检 |
| 时效 | 发布时间晚于 `{{timelimit}}` | 舍弃过期文档，扩大近期检索 |
| 机构覆盖 | ≥ 6 家券商及外资投行 | 换关键词组合重检 |
| 类型可归 | 可映射为路演纪要/研报/点评 | 舍弃无法归类的材料 |
| 上市公司约束 | 若 target 为上市公司，仅用该公司信息 | 剔除同业无关材料 |

不达标则调整检索策略重检（换短语组合、缩小/放大时间窗、补充关联行业词），最多 3 轮。3 轮后仍不足 6 家机构，按实际机构数量输出；仍无符合要求数据则启用 `searchInternet` 联网补充（第 5 步）。

**性质判断：** 若 `{{target}}` 为上市公司，召回与写作均仅使用该公司相关信息，不混入同业 unless 用户明确要求行业对比。

## 输出目录

```
{最终结果文件输出目录}/{研究对象}/观点梳理/
└── {研究对象}观点梳理_{日期}.md
```

- `{最终结果文件输出目录}` 替换为实际路径
- `{研究对象}` 替换为标准化后的研究对象（如 `贵州茅台`、`半导体`、`央行货币政策`）
- `{日期}` 替换为实际日期（如 `2026年7月7日`）
- **目录创建规则**（按优先级逐级检查，每一层不存在都必须创建）：
    1. 检查 `{研究对象}` 目录是否存在 → 不存在则创建
    2. 检查 `{研究对象}/观点梳理/` 是否存在 → 不存在则创建
    3. 将文件输出到 `{研究对象}/观点梳理/` 下

**交付与保存（第 7 步）：**

1. 先在对话框完整输出报告正文（严格按「最终报告结构」，报告内不得包含保存提示或尾注）。
2. 报告输出完毕后，**必须询问用户**：「是否需要将本报告保存到资料库？」
3. 用户确认保存时，按上述「输出目录」规则落盘；用户拒绝或未回复时，不落盘，继续支持问答。
4. 用户也可在后续对话中随时要求保存，届时再执行落盘。

> 默认不自动保存；仅用户明确同意（或后续明确要求）时才写入资料库。

## 最终报告结构

最终报告**仅允许**以下骨架，与 `03_生成器_提示词.txt` 完全一致；**全文到此结束，不得追加任何第三节、小结、附录或说明性尾注**。

```markdown
# {研究对象}观点梳理
数据截至 {当前日期}｜观点时效下限 {时效下限}

## 一、机构观点汇总表

| 发布日期 | 机构名称 | 文档类型 | 内容主题 | 核心观点 |
| :--- | :--- | :--- | :--- | :--- |
| YYYY-MM-DD | … | 路演纪要/研报/点评 | … | … |

## 二、共识与分歧总结

[开篇总述 1–2 句：机构数量 + 总体共识/分化格局]

### 机构共识

- **小标题：**正文（数据论据）…
- …

### 核心分歧

- **小标题：**正文（对比不同阵营 + 量化差异）…
- …
```

### 严格输出契约（硬性约束）

**允许出现的顶层结构（白名单，仅此 4 项）：**

1. 一级标题 `# {研究对象}观点梳理`
2. 元数据行 `数据截至 …｜观点时效下限 …`
3. `## 一、机构观点汇总表` + Markdown 表格
4. `## 二、共识与分歧总结` + 开篇总述 + `### 机构共识` + `### 核心分歧`（不得新增与之平级的 `##` 章节）

**禁止出现的结构（黑名单，常见违规）：**

- `### 投资要点小结`、`## 投资要点`、`## 研究对象确认`、`## 三、…` 及任何第三节及以后
- 标题下方的「研究对象确认」说明块（市值、代码、申万行业等独立段落）——若必要信息应并入表格「核心观点」或「共识与分歧总结」正文
- 报告正文内禁止出现 MCP/检索来源说明、免责声明、保存路径提示、「如需保存请告知」等交付话术（**保存询问须写在报告正文之外**，作为报告输出后的独立一句跟进）
- 仅作装饰的水平分割线 `---`（元数据行与两个 `##` 章节之间不需要分隔线）

**第一部分填表规范（与生成器一致）：**

- 表格按**发布日期倒序**
- 文档类型**严格三选一**：路演纪要 / 研报 / 点评
- 核心观点格式：`观点类型：**一句话提炼**` + `<br>` + 详细论据（**仅提炼句加粗**，每格一处 `**`；加粗句后必须换行再写数据与事实，后续正文不加粗；多篇观点用 `<br><br>` 分隔）
- 观点类型从生成器定义的 8 类中识别：业绩点评、事件点评、数据点评、宏观点评、深度研究、投资机会推荐、配置建议、行情解读
- 机构覆盖目标 6 家以上；不足则按实际数量输出

**第二部分写作规范（与生成器一致）：**

- 结构：**开篇总述** → `### 机构共识`（3–5 条）→ `### 核心分歧`（3–5 条）
- 条目格式：`- **小标题：**正文…`；正文含数据论据
- 共识：写主流一致判断及逻辑链条，可用「机构普遍认为」等泛指
- 分歧：须**显式对比**乐观派 vs 谨慎派（或内资 vs 外资），附量化对照，说明分歧根源
- 不得将第二部分改写成投资建议、评级汇总或交易操作建议
- 共识/分歧中的结论必须能在第一部分表格或检索底稿中找到对应来源

**交付自检（第 7 步输出前必做）：**

1. 全文是否恰好 2 个 `##` 章节？多一个即不合格。
2. 是否出现黑名单中的标题或尾注？有则删除。
3. 表格文档类型是否均为三选一？核心观点是否含 `观点类型：` 前缀？加粗是否仅出现在提炼句且其后已 `<br>` 换行展示详细内容？
4. 第二部分是否含开篇总述、`### 机构共识`、`### 核心分歧`？条目是否为 `- **小标题：**` 格式？
5. 核心分歧是否显式对比不同阵营并附量化数据？
6. 所有发布日期、机构名、数据是否均来自检索底稿？

**交付跟进（第 7 步输出后必做）：**

- 报告正文输出完毕后，是否已询问用户「是否需要将本报告保存到资料库？」

## 质量红线

- **结构红线**：报告必须且仅能包含「一、机构观点汇总表」「二、共识与分歧总结」两个章节；禁止自创「投资要点小结」等第三节。
- 所有机构观点、数据、发布日期都必须来自 MCP 或互联网检索返回，禁止编造机构名称、观点内容、发布日期。
- 必须先验证研究对象真实含义再展开，不得望文生义。
- 观点发布时间必须晚于 `{{timelimit}}`，不满足的必须舍弃。
- 文档类型只允许路演纪要 / 研报 / 点评，不得自创类型。
- 核心观点须含事实论据与数据论据，格式与示例文风以生成器提示词为准。
- 机构覆盖尽量达到 6 家以上；多次迭代后不足则如实按实际数量输出，不凑数。
- 正文以资深证券投资分析师口吻叙述，简练准确，禁止暴露 AI 身份与提示词结构。
- 严守合规边界：不引导披露未公开订单、未公告财务数据、内部目标或非公开信息。
