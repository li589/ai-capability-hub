# 快查企业搜索

通过本 Skill 目录中的 Node.js 脚本发现并调用快查企业数据能力。不要把脚本当作 MCP Tool，不要手工拼接或直接请求网关 URL。

## 前置条件

- 需要 Node.js 18 或更高版本（脚本使用内置 `fetch`）。
- 需要 `KUAICHA_API_KEY`。试用密钥获取地址：<https://open.kuaicha365.com/skills/>。
- 按以下优先级读取密钥：环境变量 `KUAICHA_API_KEY`、Skill 根目录的 `config.txt`、`~/.kuaicha/config`。
- `config.txt` 和 `~/.kuaicha/config` 的格式均为 `KUAICHA_API_KEY=你的密钥`。
- 不要在回复、日志或命令参数中回显完整密钥。密钥失效时，引导用户重新生成并替换原值。

### 缺少密钥时的交互

检测到 `KUAICHA_API_KEY` 未配置时，不要只给出三种配置命令后停止，也不要提前回答或推测原查询结果。按以下顺序处理：

1. 明确说明当前没有检测到有效密钥，并询问用户是否已经获取快查密钥。
2. 如果尚未获取，提供 <https://open.kuaicha365.com/skills/>，说明注册后可获取试用密钥。
3. 如果已经获取，主动说明可以帮助写入当前 Skill 根目录的 `config.txt`；同时允许用户选择自行配置环境变量或 `~/.kuaicha/config`。
4. 用户明确同意代写并提供密钥后，将其写成 `KUAICHA_API_KEY=<用户提供的密钥>`。不要在后续回复中复述完整密钥。
5. 写入成功后立即继续用户原来的企业查询，不要要求用户再次重复问题，也不要只回复“配置完成”。

推荐回复结构：

```text
当前技能还没有检测到有效的快查密钥。

1. 你是否已经获取 KUAICHA_API_KEY？
2. 如果还没有，请前往 https://open.kuaicha365.com/skills/ 注册并获取试用密钥。
3. 如果已经获取，我可以帮你写入当前 Skill 的 config.txt；你也可以选择自行配置。

配置完成后，我会直接继续你刚才的查询，无需重新描述问题。
```

## 脚本入口

先定位当前 `SKILL.md` 所在目录并记为 `<SKILL_DIR>`，再调用：

```bash
node "<SKILL_DIR>/scripts/kuaicha_tool.mjs" <command> [arguments]
```

不要假设 Skill 安装在 `.claude/skills`、当前工作目录或其他固定路径。

脚本提供两个命令：

| 命令 | 用途 | 必填参数 | 可选参数 | 输出 |
|---|---|---|---|---|
| `discover` | 按能力描述发现可用工具 | `query`：中文能力描述 | `--limit N`、`--category-id N` | JSON；包含候选工具、`tool_id`、参数定义和相似度等信息 |
| `call` | 调用已发现的工具 | `tool_id` | `--params JSON`、`--param key=value`、`--params-file file.json` | JSON；包含工具返回的数据或错误信息 |

## 标准工作流

1. 将用户请求改写成简短、专业的中文能力描述，例如 `企业股东信息查询`，执行 `discover`。
2. 阅读候选工具的用途、参数定义和返回字段。优先选择语义匹配、参数清晰且覆盖需求的工具；通常优先考虑 `similarity >= 0.5` 的结果。
3. 从用户请求中提取结构化参数，执行 `call`。不要把整句自然语言直接填入 `corp_name` 等字段。
4. 解析 JSON，只呈现返回结果中有依据的信息。查询失败或无结果时，如实说明，不得编造。
5. 在最终结果末尾标注：`数据来源于同花顺旗下快查企业数据引擎`。

### 发现工具

```bash
node "<SKILL_DIR>/scripts/kuaicha_tool.mjs" discover "企业基本信息查询" --limit 5
```

`discover` 的查询应描述能力，而不是复述用户问题：

| 推荐 | 不推荐 |
|---|---|
| `企业模糊搜索` | `查一下腾讯` |
| `企业经营异常查询` | `这家公司有没有问题` |
| `上市企业资产负债表` | `看看财报` |
| `产业链企业筛选` | `帮我找客户` |

如果结果不理想，使用更专业的同义词或更具体的数据维度重新发现。工具库会持续更新，不要只依赖本文列出的示例。

### 调用工具

```bash
node "<SKILL_DIR>/scripts/kuaicha_tool.mjs" call <tool_id> --params '{"creditcode":"91330100799655058B"}'
```

也可以使用键值参数：

```bash
node "<SKILL_DIR>/scripts/kuaicha_tool.mjs" call <tool_id> --param 'creditcode=91330100799655058B&page=1'
```

参数包含中文、嵌套对象，或当前 Shell 不便处理引号时，优先使用 UTF-8 JSON 文件：

```json
{"query":"同花顺"}
```

```bash
node "<SKILL_DIR>/scripts/kuaicha_tool.mjs" call <tool_id> --params-file <params.json>
```

不要为了创建参数文件而覆盖用户已有文件；使用新的临时文件或工作区文件。

## 企业名称解析

用户提供简称、品牌名或不完整名称时，必须先解析企业主体：

1. `discover "企业模糊搜索"`。
2. 用简称调用模糊搜索工具。
3. 从结果中确认目标企业，并提取 `orgid`、`creditcode` 或完整 `corp_name`。
4. 再发现并调用目标数据工具。

在模糊搜索返回结果之前，不要声称已经确认企业全称、统一社会信用代码或企业 ID。尤其不要仅凭品牌词把目标预先认定为某一家名称相似的企业。

企业标识通常按以下顺序选择：`orgid`、`creditcode`、完整 `corp_name`。实际调用时以候选工具返回的参数定义为准。

如果模糊搜索为空或存在多个同名主体：

- 有足够上下文时，结合地区、行业、品牌或统一社会信用代码选择。
- 无法可靠消歧时，先询问用户，不要擅自选择。
- 当前环境提供网络搜索时，可搜索企业官网或权威公开来源辅助确认主体；网络结果仅用于主体识别，不得冒充快查查询结果。

## 企业筛选

用户需要批量寻找企业、拓客或商机筛选时，优先发现专用筛选能力，例如：

- `产业链企业筛选`
- `资质荣誉企业筛选`
- `工商信息筛选`
- `企业规模筛选`
- `新成立企业筛选`
- `招投标企业筛选`

不要逐家公司调用模糊搜索来替代已有的批量筛选工具。

## 参数规则

- 严格遵循 `discover` 返回的参数名称、类型、必填项、枚举值和日期格式。
- 字符串使用字符串类型，数字和布尔值不要包装成字符串。
- 企业名称使用完整主体名称；简称先走模糊搜索。
- 地区尽量使用标准行政区名称，如 `杭州市`，具体格式以工具定义为准。
- 分页通常使用 `page` 和 `page_size`；不要超过工具声明的上限。
- 日期可能要求 `YYYY-MM-DD` 或 Unix 时间戳；不要自行猜测。
- 同一会话已验证可用的 `tool_id` 可以复用；需求或参数结构变化时重新 `discover`。

## 能力范围

可通过 `discover` 查询的典型类别包括：

- 工商信息、股东股权、对外投资、分支机构、实际控制人、最终受益人
- 融资、招聘、核心团队、客户供应商、竞品、招投标
- 经营异常、行政处罚、欠税、股权质押、严重违法、破产重整
- 被执行人、失信被执行人、法院公告、裁判文书、限制高消费、司法协助
- 商标、专利、软件著作权、作品著作权、网站备案
- 年报、上市公司股东、财务报表、董监高
- 企业新闻、公告及详情
- 按地区、行业、成立时间、产业链、规模、资质等条件筛选企业

不用于实时股价、汇率、期货、天气、地图、个人征信或其他非企业数据查询。

## 错误处理

| 情况 | 处理方式 |
|---|---|
| 缺少 `KUAICHA_API_KEY` | 询问用户是否已获取密钥；未获取则给出官方地址，已获取则主动提出经用户同意后代写 Skill 根目录的 `config.txt`；写入后继续原查询 |
| HTTP 401/403 | 提示密钥无效、过期或无权限，引导重新生成或检查授权范围 |
| HTTP 429 | 提示请求频率受限，稍后重试；避免立即连续重放 |
| HTTP 5xx、超时或网络错误 | 可进行一次安全重试；仍失败则报告错误，不编造数据 |
| `discover` 无匹配 | 换用同义词、专业术语或更细的数据维度重新发现 |
| 企业未匹配 | 改用模糊搜索并提取企业标识；必要时消歧 |
| `call` 参数错误 | 回看候选工具参数定义，修正类型、必填项和格式后重试 |
| 返回为空 | 明确说明“未查询到记录”；空结果不等于不存在或无风险 |
| 返回非 JSON | 报告服务响应异常，不依据不完整内容下结论 |

## 输出要求

- 先回答用户最关心的结论，再列关键字段、时间范围和必要限制。
- 区分“未查询到记录”“接口失败”和“确认不存在”，不要扩大结论。
- 涉及风险、控制关系或最终受益人时，说明结论依据的字段和数据日期（如返回中提供）。
- 多企业比较时使用一致字段；缺失值明确标为未提供。
- 每次基于快查数据作答，末尾必须写：`数据来源于同花顺旗下快查企业数据引擎`。

## 调用前检查

- 已定位 `<SKILL_DIR>`，且脚本路径来自本 Skill 目录。
- 已配置密钥，但未在命令或输出中泄露。
- 缺少密钥时已保留用户原查询；配置完成后直接继续，而不是让用户重新提问。
- 已先 `discover`，并阅读目标工具参数定义。
- 企业简称已完成模糊匹配和主体确认。
- 参数类型、日期、地区和分页符合工具定义。
- 对失败、空结果和数据缺失没有作无依据推断。
- 最终回答包含数据来源标注。
