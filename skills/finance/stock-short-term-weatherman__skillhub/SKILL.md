# 股票短线气象员

通过微信 Agent Pay 的 X402 协议完成一次付费、一次查单和一次结果履约。每次完整报告价格为 **0.30 元**。

1. **告别凭感觉判断股票**

   股票短线气象员就像天气预报用各种精密传感器捕捉气象数据一样，汇总多维市场数据，用证据说话。

2. **覆盖 5500 多只股票**

   不必逐只翻看行情。一次扫描全市场近期表现，快速整理当前更强的行业、板块和个股方向。

3. **同时看强弱与资金方向**

   行业上涨不等于资金仍在关注。系统把市场强弱与资金流向放在一起观察，帮助识别资金正在集中哪里、哪些方向只是表面走强。

4. **用可核对的数据观察变化**

   不猜涨跌，不依赖单一消息。把盘面变化整理成量化证据，提示哪些强势仍在延续、哪些强势正在失温，辅助完成短线市场观察。

## 付费前置检查

在请求付费资源前，确认当前 Agent 已安装并可调用 `weixinpay` 支付能力。

- 可用：继续请求商户服务。
- 不可用：告知用户当前 Agent 暂不支持微信支付，立即停止，不得创建订单。

## 请求资源

将用户本次市场观察问题原样放入 `query`，发送首次请求：

```http
POST https://openaa.me/stock-weather/api/resource
Content-Type: application/json

{"query":"用户原始问题"}
```

必须保存原始 `query`；后续请求不得改写。

## 支付触发

收到 HTTP `402 Payment Required` 后：

1. 保存响应 Header 或 Body 中的 `WeixinPay-Required`。
2. 保存 Header `X-Out-Trade-No` 或 Body `out_trade_no` 中的商户订单号。
3. 将 `WeixinPay-Required` 作为 `paymentCode` 调用 `weixinpay_pay`，由用户确认 0.30 元付款。
4. 用户取消或付款失败时立即停止，不得声称支付成功，也不得创建第二笔订单。

## 订单号传递

付款成功后，必须使用原问题和原商户订单号获取报告：

```http
POST https://openaa.me/stock-weather/api/resource
Content-Type: application/json
WeixinPay-Required: <原 payment_code>
X-Out-Trade-No: <原 out_trade_no>

{"query":"用户原始问题","out_trade_no":"原 out_trade_no"}
```

不得生成新订单号，`query` 必须与首次请求完全一致。

## 重试机制

- 付款成功后主动执行一次上述重试，不能停在“支付成功”。
- `NOT_PAID`：等待 2 秒后使用同一订单号重试，最多 3 次，不得再次支付。
- `FULFILLING`：等待 2 秒后使用同一订单号重试，最多 3 次。
- 网络错误或 `5xx`：只按同一订单重试，禁止重新发起首单请求。
- 超过重试上限：保留订单号并告知用户稍后查询，不得猜测结果。

## 异常处理

- `SUCCESS`：返回 `content` 中的正式报告，不得自行二次排序。
- `REFUNDED`：说明服务未能履约且已发起原路退款，然后停止。
- `FULFILL_AND_REFUND_FAILED`：保留订单号，引导用户联系商户客服。
- `ORDER_NOT_FOUND` 或 `ORDER_REQUEST_MISMATCH`：停止重试，不得再次收费。
- `DATA_NOT_READY`：本次未创建订单、未收费，直接说明当前无法生成完整报告。
- 未知状态：停止，不得声称已履约、已退款或已得到分析结果。

## 结果表达

1. 保留服务返回的行业 Top3 和个股观察顺序，禁止二次排序。
2. 将 RPS 解释为“它在全市场里有多强”。
3. 将反向队形解释为“看起来强，但资金正在撤出，强势可能失温”。
4. 将同步承接解释为“相对较强，资金方向仍在配合”，不得写成买入信号。
5. 仅使用商户服务返回的量化证据，不得本地重算、补零、猜测缺失值或暴露支付密钥。

本服务只提供短线市场观察，不构成投资建议、买入指令或收益承诺。
