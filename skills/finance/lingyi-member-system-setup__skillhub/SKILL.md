# 会员体系搭建

> 版本：v0.1.0 · 作者：小风

## 目的

帮运营者把「私域沉淀用户」跑通一条可执行的链路：**等级成长 → 积分激励 → 权益配置 → 财务测算**，产出四件套（会员等级成长表、积分获取消耗规则表、权益配置矩阵、积分财务测算表），外加可选的付费会员卡子表。

这不是「一张权益清单」或「一套送分活动」，而是「先看清楚用户成长路径、行为价值、权益成本与积分负债，再决定怎么发积分、设几级、配什么权益、算不算亏本」。可以把它看作会员体系的结构化占位框架——把散在各处的感性决策，沉淀成可执行、可滚动复算的规则表与测算表。

> 核心信念（来自调研）：等级、积分、权益是「三角咬合」——等级靠成长值驱动，成长值靠积分累计，积分靠权益兑现；三者咬合才有完整会员体系，任一独立都失效。三者之上还要压一层财务约束：单积分价值、兑换率、积分负债，前三者是「设计」，财务是「兜底」——防积分通胀破产、防平台负债崩盘、防权益被反向薅羊毛。

## 输入

**最佳搭配：** 目标会员人群 + 会员运营目标（提复购？防流失？拉客单？） + 积分预算或成本上限（月度 X 万 / 营收占比 n%）。

**也有用：** 任何已有信号——历史权益效果、私域载体（企微/小程序/社群/APP）、现有等级雏形、竞品会员体系、数据厚度（用户量/订单时长）。

调用时附带的所有内容——技能名后的文本、粘贴的上下文，或附加的 `ARGUMENTS:` 行——都视为已给出的回答。直接使用并跳过其已覆盖的部分，不要重复提问。

**手头没有任何数据？那也可以。** 技能会基于行业类型先套一版默认参数（餐饮/零售/电商三档），标 `[默认—需验证]`，后续用真实数据回填并滚动复算。

**示例调用：** `为企微沉淀的 3 万茶饮复购客设计会员积分体系——月度积分预算 5 万元，目标提升复购与客单价。`

### 输入字段与异常处理

| 字段 | 必填 | 异常处理（缺失/错误时怎么回） |
|---|---|---|
| 行业类型 | 是 | 缺失→追问「会员体系属餐饮高频复购/零售客单周期/电商跨品类哪类？」不假设 |
| 目标会员人群 | 是 | 缺失→提示「请提供目标会员人群，如：企微沉淀的 3 万茶饮复购客」 |
| 会员运营目标 | 是 | 缺失→追问复购/客单价/留存/防流失/裂变，不自行假设 |
| 私域载体 | 否 | 缺失→按企微+小程序默认，提示确认 |
| 积分预算/成本上限 | 是 | 缺失→追问「有积分预算或成本上限吗？无预算无法算单积分价值，恐防不住通胀」 |
| 现有等级/权益 | 否 | 缺失→默认冷启动经典阶梯+行业默认档，提示 |
| 数据厚度 | 否 | 缺失→默认冷启动消费+行为双轨，提示数据薄别上复杂财务模型 |
| 是否含付费会员卡 | 否 | 缺失→默认否，提示「付费卡与免费等级是两套逻辑，需时单独设计」 |

输出标准：四件套字段见 [references/template.md](references/template.md)；评分判定规则全部可量化（「如果…则…」条件句，禁"较好/一般/适度"），单积分价值必须给具体数值，兑换 ROI 必须 ≥1，兑换率目标落 15%-30%。完整异常场景见下方「异常场景」节。

## 核心概念

### 什么是会员积分体系
对私域沉淀的、可反复触达的用户，用「成长值定等级、积分做激励、权益给回报、财务兜底」的闭环体系做精细化留存与 LTV 提升。

### 等级 / 积分 / 权益三角咬合（混淆点）
```
        等级（成长值驱动）
       ↗            ↘
  积分（行为累计） ←← 权益（积分兑现/等级供给）
            ↑
      财务约束（单积分价值·兑换率·负债）压在三者之上
```
- **等级**：定位「这个用户值多少，该怎么对待」，靠成长值（累计消费/行为）阶梯驱动，决定权益档位。
- **积分**：定位「激励什么行为」，靠获取规则（行为×权重）累计，靠消耗规则（兑换×ROI≥1）兑现，是会员体系的「虚拟货币」。
- **权益**：定位「给用户什么实际回报」，分等级权益（按等级供给）+ 积分权益（按积分消耗解锁）+ 付费会员权益（前置付费锁定）三层。
- **三角咬合**：升级后积分更值钱（高价值用户核心驱动）——等级抬升积分获取倍率（如金卡 1.5 倍），积分消耗解锁更高阶权益，权益构成升级拉力。三者独立都失效：只设等级不发积分→等级无粘性；只发积分不分等级→无差异化；只配权益无等级积分→无成长路径。

### 积分 vs 成长值 vs 经验值（混淆点）
| 积分（兑换货币） | 成长值/经验值（定级货币） |
|---|---|
| 可消耗、有有效期、可兑换 | 只增不减、累计定级、不可消耗 |
| 决定「能换什么」 | 决定「是什么等级」 |
| 需财务测算与防通胀 | 需保级与降级机制防固化 |
> 双轨制（星巴克）：成长值定级 + 好礼星星兑换解耦，等级与兑换独立——复杂体系推荐；冷启动可简化为单轨（积分即成长值，如喜茶 1 元 1 积分 + 1 经验值）。

### 三行业套路差异（决定默认参数）
| 维度 | 餐饮 | 零售 | 电商 |
|---|---|---|---|
| 核心目标 | 高频复购 | 客单价 + LTV | 锁高净值 + 跨品类省钱 |
| 等级数 | 4-5 级 | 6 级 | 无等级（付费一卡通） |
| 获取比 | 1元=1成长值+1积分 | 消费分+行为分 | 品类返利 0.5%-2%（京豆式） |
| 定级周期 | 90 天滚动 / 12 月 | 年制 | 365 天付费 |
| 权益核心 | 体验特权（升杯/赠饮/优先取餐） | 价格+服务特权（会员价/2倍积分/顾问） | 生态+售后特权（免邮/专享价/只换不修） |

### 为何这么做
- **积分是虚拟货币不是福利**：有通胀、有负债、有合规线——必须财务测算前置，否则会破产（加航 AeroPlan）或崩盘（平台把商户补偿误记收入半年亏 900 万）。
- **获取易、消耗难是通病**：发得多花得少致沉淀，兑换吸引力不足/路径深/商品不对路——必须监控兑换率与分层消耗率。
- **权益鸡肋源于不分层**：优惠券为核心已失效，要刚性权益+生态权益+情感绑定组合（亚马逊 Prime 8:1 感知价值比）。
- **等级只升不降会塌缩**：金字塔塌缩、高等级泛滥、权益贬值——必须阶段制+保级评估。

### 反模式（它不是什么）
- 不是无差别送分——积分是激励手段，目的是把不同行为区别定价。
- 不是积分越多越好——无有效期+无消耗闭环=通胀破产。
- 不是权益堆砌——每项权益必须测 ROI，高使用率权益别划入免费等级（伤付费）。
- 不是一次定终身——成长值/兑换率需月/季滚动复算防失效。

### 何时使用
- 私域有一定会员沉淀（企微/小程序几百人以上），要做会员体系或治理已有体系
- 有明确预算或成本上限，需要倒推积分汇率与等级门槛
- 复购/留存/LTV 指标卡住，无差别发券效果越来越差
- 已有积分体系出现通胀/负债虚高/权益鸡肋/黑产薅羊毛信号，要治理

### 何时不要使用
- 刚起步、用户 <500、数据极薄——先跑通基础触达与事实标签，别强上财务模型（见异常 12）
- 纯拉新阶段（公域获客为主）——会员体系意义不大，先做拉新裂变
- 要做的是储值卡（预付卡）而非积分——那是《单用途商业预付卡管理办法》管辖的另一套体系（见参考）

## 应用

使用 [references/template.md](references/template.md) 获取完整的填空式结构。先按行业套默认参数，再按 8 步产出四件套，每步都过质量检查。

### 第 1 步：定体制北极星与口径

先定行业模式 + 运营目标 + 激励口径 + 预算法，决定四件套的整体形态。

```markdown
### 口径与目标
- 行业模式：[餐饮高频复购 / 零售客单周期 / 电商跨品类]（决定默认参数档）
- 会员运营目标：[复购率 / 客单价 / 留存率 / 防流失 / 裂变]
- 激励口径：[交易型(订单金额驱动) / 互动型(签到/分享/UGC) / 双轨并行]
- 积分预算法：[固定比例法=营收×n% / 固定金额法=年X万]；预算值：[具体数值]
- 当前阶段：[冷启动 / 成长期 / 成熟期]（决定用单轨还是双轨、简单还是精细测算）
```

**质量检查：**
- 行业模式与运营目标一致（餐饮提复购用 1 元 1 分 + 体验特权，电商品类返利% + 生态权益，错配触发异常 2）
- 预算法不是拍脑袋，固定比例法给 n%、固定金额法给具体金额（无预算触发异常 1）

### 第 2 步：会员等级成长体系

按行业默认档定等级数、定级货币、晋级门槛、升降级与保级。产出 [references/template.md](references/template.md)「一、会员等级成长表」。

```markdown
### 等级体系
- 等级数：[餐饮4-5级 / 零售6级 / 电商无等级付费]；等级名：[青铜→白银→黄金→铂金→钻石 等]
- 定级货币：[成长值（独立于积分，双轨） / 积分（单轨，即成长值）]
- 晋级门槛类型（五选一）：[累计消费金额 / 累计消费次数 / 单笔消费满额 / 购买指定商品 / 积分值]
- 晋级门槛值：[具体数值，如累计消费≥500元]
- 升降级算法：[累计制（简单，不能按时段降级）/ 阶段制（可降级保级，推荐成熟期）]
- 保级周期：[90天 / 12个月 / 账户年度]；保级条件：[同升级门槛，略低于升级，如升级500元/保级400元]
- 降级规则：[保级失败降一级 / 按当期成长值重算]
- 等级有效期：[永久 / 12个自然月 / 滚动12月]；高级玩法：[允许用积分抵扣部分保级门槛，防淡季流失]
```

**质量检查：**
- 等级数 ≤5 通过；6 级警告认知负担；>6 不通过要求精简（腾讯视频 8 级反例），每级有清晰跃迁价值
- 晋级门槛从五选一枚举取值并给具体数值，禁"消费较多"
- 有降级机制（只升不降会金字塔塌缩），成熟期用阶段制

### 第 3 步：积分获取规则

按行为四类配比设计获取规则，含权重、三道上限、生日倍率、负向行为。产出 [references/template.md](references/template.md)「二、积分获取消耗规则表」获取侧。

```markdown
### 获取规则（行为四类配比参考：新手10-15%/日常30-40%/消费返1-2%销售额/传播30%）
| 行为类型 | 行为 | 渠道倍率 | 单次积分 | 单次上限 | 日上限 | 月上限 | 生日倍率 |
|---|---|---|---|---|---|---|---|
| 消费 | CONSUME 消费下单 | [小程序1x/企微1.2x] | [每元1分] | [无] | [5000分] | [15万分] | [生日×2] |
| 日常 | SIGN_IN 签到 | - | [5分] | [1次/日] | [5分] | [150分] | - |
| 日常 | REVIEW 评价 | - | [20分] | [1条首条给分] | [20分] | [100分] | - |
| 传播 | REFERRAL 邀请好友 | - | [200分] | [5人/月] | [1000分] | [1000分] | - |
| 新手 | FIRST_PURCHASE 首单 | - | [100分] | [1次] | - | - | - |
负向行为：退货原路收回积分 / 无理客诉扣分 / 违规操作扣分
```

**质量检查：**
- 核心行为（消费）用明确公式，非核心行为（签到/评价）按重要度+频次赋低分；赋值排序：首次>单次>重复
- 三道上限齐：单次/单日/单月（单日上限=Σ任务数×有效次数×分值），缺则触发黑产薅羊毛异常 10
- 私域场景纳入加企微/加群/群活跃/群接龙/完善资料/UGC（区别于公域）

### 第 4 步：积分消耗规则

按五种消耗方式设计兑换规则，含兑换比、ROI、抵现三道门、有效期差异化。产出 [references/template.md](references/template.md)「二」消耗侧。

```markdown
### 消耗规则（五种方式：兑换/换购/抽奖/游戏/定期回收）
| 兑换类型 | 商品/权益 | 兑换汇率 | 库存/配额 | 日兑换上限 | 过期规则 | ROI |
|---|---|---|---|---|---|---|
| 闭环券 | 满50减10券(反哺主业) | 50分=10元(50:1) | [N张/月] | [3张] | 兑换后30天 | ≥1 ✅ |
| 开环实物 | 马克杯(成本20元) | 2000分=1个(100:1) | [N个] | [1个] | 兑换后领90天 | ≥1 ✅ |
| 抵现 | 订单抵扣 | 满门槛:满50元可用/比例≤50%/200整数倍 | - | - | 同获取积分有效期 | - |
| 抽奖 | 单次100分 | Σ(奖品积分×中奖概率)≤100分 | - | [3次/日] | - | 期望约束 ✅ |
有效期差异化：消费积分1年 / 签到积分30天 / 活动积分7天 / 会员专属按等级延长（钻石2年）
退款规则：退款按发送积分原路收回
```

**质量检查：**
- 兑换项含闭环商品（反哺主业券，50:1）+ 开环商品（实物，100:1）两类，缺开环触发异常 6
- 每个 `ROI=兑换积分价值/商品成本价值` ≥1，<1 触发反向薅羊毛异常 4（天堂伞 36.99 vs 540积分+39.6 案例）
- 抵现三道门齐：使用门槛 + 比例≤50% + 整数倍，缺任一不通过
- 抽奖满足期望约束 `Σ(奖品积分×中奖概率)≤单次消耗`；抽奖合规 5 条：明示条件/不虚构奖品/奖金不超限/押输赢设每局每日上限/联网游戏版号备案
- 有效期按行为类型差异化，全设永久触发通胀异常 5

### 第 5 步：权益配置矩阵

按三层分层与四原则设计等级×权益类型矩阵，含触发机制与动态阈值。产出 [references/template.md](references/template.md)「三、权益配置矩阵」。

```markdown
### 权益三层分层
- 等级权益（按等级差异供给）：如会员折扣/专享价/包邮/生日礼/升级礼包/专属客服
- 积分权益（按积分消耗解锁）：如兑换商品/抽奖/抵现（已在第4步消耗规则）
- 付费会员权益（前置付费，可选）：如年卡专属组合，与免费等级严格分离

### 权益×等级矩阵（每格：valueOrRatio / quota / 发放方式自动or主动）
| 权益类型 \ 等级 | 青铜 | 白银 | 黄金 | 铂金 | 钻石 |
|---|---|---|---|---|---|
| DISCOUNT 折扣 | - | 95折 | 9折 | 9折 | 85折 |
| FREE_SHIPPING 包邮 | - | 满99 | 满79 | 满50 | 无门槛 |
| BIRTHDAY_GIFT 生日礼 | 50分券 | 100分券 | 200分券+赠饮 | 300分券+赠饮(动态阈值) | 500分券+私人订制 |
| POINT_MULTIPLY 积分倍率 | 1x | 1x | 1.2x | 1.5x | 2x |
| PRIORITY_SERVICE 优先权 | - | - | - | 优先取餐 | 优先取餐+专属客服 |
| LEVEL_UP_PACKAGE 升级礼包 | - | 50分 | 100分+券 | 200分+券 | 300分+券+赠饮 |
发放方式：零成本权益(折扣/倍率/标识)自动发放；高成本权益(券/礼包)主动兑换(主动兑换率低控成本)
```

**质量检查：**
- 免费等级权益与付费卡专属权益严格分离，高使用率权益不划入免费等级（触发异常 8）
- 权益按等级递增有跃迁价值，每项测成本 ROI
- 触发机制明确（自动 vs 主动），低成本自动、高成本主动控成本
- 动态阈值权益可选：高等级生日礼按消费频次动态提升

### 第 6 步：积分财务测算

按预算两法算单积分价值、总发放量、月度成本与 7 大运营指标，锁住积分负债。产出 [references/template.md](references/template.md)「四、积分财务测算表」。

```markdown
### 财务测算
- 积分预算法：[固定比例法=营收×1% / 固定金额法=年X万]；预算值：[月5万/年60万]
- 单积分价值：= 总预算 / 总发放量 = [600000 / 60000000 = 0.01元/分]
- 总发放量：时间维度 = 单日发放×365×n(n=1.1-1.2容错) [实测/用户维度 = 单人发放×总用户数×n]
- 月度成本：= 月度发放量 × 单积分价值 × 实际履行率 [如 500万分 × 0.01 × 0.5 = 2.5万元/月]
- 目标兑换率：[15%-30%为正常]；警戒：>50%门槛过低，<15%获取易消耗难
- 沉淀率：= 1 - 兑换率；财务计提成本 = 沉淀积分 × 单积分价值
- 积分负债（合同负债科目）：发分增负债(+=单积分价值×发放量)、消耗减负债
- 单等级权益成本 ROI：= 该等级人均权益成本 / 该等级人均贡献毛利，≥1 续档、<1 砍权益

### 7大运营指标（带警戒阈值）
| 指标 | 计划值 | 实际值 | 警戒 |
|---|---|---|---|
| 计划发放积分数 | [600万分/月] | - | - |
| 实际发放积分数 | - | - | 超预算×1.2预警 |
| 积分兑换率 | [20%] | - | <15%获取易消耗难；>50%门槛过低 |
| 用户使用率 | [30%] | - | <20%权益吸引力不足 |
| 新增客单价 | [↑X%] | - | - |
| 复购率 | [↑X%] | - | - |
| 订单占比 | [X%] | - | - |

> 涉税脚注：消费积分兑换礼品不征个税（财税〔2011〕50号）；签到/注册积分兑换视同销售计销项税；企业所得税积分对应收入递延至兑换或失效时确认。积分负债计入「合同负债」科目，收入分摊用相对公允价值法。
```

**质量检查：**
- 单积分价值有具体数值（如 0.01 元/分），禁"按市场行情"
- 月度成本公式三要素齐（发放量×单积分价值×履行率），无预算触发异常 1
- 兑换率落 15%-30%，超 50% 警告门槛过低
- 积分负债按合同负债科目处理，禁把商户补偿款误记收入（崩盘案例）
- 数据薄触发异常 12（用户 <500/无订单历史别上复杂测算，先用预算比法简化起步）

### 第 7 步：防刷与合规

补四道闸风控 + 通兑闭环 + 反商业贿赂，确保体系不被薅垮、不踩金融化线。

```markdown
### 防刷四道闸
1. 单日获取上限（见第3步）
2. 同行为重复计分限制（如评价仅首条给分）
3. 违规行为扣分（退货/客诉/违规）
4. 同设备多账号注册不计分（设备唯一性+关联图谱+行为时序反黑产）

### 合规红线
- 通兑闭环：积分限定本平台闭环使用，禁提现/变相提现/积分间互兑/通兑通用（触发异常 9，易被认定虚拟货币受人行监管）
- 反商业贿赂：积分发放对象限终端消费者，避开对销售选择有控制力的经销商/采购人员（米其林向零售商发积分被认定贿赂反例）
- 抽奖合规5条（见第4步）
- 储值卡边界：本技能设计积分体系，不设计预付储值卡（属《单用途商业预付卡管理办法》另管）
```

**质量检查：**
- 四道闸齐全，缺触发黑产薅羊毛异常 10（莱阳骗招行积分判 4 年 6 月案例）
- 无任何提现/互兑/通兑设计，触发异常 9 即拒绝
- 发放对象限终端消费者

### 第 8 步：迭代咬合（防通胀防腐烂）

设滚动复算节奏与分层消耗率诊断，让体系持续有效。

```markdown
### 迭代咬合
- 复算节奏：[月度] 兑换率/使用率/沉淀率滚动重算 + [月度/季度] 等级门槛与保级复算
- 分层消耗率诊断：理想消耗率30-50%、消耗人数占比50%+；高价值用户消耗率往往更低(33%)需针对性优化兑换商品结构
- 触达反馈回灌：兑换行为→更新行为标签→重算等级→调整权益档位（与 skills/private-domain-user-ops 协同）
- 通胀监控：兑换率持续<15%或沉淀率持续>85% → 触发有效期缩短/兑换项补充，防获取易消耗难
```

**质量检查：**
- 有固定复算节奏（月度），等级超 1 季度未复算触发异常（参考 user-ops 标签腐烂）
- 兑换率与沉淀率有监控阈值与响应动作
- 与兄弟技能 user-ops/tag-system 协同：等级作 user-ops 事实标签、积分行为作 tag-system 标签原语

## 常见陷阱

### 陷阱 1：积分无有效期或一刀切长效
**症状：** 所有积分永久有效，或全部设 1 年
**后果：** 消费积分沉淀成本可控，但签到/活动积分无限累积致通胀；加航 AeroPlan 无财务计划最终资不抵债破产
**修正：** 按行为类型差异化有效期（消费 1 年/签到 30 天/活动 7 天/会员专属按等级延长）

### 陷阱 2：获取易、消耗难
**症状：** 获取渠道十几条，兑换项只有几张券
**后果：** 发得多花得少，兑换率 <15%，积分沉淀负债越积越大，财务说虚高
**修正：** 兑换项覆盖闭环（反哺主业券 50:1）+ 开环（实物 100:1）两类，监控分层消耗率，高价值客针对性优化商品结构

### 陷阱 3：等级只升不降、数太多
**症状：** 8 级体系、只升不降，或升降级时间维度不统一
**后果：** 等级金字塔塌缩、高等级泛滥、权益贬值；用户认知负担重（腾讯视频 8 级需到 V8 才解锁全部）
**修正：** 3-5 级为宜，成熟期用阶段制+保级评估（保级门槛略低于升级），允许积分抵扣保级防淡季流失

### 陷阱 4：积分换购比直接买还贵
**症状：** 换购价高于市场价（天堂伞 36.99 元 vs 540 积分+39.6 元）
**后果：** 反向薅羊毛，用户维权投诉（江苏消保委已立案调查），品牌信任崩塌
**修正：** 每个兑换项 `ROI=兑换积分价值/商品成本价值 ≥1`，上线前做市价对齐校验

### 陷阱 5：积分提现/互兑/通兑
**症状：** 为提升吸引力设计积分提现、积分间互兑、多平台通兑通用
**后果：** 被认定虚拟货币/支付工具触发人行监管，或被认定为商业贿赂（向经销商发积分）
**修正：** 限定本平台闭环使用，发放对象限终端消费者，避免提现/变相提现/互兑

### 陷阱 6：退款不退积分
**症状：** 消耗规则无退款扣分机制
**后果：** 套现漏洞——下单赚积分后退款的灰产套路
**修正：** 退款按发送积分原路收回（阿里云/有赞通行做法）

### 陷阱 7：把商户补偿款误记为收入
**症状：** 积分兑换时把商户承担的补偿款记为平台收入
**后果：** 积分负债虚高，用户大量兑换时无钱覆盖，中型平台半年亏 900 万崩盘
**修正：** 积分池资金与商户分账资金分账，会计上严格按「合同负债」科目，发分增负债、消耗减负债，收入分摊用相对公允价值法

- 纯方法论输出，免登录免 Key、不扣点，由 agent 直接产出四件套；额外可用 [scripts/gen_member_points_xlsx.py](scripts/gen_member_points_xlsx.py) 生成 Excel 空白模板（依赖 openpyxl，缺失退出码 2 给安装引导；Excel 纯本地生成不上传）。
- 四件套骨架以 [references/template.md](references/template.md) 为准，照抄填空；正例见 [references/sample.md](references/sample.md)；与兄弟技能的边界与组合用法见 [references/related.md](references/related.md)。
- 判定规则全部可量化（等级数阈值/ROI≥1/单积分价值数值/兑换率15%-30%/有效期差异化/抵现三道门），禁"较好/适度/一般"模糊词。
- 必填输入缺失时按「异常场景」表对号入座；缺预算/行业类型/运营目标须追问、不自行假设。
- 本技能聚焦「会员积分体系设计」（等级+积分+权益+财务四件套）；若用户要的是「价值分层触达」或「标签体系底座」，转对应姊妹技能（见 [references/related.md](references/related.md)），不强包。
