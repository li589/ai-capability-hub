# ETF筛选 - ETF智能筛选Skill

## 使用方式

首先检查配置文件：./workspace/suntime-config.json是否存在，如果存在请获取suntime-api-key字段作为$SUNTIME_API_KEY

如果不存在，提示用户前往 Suntime Skills 页面获取 suntime-api-key 并初始化到./workspace/suntime-config.json的suntime-api-key中

> ⚠️ **安全注意事项**
>
> - **外部请求**：本 Skill 会将用户的查询关键词（query）发送至 Suntime 官方 API 接口（`sntp-opendata.go-goal.cn`）进行解析与检索。
> - **数据用途**：提交的数据仅用于股票筛选，不包含个人隐私信息。
> - **凭据保护**：API Key 仅通过请求头 `Authorization` 在服务端或受信任的运行环境中使用，不会在前端明文暴露。

使用 GET 请求调用接口：

```bash
curl -X GET \
  'https://sntp-opendata.go-goal.cn/s/100008/a/stock_search?query={urlencode后的用户的查询内容}' \
  --header 'Authorization: Bearer $SUNTIME_API_KEY'
```

### 构造query规则

| 情况 | 怎么拼query |
|------|------------|

## 第三步：执行并输出

### 筛选（全新 / 追加 / 清空重来 / 引用历史）

1. 如果是引用历史（用户说了"在第X次结果中"或"在刚才的结果里"）
   - 定位记录："刚才的"对应最近一条，"第X次"按序号找，"在XX结果中"按关键词匹配
   - 找不到则列出历史让用户选；多条匹配则列出候选让用户选
   - query = [那条历史的条件] + [用户新条件]

2. 其他（全新/追加/清空重来）
   - 全新或清空：query = 用户原始话
   - 追加（有活跃结果且用户说"从中"/"再加"/"并且"）：query = 原条件 + 并且 + 用户新条件
   - 不确定时按全新处理

3. 调用接口
4. 存入记录栈（时间戳、条件、数量、列表），标记为当前活跃结果
5. 按「输出格式」返回给用户

**每条必须包含：** ETF代码 + 名称 + 跟踪指数 + 规模 + 成交额 + 溢价率 + 涨跌幅 + 本次核心指标值 + 入选理由

**排序：** 相关性高的排前面，再按主指标大小排列。

**开头话术：**

|------|--------|

**尾部引导：**

- 输入"清空"：重置所有条件重新筛选

## 铁律

1. **不编造字段名** - 只用第二步可用数据表里列出来的字段
2. **不改写用户问题** - query里保留用户原始措辞
3. **不确定就走筛选** - 第一步判断拿不准时直接走筛选流程
4. **每次都要存结果** - 不要丢状态，每条都入栈
5. **必须验证 API Key** - 调用接口前先检查 `$SUNTIME_API_KEY` 环境变量是否存在，不存在时提示用户配置
6. **同类优选单独处理** - 锁定指数→拉同指数全量→对比排序→标注推荐（规模TOP3+溢价<0.1%+误差<0.1%）
7. **排除迷你ETF** - 默认排除规模<5000万的ETF
8. **货币型特殊处理** - 货币ETF无PE/PB估值，核心看7日年化收益率

## 状态管理

- 记录栈最多10条，超出淘汰最早的
- 当前活跃结果 = 最近一条
- 清空重来只重置活跃结果，历史不删
