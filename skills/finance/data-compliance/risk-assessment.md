# 数据合规风险评估指引

> 最后核实日期：2026-06-04。本指引用于初判，不替代正式影响评估（见 [impact-assessment.md](impact-assessment.md)）与法务意见。

用于对常见数据处理场景做结构化风险评估，输出风险点、等级、依据与整改建议。

---

## 一、七维定级模型

> 早期版本只有前 4 维，偏内部取数视角。对营销、推荐、对外共享这类通用场景，必须叠加后 3 维，否则会系统性低估风险。

1. 数据类型：一般个人信息 / 敏感个人信息（身份证件、生物识别、金融账户、行踪轨迹、健康、14岁以下未成年人）
2. 处理环节：收集 / 存储 / 使用 / 内部流转 / 跨境传输 / 对外提供 / 删除
3. 是否跨境：境内 / 跨境（CN↔SG/US/DE）
4. 是否脱敏：明文 / 哈希脱敏（SHA256，仍属个人信息）/ 真正匿名化（不可复原）
5. 数据主体规模：小（<1万）/ 中（1万–100万）/ 大（>100万）——规模越大风险越高，也是触发跨境/评估的法定阈值
6. 是否自动化决策/画像：否 / 用于推荐营销 / 用于对个人有重大影响的决策（价格、授信、风控处置）
7. 是否对外/委托：仅内部使用 / 委托处理（受托方）/ 对外提供第三方 / 公开

### 风险等级判定

| 等级 | 典型组合 | 处置 |
| :--- | :--- | :--- |
| **高** | 敏感信息+明文+跨境/对外 ；或 大规模+自动化重大决策 ；或 对个人有重大影响的对外提供/公开 | 必须走合规评审 + 影响评估；多数需安全评估/单独同意；优先脱敏或区域隔离 |
| **中** | 一般个人信息明文使用 ；敏感信息脱敏后跨境 ；中等规模营销推送 ；委托处理 | 走合规评审，签 DPA，落实最小必要、退出机制与用途留痕 |
| **低** | 哈希脱敏数据精确匹配 ；境内一般信息脱敏使用 ；无自动化决策、仅内部 | 按规范使用脱敏表，常规备案 |

> 提醒：哈希脱敏只降低使用环节风险，不降低跨境/对外提供风险——这两个环节即便用脱敏数据，仍按个人信息定级。

## 二、评估清单（逐项核对）

```
合规风险评估检查表：
- [ ] 是否真的需要个人信息/隐私字段？（最小必要）
- [ ] 处理是否有合法性基础？（同意/合同/法定义务等；营销通常需同意）
- [ ] 是否涉及敏感个人信息？是否取得单独同意？
- [ ] 是否可用脱敏数据替代明文？（精确匹配应优先 SHA256）
- [ ] 哈希脱敏数据是否被误当作"非个人信息"用于跨境/对外？（仍属个人信息）
- [ ] 是否跨境？区域是否隔离、是否用对应区域单元表？
- [ ] 跨境是否按 2024 新规阈值判断豁免/标准合同/安全评估之一？
- [ ] 数据主体规模有多大？是否触发法定阈值？
- [ ] 是否涉及自动化决策/画像？是否提供关闭或不针对个人特征的选项？是否避免杀熟？
- [ ] 是否对外提供/委托处理？是否单独同意 + 签 DPA + 告知接收方？
- [ ] 是否为营销触达？是否有同意基础、退订入口、拒绝即停、频次上限？
- [ ] 是否定义了保留期限与到期删除/匿名化机制？
- [ ] 是否具备数据主体权利响应通道与数据泄露应急预案？
- [ ] 处理敏感/自动化决策/对外/跨境时，是否已做个人信息保护影响评估？
- [ ] 下游是否依赖该数据？改造影响面是否评估清楚？
- [ ] 是否已先过合规评审再申请离线表权限？
- [ ] 申请是否说清每个字段用途（审计留痕）？
- [ ] 私域是否填写正确 bizCode 且仅申请有写权限字段？
```

## 三、常见场景风险评估示例

### 场景 A：名单撞库 / 关联主键匹配
- 风险：低（若用脱敏表）/ 中（若申请明文）
- 结论：脱敏与明文效果相同，应用 SHA256 脱敏表，不申请明文。
- 依据：最小必要原则；改造指引场景一。

### 场景 B：跨境整合多区域会员明文数据做分析
- 风险：高
- 结论：禁止跨域整合明文；按区域使用区域单元表，在对应区域项目空间处理；如需跨境必须走安全评估/标准合同 + 评审。
- 依据：PIPL Art.38、GDPR Chapter V、区域隔离规范。

### 场景 C：使用认证/合同/资金等私域明文表
- 风险：中–高（含身份证件、金融账户等敏感信息）
- 结论：先评审；填写正确 bizCode，仅申请有写权限字段；优先脱敏；私域密文表联系私域 PII 数据 owner（当前 @陈镇南）。
- 依据：内部 PII 规范、PIPL 敏感信息单独同意。

### 场景 D：对外/第三方提供个人信息
- 风险：高
- 结论：需单独同意、告知接收方信息、签署数据处理协议；多数需评估。慎重，默认走评审。
- 依据：PIPL 第23条、GDPR Art.28/44。

### 场景 E：向买家发送营销信息（站内/短信/EDM）
- 风险：中（站内可退订）/ 中–高（短信/邮件，或高频骚扰）
- 结论：需同意为合法性基础，提供退订/拒绝入口，拒绝后立即停止，设置频次上限；平台还须对商家滥用建立监测与处置机制。
- 依据：消法第29条、广告法第43条、民法典第1033条、短信规定第18条；平台责任见电子商务法第38条。详见 [marketing-platform-compliance.md](marketing-platform-compliance.md)。

### 场景 F：个性化推荐 / 自动化营销决策
- 风险：中–高
- 结论：必须提供关闭算法推荐或不针对个人特征的选项；禁止大数据杀熟；对个人有重大影响的决策需可解释、可拒绝；事前做影响评估。
- 依据：PIPL 第24条、互联网信息服务算法推荐管理规定。

### 场景 G：委托第三方处理（受托方/SaaS/外包）
- 风险：中
- 结论：签订委托处理协议(DPA)，约定处理目的/方式/期限/安全措施与协助义务；对受托方做尽调与监督；受托方不得超范围处理或再委托未经同意。
- 依据：PIPL 第21条、GDPR Art.28。详见 [data-lifecycle.md](data-lifecycle.md)。

## 四、输出模板

```markdown
## 数据合规风险评估结果

**场景**：[一句话描述]
**数据类型**：[一般/敏感 + 具体字段]
**处理环节**：[收集/使用/跨境/对外提供...]

| 风险点 | 等级 | 法规/规范依据 | 整改建议 |
| :--- | :--- | :--- | :--- |
| ... | 高/中/低 | ... | ... |

**总体结论**：[是否需走合规评审 / 是否可用脱敏替代 / 下一步动作]
```

> 高风险或不确定场景，一律提示走合规评审，不替用户拍板放行。
