# 输入事实模型

## 最低必要事实

先从用户原话提取，不重复询问已给出的信息：

| 字段 | 说明 | 缺失时处理 |
| --- | --- | --- |
| `period` | 业务发生时间或申报所属期 | 必须追问或仅给期间条件化结论 |
| `location` | 企业所在地、业务发生地或主管税务机关 | 全国政策可先筛选；地方口径标记待确认 |
| `taxpayer_type` | 企业、个体工商户、其他单位或自然人 | 必须追问 |
| `vat_status` | 一般纳税人、小规模纳税人或未知 | 必须追问 |
| `transaction` | 货物、服务、无形资产、不动产及具体内容 | 必须追问，不能只用行业替代 |
| `goal` | 希望全面筛选，还是核验某项优惠 | 默认全面筛选当前交易 |

## 条件性事实

仅当候选优惠需要时追问：

- 申报周期、当期全部销售额、含税/不含税口径、差额扣除前后口径。
- 不动产销售或出租、土地使用权转让、预缴项目、视同应税交易等特殊事项。
- 一般或简易计税方法，开票类型，是否选择放弃优惠。
- 行业、主营业务、收入占比、高新技术或先进制造等资格、是否进入主管部门名单。
- 可抵扣进项税额、进项转出、留抵税额、欠税及纳税信用等与候选政策直接相关的数据。
- 出口、跨境、兼营、混合用途及无法划分的进项税额。
- 已享受的同类优惠及适用期间。

## 标准化格式

内部整理时使用以下结构；不要要求用户必须填写 YAML：

```yaml
period: 2026-Q1
location: 北京
taxpayer_type: 企业
vat_status: 小规模纳税人
filing_cycle: quarterly
transactions:
  - description: 咨询服务
    category: service
    sales_amount: 280000
    amount_basis: 不含税
    invoice_type: unknown
qualifications: []
cross_border: false
existing_incentives: unknown
```

每个交易单独判断。未知值保留为 `unknown`。用户给出互相矛盾的信息时，先指出冲突并询问，不选择性采用其中一个。

## 追问规则

一次优先询问不超过 3 个最能改变结论的问题。先问期间、纳税人身份和交易性质，再问金额、资格与征管细节。用户无法补充时，继续输出候选政策和条件分支，但将状态限制为“条件匹配”或“无法判断”。
