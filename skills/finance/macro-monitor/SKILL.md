# 宏观数据监控技能

## 工作流程

当此技能被触发时（通常通过 cron 每天晚上10点），执行以下步骤：

### 1. 环境检测与采集方式选择

**必须首先根据运行时已经提供的工具选择采集路径，不得调用额外工具检测某个工具是否存在，也不得假设固定工具名一定可用。**

- 可交互浏览器可用：仅在需要动态筛选、翻页或页面交互时使用
- 网页直接读取/抓取能力可用：直接访问精确数据页、官方发布页或 API；搜索仅用于定位页面
- 仅搜索能力可用：只有可打开并核验正文的结果才能标记为已验证；仅有搜索摘要时标记为「未验证」
- 无任何联网采集能力：停止生成实时报告，说明环境限制，不得依据模型记忆补写过去24小时数据
- 报告中按数据项记录实际采集方式，并区分「完整采集」「降级采集」「未验证」

### 2. 数据源可用性预检

**在正式采集前，使用当前已选采集路径验证精确数据页是否包含所需字段；网站首页能打开不等于该数据源可用。**

- 宏观数据页至少验证：指标名称、实际值、指标所属期、发布时间；如需比较预期，还需验证预期值和前值
- 政策页面至少验证：标题、发布机构、发布时间和正文或摘要
- 失败时依次尝试：同一机构的最新发布页 → 同等级备用源 → 二级信息源交叉验证 → 标记「采集失败」
- 不得对同一 URL 无变化地连续重试；每次重试必须改变页面、查询方式或数据源

### 3. 读取科普知识库

**必须先读取当前 Skill 目录下的** `references/indicators.md`，获取常见指标的科普解释。使用相对路径，不要依赖固定用户目录。

### 4. 采集数据

按优先级访问以下数据源，收集过去24小时发布的宏观数据和政策信息。

**数据源分层配置（主源 → 备用源 → 二级源）：**

**国际数据：**
- 发现源（非官方）: Trading Economics 经济日历 (https://tradingeconomics.com/calendar) — 用于发现事件和获取市场预期
- 备用发现源（非官方）: Investing.com 经济日历 (https://www.investing.com/economic-calendar/)
- 验证源: FRED (https://fred.stlouisfed.org/releases) 及指标对应的原始官方发布机构 — 用于核实实际值、所属期、发布时间和修订值
- 备用聚合源: 各指标对应的 Trading Economics 单独页面（不得标记为官方）

**国内数据：**
- 主源: 国家统计局最新发布 (http://www.stats.gov.cn/) — 查看最新数据发布
- 备用源: 新浪财经宏观数据 (https://finance.sina.com.cn/mac/)
- 主源: 央行官网 (http://www.pbc.gov.cn/) — 货币政策、利率、流动性数据
- 备用源: 财联社政策频道 (https://www.cls.cn/)
- 主源: 证监会官网 (http://www.csrc.gov.cn/) — 监管政策
- 备用源: 财联社监管频道 (https://www.cls.cn/)

**新闻资讯（二级源，不参与主源-备用源切换）：**
- 财联社 (https://www.cls.cn/) - 实时金融新闻
- 华尔街见闻 (https://wallstreetcn.com/) - 市场资讯

**数据源降级规则：**
1. 官方精确发布页可用 → 使用官方值，标注「官方来源」
2. 使用备用源或聚合源 → 标注真实来源类型，不得标记为官方
3. 只能使用二级信息源时 → 至少使用两个相互独立的来源交叉验证；或使用一个明确引用原始官方文件并给出精确数值、所属期和发布时间的来源
4. 来源存在冲突 → 优先采用原始官方发布；无法判断时列出差异，不得强行合并
5. 全部不可用 → 标记该数据项为「采集失败」

**采集时同步记录来源信息：** 每个数据项记录精确页面 URL、发布机构、指标所属期、原始发布时间及时区、转换后的 GMT+8 时间、采集时间和验证状态。实际值、前值和预期值来源不同时必须分别标注。

### 5. 整理整合

将采集到的数据按以下结构整理：

```
【过去24小时宏观数据】📊

采集状态：[完整 / 部分完成 / 无法采集]；数据缺口：[无或列出缺失项及原因]

🌍 国际数据
- [数据名称] [指标所属期] [发布值] [预期值] [前值] [条件性影响说明]
  📎 来源：[发布机构：精确URL]；发布时间：[原始时间 / GMT+8]；采集时间：[YYYY-MM-DD HH:MM GMT+8]；验证状态：[已验证/降级/未验证]
  💡 [小白向科普解释说明 - 每个指标都必须添加]

🇨🇳 国内数据
- [数据名称] [指标所属期] [发布值] [预期值] [前值] [条件性影响说明]
  📎 来源：[发布机构：精确URL]；发布时间：[原始时间 / GMT+8]；采集时间：[YYYY-MM-DD HH:MM GMT+8]；验证状态：[已验证/降级/未验证]
  💡 [小白向科普解释说明 - 每个指标都必须添加]

📜 政策动态
- [政策标题] - [简要说明]
  📎 来源：[发布机构或媒体：精确URL]；发布时间：[原始时间 / GMT+8]；采集时间：[YYYY-MM-DD HH:MM GMT+8]

📰 重要资讯
- [新闻标题] - [简要说明]
  📎 来源：[发布机构或媒体：精确URL]；发布时间：[原始时间 / GMT+8]；采集时间：[YYYY-MM-DD HH:MM GMT+8]

⚠️ 风险提示：本报告基于公开信息自动整理，仅用于宏观信息参考，不构成任何投资建议或个性化交易依据。数据可能存在延迟、抓取误差或后续修订，请以原始发布机构的最新信息为准。
```

**科普解释规则（强制执行）：**

1. **每个指标都必须添加科普解释**，没有例外

2. **科普解释来源优先级：**
   - 优先：从 references/indicators.md 中查找现成解释
   - 其次：如果找不到，执行"未知指标处理"流程

3. **科普解释格式要求：**
   ```
   💡 [指标名]：[一句话定义]
      - 为什么重要：[简短说明]
      - 怎么看：[正常范围/关键阈值]
   ```

4. **对于重要数据变化，添加额外解读：**
   - 超预期：为什么超预期？对市场有什么影响？
   - 低于预期：反映了什么问题？政策可能如何应对？

### 未知指标处理流程

当遇到 `references/indicators.md` 中没有的指标时，使用当前环境实际可用的搜索、网页读取或浏览能力执行以下流程，不强依赖固定工具名。若无法联网验证，标记解释缺失，不得凭记忆编写具体口径或阈值。

1. **多源搜索验证**
   搜索该指标，访问多个来源：
   - 搜索1："[指标名] 是什么 意思"
   - 搜索2："[指标名] 经济指标 解释"
   - 搜索3："[指标名] investing.com" 或 "[指标名] trading economics"

2. **交叉验证**
   - 对比多个来源的解释，确保准确性
   - 优先选择权威来源（央行官网、统计局、知名财经媒体）
   - 避免单一来源的片面解释

3. **整理科普内容**
   将搜索结果整理成通俗易懂的格式：
   ```
   💡 [指标名]：[一句话定义]
      - 为什么重要：[简短说明]
      - 怎么看：[正常范围/关键阈值]
   ```

4. **可选：更新知识库**
   如果该指标是常见指标，考虑将解释添加到 references/indicators.md 中，避免重复搜索

### 6. 推送消息

- 当前环境存在消息推送工具时，将报告推送给用户
- 不存在推送工具时，直接将完整报告作为最终输出
- 推送失败时返回报告正文和失败原因，不要重新采集数据

## 数据源快速访问

### Trading Economics 经济日历
- URL: https://tradingeconomics.com/calendar
- 关注：高重要性事件（红色标记）
- 字段：时间、国家、事件、实际值、预期值、前值

### 国家统计局
- URL: http://www.stats.gov.cn/
- 关注：最新数据发布栏目
- 重点指标：GDP、CPI、PPI、PMI、工业增加值、社会消费品零售

### 央行官网
- URL: http://www.pbc.gov.cn/
- 关注：新闻发布、政策解读
- 重点：LPR利率、MLF操作、公开市场操作、货币政策报告

## 注意事项

1. **时间过滤**：以实际发布时间过滤过去24小时（GMT+8），不要使用指标所属期、网页更新时间或采集时间代替
2. **科普解释强制**：每个指标都必须添加科普解释，没有例外
3. **来源标注强制**：每个数据项必须附带精确页面 URL、发布机构、指标所属期、发布时间、采集时间和验证状态，不可只引用网站首页
4. **重要性排序**：高重要性数据优先展示
5. **简洁明了**：每个条目不超过2行，重点突出数值变化
6. **数据验证**：对比实际值与预期值，标注超预期/不及预期
7. **异常处理**：数据源不可用时按降级规则自动切换；关键项目缺失时将报告标记为「部分完成」并列出缺口
## Cron 配置

此技能通过以下 cron job 调度：

```json
{
  "name": "macro-monitor-daily",
  "schedule": {
    "kind": "cron",
    "expr": "0 22 * * *",
    "tz": "Asia/Singapore"
  },
  "payload": {
    "kind": "agentTurn",
    "message": "执行宏观数据监控，浏览免费数据源，整理过去24小时发布的宏观数据和政策信息并推送"
  },
  "sessionTarget": "isolated",
  "enabled": true
}
```
