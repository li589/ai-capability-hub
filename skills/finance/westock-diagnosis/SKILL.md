# 持仓诊断 (Portfolio Diagnosis)

从持仓者视角出发，把专业分析翻译成大白话，让普通人听得懂、用得上。

**核心原则**：白话优先 | 结论先行 | 可执行建议 | 风险伴随 | 不推荐新标的

## 调用方式

**调用方式**：`python3 <本SKILL.md所在目录>/scripts/diagnose.py --portfolio <持仓JSON> [--cash <金额>] [--total-assets <金额>]`

- `<本SKILL.md所在目录>` = 本文件所在目录（解析为绝对路径后直接执行）
- 下文 `westock-diagnosis ...` 是同一调用的简写
- **每个任务 `--help` 至多 1 次**（不确定参数时先查本文「高频命令速查」，再决定是否 `--help`）
- 亦支持 `--portfolio-file <路径>`

```bash
python3 <本SKILL.md所在目录>/scripts/diagnose.py --portfolio '[{"name":"贵州茅台","code":"sh600519","qty":100,"cost":1800}]'
python3 <本SKILL.md所在目录>/scripts/diagnose.py --portfolio-file /tmp/portfolio.json --cash 472952
```

## 适用场景

用户明确要看已有持仓或组合时使用本 Skill，例如：

- "帮我诊断持仓""我的持仓怎么样""帮我看看组合""持仓分析""组合诊断""持仓概览""仓位分析""我的股票怎么样"
- 用户发送持仓截图，或粘贴包含股票、数量、成本、市值、盈亏的持仓文本
- 用户明确说"用我的自选股导入后诊断"，但仍需确认哪些是真实持仓

## 不适用边界

| 用户意图 | 处理方式 |
|---|---|
| 选股、推荐可以买什么 | 不使用本 Skill；本 Skill 不推荐新标的 |
| 只有自选股列表，没有确认真实持仓 | 先让用户确认实际持仓、数量、成本或市值 |
| 用户说“我的自选股持仓”但未提供成本 / 数量 / 仓位 | 先确认自选股是否等于真实持仓；若只是关注列表，转为自选股观察清单，不做持仓诊断 |

## 输入分流

| 用户输入 | 路径 |
|---|---|
| 发送持仓截图 | 截图持仓提取 |
| 粘贴持仓文本或直接描述持仓 | 文本持仓提取 |
| 明确要求从自选股导入 | 自选股持仓确认 |
| **只说「分析/诊断我的持仓」且未附截图或持仓明细** | **默认持仓拉取**（见下） |


### 截图持仓提取

截图为推荐输入方式。触发 vision-analyzer，使用"持仓截图提取 prompt"提取结构化数据（股票名称、代码、持仓量、成本价、现价、盈亏、可用资金等）。多张截图时合并去重，保留用户截图里的 `name`、`code`、`qty`、`cost`、`market_value`、`pnl`、`cash`、`total_assets`；识别不清的字段标为缺失，不要猜。

### 文本持仓提取

用户直接描述持仓，例如"我持有 茅台 1000股 成本1800，腾讯 500股 成本380"，解析为结构化数据。持仓 JSON 字段：

| 字段 | 必须？ | 说明 |
|---|---|---|
| `name` | **必须** | 股票名称 |
| `qty` | **必须**（可反推） | 持仓量。缺失时若有 `market_value` + 现价可反推 |
| `code` | 可选 | 股票代码，缺失时脚本自动 search 补全 |
| `cost` | 可选 | 成本价。缺失时若有 `market_value` + `pnl` + `qty` 可反推 |
| `market_value` | 可选 | 持仓市值，辅助反推 cost 或 qty |
| `pnl` | 可选 | 持仓盈亏金额，辅助反推 cost |

**脚本反推逻辑**：
- qty 缺失 + 有 market_value + 有现价 → `qty = market_value / 现价`
- cost 缺失 + 有 market_value + 有 pnl + 有 qty → `cost = (market_value - pnl) / qty`
- cost 缺失 + 有 pnl + 有现价 + 有 qty → `cost = 现价 - pnl / qty`
- 都推不出来 → 跳过盈亏分析，仍做配置分析

## 数据门禁

调用脚本前先检查每只股票：

- `name` 必须存在；只有代码但没有名称时，可用代码作为名称占位。
- `qty`、`market_value`、`pnl` 三者至少有一个；三者全缺时，无法判断仓位，必须先追问用户补充，确认后再调脚本。
- `cash` 和 `total_assets` 可缺失；缺失时只跳过现金占比或总资产相关判断。
- 成本价缺失只跳过盈亏分析，不阻断组合配置分析，不得编造成本价。

数据不足时先问用户补充，不要为了提速生成完整诊断。

## 诊断脚本调用

> ⚠️ **【强制规则】必须通过 `westock-diagnosis` 获取行情并计算组合指标。agent 不逐条调用 `westock-data`，行情、行业、代码补全由脚本内部完成。**

一次诊断只调用一次脚本；多只持仓放入同一个 JSON 数组，不要逐只拆分调用。下面给出完整可执行入口（命令前缀见顶部「调用方式」）：

```bash
python3 <本SKILL.md所在目录>/scripts/diagnose.py --portfolio '[
  {"name":"长江电力","code":"sh600900","qty":1000,"cost":27.185},
  {"name":"九丰能源","code":"sh605090","qty":300,"cost":40.057}
]' --cash 472952 --total-assets 511322
```

**参数**：
- `--portfolio`：持仓 JSON 字符串（与 `--portfolio-file` 二选一）
- `--portfolio-file`：持仓 JSON 文件路径，例如：

```bash
python3 <本SKILL.md所在目录>/scripts/diagnose.py --portfolio-file /tmp/portfolio.json --cash 472952
```

- `--cash`：可用现金（可选）
- `--total-assets`：账户总资产（可选）

**脚本自动完成**：补全股票代码 → 反推缺失字段 → 批量获取行情和行业信息 → 计算市值/权重/盈亏/行业分布/集中度 → 输出 JSON。

## 工具依赖

| 能力 | 调用方 |
|---|---|
| 截图识别 | **agent** 调用 vision-analyzer |
| 诊断计算 | **agent** 调用 `westock-diagnosis` |
| 行情/行业数据 | 脚本内部调用 westock-data（agent 无需直接调用） |

## 脚本输出解析

重点读取这些字段生成报告：

| 字段 | 说明 |
|---|---|
| `account.total_market_value` | 总持仓市值 |
| `account.cash` / `account.cash_ratio` | 可用现金 / 现金占比%（null=未提供） |
| `account.position_count` | 持仓数量 |
| `account.daily_pnl` / `account.daily_pnl_pct` | 当日盈亏 |
| `account.total_pnl` / `account.total_pnl_pct` | 累计盈亏（null=无成本价） |
| `positions[]` | 各股详情：name/code/current_price/weight_pct/industry/total_pnl_pct 等 |
| `sector_distribution[]` | 行业分布：sector + weight_pct |
| `concentration` | 集中度：top1_name/top1_pct/top3_pct/top5_pct |
| `diagnostics` | 诊断标记：各维度的 status（green/yellow/red/unknown）和 issue 描述 |

> diagnostics.status 对应信号灯：green→🟢、yellow→🟡、red→🔴、unknown→⚪

若脚本输出包含 `error`，必须停止，不生成完整诊断；向用户复述错误和需要补充的数据。

## 生成报告

**结构**（按顺序，根据数据情况灵活调整，不必每项都有）：
1. **结论先行**：2-3句大白话总结整体状态、最大问题、最该做的事
2. **行动建议**：你该怎么办（最多3条）
3. **数据支撑**：组合画像（市值/现金/板块/集中度）、个股情况、配置诊断——根据持仓数量和数据完整度灵活组织，不必死板
4. **止盈止损提醒**：对显著盈利或显著亏损的个股，给出止盈/止损方向性建议，具体到建议操作和理由
5. **调仓建议**：按优先级排列，具体可执行；不新增买入标的，只优化现有持仓
6. **免责声明**：末尾附"以上分析基于公开数据，仅供参考，不构成投资建议"

**风格**：
- 白话优先，像朋友聊天不像券商报告
- 信号灯：🟢=健康 🟡=观察 🔴=需关注 ⚪=未知/数据不足
- 结论 **加粗**，开门见山
- 数字嵌在句子里，不堆大表格（个股汇总表除外）
- 建议必须具体："从35%减到20%" ✅ "降低仓位" ❌
- 不推荐买新股，只优化现有持仓
- 缺失数据不要编造，直接标注"未提供"或跳过该部分

## 并发与批量

- 截图和文本中互不依赖的信息可同时整理；脚本调用必须在数据门禁通过后执行。
- 多只持仓必须一次性传给 `westock-diagnosis`；脚本内部批量获取 `quote` 和 `profile`。

## 容错和终止条件

- 脚本返回 `error`、无有效持仓、无法计算总持仓市值时停止，并说明需要用户补充什么。
- 股票代码缺失但有名称时，可交给脚本补全；补全失败的个股不纳入诊断，并在报告中说明。
- 行业缺失 → 脚本从公司描述推断，或标"未知"；不阻断诊断。
- 成本价缺失 → 跳过盈亏，仍做配置分析。
- 截图不完整时，若仍满足数据门禁，可基于已有字段诊断；不满足时先追问。
- 同一批输入不要反复调用脚本重试；修正输入后再调用一次。

## 合规边界

- 本 Skill 只做持仓诊断和风险提示，不做选股、交易、收益承诺或账户操作。
- 所有建议都必须基于用户已有持仓和脚本输出的数据。
- 报告末尾必须包含"不构成投资建议"的免责声明。
