# 客如云经营参谋

## 1. 文档分工

- `SKILL.md`：最小可用入口，只定义模式选择、主流程和交付要求。
- `init.md`：规则权威源，完整定义初始化、取数、构建、渲染、报告质检和安全红线。
- `api.md`：接口列表，用于自由查询时定位可用接口。
- `scene-overview.md`：预制场景总览，用于场景匹配。

> 执行细则统一查看 [init.md](init.md)。SKILL.md 不直接展开 init 内规则，也不直接跳转深层 references 文件。

## 2. 任务路由

先判断任务类型，再选择执行路径；初始化保持默认前置，除非任务明确不涉及取数、品牌或门店。

| 任务类型                 | 执行路径                                                          |
| ------------------------ | ----------------------------------------------------------------- |
| 预制场景 HTML 报告       | 初始化 → 取数 → 构建组件数据 → 渲染 HTML 报告 → 报告质检          |
| 自由查询并生成 HTML 报告 | 初始化 → 取数 → 渲染 HTML 报告 → 报告质检；仅在适用时构建组件数据 |
| 简单数据问答             | 初始化 → 取数 → 直接回答；不要求 HTML 报告和报告质检              |
| 已有 HTML 优化/修复      | 不重复取数；修复 HTML 后执行报告质检                              |
| 自定义 HTML 报告         | 可不使用标准组件；生成或修改 HTML 后执行报告质检                  |

关键条件：

- 初始化：默认执行，检查 kry-cli、选择品牌和门店；
- fetch.mjs：只在需要接口数据且接口已注册时强制使用。
- report-data.mjs：预制场景 HTML 报告强制使用；自由查询按需使用。
- 报告质检：只要生成或修改 HTML 报告就执行。

## 3. 使用模式

### 3.1 预制场景模式

用户意图匹配预制场景时优先使用：

1. 加载 [init.md](init.md)，完成步骤 1 初始化。
2. 根据 [scene-overview.md](scene-overview.md) 匹配场景编号。
3. 读取场景定义，获取数据计划、manifest 和报告结构。
4. 按 init 步骤 2 执行数据计划，所有已注册接口必须通过 fetch.mjs。
5. 按 init 步骤 3 构建 `report-data.json`。
6. 以 `facts` 组织分析文本，以 `components` 填充 HTML 报告。
7. 按 init 步骤 5 完成报告质检后交付。

### 3.2 自由查询模式

用户问题不匹配任何预制场景时使用：

1. 加载 [init.md](init.md)，完成步骤 1 初始化。
2. 拆解用户问题，最多拆成 3 个子任务；超过时先确认优先级。
3. 查阅 [api.md](api.md)，定位适用接口。
4. 执行 `kry-cli view <接口路径>`，获取官方参数示例。
5. 查阅 `references/field-map/_spec.md` 和对应 field-map 文件，核对必填参数、字段类型、分页结构和金额单位。
6. 按 init 步骤 2 构造参数并调用 fetch.mjs；禁止凭经验手写字段。
7. 提取真实数据，直接回答或生成 HTML 报告；生成 HTML 时按 init 步骤 5 完成报告质检。

## 4. 降级策略

| 情况             | 处理方式                                                               |
| ---------------- | ---------------------------------------------------------------------- |
| 对比周期数据失败 | 去掉环比/同比，仅展示当期真实数据                                      |
| 某 API 无数据    | 保留板块标题，显示「暂无数据」空态卡片                                 |
| 门店名称缺失     | 使用 shopId 兜底展示                                                   |
| 全部 API 失败    | 仍输出 HTML 报告，但只能展示查询范围、失败原因、空态卡片和缩小范围建议 |

全部 API 失败时，禁止填充任何经营数字、趋势、排名、洞察结论或经营建议；该产物是空态说明页，不是经营分析结论。

## 5. 交付要求

- 最终交付物统一为 HTML 报告，禁止只用纯文本或 Markdown 替代。
- 所有数据必须来自真实接口响应或 report-data.mjs 的确定性计算结果。
- 报告质检以 `check-report.mjs` 退出码为准：退出码非 0 必须修复；退出码为 0 且仅有 WARN 时，按 init 的 WARN 规则人工确认。
