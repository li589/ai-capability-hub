# 资源断舍离矩阵（详细模板）

> 来源：WORKFLOW.md §1.8
> 用途：需求诊断阶段，判断哪些需求值得投入、哪些该移交业务、哪些直接砍掉

## 核心原则

把80%的水浇在20%的花上，剩下的花不浇或少浇。

## 四象限断舍离决策

```
              培训效果预期
           高              低
     ┌──────────────┬──────────────┐
战 高 │ ✅ 重点投入   │ ⚠️ 换方案     │
略     │ 资源倾斜      │ 可能不是培训    │
相     │ 深度定制      │ 能解决的        │
关     │              │ → 流程/激励/架构│
性    ├──────────────┼──────────────┤
    低 │ 🔄 移交业务   │ ❌ 直接砍掉    │
      │ 提供工具包    │ 不占预算        │
      │ 业务部门自助   │ 不做培训        │
      │ 不占主体预算   │               │
     └──────────────┴──────────────┘
```

## 断舍离执行规则

| 象限 | 判定条件 | 动作 | 信号特征 |
|------|---------|------|---------|
| ✅ 重点投入 | 战略相关高 + 培训效果预期高 | 资源倾斜、深度定制、全流程跟进 | 差距大、可培训、影响核心业务 |
| ⚠️ 换方案 | 战略相关高 + 培训效果预期低 | 推荐非培训方案（流程/激励/架构调整），不做无效培训 | 员工"知道但没做"、根因是制度 |
| 🔄 移交业务 | 战略相关低 + 培训效果预期高 | 提供标准化工具包，由业务部门自行执行 | 局部需求但非公司级重点 |
| ❌ 直接砍掉 | 战略相关低 + 培训效果预期低 | 不投入、不上马、不占用任何培训预算 | 兴趣型、无绩效关联、效果难验证 |

## 砍项目的勇气指标

- 每年至少砍掉20-30%低价值项目，释放预算给战略级项目
- 砍项目不是失败，是把资源从"做了也没用"的事上收回来
- 判断标准：如果这个项目不做，6个月后业务会有感觉吗？没有→砍

## 输出模板

诊断决策报告：问题分类 → 可解决性判定 → 推荐方案 → 断舍离建议 → 预估资源 → 风险提示 → 替代方案
