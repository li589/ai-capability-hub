# 安全 & 权限模型

小P 辟谣库的权限设计，**双层防护**：

```
┌─────────────────────────────────────┐
│  第一层：企业微信文档侧权限          │
│  （强制，由企微保证，篡改不了）      │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  第二层：skill 代码侧只读默认        │
│  （防误操作，避免误删/误改）         │
└─────────────────────────────────────┘
```

## 第一层：企微文档权限（必读）

腾讯辟谣库（企微智能表格）的分享设置应配置为：

| 角色 | 权限 | 配置方式 |
|---|---|---|
| 文档创建者（你 + 你的机器人）| 所有者 | 默认 |
| 信任同事 | 可编辑 | 分享面板 → 单独添加，设为"可编辑" |
| 公司内其他同事 | 可阅读 | 分享面板 → 链接分享 → 受众"企业内"，权限"可阅读" |
| 公司外 | 无访问权限 | 默认即可 |

**操作步骤**（在企微文档 UI 里）：

1. 打开 https://doc.weixin.qq.com/smartsheet/s3_AFQAnHhjAJICNJ3VNM0oaSpCj5V03_a
2. 右上角点「分享」
3. 「权限设置」改为：
   - 受众：**仅企业内成员**
   - 默认权限：**可阅读**
4. 在分享面板搜索想授予编辑权限的同事，单独把他们改为「可编辑」

⚠️ **不要**把权限设为"任何获得链接的人可阅读/可编辑"，那是公开互联网风险。

## 第二层：skill 代码侧只读默认

skill 默认 **只读模式**，最大限度防止误操作。

### 怎么判断当前是否是管理员模式？

skill 启动时检查目录下是否存在 `wecom-admin.flag` 文件：

- ✅ 文件存在 → **管理员模式**（允许 add/update/delete）
- ❌ 文件不存在 → **只读模式**（只允许 get_records，写操作直接拒绝）

### 启用管理员模式（仅推荐管理员自己做）

```bash
# Windows (git bash 或 PowerShell):
type nul > %USERPROFILE%\.workbuddy\skills\tencent-rumor-refuter\wecom-admin.flag

# macOS / Linux:
touch ~/.workbuddy/skills/tencent-rumor-refuter/wecom-admin.flag
```

### 关闭管理员模式

```bash
# Windows:
del %USERPROFILE%\.workbuddy\skills\tencent-rumor-refuter\wecom-admin.flag

# macOS / Linux:
rm ~/.workbuddy/skills/tencent-rumor-refuter/wecom-admin.flag
```

## 安全总结

| 攻击场景 | 是否能成功 | 原因 |
|---|---|---|
| 外部网友拿到 zip 想读你的表 | ❌ | 企微"仅企业内"权限拦截 |
| 公司同事装 zip 想读 | ✅（这是预期）| 同公司有"可阅读"权限 |
| 公司同事装 zip 想改 | ❌ | 企微只给他"可阅读"，写接口报 851003 |
| 外部分发后 AI 误删 | ❌ | skill 默认只读，没有 admin.flag 写不了 |
| 你想加一条谣言 | ✅ | 你 admin.flag 在，且你是协作者 |

**Zip 里没有任何凭证（token / 密钥 / 密码）**，只有 docid 和 sheet_id —— 这两个等同于"文档地址"，靠企微鉴权拦截非授权访问。

## 风险残留 & 应对

| 残留风险 | 应对 |
|---|---|
| docid 在 zip 里暴露 | docid 本身不是凭证，靠企微账号鉴权防护，不是大问题 |
| AI 被诱导跳过只读检查 | SKILL.md 工作流明确"默认只读"，AI 调用前会检查 admin.flag |
| 公司离职员工还能读 | 企微账号注销后自动失权，无需额外操作 |
| 信任同事变心想恶意改表 | 企微表自带版本历史，可恢复到任意历史版本 |
