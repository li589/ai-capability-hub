# 外资研报日报

仅在用户明确要求某日外资研报日报、行业日报或全市场日报时使用。成文同时遵守 [writing-style.md](writing-style.md)。

**日报只处理单日。** 跨日期范围应走条件查询、语义查询或另行设计周报，不能把多日结果冒充日报。

---

## 一、日报范围

| 用户需求 | 执行方式 |
|----------|----------|
| 单个行业日报 | 主 agent 查询并成文 |
| 多个行业日报 | 每个行业一个并行 subagent；子文件 + 总文件 |
| 全市场日报 | 先拉单日全量作为基准，再按全部申万一级行业并行分治；补「宏观策略与综合」兜底 |

全市场不是一篇抽象的大综述，而是**按行业拆开写、最后汇总**。总文件先给市场总判断和行业导航，再拼接各行业正文。

### 支持的行业

农林牧渔、基础化工、钢铁、有色金属、电子、汽车、家用电器、食品饮料、纺织服饰、轻工制造、医药生物、公用事业、交通运输、房地产、商贸零售、社会服务、银行、非银金融、建筑材料、建筑装饰、电力设备、机械设备、国防军工、计算机、传媒、通信、煤炭、石油石化、环保、美容护理。

`TMT` 不是单一行业，展开为：电子、计算机、通信、传媒。

## 二、开始前确认

1. **日期**：用户说「昨天」就按当前日期减一天；未给日期则追问。
2. **范围**：明确是指定行业、多个行业还是全市场。
3. **输出目录**：成文前询问用户希望保存的位置；未指定时使用当前工作空间根目录。目录不可写时告知用户并重新询问，不要回退到技能目录。

落盘结构：

```text
{输出目录}/
├── 外资研报日报_YYYY-MM-DD.md
└── 日报分行业_YYYY-MM-DD/
    ├── 电子.md
    ├── 基础化工.md
    ├── 有色金属.md
    └── 宏观策略与综合.md
```

单行业也写行业文件；用户只要对话答案时可不落盘。

## 三、数据获取

### 指定行业

```text
research_query(
  type="oversea",
  industryName="{行业}",
  startTime="YYYY-MM-DD 00:00:00",
  endTime="YYYY-MM-DD 23:59:59",
  pageSize=100,
  page=1..N
)
```

返回空或本页不足 100 条时停止。API 返回多少条，行业正文就覆盖多少条；不得因为标题模糊、公司陌生或看似汇编而静默删除。

### 全市场

全市场必须先执行一次不带行业参数的单日全量查询，得到：

- 当日唯一研报总数
- 研报 ID 或链接清单
- 发布机构分布

然后并行查询全部行业。完成后按研报 ID 或链接核对：

1. **重复归属**：允许同一研报出现在多个相关行业子文件中，但总文件统计唯一篇数时必须去重。
2. **未归入任何行业**：写入「宏观策略与综合」子文件，确保全市场基准中的每篇研报都有去处。
3. **明显串标签**：不静默删掉。在行业报告末尾列为「标签口径提示」，用一句话说明为什么它可能只是跨行业或汇编内容。
4. **对账**：`各行业并集（去重） + 未分类 = 全市场基准唯一总数`。不相等就继续排查，不得宣称全量完成。

行业查询可每批并行不超过 8 个，分批完成全部行业。全市场基准用于完整性校验，不能用 `searchForeignReports` 代替。

## 四、并行分治

### 启用条件

- 1 个行业：主 agent 直接执行
- 2 个及以上行业：每行业一个 `generalPurpose` subagent
- 全市场：按行业分批并行，每批建议不超过 8 个

分工原则：**子代理只写一个行业的子文件，主 agent 只做基准对账、总览与总文件拼接。**

### 子代理任务

子代理必须：

1. Read `SKILL.md`、`writing-style.md`、`daily-report.md`
2. 只查询指派行业和日期
3. 覆盖 API 返回的全部研报
4. 把完整正文写到指定绝对路径
5. 只回传短状态，不把正文贴回主对话

薄调度 prompt：

```text
你是「外资研报查询」子代理，只负责一个行业的日报。

依次 Read：
1. {skill_dir}/SKILL.md
2. {skill_dir}/writing-style.md
3. {skill_dir}/daily-report.md

派工：日期={YYYY-MM-DD}；行业={行业}
写入：{行业子文件绝对路径}

使用 research_query，type=oversea，industryName={行业}，完整翻页。
按 daily-report.md 的单行业模板写作，API 返回 N 篇就覆盖 N 篇。
结构固定为：行业综合总结 → 自然归纳的主题 → 重点标的 → 催化展望 → 研报列表 → 逐篇摘要 → 标签口径提示。
必须严格遵守层级与缩进：主题用 ####，重点标的/催化展望用 ####，标的或事件用 #####，相关研报用有序列表且标题与观点分行，逐篇摘要用 #### 第N篇。
禁止把主题、重点标的、相关研报都写成同一层加粗正文。
所有正文必须说人话：先说结论，再解释依据和数字；写清机构、主张和理由。

只返回：
OK | {行业} | {N}篇 | {绝对路径} | {一句话结论}
或 FAIL | {行业} | {原因}
不要写总文件，不要处理其他行业，不要再开 subagent。
```

### 主 agent 任务

1. 确认日期、范围、输出目录并预建目录
2. 全市场模式先拉全量基准
3. 并行派发行业子任务
4. 对账唯一研报数，处理未分类项
5. 根据各行业短状态写市场总览与目录
6. 按固定行业顺序拼接子文件；失败行业在目录中标明并可单独重试
7. 拼接时每个行业正文前保留空行，禁止出现 `---## 行业` 粘连

---

## 五、层级与缩进（呈现硬规则）

目标：打开文件后，一眼能分清「章节 → 主题 → 研报 → 摘要」。

| 层级 | 写法 | 作用 |
|------|------|------|
| L1 行业 | `## {行业}（N篇）` | 行业入口 |
| L2 大节 | `### 行业综合总结` / `### 研报列表` / `### 逐篇摘要` / `### 标签口径提示` | 四大板块 |
| L3 导航项 | `#### 1｜{判断句}`、`#### 重点标的`、`#### 催化展望`、`#### 第1篇｜...` | 可扫读导航 |
| L4 子项 | `##### {公司或事件}` | 重点标的/催化下的条目 |
| L5 研报 | 有序列表：标题单独一行，观点另起一行并缩进 | 正文主体 |

强制格式：

1. **主题必须是 `####` 标题**，禁止写成 `**1、xxx**`。
2. **重点标的、催化展望必须是 `####` 标题**，禁止写成 `**重点标的：**` 混在主题中间。
3. **相关研报必须用有序列表**：标题单独一行加粗带链接；观点另起一行，相对列表项缩进。
4. **栏目之间空一行**；主题与主题之间空一行；列表项之间空一行。
5. **逐篇摘要每篇用 `#### 第N篇｜...`**，不要用 `**第N篇｜...**`。
6. 拼接总文件时，行业正文前必须有空行。

视觉示意（正确）：

```text
## 基础化工（22篇）
  ### 行业综合总结
    #### 1｜亚洲业绩超预期……
      1. [高盛｜标题]
         观点段落……
      2. [摩根士丹利｜标题]
         观点段落……
    #### 重点标的
      ##### 锦湖石油化学
        1. [高盛｜标题]
           观点段落……
    #### 催化展望
  ### 研报列表
  ### 逐篇摘要
    #### 第1篇｜高盛｜标题
```

## 六、单行业正文模板

```markdown
## {行业}（{N}篇）

### 行业综合总结

**总判断：** {用一两句白话说明今天外资在这个行业最关心什么，整体偏乐观还是谨慎，以及原因}

#### 1｜{判断句，不要只写主题名}

{1-2 句解释共识或分歧。这是导航层，不要写成大段分析。}

**相关研报观点总结**

1. **[{机构}｜{研报标题}]({链接})**

   {另起一行写 2-5 个完整句：主张、依据、关键数字、这意味着什么。}

2. **[{机构}｜{研报标题}]({链接})**

   {同上。若与上一条有分歧，明确写出差异。}

#### 2｜{第二条判断句}

{1-2 句概括}

**相关研报观点总结**

1. **[{机构}｜{研报标题}]({链接})**

   {观点总结}

#### 重点标的

##### {公司或标的1}

{一句话说清为什么值得看：受益/承压点，以及跟踪什么。}

1. **[{机构}｜{研报标题}]({链接})**

   {评级、目标价、盈利变化与依据。}

##### {公司或标的2}

{一句定位}

1. **[{机构}｜{研报标题}]({链接})**

   {观点总结}

#### 催化展望

##### {事件或数据1}

{时间节点、验证指标，以及什么结果算超预期/低于预期。}

1. **[{机构}｜{研报标题}]({链接})**

   {机构如何判断及其依据。}

##### {事件或数据2}

{一句定位}

1. **[{机构}｜{研报标题}]({链接})**

   {观点总结}

> 若当日没有明确标的或催化，在对应 `####` 下写一句「当日研报未形成明确重点标的/催化共识」，不要空着，也不要编造。

### 研报列表

| 序号 | 日期 | 机构 | 研报标题 | 主要标的/主题 | 评级或动作 |
|------|------|------|----------|---------------|------------|
| 1 | YYYY-MM-DD | 摩根大通 | [标题](链接) | 公司/主题 | 增持/减持/首次覆盖/上调目标价/未披露 |

### 逐篇摘要

#### 第1篇｜[{机构}｜{标题}]({链接}) · `YYYY-MM-DD`

{忠实跟随原文结构，用自然语言记录核心结论、依据、关键数字、评级/目标价和风险。原文信息丰富时不能压缩成两三句话。}

#### 第2篇｜[{机构}｜{标题}]({链接}) · `YYYY-MM-DD`

{同上}

### 标签口径提示

{无明显问题则写“未发现明显串标签”；有则逐条说明，不静默删除。}
```

要求：

- 根据当天研报内容自然归纳主题，不预设数量上限或下限
- 主题判断只负责搭建阅读框架，「相关研报观点总结」才是综合章节正文主体
- 每篇研报至少在一个主题的「相关研报观点总结」中得到实质覆盖
- 「重点标的」「催化展望」没有明确内容时如实说明，不得补写
- 同一篇研报可支持多个主题，但每次只写与当前主题有关的内容
- 评级、目标价、盈利预测变化必须注明机构；分歧要写清
- 「研报列表」覆盖全部 N 篇，顺序与逐篇摘要一致；未披露评级写「未披露」
- 主题用 `#### 1｜判断句`；标的/事件用 `##### 名称`；相关研报用 `1. 2. 3.` 列表
- 逐篇摘要用 `#### 第N篇｜机构｜标题`
- 禁止旧写法：`**1、主题**`、`**重点标的：**`、`（1）**[标题]：** 长段` 挤在同一视觉层级

## 七、总文件模板

```markdown
# 外资研报日报｜YYYY-MM-DD

**覆盖范围：** 全市场 / {指定行业}  
**研报唯一数：** {N}篇  
**行业子报告：** {M}个

## 今日市场总览

**总判断：** {只写最重要的市场结论，不堆行业名}

1. **{跨行业判断句}**

   {用白话解释原因和证据}

2. **{第二条判断句}**

   {明确分化或风险}

3. **{第三条判断句}**

   {明确后续验证点}

## 行业导航

- [电子（N篇）](相对路径)
- [基础化工（N篇）](相对路径)
- [宏观策略与综合（N篇）](相对路径)

## 全市场研报总表

| 序号 | 日期 | 机构 | 研报标题 | 归属行业 | 评级或动作 |
|------|------|------|----------|----------|------------|
| 1 | YYYY-MM-DD | 摩根大通 | [标题](链接) | 电子 | 增持/未披露 |

---

{按固定顺序拼接各行业子文件正文；每个行业前空一行}
```

总览只负责告诉读者「今天最重要的三五件事」，不能重新复述所有行业，也不能用空话代替事实。

全市场模式的「全市场研报总表」按研报 ID 或链接去重，每篇只列一次；同时属于多个行业时，归属行业可并列。指定行业日报不需要额外制作全市场总表，以各行业子文件中的「研报列表」为准。

## 八、质量检查

- [ ] 全市场基准已完整翻页
- [ ] 全市场唯一总数已与行业并集及未分类对账
- [ ] API 返回的每篇研报均有覆盖
- [ ] 重复研报在总数中已去重
- [ ] 串标签内容已提示，而非静默删除
- [ ] 主题/重点标的/催化/逐篇均使用规定标题层级，不是同级加粗
- [ ] 相关研报为有序列表，标题与观点分行，观点有缩进
- [ ] 栏目之间有空行，总文件无 `---##` 粘连
- [ ] 每个主题先给白话结论，再给证据
- [ ] 每个数字后说明「这意味着什么」
- [ ] 每条机构观点写清「谁、怎么看、为什么」
- [ ] 没有箭头链、加号堆词、数字墙和空泛行话

---

## 禁止

- 跳过分页却声称已覆盖全量
- 把多个行业内容塞进同一段
- 仅按 `keywords=TMT` 代替 TMT 四行业
- 用语义搜索结果冒充全市场全集
- 因行业标签不准而擅自删除返回结果
- 子代理把长正文回传给主 agent，导致上下文膨胀
- 用加粗正文冒充标题层级，导致主题、标的、研报挤在同一视觉平面
