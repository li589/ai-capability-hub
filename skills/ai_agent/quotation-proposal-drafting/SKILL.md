# 报价方案生成

## 目标与边界

定位：将已确认的价格、币种、MOQ、交期、付款和贸易条件组装为报价邮件和方案对比。边界：标准对象无报价接口；缺少数据只输出待填写模板，不计算或承诺未知条件。

## 输入要求

- 用户目标与使用场景
- 产品/品牌/案例等事实资料
- 目标市场、受众、渠道与语言
- 输出格式和必须遵守的企业规则

## 工作流程

1. 确认用户目标、目标市场/受众、输出语言和交付格式。
2. 整理用户提供的产品、品牌、案例和渠道资料，区分事实、推断和缺失项。
3. 按报价方案生成的方法生成结构化初稿。
4. 检查技术参数、案例、认证、价格、版权和商业承诺是否有依据。
5. 输出可直接修改的结果、待确认项和发布/执行前检查清单。

## 输出要求

- 结构化分析或内容草稿
- 事实依据与假设
- 待企业确认项
- 发布或执行前检查清单

## 固定口径与输出模板

- 每个单价必须同时显示币种、计价单位和数量档位；不同币种不得相加或暗示等值。
- Incoterm必须带版本和命名地点（如EXW Ningbo, Incoterms 2020）；地点或版本缺失时保留待确认占位符。
- 交期需声明起算点，付款需声明节点，报价有效期需声明截止日或天数；未知条件不得计算或承诺。
- 输出表：方案｜数量｜单价/币种/单位｜MOQ｜贸易条款/地点｜交期起算｜付款节点｜有效期｜待确认项。

## 实战使用卡

### 可直接复制的任务示例

> 为德国批发商生成英文报价：304保温杯，500件USD4.80/件、1000件USD4.35/件，EXW Ningbo，交期25天（定金到账起），30% T/T定金、余款发货前付，有效期14天。

### 最小任务卡

用户信息不完整时，只补问会阻塞执行的项目；其余内容先按已知事实交付草稿。

- 业务目标
- 已确认的产品/企业事实
- 目标市场、受众与渠道
- 语言、格式和必须保留的条件

### 默认交付顺序

1. 可直接使用或修改的第一版成品
2. 事实/来源与推断分栏
3. 仅保留真正阻塞执行的待确认项
4. 发布、发送或执行前检查清单

### 完成标准

- 结果可被业务人员直接复制、筛选、修改或提交复核，不只给方法论。
- 每个关键结论能追溯到输入、CRM字段、消息原文或明确标注的推断。
- 缺失信息用占位符或缺口清单表达，不因缺一个非关键字段而停止全部工作。
- 涉及发送、发布、投放或CRM写入时，停在明确的确认点。

## 询盘云API接入

- 本Skill不读取或写入实时CRM。若用户提出CRM操作，说明超出本Skill边界并转交已配置的CRM能力；禁止索取任何密钥。

## 禁止事项

- 不编造客户、公司、产品、价格、认证、案例、实时数据或商业承诺。
- 不把推断写成事实；资料不足时明确列出待确认项。
- 不执行本Skill边界外的发送、发布、删除、批量修改或系统写入。
- 涉及CRM写入时，不得跳过字段发现、目标查询、变更预览、明确确认和执行回查。
- 不得把 client_id、client_secret 或 access_token 写入SKILL.md、参考资料、工作簿、对话或日志。
