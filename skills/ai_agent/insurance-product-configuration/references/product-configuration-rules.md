# 产品配置参考

## 1. 需求诊断输入

产品配置前必须取得以下经确认信息：

| 输入 | 用途 |
|---|---|
| 客户与被保对象资料 | 核验适用条件、保障期限和缴费安排 |
| 本次重点模块 | 确定主产品和保障优先级 |
| 建议保额/待补足金额 | 确定保额范围 |
| 已有保障 | 避免重复保障或遗漏关键责任 |
| 年度预算与缴费偏好 | 控制方案可承受性 |
| 待确认事项 | 不确定信息不进入正式报价或合规结论 |

不完整时返回需求诊断补充，不直接配置产品。

## 2. 组合规则

### 单主险规则

- 一个方案只配置一个主险。
- 附加险必须满足所选主险的主附关系、保障期限、缴费期和保额比例要求。
- 当产品规则或报价引擎反馈组合不符合要求时，调整方案后重新执行完整报价与校验；不要展示未通过的内部错误给代理人或客户。

### 本次重点与后续规划

- 主险围绕需求诊断中已确认的本次重点模块配置。
- 强相关但不属于本次重点的保障，可标记为“可选同步补”。
- 其他模块列入“后续规划”，不强推一次性配置。

## 3. 产品资料最低要求

每个纳入配置的产品必须具备当前有效资料：

- 中文产品名称与内部标识。
- 产品状态与适用渠道。
- 保障责任、等待期、免责、期限和缴费方式。
- 主险/附加险关系与组合限制。
- 适用条件和投保限制。
- 费率/报价来源、条款版本与生效时间。

缺少任一关键资料时，可作为“待核验候选”，不可输出精确保费、条款承诺或合规通过结论。

## 4. 报价与合规校验

推荐使用一次完整的组合报价与规则校验，输入至少包括：

```text
被保对象资料
+ 主险与附加责任
+ 保额
+ 保障期限
+ 缴费期限/缴费方式
+ 预算范围
+ 当前产品、费率与规则版本
```

输出至少包括：

```text
年缴/月缴保费
保费构成
规则校验结果
待核验或待确认事项
报价日期、费率/条款版本、适用渠道
```

本 Skill 已内置经代理人确认有效的脱敏产品库，并提供 `scripts/quote_plan.py`：

- 可对已解析产品执行年龄、性别、保额、缴费期、保障期限和社保条件下的保费测算。
- 可校验单主险、产品库中已维护的主附关系和保额比例规则。
- 输出产品说明书、费率表、文档标识和“资料库版 2025-03-17”的引用。
- 非标准体、豁免险加费、产品库未覆盖的缴费/保障参数、健康告知与正式核保仍标记“待核验”。
- 资料库默认有效；如后续接入保司 MCP，应以保司实时产品状态、费率和规则版本覆盖资料库结果。

## 5. 推荐理由与未选原因

| 情况 | 推荐理由示例 |
|---|---|
| 与本次重点匹配 | 直接覆盖本次确认的保障重点和待补足金额 |
| 与预算匹配 | 在已确认预算范围内安排缴费与保障额度 |
| 与家庭责任匹配 | 对应房贷、子女、赡养或收入中断责任 |
| 与已有保障互补 | 补充现有保单尚未覆盖的责任 |

| 未选原因 | 表达方式 |
|---|---|
| 非本次重点 | 暂不作为本次重点，列入后续规划 |
| 预算不匹配 | 当前预算下优先保障本次重点 |
| 条件待确认 | 待确认适用条件后再评估 |
| 资料未核验 | 待核验有效条款、费率或适用渠道 |

不得贬低其他产品或保险公司。

## 6. 展示规则

- 对代理人和客户展示中文产品名称，不展示内部代码。
- 每项产品至少说明一条匹配理由，不只呈现价格。
- 方案输出保持简洁，默认不超过 12 行；详细责任、对比表和引用交由建议书生成能力承接。
- 正式方案发送前，必须标记报价与条款版本并由代理人确认。
