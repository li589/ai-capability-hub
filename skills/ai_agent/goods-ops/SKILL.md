# 商品运营

## 功能说明

本 skill 让 WAI 代表商家完成商品查询与商品运营动作。底层接口能力用于直接获取真实商品数据和商品辅助信息；业务流程能力用于整理客户可决定的信息，并把创建或本 skill 不直接支持的商品写操作交给商品业务 subagent。

### 设计原则

1. **原有能力优先**
   - 原子接口：一次 `woscli admin-api query-goods-list` 调用即可完成，直接返回结果。
   - 商品列表、详情、筛选、排序和类目/标签/分组查询继续按本 skill 执行，不因存在 subagent 而改道。

2. **创建商品直接委派**
   - 查询类操作（查列表、查详情）属于原子接口，直接执行并返回命令原始结果。
   - 用户要求创建商品、上新、以图/无图发品、自动补充信息、分配门店或完整测试创建接口时，先整理已知业务信息，再调用商品业务 subagent 完成。
   - 父 skill 只负责业务信息收集、必要确认和交接，不编排 subagent 的参数、工具或执行步骤。

3. **缺什么问什么**
   - 使用本 skill 原有能力时，用户意图明确但缺少无法从当前结果取得的业务条件，再合并追问。
   - 创建商品只询问客户能理解和决定的业务信息，不询问技术参数。
   - 缺少图片不阻塞委派；将无图情况和用户授权原样交给 subagent。
   - 用户已说“按默认值”“完整测试”或同义表达时，保留这项授权并交接，不在父 skill 中展开默认值。

4. **无法完成才回退委派**
   - 非创建任务先按本 skill 的原有命令和流程执行。
   - 只有当前能力明确不支持、所需直接能力不可用，或正常执行后仍无法形成用户要求的业务闭环时，才把未完成任务委派给商品业务 subagent。
   - 不要为了省步骤提前委派，也不要在本 skill 与 subagent 中重复执行同一写操作。

### 前置条件

- 当前登录态、商户、门店上下文由 Weimob Assistant 上层统一提供，woscli 自动注入。
- 本 skill 不负责获取或写入会话级上下文数据。
- **重要：只能查询当前店铺的数据，禁止使用其他店铺的 bos_id、vid 等标识进行查询。**
- 查询商品必须以接口真实返回为准；不要自行补充库存、销量、价格等未返回字段。

## 触发场景

- 查商品、搜商品、看商品列表、翻页看商品
- 按商品 ID 查商品、按商品名称查商品、按商品编码/SKU 编码查商品
- 看上架商品、看下架商品、看可售商品、按价格区间筛商品
- 按销量排序商品、卖得最好的商品、价格从低到高
- 看库存、看销量、看商品基础信息
- 搜商品类目、搜商品标签、搜商品分组、理解商品图片
- 创建商品、上新、以图发品、无图发品、按默认值创建、完整测试创建接口
- 改价、改库存、上下架、修改商品（本 skill 定位后委派）

## 调用方式

本 skill 查询类能力统一走 `woscli admin-api query-goods-list`；类目/标签/分组搜索与图片理解走 `woscli`（其他类目）。

| 调用方式 | 适用场景 |
|---|---|
| `woscli admin-api query-goods-list` | 商品列表查询、搜索、筛选、排序、详情查询（按商品 ID 列表） |
| `woscli` | 类目搜索、标签搜索、分组搜索、图片理解 |

### query-goods-list 调用

```bash
woscli admin-api query-goods-list --pageNum 1 --pageSize 20
```

### 通用调用约定

- 命令入口：`woscli admin-api query-goods-list [args]`，底层为微盟商家后台真实接口，由 woscli 统一处理登录态、商户、门店上下文。
- 依赖上层提供登录态、当前商户、当前门店。

### 能力路由

| 用户意图 | 处理方式 |
|---|---|
| 查商品列表、搜商品、按名称/编码查商品 | `woscli admin-api query-goods-list` 并组合搜索/筛选/排序参数 |
| 按价格、上下架、可售状态筛商品 | `woscli admin-api query-goods-list` 并组合筛选参数 |
| 按销量、价格、上下架时间、排序值排序商品 | `woscli admin-api query-goods-list` 并组合排序参数 |
| 看库存、看销量、看商品基础信息 | 先列表命中商品；如需更完整字段，再用 `--goodsIdList` 查详情 |
| 按商品 ID 查详情 | `woscli admin-api query-goods-list --goodsIdList [<id>,...]` |
| 搜商品类目 | `woscli` 调用 `search_category` |
| 搜商品标签 | `woscli` 调用 `search_tags` |
| 搜商品分组 | `woscli` 调用 `search_groups` |
| 创建商品、以图/无图发品、完整测试创建 | 整理业务信息后调用商品业务 subagent |
| 非创建任务按现有能力执行后仍无法完成 | 携带已有结果和失败原因调用商品业务 subagent |

## 支持的操作

### 1. 商品列表查询

| 命令 | 用途 | 关键参数 |
|---|---|---|
| `woscli admin-api query-goods-list` | 查询商品列表 | `--pageNum`、`--pageSize` |
| 同上 | 按名称/编码搜索 | `--search`、`--searchType` |
| 同上 | 按价格区间筛选 | `--minSalePrice`、`--maxSalePrice` |
| 同上 | 按上下架状态筛选 | `--goodsStatus`（0=上架、1=下架、2=已售罄） |
| 同上 | 按可售状态筛选 | `--isCanSell`（0=不可售、1=可售） |
| 同上 | 排序 | `--sort`（1=销量、2=上下架时间、3=价格、4=排序值）、`--sortType`（0=升序、1=降序） |

常用调用：

```bash
woscli admin-api query-goods-list --pageNum 1 --pageSize 20
woscli admin-api query-goods-list --search '牛奶' --searchType 1
woscli admin-api query-goods-list --search 'SP001' --searchType 2
woscli admin-api query-goods-list --goodsStatus 0 --isCanSell 1 --minSalePrice 10 --maxSalePrice 200
woscli admin-api query-goods-list --sort 1 --sortType 1
```

列表查询工作流：

1. 根据用户意图组合搜索、筛选、排序参数。
2. 执行 `query-goods-list` 命令。
3. 直接使用命令结果回复，不捏造、不补全字段。
4. 若缺少认证、商户或门店上下文，按命令返回提示上层补齐后再继续。
5. 完整的参数映射和响应字段说明见 `@references/goods-list.md`。

### 2. 商品详情查询

用于通过 `goods_id` 查询单个或多个商品的详细信息，补充列表查询中未返回的字段（如更完整的库存、规格、详情图等）。

| 命令 | 用途 | 关键参数 |
|---|---|---|
| `woscli admin-api query-goods-list` | 按商品 ID 列表查询详情 | `--goodsIdList`（商品 ID 列表，如 `[102781859999837,102783709999837]`） |

详情查询工作流：

1. 从列表查询结果或用户输入中获取 `goods_id`。
2. 调用 `query-goods-list`，传入 `--goodsIdList` 参数。
3. 直接使用接口返回结果回复，不自行补充字段。
4. 若 `goods_id` 无效或接口报错，按原始错误信息提示用户。

组合查询工作流（列表 + 详情）：

1. 先用 `query-goods-list` 按名称/条件搜索商品列表。
2. 从列表中提取目标商品的 `goods_id`。
3. 再用 `query-goods-list --goodsIdList` 查询该商品完整详情。
4. 合并两次结果向用户展示：列表提供概览，详情提供深度信息。

### 3. 参数词典

- `--pageNum`：页码，默认 `1`。
- `--pageSize`：每页数量，默认 `20`。
- `--search`：搜索关键词。
- `--searchType`：`1` 按商品名称，`2` 按商品编码，`3` 按规格条码，`4` 按规格编码。
- `--goodsIdList`：按商品 ID 列表精确查询，数组格式如 `[102781859999837,102783709999837]`。
- `--minSalePrice` / `--maxSalePrice`：价格区间。
- `--goodsStatus`：上下架状态，`0`=上架、`1`=下架、`2`=已售罄。
- `--isCanSell`：可售状态，`0`=不可售、`1`=可售。
- `--sort`：`1`=销量、`2`=上下架时间、`3`=价格、`4`=排序值。
- `--sortType`：`0`=升序、`1`=降序，默认 `1`。

参数选择约定：

- 用户给商品名时默认 `--searchType 1`；给明显商品编码、SKU 编码或外部编码时用 `--searchType 2`。
- 用户给明确商品 ID 或一组商品 ID 时用 `--goodsIdList`，不要改走名称/编码模糊搜索。
- 用户要求“销量最高”“卖得最好”时用 `--sort 1 --sortType 1`。
- 用户要求“价格从低到高”时用 `--sort 3 --sortType 0`。

### 4. 商品类目/标签/分组搜索、图片理解（woscli）

用户明确要求搜索商品类目、标签、分组或理解商品图片时，根据商品名称、图片和描述生成关键词并匹配结果。正式创建商品由商品业务 subagent 处理，不因创建任务预先执行本节。

| 命令 | 用途 | 结构 | 关键参数 |
|---|---|---|---|
| `search_category` | 搜索商品类目 | 两级（一级类目 > 二级类目） | `keywords`、`l1_category`（可选） |
| `search_tags` | 搜索商品标签 | 扁平级 | `keywords`、`top_k`（可选，默认 20） |
| `search_groups` | 搜索商品分组 | 两级（一级分组 > 二级分组） | `keywords`、`l1_group`（可选） |
| `understand` | 根据用户要求编写 question，从指定角度理解图片 | - | `woscli image understand --imageUrl "xxxxx" --question "xxx"` |

**关键词生成原则**：

- 基于商品名称、图片内容和用户描述，生成 1-8 个关键词，每个 1-3 个字。
- 用户明确要求同时搜索类目、标签和分组时，默认并行调用 `search_category`、`search_tags`、`search_groups` 三个 tool，各调用一次。
- 每个 tool 每个商品最多调用 2 次；第一次尽量将核心品类、同义词和特征词用 `|` 拼接到同一个 `keywords` 中，例如：白色 T 恤图片 → `"短袖|纯棉|白色|夏季|衣"`，不要为单个关键词拆成多次调用。
- 三个 tool 的结果互不替代：`search_category` 用于类目，`search_tags` 用于标签，`search_groups` 用于分组。
- 只有某个 tool 第一次结果为空或明显不匹配，且可以基于结果调整关键词时，才对该 tool 再调用一次；第二次仍无合适结果则停止该 tool 的搜索。

**调用方式：**

```bash
woscli mall-goods search_category --keywords "运动鞋|男鞋|鞋"
```

其他命令仅替换 `command` 和 `args`：

```bash
woscli mall-goods search_tags --keywords "新品|爆款|纯棉"
woscli mall-goods search_groups --keywords "夏季系列|上衣"
```

**搜索结果使用规则：**

- 返回多个结果时，选择并返回最匹配项；存在明显歧义时，列出少量候选供用户确认。
- 搜索结果为空或不匹配时如实说明，不虚构 ID、名称或层级。
- 类目结果可返回 `id`、`name`、`full_path` 和 `category_type`。
- 标签和分组结果可返回名称、ID 和层级信息。

### 5. 创建商品（委派 subagent）

用户表达以下任一意图时进入委派准备；需要用户决定的关键信息齐全后再调用商品业务 subagent：

- 创建商品、上新、自动上架商品
- 以图发品或无图发品
- 自动补充创建所需信息
- 创建后分配门店、设置库存并上架
- 测试或完整测试商品创建接口

创建商品要准备的业务字段含义与规则见 `@references/goods-form.md`。

#### 业务交接边界

父 skill 只汇总用户可理解和决定的业务信息、用户约束与授权，以及当前非敏感业务上下文。实现参数、默认值策略、内部工具和执行步骤由商品业务 subagent 自行处理，不在本 skill 中映射或展开。

委派前遵循以下原则：

- 优先使用用户原始请求、图片、当前会话和商户/门店上下文中的已知信息。
- 只有缺少必须由用户决定且会实质影响业务结果的信息时，才集中向用户确认。
- 缺少的信息若可由 subagent 自行处理，不阻塞委派。
- 没有图片时不向用户索要图片；原样传递无图情况和用户对生成图片的授权。
- 用户要求“按默认值创建”或“完整测试”时，原样传递授权，不在父 skill 中设定具体默认值。
- 已经成功完成的动作不在 subagent 中重复执行。

#### 友好询问方式

只确认仍缺少且会影响创建结果的客户决策，不要用参数名或内部术语提问。已经从用户请求、图片或当前门店上下文取得的内容不要重复询问，尽量把相关问题合并为一条自然表达。

商品对象不清楚时，可以这样问：

> 想创建什么商品？请告诉我商品名称、品类和规格。如果是多规格、虚拟商品或预售商品，也请一起说明。

销售设置不完整且必须由用户决定时，可以这样问：

> 请告诉我销售价和初始库存。如果有市场价、成本价、指定门店，或者希望创建后直接上架，也可以一起说明。

#### 传给 subagent

使用业务语言进行结构化交接：

```text
原始请求：<保留用户原话和执行授权>
已知商品信息：<名称、对象、品类、规格、商品形态和素材等>
销售与库存：<用户给出的价格、库存和相关约束>
目标门店与上架意图：<已知业务要求>
用户约束与授权：<默认处理、测试或其它明确要求>
当前业务上下文：<商户、门店和会话中的非敏感业务信息>
已完成内容：<已有查询结果或已完成动作；没有则写“无”>
待完成目标：<需要 subagent 接续完成的业务结果>
```

未知信息如实保留为未知，不替用户编造业务决策。subagent 返回信息不足时继续向同一 subagent 追问，不在父 skill 中重复写操作。

### 6. 其它商品写操作

用户要求修改商品、调整库存或价格、上下架等本 skill 不直接执行的操作时：

1. 如果需要定位目标或了解当前状态，先使用本 skill 的列表或详情查询。
2. 如果用户提供的信息已经足以唯一定位目标，可直接委派，不为取得技术参数而追问。
3. 将原始请求、已有查询结果、当前业务上下文和尚未完成的目标交给商品业务 subagent。

## 输出格式

`query-goods-list` 返回结构：

- `totalCount`：总数。
- `pageNum`：当前页码。
- `pageSize`：每页数量。
- `pageList`：商品列表（`items` 内）。

单个商品字段：

- `goodsId`：商品 ID。
- `title`：商品标题。
- `goodsCode`：外部商品编码。
- `goodsPrice.minSalePrice` / `goodsPrice.maxSalePrice`：最低/最高销售价。
- `goodsStock.goodsStockNum`：库存数。
- `isOnline`：是否上架。
- `isCanSell`：是否可售。
- `defaultImageUrl`：默认图片。
- `realSaleNum`：真实销量。

回复要求：

- 查询结果以接口真实返回为准，不捏造、不补全。
  - 列表/搜索/筛选/排序场景：以 `woscli admin-api query-goods-list` 的返回为准。
  - 详情查询场景：以 `query-goods-list --goodsIdList` 的返回为准。
- 如果接口返回商品列表，保留用户关心的字段；用户要求完整结果时直接完整返回。
- 不自行补充库存、销量、价格等未返回字段，也不重命名类目、销量口径。
- subagent 返回部分失败或结果不确定时，如实报告，不把已完成部分扩大为全部成功。
- 若已知当前商户/门店名称，回答结尾附带当前商户与门店。

## 注意事项/边界

- 非创建任务必须先执行本 skill 的原有路径。出现以下任一情况，才调用商品业务 subagent 完成剩余任务：
  - 本 skill 明确不支持用户要求的操作，例如修改商品、独立上下架或库存写入。
  - 所需命令在当前运行环境不可用。
  - 原有接口正常执行后仍缺少完成业务目标所需的数据或写能力。
  - 已按本 skill 的失败处理完成一次安全定位，仍无法形成可交付结果。
- 委派时传递原始请求、已经获得的查询结果、当前商户/门店上下文、失败原因和尚未完成的目标。已经成功的写操作不得在 subagent 中重发。
- “先执行原有路径”只适用于本 skill 已经定义的能力。文档已经明确不支持的写操作不需要故意调用不存在的命令来制造一次失败：
  - 修改商品：可以先用原有列表/详情查询定位商品，但价格或其它正式写入直接委派。
  - 独立上下架或库存写入：可以先用原有查询取得商品和当前状态，但正式变更直接委派。
  - 如果用户已经给出足以唯一定位目标的信息，也可以直接委派未支持的写入，不为获取技术参数追问用户。
- 通过 `goods_id` 修改商品等当前 skill 无法完成的任务，按“无法完成时委派”处理，不直接拒绝。
