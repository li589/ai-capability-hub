# 最终验收清单

## 目录

- 交付清单
- 数据验收

在声称系统“已完成”前逐项验证。把证据写入测试报告或 `delivery-manifest.json`；未测试与未通过必须分开标记。

## 交付清单

- [ ] 源码、配置模板、数据库初始化/迁移、测试和启动脚本齐全。
- [ ] `system-spec.json` 与最终实现一致。
- [ ] `input-profile.json` 能追溯全部用户输入。
- [ ] `data-quality-report.md` 列出阻断、警告和处理结果。
- [ ] `build-checkpoint.json` 指向最近一次验证通过的阶段。
- [ ] 中文使用说明包含启动、首次登录、数据目录、备份、恢复和停止。
- [ ] `delivery-manifest.json` 通过 `validate_delivery.py --strict`。
- [ ] 未打包真实密码、会话、令牌、私钥或不必要的真实数据。

## 输入解析验收

- [ ] 输入目录中的每个文件都出现在 `input-profile.json`，`input_files_silently_skipped=0`。
- [ ] 每个 error/warning 都有错误码、阶段、最小可定位位置、原因、影响、处理动作和恢复点。
- [ ] 单个文件损坏时，其余文件仍完成只读盘点；总体明确区分 `partial_with_errors` 与 `passed`。
- [ ] XLSX/XLSM、DOCX、PDF 至少完成离线容器/结构完整性预检；CSV/JSON 错误可定位到行或行列。

## 数据验收

- [ ] 每个目标字段都有来源与转换规则。
- [ ] 主键唯一性、外键完整性和重复导入已验证。
- [ ] 原始行数、成功数、失败数和排除数可以对平。
- [ ] 关键数量与金额合计和源文件一致，差异有解释。
- [ ] 日期、时区、单位、前导零、空值和枚举映射正确。
- [ ] 金额使用 Decimal 或整数分，舍入规则固定且有测试。
- [ ] 示例数据和正式数据物理或逻辑隔离。

## 功能验收

- [ ] 首次登录、修改密码、退出和会话过期可用。
- [ ] 每个角色的允许操作和拒绝操作都至少测试一次。
- [ ] 核心对象的新增、查看、修改、提交、退回/撤回和审批闭环可用。
- [ ] 已审批记录无法被无痕覆盖，更正流程保留前后值。
- [ ] 导入先预览、逐行报错、防重且失败不会污染正式数据。
- [ ] 筛选、搜索、分页、排序和导出在真实数据量级下可用。
- [ ] 空状态、无权限、校验失败、数据库失败和未知异常均显示中文提示。
- [ ] 重启服务后数据仍存在，不依赖浏览器内存。

## 安全验收

- [ ] 服务端实施 RBAC；直接调用接口也无法越权。
- [ ] 密码使用合格的带盐慢哈希，无默认生产密码。
- [ ] SQL 参数化、输出转义、CSRF、上传限制和路径校验已覆盖。
- [ ] CSV 公式注入、压缩包路径穿越和危险文件类型有测试。
- [ ] 审计日志覆盖登录、导入、提交、审批、导出、配置、备份和恢复。
- [ ] 日志与错误页面不泄露凭证、堆栈和完整敏感字段。
- [ ] 依赖版本锁定并检查已知风险；结果注明扫描日期和范围。
- [ ] 未把内部检查描述成第三方认证。

## 离线与国内环境验收

- [ ] 断开外网后完成安装或解压、启动、登录和核心业务流程。
- [ ] 断网后导入、导出、备份和恢复可用。
- [ ] 浏览器开发者工具中没有非本机/内网的网络请求。
- [ ] 页面不引用 CDN、远程字体、远程图标或在线许可证。
- [ ] Windows 10/11 x64 目标机完成实测，或清楚列出实际测试环境。
- [ ] 交付包含一键诊断和目标电脑验收入口；目标机未执行时 `target_pc_smoke_verified=false`。
- [ ] 目标机验收覆盖启动、核心冒烟、持久化、导入导出、备份、停止和重启。
- [ ] WPS 与 Office 打开导出文件时中文、金额、日期和分页正确。
- [ ] CSV 在常用国内环境中不乱码，文件名和路径支持中文。
- [ ] 人民币负数、退款、千位符和两位小数显示正确。

## 恢复与升级验收

- [ ] 中断构建后能从 `build-checkpoint.json` 继续，不重新覆盖数据库。
- [ ] 备份生成、校验、恢复前自动备份和恢复后核对均通过。
- [ ] 升级脚本可重复执行，失败时事务回滚或有明确恢复步骤。
- [ ] 旧版本数据迁移后行数、金额、状态分布和孤儿记录核对通过。
- [ ] 系统迁移版本一致；若同时发布技能包，还需通过“技能发布验收”的全位置版本检查。

## 技能发布验收

本节检查技能包本体，不替代生成系统的业务验收：

- [ ] `SKILL.md` 通过技能结构校验，正文少于 500 行，引用文件都可定位。
- [ ] `agents/openai.yaml` 的显示名称、短描述和默认提示与当前技能一致；默认提示明确由执行者代运行命令。
- [ ] `python scripts/check_version.py` 通过，技能说明与脚手架基线一致。
- [ ] `python scripts/diagnose.py --source <最小材料> --strict` 通过，且不使用网络。
- [ ] 所有 Python 脚本可编译，公开入口的 `--help` 可运行。
- [ ] 文档优化版本不得改写既有业务脚本、工程骨架或模板；以原包 SHA-256 清单逐文件核对。
- [ ] ZIP 不包含 `__pycache__`、`.pyc`、一次性运行报告、用户数据、平台生成的 `_meta.json` 或临时输出。
- [ ] ZIP 完整性测试通过，解压后再次运行技能结构和版本检查。

## 交付清单格式

`delivery-manifest.json` 使用以下最小结构。文件哈希为实际 SHA-256，不得使用占位符：

```json
{
  "schema_version": "1.0",
  "system": {
    "name": "生产报工系统",
    "version": "1.0.0",
    "locale": "zh-CN",
    "timezone": "Asia/Shanghai",
    "network_mode": "offline"
  },
  "source_files": [
    {"name": "工单计划.xlsx", "sha256": "64位小写十六进制哈希"}
  ],
  "start_commands": {
    "windows": "start-windows.bat"
  },
  "files": [
    {"path": "app/main.py", "sha256": "64位小写十六进制哈希"}
  ],
  "modules": ["报工", "审核", "导入导出", "审计", "备份恢复"],
  "roles": ["报工员", "生产主管", "系统管理员"],
  "security": {
    "password_hash": "PBKDF2-HMAC-SHA256",
    "rbac": true,
    "audit_log": true,
    "csrf": true,
    "no_cdn": true
  },
  "tests": {
    "command": "python -m unittest discover -s tests",
    "status": "passed",
    "executed_at": "2026-08-04T10:00:00+08:00"
  },
  "known_limitations": []
}
```

`files` 只列交付包内文件，路径必须相对项目根目录且不得包含 `..`。`source_files` 记录来源证据，不要求把敏感原文件打包。

## 结论规则

- **通过**：所有阻断项通过，警告有证据和用户可接受的限制。
- **有条件通过**：核心流程可用，但存在明确、非安全关键的未满足项；必须列出影响和补齐方法。
- **不通过**：数据可能错写/丢失、权限可绕过、核心流程失败、无法恢复、版本不一致或声称的离线能力未实测。

只在“通过”时使用“完整交付”措辞；“有条件通过”必须在交付首段直接说明限制。
