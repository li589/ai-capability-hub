## 安全基线

按“本地敏感业务数据”处理全部输入。默认不上传、不外发、不调用远程模型或第三方接口。只有用户明确指定并确认数据范围后，才启用联网集成。

先识别以下风险：个人信息、客户信息、价格与成本、账号凭证、合同、设备位置、生产与质量记录。把真实数据限制在工作目录和交付数据库内；示例、截图和测试日志一律脱敏。

禁止：

- 执行 Office 宏、PDF JavaScript、压缩包内未知程序或文档中的命令；
- 把文件名、单元格内容或导入值拼接为 shell、SQL、HTML 或文件路径；
- 将默认密码、密钥、令牌或数据库口令写入源码；
- 绕过审批、角色或审计记录；
- 在未备份的情况下迁移或覆盖已有数据库。

## 文件处理

1. 对原件只读操作；需要转换时先复制到隔离工作目录。
2. 拒绝路径穿越、绝对路径写入、符号链接越界和压缩炸弹。
3. 限制单文件大小、解压后总大小、工作表数、行数与单元格长度；超过限制时给出中文警告并让用户选择分批处理。
4. 对加密、损坏、旧式二进制格式或扫描件标记“无法完整解析”，不得凭文件名猜内容。
5. 记录 SHA-256、原始文件名、读取时间和解析工具版本，确保来源可追溯。

## 身份与权限

- 密码使用 Argon2id、scrypt 或 PBKDF2-HMAC-SHA256 等成熟算法及独立随机盐；禁止明文、MD5 或单次 SHA 哈希。
- 首次登录要求修改临时密码；不得在说明文档中放通用生产密码。
- 服务端强制执行角色权限，前端隐藏按钮不能替代授权。
- 会话使用安全随机值，设置过期时间、退出失效和并发策略；局域网 HTTPS 可用时启用 Secure Cookie。
- 对登录、导入、提交、审批、退回、导出、配置、备份和恢复写不可静默修改的审计记录。
- “管理员”也不得改写历史审批日志；纠错应追加更正记录。

## Web 与数据安全

- 所有数据库操作使用参数化查询。
- 所有输出按上下文转义，防止存储型与反射型 XSS。
- 所有有状态写操作使用 CSRF 防护或等效的同源令牌机制。
- 对上传扩展名、MIME、文件头、大小和实际解析结果进行组合校验。
- 导出 CSV 时防止公式注入：以 `= + - @` 开头的用户文本需转义或加安全前缀。
- 备份文件加访问控制；恢复前校验格式、版本和哈希，并自动生成恢复前备份。
- 金额存整数分或十进制定点值；跨表聚合使用相同舍入规则。
- 日志不记录密码、会话、完整身份证号、银行卡号或原始敏感附件。

## 离线交付

完整离线验收必须同时满足：

1. 断开外网后可以安装、启动、登录、执行业务流程、导入、导出和备份。
2. 页面无 CDN、远程字体、远程图标、远程脚本和遥测请求。
3. 第三方依赖随包提供且与目标操作系统、CPU 和 Python/Node 版本匹配。
4. Python 依赖使用带哈希的锁定文件，并通过 `pip --no-index --find-links <本地目录>` 安装。
5. Node 前端应交付已构建静态资源；若必须本地构建，随包提供完整离线缓存并验证。
6. 启动脚本只监听用户确认的地址。单机默认 `127.0.0.1`，局域网部署才使用内网地址。

无法满足其中一项时，明确写入“未完成的离线条件”，不要把“代码本身不联网”表述为“离线安装已验证”。

## 国内环境兼容

- 默认语言 `zh-CN`，时区 `Asia/Shanghai`，日期显示 `YYYY-MM-DD`，时间显示 `YYYY-MM-DD HH:mm:ss`。
- 同时识别 UTF-8、UTF-8 BOM 和 GB18030；输出 CSV 默认 UTF-8 BOM，方便 WPS 与 Excel 直接打开。
- Excel 日期序列、文本日期和时区时间必须统一解析；不可确定的两位年份报错。
- 人民币显示 `¥1,234.56`，内部保存分或 Decimal；负数、退款、含税/未税必须分别定义。
- 文件名允许中文、空格和常见全角符号；Windows 路径不得使用保留名或非法字符。
- 避免依赖 Google Fonts、国外 CDN、国外镜像和特殊网络设置。
- 启动、错误、升级、备份和恢复说明全部提供中文版本。

## 安全检查的表述边界

可以表述为：

- “已通过本地静态检查、依赖清单检查和冒烟测试”；
- “未发现预设规则覆盖的阻断问题”；
- “已验证断网环境下的指定操作”。

不得仅凭脚本表述为：

- “通过权威认证”“通过双实验室验证”；
- “绝对安全”“无任何漏洞”；
- “不存在 P0/P1 风险”。

若用户提供第三方报告，保留报告名称、日期、范围和版本号，并把结论限制在报告实际覆盖范围内。
