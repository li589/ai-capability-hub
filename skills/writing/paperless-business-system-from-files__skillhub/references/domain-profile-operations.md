# 运营记录业务 Profile（仅在证据支持时加载）

## 识别信号

典型字段/词：运营记录、人工工时、机器工时、制造人工、包装人工、品项切换人工、启机人工、故障人工、保养人工、夹赠工时、原料损耗、物料损耗、化学品/油品、产品品项、规格/品项、线别、班次、班时。

## 已验证参考能力

该 Profile 由成熟运营记录系统的稳定结构反向验证，适合“生产运营综合记录表”类系统，但不得复制参考系统的具体产品、人员、账号或默认字段到其他项目。

常见对象包括：运营记录、线别、班次、班时、产品品项、动态字段类别、动态字段项、人工工时、机器工时、原料损耗、化学品/油品、能耗、物料损耗、备注、经办人、导出模板。

## 动态字段优先

运营记录表经常随着工艺、产品和管理口径变化。若附件显示字段可由基础数据管理维护，应把“字段类别/字段项”建模为数据，而不是全部硬编码在 Python 中。

每条正式记录建议保存 `_schema` 或等价 schema snapshot，包括当时的：字段名称、顺序、分组、行数、制造/包装子列、物料分组等。这样基础资料更新后，旧记录仍可按当时结构打开和导出。

## 两级表头与成对字段

当附件存在“品项切换人工 → 制造/包装”“启机人工 → 制造/包装”等两级表头时，应把父标题与叶子字段分开建模；Excel 导出要正确合并父标题单元格并保持叶子列对齐。

不得仅凭字段尾缀猜测成对关系；优先从模板、当前系统配置或明确命名规则中确认。

## 历史字段迁移

字段拆分/重命名必须提供旧字段到新字段的显式映射。例如旧单列字段升级为制造/包装双列时：

- 保留旧键以便审计和回滚；
- 新字段为空时才从旧字段迁移；
- 不覆盖用户已经录入的新字段；
- schema snapshot 同步升级，但已确认历史记录可按原结构保留；
- 为迁移逻辑编写回归测试。

## 审核不是默认功能

运营记录可能“保存即正式”，也可能需要审核。不得因为其他业务存在审核就自动加审核。若现有源码明确取消旧审核权限，应清理已废弃权限关系但保留历史字段兼容，不应让旧状态继续锁死记录。

## Excel 导出

若附件是固定运营表，应重点复刻：工作表名、标题、合并单元格、两级表头、行高、列宽、边框、对齐、打印区域、分页、签字空白区。若用户明确要求纸面签字，不要擅自改成电子签名画布。

## 权限

典型权限可拆为：查看本人、查看他人、新增、编辑本人、编辑他人、删除、导出、字段管理、基础数据管理、用户管理、权限管理、修改密码。最终权限名和粒度以附件为准。
