## 格式处理策略

| 格式 | 默认处理 | 不确定时的动作 |
| --- | --- | --- |
| `.xlsx` | 读取单元格值、公式结果、工作表名、隐藏行列与合并区域 | 公式结果缺失时要求用 WPS/Excel 重算后另存 |
| `.xls` | 使用可用的旧格式解析器或先转换副本 | 不覆盖原件；说明转换可能损失格式 |
| `.csv/.tsv` | 探测 UTF-8/GB18030、分隔符、引号与换行 | 探测冲突时让用户指定编码和分隔符 |
| `.docx` | 读取段落、表格、标题层级和页眉页脚 | 只把明确表格/标签映射为字段 |
| `.doc` | 先转换只读副本 | 转换不可用时列为阻断项 |
| `.pdf` | 提取文本、表格和页码定位 | 扫描件需 OCR；低置信结果不得直接入库 |
| `.json` | 校验语法、层级、数组和类型 | 混合类型字段需定义规范化规则 |
| 图片 | OCR 仅作为候选数据 | 人工复核后才能进入正式记录 |

不要把展示格式等同于业务含义。例如红色单元格可能是视觉强调，只有用户材料或规则明确说明时才代表异常状态。

## 来源追溯

为每个目标字段记录：

| 项目 | 内容 |
| --- | --- |
| 目标对象/字段 | 如 `work_order.completed_qty` |
| 来源文件 | 原始文件名与 SHA-256 |
| 来源位置 | 工作表、列名、页码、表格或 JSON 路径 |
| 转换规则 | 去空格、单位换算、枚举映射、舍入等 |
| 示例 | 脱敏后的原值与目标值 |
| 可信度 | 已确认 / 高 / 中 / 待确认 |
| 冲突处理 | 优先级、人工确认或拒绝导入 |

系统导入日志至少保留批次号、文件哈希、导入人、时间、成功数、失败数、逐行错误和重复判断键。

## 表格解析

1. 找到真实表头，不默认第一行就是字段名。
2. 保留原始列名，并生成稳定的内部字段名；同名列使用表名或业务域消歧。
3. 展开合并单元格时，只在业务含义明确时向下填充。
4. 识别小计、合计、说明行和空白分隔行，避免当成业务记录。
5. 同时检查可见值与公式。金额、数量等关键字段的公式和缓存结果不一致时阻断。
6. 隐藏工作表、隐藏列和筛选掉的行仍需在输入清单中披露。
7. 重复表头、跨页表头、单位行和多层表头需先规范化再映射。

## Word 与 PDF

- 先按标题、段落、表格、页码建立结构索引。
- 只有具有稳定标签、表头或重复结构的内容才自动映射为字段。
- 合同、制度和说明文字主要用于提取规则与流程，不直接生成虚构记录。
- PDF 表格跨页时检查表头重复与行断裂；扫描件记录 OCR 置信度和人工复核状态。
- 印章、签名图片只作为附件证据，不自动判断“已批准”。

## 字段和关系

优先识别自然主键：工单号、检验单号、设备编号、批次号、客户编码。没有可靠主键时生成内部 UUID，同时保留来源行定位；不要用行号作为长期主键。

建立关联前检查：

- 主表键是否唯一；
- 从表外键是否全部可匹配；
- 一个编号是否跨年月重复；
- 前导零是否被 Excel 丢失；
- 全角/半角、大小写和不可见空格是否造成伪差异；
- 同名人员是否需要工号或账号消歧。

## 金额、日期与单位

- 解析 `1,234.56`、`￥1,234.56`、`¥1 234.56` 和括号负数前先明确千位符与小数点规则。
- 保存原始文本、规范化 Decimal/整数分和币种；舍入方式必须写入规格。
- 含税价、未税价、税额和税率分字段保存，不能互相覆盖。
- 日期统一到明确时区；只含日期的业务字段不要擅自补 UTC 时间。
- Excel 1900/1904 日期系统需探测；`01/02/26` 等歧义日期阻断并确认。
- 数量同时保存数值和单位；箱、包、件、千克等换算必须来源明确并保留换算版本。

## 数据质量分级

### 阻断

- 主键大量重复或缺失；
- 审批状态、金额、数量或日期含义冲突；
- 关键表无法读取、加密或损坏；
- 跨表关系无法判定；
- 单位换算缺少可信规则；
- 真实数据可能被覆盖。

### 警告

- 可选字段缺失；
- 少量异常值可逐行排除；
- 扫描/OCR 结果等待人工复核；
- 存在旧格式或样式损失但数值可验证。

### 提示

- 字段命名、显示顺序、默认筛选和报表格式优化。

每条问题记录文件、位置、示例、影响、建议和是否需要用户决定。

## 导入与迁移

先预览、后提交。预览阶段不得写正式表。提交时使用事务：一个批次整体成功，或按用户确认的逐行策略明确记录部分失败。

重复导入使用文件哈希与业务唯一键双重判断。更新已有数据时显示前后差异；审批完成记录默认禁止批量覆盖。

迁移前备份，迁移后核对总行数、关键金额合计、状态分布、孤儿记录和随机抽样。所有差异写入迁移报告。

## 零静默失败标准

每个输入文件都必须出现在 `input-profile.json`。任何解析器拒绝、损坏、密码保护、编码冲突、工作簿 XML 异常或 PDF 结构异常，都不能简单跳过。每条问题必须记录：`code`、`severity`、`stage`、`location`、`cause`、`impact`、`action`、`resume_point`。

目录中只有个别文件失败时，先继续处理其余可读文件，并把总体状态设为 `partial_with_errors`；如果失败文件承载关键金额、审批、公式或主数据，再把该业务环节标为阻断。这样“部分可用”和“完全通过”不会混在一起。

对于 Excel，位置尽量定位到工作表、关系文件或 worksheet XML；CSV 定位到行；JSON 定位到行列；DOCX 定位到容器成员；PDF 至少定位到文件结构/页对象阶段。不能确定更细位置时必须写 `location=file`，不得省略。
