# 轻流系统搭建总地图

## 硬边界

开始前先锁定这些不可突破的规则：

1. 登录、切换工作区和系统搭建优先使用轻流 CLI/MCP，不用浏览器自动化代替可用接口。
2. 业务编号使用轻流系统默认编号；不增加手工编号和与系统流程重复的审核/审批状态字段。
3. 普通字段默认一行四个；引用字段一行最多两个，复杂引用单独一行。
4. 每个应用最终只保留表格、看板、卡片三个业务视图，顺序固定为 `table → board → card`，表格为默认入口。
5. 主表格视图查询条件只有一行、恰好三个字段，顺序为选项、日期、核心名称，且 `exact=false`。
6. 主从关系必须形成“创建下游记录、数据 ID 赋值、详情反向查看、必要回写”的闭环；默认最多三个列表自定义按钮，且不保留自定义顶部按钮。
7. Q-Robot 优先用引用字段承载的真实数据 ID 唯一更新；禁止用名称等可重复字段定位目标记录。
8. 流程每个业务节点都显式覆盖全部字段权限：本节点可编辑、必要历史只读、无关及未来字段隐藏。
9. 门户无快捷入口，只引用表格视图；必须有且仅有一个全宽“包含”筛选组件，PC 与移动端分别设计。
10. Word 打印占位符必须来自官方复制、有效模板或真实 `que_id` 的已验证编码，必须渲染校验。
11. 全部结构验收后，每个业务应用保留 3 至 5 条贴合场景的数据，不出现“模拟”“测试”“虚拟”等字样；已有业务基础字典按用户来源完整保留，不强行裁剪为样例数量。
12. 未通过回读验证不得报告完成；写入返回成功不等于最终状态正确。

## 加载规则

- `SKILL.md` 是唯一总入口。先在下面地图选择任务所需模块，只加载必要文件。
- 所有引用文件都与本文件同属一层，必须从本地图直接进入；不要把兄弟文件当作另一兄弟文件的必读前置。
- 引用文件中的兄弟链接只用于定位和返回，不形成嵌套加载链。
- 同时涉及多个路径时，按“基础应用 → 关系/流程 → 门户/打印 → 验收数据”加载对应模块。
- 生成打印占位符时直接使用 [qingflow_placeholder.py](scripts/qingflow_placeholder.py)，不要临时重写算法。

## 工具路由

- 应用、字段、排版、视图、按钮、关联资源、应用包导航、门户和图表：`qingflow-app-builder`。
- 已有字段上的工作流、节点、权限、分支和自动化：`qingflow-workflow-builder`。
- 记录新增、更新、删除：对应的 `qingflow-record-*` Skill，始终先读 Schema。
- Word 创建与渲染：`documents` Skill；占位符生成配合本 Skill 的脚本。
- 登录和工作区：轻流 CLI/MCP；仅在接口缺能力且用户允许时才考虑 UI。

## 核心流程

1. 用 CLI 确认账号、工作区、应用包、目标应用和权限。
2. 回读现有字段、布局、视图、按钮、关联资源、流程、门户、图表和数据量；不得基于名称猜测真实 ID。
3. 建立最小业务模型：基础数据、核心业务、下游过程、真实引用和回写方向。
4. 按系统编号、状态字段和表单布局规范搭建 Schema 与 Layout。
5. 遍历全部引用字段，形成“主应用 → 下游应用 → 引用字段 → 按钮/反向入口 → 回写”关系清单。
6. 配置业务按钮、反向关联资源和明确名称；所有当前记录赋值使用真实数据 ID。
7. 按需搭建流程、Q-Robot 和完整节点字段权限矩阵，不用冗余状态字段模拟流程。
8. 创建三个业务视图，删除其他视图，确保顺序、列顺序和唯一一行三个模糊查询条件正确。
9. 调整应用包导航为实际操作顺序；有数据看板时置顶，否则从首个业务操作应用开始。
10. 按任务选择门户路径或 Word 打印路径；不需要的分支不要加载、不要搭建。
11. 发布后回读真实配置；对写入失败、部分成功或读回待定状态先修复再继续。
12. 最后按依赖顺序录入业务数据，验证引用、自动填充、计算、流程、按钮和展示效果。

## 受控探索

- 允许根据行业和业务场景调整字段名称、分组、报表数量和视觉表达，但不得突破硬边界。
- 允许高度复刻用户指定的优秀门户，但必须剔除快捷入口、非表格视图、重复标题、重复绑定和移动端重叠。
- 当 CLI 契约与历史经验冲突时，以当前 `builder contract`、Schema、写入结果和发布回读为准。
- 遇到接口缺陷时先证明没有半写入，再采用最小修复；不得用重复创建掩盖错误。

## 完成闸门

结束前重新检查开头硬边界，并满足以下条件：

- 工作区、应用包和真实资源 ID 已确认；无误切换、无名称猜测。
- 无冗余手工编号和流程状态字段；表单与引用排版合规。
- 每个应用严格只有 `table + board + card`，顺序正确，查询条件只有一行三个字段。
- 所有主从关系有可操作入口或反向查看入口；列表按钮不超过三个且无自定义 `header` 按钮。
- Q-Robot 和按钮用真实数据 ID；流程节点权限覆盖全部字段。
- 门户仅含允许组件，唯一筛选器、PC/移动端布局、标题、指标名称和样式均已回读。
- Word 占位符、结构、单元格对齐和逐页渲染均已校验。
- 样例数据数量、语义、引用、计算和流程表现已回读；不会触发不必要的外部副作用。
- 只有实际发布态与预期一致后，才报告任务完成。
