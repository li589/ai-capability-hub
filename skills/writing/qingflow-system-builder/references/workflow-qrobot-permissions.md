## 8. 流程与状态回写

- 不新增字段模拟轻流审核节点或系统流程状态。
- 只有确实独立于审核流程的业务维度才设计业务状态，例如履约、发货、回款、库存或结算状态。
- 流程覆盖发起、审核、执行、确认和完成等必要阶段。
- 审核阶段直接使用轻流系统流程节点；独立业务状态才由明确业务动作或 Q-Robot 推进。
- 为流程节点配置处理角色和字段可编辑权限。
- 下游完成后回写核心应用的状态、累计金额、累计数量或完成进度。
- 多次发货、多次回款等场景使用累计逻辑，不简单覆盖历史值。
- 核心记录完结后限制关键字段修改。
- 看板和按钮需要表达审核进度时优先使用系统流程状态；需要表达履约、发货、回款等业务进度时才使用独立业务状态。

### 8.1 Q-Robot 更新节点唯一筛选

- 来源应用已有指向目标应用的引用/关联字段时，第一优先使用“目标应用数据 ID = 来源引用/关联字段”精确匹配。
- 轻流引用/关联字段底层保存的是被引用记录的数据 ID，因此该匹配天然唯一，不需要再冗余新增“目标数据 ID”或“目标系统编号”字段。
- 没有引用/关联字段、但已取得目标数据 ID 时，使用“目标应用数据 ID = 来源保存的数据 ID”。
- 只有无法取得引用字段和数据 ID 时，才使用轻流系统默认编号精确匹配；不要改用客户名称、产品名称、订单名称等非唯一字段。
- 系统编号可以作为没有引用关系时的后备定位条件，或在确有必要时作为附加校验；已有直接引用关系时不强制联合系统编号。
- 禁止使用模糊匹配、包含、前缀匹配或其他可能命中多条数据的条件执行更新。
- Q-Robot 执行更新前应确保筛选结果恰好为一条；零条或多条时停止更新并保留异常信息。
- 下游应用已通过真实引用/关联字段关联核心记录时，直接复用该字段供后续 Q-Robot 安全回写，不再创建重复的 ID 字段。
- 数据 ID 与系统编号只用于定位目标记录；业务金额、数量和状态仍按明确映射字段更新。

筛选优先级：

```text
1. 目标数据 ID = 来源引用/关联字段
2. 无引用字段时：目标数据 ID = 来源保存的数据 ID
3. 无引用字段和数据 ID 时：目标系统编号 = 来源系统编号
```

### 8.2 利冲审查申请示例

```text
来源应用：利冲审查申请
来源引用字段：关联案件项目
目标应用：项目立项申请
Q-Robot 节点：项目更新为不予承接

筛选条件：
项目立项申请.数据 ID = 匹配字段“利冲审查申请.关联案件项目”

更新内容：
项目立项申请.项目状态 = 不予承接
```

配置说明：

- “关联案件项目”已经指向“项目立项申请”的具体记录，其匹配值就是目标记录的数据 ID。
- 不要使用项目名称、客户名称或案件名称作为更新条件。
- 不需要为了 Q-Robot 再新增“关联项目数据 ID”或“关联项目编号”字段。
- 回读 Q-Robot 节点时，确认左侧为目标应用系统字段“数据 ID”，右侧为来源应用的引用字段“关联案件项目”。

## 9. 流程节点字段权限

### 9.1 强制权限模型

- 不要依赖分区标题的 `hide` 权限级联隐藏内部字段；轻流可能仍显示或开放分区内字段。
- 每个申请、填写、审批等业务节点必须显式声明全部表单业务字段的权限，不允许只声明本节点的可编辑字段。
- 申请人节点只开放首节点需要填写的字段；所有后续流程分区及其内部字段全部设置为 `hide`。
- 当前处理节点的业务字段设置为 `edit`。
- 已完成且当前判定需要参考的历史字段设置为 `readonly`。
- 无关字段、同级其他分支字段和所有未来节点字段设置为 `hide`。
- 独立业务状态字段只有在当前节点确实需要人工更新时才设置为 `edit`；不得新增或编辑冗余审核状态字段。
- 分区标题和分区内部字段都要配置权限，不能只处理其中一层。

### 9.2 分支与汇合节点

- 放行节点隐藏返工、报废处置等同级其他分支字段。
- 返工节点隐藏品质放行等同级其他分支字段。
- 汇合后的品质工程师节点只读展示判定所需的历史处理结果，隐藏责任改善和最终确认等未来字段。
- 责任部门节点只读展示问题、工程判定、处理结果和改善要求，只编辑原因、纠正措施和预防措施。
- 最终确认节点只读展示全部必要历史信息，只编辑确认结论、确认人、确认日期、关闭日期和确认意见。

### 9.3 更新与发布

- 调整已有流程时，先用 `builder flow get` 取得真实节点 ID。
- 优先使用 `patch_nodes` 更新节点 `attrs.fieldPermissions`，不得为修改权限而重建节点或改变节点 ID。
- 权限更新不得减少、重建或重新编号现有节点和连线。
- 发布后读取发布版本快照，不只读取草稿。
- 逐节点统计 `edit`、`readonly` 和 `hide`，确认每个业务节点覆盖全部表单业务字段。
- 重点检查申请人节点不存在后续流程字段的 `edit` 或 `readonly` 权限。
- 同时确认发布前后的节点数、连线数和条件分支数量保持一致。
