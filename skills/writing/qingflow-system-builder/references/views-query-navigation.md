## 5. 查询条件

每个应用必须配置查询条件：

```json
{
  "enabled": true,
  "exact": false,
  "hide_before_query": false,
  "rows": [
    ["业务状态", "业务日期", "核心名称"]
  ]
}
```

强制要求：

- 使用模糊查询：`exact=false`。
- 只设置三个查询字段。
- 三个查询字段放在同一行，不能拆成三行。
- 优先选择一个选项类型字段。
- 其次选择一个日期字段。
- 最后选择应用核心名称字段。
- 核心名称示例：物料名称、供应商名称、资产名称、客户名称、项目名称。
- 没有对应类型时选择最接近的有效标量字段，但仍保持三个字段同一行。

不要直接使用：

- 关联字段；
- 附件；
- 子表及子字段；
- 地址；
- Q-Linker；
- 代码块。

如果需要按关联业务查询，使用引用填充后的系统编号、名称或状态。

## 6. 固定三种视图

每个应用最终必须且只能保留以下三种业务视图：

1. 表格视图；
2. 看板视图；
3. 卡片视图。

规则：

- 三种视图全部真实创建，不能用同类型视图凑数。
- 每种类型只能保留一个目标业务视图。
- 视图展示顺序固定为：表格视图、看板视图、卡片视图。
- 表格视图必须位于第一位，并作为应用默认业务入口。
- 表格视图承担台账、查询和列表按钮。
- 看板视图按状态、类型或阶段等选项字段分组。
- 卡片视图展示系统编号、核心名称、负责人、日期和状态等摘要。
- 不保留甘特、地图或其他额外视图。
- 不保留轻流自动生成的“全部数据”“我的数据”，也不保留“我发起的”“待办视图”“已办视图”“抄送视图”等系统或历史视图；三个目标视图以外的所有视图都必须删除。
- 调整已有应用时，先回读全部真实 `view_key`，明确三个保留目标，再按真实键删除其余视图；不得按名称猜测或误删目标视图。
- 使用轻流支持的视图排序能力，将三个真实 `view_key` 按表格、看板、卡片排序；不得用删除重建来冒充排序。
- 排序后回读视图导航顺序。只有回读顺序确认为 `table → board → card` 时，才能报告表格为默认业务视图。
- 删除后再次回读，逐应用确认视图总数为3，且类型集合严格等于 `table + board + card`。
- 查询条件优先配置在主要表格视图，并按当前工具能力同步到必要视图。

### 6.1 表格视图列顺序

表格视图的 `columns` 按以下优先级排列：

1. 第一列优先选择一个选项类型字段，例如状态、类型、阶段、分类或处理结果；
2. 第二列放应用核心名称或标题字段，例如客户名称、供应商名称、项目名称、案件名称、申请主题；
3. 后续依次放外部单号、关键摘要、负责人、日期、金额、结论及其他业务字段。

补充规则：

- 第一列优先选择最能帮助用户快速分辨和筛选记录的单选/多选字段，通常先选业务状态，其次选业务类型或分类。
- 核心名称必须是可读的文本、标题或已填充的名称摘要；能使用“客户名称”“供应商名称”等标量字段时，不直接用关联字段代替。
- 如果应用没有任何合适的选项类型字段，核心名称字段改为第一列，并在验收结果中说明例外。
- 关联、附件、长文本、子表、代码块、Q-Linker 不作为第一列。
- 写入后回读 `columns`，逐应用验证实际第一列和第二列，不以预期配置代替回读。

### 6.2 应用导航顺序

- 应用包内的应用和数据看板必须按业务人员的实际操作顺序排列。
- 数据看板固定置于第一位；没有数据看板时，从首个业务操作应用开始。
- 其余应用依次按业务动作先后排列，不按创建时间、应用名称、应用 ID 或技术依赖排序。
- 客户业务示例：`数据看板 → 客户录入 → 客户跟进 → 客户报价`。
- 多条业务流程并存时，先排列主要业务流程，再排列次要流程；同一流程内部仍按实际操作先后排序。
- 基础配置或低频辅助应用没有明确操作位置时放在业务流程应用之后。
- 使用轻流支持的应用包导航排序能力调整真实应用或导航项，不通过删除重建应用实现排序。
- 排序后回读应用包导航。只有实际顺序与预定业务操作顺序一致时，才能报告排序完成。
