## 10. 回读验收

- [ ] 没有冗余手工编号字段。
- [ ] 没有与系统流程节点重复的审核状态或审批状态字段。
- [ ] 独立业务状态与系统流程状态已明确区分。
- [ ] 应用包导航第一位为数据看板；没有数据看板时从首个业务操作应用开始。
- [ ] 其余应用已按实际业务操作顺序排列，没有按创建时间、名称或技术依赖代替业务顺序。
- [ ] 应用包导航已回读，实际顺序与预定业务流程一致。
- [ ] 普通字段按一行四个排版。
- [ ] 引用字段每行不超过两个。
- [ ] 复杂引用字段没有与多个普通字段混排。
- [ ] 每个应用有且仅有三个视图。
- [ ] 三个视图的类型严格为表格、看板和卡片，各一个。
- [ ] 三个视图的展示顺序严格为表格、看板、卡片。
- [ ] 表格视图位于第一位并作为默认业务入口。
- [ ] 表格视图第一列优先为选项类型字段。
- [ ] 表格视图第二列为核心名称或标题字段。
- [ ] 没有合适选项字段的应用已记录列顺序例外。
- [ ] “全部数据”“我的数据”“我发起的”“待办视图”“已办视图”“抄送视图”等系统自动生成视图和其他历史视图均已删除。
- [ ] 每个应用都有三个字段同一行的模糊查询。
- [ ] 查询字段顺序符合选项、日期、核心名称优先级。
- [ ] 下游应用真实关联核心应用。
- [ ] 关联选择后自动带出关键字段。
- [ ] 核心应用可以创建并查看下游记录。
- [ ] 每个反向关联视图都已按下游业务语义命名，没有“全部数据”“我的数据”“关联数据”等默认或泛化名称。
- [ ] 关联视图只配置在数据详情关联区域，没有固定、置顶或加入应用业务视图列表。
- [ ] 关联视图名称、目标应用、引用字段、列表按钮和详情按钮使用同一真实主从关系。
- [ ] 已遍历全部引用字段并形成完整主从关系清单。
- [ ] 每个主应用默认表格视图的 `list` 列表自定义按钮不超过 3 个，除非用户明确要求突破上限。
- [ ] 下游关系不超过 3 条时已逐一配置列表按钮；超过 3 条时其余关系仍有 `detail` 按钮和反向关联入口，没有遗漏。
- [ ] 核心应用的重要关联按钮同时存在于表格字段/数据操作主按钮和数据详情主按钮。
- [ ] 只为明确主从关系配置了按钮，没有为了覆盖所有应用而增加无意义按钮。
- [ ] 已复用或修复既有按钮，没有创建同名、同目标的重复按钮。
- [ ] 表格视图不存在自定义 `header` 顶部按钮。
- [ ] 业务按钮只保留 `list` 与 `detail` 双入口，且两个位置都设置为主按钮。
- [ ] 关联按钮使用真实数据 ID 传递核心记录，并按需预填系统编号和关键摘要。
- [ ] 按钮编译结果确认来源为 `数据ID(-17)`，目标为正确的下游引用字段。
- [ ] 存在引用/关联字段时，Q-Robot 使用“目标数据 ID = 来源引用/关联字段”精确筛选。
- [ ] 已有直接引用关系时，没有为 Q-Robot 冗余新增目标数据 ID 或系统编号字段。
- [ ] 无引用关系时，Q-Robot 才使用保存的数据 ID 或系统编号精确筛选。
- [ ] Q-Robot 更新筛选只允许命中一条目标数据，未使用可能重复的名称字段。

## 11. 搭建完成后的业务样例数据

所有结构、流程、视图、按钮、门户和模板完成并验收后，必须为每个应用录入并保留 3 至 5 条业务样例数据。不得默认删除已有数据；只有用户明确要求清空时才执行清空步骤。

### 11.1 清空数据

- 从应用包回读全部真实 `app_key`，不得只处理当前可见的几个应用。
- 使用 `record list` 配合系统视图 `system:all` 读取记录；处理实际分页上限，确保收集的记录 ID 数量等于 `total_count`。
- 删除前保存应用、记录数量和真实 `record_id` 清单。
- 按“下游过程数据 → 主业务数据 → 产品与基础字典”的逆依赖顺序删除。
- 当前 CLI 的 `record delete` 需要显式传入 `view_id=system:all`；不使用自定义视图执行删除。
- 遇到配置校验失败且 `write_executed=false` 时按 CLI 修复提示调整；遇到 `write_executed=true` 或 `safe_to_retry=false` 时先回读，不盲目重试。
- 删除后重新读取全部应用，只有总记录数为 0 才能报告清空完成。

### 11.2 录入顺序

全部搭建完成后按依赖顺序录入：

```text
1. 基础字典、组织、成员映射、产品
2. 线索、客户、联系人
3. 商机、报价、合同
4. 客户订单、回款计划、收款、发票申请
5. 跟进记录、转交、认领、回退等过程数据
6. 公告、营销等辅助数据
```

- 每个应用先调用新增记录 Schema，读取必填字段、选项、子表、引用和联动要求。
- 引用数据必须指向本轮已创建的真实上游记录，优先使用记录 ID 或唯一可解析的自然值。
- 录入完成后回读记录，验证引用关系、自动填充和记录数量。
- 轻流系统编号自动生成，样例数据不手工编造冗余业务编号。
- 每个应用最终必须保留 3 至 5 条记录；不得遗漏基础、核心、下游、过程或辅助应用。

### 11.3 内容规范

- 数据应贴合行业、岗位、客户、产品、金额、日期和业务阶段等真实场景。
- 字段值中禁止出现“模拟”“测试”“虚拟”“样例数据”等说明性字样。
- 不使用“客户A”“产品1”“张三测试”等低质量占位内容。
- 公司、联系人、商品和业务描述可以使用合理构造的信息，但必须保持跨应用名称、金额、日期和引用关系一致。
- 每个应用保留 3 至 5 条，以覆盖主要业务状态且不过度堆积为准。

### 11.4 外部副作用

- 发邮件、真实数电开票、短信、支付、外部 API 和 Q-Robot 应用在写入前检查是否会立即触发真实动作。
- 如果创建记录会向真实地址发送内容、提交真实票务或调用生产接口，不得为了凑齐“所有应用”而执行；保留为空并在结果中说明。
- 只有用户明确授权真实外部动作并提供合法目标时才执行。
- 优先选择草稿、未提交或不会触发外部动作的安全状态录入；如果应用没有安全写入路径，明确记录该应用的阻断原因。
- [ ] 每个可安全写入的应用最终保留 3 至 5 条业务样例数据。
- [ ] 样例数据贴合当前业务场景，字段值未出现“模拟”“测试”“虚拟”“样例数据”等说明性字样。
- [ ] 基础、核心和下游数据按真实引用关系连接，跨应用名称、金额、日期和状态一致。
- [ ] 流程推进和独立业务数据回写均已完成，未用自建字段模拟系统审核状态。
- [ ] 每个流程业务节点显式覆盖全部表单业务字段权限。
- [ ] 申请人节点仅首节点字段可编辑，所有后续字段均隐藏。
- [ ] 当前节点字段可编辑，必要历史字段只读，无关及未来字段隐藏。
- [ ] 分区标题与分区内部字段均已配置权限。
- [ ] 分支节点隐藏同级其他分支字段。
- [ ] 发布快照中的节点数、连线数和条件分支未因权限调整发生变化。
- [ ] 所有修改均已发布并回读验证。
