## 7. 应用间连贯性

多应用方案不能只是多个独立表单，必须同时具备：

- 下游应用真实关联核心应用；
- 关联选择后引用填充关键字段；
- 核心应用提供创建下游记录的当前记录按钮；
- 按钮使用“数据ID → 下游关联字段”传递当前记录；
- 核心详情可以查看全部相关下游数据；
- 下游详情可以查看或返回核心记录；
- 相关应用之间的金额、数量、状态和进度可以通过流程更新。

创建按钮、关联资源和回写逻辑必须使用同一真实关系字段。

### 7.1 核心应用关联业务按钮

- 只有存在明确主从关系时才配置按钮；基础字典、纯明细展示和没有下游动作的应用不为凑数量增加按钮。
- 必须遍历应用包内全部应用的引用字段，形成“主应用、下游应用、下游引用字段、目标按钮”关系清单；不能只根据应用名称或当前可见页面判断主从关系。
- 只要下游应用存在指向主应用的业务引用字段，就视为明确主从关系，并必须提供从主记录进入该下游业务的操作或查看入口。
- 每个主应用默认表格视图最多保留 3 个 `list` 列表自定义按钮。下游关系不超过 3 条时必须逐一配置列表按钮；超过 3 条时按业务频率、重要性和操作闭环优先选择 3 个，其余关系配置 `detail` 数据详情按钮和反向关联入口。
- 只有用户明确要求时才允许某个主应用的列表自定义按钮超过 3 个；不得为了覆盖全部关系而默认堆叠大量列表按钮。
- 每条真实下游引用关系都必须与明确的按钮或反向关联入口对应，不得遗漏；列表按钮数量上限不等于删除其他业务关系。
- 写入前回读按钮目录和表格视图绑定。已有同义按钮时优先按 `button_id` 修复触发目标、赋值和位置，不重复创建。
- 目标应用必须有真实引用字段指向当前主应用。若业务明确要求直接创建，但目标引用字段不存在，应先补充单选引用字段并回读验证；不得把当前数据 ID 填入文本字段。
- 同一关联动作必须同时绑定表格视图的 `list` 数据操作主按钮和 `detail` 数据详情主按钮，两个位置都设置 `primary=true`。
- 上一条适用于进入列表区的最多 3 个核心动作；超过列表上限的其他下游关系只保留 `detail` 主按钮和反向关联入口。
- 表格视图禁止保留自定义 `header` 顶部按钮。调整旧系统时，保留按钮本体及 `list`/`detail` 绑定，只删除 `header` 绑定。
- 按钮从当前核心记录传递真实数据 ID 到下游引用字段，并按需预填系统编号、客户、日期、负责人、金额等摘要。
- 相关按钮必须使用同一真实引用字段，不得仅传递名称、客户名、产品名等可能重复的文本。
- 核心详情中配置反向关联资源，能够查看按钮创建出的全部下游记录。
- 按钮名称使用明确业务动作，例如“新建销售开票”“登记销售回款”，不要使用“新建数据”“关联操作”等模糊名称。
- 发布后回读按钮目录和视图绑定，确认没有重复按钮；进入列表区的核心按钮恰好具有 `list`、`detail` 两种业务位置，超过列表上限的其他按钮只具有 `detail` 位置，且每个主应用的 `list` 按钮不超过 3 个。
- 检查写入结果的 `compiled_match_rules`：来源必须为系统字段 `数据ID(-17)`，目标必须为预期引用字段。

### 7.2 反向关联视图命名

- 本节“关联视图”指主应用数据详情页中展示下游记录的反向关联组件，只配置在数据详情关联区域，不固定、不置顶、不加入应用左侧或顶部的业务视图列表。
- 关联视图不属于应用导航中的表格、看板、卡片三个业务视图，也不改变“三种业务视图”的数量限制；应用视图列表始终只保留这三个业务视图。
- 每条主从引用关系都必须检查关联视图的显示名称；不得直接沿用下游默认视图名称。
- 关联视图名称必须描述当前主记录下的下游业务集合，优先使用“业务对象 + 记录/明细/历史”的短名称。
- 禁止使用“全部数据”“我的数据”“我发起的”“待办视图”“关联数据”“相关数据”“数据列表”等默认、系统化或语义不清的名称。
- 关联视图名称应与对应按钮和下游应用语义一致，但不要机械照搬完整应用名；例如按钮“客户跟进”对应关联视图“跟进记录”，按钮“客户报价”对应关联视图“报价记录”。
- 同一主应用关联同一下游应用的多个引用字段时，按关系用途分别命名，例如“发货记录”“退货记录”，不能使用相同标题造成混淆。
- 调整已有系统时，先回读关联资源或关联视图的真实 ID，优先原位修改显示名称，不通过重复创建新组件实现改名。
- 如果历史配置把关联视图固定或加入了应用视图列表，应移除该导航或固定关系，但保留数据详情中的反向关联组件及其真实引用筛选。
- 发布后回读主应用详情的全部关联组件，逐一核对名称、目标应用、引用字段和筛选关系一致。

客户管理示例：

```text
主应用：客户信息库
下游应用：客户报价
下游引用字段：关联客户
按钮：客户报价

主应用：客户信息库
下游应用：客户跟进
下游引用字段：关联客户
按钮：客户跟进

客户信息库默认表格视图必须同时存在：
- list 主按钮“客户报价”
- list 主按钮“客户跟进”
- detail 主按钮“客户报价”
- detail 主按钮“客户跟进”

赋值跳转：
- 当前客户信息库数据 ID -> 客户报价.关联客户
- 当前客户信息库数据 ID -> 客户跟进.关联客户

客户信息库详情关联视图：
- “报价记录” -> 客户报价.关联客户
- “跟进记录” -> 客户跟进.关联客户

禁止命名：
- “客户报价-全部数据”
- “客户跟进-我的数据”
- “关联数据”
```

推荐配置：

```text
placement=list, primary=true
placement=detail, primary=true
禁止 placement=header

field_mappings:
source_field=数据ID
target_field=下游引用字段
```

销售订单示例：

```text
核心应用：销售订单
关联应用：销售开票、销售回款登记

表格视图数据操作主按钮：
- 新建销售开票
- 登记销售回款

数据详情主按钮：
- 新建销售开票
- 登记销售回款

传值规则：
- 当前销售订单数据 ID -> 下游“关联销售订单”
- 当前销售订单系统编号 -> 下游“销售订单编号摘要”
- 客户、订单金额、负责人 -> 下游对应引用或预填字段
```
