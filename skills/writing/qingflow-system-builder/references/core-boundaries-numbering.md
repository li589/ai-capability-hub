## 本模块职责

本文件只负责“执行边界、系统编号与状态字段”相关的详细规则、示例与验收点。执行其他路径时从总地图直接加载对应模块，不从本文件递归加载。

## 1. 执行边界

- 登录、切换工作区和系统搭建只使用轻流 CLI/MCP，不使用浏览器自动化。
- 操作前确认账号、工作区、环境、应用包和目标应用。
- 写入前先回读，写入后再次回读。
- 遇到超时、`partial_success`、`write_executed=true` 或 `safe_to_retry=false` 时先回读，不直接重复写入。

## 2. 系统编号

- 所有原本需要用户手工填写的编号字段改用轻流系统默认编号。
- 不新增“订单编号”“单据编号”“项目编号”“任务编号”等冗余字段。
- 不用流程额外生成一个与系统编号重复的编号。
- 关联字段的展示字段优先使用系统默认编号。
- 按钮和关联匹配使用真实数据 ID，不使用显示编号代替数据 ID。
- 只有客户明确要求保存外部系统编号时才新增字段，并命名为“客户 PO”“ERP 单号”“外部单号”等。

### 2.1 禁止冗余审核状态

- 不新增“审核状态”“审批状态”“当前审批节点”“当前流程状态”“流程状态”等用于复刻轻流流程节点的字段。
- 轻流系统流程节点和系统流程状态已经能反映记录处于申请、审核、填写、退回或完成等阶段，直接使用系统能力。
- 不用 Q-Robot、公式或人工填写字段重复维护系统流程状态。
- “订单履约状态”“发货状态”“回款状态”“库存状态”等独立业务状态可以保留，但必须表达流程节点以外的业务事实。
- 调整已有应用时，不直接删除已有状态字段；先判断它是独立业务状态还是冗余审核状态，再决定保留、停用或迁移。
