## 1. 能力边界

- 使用轻流当前 Word 打印模板能力。
- 在本地完成 `.docx` 样式，再写入真实轻流字段占位符。
- 不配置已下架的旧版在线打印设计器。
- 不因为 Builder MCP 缺少 Word 上传工具而回退到旧能力。

## 2. 占位符来源

按以下优先级获取：

1. 用户从轻流 Word 打印模板配置中复制的官方占位符。
2. 已存在且确认可用的轻流 Word 模板。
3. Builder MCP 返回的真实 `que_id` 加已验证的编码脚本。

禁止：

- 根据字段名称猜测 Token；
- 根据应用 key 猜测字段 ID；
- 跨应用或跨工作区复用 Token；
- 把普通 `field_id` 文本直接放入 `$$...$$`；
- 声称 CLI 已返回占位符，但实际只返回了 `que_id`。

## 3. que_id 编码

Builder MCP 的字段配置通常包含：

```json
{
  "name": "订单号",
  "field_id": "field_462116040",
  "que_id": 462116040
}
```

运行：

```bash
python3 scripts/qingflow_placeholder.py \
  --que-id 462116040 \
  --title "订单号"
```

输出：

```text
{订单号$$47445B6B8$$}
```

子表字段：

```bash
python3 scripts/qingflow_placeholder.py \
  --que-id 462116053 \
  --parent "检验明细" \
  --title "产品型号"
```

输出格式：

```text
{检验明细 · 产品型号$$编码$$}
```

已知验证向量：

```text
462116040 -> 47445B6B8
462116041 -> 47445B6B9
3         -> ROXC
```

该编码逻辑来自轻流打印模块的前端实现，不属于稳定公开 CLI 接口。轻流升级后如果生成结果不能被识别：

1. 停止批量生成。
2. 从当前轻流界面复制一个相同字段的官方占位符。
3. 对比官方 Token 与脚本结果。
4. 重新检查当前打印模块的编码实现。
5. 更新脚本和验证向量后再继续。

不要硬编码历史 CDN 文件名或压缩函数名，它们会随版本变化。

## 4. 字段映射

生成模板前建立清单：

| 项目 | 内容 |
| --- | --- |
| 应用名称 | 当前打印模板所属应用 |
| app_key | 当前工作区真实 key |
| 字段名称 | 轻流字段标题 |
| que_id | Builder MCP 返回的数字 ID |
| 字段类型 | 文本、日期、成员、子表等 |
| 父子关系 | 是否属于子表 |
| 占位符 | 官方复制或脚本生成结果 |
| 使用位置 | 标题、信息区、明细、合计、签章 |

规则：

- 普通字段：`{字段名称$$编码$$}`。
- 子表字段：`{子表名称 · 子字段名称$$编码$$}`。
- 系统字段也必须使用其真实 `que_id`。
- 同名字段按 `que_id` 区分，不能只按名称匹配。
- 关联字段、引用字段、成员字段和公式字段先用官方样例验证输出格式。
- 子表明细只保留一行占位符数据行，由轻流打印时扩展。
