## 5. Word 版式

### 5.1 页面

- 明细列较多时使用 A4 横向。
- 信息少、明细列少时可以使用 A4 纵向。
- 设置明确页边距、页眉距离和页脚距离。
- 避免大面积无意义留白，但不要为了填满页面拉伸表格。

### 5.2 表格

- 设置固定表格布局和明确列宽。
- 表格总宽度不得超过页面可用宽度。
- 所有单元格强制上下居中。
- 段前、段后归零。
- 单元格上下内边距保持对称。
- 表头使用统一行高并设置跨页重复。
- 明细数据行使用最小行高，不使用可能裁切内容的固定高度。
- 金额、数量、日期和状态按统一规则对齐。
- 备注字段使用足够宽度并允许自动换行。

### 5.3 结构

推荐结构：

1. 品牌抬头；
2. 单据标题；
3. 基础信息区；
4. 明细表；
5. 合计区；
6. 备注或条款；
7. 审核、确认和签章区；
8. 页脚。

双语模板保持中文与英文层级一致，不把英文单独挤到另一行或另一列。

## 6. 制作流程

1. 使用 Builder MCP 读取字段配置并获得 `que_id`。
2. 建立字段和占位符映射表。
3. 对一个普通字段、一个系统字段和一个子表字段做验证。
4. 使用 `documents` Skill 和工作区依赖创建或修改 `.docx`。
5. 如果用户提供现有模板，先读取其页面、表格、图片和占位符，再进行样式优化。
6. 如果用户只提供 Excel 表单，先还原业务结构，再设计适合 Word 打印的版式。
7. 每个占位符使用单独且连续的 Word 文本运行。
8. 不对占位符内部字符设置不同格式。
9. 保存为新文件，不覆盖用户原始模板，除非用户明确要求。
10. 渲染并检查后再交付。

## 7. 校验

### 7.1 占位符

检查 Token：

```bash
unzip -p "template.docx" word/document.xml \
  | rg -o '\$\$[A-Z0-9-]+\$\$' \
  | sort -u
```

验证：

- 所有预期字段都有 Token；
- 没有多余 Token；
- 没有跨工作区 Token；
- 子表字段名称和父表名称正确；
- Token 未被 Word 拆分；
- 修改已有模板时，输入输出 Token 多重集合一致。

### 7.2 文档结构

- `.docx` 可以被 `python-docx` 重新打开。
- ZIP 包完整。
- 页面方向和尺寸正确。
- 表格列宽总和正确。
- 单元格上下居中。
- 表头跨页重复。
- 明细行不被裁切。

### 7.3 渲染

使用 `documents` Skill 的 `render_docx.py`：

- 生成 PDF 和每页 PNG；
- 检查实际页数；
- 逐页检查越界、裁切、重叠、额外空白页和页脚贴边；
- 修改后必须重新渲染最终版本。

渲染环境缺少中文字体时，方框只代表预览字体缺失；仍需通过 XML 和文档结构确认中文文本存在，并优先选择 Word 可用的中文字体。

## 8. 上传与交付

- 如果当前 Builder MCP/CLI 提供 Word 打印模板上传能力，先读取工具 schema，再上传并回读验证。
- 如果没有公开上传能力，交付本地 `.docx`，明确由用户在轻流后台上传。
- 不使用浏览器自动化代替缺失的上传工具。
- 最终只交付用户需要的 `.docx`；QA PDF 和 PNG 保留在临时目录，除非用户明确要求。

## 9. 常见错误

### 占位符无法识别

- `que_id` 来自错误应用或工作区；
- 使用了字段名称而不是真实 ID；
- 编码规则已经变化；
- 占位符被 Word 拆分成多个文本运行；
- 子表父名称或分隔符错误；
- Token 中混入空格、全角符号或样式标签。

### 打印后单元格不齐

- 行高完全自动且不同单元格段落行距不一致；
- 单元格上下内边距不对称；
- 段前段后未归零；
- 表头存在不同字号或多余空段落；
- 使用固定明细行高导致内容裁切。

### 模板看起来正常但数据不替换

- Word 只是显示了伪造占位符；
- Token 属于另一个应用；
- 字段已经删除重建，`que_id` 发生变化；
- 使用了旧版打印能力的字段格式；
- 模板没有在正确应用中配置。
