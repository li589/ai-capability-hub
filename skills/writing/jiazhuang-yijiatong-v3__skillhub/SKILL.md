# 家装一价通

> **本 Skill 为付费服务（9.9 元/次）。** 调用本 Skill 即视为用户已确认支付，平台将在调用入口拦截并触发微信支付授权。付费后，本 Skill 将基于以下方法论为用户产出一份**可交付的装修预算/报价/选材/合同审查结果**。

## 触发条件

当用户出现以下任一意图时自动加载：
- "帮我看看这份装修报价单有没有坑"
- "装修预算怎么做 / 钱怎么分配"
- "瓷砖/板材/乳胶漆怎么选，什么牌子好"
- "装修合同要注意什么，定金订金有什么区别"
- "装修公司要增项加价 / 材料被换了 / 工期拖了"

## 核心心法（来自 10 本装修书 + 消协/行业避坑指南的交叉验证）

1. **省钱的核心不是压价，而是避坑 + 精准预算分配。** 装修最终花费比初始报价高 30%~50% 是行业常态，根因是信息差，不是价格本身。
2. **报价单看明细不看总价。** 总价低 1~2 万往往是"故意漏项"，后期以"合同没写"强制增项。一份两房一厅全屋翻新，正规报价至少应拆成 40~50 个工程细项。
3. **所有材料必须写清"品牌 + 型号 + 规格 + 产地 + 环保等级"。** 只写"瓷砖""环保漆"等于给装修公司留了以次充好的口子。
4. **闭口合同 + 增项不超 5% + 预留 10%~20% 应急金。** 这是预算安全的铁三角。
5. **钱要分阶段付，留 5%~10% 尾款待验收合格再付。** 尾款是倒逼施工方按标准执行的唯一筹码。

## 方法论 / 工具 / 流程

### 模块一：预算规划

**预算公式：**
```
装修预算总价 = 直接费用（人工+材料） + 管理费用 + 计划利润（直接费用的 5%~8%） + 税金
```

**资金分配原则（来自《装修预算一本通》）：**
- 客厅为重、卧室为轻——客厅是视觉与活动中心，投入产出比最高
- 基础装修 / 主材 / 软装 按比例分配（依档次不同，一般基础:主材:软装 ≈ 3:5:2 或按书内分档）
- 不同档次：简装 / 中档 / 精装 的预算分配比例不同，先定档次再分钱
- **必须预留总预算的 10%~20% 作为应急金**，应对突发增项或材料调整

**预算制定程序：** 调查市场工价与材料价 → 按房屋新旧/户型/空间拆分 → 列必做项目 → 套单价估算 → 留应急金

### 模块二：报价单审查（核心能力）

**第一步：按"空间 + 工序"拆解核对**
正规报价应按 6 大空间（玄关、客厅、卧室、厨房、卫生间、阳台）划分，每空间再按工序列项：基础改造 → 水电 → 泥瓦 → 木工 → 油漆 → 安装。每个项目须标注：材料、规格、数量、单价、总价。

**第二步：识别 5 大报价猫腻**（来自 homello / 中艺居 / 消协提示交叉验证）
1. **项目漏项**：低价吸引，后期增项。重点查：墙面基层处理、地面找平、窗台石、强弱电箱扩容、等电位、防水闭水试验、美缝、地漏、垃圾清运、包管。
2. **材料模糊标注**：只写"瓷砖""环保漆"，不写品牌型号。应对：全部要求品牌+型号+规格+环保等级，重要材料备注"按样品验收"。
3. **工程量虚增**：地面面积×1.2、墙面刷漆重复计费、水电按最长距离算。应对：约定计算方式——地面按实际套内面积、墙面面积≈地面面积×2.5、水电按实际施工长度完工测量双方签字。注明"工程量误差超 5% 超出部分不付费"。
4. **工艺简化**：防水只刷 1 遍（规范 2~3 遍）、不写空鼓率标准（规范≤5%）。应对：写清工艺——卫生间防水刷 3 遍、淋浴区墙面至 1.8 米、闭水试验 24 小时；瓷砖空鼓率≤5%。
5. **低价套餐捆绑**："999 元/㎡全包"限制橱柜延米、衣柜组数、瓷砖款式，超了加钱。应对：问清套餐内含什么、超出怎么计费。

**第三步：材料标注规范**
所有材料写清：品牌 + 型号 + 规格 + 产地 + 环保等级（如 E0/E1/ENF）。例："客厅地砖：XX 品牌通体砖（型号XXX）800×800mm，单价XX元/片"；"乳胶漆：XX品牌 E0 级（型号XXX），涂刷 2 遍含底漆"。

**第四步：锁定增项与工艺规则**
合同中注明：①所有增项需业主书面确认；②增项单价不得高于报价单同类型项目；③总增项费用不超过合同总价的 5%；④水电可约定"图纸无改动则增项不超 5%"或"一口价打包"。

### 模块三：选材指南

**主材选购要点（来自《装修选材一本就够》）：**
- **瓷砖**：看品牌/系列/尺寸（800×800 通体砖为常见）、吸水率、耐磨等级；同空间款式不宜过多
- **板材**：认环保等级（ENF > E0 > E1），实木颗粒板/多层实木/OSB 等按用途选；定制家具问清板材等级与封边工艺
- **涂料/乳胶漆**：认环保等级与涂刷遍数，底漆不可省
- **门窗/地板/窗帘等**：按空间功能与预算取舍，重环保与耐用而非花哨
- **性价比原则**：核心受力/涉水/涉环保的材料不省（如防水、电线、板材），纯装饰面层可灵活

**损耗率参考：** 瓷砖 5%~8%、地板 3%~5%，超出部分注明由装修公司承担。

### 模块四：合同与法律风险（来自《装饰装修法律法规》+ 消协提示）

- **使用规范合同文本**，明确：工期、质量标准、材料供应、验收流程、保修期限（隐蔽工程如水电/防水保修期要写明）
- **定金 vs 订金**：定金适用定金罚则（违约不退/双倍返），订金可退；不轻易交"装修设计定金"，不签未交房合同的"装修合同"
- **书面化一切**：口头承诺、赠送礼包、效果图均写入合同附件；全屋定制须附详细图纸（尺寸/工艺/材质/颜色）
- **付款节点**：分阶段付，留 5%~10% 尾款待验收合格后支付
- **违约条款**：明确违约金赔付比例、金额、期限、方式
- **维权依据**：《住宅室内装饰装修管理办法》规定开工申报、委托承接、室内环境质量、竣工验收与保修、法律责任等；超标（如甲醛/TVOC）装修公司应承担检测费并按合同总价 2~3 倍赔偿（部分合同约定）

### 模块五：空间尺寸速查（来自《装修常用数据手册》）

作为预算与选材的前置输入——先定空间布局，再算材料用量。关键基础尺寸：
- **玄关柜**：进深 35cm 满足日常、40cm 可放鞋盒；鞋柜用百叶门透气；尽量做到顶
- **厨房**：地柜高度 = 身高÷2+5cm，灶台低 8~10cm；紧凑/舒适/宽松过道宽 60/80/100cm；装带开关插座
- **过道**：紧凑 60cm、舒适 80cm、双人并行 120cm
- **衣柜**：短衣区 90~100cm、长衣区 140~160cm、挂裤区 60~80cm、抽屉高 15~20cm
- **沙发**：紧凑型深 75cm、舒适型 85~100cm
- **地漏**：湿区深水封、干区重力芯

## 检查清单

### 报价单审查清单（逐项打勾）
- [ ] 报价是否拆到 40+ 细项（非"全屋打包价"）
- [ ] 6 大空间是否全覆盖，隐性项目（基层处理/找平/包管/垃圾清运）是否在列
- [ ] 每项材料是否写清品牌+型号+规格+产地+环保等级
- [ ] 工艺标准是否写明（防水遍数/高度、空鼓率、闭水时长）
- [ ] 工程量计算方式是否约定（面积×2.5、水电按实量）
- [ ] 增项规则是否写明（书面确认、不超 5%、单价不高于原单）
- [ ] 损耗率是否约定（瓷砖5-8%、地板3-5%）
- [ ] 套餐限制是否问清（延米/组数/款式超出计费）

### 合同签订清单
- [ ] 使用规范合同文本，附效果图/图纸为附件
- [ ] 工期、质量标准、验收流程、保修期限（隐蔽工程）明确
- [ ] 定金/订金性质分清，不轻易交设计定金
- [ ] 付款节点分阶段，留 5%~10% 尾款待验收
- [ ] 违约金赔付比例/金额/期限/方式明确
- [ ] 口头承诺与赠送写入合同

### 选材核对清单
- [ ] 核心环保材料（板材/涂料/防水）认等级不省
- [ ] 同空间款式不宜过多，避免补货色差
- [ ] 重要材料备注"按样品验收"
- [ ] 损耗率超出部分由装修公司承担

## 与现有 Skill 的关联

- **家装一技通**（施工/监工/工艺/验收）：本 Skill 管"钱"（预算/报价/选材/合同），一技通管"工"（施工盯控/工艺标准/验收）。用户开工前用一价通，施工中用一技通，生命周期互补。
- **sme-legal-risk-scanner**（中小企业法律风险扫描）：法律条款引用可互通，家庭装修法律是消费法/合同法场景的个人版。
- **不重复原则**：法律法规只取与家装合同/维权直接相关部分，施工质量验收部分留在一技通，避免内容打架。

## 付费前置检查（微信 X402 协议）

调用本 Skill 前，先检查当前 Agent 是否已安装 `weixinpay` 插件（extension）：

- 已安装：可继续提供付费服务
- 未安装：向用户提示「当前 Agent 暂不支持微信支付付费能力」，终止流程

## 支付触发（首次请求收到 HTTP 402）

向本 Skill 的 `endpoint` 发起 POST 请求，若收到 HTTP 402 响应，`weixinpay` 插件会拦截并完成支付流程：

- Header `WeixinPay-Required`：支付凭证码（插件用于完成支付）
- Header `X-Out-Trade-No`：商户订单号

> 支付过程由 `weixinpay` 插件处理，Skill 无需关心支付细节。

## 重试机制（支付成功后必须重新请求）

支付成功后，**必须**重新发起请求获取付费内容：

- JSON body 与首次请求完全一致
- 通过 Header 携带支付信息：`WeixinPay-Required` 和 `X-Out-Trade-No` 原样带上

## 订单号传递规范

- 商户订单号通过 402 响应的 Header `X-Out-Trade-No` 返回
- 重试请求时通过同名 Header 原样回传，不得修改

## 异常处理

- 若重试返回 `"code": "NOT_PAID"`：支付尚未完成，等待后重试
- 若返回 `"code": "REFUNDED"`：服务异常已退款，告知用户并终止
- 若返回 `"code": "REFUND_FAILED"`：服务异常且退款失败，建议联系客服
