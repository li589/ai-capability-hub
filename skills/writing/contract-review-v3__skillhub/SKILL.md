## 零、法规时效性原则（动态版本确认铁律，必读）

本 Skill 的内化边界必须严格切分「知识层」与「法规版本层」——这是本 Skill 能否跨年度长期可用的核心，执行者被调用时务必遵守。

### 0.1 两层切分
- **知识层（Skill 内置，相对稳定）**：合同审查方法论、10 类合同审查要点、风险清单逻辑、修改建议框架。这部分源于书籍内化，跨年度变化慢，可直接调用。
- **法规版本层（运行时确认，逐年剧变）**：具体法条文本、条文序号、施行日期、修订/修正/废止状态、罚则数额、司法解释、部门规章与地方性法规版本。**法律持续修订——民法典合同编及配套司法解释持续更新，具体法条序号与裁判口径可能变化。Skill 内置的年份/版本只是成书时点快照，绝不保证"现行有效"。**

### 0.2 版本确认铁律（最关键）
- 用户在 **N 年**调用本 Skill → 涉及的具体法规，必须确认其 **N 年（或最新）现行有效文本与修订状态**。
- 本 Skill 内化的书籍多为 **2024 年及以前**成书（基于已出版书籍与公开资料），其引用的法条版本可能已修订、已废止或已有新司法解释。**2025 年及以后调用，严禁直接引用内置年份版本作答具体条款，必须先在线确认。**

> 结论：执行者被调用时，**涉及具体法条/罚则/版本状态的问题，第一步先在线确认现行有效文本**，再作答。Skill 内置的任何法条年份、条文序号都只是"成书时点参考"，不是现行答案。

### 0.3 必须在线确认的情形（缺确认不可断言"现行/有效/已修订/未修订"）
1. 具体法条条文、序号、罚则数额（如赔偿金倍数、罚款区间、刑期）。
2. 法规的施行日期与修订/修正/废止状态（是否已被新法替代）。
3. 最新司法解释、部门规章、地方性法规版本。
4. 行业特殊合同（如建设工程、知识产权许可）关联法规。

### 0.4 推荐官方数据源（优先级从高到低）
- **全国人大法律法规数据库**（flk.npc.gov.cn）：法律、司法解释权威文本。
- **国务院政策文件库 / 司法部**：行政法规、部门规章。
- **最高人民法院**：司法解释与指导案例。
- **各部委官网**：市场监管总局、人社部、发改委、财政部等对应领域最新规定。

### 0.5 执行者动作规范
- 凡用户问"某法第 X 条怎么规定""罚多少""现在还有效吗""已经修订了吗"等，**必须先联网确认现行有效文本再作答**，不得以 Skill 内置年份版本断言"现行/已修订/未修订"。
- 若在线确认失败，必须明确告知"未核实最新版本、结论仅供参考"，并给出官方查询路径，**不得编造任何法条/罚则/版本状态**。
- Skill 内若引用具体法条年份，一律标注「成书时点版本，以官方最新文本为准」。

# 合同审查专家

## 一、快速定位：你要审查什么合同？

调用本 Skill 前，先明确以下 4 个问题，决定审查重心：

| 问题 | 选项 | 审查重心 |
|------|------|----------|
| 1. 合同阶段 | 谈判前 / 起草中 / 已签署 / 履行中 / 纠纷后 | 谈判前重交易模式；履行中重证据与变更 |
| 2. 合同类型 | 买卖 / 租赁 / 借款担保 / 建设工程 / 技术 / 服务 / 股权转让 / 保密 / 其他 | 跳到第五部分“分类合同审查要点” |
| 3. 你的角色 | 甲方（付款/收服务） / 乙方（收款/提供服务） / 居间 / 法务中台 | 决定审查立场、尺度、模式 |
| 4. 交付物形式 | 清洁版合同 / 痕迹版批注 / 审查意见书 / 条款修改建议 | 决定输出格式 |

> **核心心法**：合同审查不是“找茬比赛”，而是 **在防范风险与促进交易之间找平衡**。律师/法务的价值是告诉当事人“怎么行”，而不只是“这个不行”。

---

## 二、审查前准备：三个基本前提

任何合同审查前，必须先确认以下三前提（来自张海燕《合同审查思维体系与实务技能》），否则修改可能不切实际。

### 2.1 修改立场：你代表谁？

- 明确委托人是合同中的哪一方（或关联方）。
- 从委托人合同主体身份出发，判断条款是权利还是义务。
- **红线**：不能站到对方立场修改，否则南辕北辙。

### 2.2 修改尺度：谈判地位如何？

| 谈判地位 | 修改策略 |
|----------|----------|
| 委托人优势明显 | 可大幅倾斜权利条款、收紧对方义务 |
| 双方势均力敌 | 以完善内容、增强可操作性为主，权利义务对等 |
| 委托人处于劣势 | 底线问题必须改；非底线问题力争权利；避免过度修改导致交易破裂 |

### 2.3 修改模式：客户需要什么形式？

- **清洁修改模式**：直接生成修改后干净文本，适合商务谈判。
- **痕迹修改模式**：保留修订痕迹+批注，适合内部审批和与对方博弈。
- **意见书模式**：只出法律意见书+条款建议，不动原文，适合重大合同或外部律师服务。

> 选择原则：以客户习惯和场景为准，不强行固定。

## 三、四步审查法：从宏观到微观

### 步骤1：审查交易模式——先搞清“干什么、怎么干”

- 识别合同当事人之间的法律关系（买卖、租赁、借贷、委托、承揽、技术许可等）。
- 判断交易是否合法合规，是否存在无效或可撤销风险。
- 提炼交易主体、付出内容、获取内容、交易对价、履行方式。
- 对新型或复杂交易（如 PPP、融资性贸易、对赌、VIE、分布式光伏），需补充行业知识或请专业律师复核。

### 步骤2：审查合同结构——骨架是否完整、是否有多余

- 检查合同是否具备必要模块：标题、当事人、鉴于条款、定义、标的、价款、履行、质量/验收、权利义务、违约、保密、知识产权、不可抗力、通知送达、争议解决、签署。
- 删除与本次交易无关的冗余条款，避免义务放大。
- 确保条款顺序符合交易逻辑，避免前后矛盾。

### 步骤3：审查合同条款——核心风险都在这里

按第六部分“通用条款审查清单”逐项核对，重点关注：
- 主体资格与履约能力
- 标的明确性与可交付性
- 价款/报酬及其支付方式、时间、条件
- 履行期限、地点、方式、验收标准
- 违约责任是否对等、可执行
- 争议解决条款是否便于己方
- 知识产权归属与许可范围
- 保密义务的范围与期限
- 不可抗力、情势变更、合同解除条件

### 步骤4：审查文字符号——消除歧义

- 统一称谓：避免“甲方/乙方”与“买方/卖方”“公司”混用。
- 删除模糊词：如“合理”“适当”“必要时”“重大”等，尽量量化或定义。
- 检查数字、金额、日期、比例、币种是否准确。
- 检查“的、地、得”及“和/或/及”使用是否导致歧义。
- 确保页眉页脚、页码、附件清单、签署栏完整。

## 四、通用条款审查清单

| 条款 | 审查要点 | 常见问题 |
|------|----------|----------|
| **主体条款** | 名称与营业执照一致；法定代表人/授权代表；履约资质；关联关系披露 | 主体名称写错、无权代理、资质缺失 |
| **标的条款** | 名称、规格、数量、质量标准、交付方式、知识产权归属 | 标的描述模糊、质量标准缺失 |
| **价款条款** | 金额、含税/不含税、发票类型与税率、支付方式、账期、逾期利息 | 价款构成不清、发票责任不明 |
| **履行条款** | 时间、地点、方式、验收标准与程序、交付确认 | 履行条件不可操作、验收标准缺失 |
| **权利义务** | 双方核心权利义务是否匹配、是否遗漏关键义务 | 权利义务不对等、关键义务缺失 |
| **违约条款** | 违约情形、违约金/损失赔偿、责任上限、解除权 | 违约金过高/过低、解除条件不清 |
| **保密条款** | 保密信息范围、保密期限、违约责任、例外情形 | 范围过宽或过窄、期限不明 |
| **知识产权** | 归属、许可范围、侵权责任、改进成果归属 | 归属约定不明、侵权赔偿缺失 |
| **争议解决** | 诉讼/仲裁、管辖地、法律适用 | 管辖对己方不利、仲裁机构约定不明 |
| **通知送达** | 送达地址、联系人、方式、变更程序 | 无送达条款，维权时无法有效通知 |
| **不可抗力** | 定义、通知义务、后果处理、合同终止/变更 | 定义过窄、后果处理缺失 |
| **合同变更/解除** | 变更程序、解除条件、善后处理、结算 | 口头变更有效、解除后责任不清 |
| **附件/定义** | 附件清单是否完整、定义是否前后一致 | 附件缺失、定义冲突 |

## 五、分类合同审查要点

### 5.1 买卖合同

- **标的**：名称、规格、数量、质量标准（国标/行标/约定标准）。
- **交付与验收**：交付时间、地点、风险转移、验收期限、异议期。
- **所有权保留**：是否约定所有权保留条款。
- **价款与结算**：账期、预付款比例、质保金比例（通常 3%-10%）。
- **违约责任**：逾期付款/交货违约金、质量不符合约定的处理。

### 5.2 租赁合同

- **租赁物**：明确地址/编号/面积/附属设施，产权证明或授权出租证明。
- **租期与租金**：起止日、递增机制、押金、物业费/税费承担。
- **维修义务**：明确出租方/承租方维修责任边界。
- **转租与优先购买权**：是否允许转租、承租人优先购买权通知义务。
- **合同终止**：装修补偿、腾退期限、物品处置。

### 5.3 借款/担保合同

- **借款要素**：金额、用途、利率（不超过 LPR 四倍红线）、期限、还款方式。
- **担保方式**：保证/抵押/质押，担保范围、期间、实现方式。
- **主体审查**：出借人资金来源合法、借款人用途合规。
- **风险提示**：避免职业放贷、非法集资、套路贷风险。

### 5.4 建设工程合同

- **资质要求**：承包人必须具备相应资质，否则合同无效。
- **工程范围**：图纸、工程量清单、变更签证程序。
- **价款结算**：固定总价/单价/成本加酬金，进度款支付节点。
- **质量与验收**：质量标准、隐蔽工程验收、质保期与质保金。
- **分包与转包**：禁止违法分包、转包，明确违约责任。

### 5.5 技术/知识产权合同

- **技术成果归属**：背景知识产权、前景改进成果归属。
- **许可范围**：地域、期限、用途、是否可转授权。
- **验收标准**：技术指标、测试方式、交付物形式。
- **保密与竞业**：保密期限、竞业限制范围与补偿。

### 5.6 服务/委托合同

- **服务范围**：明确服务内容、交付物、验收标准。
- **人员要求**：是否指定服务团队、人员资质、替换程序。
- **费用与支付**：固定费用/计时/里程碑付款。
- **知识产权**：服务成果归属、委托方资料保密。

### 5.7 股权转让/并购合同

- **标的股权**：公司基本信息、股权比例、出资情况、质押/冻结。
- **交易对价与支付**：估值依据、价款调整机制（如业绩对赌）。
- **陈述与保证**：财务、税务、资产、诉讼、合规。
- **过渡期安排**：目标公司经营管理限制、损益归属。
- **交割条件**：内外部审批、工商变更、共管账户。

### 5.8 保密协议（NDA）

- **保密信息定义**：明确范围、标识要求、例外情形。
- **保密义务**：使用限制、披露限制、保密期限。
- **返还/销毁**：合同终止后保密信息处理方式。
- **违约责任**：违约金、损失赔偿、禁令救济。

## 六、合同全过程管理要点

合同风险不只出现在审查环节，而是贯穿全生命周期（来自闫周秦《合同全过程管理》）。

### 6.1 谈判阶段

- 明确谈判目标、底线、可让步项。
- 收集对方资信、履约能力、行业口碑。
- 保留谈判纪要、邮件、微信记录，作为后续解释依据。

### 6.2 起草阶段

- 优先使用己方模板或国家示范文本。
- 先确定交易结构，再填条款细节。
- 避免直接套用网络模板而不做适配。

### 6.3 审查阶段

- 业务部门审商务条款，财务部门审财税风险，法务部门审法律风险。
- 建立分级审批：重大合同、涉外合同、高风险合同需升级审批。

### 6.4 修改阶段

- 区分“必须改”“建议改”“可接受”三类意见。
- 重大修改先内部沟通，再与对方谈判。
- 保留修改痕迹和版本号，建议命名规则：`日期+文件名称+修改人+版本`。

### 6.5 签订阶段

- 核对签署人授权（法定代表人/授权委托书）。
- 核对盖章类型（公章/合同专用章），骑缝章。
- 确认合同份数、生效条件、签订日期。

### 6.6 履行阶段

- 建立合同履行台账，跟踪关键节点。
- 保留交付凭证、验收单、付款凭证、往来函件。
- 发现违约及时发函催告，固定证据。

### 6.7 履行后管理

- 合同归档（纸质+电子），保存期限不少于诉讼时效期间。
- 总结履约问题，反哺合同模板优化。
- 定期评估合同相对方信用。

## 九、使用限制与免责声明

1. 本 Skill 提供的是合同审查方法论、风险识别框架和条款修改建议，**不构成法律意见**。
2. 禁止凭记忆引用具体法条；需要具体法律条文时，应查阅现行有效法律或咨询专业律师。
3. 重大合同、涉外合同、涉及高额标的或复杂结构的合同，建议委托专业律师审查。
4. 本 Skill 基于已出版书籍和公开资料提炼，具体应用需结合最新法律法规和司法解释。

## 付费前置检查（微信 X402 协议）

调用本 Skill 前，先检查当前 Agent 是否已安装 `weixinpay` 插件（extension）：

- 已安装：可继续提供付费服务
- 未安装：向用户提示「当前 Agent 暂不支持微信支付付费能力」，终止流程

## 支付触发（首次请求收到 HTTP 402）

向本 Skill 的 `endpoint` 发起 POST 请求，若收到 HTTP 402 响应，`weixinpay` 插件会拦截并完成支付流程：

- Header `WeixinPay-Required`：支付凭证码（插件用于完成支付）
- Header `X-Out-Trade-No`：商户订单号

> 支付过程由 `weixinpay` 插件处理，Skill 无需关心支付细节。

## 重试机制（支付成功后必须重新请求）

支付成功后，**必须**重新发起请求获取付费内容：

- JSON body 与首次请求完全一致
- 通过 Header 携带支付信息：`WeixinPay-Required` 和 `X-Out-Trade-No` 原样带上

## 订单号传递规范

- 商户订单号通过 402 响应的 Header `X-Out-Trade-No` 返回
- 重试请求时通过同名 Header 原样回传，不得修改

## 异常处理

- 若重试返回 `"code": "NOT_PAID"`：支付尚未完成，等待后重试
- 若返回 `"code": "REFUNDED"`：服务异常已退款，告知用户并终止
- 若返回 `"code": "REFUND_FAILED"`：服务异常且退款失败，建议联系客服
