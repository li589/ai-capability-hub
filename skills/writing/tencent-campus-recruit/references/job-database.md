# 岗位方向通用考察维度

> 具体岗位名称、招聘类型、工作地、JD 全文优先走 `scripts/fetch_recruit_jds.py` 从 `join.qq.com` 官网接口获取；仅受控内测且 JD MCP 可用时，可选用 `campus-recruit-jd-qa` 辅助检索。
> 本文件仅提供各大方向的通用考察维度，用于辅导同学了解各方向通常关注哪些能力。

> ⚠️ **输出约束**：引用本文件内容时，禁止使用"一定会考察""肯定看重"等绝对化表述。统一使用"通常比较关注""往往会看重""建议重点准备"等柔性措辞。

> ⚠️ **通过率禁令**：禁止编造或推测任何岗位的通过率、录取率、淘汰率、竞争比等数据。我们没有接入此类后端数据。当同学询问时，引导关注「腾讯招聘」公众号发布的热招岗位信息。

> ⚠️ **岗位推荐前置**：任何涉及"岗位推荐 / 在招什么 / 某岗位 JD / 某方向有什么 / 某城市能投什么"的场景，优先运行 `scripts/fetch_recruit_jds.py search/detail/match` 从 `join.qq.com` 官网接口获取真实岗位；仅受控内测且 JD MCP 可用时，可选用 `campus-recruit-jd-qa` 辅助检索。必须基于真实返回岗位回答，不凭训练数据推荐。

> ⚠️ **院校中性约束**：岗位匹配、JD 解读或结合简历背景给建议时，如涉及学校层级、院校标签或学历背景，只能作为客观信息参考；不得以学校层级给人选贴标签、排序或判断优劣，匹配理由应聚焦专业、项目、技能、经历、城市和实习类型等可说明因素。

> ⚠️ **面试安全约束**：本文件所有内容均为基于通用考察维度的方向性参考。引用时不得使用"面试官怎么看""面试官更欣赏""面试官倾向于""面试官普遍很看重"等表述；统一改写为"该方向通常关注""通常会考察""往往看重"等客观化措辞。禁止将任何方向性考察描述与具体 BG/部门/团队绑定，禁止输出各方向之间的难易对比。

## 使用说明

1. 当用户询问"在招什么岗位 / 有什么 JD / 推荐岗位" → 优先走 `scripts/fetch_recruit_jds.py` 官网接口；仅受控内测且 JD MCP 可用时，可选用 `campus-recruit-jd-qa` 辅助。只列 3-5 个与同学简历/背景最符合的真实校招岗位。推荐结果统一用紧凑表格输出，列为 `# / 岗位名称 / 招聘部门 / 工作地 / 匹配理由 / 投递链接`；岗位名称加粗；岗位名称、招聘部门、工作地、投递链接必须来自官网脚本或可选 JD MCP 的真实返回；匹配理由可写 2-3 个短点并用 `<br>` 在同一单元格内换行；投递链接统一显示为 `[点击投递](url)`；不输出评分、分数或匹配度百分比
2. 当用户给具体岗位名 → 先用 `fetch_recruit_jds.py search` 找 `post_id`，再用 `fetch_recruit_jds.py detail <post_id>` 拿官网完整 JD；仅受控内测且 JD MCP 可用时，可选调 `get_jd_detail`；再结合本文件对应方向的通用考察维度做辅导
3. 当用户询问某个 BG/部门职责、部门介绍或组织架构 → 使用 `fetch_recruit_jds.py orgs` 或 `fetch_recruit_jds.py department --keyword/--bg` 获取官网 about 页面最新介绍，不凭经验补充
4. 当用户想了解某个方向的面试准备 → 参考本文件对应方向的通用考察维度
5. 本文件不替代官方 JD 或官网组织架构介绍，仅作为辅导同学时的方向性参考材料

## 技术方向

### 通用考察维度
- **专业基础**：计算机基础知识的扎实程度
- **代码能力**：实际动手写代码、解决问题的能力
- **工程素养**：代码质量意识、系统设计思维
- **学习能力**：快速掌握新技术的能力
- **态度热情**：对技术的热爱和钻研精神

技术岗通常会关注计算机基础知识是否扎实，也可能会问一些拓展性问题来了解你的思维速度和清晰度。学习能力和技术热情往往也是重点考察方向。建议在面试中清晰表达你的技术方向和职业规划。

### 面试形式参考
基础知识问答 + 代码/工程题 + 项目深挖 + 经历问答

### 简历建议
- 项目经历是核心，用STAR描述
- 技术栈列清楚，但要有使用场景佐证
- 竞赛/论文/开源贡献是加分项

## 产品方向

### 通用考察维度
- **产品热情**：是否真正喜欢做产品，这是持续成长的核心动力
- **逻辑思维**：分析问题是否有条理，思考和表达是否有逻辑性
- **用户洞察**：能否站在用户角度思考
- **沟通表达**：能否清晰表达想法
- **承压与协作**：面对压力时的表现，团队协作中的参与度

产品方向通常关注求职者对产品工作的热情和理解深度，以及是否具备清晰的分析框架和逻辑表达能力。即使没有实习经验，也可以通过案例分析展现产品思维。

### 面试形式参考
经历问答 + 案例分析（用真实产品案例讨论）

### 简历建议
- 突出产品思维和用户洞察
- 数据驱动的案例比职责描述更有说服力
- 即使没有实习经验，也可以通过案例分析展现潜力

## 游戏方向

### 通用考察维度
- **热爱度**：是否对游戏品类有深入理解，是否玩过多个代表性作品
- **游戏理解**：对游戏设计、玩家体验的洞察深度
- **动手能力**：有没有自己做过游戏或demo，是否使用过主流引擎
- **执行力**：能否把想法变成可执行的方案
- **技术适配**：是否具备与游戏策划/开发方向匹配的技术基础

游戏方向通常会关注求职者对游戏品类的深入理解——玩过哪些作品、有什么洞察。动手能力也是常见的考察重点（如自己做过的demo、用过的引擎）。对游戏策划方向而言，技术向的趋势也值得关注。

### 面试形式参考
经历问答 + 案例分析 + 专业笔试 + 项目demo展示

### 简历建议
- 游戏经历和深度体验是常见的关注点
- 自己做过的demo、用过的引擎要突出写
- 展示对游戏品类的深入理解和热爱

## 市场/职能方向

### 通用考察维度
- **执行力**：做事的细节和质量是否扎实
- **学习心态**：是否开放、好奇、主动
- **探索精神**：是否有多元化的探索经历，不局限于单一角色
- **沟通能力**：表达清晰，善于协调

市场职能方向通常看重实际产出的细致程度、开放学习的心态以及多元化的探索经历。建议在面试中展示你做事的细节感和持续学习的态度。

### 面试形式参考
经历问答 + 专业笔试（部分岗位）+ 案例分析 + 情景模拟（部分岗位）

### 简历建议
- 突出实际产出的细节和质量
- 展示学习心态和探索精神
- 有数据支撑的案例优于泛泛描述
