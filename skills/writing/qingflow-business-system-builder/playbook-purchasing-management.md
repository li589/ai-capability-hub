# Playbook 案例：搭建采购管理系统

**所属 Skill：** 轻流业务系统搭建（`qingflow-business-system-builder`）

---

## 场景概述

| 项目 | 内容 |
|------|------|
| **一句话** | 对着 AI 说句话，30 分钟搭完一套带审批流程、数据看板、权限控制的采购管理系统 |
| **目标用户** | 中小企业 IT 负责人、业务负责人、轻流实施顾问 |
| **复杂度** | 中等（13 个字段 + 4 节点审批流 + 3 角色权限 + 数据看板） |
| **覆盖能力** | 字段建表 → 排版 → 流程 → 视图 → 图表 → 门户 → 发布 |

---

## 用户说了什么

```
帮我搭建一套采购管理系统，需求如下：

1. 采购申请单：申请人、部门、供应商、采购物品明细（名称/规格/数量/单价）、
   采购总金额、申请日期、紧急程度、备注、附件
2. 审批流程：提交 → 部门负责人审批 → 财务审批 → 总经理审批（金额>10000才触发）→ 完成
3. 采购进度看板：待审批 / 审批中 / 已通过 / 已驳回 / 已下单
4. 数据看板：本月采购金额、各部门采购排名、供应商采购排行
5. 权限：普通员工只能看自己的单子，部门负责人看本部门，财务和总经理看全部
```

---

## Skill 做了什么

### Step 1 — 字段建模（零冗余设计）

AI 不直接照搬需求，而是按轻流规范做了**减法**：

| 需求字段 | 处理方式 | 理由 |
|----------|---------|------|
| 采购单编号 | ❌ 移除 | 用系统默认编号 |
| 审批状态 / 当前节点 | ❌ 移除 | 禁止与流程节点重复 |
| 采购总金额 | 💡 改为公式字段 | `SUM(采购物品明细.数量 * 采购物品明细.单价)` |
| 紧急程度 | ✅ 保留 | 单选：普通 / 紧急 / 特急 |
| 供应商 | ✅ 关联字段 | 关联供应商档案表 |

最终表单仅 **12 个字段**，比需求中的字段列表减少了 3 个冗余项。

### Step 2 — 表单排版（一行四字段规范）

```
┌────────────┬────────────┬────────────┬────────────┐
│  申请人     │  所在部门   │  申请日期   │  紧急程度   │
├────────────┴────────────┴────────────┴────────────┤
│                  供应商（关联字段）                 │
├───────────────────────────────────────────────────┤
│              采购物品明细（子表：名称/规格/数量/单价）│
├────────────┬────────────┬────────────┬────────────┤
│  采购总金额  │  备注       │            │            │
├────────────┴────────────┴────────────┴────────────┤
│                  附件                              │
└───────────────────────────────────────────────────┘
```

### Step 3 — 审批流程（含条件分支）

```
[申请人提交] → [部门负责人审批] → [财务审批]
                                       │
                          ┌─ 金额 ≤ 10000 → [完成]
                          │
                          └─ 金额 > 10000 → [总经理审批] → [完成]

每个审批节点均配置：
  - 通过 / 驳回 / 转交 三种动作
  - 审批意见必填
  - 超时 48 小时自动提醒
```

### Step 4 — 三视图（table + board + card）

- **表格视图**：全量字段列表，带筛选（按状态、部门、日期）、排序（申请日期倒序）
- **看板视图**：按采购进度分列，拖拽式管理
- **卡片视图**：摘要信息，适合手机端快速浏览

### Step 5 — 数据看板

| 图表 | 类型 | 说明 |
|------|------|------|
| 本月采购总金额 | 指标卡 | 大数字展示 |
| 各部门采购金额排名 | 横向柱状图 | Top 10 |
| 供应商采购排行 | 条形图 | 按金额降序 |
| 月度采购趋势 | 折线图 | 近 6 个月 |
| 紧急采购占比 | 饼图 | 普通/紧急/特急比例 |

### Step 6 — 角色权限矩阵

| 角色 | 可见范围 | 可操作 |
|------|---------|--------|
| 普通员工 | 仅自己的申请 | 新建 / 撤回 |
| 部门负责人 | 本部门全部申请 | 新建 + 审批 |
| 财务 / 总经理 | 全部申请 | 查看 + 审批 |

### Step 7 — 发布验证

- 执行 `app_publish_verify` 检查，定位了 1 处「视图未绑定筛选条件」警告并自动修复
- 发布成功，生成应用访问链接

## 产出效果

| 指标 | 结果 |
|------|------|
| 总耗时 | 约 30 分钟（全程 AI 自动执行，人只需确认关键决策） |
| 人工介入 | 2 次（确认供应商档案表是否已存在 + 确认总经理审批节点金额阈值） |
| 表单字段 | 12 个（精简后，比原始需求少 3 个冗余字段） |
| 审批节点 | 4 个（含 1 个条件分支） |
| 视图 | 3 个（table + board + card，完全符合规范） |
| 图表 | 5 个（指标卡 + 柱状图 x2 + 折线图 + 饼图） |
| 权限角色 | 3 个（普通员工 / 部门负责人 / 财务与高管） |
| 规范违规 | 0 处（全部通过 20+ 项完成标准校验） |

---

## 技术亮点

1. **AI 会主动做减法**：不会照搬用户需求中的冗余字段（如审批状态、编号），而是用轻流系统能力替代
2. **条件分支自动推导**：根据「金额 > 10000」自动配置条件审批节点，无需手动画流程图
3. **自检闭环**：发布前自动执行 20+ 项完成标准检查，发现的 1 处警告自动修复后才发布
4. **MCP 原生操作**：全程走 MCP 接口，不依赖浏览器自动化，速度快且稳定
5. **零回滚**：发布后 AI 回读实际应用状态进行最终验证，确保「你看到的就是 AI 搭出来的」
