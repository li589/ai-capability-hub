# 混凝土裂缝侦探·智用（Pay Skill）

## 能力概述

本 Skill 面向桥梁承台、筏板基础、水工大坝等大体积混凝土工程，提供四项计算服务：

1. **浇筑前裂缝预测**（`pre_pour`）— 还没浇，算方案是否安全
2. **浇筑后实测反算**（`post_pour`）— 已浇筑，输入实测温度反算当前安全度
3. **保温层计算**（`insulation`）— 算保温层厚度并验算表面温度
4. **裂缝宽度验算**（`crack_width`）— 已开裂，算缝宽并给出分级处理建议

所有计算严格按《大体积混凝土施工标准》GB 50496—2018、《混凝土结构设计规范》GB 50010-2010（2015 年版）等国家规范公式执行，7 个标准算例复算误差 < 1%。

### 计算主接口流程

1. **首次调用**（`POST /api/calculate`）：携带 `expert_id`、`mode`、`params`、`conversation_id`（同一对话的稳定标识）
2. **后端判断免费试用**：同一对话首次调用本 Skill 时，直接执行计算并返回 HTTP 200（免费试用报告）
3. **后续调用进入付费流程**：后端创建订单，调用微信支付 Native 支付接口获取 `code_url`，再调用 X402 AI 预下单换取 `payment_code`，最后将支付触发标识返回给 Agent
4. **返回支付触发标识**（X402 协议，HTTP 200/402 兼容模式）：详见「X402 协议规范」章节
5. **AI 触发弹卡**：按「支付弹窗方案」章节执行——AI 收到支付触发标识后调用 `retry_pay` 触发微信支付弹卡，用户扫码完成 ¥9.90 支付
6. **支付回调**：微信支付系统异步调用 `POST /api/pay-notify`，后端将订单标记为 `paid`
7. **二次调用**（`POST /api/calculate`）：携带 `payment_code`（取自 402 响应的 `payment_code` 字段），后端执行计算并返回结果，同时返回 `expires_at`（本次支付有效期截止时间，24 小时内可无限重算）
8. **报告重取**（`POST /api/result`）：AI 侧展示失败或需要重取时，可用 `out_trade_no` 或 `payment_code` 调用 `/api/result` 秒取已生成的报告，无需重新计算
9. **同会话无限重算**：同一次支付的 `payment_code` 在 24 小时内可无限次换参数重算，直到 `expires_at` 过期；过期后再次调用返回 HTTP 403「支付会话已过期，请重新下单」

> AI Agent 应当根据返回的 HTTP 状态码判断下一步：
> - `200` 且 `trial: true`：免费试用报告，响应体中 `html` 字段就是可直接展示的 HTML 报告
> - `200` 且无 `trial`：普通结果（如免费模式），响应体中 `html` 字段可直接展示
> - `402` / `200`（兼容模式）：返回了支付触发标识，按「支付弹窗方案」章节立即调用 `mcp__weixinpay__weixinpay_retry_pay` 触发工程化支付弹卡

## X402 协议规范（合规说明）

本 Skill 完全遵循 SkillHub 官方教程《升级为 Pay Skill》中定义的 X402（微信支付 Agent Pay）协议规范。本节按官方教程结构逐章节展开，便于审核员核对。

### 4.1 协议分层

一次完整的支付调用分四段：

```
企业服务生成微信支付订单
   ↓
用 SkillHub 开发者密钥签名，调用 X402 AI 预下单换取 payment_code
   ↓
通过 WeixinPay-Required 响应头 + WeixinPay 响应体返回给 Agent
   ↓
Agent 向用户申请支付授权，然后继续获取付费内容
```

### 4.2 预下单接口（Step 3）

**接口 URL**：`POST https://payapp.weixin.qq.com/palmpayminiapp/clawagentpay/preorder`

**鉴权方式**：纯 Body 鉴权（不使用 `Authorization` 头），鉴权字段与业务内容全部置于 HTTP Body。

**请求体采用 2 层结构**：

| 层级 | 说明 |
|:--|------|
| **L1** — HTTP Body（鉴权外层） | 包含签名相关字段（`signature_type`、`developer_platform`、`developer_id`、`pub_key_id`、`nonce_str`、`timestamp`、`signature`），以及封装后的业务字段 `payment_required` |
| **L2** — 业务 JSON | 实际的业务内容序列化为 JSON 后，做 Base64 编码（**非 URL-safe，不带换行**），填入 L1 的 `payment_required` 字段 |

**L2 业务 JSON 示例**：

```json
{
  "skill_info": {
    "skill_id": "concrete-crack-detective",
    "skill_version": "1.0.0"
  },
  "pay_type": "SKILL_PAY",
  "pay_mode": "AUTH_AND_PAY",
  "pay_items": [
    {
      "product_id": "SP250625A001",
      "pay_data": {
        "type": "code_url",
        "value": "weixin://wxpay/bizpayurl?pr=xxx"
      }
    }
  ],
  "expires_at": "1750924500"
}
```

**L2 字段说明**：

| 字段 | 说明 |
|:--|:--|
| `skill_info.skill_id` | 你在 SkillHub 发布的 Skill slug |
| `skill_info.skill_version` | Skill 版本号 |
| `pay_type` | 固定填 `SKILL_PAY` |
| `pay_mode` | 固定填 `AUTH_AND_PAY`（授权即支付） |
| `pay_items[].product_id` | 保留字段，格式 `SPxxx`，值任意 |
| `pay_items[].pay_data.type` | 填 `code_url` |
| `pay_items[].pay_data.value` | Step 2 微信支付 Native 下单返回的 `code_url` |
| `expires_at` | 过期时间，Unix 秒级时间戳，最长 **15 分钟** |

**签名串（5 行）**：

```
POST\n/palmpayminiapp/clawagentpay/preorder\n{timestamp}\n{nonce_str}\n{payment_required}\n
```

每行以换行符 `\n`（0x0A）结尾，**包括最后一行**。

| 行 | 内容 |
|:--|:--|
| 1 | HTTP 方法，固定 `POST` |
| 2 | 请求路径，固定 `/palmpayminiapp/clawagentpay/preorder` |
| 3 | Unix 秒级时间戳（10 位数字） |
| 4 | 32 位随机字母数字串 |
| 5 | 上一步的 `payment_required`（Base64 编码后的 L2） |

**签名算法**：SHA256withRSA（PKCS#1 v1.5），结果 Base64 编码即得 `signature`。

```
signature = Base64( RSA_PKCS1v15_Sign( private_key, SHA256(sign_string_bytes) ) )
```

**L1 请求体示例**：

```json
{
  "signature_type": "SKILLHUB-SHA256-RSA2048",
  "developer_platform": "SKILLHUB",
  "developer_id": "sh-XXXXXXXX",
  "pub_key_id": "PUB_KEY_408B07E79B8269FEC3D5D3E6AB8ED163",
  "nonce_str": "a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6",
  "timestamp": "1750924200",
  "signature": "BASE64_RSA_SIGNATURE...",
  "payment_required": "eyJza2lsbF9pbmZvIjp7..."
}
```

**L1 字段说明**：

| 字段 | 值 | 说明 |
|:--|:--|:--|
| `signature_type` | `SKILLHUB-SHA256-RSA2048` | 固定值 |
| `developer_platform` | `SKILLHUB` | 固定值 |
| `developer_id` | `sh-XXXXXXXX` | 你的 SkillHub 商户号 |
| `pub_key_id` | `PUB_KEY_xxx` | Step 1 生成的密钥 ID |
| `nonce_str` | 32 位随机字符串 | 每次请求唯一 |
| `timestamp` | Unix 秒级时间戳 | 当前时间 |
| `signature` | Base64 签名值 | 3.4 步骤的输出 |
| `payment_required` | Base64 编码的 L2 JSON | 3.2 步骤的输出 |

1. 微信支付下单成功，能通过 `out_trade_no` 或回调确认支付结果

## 支付弹窗方案（唯一方案，所有弹窗行为以此为准）

### 第 1 步：付费前置检查（AI 内部执行）

调用 `/api/calculate` 前确认 weixinpay 插件已接入；未接入则停止调用，不向用户解释原因。

### 第 2 步：收到 402 后弹卡

后端 402 响应按 X402 协议返回 `WeixinPay-Required` 响应头 + `WeixinPay` 响应体。AI 收到支付凭据后调 `mcp__weixinpay__weixinpay_retry_pay`，参数为 `{ "paymentCode": "<WeixinPay-Required 的值>" }`，然后等用户付款。该工具仅回显支付凭据以触发工程化支付，**不会重复下单，也不会立即扣款**，是本 Skill 在 WorkBuddy 客户端内**唯一被允许**的支付触发方式。

### 第 3 步：弹卡后按 3 种情况处理

**情况 1：弹卡成功，用户付款**
→ 等用户回复「付好了」→ 带 `payment_code` 二次调 `/api/calculate` 出报告。

**情况 2：弹卡成功，但用户取消**（用户在支付卡里点了取消，或 `retry_pay` 返回体提示「用户未授权微信支付」「订单未完成支付」）
→ 输出：
> 卡片没付成功。您可以：① 回复『重新支付』，我再弹一次支付卡片，按提示完成支付；② 换一种支付方式，用普通微信扫码支付，我生成一个二维码，任意微信都能扫。回 1 或 2 就行。
>
> 如果您的微信服务没有绑定 AI 专属卡，可以回复『帮我绑定』。

- 回 1（或「重新支付」）→ 同一 `paymentCode` 再调 `retry_pay`，最多 3 次
- 回 2（或「扫码」「换一种支付方式」）→ 生成 `支付卡片.html` 展示，任意微信可扫（模板见下方）
- 回『帮我绑定』→ 调用 `mcp__weixinpay__weixinpay_register` 引导用户开通微信 AI 支付（仅对完整包含『帮我绑定』四字的回复触发，问「怎么绑定」等闲聊意图不触发）

**情况 3：弹卡失败**（`retry_pay` 调用出错）
→ 静默重试，最多 3 次，每次都重调 `retry_pay`
→ 3 次全败 → 输出与情况 2 相同的话术（含『帮我绑定』分支），并按用户选择继续

### 铁律

- 弹卡成功等付款时，只输出固定台词：「本次查询需要支付 ¥9.90。系统正在唤起微信支付卡片，请按提示完成支付；付款成功后回复『付好了』，我立即出报告。」，不加任何括号备注、不提前提取消/降级
- 任何情况下不向用户输出「系统繁忙」「支付失败」等平台内部信息

### 异常处理

| 状态码 | 含义 | AI 应如何处理 |
|--------|------|---------------|
| `400` | 请求参数错误 | 详见下方「400 错误处理原则」 |
| `402` | 需要支付（仅收费模式） | 按「支付弹窗方案」章节执行 |
| `403` | 支付会话已过期 | 提示用户重新下单 |
| `404` | 专家不存在 / 订单不存在 | 提示用户检查 `expert_id` |
| `500` | 服务端错误 | 提示用户稍后重试 |

#### 400 错误处理原则

后端书表校验返回 400 时，AI 必须按以下顺序处理：

1. **AI 内部字段问题（冗余、字段映射错误）→ AI 自己修复后重试，不告诉用户**：
   - 典型场景：「未知参数 W」—— 这是 AI 误传或字段映射没做对，AI 默默去掉后重新调用即可。
   - 用户不需要知道 AI 内部修复了哪个字段，**不要把"去掉冗余字段""字段映射由 X 表达"等等细节告诉用户**。
   - 重试成功后照常展示结果即可。

2. **AI 内部操作日志不要展示给用户**：
   - 类似于「修改 / 运行校验：crack_payload.json」「写入临时文件 / 删除」这种开发者向日志，AI 内部处理就行。
   - 仅当 AI 自己调试时可在思维链里出现，**用户对话窗口里看不到这些字眼**。

3. **AI 内部无法修复 → 简洁告诉用户**：
   - 只有用户参数真的越界（比如强度等级填了 C100、超出 C15~C80 范围），AI 才简洁告诉用户。
   - 提示风格：「参数有点问题：xxx 字段需要 C15~C80 之间的值，麻烦您确认一下。」—— 一句话讲清楚字段 + 范围 + 期望值，不解释技术细节。

总结：**用户看到的应该是「参数有问题 → 改好后调用成功」，而不是「AI 错误的内部修复过程」**。

#### 500/5xx 错误处理原则

后端返回 `500` / `502` / `503` / `504` 等 5xx 时，代表 SkillHub 预下单服务或网关内部出现短暂异常。AI 必须按以下原则处理：

1. **绝不暴露内部错误细节**：
   - 不要把后端返回的任何原始错误信息、错误码、堆栈、响应片段展示给用户。
   - 禁止说「SkillHub 预下单失败」「X402 预下单失败」「微信支付返回系统繁忙」等内部归因词汇。

2. **不向用户归因具体原因**：
   - 不要告诉用户「微信支付失败了」「系统繁忙」「服务器挂了」——这些判断可能不准确，会让用户误解为钱已扣走或支付链路断了。
   - 5xx 只是后端响应异常，不代表用户扫码付款一定失败。

3. **不向用户输出任何平台内部信息**：5xx 时不归因原因，弹卡相关按「支付弹窗方案」章节执行。

4. **区分场景**：
   - **首次调用即返回 5xx**：不归因原因，引导用户重新触发计算。
   - **已看到支付卡片并完成扫码付款，二次调用返回 5xx**：安抚用户「您的付款仍然有效」，引导回复「重试」；若连续失败，调用 `POST /api/order-status` 查询真实订单状态。

总结：**用户看到的永远只是「看不到二维码就回复看不到二维码」这类简单提示，任何内部错误细节和归因都不允许出现**。

# AI Agent 工作流程（v3.0 — 弹窗/表格双模式）

> 以下流程是给 AI Agent 看的"操作手册"。当用户说"想算个混凝土裂缝"时，AI 应严格按本流程执行。
>
> **本版本采用「平台自适应双版本」交互模式**：每个交互步骤同时提供「弹窗版」和「表格版」两个版本，AI 根据当前平台能力自动选择其一发给用户。两版选项内容完全一致，仅输出格式不同。

## 平台识别与交互模式

AI 在开始参数收集前，必须先识别当前平台是否支持 `AskUserQuestion` 弹窗：

- **支持弹窗**（如 WorkBuddy）→ 使用「弹窗版」输出格式（原生点选体验）
- **不支持弹窗**（大多数其他 AI 平台）→ 使用「表格版」输出格式（Markdown 表格 + 用户回复数字/名称）

以下每个交互步骤同时给出两个版本。AI 根据当前平台**只选一个版本**发给用户，不要两个版本都发。两版的选项内容完全一致，仅输出格式不同。

## 核心原则

1. **平台自适应**：先识别平台支持哪种交互方式，选弹窗版或表格版，每轮只发一个版本。
2. **校验放最后**：收集阶段只管收集不打断，校验统一在最终确认环节。
3. **AI 不算公式**：所有计算交给云端 Python 引擎，AI 只负责问参数、确认参数、调用接口、展示报告。
4. **不抛 JSON**：全程用弹窗或 Markdown 表格和简短文字与用户交互，组装 JSON 是 AI 自己的事，不暴露给用户。
5. **规范名称完整**：提到任何规范时必须使用完整规范名称+编号，例如"《大体积混凝土施工标准》GB 50496—2018"，不能只写编号"GB 50496—2018"。
6. **支付弹窗按「支付弹窗方案」章节执行**：收到 402 响应后按该章节调用 `retry_pay` 触发弹卡，不得自渲染任何支付卡片或二维码。

- **离散枚举参数**（如强度等级、水泥品种、水泥标号、地基类型等）：值必须严格在书表枚举列表中，否则返回 HTTP 400

- **试验值允许**：用户提供的 `Q`、`Q3`、`Q7` 等试验水化热值，只要在合理物理范围内就允许通过

## 风险提示清单

以下情况必须主动告知用户：

1. **水泥品种"低热水泥/火山灰水泥/抗硫酸盐水泥"**：水化热参考表仅收录普通和矿渣两个品种，需补试验值或确认按近似值。
2. **地基"岩石地基"用于模式 B/D**：Cx 表无岩石地基，需提供实测 Cx 值或确认按砂质黏土近似。
3. **粉煤灰掺量 >40%** 或 **矿渣粉掺量 >40%**：λ₁/λ₂ 调整系数仅到 40%，按 40% 截断。
4. **养护时间 11~13 天**：书表无数据，按 10 天取值（偏保守）。
5. **结构厚度 ≤1m**：不属于大体积混凝土，本书公式不适用，建议专业工程师另行分析。
6. **箱梁等空心结构**：按净截面近似，仅供收缩参考，注明后继续。
