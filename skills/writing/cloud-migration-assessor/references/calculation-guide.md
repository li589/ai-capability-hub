# 计算引擎说明 v4.1

## 三层计算架构

### 第一层：资源级工时

```
单资源阶段工时 = 单台基础工时 × 数量规模因子 × 复杂度系数 × 规格权重
```

#### 数量规模因子（边际递减）
```
qtyEffectiveFactor = qty <= 1 ? 1 : (1 + (qty - 1) × 0.6)
```
- 1台：因子 1.0
- 5台：因子 1 + 4×0.6 = 3.4（等效3.4台，非5台）
- 10台：因子 1 + 9×0.6 = 6.4（等效6.4台，非10台）
- 批量操作有复用效应，使用SMC/DTS后效率更高

#### AI优化折减
```
AI优化后 = 原始工时 × (1 - 阶段AI效率 × AI辅助程度)
下限 = 原始工时 × 0.2（AI最多减80%）
```

各阶段AI效率天花板：
| 阶段 | AI效率 | 说明 |
|------|--------|------|
| 规划设计 | 35% | AI辅助方案文档 |
| 基础环境 | 40% | IaC脚本自动化 |
| 资源开通 | 50% | 高度可脚本化 |
| 数据迁移 | 25% | 仍需人工决策 |
| 业务部署 | 30% | 部署脚本可自动化 |
| 测试割接 | 35% | 自动化测试 |

资源类型修正系数（复杂资源AI效果打折）：
- 云数据库：×0.8
- 搜索服务：×0.85
- 容器产品：×0.9
- 大数据：×0.8
- 其他：×1.0

### 第二层：项目固定开销

不随资源数量线性增长的管理/协调开销，按项目规模动态缩放：

| 项目规模 | 缩放系数 | 适用场景 |
|---------|---------|---------|
| ≤3台且≤2种资源 | ×0.15 | 极小项目 |
| ≤10台且≤5种 | ×0.35 | 小项目 |
| ≤30台且≤10种 | ×0.60 | 中等项目 |
| ≤80台 | ×0.80 | 中大项目 |
| >80台 | ×1.00 | 大项目 |

固定开销基准值（满额）：
| 阶段 | 工作项 | 基础天数 | AI可减 |
|------|--------|---------|--------|
| 规划 | 项目启动会 | 1天 | 10% |
| 规划 | 网络方案设计 | 1.5天 | 30% |
| 规划 | 排期规划 | 1天 | 40% |
| 规划 | 方案文档编写评审 | 2天 | 35% |
| 环境 | VPC/子网搭建 | 1.5天 | 45% |
| 环境 | 监控体系搭建 | 1天 | 40% |
| 开通 | 迁移工具部署 | 0.5天 | 40% |
| 迁移 | 数据一致性校验 | 1.5天 | 30% |
| 部署 | 第三方系统联调 | 1.5天 | 15% |
| 测试 | 割接演练 | 2天 | 20% |
| 测试 | 正式割接 | 1天 | 10% |
| 测试 | 上线观察 | 3天 | 15% |

### 第三层：全局汇总

```
原始总工时 = Σ各资源原始工时 + 固定开销原始
AI优化后 = Σ各资源AI优化后 + 固定开销AI优化后
含风险缓冲 = AI优化后 × (1 + 风险缓冲%)
日历天数 = floor(含缓冲 ÷ (团队人数 × 有效并行度))
```

#### 团队并行度规则
- 1人：并行度 = 1.0（无协作损耗）
- 2-6人：用户配置值（默认0.7）
- >6人：Brooks定律递减，每多1人降3%，最低0.3

#### 关键路径保护
当迁移+测试阶段工时 > 5人天时，启用关键路径下限保护，加人无法无限压缩日历天数。
