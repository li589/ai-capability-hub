# Playbook 案例 1：中型 Web 业务系统上云迁移评估

> 本 Playbook 演示如何用 `cloud-migration-assessor` Skill 对一个典型的中型互联网业务系统进行公有云迁移工作量评估，从输入资源清单到产出完整评估报告的全过程。

## 适用场景

- 售前阶段客户询问「迁移要多少人天、多少钱」，需快速给出专业估算
- 交付立项前需要一份标准化、可复核的工作量评估报告
- 需要对比不同团队规模 / 排期方案的成本

## 前置条件

- 已在 CodeBuddy 中加载 `cloud-migration-assessor` Skill
- 手头有客户的资源清单（Excel、表格或口述均可）

---

## 步骤一：提供资源清单

将客户资源清单直接贴给 CodeBuddy（支持表格粘贴、Excel 截图或自然语言描述）。

**输入示例：**

```
类别      资源名称        规格配置          数量  用途说明
云服务器   Web应用服务器    8C16G 200G SSD    4    Web前端服务
云服务器   后端业务服务器   16C32G 500G SSD   6    核心业务微服务
云数据库   MySQL主库       16C64G 1T SSD     2    核心业务数据库
缓存      Redis缓存       标准版 16G         3    缓存+会话管理
消息队列   RocketMQ        专业版            1    消息队列
容器产品   K8s集群         3M+10W节点        1    微服务容器化部署
网络产品   负载均衡        公网型 100Mbps     2    业务入口
安全产品   WAF防火墙       企业版            1    Web安全防护
CDN/存储  对象存储        存储1T            1    静态资源存储

帮我评估迁移工作量
```

---

## 步骤二：查看评估报告

Skill 会自动解析清单并在 30 秒内输出结构化报告，核心结论如下：

**项目概要：** 资源条目 9 条 / 实例 21 台 / 资源大类 7 类

**工时汇总：**

| 指标 | 数值 |
|------|------|
| 原始总工时 | 28.72 人天 |
| AI 优化后 | 24.20 人天 |
| 含风险缓冲(15%) | 27.8 人天 |
| 预估日历天数 | 7 天（5人团队） |
| AI 节省 | 4.52 人天 / 15.7% / ¥6,780 |

**六阶段工时分解：** 数据迁移占比最高（24%，5.85人天），主要来自 MySQL 主库的 DTS 同步与校验。

**风险评估：** 自动识别出「数据一致性（高）」「业务中断（高）」「应用兼容性（中）」等 5 类风险及应对措施。

---

## 步骤三：交互式调优（可选）

根据实际情况，可用自然语言随时调整参数，Skill 会重新计算：

| 你的诉求 | 对 Skill 说 | 效果 |
|---------|------------|------|
| 团队只有 3 人 | 「把团队改成 3 人重新算」 | 日历天数相应拉长 |
| 客户要求更保守 | 「风险缓冲调到 20%」 | 含缓冲工时上调 |
| 临时增加资源 | 「再加 5 台 CVM」 | 重新计算总量 |
| 纯手工不用 AI | 「不用 AI 辅助重新算」 | 还原到原始工时 |

---

## 步骤四：导出正式报告

评估满意后，导出可交付的报告文档：

```
导出 Word 报告
```

或

```
导出 Excel 工时明细
```

Skill 会在当前工作目录生成格式化的 `docx` / `xlsx` 报告，可直接附在项目方案中交付客户。

---

## 预期产出

1. 一份结构化的迁移工作量评估报告（含工时汇总、六阶段分解、风险评估、实施建议）
2. 一份可交付的 Word / Excel 文档
3. 一个可用于售前报价参考的人天与成本区间

## 关键提示

- 评估结果为**经验模型测算**，最终工时需结合实际项目复核，建议报价时保留 15%~20% 风险缓冲
- 数据库、大数据等复杂资源建议安排资深工程师负责，其占单项工时比重最高
- 推荐分批迁移：基础设施先行 → 应用层 → 核心数据库最后割接
