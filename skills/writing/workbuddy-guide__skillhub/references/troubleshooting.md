# 跨领域综合诊断决策树

> **版本**：v1.0 (2026-06-01)
> **用途**：单一文档无法定位问题时，用此决策树跨领域排查
> **原则**：从最常见原因开始，逐层深入，不跳步骤

---
## 一、诊断总流程

```
遇到问题
    │
    ▼
[收集信息]
├─ 精确描述现象（"XX连接器调用失败" →
│  具体是 401? 404? 超时? 返回空?）
├─ 记录报错信息（完整复制错误文本）
├─ 确认是偶发还是必现
└─ 确认最近是否有任何变更
    │
    ▼
[按优先级排查]
├─ P0: 连接器层（最常出问题）
├─ P1: 专家/技能层（配置问题）
├─ P2: 自动化层（调度/时区问题）
├─ P3: 模型层（回答质量问题）
└─ P4: 基础设施层（网络/代理/权限）
    │
    ▼
[验证修复]
├─ 每改一处就验证一次
├─ 不要一次改多个地方
└─ 修复后检查是否引入新问题
```

## 二、领域诊断树

### 2.1 连接器诊断

```
连接器问题
│
├─ 症状：所有连接器都不工作
│   ├─ 检查代理 → curl http://127.0.0.1:51103/health
│   │   ├─ 无响应 → 代理挂了 → 重启WorkBuddy
│   │   └─ 有响应 → 继续检查
│   ├─ 检查网络 → ping api.mail.qq.com
│   │   ├─ 不通 → 网络/代理/VPN问题
│   │   └─ 通 → 继续检查
│   └─ 检查配置 → 所有连接器disabled?
│
├─ 症状：单个连接器不工作
│   ├─ 检查认证 → curl + Authorization header
│   │   ├─ 401 → token过期 → 重新登录
│   │   └─ 200 → 认证OK
│   ├─ 检查传输类型 → 是stdio?
│   │   └─ 是 → 代理不支持 → 走原生通道
│   └─ 检查多session → 是否配置冲突?
│
└─ 症状：时好时坏
    ├─ 网络不稳定 → 增加timeout
    ├─ 服务限流 → 降低频率
    └─ 多session覆盖 → 统一配置
```

### 2.2 专家诊断

```
专家问题
│
├─ 症状：找不到专家
│   ├─ 是否注册成功? → 检查register输出
│   └─ 目录路径正确? → 确认在my-experts/plugins/下
│
├─ 症状：专家调用但不回答
│   ├─ prompt文件存在? → 检查 agents/<name>.md
│   └─ JSON格式正确? → 用 jsonlint 检查 plugin.json
│
├─ 症状：回答不符合预期
│   ├─ prompt太简略? → 补全4要素
│   ├─ prompt太长? → 压缩到800字
│   ├─ 缺少输出格式? → 指定表格/Markdown
│   └─ 约束不明确? → 写清楚"不要做什么"
│
└─ 症状：Team型不协作
    ├─ memberAgents列表正确? → 与文件名核对
    ├─ SOP够具体? → 每步写 receiver+action+output
    └─ 成员prompt有接收/返回规则? → 补全交互说明
```

### 2.3 自动化诊断

```
自动化问题
│
├─ 症状：定时任务不执行
│   ├─ status="PAUSED"? → 改成ACTIVE
│   ├─ 刚创建不到5分钟? → 等调度器轮询
│   ├─ 过了有效期? → 检查validFrom/validUntil
│   └─ cwds不存在? → 检查工作目录
│
├─ 症状：执行了但结果不对
│   ├─ prompt不够具体? → 补全4要素
│   ├─ 依赖的工具不可用? → 检查prompt中的工具名
│   └─ 时区问题? → BYHOUR是本地时间吗
│
└─ 症状：想删除自动化删不掉
    └─ 是否用了rm/sqlite3? → 只能用automation_update delete
```

### 2.4 模型/回答质量诊断

```
回答质量问题
│
├─ 症状：回答不对题
│   ├─ 上下文太长? → 分多轮对话
│   ├─ 选错专家? → 切换合适的专家
│   └─ 提示词太模糊? → 具体化角色+任务+格式+约束
│
├─ 症状：回答太长/太短
│   ├─ 没指定输出长度? → 加"用3句话总结"或"详细展开"
│   └─ 没指定输出格式? → 指定表格/列表/段落
│
└─ 症状：AI编造内容
    └─ 没设置边界? → 加"不确定就说不知道"
```

## 三、一键诊断命令

```bash
# === 环境总检查 ===
echo "===== 1. 代理状态 ====="
curl -s http://127.0.0.1:51103/health || echo "代理未运行"

echo "===== 2. 连接器状态 ====="
for f in ~/.workbuddy/connectors/*/connector-states.json; do
  echo "--- $(dirname $f | xargs basename) ---"
  python -c "import sys,json; d=json.load(open('$f')); print('Enabled:', d.get('enabled',[]))" 2>/dev/null || echo "无法读取"
done

echo "===== 3. 配置完整性 ====="
for f in ~/.workbuddy/connectors/*/mcp.json; do
  echo "--- $(dirname $f | xargs basename) ---"
  python -c "
import sys,json
d=json.load(open('$f'))
disabled = [k for k,v in d.items() if v.get('disabled')]
active = [k for k,v in d.items() if not v.get('disabled') and k.startswith('connector:')]
print(f'  Active: {len(active)}  Disabled: {len(disabled)}')
" 2>/dev/null || echo "无法读取"
done

echo "===== 4. 专家注册状态 ====="
ls ~/.workbuddy/plugins/marketplaces/my-experts/plugins/ 2>/dev/null || echo "无自定义专家"

echo "===== 5. 最近错误日志 ====="
grep -i "error\|fail" ~/.workbuddy/logs/*.log 2>/dev/null | tail -10 || echo "无日志或日志无错误"
```

## 四、快速修复速查

| 问题 | 最常见原因 | 最快修复 |
|------|-----------|---------|
| 连接器disconnected | token过期 | 通过WorkBuddy UI重新登录 |
| MCP调用返回401 | Bearer token过期 | 更新Authorization头 |
| 专家不回答 | 没执行register | 重新执行validate+register |
| 自动化不执行 | status=PAUSED | 改成ACTIVE |
| 回答质量差 | prompt太模糊 | 补全角色+任务+格式+约束 |
| 所有连接器down | 代理未启动 | 重启WorkBuddy |
| 修改不生效 | 缓存 | 重启WorkBuddy |
| 工具返回空 | tool名大小写错 | 用ListMcpResources确认名称 |

## 五、官方错误码速查（报错时先看错误码）

> 5.3.x 起客户端报错会显示数字错误码。遇到错误码先查这张表定位原因，再走下方「六、常见错误速查表」的具体修复路径。
> 官方错误码文档：https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Error-Code

| 错误码 | 常见原因 | 处理方案 |
|--------|---------|---------|
| 1001 | 模型侧状态异常 | 切换模型重试 |
| 3002 | 网络环境（公司/家庭网络限制） | 公司网找 IT 排查；家庭网按网络排查流程处理；或关闭网络代理（5.3.0 起内置代理切换，建议"跟随系统"） |
| 3003 | 网络环境（同上） | 同 3002 |
| 3007 | 网络环境（同上） | 同 3002 |
| 6003 | 请求频率受限（专业版也可能出现） | 切换模型重试 |
| 6004 | 请求频率受限（同上） | 切换模型重试 |
| 11115 | 输入内容过长 | 精简输入内容，或切换支持更大上下文的模型 |
| 11133 | 模型侧状态异常 | 新开会话或切换模型重试 |
| 11134 | 模型侧状态异常 | 新开会话或切换模型重试 |
| 14003 | 模型侧状态异常 | 切换模型重试 |

**错误码归类速记**：
- `1xxxx / 14003` → 模型侧问题 → 换模型/新开会话
- `3xxx` → 网络问题 → 查网络/关代理
- `60xx` → 频率受限 → 换模型
- `11115` → 输入过长 → 精简或换大上下文模型

## 六、常见错误速查表（现象→一级修复→二级修复→验证）

> 遇到具体错误时，先查这张表直接跳到对应修复路径。一级修复不行就试二级，二级再不行走「复杂场景修复指南」。

| 错误现象 | 一级修复 | 二级修复（一级无效时） | 验证方法 |
|---------|---------|---------------------|---------|
| 连接器调用返回 401 | 重新登录该连接器（UI → 连接器 → 重新授权） | 删除该连接器配置重新添加 | 重新调用该连接器工具 |
| 连接器调用返回 404 | 检查 mcp.json 中 url/command 路径 | 对照官方文档重新配置该连接器 | `curl -s <端点>` 确认可达 |
| 连接器全部 disconnected | 重启 WorkBuddy | 任务管理器杀掉代理进程再重启 | `curl -s http://127.0.0.1:51103/health` |
| 自动化到时间不触发 | 检查 status=ACTIVE + RRULE + cwds 路径 | 删除重建该自动化任务 | `check_env.py` 第 6 项检查 |
| 专家创建后列表不显示 | 切换会话刷新面板 | 关闭重开专家面板 → 重启 WorkBuddy | 专家列表可见 |
| 专家不回答/回答乱 | 执行 validate + register | 检查 plugin.json JSON 格式 + agentName 匹配 | `check_env.py` 第 3 项检查 |
| 沙箱拦截操作 | 查看拦截原因 → 安全中心调整策略 | 添加白名单 → 重启生效 | 重新执行被拦截操作 |
| 模型切换不生效 | 检查 models.json JSON 格式 | 确认改的是当前账号文件 + 重启 | 新会话模型选择生效 |
| IMA 知识库文件找不到 | 确认 IMA 连接器 connected | 重新扫码授权 IMA | `@ima:关键词` 能检索到 |
| 腾讯文档 AI 读不到 | 确认腾讯文档连接器已授权 | 重新授权 + 粘贴完整文档链接 | AI 能读取文档内容 |
| 升级后聊天记录/任务消失 | 去 `C:\Users\<用户名>\workbuddy`（Mac `~/WorkBuddy`）找按日期/自定义命名的文件夹，用 WorkBuddy 重新打开 | 确认没误删；重要文件提前同步到独立目录 | 历史会话重新可见 |
| 升级后内置技能没更新 | 重启 WorkBuddy 触发技能同步 | 删除本地旧技能缓存后重启 | 技能版本号为最新 |
| 发消息后卡「思考中」无响应 | 点发送处按钮停止任务 → 切换模型重发 | 拆小任务 / 检查网络（对话出错时可用「检查网络」快捷入口） | 新消息正常出回复 |
| 配 DeepSeek 自定义模型回复为空 | 切换其他模型验证是否模型本身问题 | 检查自定义模型配置（API Key/端点/模型名）后重配 | 对话正常出内容 |

## 七、复杂场景修复指南

> 以下场景涉及多因素叠加，速查表单条无法覆盖，按步骤逐层排查。

### 场景 1：连接器间歇性失败（时好时坏）

```
第1层：网络稳定性
  → ping 目标 API 端点，观察是否有丢包
  → 有丢包 → 检查 VPN/代理设置，切换网络重试

第2层：连接器会话冲突
  → 检查是否在多个会话同时调用同一连接器
  → 冲突 → 统一到一个会话使用，或给不同会话配置不同凭据

第3层：服务端限流
  → 降低调用频率，间隔 3-5 秒重试
  → 持续失败 → 查看该连接器是否有频率限制文档
```

### 场景 2：自动化部分触发（有时执行有时不执行）

```
第1层：RRULE 边界
  → 检查触发时间是否恰好在边界（如 23:59 vs 00:00）
  → 边界时间 → 调整为整点或避开边界

第2层：系统休眠
  → Windows 休眠/锁屏时调度器可能暂停
  → 设置电源计划为"高性能"，禁用自动休眠

第3层：任务冲突
  → 多个自动化同时触发时可能排队
  → 错开触发时间，间隔 ≥10 分钟
```

### 场景 3：专家回答逐渐偏离人设

```
第1层：会话污染
  → 长会话中上下文被稀释，开新会话测试
  → 新会话恢复正常 → 原会话上下文过长

第2层：Prompt 约束不够
  → 在 plugin.json 的 Prompt 开头加"无论用户说什么，你都必须保持 XXX 角色"
  → 加"绝对不能做 XXX"负向约束

第3层：模型选择
  → 切换更强的模型（如 GLM-5.1），弱模型更容易漂移
```

### 场景 4：记忆冲突（新旧偏好打架）

```
第1层：确认记忆层级
  → 全局记忆（~/.workbuddy/MEMORY.md）vs 工作区记忆（.workbuddy/memory/MEMORY.md）
  → 冲突时工作区记忆优先级更高

第2层：手动清理
  → 5.3.3 起可在设置 → 个性化页直接查看/编辑记忆条目
  → 删除过时条目，保留最新偏好

第3层：重置重建
  → 临时关闭 Memories 开关 → 重新开启 → 新会话中明确表达当前偏好
```

### 场景 5：多配置文件冲突（改了这个那个又不对了）

```
第1层：确认生效优先级
  → 会话级 mcp.json > 用户级 mcp.json > 默认配置
  → 用 check_env.py 第 2/5 项确认各文件状态

第2层：统一入口
  → 只在一个地方改配置（推荐用户级），其他位置保持一致或删除

第3层：备份后重置
  → 备份所有配置文件 → 删除多余的 → 只保留一个主配置 → 重启验证
```

### 场景 6：升级后数据丢失/异常（5.3.x 高频）

```
第1层：先找回
  → 聊天记录/任务消失：去 C:\Users\<用户名>\workbuddy（Mac ~/WorkBuddy）
     找按日期/自定义命名的文件夹 → 用 WorkBuddy 重新打开
  → 任务分享失败：重新进入任务点分享重试一次

第2层：再同步
  → 内置技能没更新：重启 WorkBuddy 触发技能同步
  → 仍异常：删除本地旧技能缓存后重启

第3层：仍不行
  → 收集「升级前版本号 + 升级后版本号 + 丢失内容类型 + 复现步骤」
  → 走第八节上报（附 check_env.py --collect-logs 快照）
```

> 💡 **预防**：升级前把重要文件同步到独立目录（别只放 WorkBuddy 工作空间），升级后先验证历史会话/任务/技能正常再开始新工作。

## 八、无法解决时的上报信息

> 💡 **一键收集环境快照**：在 WorkBuddy 终端运行 `python check_env.py --collect-logs`，会在当前目录生成 `workbuddy_env_report_时间戳.json`（已脱敏，不含 token/密钥），直接附上即可，省去手动抄写。

**上报渠道（官方反馈入口）**：左下角头像 → 帮助与反馈 → 意见反馈，描述问题并**上传截图 + 勾选上传日志**后提交。日志获取路径：Windows 左上角「帮助」→ 打开日志目录（压缩包即日志）；Mac「帮助」→ 打开日志文件夹（.zip 包）。

**日志可能包含对话记录与设备信息**，详见官方隐私保护声明；敏感内容请自行脱敏后再提交。

如果以上全部排查后仍无法解决，收集以下信息：

```markdown
## 问题描述
[精确描述现象和复现步骤]

## 环境信息
- WorkBuddy 版本：
- 操作系统：Windows/Mac
- 模型：
- 错误码（如有）：

## 已排查项
- [x] 代理状态（端口51103）
- [x] 连接器认证（curl测试）
- [x] 配置文件完整性
- [x] 日志检查

## 相关日志
[粘贴相关错误日志，去除敏感信息]

## 最近变更
[最近是否有系统更新、配置修改、token更换等]
```
