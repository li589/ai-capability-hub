# 周报模式执行流程

> 成文时必须同时遵守 [writing-style.md](writing-style.md)。编排与多行业并行见 [SKILL.md](SKILL.md)。

固定查询**过去 7 天**（以今天为基准）。**每个行业内部**每天一个查询，共 7 个查询同时并行发出。

## 第零步：决定是否启用并行 Subagent

- **1 个行业**：主 agent 直接执行下列步骤一至二
- **≥2 个行业**：先确认保存位置，再按 SKILL.md「并行 Subagent 编排」启动 Task；每个 subagent 完成「7 天拉取 + 完整周报」并**自己写入** `行业主题周报_{行业}_{日期}.md`；主 agent **只拼** `行业主题周报汇总_{日期}.md`。**禁止**主 agent 对 N 个行业各打 7 枪。

## 第一步：并行采集该行业 7 天数据

**在同一条消息中同时发出该行业全部 7 天的查询（1×7 个请求并行）。**

```
# 示例：今天=2026-05-21，1个行业，7个请求同时发出
research_query(type="minutes", industryName="{行业}", startTime="2026-05-15 00:00:00", endTime="2026-05-15 23:59:59", pageSize=50)
research_query(type="minutes", industryName="{行业}", startTime="2026-05-16 00:00:00", endTime="2026-05-16 23:59:59", pageSize=50)
...
research_query(type="minutes", industryName="{行业}", startTime="2026-05-21 00:00:00", endTime="2026-05-21 23:59:59", pageSize=50)
```

**处理溢出（出现 `<persisted-output>` 标签）：**

当某天内容过大被存为外部 JSON 文件时，**必须读取完整内容，不允许只用 2KB 预览**。按宿主返回的实际路径读取完整 tool-results JSON（路径随环境变化，以工具回传为准），禁止只用预览片段下结论。

**7 天数据全部到位后，直接进入分析，不需要写任何中间文件。**

> ⚠️ **如实记录原则同样适用于周报模式**。每天返回的所有纪要均属于该行业，禁止做任何二次筛选。**尤其是「每日纪要亮点」环节，必须覆盖当天所有纪要的主题。**

## 第二步：直接分析，输出周报

7 天内容全部在上下文后，直接进行跨天主题对比分析，识别四类变化：

1. **持续主线**：≥4 天出现的主题
2. **新兴方向**：后半周（d5/d6/d7）首次出现的主题
3. **降温方向**：前半周高频、后半周消失的主题
4. **观点转向**：同一主题在不同天观点明显变化

分析完成后写入最终报告。输出前先确认用户保存位置，未指定时默认当前工作空间。

**输出文件名：**

- **子代理写**子文件：`行业主题周报_{行业}_{今天日期}.md`（每行业一份）
- **主 agent 拼**总文件（多行业）：`行业主题周报汇总_{今天日期}.md`（目录索引 + 拼接各子文件全文；不要另做跨行业主题矩阵；优先脚本读盘合并）
