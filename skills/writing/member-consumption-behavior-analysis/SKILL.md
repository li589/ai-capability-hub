# 会员-消费行为分析

## 能力边界

仅使用本文已有消费、复购、回头、偏好和 RFM 模块；完整会员营业汇总、资产、生命周期、画像、评价与活动问题仍按现有路由处理，不改变分类标准或计算口径。

## 输入输出示例

- 输入：`生成本月复购会员分析报告，并说明重点保持和重点挽留会员。`
- 输出：按固定复购与 RFM 模块返回复购指标、分类标准、各类会员数量和既定报告产物，并标注周期和异常情况。

**类型**：领域 Skill | **可见性**：standard | **视角**：CRM/SCRM | **安全级别**：只读

## 职责

回答 SCRM 消费分析页面及复购相关深度问题，包括消费基础指标、趋势、复购整体指标、RFM 会员分类、复购健康度、老客回头与商品/来源分布。

## 触发意图

- 消费分析、营业额、消费笔数、客单价、消费人数
- 复购率、消费2次及以上、复购趋势、复购排行
- RFM、RFM会员分类、会员分类、会员分层、重点保持会员、重点挽留会员、哪个类别会员最多、分类标准
- 这些分类标准是怎么定的、哪个类别的会员数量最多
- 生成会员复购会员分析报告、完整复购分析报告、复购会员分析报告
- 复购健康度、21/60/90天复购
- 老客回头率、平均复购周期、未回访会员
- 商品偏好、消费来源分布、城市/门店/品牌维度消费占比

## 公共规范

公共规范已内置在本节，运行时不要额外打开公共规范维护副本；维护副本只用于发布生成，不是执行前置步骤。

- 路径：`references/...`、`scripts/...`、`pipelines/...` 均以当前 `SKILL.md` 所在目录为基准；工具需要路径时先定位当前 Skill 目录，再追加相对路径，禁止直接从运行时根目录拼接。
- 门店：用户提供门店名称、简称、别名或编码时，必须先按《门店编码获取》检索真实门店；无结果或多结果均停止并请用户补充或确认，唯一结果才可将真实门店编码传给本轮所有查询。不得把用户输入名称直接当作查询条件或报告标题；未指定门店时不传门店条件，按当前可用范围查询。
- 时间：默认最近 7 个完整自然日。对客户展示结果时，必须写明完整统计区间（如“7 月 9 日 00:00:00 至 7 月 15 日 23:59:59”）；需要上一周期时自动选取此前等长周期。
- 缓存：`cache/cysms-stores.json` 只作候选清单；不要主动读取或依赖 `cache/cysms-selected-stores.json`。
- 执行主体：本 Skill 必须由当前助手在当前会话内完成。除非用户明确要求多个助手协作，否则禁止创建子代理、子会话或把任何查询、分析、报告任务交给其他代理后等待。“并发”只表示固定脚本或数据查询可同时执行；“改读其他业务 Skill”只表示当前助手切换规则后继续处理。
- 安全输出：不暴露 token/session/cookie/密钥/内部 ID/taskId/查询编号/子命令名；会员、手机号、订单号默认脱敏；金额写“元”、人数写“人”、比例写“%”。
- 业务化表达：最终答复、表格和页面只展示经营结论、指标含义、统计范围与行动建议；查询名称、字段、脚本、数据结构及其他内部处理细节只用于内部，不得向客户展示。
- 失败与 JSON：命令失败不等于指标为 0，空数组不等于接口异常；优先读脚本 `summaryMetrics`/`summary`/`facts`，二次解析 JSON 优先用 Node.js `JSON.parse`，避免 jq 中文 key 引号问题。

## 路由判定规则

1. 用户问消费汇总或 SCRM 页面 → 「消费基础指标」，可与「消费趋势」**同时查询**。
2. 用户问复购率、消费2次及以上 → 「复购整体指标」。
3. 用户说 RFM、会员分类、会员分层、重点保持、重点挽留，或单独说“这些分类标准是怎么定的”、“哪个类别的会员数量最多” → 「RFM会员分类」。当前助手必须先读取 `references/modules--RFM会员分类.md`，再按其中完整时间执行一次固定脚本并直接回复；禁止转交子代理或子会话，禁止先用缺少截止时间的命令试跑，禁止搜索工作区中的 RFM 示例文件、临时创建分析脚本或改用卡型分布、高净值会员排行代替。
4. 用户问复购健康度、21/60/90天窗口 → 「复购健康度」。
5. 用户问老客回头率、未回访 → 「老客回头与未回访」。
6. 用户问商品偏好 → 「商品偏好排行」；问来源/占比 → 「消费来源分布」。
7. 完整会员营业数据、会员营收贡献、会员/非会员占比 → 当前助手改读「会员-概览与基础指标」→「会员营业完整汇总」。
8. 用户说“生成会员复购会员分析报告”、“完整复购分析报告”或同义表达 → 「复购会员分析报告」。必须先读取 `references/modules--复购会员分析报告.md`，再执行一次固定报告脚本；每次请求都必须新执行，禁止从记忆、历史会话或已有报告目录复用、查找旧报告；最终回复必须原样包含脚本返回的 `reportLinkMarkdown`；禁止逐条手工查询、禁止临时写报告文件、禁止转交子代理或子会话。
9. 完整消费报告 → G1 内各模块**可同时取数**，按 基础 → 复购/RFM → 偏好/来源 顺序**展示**。

## 输出契约

1. **首句结论**：消费与复购健康度判断。
2. **查询范围**：时间、上一周期、卡型、门店、`newMemberType`、`hasTakeOut`。
3. **核心指标**：金额/笔数/人数/比例带单位；趋势仅 `dateList` 对齐时按下标解释。
4. **对比说明**：复购较上一周期用 `FloatRangeValue/Type`。
5. **明细限制**：会员明细默认最多 3 条脱敏样例。
6. **RFM结果**：按查询返回的真实分类展示会员数、有余额人数、平均未到店天数和建议；不得自行改分类名称、虚构分类数量或用 TOP 会员数量代替分类结果。

## 失败处理

- 单模块失败继续其他模块；基础指标失败须标注缺少汇总。
- 命令名 `comsume` 拼写须保持原样，不可改为 `consume`。
- 老客未回访名单受 `limit` 截断时须说明。
- RFM固定脚本缺少截止时间、失败或返回空结果时，说明本次未取得有效分类结果；不得绕过参数校验、扫描示例文件、改写查询或把空结果解释为没有会员。
