# 复购会员分析报告

## 适用意图

- 生成会员复购会员分析报告
- 生成完整复购分析报告
- 同时查看复购表现、RFM 分类和复购健康度

## 直接执行规则

1. 当前助手对每次请求都执行一次固定报告脚本并等待完成；禁止从记忆、历史会话或 `repurchase-report-runs` 中读取、搜索、挑选旧报告，不逐条手工查询，不搜索示例，不临时创建报告脚本，不转交子代理或子会话。
2. 用户未指定时间时，固定使用最近 7 个完整自然日，传入 `--endDate "auto"`；脚本自动计算本期和上一等长周期。
3. 用户指定门店时，先完成门店唯一匹配，再将真实门店编码传给报告脚本；未指定门店时不传门店条件。
4. 脚本内部同时获取复购核心指标、RFM 会员分类和 21/60/90 天复购健康度。任一模块失败时继续生成其他有效内容；不把失败或空结果解释为 0。
5. 脚本返回成功后，使用返回的业务摘要直接给出结论，并交付已生成的 HTML 报告。最终回复必须原样包含脚本返回的 `reportLinkMarkdown`，该值已是可打开报告的完整 Markdown 链接；不用绝对路径重新组装，不再重新查询。

## 固定执行

```bash
node skills/会员-消费行为分析/scripts/render_repurchase_health_card.js \
  --section repurchase-report \
  --endDate "auto" \
  --outDir "repurchase-report-runs"
```

用户指定截止日时，将 `auto` 替换为截止日下一天 `00:00:00`。用户指定完整开始时间时，追加 `--startDate "<yyyy-MM-dd 00:00:00>"`。

## 结果要求

- 开头直接说明复购表现和最需关注的会员类别。
- 展示完整统计区间，结束时间展示到 `23:59:59`。
- 展示消费会员数、复购会员数、复购占比、与上一周期的变化、RFM 各类人数和复购健康度。
- 只使用脚本返回的实际分类和数值；不自行改名、估算或用卡型数量代替 RFM 数量。
- 某个模块不可用时，用业务语言说明该部分暂未取得，不展示查询细节。
- 回复末尾必须包含 `reportLinkMarkdown`，不得只说“报告已生成”。
