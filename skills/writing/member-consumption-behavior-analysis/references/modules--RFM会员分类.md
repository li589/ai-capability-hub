# RFM会员分类

## 适用意图

- 跑一下 RFM 会员分类分析
- 查看会员分类、会员分层或各类别会员数量
- 查询重点保持、重点挽留等会员群体
- 判断哪个会员类别数量最多
- 解释 RFM 分类标准或给出分类运营建议

## 直接执行规则

1. 命中上述意图后，由当前助手直接执行本模块固定脚本并在同一轮给出结果；不要转交子代理或子会话，不要搜索工作区中的 RFM 示例文件，不要读取无关配置，不要临时创建分析脚本，也不要使用高净值会员排行代替 RFM 分类。
2. 用户未指定门店时，按当前可用门店范围查询；用户指定门店时，先完成门店唯一匹配，再传入真实门店编码。
3. 用户未指定截止日期时，固定传 `--endDate "auto"`，由脚本自动选择最近一个完整自然日；不要由模型自行计算日期。用户指定截止日时，对客户展示到该日 `23:59:59`，查询时使用下一日 `00:00:00`。
4. 用户未指定分类标准时，使用固定默认值：回看最近 365 天消费记录，连续 60 天未到店视为流失风险，高消费门槛 1000 元，高频门槛 5 次。必须在结果中用普通业务语言说明这些默认口径。
5. 只执行一次完整命令。禁止先省略 `endDate` 试跑，也禁止传入只有日期、没有时分秒的截止时间。

## 固定执行

```bash
node skills/会员-消费行为分析/scripts/render_repurchase_health_card.js \
  --section rfm \
  --endDate "auto" \
  --lostDays "<默认60>" \
  --rfmHistoryDays "<默认365>" \
  --highValueAmount "<默认1000>" \
  --highFrequencyCount "<默认5>" \
  --outDir "rfm-card-runs"
```

指定门店时追加 `--omShopCodes "'<真实门店编码>'"`。只允许使用门店查询唯一返回的真实编码。

用户明确指定截止日时，将 `auto` 替换为截止日下一天的完整时间，例如用户要求截至 7 月 15 日，则传 `2026-07-16 00:00:00`。

## 结果解释

- 按查询实际返回的分类名称展示，不自行重命名或合并分类。
- 统计截止必须读取脚本结果中的展示截止时间，向客户展示到 `23:59:59`；不得把查询使用的下一天 `00:00:00` 说成统计截止日。
- 展示每类会员数量、有余额人数、平均未到店天数和对应运营建议。
- “哪个类别最多”必须根据本次分类结果比较后回答，不能根据经验猜测。
- “重点保持和重点挽留有什么区别”应结合消费价值、消费频次和距离最近一次消费的时间，用业务语言解释；不要展示字段名、脚本、任务编号或数据结构。
- 用户只问分类结果时，不展开会员个人明细；需要明细时最多展示少量脱敏样例。

## 失败处理

- 固定脚本执行失败：说明本次暂未取得有效分类结果，并建议稍后重试。
- 缺少完整截止时间：先按默认时间规则补齐，再执行；不得用空值或仅日期格式继续查询。
- 返回空结果：说明当前查询范围未取得可用分类数据，不得解释为所有分类人数都是 0。
- 分类字段缺失：停止给出“最多类别”或确定性运营结论。
