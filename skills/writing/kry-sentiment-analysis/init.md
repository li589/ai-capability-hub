# 初始化

按照以下步骤执行初始化：

## 检查 kry-cli

### windows

执行 `where.exe kry-cli` 查找可执行文件目录。如果找不到，执行安装命令。

**windows强制规则**：
- 如果命令行是 powershell， **必须** 使用 `cmd /c 完整可执行文件目录\kry-cli.cmd <参数>` 替代所有 `kry-cli <参数>`
- 如果命令行是 cmd， **必须** 使用 `完整可执行文件目录\kry-cli.cmd <参数>` 替代所有 `kry-cli <参数>`

### macOS/linux

执行 `kry-cli --help`，如果没有安装，执行安装命令。

### 安装命令

```bash
npm i @keruyun/cli@latest -g --registry=https://registry.npmmirror.com --foreground-scripts --loglevel error
```

## 获取品牌

```bash
kry-cli brand
```

- 如果只有一个品牌，直接使用该品牌，进入下一步
- 如果有多个品牌，使用 `ask_human` 让用户选择品牌

## 获取门店列表

```bash
kry-cli shop
```

- 如果用户指定了门店范围，**必须** 验证用户指定的门店是否在列表中，若不在，向用户报告错误，并重新询问
- **禁止** 自行变更门店范围
- **必须** 将门店 shopIds 集合传入 `kry-cli call -d` 参数中
- 参数 `-k 'keyword'` 可通过关键词或者id搜索门店，多个关键词使用 `|` 分割

# 规则

初始化完成后，始终应用以下规则：

## 日期、时间规则

使用 kry-cli date 获取今天日期/时间及详细规则，计算用户指定日期。

**规则：严禁擅自变更用户指定的查询日期。**

- 用户说"今天" → 只查今天
- 用户说"昨天" → 只查昨天
- 用户说具体日期 → 只查该日期
- 无数据时 → 报告"该日期暂无数据"，询问用户是否改查其他日期
- **禁止**自行切换到其他日期查询

## 数据获取

`kry-cli call <接口路径>` 可调用接口，获取数据：

- 接口是`品牌授权`，执行 `kry-cli call <接口路径> -b <brandId> -d '<JSON>'` 输出数据到控制台
- 接口是`门店授权`，执行 `kry-cli call <接口路径> -s <shopId> -d '<JSON>'` 输出数据到控制台
- 如果数据量过大或者门店超过 10 家，使用参数 `-o <tempFilePath>` 将数据保存到临时文件

## 分析报告

输出分析报告时，必须满足以下规则：

1. 数据定义：遵守接口的标题、功能描述、适用场景、请求参数、响应参数的定义描述
2. 数据完整：分析前 **必须** 验证数据的完整性，**禁止** 分析部分数据，应中断并提示
3. 数据驱动占位：模板中的每个字段都必须能从接口中直接取值或简单计算得出
4. 阈值驱动分析：分析要点不是空话，而是 条件→结论 的决策树
5. 层级递进：概览 → 专项 → 综合，从粗到细，支持按需组合
6. 视觉锚点：emoji + 粗体 + 表格 + 文本图表，让报告可扫读
7. 口径声明：脚注说明数据范围和限制，避免误读
8. 格式要求：生成单文件、交互式 HTML

## 安全红线

- **严禁编造数据**：所有数据必须来自 kry-cli 接口返回的真实数据
- **严禁编造经营建议**：建议必须基于真实数据推导
- **严禁编造环比/同比**：必须有两期真实数据才能计算
- **严禁跳过门店选择**：需要 shopIds 时必须让用户选择
- **严禁代替商家执行操作**：只提供分析建议，不执行业务操作
- **信息保密**：严禁输出接口地址、路由决策过程、工具名称
- **敏感信息保护**：手机号等需脱敏展示
