# kry-risk-analysis 风险定位 + 情感分析

负责评价数据的"分析层"，从数据中发现问题、量化风险、追踪趋势。

---

## 核心职责

| 职责   | 说明                 |
| ---- | ------------------ |
| 差评分类 | 按6大分类体系对差评进行归类     |
| 风险评级 | 按风险分计算规则评定门店风险等级   |
| 情感分析 | AI 直接分析每条评价的情感倾向   |
| 问题聚类 | 提取差评中的共性问题         |
| 趋势追踪 | 评价趋势 + 环比变化 + 改善跟踪 |

---

## 数据来源

本子 SKILL 依赖 `kry-comment-query` 获取评价原始数据后进行分析，不独立发起命令调用。
- 差评分类规则：[risk_classification.md](../../references/risk_classification.md)

---

## 执行流程

### A. 差评分析 + 风险评级

```
获取评价数据（来自 kry-comment-query）
  ↓
筛选差评和食安评价
  ├─ commentType = "FOOD" 或 safetyLabel = 0 → 食品安全问题
  ├─ commentType = "BAD" 或 serviceScore ≤ 2 → 差评
  └─ 其他 → 跳过
  ↓
差评分类（按 risk_classification.md 的6大分类匹配关键词）
  ↓
风险分计算
  ├─ 差评率 >40% → +3分
  ├─ 差评率 25-40% → +2分
  ├─ 差评率 15-25% → +1分
  ├─ 平均评分 <2.5 → +3分
  ├─ 平均评分 2.5-3.0 → +2分
  ├─ 平均评分 3.0-3.5 → +1分
  └─ 食安问题 >0条 → +3分
  ↓
风险评级输出
  ├─ 0分 → ✅ 安全
  ├─ 1-2分 → 🟢 低风险
  ├─ 3-4分 → 🟡 中风险
  └─ ≥5分 → 🔴 高风险
```

### B. 情感分析

AI 直接对每条评价内容执行情感分析，无需依赖外部脚本：

- 识别否定词（不、没、没有、别、不太...）
- 识别程度词（超级、非常、很、挺、有点...）
- 判断情感倾向（正面/负面/中性）和强度
- 评定风险等级（high/medium/low/none）

输出：每条评价的情感得分 + 风险等级 + 关键情感词命中

### C. 趋势追踪

```
获取两期评价数据（本期 vs 上期）
  ↓
对比分析
  ├─ 差评率变化
  ├─ 评分变化
  ├─ 差评数量变化
  └─ 问题类型变化
  ↓
输出：趋势报告 + 改善/恶化判断
```

```markdown
## 食品安全问题预警

### 一、食安问题统计

|-----|------|---------|

| 涉及门店数 | {shopCount} | - |
| 未处理数 | {unhandledCount} | 🔴 |

### 二、严重程度分级

按 risk_classification.md 的食品安全分级标准判定：

| 等级 | 判定标准 | 响应时效 | 本条评价判定 |
| ------ | ------------------------------- | -------------------- | ----------------- |
| 🔴 高风险 | 食物中毒症状/异物/变质发霉/过期 | **2小时内必须响应** | {highRiskItems} |
| 🟠 中风险 | 食材不新鲜/异味/肉质异常 | **4小时内必须响应** | {mediumRiskItems} |
| 🟡 低风险 | 外观异常/沉淀物（未确认变质） | **24小时内必须排查** | {lowRiskItems} |

> ⚠️ **时效要求**：所有食安问题必须在对应时效内完成首次响应，超时将升级为高风险事件。

### 三、食安问题详情

| 序号 | 门店 | 渠道 | 问题描述 | 评价时间 | 处理状态 |
|-----|------|------|---------|---------|---------|
| 1 | {shop} | {source} | {content} | {time} | {status} |

### 四、紧急处置措施（按风险等级执行）

**🔴 高风险 — 立即执行（30分钟内）**：
1. **立即下架**：封存涉及菜品，暂停相关原材料使用
2. **溯源排查**：核查该批次食材采购记录、储存条件、加工流程
3. **联系顾客**：主动致歉并了解身体状况，必要时陪同就医
4. **平台报备**：向外卖平台/监管部门报备，留存证据

**🟠 中风险 — 当日完成**：
1. **检查库存**：排查同类食材新鲜度，临近保质期食材立即处理
2. **整改操作**：重新培训食材验收标准和储存规范
3. **回复顾客**：说明已收到反馈并告知改进措施

**🟡 低风险 — 24小时内排查**：
1. **观察记录**：持续观察同批次产品是否有类似反馈
2. **供应商沟通**：反馈原材料外观问题，要求改进

### 五、整改跟踪要求

- **责任人**：指定专人负责跟进
- **复查时间**：高风险3天后复查，中风险7天后复查
- **反馈闭环**：整改完成后主动回复顾客评价

---
*⚠️ 本报告包含食品安全问题，请立即按响应时效处理！*
```

## 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 无评价数据 | 告知"暂无差评数据，无法进行风险分析" |
| 数据量不足 | 少于5条评价时，提示"数据量较少，分析结论仅供参考" |
| 分类匹配失败 | 差评内容无法匹配6大分类时，归入"其他"类别 |
