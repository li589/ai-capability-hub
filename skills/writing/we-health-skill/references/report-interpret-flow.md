# 报告解读追问流程

> 本文件由 SKILL.md 主流程按需引用，不可独立执行。
>
> 本 Skill 严格限制：**最多追问 1 次**。

---

## 核心规则

| 规则 | 说明 |
|------|------|
| 先判断信息充分性 | AI 需先判断 query 是否含足够信息（症状、持续时间、病史等），充分时直接解读，不足时才走追问流程 |
| 最多追问 1 次 | 整个报告解读流程中，向用户追问最多 1 轮 |
| 追问后必须解读 | 用户回答追问后，下一次 API 调用必须使用 `--no-followup` |
| 严禁无限追问 | 不得进行第 2 轮及以后的追问 |
| 合并 query | 追问回答必须与原始 query 合并，不能丢失报告上下文 |

---

## 完整流程

### 阶段 1：信息充分性判断

AI 在调用 API 前，先判断当前 query 是否包含足够信息进行解读：

| 判定 | 条件 | 示例 |
|------|------|------|
| **充分** | 含症状描述、持续时间、相关病史或具体关注点 | "帮我解读血常规报告，最近一周头晕乏力，血红蛋白偏低" |
| **不足** | 仅要求解读，无任何上下文 | "帮我看看这份报告" |

- **充分** → 跳到阶段 5，首次调用即用 `--no-followup` 直接解读
- **不足** → 进入阶段 2

### 阶段 2：首次查询（正常调用）

用户上传报告（图片或 PDF），AI 不加 `--no-followup` 调用 API：

```bash
python3 scripts/query.py --stdin << 'EOF'
{
  "query": "帮我解读这份体检报告",
  "file_list": [
    {"file_url": "https://...", "file_type": "pdf"}
  ]
}
EOF
```

### 阶段 3：判断返回类型

API 返回 `markdown_content`，AI 需判断是**追问问题**还是**解读结果**：

| 特征 | 追问问题 | 解读结果 |
|------|---------|---------|
| 长度 | 简短（通常 1-3 句话） | 较长（包含指标分析、建议等） |
| 内容 | 向用户提问 | 报告指标解读、异常分析、健康建议 |
| 结尾 | 通常以「？」结尾 | 通常以总结或建议结尾 |
| 结构 | 无结构化分析 | 可能包含标题、列表、表格等 |

- **判定为解读结果** → 跳到阶段 6，直接展示结果
- **判定为追问问题** → 进入阶段 4（第 1 轮追问，也是唯一一轮）

### 阶段 4：展示追问，等待用户回答

将 API 返回的追问问题展示给用户，等待用户回答。

> 注意：这是**唯一一轮**追问。无论 API 返回的追问包含几个问题，都作为一轮处理。

### 阶段 5：直接解读（加 `--no-followup`）

根据进入路径不同，query 组合方式不同：

- **从阶段 1 进入**（信息充分）：query = 原始 query，直接加 `--no-followup`
- **从阶段 4 进入**（追问后）：query = 原始 query + 用户补充

```bash
python3 scripts/query.py --stdin << 'EOF'
{
  "query": "帮我解读这份体检报告。用户补充：最近有点头晕，持续约一周",
  "file_list": [
    {"file_url": "https://...", "file_type": "pdf"}
  ],
  "no_followup": true
}
EOF
```

或 CLI 模式：

```bash
python3 scripts/query.py "帮我解读这份体检报告。用户补充：最近有点头晕，持续约一周" --no-followup
```

#### query 合并规则

```
新 query = {原始 query}。用户补充：{用户回答}
```

- 保留用户原始问题（如「帮我解读这份体检报告」）
- 追加追问回答，前缀为「。用户补充：」
- `file_list` 与首次查询保持一致（同一份报告）
- 如用户回答包含多个信息点，用逗号或分号拼接

#### `--no-followup` 的作用

启用后在 query 末尾追加「（请直接解读报告，无需追问，直接给出解读结果）」，其中「直接解读」是服务端识别的跳过追问关键词，触发服务端直接进入解读流程。

### 阶段 6：展示解读结果

将 API 返回的 `markdown_content` **原样完整展示**给用户（不得删减、精简、改写或截断，见 SKILL.md 核心规则 14），末尾附加免责声明：

> ⚠️ 以上健康信息仅供参考，具体诊疗请遵医嘱。如有紧急情况请立即就医或拨打 120。

#### 兜底处理：API 仍返回追问

如果阶段 5 调用后 API 仍返回追问问题（而非解读结果）：
- **不要**将追问展示给用户
- **不要**进行第 2 轮追问
- 直接告知用户：「根据您提供的信息，以下是对报告的解读：」
- 将 API 返回的 `markdown_content` 原样完整展示，附加免责声明

## 禁止行为清单

| # | 禁止行为 | 原因 |
|---|---------|------|
| 1 | 不判断信息充分性直接调用 API | 信息充分时应直接解读，减少不必要追问 |
| 2 | 进行第 2 轮追问 | 违反「最多追问 1 次」规则 |
| 3 | 阶段 5 调用 API 时不加 `--no-followup` | API 可能继续返回追问 |
| 4 | 将追问回答作为独立 query 调用 API | 丢失原始报告上下文 |
| 5 | `file_list` 与首次查询不一致 | 导致解读的是不同报告 |
| 6 | 阶段 5 后仍向用户提问 | 陷入无限追问循环 |
| 7 | 删减、改写或截断 `markdown_content` | 违反核心规则 14 |
