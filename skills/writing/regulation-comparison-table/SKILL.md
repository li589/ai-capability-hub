# 新旧条文对比表生成

生成新旧法规/合同条款的逐条对比 Excel 表，交付质量对标团队既往人工制作的"新旧法规逐条对比表"成果。

## 核心交付标准（务必遵循）

参照历史成果的固定范式，不要自行发明新的表格结构：

1. **以新文为主轴**：按新条文的自然顺序（第一条→最后一条）逐条排列，旧条文对齐放在左侧。绝不按旧文顺序排列。
2. **完整正文并列，不重复条次编号**：旧条文列、新条文列都放**完整条文原文**，不做摘要或截断。由于 `old_no`/`new_no` 列已经单独列出条次编号，**单条对应场景下正文开头不要重复写"第X条"**，避免信息冗余；**仅当该行是组合条次（多条合并为一行，如"第九条 + 第十条"）时**，才需要在正文里对各条内容做区分标注（如按顺序换行并标注各自出处），避免多段原文混在一起分不清边界。
3. **差异用颜色/删除线呈现，而非用括号加注说明**：相同部分黑色，改动部分新文标红加粗、旧文灰色删除线。此高亮渲染由脚本自动完成（词语级 diff，以完整词语为最小比较单元，而非逐字符比较），不需要手动标记。
4. **新增条款**：旧条文列写"（无对应条款）"，新条文列全文标红加粗。
5. **删除条款**：新条文列留空，旧条文列全文加删除线。
6. **拆分/合并条款**：条次列直接写组合形式，如旧"第九条 + 第十条 + 第十一条"对应新"第九条"。若拆分/合并发生在**款级别**（同一条内不同款被拆到不同新条，或不同条的某几款被合并进同一新条），支持细化到款级写法，如 `"第九条第二款"`，此时对应的原文只需填该款内容，不必强行把整条重复粘贴多次。详见 [references/table-format-spec.md](references/table-format-spec.md) 中"款级别拆分/合并"说明。
7. **无法挂靠主表的旧条款**（内容打散并入多个不相邻条款、或彻底删除）：汇总到表格末尾"旧文中未被保留的条款"区块，并写明去向。
8. **每条一句话变更说明**：简洁点出实质变化（如"新增平台内容治理责任""细化主体资质要求""表述调整"），不写长篇法律分析。
9. **不生成法务评注/风险提示列**：历史成果中的法务注释列属于人工附加内容，本技能默认不生成，除非用户明确要求。
10. **多部法规/多份合同对比**：每部单独一个 sheet，sheet 名即法规/合同简称。
11. **逐字照录原文，禁止擅自修改或衍生解读**：新旧条文列必须完整保留原文字面内容，不得润色、改写、补全残缺内容，也不得加入基于个人理解的引申解读；一句话变更说明只能做客观归纳，不能超出原文字面进行主观解读。详见 [references/source-verification.md](references/source-verification.md)。
12. **表头附官方原文超链接**：来源核实确认后，应在整理输入 JSON 时填写 `old_source_url`/`new_source_url` 字段，脚本会自动为旧条文列、新条文列表头加上超链接，方便用户点击直接核验来源，无需用户额外要求。
13. **判定"纯新增条款"前必须先做关键词+语义双重确认**：不能仅凭"旧文里没有条次编号完全对得上的这一条"就断定为新增，也不能仅凭关键词字面命中与否下结论。必须提取该条的核心关键词/规制事项（如具体的行为主体、禁止性规定、处罚措施、义务内容），在旧文全文中做关键词检索，并进一步从**语义/规制意图**层面判断：即使关键词、措辞完全不同，只要旧文中存在规制同一事项、同一行为、同一法律后果的条款/款项，也不能算纯新增。只有关键词检索和语义判断都确认旧文全文（含任何条款、任何款项）中不存在对应规制内容后，才能标注为纯新增（`old_no`/`old_text` 留空）。详见第二步规程第 8 条。
14. **同一行的新旧文本必须做语义对应关系校验，不能只看字段是否填齐**：`rows` 中每一行把某条旧文与某条新文放在一起，本身就是在断言"这两者是同一事项的新旧版本"。这个断言必须基于对两段文字规制内容、适用主体、法律后果的实质理解来验证，不能因为字段凑巧都填了值、或条次数字看起来接近就认为对应关系天然成立。详见第二步规程第 9 条、第四步校验第 6 项。

## 工作流程

### 第一步：获取新旧条文原文

- 若用户已上传新规、旧规（或新旧合同）原文文件（docx/pdf），直接提取全文，按条款/条文切分。
- 若用户未提供原文，需要联网检索获取：**必须先阅读 [references/source-verification.md](references/source-verification.md)**。用户说"最新修订的 XX 法"时，**最容易出错的不是识别出草案，而是检索本身不彻底**——只搜到第一批结果就当作最新版，根本没意识到可能已有更新的正式修订发布。因此必须先完成文档中"检索是否存在更新版本"的主动排查（用带时效性的关键词二次检索证伪、核查最新立法动态），确认没有遗漏更晚的版本后，再执行可信来源核实（仅信任国家级/部委级官网发布）和发布阶段核实（确认是已正式通过公布的定稿，而非征求意见稿/草案/审议稿）。任一环节存疑都必须停下向用户确认，禁止直接采用未经充分检索或来源存疑的结果生成对比表。
- 合同场景通常由用户直接提供新旧版本文件，无需检索。

### 第二步：逐条对齐新旧条文

这是最需要人工判断（而非机械脚本）的一步，也是历史上出错率最高的一步（曾发生过因跳跃式内容相似度匹配漏检中间插入的新增条款，导致后续全部条次系统性错位的事故）。必须严格按以下规程执行，禁止凭"内容相似度"跳跃匹配：

1. **逐条顺序核对，禁止跳跃匹配**：按新文条次自然顺序（第一条、第二条、第三条……）逐条核对，每次只判断"当前这一条新文"对应旧文的哪一条。不允许先扫一遍找相似内容再回填，那样容易跳过中间插入的新增条款而导致后续条次连锁错位。
2. **同步维护一个"旧文已用条次"清单**：每对齐一条旧文条次，就从"待归宿清单"中划掉。核对完新文全部条次后，检查旧文清单是否有剩余条次未被划掉；若有，说明这些旧条款未被吸收，必须归入"未被保留的条款"区块，禁止遗漏。
3. **警惕条次数字本身不能说明对应关系**：新文"第十一条"不代表必然对应旧文"第十一条"，必须以条文内容为准。凡遇到新文中出现旧文没有的规定（纯新增）、或新文条次相对旧文发生错位，都要如实按对齐结果记录，不要因为条次数字凑巧相同就想当然地配对。
4. **完成初次对齐后，做一次条次连续性自检**：检查 `rows` 中的 `new_no` 是否覆盖新文从第一条到最后一条的完整序列、没有遗漏或重复；`build_comparison_table.py` 会在生成时自动做这项检查并打印警告，但人工过一遍更可靠。
5. 条次发生整体后移/前移（如旧文一条拆成新文三条、或新文中间插入新条款导致后续条次整体错位）时，如实按对齐结果记录组合条次，不要强行按序号对应。
6. 每对条文写一句变更说明，聚焦实质变化点；纯文字顺序调整、无实质内容变化的可留空或简单标注"表述调整"。
7. **警惕机构名称/专有名词整体替换、以及仅一两字不同但语义完全不同的词语被拆散误判（重要，曾发生误判事故）**：脚本已采用词语级 diff（以完整词语为最小比较单元），能大幅缓解"工商行政管理部门"→"负责商标执法的部门"因共享单字被误判局部未变、"恶意侵犯"→"故意侵犯"仅标出单字差异等历史误判问题。但词语级diff依赖分词库，仍可能因分词切分不理想而残留误判，不能完全免除人工核验义务。撰写 `change_note` 时，凡涉及机构名称、职务主体整体替换，或看似"只改了一两个字"但涉及主观恶性程度（如"恶意"变"故意"）、期限、数额、法律后果等关键要素的情形，都要基于两个词语的完整语义重新判断，如实指出"机构主体变更""职责归属调整""主观要件变更"等实质内容，不能只看渲染出来的高亮范围大小来判断改动程度。详见 [references/source-verification.md](references/source-verification.md) 中"差异高亮的局限性"章节。
8. **判定新增条款前，必须用关键词+语义双重确认，不能只靠字面检索或条次对不上就下结论（重要，防止误判）**：当某一新文条款在初步核对中找不到明显对应的旧文条次时，不要直接判定为"纯新增"。正确做法分两层：第一层，提取该条的核心关键词/规制事项（例如具体的行为主体名称、禁止性用语、处罚金额、义务表述、适用场景），拿这些关键词去旧文全文中检索，逐一排查是否存在于旧文的任何条款、**任何款项**中；第二层，即使关键词检索没有直接命中，也要进一步从**语义和规制意图**角度判断——旧文中是否存在措辞完全不同、但实际规制的是同一行为/同一事项/同一法律后果的条款，因为修订时常见的做法是换一套说法表达相同的规制内容，此时字面关键词可能完全不重合，但本质并非新增。只有关键词检索和语义判断都确认旧文全文（含藏在其他条的某一款里的情形）中不存在对应规制内容后，才能最终定性为"纯新增条款"（`old_no`/`old_text` 留空）。如果发现旧文某条的某一款确实规制了相同事项（无论措辞是否相似），应改用"款级别拆分/合并"的写法（见 [references/table-format-spec.md](references/table-format-spec.md)），把该款的原文填入 `old_text`，而不是标记为无对应条款。
9. **对齐产生的每一行，都要做一次"同一事项"的语义校验，不能只满足于字段填齐**：完成初步对齐、写入某一行的 `old_no`/`old_text`/`new_no`/`new_text` 后，不要想当然地认为字段填上了就代表对应关系成立。要反问自己：这两段文字规制的是否确实是同一件事（同一行为主体、同一适用场景、同一权利义务或法律后果）？条次数字接近、内容表面相似、甚至共享若干关键词，都不能替代这个判断。尤其警惕两种反向错误：一是把实际无关但凑巧条次相邻/内容表面相似的两条错误配对成"新旧对应"；二是把实际是同一事项、只是表述大幅改写的两条误判为互不相关（从而错误标注为"新增"和"删除"各一条，而不是"修改"关系）。发现语义上根本不对应的两条被放在同一行时，必须重新核对，找到各自真正对应的条款或改判为新增/未保留。

### 第三步：整理为 JSON 并生成 Excel

按 [references/table-format-spec.md](references/table-format-spec.md) 中的字段规范，将对齐结果整理成 JSON 文件，然后调用脚本生成最终 Excel：

```bash
python3 scripts/build_comparison_table.py <input.json> <output.xlsx>
```

脚本会自动完成：标题行、图例说明行、表头、逐条对比行的词语级差异高亮渲染（相同片段黑色，新文改动片段标红加粗，旧文改动片段灰色删除线）、末尾未保留条款区块。**不需要**手动在 Excel 中设置颜色或字体，也不需要手动做差异比对。首次使用请确保已安装依赖（`pip install -r scripts/requirements.txt`，核心是 `openpyxl` 和 `jieba`）；若环境缺少 `jieba`，脚本会自动降级为字符级diff并打印警告，此时机构名称/专有名词整体替换等场景的误判风险会重新出现。

### 第四步：交付前全方位校验（生成结果后必做，不可省略）

结果生成后，禁止直接交付，必须完整走完以下六项校验，任一项发现问题都要退回相应步骤修正后重新生成，再重新走一遍校验：

1. **条次连续性校验**：读回生成的文件，打印每一行的"对应旧条次"与"新条次"两列，确认新条次列从第一条到最后一条连续无遗漏、无重复；若发现跳号或重复，说明第二步对齐存在遗漏，必须回到第二步重新核对。运行脚本时也要留意终端输出的自动告警。
2. **逐条原文文字级核验（重点，最容易被忽略）**：将生成结果中每一条的 `old_text`/`new_text` 与最初获取的原始来源文本（用户上传文件或联网检索到的官方原文）逐字比对，确认没有在录入/整理 JSON 过程中出现的漏字、错字、多字、标点差异、条款顺序颠倒等问题。这一步核验的是"文字是否忠实原文"，与条次编号是否连续是两个独立维度，编号连续不代表文字内容没有被抄错，必须都查。同时要重新审视每条的 `change_note`：凡涉及机构名称、职务/部门主体整体替换的（如"商标局"变"国务院商标管理部门"），或仅一两字不同但语义完全不同的词语（如"恶意"变"故意"），即便词语级diff渲染已比早期字符级diff更准确，仍要基于完整语义复核 `change_note` 是否如实指出了这类实质变更，不能机械信任渲染范围大小。
3. **新旧文双向覆盖核验**：分别确认新文从第一条到最后一条、旧文从第一条到最后一条，每一条都能在生成结果中找到（新文各条落在 `rows` 的 `new_text`，旧文各条落在 `rows` 的 `old_text` 或 `unretained_clauses` 的 `old_text`），不存在被整体遗漏、既没进主表也没进未保留区块的"消失条款"。同时要检查旧文条次是否被**错误地重复关联到多个新条次**：正常的"一拆多"（一条旧文拆给多条新文）每一处都应有 `change_note` 写明"拆分自旧XX条"；如果某个旧条次出现在多行但其中某一行的 `change_note` 写的是"新增条款、与旧文无关"却仍填了这个旧条次，说明该行的 `old_no`/`old_text` 字段和 `change_note` 自相矛盾，必须以 `change_note` 描述的语义关系为准去修正字段值（曾发生过将纯新增条款误填了旧条次全文，制造出虚假的"一对多"错觉的事故）。对于所有标注为"（无对应条款）"的纯新增行，逐一确认第二步第 8 条的关键词+语义双重确认确实已执行过（不仅检索了关键词，还判断了旧文中是否存在换了说法但规制同一事项的条款），不能是凭"条次对不上"或"关键词没搜到"就直接留空，若发现漏检，必须补做检索与语义判断后再确认。
4. **未保留区块交叉核验**：`unretained_clauses` 中每一条的 `disposition` 描述的去向（并入哪条/彻底删除）要能在主表中找到对应印证，不能是随意编写的猜测性描述。检查方式不是只读 `change_note` 文字判断"写得是否合理"，而是要对照该条实际写入的 `old_no`/`new_no` 字段值，确认字段本身与 `change_note` 描述的关系完全一致，两者不一致时以官方原文重新核实为准。
5. **富文本渲染抽查**：用 `openpyxl`（`rich_text=True`）读回生成的文件，抽样检查若干行（尤其是新增、删除、修改类型各抽一行）的高亮渲染是否符合预期（可参考脚本内 `render_pair` 逻辑），确认新增标红加粗、删除灰色删除线均正常显示，没有因特殊字符导致渲染异常。
6. **同行语义对应关系校验（重要，与字段完整性是两件事）**：逐行重新审视 `old_text` 与 `new_text` 是否确实是"同一事项"的新旧版本，即规制的行为主体、适用场景、权利义务、法律后果实质上是同一件事，而不只是字段都填了值、条次数字接近、或字面上有相似片段。重点排查两类错误：一是把内容实际无关但表面相似/条次相邻的两条错误配对在了同一行；二是把措辞被大幅改写、实际仍是同一事项的两条误判成了互不相关（进而错误地各自标成新增/删除，而不是识别为同一事项的修改关系）。发现任何一行的语义对应关系存疑，都要退回第二步重新核对该行涉及的条款，而不是直接放行。

六项全部通过后：
- 若原文来源于联网检索，在交付回复中附上新规、旧规的官方原文链接及发布日期，供用户核验。
- 告知用户对比表已生成并已完成全方位校验，简要说明本次新旧条文的主要变化数量级（新增几条、删除几条、修改几条），不需要逐条复述。
