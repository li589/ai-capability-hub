# 输入 JSON 格式规范

`scripts/build_comparison_table.py` 的输入是一个 JSON 文件，描述一个或多个 sheet。每个 sheet 对应一部法规/合同的逐条对比数据。

## 顶层结构

```json
{
  "sheets": [ <sheet_def>, <sheet_def>, ... ]
}
```

多部法规/多份合同对比时，每部单独一个 `sheet_def`，会生成为 Excel 中的独立 sheet（对应历史成果中"每部法规一个 sheet"的组织方式）。

## sheet_def 字段

| 字段 | 必需 | 说明 |
|---|---|---|
| `sheet_name` | 是 | Excel sheet 标签名，会自动截断到 31 字符 |
| `title` | 否 | 表格标题（第1行合并单元格），默认使用 `sheet_name` |
| `legend` | 否 | 图例说明（第2行合并单元格），默认使用通用图例文案 |
| `old_column_header` | 否 | 旧条文列表头文字，默认"旧条文原文"。建议写成如 `《XX办法》（旧文号）原文` |
| `new_column_header` | 否 | 新条文列表头文字，默认"新条文"。建议写成如 `《XX办法》（新文号）` |
| `old_source_url` | 否 | 旧条文官方原文的来源链接，设置后旧条文列表头会自动加上超链接（下划线样式），方便用户点击核验来源 |
| `new_source_url` | 否 | 新条文官方原文的来源链接，设置后新条文列表头会自动加上超链接（下划线样式），方便用户点击核验来源 |
| `rows` | 是 | 逐条对比数据行数组，见下 |
| `unretained_clauses` | 否 | 旧文中未被保留条款的汇总区块，见下 |

## rows 中每一行

以**新条文的自然顺序**为主轴排列（这是历史成果的核心组织逻辑，务必遵循，不要按旧文顺序排列）。

| 字段 | 说明 |
|---|---|
| `old_no` | 对应旧条次文本，如 `"第八条"`；多条合并对应时写 `"第九条 + 第十条 + 第十一条"`；无对应旧条款时留 `null`；若合并/拆分发生在**款级别**（同一条内不同款被拆到不同新条，或不同条的某几款被合并进同一新条），可细化写成 `"第九条第二款"` `"第九条第一款 + 第十条第三款"`，见下方"款级别拆分/合并"说明 |
| `old_text` | 旧条文原文（不要摘要或截断）；**正文开头不要重复写"第X条"，因为 `old_no` 列已经是条次编号，正文重复写会造成冗余**；无对应旧条款时留 `null`，脚本会自动填充"（无对应条款）"；当 `old_no` 精确到某一款时，这里只填**该款的原文**，不需要把整条其余款都重复贴出来；**仅当 `old_no` 是组合条次（如"第九条 + 第十条 + 第十一条"，即多条合并为一行）时**，才需要在正文里对各条内容做区分标注（如按顺序换行、或在每段开头标"（第九条）""（第十条）"），避免多条原文混在一起看不出彼此边界；单条对应场景不需要任何前缀标注 |
| `new_no` | 新条次文本，如 `"第七条"`；被完全删除、新文无对应时留 `null`；同样可细化到款级，如 `"第七条第一款"` |
| `new_text` | 新条文原文；与 `old_text` 同样的规则：单条对应时正文开头不重复"第X条"；被删除时留 `null`；精确到某一款时同样只填该款原文；仅组合条次场景才需要标注区分各条 |
| `change_note` | 一句话变更说明，参考历史成果风格，如"细化互联网公募平台的主体要求""新增平台内容治理责任""表述调整"。没有实质变更（纯保留）时可留空字符串 |

脚本会自动对 `old_text`/`new_text` 做词语级差异比对并渲染高亮，**不需要**在文本里手动插入任何标记符号（组合条次场景标注各条出处除外，见上）。

## 款级别拆分/合并（当条次整体对应关系不成立时使用）

有些情况下，一条法条内部的**不同款**在修订后被拆散到不同的新条中；或者反过来，旧文中分散在不同条的某几款，被合并进了同一个新条。这类场景**不要求必须把整条重复粘贴**，可以按款拆分成多行，每行只对应具体的那一款：

- 旧条被按款拆开分给不同新条：例如旧"第十条"第一款、第二款分别被吸收进新"第十五条"和新"第二十条"，就写两行：一行 `old_no: "第十条第一款"` 对应 `new_no: "第十五条"`（或"第十五条第一款"），另一行 `old_no: "第十条第二款"` 对应 `new_no: "第二十条"`；每行的 `old_text`/`new_text` 只放该款文字，不必在两行里都重复整条原文。
- 多个旧条的部分款被合并进同一新条：例如旧"第九条第一款"与旧"第十一条第二款"共同构成了新"第十二条"，可以在 `old_no` 里写组合形式 `"第九条第一款 + 第十一条第二款"`，`old_text` 里按顺序放这两款的原文（可用换行分隔并标明各自出处），`new_no`/`new_text` 正常放新条整体。
- 判断原则：是否细化到款级，取决于**条内不同款的去向是否本身就不一致**。如果整条都指向同一个新条/旧条，仍按整条处理即可，不要为了细化而把简单的一对一整条对应也拆成多行款级行，增加不必要的复杂度。

## unretained_clauses（可选，末尾汇总区块）

对应历史成果中"旧文中未被保留的条款"专门区块。当某些旧条款的内容被拆散并入多个新条款、或彻底删除且不适合在主表中单独占一行时，汇总到这里：

```json
{
  "old_no": "第二十二条",
  "old_text": "调整或者变更已经批准开展的评比达标表彰项目的，应当重新提出申请。",
  "disposition": "→ 新办法将调整、撤销并入第九条统一审批程序，未单设本条"
}
```

`disposition` 写清楚该条款内容的去向（并入哪条/彻底删除），风格参考历史成果："→ 新XX办法将……并入……未单设本条"。

## 何时该用主表行 vs 末尾汇总区块

- 一对一、一对多拆分（旧一条拆成新几条）、多对一合并（旧几条合并为新一条）：直接在 `rows` 里用组合条次表示，仍属于主表逐条对比范围。
- 旧条款内容被**打散吸收进多个不相邻的新条款**、或**彻底删除且没有直接对应新条款可挂靠**：放入 `unretained_clauses`，避免主表出现大量空行破坏"新文为主轴"的阅读逻辑。

## 完整示例

```json
{
  "sheets": [
    {
      "sheet_name": "互联网公开募捐平台服务管理办法",
      "title": "《互联网公开募捐服务平台管理办法》修订前后对比表",
      "old_column_header": "原条文（2016年）",
      "new_column_header": "新条文（2026年4月27日公布）",
      "old_source_url": "https://www.gov.cn/example-old-source",
      "new_source_url": "https://www.gov.cn/example-new-source",
      "rows": [
        {
          "old_no": "第一条",
          "old_text": "为进一步规范互联网公开募捐服务平台行为……",
          "new_no": "第一条",
          "new_text": "为加强互联网公开募捐服务平台管理……",
          "change_note": "表述调整，突出管理导向"
        },
        {
          "old_no": null,
          "old_text": null,
          "new_no": "第八条",
          "new_text": "互联网公开募捐服务平台应当加强网络信息内容生态治理……",
          "change_note": "新增平台内容治理责任"
        },
        {
          "old_no": "第十七条",
          "old_text": "互联网公开募捐服务平台运营主体所在地省级以上人民政府民政部门……",
          "new_no": null,
          "new_text": null,
          "change_note": ""
        },
        {
          "old_no": "第九条 + 第十条",
          "old_text": "（第九条）募捐信息平台应当对慈善组织的公开募捐资格进行核实……\n（第十条）募捐信息平台应当为慈善组织在其平台发布公开募捐信息提供不少于两次的机会……",
          "new_no": "第十二条",
          "new_text": "募捐信息平台应当对慈善组织的公开募捐资格进行核实，并为其在平台发布公开募捐信息提供不少于两次的机会……",
          "change_note": "合并原第九条、第十条，整合资格核实与发布机会条款"
        }
      ],
      "unretained_clauses": []
    }
  ]
}
```
