# 资助方档案：结构、填写说明与通用基线

一个资助方一份档案，文件名 `funder-<机构简称>.md`。

**存到哪**：建议放在你自己的工作目录，如 `资助方档案/funder-<简称>.md`。装好的 skill 目录通常是只读的，写不进去，而且换机器就丢了。

档案的作用是把**所有随资助方变化的东西**集中到一处，让通用方法保持干净。写申报材料时先读档案，再按档案的章节结构和门槛值起草。

**只知道对方类型、还没拿到官方文件时不用建档案**，直接用 [funder-types.md](funder-types.md) 里对应类型的典型要求起草。拿到官方文件后再回来按本模板落成正式档案。

---

## 填写来源等级

每一项都要标来源，因为「猜的阈值」比「留空」危害更大：

| 标记 | 含义 | 可否直接用 |
|------|------|-----------|
| `【指南明确】` | 官方申请指南、申报通知、空白模板里有原话 | 可以，建议附原文摘录 |
| `【口头确认】` | 资助方接口人口头或邮件告知 | 可以，注明确认人与日期 |
| `【推断】` | 从模板结构、往年获资助项目公示反推 | **须用户确认后才用** |
| `【未知】` | 查不到 | **不许填数**，写作时标 `【需向资助方确认】` |

## 九项结构

### 一、基本信息

| 项 | 说明 |
|----|------|
| 机构全称 / 简称 | |
| 机构类型 | 企业基金会 / 家族基金会 / 社区基金会 / 政府部门 / 国际组织 / 行业协会 |
| 是否公募 | 影响资金来源与信息公开要求 |
| 文书正式名称 | 如「项目立项申请书」「资助申请表」「项目建议书」 |
| 适用项目类型 | 如捐赠类 / 资助类 / 采购类，不同类型模板常常不同 |
| 模板版本与日期 | 模板会改版，记下版本避免用旧格式 |
| 官方文件来源 | 链接或文件名 |

### 二、章节结构

按官方模板的**实际顺序和实际命名**列出。这决定生成时的章节顺序。

| 序号 | 章节名（用资助方的原始叫法） | 必填 | 本 skill 对应模块 | 特殊要求 |
|------|---------------------------|------|-----------------|---------|
| 1 | | 是/否 | 项目概要 / 为什么做 / … | 字数、格式、是否表格 |

**关键**：左边用资助方的原话，右边映射到 skill 的通用模块，这样通用撰写规则才能套用。资助方有独特章节（如「与本会战略的契合度」「往期合作情况」）时，在「特殊要求」里写清要回答什么。

### 三、目标体系

不同资助方要求的目标格式差别最大，必须写清。

| 项 | 说明 |
|----|------|
| 范式 | OKR / 逻辑模型 Logframe / 变革理论 ToC / SMART 目标 / 自定义表格 |
| 字段清单 | 逐个列出要填的字段 |
| 层级数量约束 | 如几个目标、每个目标几条关键结果 |
| 是否要分期目标 | 如是否区分「全周期」与「本年度」 |
| 额外栏位 | 逐个列出。常见的有：验证方式、前提假设、基线值、置信度、挑战点、责任人 |
| 是否作为验收依据 | **重要**：若是，措辞必须能验收，写什么将来就验收什么 |

四种范式的写法与互转见 [goal-frameworks.md](goal-frameworks.md)。

### 四、硬性阈值

**这一节只填有官方依据的数字。** 没依据就写 `【未知】`。

**每条阈值都要写明边界是否含等于。** 官方文件常写「超过 100 万」「不超过 1 年」，遇到金额刚好等于 100 万、周期刚好 12 个月的项目时，触发与不触发的差别是要不要额外走一套流程。边界不明的写成 `100 万（> 还是 ≥ 待确认）`，不要自己选一个。

| 项 | 值 | 来源 |
|----|----|------|
| 执行周期上限 | | |
| 超期是否可申请及所需说明 | | |
| 管理费 / 行政费上限 | 注意分母是「执行支出总额」还是「项目总金额」 | |
| 触发额外评审的金额阈值 | 如超过某金额需专项评审会 | |
| 预算变更免报备阈值 | | |
| 预算变更需重新评审阈值 | | |
| 单一供应商采购需比价的金额 | | |
| 受益人推荐名额上限比例 | | |
| 资金拨付方式限制 | 如是否允许一次性拨付 | |

### 五、分类选项

资助方要求勾选的分类，**必须列出全部可选值原文**，不许自创。

| 分类维度 | 可选值 | 判断提示 |
|---------|--------|---------|
| 业务属性 / 资助方向 | | 拿不准时找谁确认 |
| 项目领域 | | |
| 覆盖区域口径 | | |
| 受益群体口径 | | |

### 六、表述规则与禁忌

| 项 | 说明 |
|----|------|
| 主体表述 | 基金会与关联企业是否必须分开写、怎么写 |
| 论证角度 | 从谁的角度论证、不能论证什么 |
| 禁用词 | 该资助方特别忌讳的表述 |
| 项目名称格式 | 如是否要求「年份 + 名称」、是否禁止标点 |
| 语言与计量 | 币种、单位、是否要求大写金额 |

### 七、附件清单

| 附件 | 必附 / 条件附 | 触发条件 | 有无官方模板 |
|------|-------------|---------|-------------|
| | | 如「金额超过 X 万时」「首次合作时」 | |

### 八、评审关注点

写给撰写者看的「阅卷人视角」，是档案里最有价值的部分。

| 项 | 说明 |
|----|------|
| 评审角色 | 谁会看、各看什么 |
| 评审顺序或分级 | 如初审 → 合规评议 → 决策 |
| 打分维度 | 若有评分表，列出维度与权重 |
| 高频退回原因 | **按频次排序**，这是最实用的信息 |
| 加分项 | 该资助方偏好什么 |

### 九、提交与流程

| 项 | 说明 |
|----|------|
| 提交渠道 | 线上系统 / 邮件 / 纸质 |
| 文件格式要求 | |
| 申报窗口期 | 常年受理还是定期批次 |
| 预计审批周期 | |
| 接口人 | 角色与联系方式，不写个人隐私信息 |
| 补正与申诉机制 | 被退回后能改几次 |

## 从官方文件生成档案

用户手上通常只有一份《申请指南》PDF 或一个空白模板。抽取顺序：

1. **空白模板**是章节结构和字段清单最可靠的来源，优先解析。
2. **申请指南 / 申报通知**里找阈值、附件清单、申报窗口、评审流程。数字门槛通常出现在「申报要求」「资金管理」「预算编制」几节。
3. **往年获资助项目公示**用来推断资助偏好、典型金额区间、项目周期长度，全部标 `【推断】`。
4. **机构章程或年报**用来确认业务范围，判断项目内容是否落在可资助范围内。

抽完后按上面九节填，把所有 `【推断】` 和 `【未知】` 汇总成一张确认清单交给用户：

```
资助方档案已生成，建议保存为：资助方档案/funder-xxx.md

【指南明确】12 项，可直接使用
【推断】3 项，请确认：
  · 执行周期上限：往年项目多为 1 年，推断上限 1 年
  · ...
【未知】5 项，写作时会标注待确认：
  · 管理费上限
  · ...
```

## 通用基线

**仅在连资助方类型都不确定时使用，且必须在交付稿开头声明。** 知道类型的走 [funder-types.md](funder-types.md)，比通用基线精确得多。

这些是公益行业的常见做法，不是任何一家的规定。

| 项 | 通用基线取值 | 说明 |
|----|------------|------|
| 章节结构 | 概要 → 为什么做 → 帮助谁 → 在哪做 → 做多久 → 怎么做 → 公益属性与社会价值 → 可持续性 → 项目目标 → 实施方案与预算 → 团队与风险 → 附件 | 覆盖绝大多数资助方要求的信息 |
| 目标体系 | 「产出层 + 成效层」双层写法 | 任何范式都能由此改写，见 goal-frameworks.md |
| 执行周期 | 建议按 1 年设计，更长的拆成分年申请 | 多数资助方倾向一年一签 |
| 管理费 | **留空**，标 `【需向资助方确认】` | 行业实际区间跨度极大（0%–20%），猜必错 |
| 分类选项 | **留空** | 自创分类一定被退回 |
| 附件 | 法人登记证书、机构章程、最近一期财务审计报告、项目预算明细、团队与执行能力说明 | 这五项几乎所有资助方都要 |
| 预算科目 | 人力费 / 物料设备费 / 活动费 / 传播费 / 差旅费 / 其他直接费用 / 管理费 | 通用分法，见 budget-and-compliance.md |
| 币种单位 | 人民币元 | |

声明模板见 SKILL.md 的 Step 0 情况四。
