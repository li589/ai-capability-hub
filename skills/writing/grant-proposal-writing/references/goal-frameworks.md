# 项目目标：四种范式、互转与质量评分

不同资助方要求的目标格式不一样，但底层逻辑是同一个。先理解底层，再套具体格式。

---

## 共同底层：结果链

所有目标范式都是这条链的不同切法：

```
投入 → 活动 → 产出 → 成效 → 影响
Input  Activity  Output  Outcome  Impact
 钱和人  做了什么  直接交付物  受益人的改变  更广泛的社会变化
```

**写目标最常见的错误是停在「活动」层**。「开展 200 场读书会」是活动，不是产出也不是成效。

| 层 | 是什么 | 例子 | 申报里的作用 |
|----|--------|------|-------------|
| 活动 | 做的动作 | 开展读书会 | ❌ 不能当目标 |
| **产出** | 直接交付物，数得出来 | 完成 200 场读书会，覆盖 3000 名儿童 | ✅ **必须有** |
| **成效** | 受益人因此发生的改变 | 儿童月均课外阅读时长从 2 小时提升至 8 小时 | ✅ **尽量有** |
| 影响 | 长期、更广泛的变化 | 区域内乡村小学形成课外阅读常规 | 可选，写了加分 |

**通用底线：至少有产出层目标，尽量加成效层目标。** 只有产出层的申报能过但不出彩；只有成效层的会被质疑不可控；有基线对比的成效层（从 X 到 Y）最受欢迎。

## 四种范式

### 1. OKR

企业背景的基金会常用。

```
O（目标）：一句话说清为谁解决什么问题
信心指数：百分比
KR1（关键结果）：可量化的结果
  ├─ Action（实施计划）：做什么 + 何时做 + 怎么做
  └─ 挑战点：可能的困难 + 应对措施
KR2 …
```

O 对应结果链的「成效/影响」，KR 混合了「产出」和「成效」，Action 是「活动」。有的资助方要求 KR 分「全周期」和「本年度」两列，前者放成效，后者放产出。

### 2. 逻辑模型 / 逻辑框架（Logframe）

政府项目、国际组织、专业基金会常用。表格形式，四行四列：

| 层级 | 指标 | 验证方式 | 假设与风险 |
|------|------|---------|-----------|
| 总体目标（Impact） | | | |
| 项目目标（Outcome） | | | |
| 产出（Output） | | | |
| 活动（Activity） | | | |

特点是**每层都要写「怎么验证」和「前提假设」**。「验证方式」比 OKR 严格，要写数据从哪来（问卷、台账、第三方评估）。「假设」写的是不受项目控制但影响成败的外部条件。

### 3. 变革理论（Theory of Change）

强调因果逻辑的资助方常用，形式更叙述化：

```
如果 [我们做 X]，
那么 [会产生 Y 变化]，
因为 [Z 机制成立]，
最终实现 [长期目标]。
```

关键是**把因果链的每一步假设讲出来并给出依据**。比 Logframe 更看重「为什么这样做就会有效」的论证，通常要引用同类实践或研究。

### 4. SMART 目标

小额资助、企业捐赠、社区基金会常用，最轻量：

每条目标满足 Specific 具体、Measurable 可衡量、Achievable 可实现、Relevant 相关、Time-bound 有时限。

通常 3–5 条平铺，不分层。写的时候仍要保证其中既有产出层也有成效层。

## 范式对照与互转

| 结果链 | OKR | Logframe | ToC | SMART |
|--------|-----|----------|-----|-------|
| 影响 | O（部分） | 总体目标 | 长期目标 | — |
| 成效 | O / KR（全周期） | 项目目标 | 中期变化 | 成效类目标 |
| 产出 | KR（本年度） | 产出 | 直接产出 | 产出类目标 |
| 活动 | Action | 活动 | 干预措施 | 不写 |
| 前提 | 挑战点 | 假设与风险 | 关键假设 | 不写 |
| 验证 | 隐含在 KR 措辞里 | 验证方式（独立列） | 证据来源 | Measurable 里 |

**互转要点**

- **OKR → Logframe**：O 拆成总体目标和项目目标两层；KR 按产出/成效归到对应行；Action 填活动行；挑战点改写成「假设与风险」；**新增「验证方式」列**（OKR 里没有，必须补）。
- **Logframe → OKR**：项目目标写成 O；产出行和成效行的指标写成 KR；活动写成 Action；假设写成挑战点。
- **任何范式 → SMART**：把各层指标平铺，每条补上时限。
- **ToC 与其他互转**：ToC 的因果叙述可以整体作为「为什么做」章节的第三层，其中的具体变化再按目标范式落成指标。

**转换时最容易丢的两样东西**：验证方式（转出 Logframe 时）和前提假设（转成 OKR 或 SMART 时）。即使目标格式不要求，也建议在风险章节里保留假设的内容。

## 目标质量规则

不管用哪种范式，都按这两组规则查。

### 目标层（O / 项目目标 / 长期目标）

| # | 检查项 | 标准 | 常见错误 |
|---|--------|------|---------|
| G1 | 具体性 | 一句话说清「为谁解决什么问题」 | 「推动项目发展」「提升影响力」 |
| G2 | 公益指向 | 指向社会问题或受益人需求 | 指向商业价值或品牌曝光 |
| G3 | 适度挑战 | 有难度但可实现 | 过于保守或过于空洞 |
| G4 | 唯一性 | 一个目标聚焦一个核心问题 | 一个目标里塞多个不相关方向 |
| G5 | 时间框架 | 与项目周期一致 | 无时间概念或与周期不匹配 |

**语言公式**：`[动词] + [服务对象或问题领域] + [要达成的改变]`

- ❌ 提升项目影响力 —— 太泛，不知道帮谁
- ❌ 完成项目执行 —— 这是工作描述，不是目标
- ✅ 为粤西 5 县乡村儿童建立可持续的课外阅读体系
- ✅ 帮助 200 名听障儿童在学龄前完成语言康复训练

### 指标层（KR / 产出与成效指标 / SMART 条目）

| # | 检查项 | 标准 | 权重 |
|---|--------|------|------|
| I1 | 可量化 | 有明确数字 | 必须 |
| I2 | 有时间 | 有截止日期或阶段节点 | 必须 |
| I3 | 可验收 | 有明确交付物，第三方能判断做到没做到 | 必须 |
| I4 | 结果导向 | 描述「会变成什么」而非「要做什么」 | 必须 |
| I5 | 与目标对齐 | 全部完成能支撑目标实现 | 重要 |
| I6 | 独立无重叠 | 各条之间不重复计算同一件事 | 重要 |
| I7 | 分层完整 | 有产出层，尽量有成效层 | 重要 |
| I8 | 有基线 | 变化类指标写明起点 | 加分 |
| I9 | 分期区分 | 资助方要求分期时，区分全周期与本年度 | 看档案 |

**语言公式**：`[动词] + [量化指标] + [对象或范围] + [达到的标准] + [截止时间]`

### 实施计划 / 活动

三要素：`做什么 + 何时做 + 怎么做`

| 好 | 差 |
|----|-----|
| 2026 年 4–5 月，与 5 县教育局对接场地和学校名单 | 前期准备 |
| 2026 年 6–8 月，分 3 批次完成 50 个图书角建设 | 建设图书角 |

### 信心指数（若资助方要求）

建议 60–80%。低于 60% 说明目标可能过高，需说明挑战；高于 80% 说明不够有挑战；填 100% 基本判定为目标过于保守。

### 数量约束

| 维度 | 通用建议 | 说明 |
|------|---------|------|
| 目标 | 1 个 | 一个项目一个核心目标；资助方允许多个时也不超过 2 个 |
| 指标 | 2–5 条，推荐 3–4 条 | 超过 5 条说明聚焦不够 |
| 每条指标下的活动 | 1–3 条 | |

具体约束以资助方档案为准。

## 20 分评分表

用于 Step 3 预检和模式 B 诊断。**评分过程只出现在预检报告里，不写进申报正文。**

| 维度 | 检查项 | 分值 | 扣分标准 |
|------|--------|------|---------|
| 目标层 | G1 具体性 | 2 | 模糊 -1，完全不合格 -2 |
| | G2 公益指向 | 1 | 缺失 -1 |
| | G3 适度挑战 | 1 | 过保守或过空洞 -1 |
| | G4 唯一性 | 1 | 多方向混杂 -1 |
| 指标层 | I1 可量化 | 2 | 每条不合格 -0.5，最多 -2 |
| | I2 有时间 | 2 | 每条不合格 -0.5，最多 -2 |
| | I3 可验收 | 2 | 每条不合格 -0.5，最多 -2 |
| | I4 结果导向 | 2 | 每条活动型指标 -0.5，最多 -2 |
| | I5 与目标对齐 | 1 | 指标与目标脱节 -1 |
| | I7 分层完整 | 1 | 无产出层 -1，仅产出层无成效层 -0.5 |
| 实施计划 | 三要素完整 | 2 | 缺要素 -1，完全没写 -2 |
| 结构 | 数量合规 | 1 | 超出或不足 -1 |
| 资助方专项 | 档案要求的额外栏位（如分期节点、验证方式、前提假设、置信度） | 2 | 每缺一项 -1 |

档案里没有额外栏位要求时，这 2 分按「验证方式是否写清」评。

**等级与处理**

| 分数 | 等级 | 处理 |
|------|------|------|
| 16–20 | 优秀 | 给微调建议 |
| 12–15 | 合格 | 逐条给修改建议 |
| 8–11 | 需改进 | 直接给出修改版目标 |
| 0–7 | 不合格 | 给出重写版目标 |
