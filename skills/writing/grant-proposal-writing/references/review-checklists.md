# 检查清单：形式审查 / 模块预检 / 跨模块一致性 / 审查员

四组检查按顺序跑。前三组是**规则性检查**（能机械核对），第四组是**判断性检查**（需要换视角思考）。

结论符号统一用：`✅ 通过` / `⚠️ 有问题但不阻塞` / `❌ 不合格必须改` / `🔍 需向资助方确认`。

---

## 第零组：形式审查自查

**这一关淘汰的项目最多，也最不值得被淘汰。** 内容写得再好，材料不合规就进不了内容评审。所以放在最前面。

| # | 检查项 | 说明 |
|---|--------|------|
| F1 | 资质证书在有效期内 | 法人登记证书、慈善组织证书、免税资格。**过期是最常见的淘汰原因** |
| F2 | 审计报告在要求年限内 | 常要求最近一期或近三年 |
| F3 | 附件齐全 | 按档案清单逐项核对，条件附的先判断是否触发 |
| F4 | 字数与页数在限制内 | 表单字段有上限的，逐字段核 |
| F5 | 文件格式与命名符合要求 | 有些系统只接受 PDF，或要求特定命名规则 |
| F6 | 签字盖章齐全 | 法定代表人签字、机构公章、财务章 |
| F7 | 提交渠道与截止时间确认 | 政府项目逾期不受理，没有补救余地 |
| F8 | 必填字段无空缺 | 系统常常有字段没填就无法提交 |
| F9 | 业务范围覆盖项目内容 | 项目内容超出章程业务范围会被直接退回 |
| F10 | 特殊资质已具备 | 如公开募捐资格、承接政府购买服务资格、境外资金备案 |

这一组里凡是「无法在截止前补齐」的项，要**立刻告知用户**，不要等交付时才说。

---

## 第一组：模块预检

逐模块核对。带 `*` 的项若资助方档案有更严格要求，以档案为准。

| 模块 | 检查项 |
|------|--------|
| 项目概要 | 6 要素完整 / 有具体数字 / 150–300 字* / 无虚话 / 主体不混同 / 从公益角度论证 |
| 为什么做 | 至少 1 处数据且标来源 / 覆盖社会问题 / 覆盖紧迫性 / 有项目定位 / 逻辑链完整 / 非商业论证 |
| 帮助谁 | 受益人明确 / 有规模数字 / 有选择原因 / 区分直接与间接受益人 / 涉定向受益人时有完整筛选流程 |
| 在哪做 | 区域具体 / 有选择原因 / 多实施地有统筹说明 |
| 做多久 | 精确起止时间 / 有分阶段说明 / 有拨付节奏 / 超周期上限有合理性说明* |
| 怎么做 | 覆盖核心活动 / 与目标章节方向一致 / 粒度不与目标章节重复 |
| 公益属性与社会价值 | 公益属性四角度至少 2 条 / 社会价值至少分两层 / 有独特性论述 / 无绝对化表述 / 无商业价值论证 |
| 可持续性 | 三维度至少覆盖 2 个 / 有具体措施 / 未写成「希望持续获得资助」 |
| 项目目标 | 按 20 分评分表评分（见 goal-frameworks.md）/ 范式符合档案要求* |
| 实施方案与预算 | 方案-产出-验收-金额四列对齐 / 验收标准是可留存证据 / 无方案外支出 |
| 预算 | 每项有测算依据 / 无禁止科目 / 管理费符合档案* / 需比价的已附比价 |
| 团队 | 每人有岗位职责分工 / 负责人有相关经验 / 规模与项目体量匹配 |
| 风险 | 每条有应对措施 / 覆盖主要风险类型 / 风险真实 |
| 附件 | 按档案清单逐项核对 / 条件附的判断条件已确认* |

## 第二组：跨模块一致性

**最容易出错、也最容易被机械核对出来的一组，必查。**

| # | 检查项 | 规则 |
|---|--------|------|
| C1 | 金额一致 | 概要金额 = 实施方案合计 = 预算表合计，精确到分 |
| C2 | 受益人数一致 | 概要 = 受益人章节 = 公益属性章节 = 目标指标里的人数 |
| C3 | 问题对应 | 背景讲的问题 = 公益属性要解决的问题 = 目标要解决的问题 |
| C4 | 时间一致 | 项目周期 = 目标指标的截止时间 = 实施计划的时间跨度 |
| C5 | 区域一致 | 实施区域 = 概要的覆盖区域 = 预算里的差旅覆盖范围 |
| C6 | 承诺覆盖 | 概要里承诺的每项产出，在目标章节都有对应指标 |
| C7 | 方案与预算互覆盖 | 方案里的每个活动都有预算，预算里的每笔钱都有对应活动 |
| C8 | 目标与验收对应 | 每条目标指标在实施方案的「验收标准」列里有对应证据 |
| C9 | 团队与预算对应 | 预算里的人力费岗位，在团队章节里出现 |
| C10 | 附件与正文对应 | 正文提到「详见附件」的，附件清单里确实有 |
| C11 | 名称与周期一致 | 项目名称里的年份，与项目周期跨越的年度不矛盾。跨年项目叫「2026年 XX 项目」但执行到 2027 年，需确认命名口径 |
| C12 | 阈值边界已核对 | 金额、周期、比例恰好落在阈值边界上时（如金额正好 100 万、周期正好 12 个月），已确认是否触发额外流程 |

C2 有个容易踩的坑：直接受益人和间接受益人分开算之后，各章节引用的必须是同一个口径。前面写「服务 100 名教师」后面写「受益 3000 人」，评审会认为数据不实。

## 第三组：审查员清单

切换成**持怀疑态度的评审专家**，找规则查不出来的问题。这一组不看格式，只看可信度。

1. **模糊表述** —— 有没有读完不知道具体指什么的句子
2. **无证据的断言** —— 「效果显著」「广受好评」这类有结论没依据的地方
3. **模块间矛盾** —— 前后说法不一致，或方案与目标暗含冲突
4. **夸大措辞** —— 「首创」「唯一」「填补空白」这类经不起追问的表述
5. **目标可验收性** —— 逐条问自己：项目结束时验收人拿着这条，能明确判断做到了还是没做到吗
6. **周期合理性** —— 超期理由站得住吗，还是只是不想分年申请
7. **预算与叙述匹配** —— 花钱最多的科目，在方案叙述里是重点吗；叙述里的重点活动，预算够吗
8. **执行能力匹配** —— 团队规模和经验，撑得起这个目标吗
9. **风险回避** —— 有没有明显该提的风险被绕开了
10. **数据可追溯** —— 每个数字问一遍从哪来，答不出的标待确认

**能直接改的改掉并标注，需要用户判断的列进待确认清单。** 审查员不替用户做业务决策。

## 输出格式

### 预检报告

```
📋 合规预检报告

【项目概要】 ✅
【为什么做】 ⚠️ 缺数据支撑
  · 「农村阅读资源匮乏」为定性描述，需补 1 处数据
【帮助谁】 ❌ 缺选择原因
  · 写了受益群体和规模，未说明为什么选这个群体
【项目目标】 ⚠️ 15/20 分（合格）
  · I3 可验收：KR2「提升阅读兴趣」无验收方式，-0.5
  · I7 分层完整：仅产出层，无成效层，-0.5
  · 档案专项：未写验证方式，-1
【预算】 🔍 需确认
  · 管理费上限未核对官方文件，暂留空

【跨模块一致性】 ⚠️
  ✅ C1 金额一致：概要 200 万 = 方案合计 200 万 = 预算合计 200 万
  ⚠️ C2 人数不一致：概要写 3000 名儿童，目标指标未出现受益人数
  ✅ C4 时间一致
  ❌ C6 承诺未覆盖：概要承诺「培训 100 名教师」，目标章节无对应指标

【需向资助方确认】
  1. 管理费上限与分母口径
  2. 业务属性该选哪一项
```

### 对标差异报告（模式 B）

```
📊 对标差异报告 —— 对照 [资助方名称] 要求

总览：要求 42 项，已达标 28 项，需补充 8 项，缺失 6 项，达标率 67%

模块              达标      状态   主要差异
────────────────────────────────────────────
基本信息          5/6       ⚠️    缺业务属性
为什么做          2/4       ⚠️    无数据、缺紧迫性
帮助谁            0/3       ❌    整章缺失
在哪做            0/2       ❌    整章缺失
做多久            1/4       ⚠️    缺分阶段说明
怎么做            2/2       ✅    —
公益属性          1/3       ⚠️    缺分层、缺独特性
项目目标          5/9       ⚠️    未分两列、缺验证方式
实施方案与预算    1/2       ⚠️    管理费占比待确认
团队与风险        2/3       ⚠️    缺风险预案

详细差异：

【帮助谁 — 整章缺失】❌
  资助方要求：独立章节，写明受益人是谁、多少人、为什么选这个群体
  稿件现状：受益人信息散落在概要和实施方案里，无独立论述
  影响：评审无法快速判断服务对象与选择依据
  建议：提取现有内容扩写为独立章节，补充选择原因
```

**用类型档案（funder-types.md）诊断时，差异必须分两类标**：

| 标记 | 含义 | 例子 |
|------|------|------|
| `❌ 确定不合格` | 任何资助方都不会接受 | 目标不可量化、预算无测算依据、金额前后不一致 |
| `🔍 按类型推断可能不符` | 需核对该方官方文件 | 周期超 1 年、管理费 12%、缺某份附件 |

把推断说成要求，会让用户白改一轮。

### 审查员意见

```
🔍 审查员意见

1. 【无证据断言】「该模式已在多地验证有效」未说明是哪些地方、什么结果
   → 建议：补充具体地点与成效数据，或改为「参考同类实践」并注明出处

2. 【可验收性】KR3「增强乡村教师阅读教学能力」无法验收
   → 建议：改为「完成 100 名教师培训并通过考核，考核合格率 ≥85%」

3. 【预算与叙述不匹】传播费占总预算 22%，但方案叙述里传播只有一句话
   → 建议：要么补充传播方案的必要性论证，要么下调该科目

总体评价：项目逻辑成立，主要问题集中在目标可验收性和预算论证。
建议补齐后再提交。
```

### 待确认清单

```
📌 待确认清单

需要你补充的信息：
1. 农村小学生均图书拥有量数据（用于背景章节）
2. 项目结束后图书角的产权归属和维护安排

需要向资助方确认的：
3. 管理费上限与分母口径
4. 业务属性归类

需要你决策的：
5. 是否将周期从 3 年调整为 1 年并分年申请（当前超出资助方周期上限）
```
