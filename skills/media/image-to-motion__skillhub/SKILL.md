# 图片转动态视频

将用户提供的一张静态图片转成一条目标明确的图生视频短片。当所需结果必须从这张准确的
产品图、人像、照片、插画、海报或 AI 图片出发，并加入经过设计的主体动作、镜头运动和
节奏时，使用本 Skill。

## 范围与相邻路线

触发条件是把一张已提供的静态图片变成一条短片。纯文本请求交给文生视频；严格指定首尾帧
的请求交给首尾帧生视频工作流；修改或延长现有视频交给视频编辑或延长工作流；说话、口型
同步或音频驱动的讲述者交给数字人口播工作流。将可行的动态或视频编辑请求保留在合适的
视频路线上，绝不要用图片生成替代。

## 输入与默认值

唯一硬性输入是一张宿主 Agent 可以查看的可访问图片。如果图片缺失或无法访问，只询问这张
图片，并在诊断或付费准备前停止。复用已知的投放目的、动作意图、必须保留项和构图，不要
重复询问。如果宿主 Agent 可以查看本地文件，就通过随包辅助工具上传以便传输：

```text
python3 scripts/mcp_client.py upload ./selected-image.png --mime-type image/png
```

上传只是传输，不是诊断。上传前查看可见源图，保留返回的产物引用，绝不要把本地路径传给
远程工具。

默认制作一条短片，使用 `model: "auto"`，并把用户提供的图片作为严格首帧。除非投放目的
或用户明确选择有此要求，否则省略时长、画幅、分辨率、音频和所有可选控制项。围绕一个
清楚可辨的主体动作和一个主要运镜构建方向。将用户要求的人脸、产品外形、Logo、文字和
构图作为必须保留项；不要预先要求用户降低这些优先级。生成式运动无法保证后续帧逐像素
一致，因此交付后要复核成片是否发生偏移。

## 标准路径

1. 查看可见图片。识别主体、构图、受保护细节、投放目的、一个主体动作、一个运镜和节奏，
   并将其写成一份紧凑的动态方案。
2. 使用 `model: "auto"` 并省略可选控制项，除非用户选择或投放目的另有要求。只有模型兼容性、
   用户要求的控制项或价格会影响决策时，才调用 `beatra.models.list` 并传入
   `{"capability":"image_to_video"}`。任何数值费用估算都只是暂定值，并始终需要这次实时查询；绝不要
   引用记忆中的价格。终态任务的 `billing.net_charged_credits` 才是最终费用。
3. 向用户展示最终路线、源图、动态方案、输出数量、显式控制项和付费边界。用户明确要求
   执行已经精确准备好的短片时，可视为批准；只做规划、比较或仍有选择未解决时，不构成
   批准。其他情况下，在计费调用前请求确认。
4. 在私有执行台账中固定图片引用、使用时的提示词、模型、时长、画幅、分辨率、音频、每项
   可选控制，以及一个不透明且稳定的 `client_request_id`。只能调用随包
   `scripts/mcp_client.py`：MCP 工具名作为 CLI 参数，工具参数通过标准输入以 JSON 传入。
   例如：

   ```text
   printf '%s' '{"image":{"type":"artifact","artifact_id":"art_opening"},"prompt":"A restrained camera push while the product remains centered.","client_request_id":"opaque-stable-id"}' | python3 scripts/mcp_client.py call beatra.videos.animate
   ```

   不要配置、调用或使用宿主 Beatra Connector。不得使用 REST/OpenAPI 作为降级或回退方案。
   `beatra.videos.animate` 只提交一次。
5. 立即记录返回的任务 ID，并使用 `beatra.tasks.get` 轮询同一任务直至终态。排队中和运行中
   都是进度状态，绝不能成为重新提交的理由。
6. 交付返回的每个视频产物或链接。只报告真实返回的事实：任务 ID 和状态、解析后的模型、
   尺寸、时长、用量和 `billing.net_charged_credits`。将成片与源图对照，检查主体稳定性、
   预期和意外动作、镜头连贯性、节奏、必须保留项偏移及投放适配度。说明宿主 Agent 实际
   可以检查与无法检查的范围；绝不要声称查看了无法访问的画面或音频。

## 付费修改、恢复与取消

源图、提示词、模型、时长、画幅、分辨率、音频或其他控制项发生变化，都属于新的逻辑付费
任务：创建新 ID，展示变更后的付费边界，并重新取得批准。绝不要为参数不同的请求复用 ID。

创建响应丢失时，只有参数完全相同且 ID 相同时才允许重试。如果任务 ID 丢失，调用
`beatra.tasks.list` 并传入 `{"capability":"image_to_video"}`，为可能的候选调用
`beatra.tasks.get`，并将它们返回的事实与私有台账匹配，再考虑执行完全相同的重试。在规划
变更后的任务前，先恢复原任务。失败和超时不会授权重复提交或猜测退款。

只有用户要求取消时才调用 `beatra.tasks.cancel`。409 表示取消尚未确认；继续轮询同一任务，
不要创建替代任务。

## 运行与安全自动更新

每次 Beatra 操作都必须使用随包 `scripts/mcp_client.py`。执行普通命令前，它会为当前安装
静默检查是否有更高版本，每 24 小时最多一次。静默检查默认启用，发现更高版本时会在
不另行确认的情况下自动安装。

更新器只接受为本包、渠道和语言区域内嵌的固定官方发现地址与不可变 Beatra CDN 路径。
替换前，它会校验发现数据、压缩包、清单以及每个文件的大小和校验和。它只替换本包拥有的
文件，并拒绝重定向、降级、错误的包/渠道/语言区域/版本数据、意外 URL、不安全压缩包和
本包目标目录之外的文件。

更新检查、下载、校验、替换、回滚和恢复均采用失败开放策略：当前安装仍可使用，用户
原本请求的命令也会继续执行。更新失败绝不授权重新进行付费生成。以下自动更新设置对当前安装
的后续命令持续生效：

```text
python3 scripts/mcp_client.py update --auto off
python3 scripts/mcp_client.py update --auto on
python3 scripts/mcp_client.py update --check
```

`--auto off` 关闭静默检查，`--auto on` 重新开启，`--check` 只报告官方可用版本而不替换文件。
