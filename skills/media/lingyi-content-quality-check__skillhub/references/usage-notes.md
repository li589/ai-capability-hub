# 信息收集与交付约定

## 待检字段

| 字段 | 必填 | 示例 |
|------|------|------|
| 待检文本 | 是 | 口播文案 / 标题 / 字幕条 / 标签文本（给文本或文件路径） |
| 平台 | 是 | 视频号(`channels`) / 公众号(`mp`)，默认视频号 |
| 检测模块 | 否 | 合规 / 人群 / 爆款；可任意组合。不指定 = 三项全跑 |
| 人群指定 | 否 | `25-34-女-白领-高消费` 等（格式：年龄段-性别-职业-消费层级；仅在启用人群模块时生效） |
| 评论条数 | 否 | 默认 6（仅在启用人群模块时生效）。每个人群已在卡片内带 1 条评论，超过人群数的名额作为卡片后「其他声音」补充 |

## 收集流程

1. 触发 skill 后先判断待检文本与平台是否齐全。
2. **必填齐全** → 直接质检（默认三块全跑）。
3. **有缺失** → 一次性追问缺失项（只问 1 轮）。话术示例：
   > 技能已就绪 ✅ 帮你做发布前质检（合规敏感词+广告法、人群模拟、爆款预测三块能力）。方便补我几条信息就能开检：
   > 1. **要质检的文本**——口播文案/标题/字幕/标签都行，贴过来或给文件路径。
   > 2. **发布平台**——视频号 / 公众号？（默认视频号）
   >
   > 想更快更省的话可以只跑合规检测（词库匹配、秒级返回）；如果要一份完整报告，我默认三块全跑。不指定人群/评论数也行，我用默认。
4. **仍不给** → 用默认（平台默认视频号；三块全跑；人群/评论数走后端默认）继续质检，不阻塞。

要点：一次问清，不挤牙膏；不展示技术字段名（platform/personas/only 等不出现给用户）。

## 人群维度格式

人群字符串格式：`年龄段-性别-职业-消费层级`，各段取值：

- 年龄段：`18-24` / `25-34` / `35-44` / `45+`
- 性别：`男` / `女`
- 职业：`学生` / `白领` / `宝妈` / `退休` / `自由职业`
- 消费层级：`高` / `中` / `低`

示例：`25-34-女-白领-高消费`、`35-44-女-宝妈-中消费`、`45+-男-退休-低消费`。

## 模块选择引导

| 用户意图 | 推荐模块 | 说明 |
|----------|----------|------|
| 「快速过一下合规」 | `--only compliance` | 秒级、最省 |
| 「这个脚本发出去违规吗」 | `compliance` 为主 | 需要时再加人群/爆款 |
| 「目标人群会怎么想」 | `compliance,persona` | 加人群模拟 |
| 「值不值得发 / 爆的概率」 | `compliance,burst` | 加爆款预测 |
| 「我要一份完整报告」 | 三块全跑（默认） | 约扣 38 点 |

## 调用与重试

- **主路径（异步）**：`POST /tasks` 立即拿 `task_id` → `GET /tasks/{id}` 轮询 → 终态交付。
- **默认报告文件**：未传 `--out` 时，脚本自动写入当前目录的 `质检报告-<task_id>.md`。
- **实扣字段**：`data.billing.total_points`（字符串）。
- **进度**：脚本 stderr 会周期性输出，例如：
  ```text
  [quality_check] 任务已提交：status=running elapsed=0s task_id=... | 当前：合规检测
  [quality_check] CONTENT_QUALITY_TASK_ID=<uuid>
  [quality_check] 进度：status=running elapsed=12s task_id=... | 已完成：合规检测；当前：人群反馈与用户评论
  ```
  用户中途问「跑到哪了」时：**读 stderr 最新进度行**转述（status / 当前模块 / 已用时 / task_id），不要说「查不了」。
- **失败重试**：若上次输出含 `CONTENT_QUALITY_TASK_ID` 或 stderr 含 `task_id=`，用户同意后执行：
  ```bash
  python3 scripts/quality_check.py --retry-task <task_id> --out ./质检报告.md
  ```
  已成功模块不会重复调用。
- **幂等**：同一次用户意图的重复提交尽量使用同一 `--idempotency-key`（脚本默认每次新建 UUID；仅当用户说「刚才那次再提交一次」且你持有上次 key 时复用）。

## 免责声明（交付报告时附一句）

- 合规检测（敏感词+广告法）基于后端词库，可能滞后于平台规则/法律更新，**重大发布前建议人工复核**。
- **仅当报告里包含人群/评论/爆款段落时**，才追加：「人群模拟 / 用户反应 / 爆款预测为**模拟参考，不承诺精确**，仅作辅助参考，不作为发布决策唯一依据。」如果用户只跑了合规，不提这条模拟参考的免责。**报告正文不再含 ⚠️ / 「模拟参考」字样**（全部由后端渲染去掉），免责统一由此处话术在交付时口头说明，保证正文读起来就是真实观众反应。

## 交互节奏

- **收集**：最多 1 轮追问，之后用默认继续，不让用户反复等待。
- **扣点确认**：跑脚本**前**必须告知「本次任务较复杂，预计扣点约 38 点，实际扣点视任务复杂程度而定、以最终完成任务时的实际点数为准，是否继续？」，用户**明确确认**后才跑脚本。这是硬性步骤，跳过不得。
- **速度差异**：只跑合规通常数秒；带人群/全跑通常 30–120 秒（默认全链路 timeout 180s）。开跑前可说「全量大约半分钟到两分钟，期间 stderr 会有进度」。用户问进度时转述 stderr，勿空等不回。
- **交付**：质检报告 MD 一次性渲染给用户（务必把分隔符之间的 Markdown 真正渲染出来，不能只甩文件路径或贴带 `\n` 的原始文本）；高危违禁（❌）明确提示「不建议发布」。
- **成功后**：告知实际扣除点数 + 报告查看方式（已渲染在上方 + 已存为 MD 文件）。
- **失败后**：告知「因网络原因本次任务执行失败，相应点数已返还」；有 task_id 时询问是否用 `--retry-task` 重试。
- **交付后**：主动询问是否需要修改建议或就某条违禁词给替换词。
