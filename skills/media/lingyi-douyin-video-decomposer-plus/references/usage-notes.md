# 信息收集与交付约定

## 待检字段

| 字段 | 必填 | 示例 |
|------|------|------|
| `--input`（抖音分享链接 或 本地视频路径） | 必填 | `https://v.douyin.com/xxxxx/` 或 `/path/to/aweme.mp4` |
| `--industry` | 否（缺省不传） | `beauty` |
| `--campaign_type` | 否（缺省不传） | 活动/投放类型 |
| `--account_size` | 否（缺省不传） | 账号体量 |

> `--input` 是单次唯一输入：一条抖音视频。`share_url` 与本地视频文件二选一；一次给多条或同时给链接和文件时，先让用户指定一条。

## 收集流程

1. 触发 skill 后先判断 `--input` 是否给出且有效（抖音链接或可访问的本地视频文件）。
2. **必填齐全** → 进入「扣点确认」后直接执行（默认参数，`origin`/`origin_method` 由脚本自动写 `01workbuddy`/`skill`）。
3. **有缺失** → 一次性追问（只问 1 轮）。话术示例：
   > 技能已就绪 ✅ 帮你把一条抖音视频拆成结构分段、爆款归因、评分和可借鉴策略。方便发我其中一种就能开拆：
   > 1. **抖音分享链接**——抖音 App 里打开视频 → 分享 → 复制链接，贴过来（短链 `https://v.douyin.com/...` 优先）
   > 2. **本地视频文件**——已下载到电脑的视频，把文件拖进来或把路径发给我（支持 mp4/mov/m4v/mkv/webm/avi，200MB 以内）
   > 行业/活动类型/账号体量是可选项，不给我用默认。
4. **仍不给** → 用默认继续，不阻塞。

要点：一次问清，不挤牙膏；不向用户暴露内部枚举值（如 `origin`、`platform`）。

## 调用与重试

- **主路径（异步）**：`POST /api/v1/social-analytics/collector/douyin-video-analyses` 立即拿 `analysis_task_id` → `GET .../douyin-video-analyses/{id}` 轮询 → 终态交付。
- **拆分轮询（WorkBuddy/Web 防会话中断，推荐）**：
  - 创建：`python3 scripts/analyze_dy_video.py --input "<抖音链接 或 本地路径>" --only-create`（退出码 0，拿 `DY_VIDEO_TASK_ID`）
  - 轮询：`python3 scripts/analyze_dy_video.py --poll-task <task_id> --input "<同上源>" --out ./抖音视频拆解报告.md`（退出码 13 仍运行，再跑一次；退出码 0 交付报告）
  - ⚠️ `--poll-task` 必须带 `--input`（与创建时相同的源），否则报告标题退化为「任务 xxx」。
- **重试**：`--retry-task <task_id>` 对同一 task_id **重新轮询**（本接口无 `/retry`，不重新创建、不重复扣点）。任务真失败（`failed`/`error`/`timeout`）后，需用户确认再用 `--input` **重新发起一次新拆解**（新 task_id、重新扣点）。
- **默认报告文件**：未传 `--out` 时，脚本自动写当前目录的 `抖音视频拆解报告-<task_id>.md`（三级兜底到 `/tmp`）。
- **实扣字段**：本 API 轮询响应不含 billing 字段，`DY_VIDEO_POINTS_USED` 常为空 → 按「约 128 点（实际以服务端扣点为准，可在 01Claw 账户查看）」回退。余额不足（402）在创建阶段拦截。
- **进度**：脚本 stderr 周期输出，用户中途问「跑到哪了」时读 stderr 最新行转述（status / current_stage / progress_message / task_id），不要说「查不了」。
- **幂等**：同一次用户意图的重复提交尽量用同一 `--idempotency-key`；用户说「刚才那次再提交」且你持有上次 key 时复用。注意：幂等只对“创建”阶段有效，已创建任务的轮询不涉及重复提交。

## 交互节奏

- **收集**：最多 1 轮追问，之后用默认继续，不让用户反复等待。
- **扣点确认（硬性，跳过不得）**：跑脚本**前**必须告知「本次拆解预计扣点约 128 点，实际扣点视任务复杂程度而定、以最终完成任务时的实际点数为准，是否继续？」，用户**明确确认**后才跑脚本。
- **速度差异**：说明本次大约耗时（如「远端拆解约 1–5 分钟，期间 stderr 会有进度」）。用户问进度时转述 stderr，勿空等不回。
- **交付**：报告 MD 一次性渲染给用户（务必把分隔符之间的 Markdown 真正渲染出来，不能只甩文件路径或贴带 `\n` 的原始文本）。
- **成功后**：告知实际扣除点数（空则「约 128 点、以服务端为准」）+ 报告查看方式（已渲染在上方 + 已存为 MD 文件）。
- **失败后（退出码 11/12）**：告知「因网络原因本次任务执行失败，相应点数已返还」；有 task_id 时先 `--retry-task`（重轮询）续查，仍失败则询问是否重新发起（新任务、重新扣点）。
- **交付后**：主动询问是否需要后续动作（如「照这条拆解结果给一份可借鉴脚本」「换一条视频对比拆解」）。
