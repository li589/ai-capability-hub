# Guide spécifique à la recherche qualitative

## Paradigmes de recherche

### Constructivisme
- La réalité est socialement construite
- Accent sur la compréhension subjective
- Le chercheur fait partie du monde étudié
- Méthodes : théorie ancrée, phénoménologie, recherche narrative

### Herméneutique
- Comprendre le sens des actions sociales
- Description dense (thick description)
- Explication contextualisée
- Méthodes : ethnographie, étude de cas

### Théorie critique
- Révéler les rapports de pouvoir
- Viser le changement social
- Réflexivité sur la posture du chercheur
- Méthodes : recherche-action, recherche participative

## Méthodes de recherche

### Théorie ancrée (Grounded Theory)
**Application** : explorer un nouveau domaine, construire une théorie

**Processus** :
1. Échantillonnage théorique (non statistique)
2. Codage ouvert (codage ligne par ligne / paragraphe par paragraphe)
3. Codage axial (découvrir les relations entre catégories)
4. Codage sélectif (catégorie centrale)
5. Saturation théorique (les nouvelles données ne génèrent plus de nouvelles catégories)

**Versions** :
- Glaserienne : plus objective, codage rigoureux
- Straussienne : plus structurée, utilise le modèle paradigmatique
- Constructiviste (Charmaz) : accent sur le processus de construction

**Critères de qualité** :
- Adéquation théorique (fit)
- Pouvoir de compréhension (grab)
- Pertinence (relevance)
- Modifiabilité (modifiability)

### Phénoménologie
**Application** : comprendre l'essence de l'expérience vécue

**Types** :
- Phénoménologie descriptive (Giorgi) : décrire la structure de l'expérience
- Phénoménologie interprétative (IPA/IPR) : construction de sens personnel
- Phénoménologie existentielle : thèmes de l'existence

**Collecte de données** : entretiens approfondis (1-2 heures)
**Échantillon** : échantillon homogène (expérience partagée)
**Analyse** :
- Mise entre parenthèses (bracketing) des préconceptions
- Découpage en unités de sens
- Extraction des thèmes essentiels

### Ethnographie
**Application** : comprendre une culture / un groupe

**Caractéristiques** :
- Travail de terrain de longue durée (plusieurs mois à plusieurs années)
- Observation participante
- Description dense
- Perspective holiste

**Données** :
- Notes de terrain (descriptives, analytiques, réflexives)
- Entretiens (formels / informels)
- Artéfacts / documents

**Rédaction** :
- Scènes descriptives
- Citations directes
- Réflexion du chercheur
- Interprétation culturelle

### Étude de cas (Case Study)
**Application** : compréhension approfondie d'un cas spécifique

**Types** :
- Cas unique : cas extrême / critique / révélateur
- Cas multiples : logique de réplication (par cas / théorique)

**Sources de données** :
- Documents
- Archives
- Entretiens
- Observation directe
- Observation participante
- Artéfacts physiques

**Analyse** :
- Correspondance de patterns
- Construction d'explications
- Séries temporelles
- Modèle logique

### Recherche narrative (Narrative Inquiry)
**Application** : comprendre les récits d'expérience personnelle

**Dimensions d'analyse** :
- Temporalité (temporality)
- Socialité (sociality)
- Lieu (place)

**Outils d'analyse** :
- Analyse de l'intrigue
- Analyse thématique
- Analyse conversationnelle

### Recherche-action (Action Research)
**Application** : résoudre des problèmes pratiques tout en produisant des connaissances

**Cycle** :
1. Plan (identifier le problème)
2. Action (mettre en oeuvre l'intervention)
3. Observation (collecter des données)
4. Réflexion (analyser et évaluer)
5. Nouveau plan (spirale ascendante)

**Types** :
- Technique : dirigé par l'expert
- Pratique : réflexion du praticien
- Émancipatoire : empowerment des participants
- Participatif : engagement communautaire

## Collecte de données

### Entretiens approfondis
**Types** :
- Structuré : ordre des questions fixe
- Semi-structuré : guide + relances flexibles
- Non structuré : conversation ouverte

**Techniques** :
- Établir le rapport (rapport)
- Utiliser des questions ouvertes
- Éviter les questions orientées
- Le silence est d'or (laisser du temps de réflexion à l'interviewé)
- Relances (« Pouvez-vous préciser ? »)
- Reformulation et confirmation

**Éthique** :
- Consentement éclairé
- Autorisation d'enregistrement
- Anonymat / confidentialité
- Droit de retrait

### Groupes de discussion (Focus Groups)
**Application** : interactions de groupe, consensus / divergences

**Organisation** :
- 6-10 personnes
- Homogénéité (caractéristiques partagées)
- 1h30-2h
- Animation par un modérateur

**Analyse** :
- Modèles d'interaction de groupe
- Consensus et divergences
- Hypothèses non formulées

### Observation participante
**Rôles** :
- Participant complet : identité de chercheur cachée
- Participant-observateur : identité dévoilée, participation aux activités
- Observateur-participant : principalement observation, participation limitée
- Observateur complet : aucune participation

**Enregistrement** :
- Notes descriptives (ce qui est vu et entendu)
- Notes réflexives (sentiments, pensées)
- Notes analytiques (analyse préliminaire)

### Analyse de texte
**Types** :
- Analyse du discours (Discourse Analysis)
- Analyse critique du discours (CDA)
- Analyse narrative
- Analyse de contenu (quantitative + qualitative)

## Analyse des données

### Processus de codage
1. **Codage initial** : ligne par ligne / paragraphe par paragraphe, rester ouvert
2. **Codage focalisé** : regrouper, fusionner, affiner
3. **Codage axial** : établir les relations entre catégories
4. **Codage théorique** : intégrer dans un cadre théorique

### Analyse thématique (Thematic Analysis)
**Étapes** (Braun & Clarke) :
1. Familiarisation avec les données (lectures répétées)
2. Génération des codes initiaux
3. Recherche des thèmes
4. Révision des thèmes
5. Définition / nommage des thèmes
6. Rédaction du rapport

**Types** :
- Inductif : génération des thèmes à partir des données
- Déductif : guidage par un cadre théorique
- Sémantique : sens de surface
- Interprétatif : sens profond

### Outils logiciels
- **NVivo** : complet
- **Atlas.ti** : forte capacité de visualisation
- **MAXQDA** : méthodes mixtes
- **Dedoose** : cloud, adapté au travail en équipe
- **Taguette** : gratuit et open source

## Critères de qualité

### Crédibilité
- Triangulation (méthodes, sources de données, chercheurs)
- Validation par les membres (member checking)
- Débriefing par les pairs (peer debriefing)
- Engagement prolongé (prolonged engagement)

### Transférabilité
- Description dense (thick description)
- Rapport contextualisé
- Jugement d'applicabilité par le lecteur

### Fiabilité (Dependability)
- Piste d'audit (audit trail)
- Documentation du processus
- Transparence des décisions

### Confirmabilité
- Journal réflexif
- Reconnaissance de l'influence du chercheur
- Distinction entre données et interprétation

### Cadres alternatifs
- **Authenticité** : représentation équitable des perspectives multiples
- **Éthique** : respect, justice, absence de préjudice
- **Résonance** : résonance chez le lecteur
- **Utilité** : utilité pour la pratique

## Caractéristiques rédactionnelles

### Modes de présentation
- Citations directes (donner la parole)
- Description dense (scènes, dialogues, détails)
- Voix du chercheur (réflexivité)
- Polyphonie (interviewés, littérature, chercheur)

### Choix structurels
- Récit analytique (piloté par les thèmes)
- Récit narratif (piloté par le temps)
- Structure mixte

### Rédaction éthique
- Protection de la vie privée (pseudonymes, floutage des détails)
- Présentation équitable (ne pas déformer)
- Consentement éclairé (autorisation de publication)
- Réciprocité (partage des résultats)

## Erreurs courantes
1. **Mythe de la taille de l'échantillon** : la recherche qualitative ne mise pas sur la quantité mais sur la saturation informationnelle
2. **Codage trop fin** : perte de la perspective globale
3. **Détachement des données** : sur-théorisation
4. **Négligence des contre-exemples** : présentation sélective
5. **Manque de réflexivité** : absence de discussion sur l'influence du chercheur
6. **Terminologie quantitative** : utilisation abusive de « significatif », « corrélé »
7. **Généralisation excessive** : généralisation d'un cas à l'ensemble

## Dialogue avec la recherche quantitative
- **Triangulation** : les méthodes mixtes renforcent la crédibilité
- **Séquence d'explication** : quantitatif → qualitatif (explication des mécanismes)
- **Séquence d'exploration** : qualitatif → quantitatif (validation des découvertes)
- **Design convergent** : collecte parallèle, présentation conjointe

## Lectures recommandées
- Creswell, J. W. (2013). *Qualitative Inquiry and Research Design*
- Braun, V., & Clarke, V. (2006). Using thematic analysis in psychology
- Charmaz, K. (2014). *Constructing Grounded Theory*
- Denzin, N. K., & Lincoln, Y. S. (2018). *The SAGE Handbook of Qualitative Research*


# Guide complet de la recherche quantitative

## Bases de la conception de recherche

### Types de recherche
- **Recherche descriptive** : Qu'est-ce que c'est ? (enquête de l'état actuel)
- **Recherche corrélationnelle** : Y a-t-il une relation ? (analyse de corrélation)
- **Recherche causale** : Pourquoi ? (expérimentation/quasi-expérimentation)
- **Recherche prédictive** : Que va-t-il se passer ? (régression/apprentissage automatique)

### Types de variables
- **Variable indépendante (VI)** : variable prédictive, variable explicative, variable de traitement
- **Variable dépendante (VD)** : variable de résultat, variable de réponse
- **Variable de contrôle** : facteurs confusionnels à contrôler
- **Variable modératrice** : influence l'intensité ou la direction de la relation VI-VD
- **Variable médiatrice** : explique comment la VI influence la VD

## Méthodes d'échantillonnage

### Échantillonnage probabiliste
- **Échantillonnage aléatoire simple** : tirage au sort, table de nombres aléatoires
- **Échantillonnage stratifié** : stratification selon les caractéristiques, aléatoire intra-strate
- **Échantillonnage par grappes** : échantillonnage par groupe
- **Échantillonnage systématique** : échantillonnage à intervalle régulier (attention à la périodicité)

### Échantillonnage non probabiliste
- **Échantillonnage de commodité** : accès facile (mentionner les limites)
- **Échantillonnage par choix raisonné** : jugement d'experts
- **Échantillonnage en boule de neige** : par chaîne de recommandation
- **Échantillonnage par quotas** : quotas selon les caractéristiques

### Calcul de la taille de l'échantillon
- **Règle empirique** : 30+ par groupe (grand échantillon), 10-20 par groupe (petit échantillon)
- **Analyse de puissance** : logiciel G*Power
  - Taille de l'effet (petit 0,2, moyen 0,5, grand 0,8)
  - Niveau de significativité (α = 0,05)
  - Puissance statistique (1-β = 0,80)

## Mesure et instruments

### Fidélité (Reliability)
- **Fidélité test-retest** : même instrument à différents moments
- **Fidélité par formes parallèles** : instruments équivalents administrés simultanément
- **Consistance interne** :
  - Alpha de Cronbach : > 0,7 acceptable, > 0,9 excellent
  - Fidélité split-half : Spearman-Brown
  - Oméga de McDonald : plus robuste
- **Fidélité inter-évaluateurs** : coefficient Kappa, ICC

### Validité
- **Validité de contenu** : jugement d'experts, correspondance avec le contenu
- **Validité de construit** :
  - Analyse factorielle exploratoire (AFE)
  - Analyse factorielle confirmatoire (AFC)
  - Modèles d'équations structurelles (MES)
- **Validité critère** : corrélation avec un critère externe
- **Validité de construit** : validité convergente, validité discriminante

### Principes de conception de questionnaire
- Éviter les questions doubles
- Éviter le langage orienté
- Options mutuellement exclusives et exhaustives
- Échelle de Likert 5-7 points la plus courante
- Questions de contrôle d'attention (filtrer les réponses non sérieuses)
- Questions à score inversé (prévenir les réponses par défaut)

## Statistiques descriptives

### Tendance centrale
- **Moyenne (Mean)** : distribution symétrique, influencée par les valeurs extrêmes
- **Médiane (Median)** : distribution asymétrique, robuste
- **Mode** : variables catégorielles, distribution multimodale

### Tendance de dispersion
- **Écart-type (SD)** : complément de la moyenne
- **Variance** : carré de l'écart-type
- **Intervalle interquartile (IQR)** : robuste, non influencé par les valeurs extrêmes
- **Étendue (Range)** : maximum - minimum

### Forme de distribution
- **Asymétrie (Skewness)** : symétrique = 0, asymétrie à droite > 0, asymétrie à gauche < 0
- **Aplatissement (Kurtosis)** : normal = 3 (ou excès = 0)
- **Test de normalité** : Shapiro-Wilk (petit échantillon), Kolmogorov-Smirnov (grand échantillon)

## Statistiques inférentielles

### Bases des tests d'hypothèses
- **Hypothèse nulle (H₀)** : pas d'effet, pas de différence, pas de relation
- **Hypothèse alternative (H₁)** : effet, différence, relation
- **Niveau de significativité (α)** : généralement 0,05
- **Valeur p** : probabilité d'observer le résultat actuel ou plus extrême sous H₀
- **Puissance statistique (1-β)** : probabilité de rejeter correctement H₀

### Erreurs courantes
- **Erreur de type I** : faux positif (rejet de H₀ vraie)
- **Erreur de type II** : faux négatif (acceptation de H₀ fausse)
- **p-hacking** : rapport sélectif, tests multiples sans correction

### Corrections pour comparaisons multiples
- **Bonferroni** : α/m, conservateur
- **Holm-Bonferroni** : correction par étapes
- **FDR (Benjamini-Hochberg)** : contrôle du taux de fausses découvertes

## Méthodes statistiques courantes

### Comparaison de deux groupes
- **Test t pour échantillons indépendants** : deux groupes indépendants, normalité, homogénéité des variances
- **Test t de Welch** : hétérogénéité des variances
- **U de Mann-Whitney** : alternative non paramétrique
- **Test t pour échantillons appariés** : pré-test/post-test, dispositif apparié
- **Test des rangs signés de Wilcoxon** : non paramétrique apparié

### Comparaison de plusieurs groupes
- **ANOVA à un facteur** : trois groupes+, échantillons indépendants
- **ANOVA à mesures répétées** : même groupe, mesures multiples
- **ANOVA à plusieurs facteurs** : plusieurs variables indépendantes
- **ANCOVA** : analyse de covariance (variable de contrôle)
- **Kruskal-Wallis** : ANOVA non paramétrique
- **Test de Friedman** : mesures répétées non paramétriques

### Tests post hoc
- **Tukey HSD** : toutes les comparaisons deux à deux
- **Bonferroni** : conservateur, adapté aux comparaisons prédéfinies
- **Dunnett** : comparaison avec le groupe de contrôle
- **Scheffé** : comparaisons complexes

### Analyse de corrélation
- **Pearson r** : corrélation linéaire, variables continues, normalité
- **Spearman ρ** : corrélation par rangs, relation monotone
- **Kendall τ** : corrélation par rangs, plus adapté aux petits échantillons
- **Corrélation partielle** : contrôle d'une troisième variable
- **Corrélation bisériale ponctuelle** : une variable continue et une variable dichotomique

### Analyse de régression
- **Régression linéaire** : variable dépendante continue
  - Hypothèses : linéarité, indépendance, normalité, homoscédasticité (LINE)
  - Diagnostic : graphiques des résidus, VIF, Cook's D
- **Régression logistique** : variable dépendante dichotomique
  - Interprétation du odds ratio
  - Test de Hosmer-Lemeshow
- **Régression logistique multinomiale** : variable dépendante multicatégorielle
- **Régression ordinale** : variable dépendante catégorielle ordinale
- **Régression de Poisson** : variable dépendante de comptage
- **Régression binomiale négative** : surdispersion

### Méthodes avancées
- **Modèle linéaire hiérarchique (MLH/MLM)** : données emboîtées (élèves dans des classes)
- **Modèles d'équations structurelles (MES)** : variables latentes, analyse de chemin
- **Analyse factorielle** :
  - AFE : exploration de la structure
  - AFC : validation de la structure
- **Analyse de clusters** : K-means, classification hiérarchique
- **Analyse discriminante** : prédiction de classification
- **Analyse de survie** : temps jusqu'à l'événement

## Taille de l'effet

### Importance
- La valeur p indique seulement si c'est significatif, pas l'ampleur
- La taille de l'effet indique la signification pratique
- Un petit effet peut être significatif dans un grand échantillon
- Un grand effet peut ne pas être significatif dans un petit échantillon

### Indicateurs courants
- **D de Cohen** : standardisation de la différence des moyennes
  - Petit = 0,2, moyen = 0,5, grand = 0,8
- **η² (êta-carré)** : proportion de variance expliquée dans l'ANOVA
- **R²** : proportion de variance expliquée dans la régression
- **r²** : proportion de variance expliquée dans la corrélation
- **V de Cramer** : force d'association entre variables catégorielles
- **Odds Ratio** : régression logistique

## Prétraitement des données

### Traitement des valeurs manquantes
- **Suppression** : suppression par liste, suppression par paire
- **Imputation** : imputation par la moyenne, imputation par régression, imputation multiple
- **Marquage** : création d'une variable indicatrice de valeurs manquantes

### Traitement des valeurs aberrantes
- **Détection** : boîte à moustaches, Z-score, Cook's D
- **Traitement** : suppression, transformation, méthodes robustes
- **Rapport** : indiquer la méthode de traitement

### Transformation des données
- **Normalisation** : logarithme, racine carrée, Box-Cox
- **Standardisation** : Z-score (moyenne 0, écart-type 1)
- **Normalisation Min-Max** : Min-Max (0-1)
- **Codage indicateur** : variables catégorielles

## Normes de rapport des résultats

### Tableaux
- Statistiques descriptives : M, SD, N
- Statistiques inférentielles : statistique, ddl, valeur p, taille de l'effet, IC
- Exemple : t(98) = 2,45, p = ,016, d = 0,49, IC 95% [0,08, 0,90]

### Graphiques
- Barres d'erreur : erreur standard ou IC 95%
- Nuage de points : ajouter la droite de régression
- Boîte à moustaches : montrer la distribution
- Éviter les diagrammes circulaires, les graphiques 3D

### Rapport textuel
- D'abord les statistiques descriptives, puis les statistiques inférentielles
- Rapporter la taille de l'effet et l'intervalle de confiance
- Interpréter la signification pratique
- Ne pas rapporter de « significativité marginale » (p = 0,051)

## Logiciels courants

### Initiation
- **SPSS** : interface par menus, adapté aux débutants
- **JASP** : gratuit, interface similaire à SPSS

### Avancé
- **R** : gratuit, puissant, reproductible
  - Packages : tidyverse, psych, lavaan, lme4
- **Python** : programmation générale
  - Bibliothèques : pandas, scipy, statsmodels, pingouin
- **Stata** : couramment utilisé en économie
- **Mplus** : spécialisé pour les MES
- **AMOS** : MES graphique
- **G*Power** : analyse de puissance

# Guide de gestion et de partage des données

## Principes FAIR

### 1. Qu'est-ce que FAIR ?
FAIR est l'étalon-or de la gestion des données, proposé par l'organisation FORCE11 et largement adopté par les institutions de recherche et les bailleurs de fonds du monde entier.

- **F**indable (trouvable) : les données possèdent un identifiant unique et sont récupérables
- **A**ccessible (accessible) : les données sont accessibles avec un protocole d'utilisation clairement défini
- **I**nteroperable (interopérable) : les formats de données sont standardisés et peuvent être intégrés à d'autres données
- **R**eusable (réutilisable) : les données sont accompagnées d'informations descriptives suffisantes pour être comprises et utilisées par d'autres

### 2. Findable (trouvable)

**Points clés de mise en oeuvre** :
- [ ] Les données possèdent un identifiant persistant (DOI, Handle, URL)
- [ ] Les données disposent de métadonnées descriptives détaillées (titre, auteur, date, sujet)
- [ ] Les données sont enregistrées dans un entrepôt ou une base de données interrogeable
- [ ] Les métadonnées comprennent des mots-clés et des étiquettes de classification

**Outils** :
- DataCite : service d'enregistrement de DOI
- Zenodo : entrepôt généraliste avec attribution automatique de DOI
- Figshare : stockage de données, figures et code
- Centres nationaux de données : stockage de données disciplinaires nationaux

**Normes de métadonnées** :
- Dublin Core : norme générale (15 éléments : titre, créateur, sujet, description, etc.)
- DataCite Metadata Schema : spécifique aux données de recherche
- ISO 19115 : données géospatiales
- DDI (Data Documentation Initiative) : données en sciences sociales

### 3. Accessible (accessible)

**Choix du niveau d'ouverture** :
- Entièrement ouvert : téléchargeable par tous (licence CC0 ou CC-BY)
- Conditionnellement ouvert : inscription requise, signature d'un accord, ou usage non commercial
- Accès contrôlé : demande nécessaire, processus d'approbation (données sensibles)
- Accès fermé : accessible uniquement par l'auteur et les collaborateurs (ouverture après embargo)

**Protocoles d'accès** :
- Décrire clairement comment obtenir les données (lien de téléchargement, processus de demande)
- Fournir les coordonnées (e-mail du gestionnaire de données)
- Préciser les conditions d'utilisation (exigences de citation, interdictions)
- Engagement de conservation à long terme (accord de l'entrepôt)

**Embargo (ouverture différée)** :
- Application : protéger la priorité avant la publication d'un article
- Durée : généralement 6 à 24 mois
- Configuration : au moment de la soumission ou du téléchargement des données
- Attention : certaines revues exigent l'accès immédiat aux données, vérifier à l'avance

### 4. Interoperable (interopérable)

**Normes de format de données** :
- Données tabulaires : CSV (recommandé), TSV, JSON
- À éviter : format propriétaire Excel (.xlsx), tableaux dans PDF
- Données textuelles : TXT, XML, JSON
- Données image : TIFF (sans perte), PNG (recommandé), JPEG (photos uniquement)
- À éviter : PSD, AI et autres formats propriétaires
- Données géographiques : Shapefile, GeoJSON, GeoTIFF
- Données de séquences : FASTA, FASTQ, VCF (bio-informatique)

**Normes de métadonnées** :
- Utiliser des vocabulaires contrôlés du domaine (ontologie)
- Biologie : Gene Ontology (GO), NCBI Taxonomy
- Sciences sociales : DDI Controlled Vocabulary
- Géographie : ISO 19115, INSPIRE
- Général : Schema.org, Dublin Core

**Intégration des données** :
- Fournir un dictionnaire de données (noms de variables, types, plages de valeurs, codage)
- Utiliser un codage standard (ex. : genre : ISO 5218)
- Fournir les relations de correspondance entre jeux de données
- Documenter le processus de transformation des données (provenance)

### 5. Reusable (réutilisable)

**Documentation des données** :
- Fichier README : aperçu des données, structure des fichiers, instructions d'utilisation
- Dictionnaire de données : description détaillée de chaque variable
- Codebook : règles de codage, définition des valeurs manquantes
- Documentation méthodologique : processus de collecte, traitement et nettoyage des données

**Accords de licence** :
- CC0 : sans restriction, recommandé pour les données
- CC-BY : attribution requise
- CC-BY-SA : attribution + partage dans les mêmes conditions
- CC-BY-NC : attribution + usage non commercial
- ODbL : licence de base de données ouverte (spécifique aux bases de données)
- Personnalisé : accord spécifique à l'institution/au projet

**Exigences de citation** :
- Fournir un format de citation recommandé
- Inclure DOI, auteur, titre, entrepôt, année
- Exemple : « Smith, J. (2023). Dataset Title. Repository Name. https://doi.org/10.xxxx/xxxxx »

## Normes de nettoyage des données

### 1. Protection des données brutes

**Principes** :
- Toujours conserver les données brutes (raw data) sans aucune modification
- Processus de nettoyage reproductible et documenté
- Utiliser des scripts plutôt que des modifications manuelles (auditabilité)

**Organisation des fichiers** :
`
data/
├── raw/              # Données brutes (lecture seule, jamais modifiées)
│   ├── survey_raw.csv
│   ├── interview_recordings/
│   └── experiment_logs/
├── processed/        # Données nettoyées (contrôle de version)
│   ├── survey_cleaned_v1.csv
│   ├── survey_cleaned_v2.csv
│   └── README.md
├── derived/          # Données d'analyse (générées à partir de processed)
│   ├── analysis_dataset.csv
│   └── variables_documentation.md
└── scripts/          # Scripts de nettoyage
    ├── clean_survey.R
    ├── clean_survey.py
    └── README.md
`

### 2. Étapes de nettoyage des données

**Étape 1 : Importation et inspection des données**
- Vérifier l'encodage du fichier (UTF-8 recommandé)
- Vérifier que le nombre de lignes et de colonnes correspond aux attentes
- Examiner les types de données (numérique/texte/date)
- Identifier le mode de représentation des valeurs manquantes (vide, NA, -999, « sans réponse »)

**Étape 2 : Traitement des valeurs manquantes**
- Identification : calculer le taux de valeurs manquantes pour chaque variable
- Documentation : enregistrer la raison des valeurs manquantes (non réponse, non applicable, erreur de saisie)
- Stratégies de traitement :
  - Suppression : lorsque le taux de valeurs manquantes > 50% ou l'échantillon est suffisant
  - Imputation : imputation par la moyenne/médiane/mode (simple)
  - Imputation multiple : MICE, Amelia (complexe, plus optimal)
  - Conservation : marquer les valeurs manquantes, traiter lors de l'analyse
- Attention : rapporter la méthode de traitement des valeurs manquantes, analyse de sensibilité

**Étape 3 : Détection des valeurs aberrantes**
- Méthodes statistiques :
  - Boîte à moustaches (au-delà de 1,5 fois l'IQR)
  - Z-score (|z| > 3)
  - Distance de Mahalanobis (multivarié)
- Connaissances du domaine :
  - Âge > 120 ans
  - Revenu négatif
  - Date dans le futur
- Traitement :
  - Vérification : consulter les enregistrements originaux
  - Correction : en cas d'erreur manifeste
  - Conservation : si valeur extrême réelle, rapporter l'analyse de sensibilité
  - Suppression : en cas d'erreur de saisie non vérifiable

**Étape 4 : Vérification de cohérence des données**
- Vérifications logiques :
  - Date de naissance < date d'inscription
  - Revenus ≥ dépenses (sauf en cas d'endettement)
  - Cohérence entre sous-questions et question principale (ex. : « Fumez-vous ? » = non, mais « Nombre de cigarettes par jour » = 20)
- Vérifications de plage :
  - Codage du genre : 1/2 plutôt que homme/femme (ou uniformiser)
  - Échelle de Likert : 1-5 plutôt que 1-5+0
- Vérifications de doublons :
  - Même répondant ayant soumis plusieurs fois
  - Enregistrements strictement identiques

**Étape 5 : Transformation des données**
- Recodage de variables :
  - Scores inversés (ex. : 1→5, 2→4, 3→3, 4→2, 5→1)
  - Création de variables indicatrices pour les variables catégorielles
  - Regroupement de variables continues (avec prudence, perte d'information)
- Calcul de variables :
  - Génération de nouvelles variables (ex. : IMC = poids/taille²)
  - Standardisation/normalisation (Z-score, Min-Max)
  - Transformation logarithmique (distribution asymétrique à droite)
- Variables temporelles :
  - Format de date unifié (AAAA-MM-JJ)
  - Calcul des intervalles de temps (ex. : âge, durée de maladie)

**Étape 6 : Validation des données**
- Comparaison avec les données brutes : vérification par échantillonnage
- Résumé statistique : moyenne, écart-type, distribution, comparaison avec les attentes
- Validation croisée : comparaison avec des données publiées (le cas échéant)
- Visualisation : histogrammes, diagrammes de dispersion, inspection visuelle

### 3. Documentation du nettoyage des données

**Contenu à documenter** :
- Opérations de chaque étape (code + commentaires)
- Données modifiées (numéro de ligne, ancienne valeur, nouvelle valeur)
- Données supprimées (raison, quantité)
- Variables générées (formule, source)
- Date de traitement, responsable

**Exemple de documentation** :
`

## Normes de visualisation des données

### 1. Principes de conception graphique

**Clarté** :
- Un graphique véhicule un message central
- Éviter les effets 3D et les décorations inutiles
- Maximiser le ratio données-encre (principe de Tufte)

**Intégralité** :
- Titre : décrire le contenu du graphique (non la conclusion)
- Axes : étiquettes + unités
- Légende : claire, positionnement approprié
- Annotations : sources de données et explications nécessaires

**Exactitude** :
- Les axes commencent à 0 (sauf échelle logarithmique)
- Barres d'erreur : écart-type, erreur standard, intervalle de confiance
- Taille de l'échantillon : indiquer n=XX
- Significativité statistique : *p<0,05, **p<0,01, ***p<0,001

### 2. Types de graphiques courants

**Comparaison** :
- Diagramme à barres : comparaison de données catégorielles
- Boîte à moustaches : comparaison de distributions (médiane, quartiles, valeurs aberrantes)
- Diagramme en violon : comparaison de la forme des distributions
- Diagramme radar : comparaison multidimensionnelle (utiliser avec prudence)

**Relation** :
- Nuage de points : relation entre deux variables continues
- Diagramme à bulles : ajout d'une troisième variable (taille)
- Carte de chaleur : tendances dans les données matricielles
- Graphe de réseau : relations entre nœuds

**Tendance** :
- Graphique linéaire : séries temporelles
- Graphique en aires : tendance cumulée
- Graphique en escalier : variations discrètes

**Composition** :
- Diagramme circulaire : composition simple (≤ 5 catégories)
- Diagramme à barres empilées : composition multi-catégories
- Treemap : composition hiérarchique

**Géographique** :
- Carte choroplèthe : remplissage par zone
- Carte de points : marquage de positions
- Carte de chaleur : distribution de densité

### 3. Normes de couleurs

**Principes** :
- Accessibilité pour les daltoniens : éviter la combinaison rouge-vert (8% des hommes daltoniens)
- Compatible avec l'impression noir et blanc : double codage motif + couleur
- Sensibilité culturelle : la signification des couleurs varie selon les cultures

**Schémas de couleurs recommandés** :
- ColorBrewer : outil de palette professionnelle (colorbrewer2.org)
- Monochrome : même teinte avec différentes luminosités (données continues)
- Bichrome : deux teintes (positif/négatif, avant/après)
- Multichrome : distinguer les catégories (≤ 7 catégories)

**À éviter** :
- Arc-en-ciel (rainbow colormap) : perception non uniforme
- Haute saturation : éblouissant, non professionnel
- Trop de couleurs : > 7 catégories difficilement distinguables

### 4. Résolution et format des graphiques

**Résolution** :
- Affichage écran : 150 dpi suffisant
- Impression/publication : 300 dpi (minimum), 600 dpi (recommandé)
- Graphiques linéaires : 1200 dpi (éviter l'effet d'escalier)

**Choix du format** :
- Graphiques vectoriels (recommandés) : PDF, EPS, SVG, EMF
  - Avantages : zoom illimité, fichier léger, modifiable
  - Adaptés aux : graphiques linéaires, organigrammes, schémas
- Bitmap : PNG (recommandé), TIFF
  - Avantages : photographies, images complexes
  - Inconvénients : distorsion lors du zoom
- À éviter : JPEG (compression avec perte), BMP (fichier volumineux)

**Paramètres d'exportation** :
- Intégration des polices : garantir un affichage cohérent entre plateformes
- Recadrage : supprimer les marges blanches superflues (tight bbox)
- Dimensions : selon les exigences de la revue (généralement 8 cm pour une colonne, 17 cm pour deux colonnes)

### 5. Outils de visualisation

**Outils de programmation** :
- Python : matplotlib, seaborn, plotly, bokeh
- R : ggplot2, lattice, plotly, shiny
- JavaScript : D3.js, ECharts, Highcharts

**Outils interactifs** :
- Tableau : glisser-déposer, adapté à l'analyse exploratoire
- Power BI : écosystème Microsoft, couramment utilisé en entreprise
- Flourish : en ligne, adapté à la visualisation journalistique
- Datawrapper : en ligne, simple et rapide

**Outils spécialisés académiques** :
- Origin : couramment utilisé en sciences et ingénierie, graphiques professionnels
- SigmaPlot : graphiques de biostatistiques
- GraphPad Prism : statistiques médicales/biologiques
- MATLAB : visualisation en ingénierie/mathématiques

## Stockage et sauvegarde des données

### 1. Stratégie de stockage

**Principe 3-2-1** :
- 3 copies : original + sauvegarde locale + sauvegarde distante
- 2 supports : disque dur + cloud/bande/optique
- 1 copie hors site : protection contre les incendies, vols et autres catastrophes locales

**Supports de stockage** :
- Local : disque dur externe (SSD recommandé, rapide, résistant aux chocs)
- Réseau : stockage cloud (OneDrive, Google Drive, Dropbox)
- Institutionnel : serveurs universitaires/d'institut (généralement avec sauvegarde)
- Spécialisé : Figshare, Zenodo, Dryad (dédiés à la recherche)

### 2. Contrôle de version

**Convention de nommage** :
- Date : data_2023-06-15.csv
- Version : data_v1.2.csv
- Contenu : survey_cleaned_n1000.csv
- À éviter : data_final.csv, data_final_final.csv, data_really_final.csv

**Outils de contrôle de version** :
- Git/GitHub : code + petites données (< 100 Mo)
- Git LFS : contrôle de version pour les gros fichiers
- DVC (Data Version Control) : spécifique au machine learning
- Manuel : date + numéro de version, journal des modifications

### 3. Conservation à long terme

**Choix du format** :
- Privilégier les formats ouverts (CSV, TXT, PDF/A, TIFF)
- Éviter les formats propriétaires (.xlsx, .docx, .psd)
- Migration régulière (vérifier la disponibilité des formats tous les 5-10 ans)

**Choix de l'entrepôt** :
- Entrepôts disciplinaires : GenBank (gènes), PDB (protéines), ICPSR (sciences sociales)
- Entrepôts généralistes : Zenodo, Figshare, Dryad, Mendeley Data
- Entrepôts institutionnels : dépôts universitaires/d'institut
- Entrepôts nationaux : centres nationaux de données, plateformes nationales d'infrastructure scientifique et technologique

## Éthique et confidentialité des données

### 1. Identification des données sensibles

**Informations personnelles identifiables (IPI)** :
- Identifiants directs : nom, numéro d'identité, numéro de téléphone, adresse
- Quasi-identifiants : code postal, date de naissance, genre, ethnie (identification par combinaison)
- Attributs sensibles : santé, finances, orientation sexuelle, opinions politiques

**Catégories spéciales** :
- Données génétiques humaines : protection supplémentaire requise
- Données de mineurs : consentement du tuteur requis
- Peuples autochtones/minoritaires : consentement communautaire requis
- Espèces menacées : informations de localisation à brouiller

### 2. Anonymisation

**Anonymisation** :
- Suppression : identifiants directs
- Généralisation : âge → tranche d'âge, code postal → 3 premiers chiffres
- Perturbation : ajout de bruit aléatoire (confidentiel différentiel)
- Données synthétiques : génération de fausses données aux caractéristiques statistiques similaires

**Pseudonymisation** :
- Remplacement des identifiants par des codes (ID001, ID002)
- Conservation de la table de correspondance des clés (stockage sécurisé séparé)
- Réversible : possibilité de ré-identification si nécessaire

**k-anonymat** :
- Chaque combinaison de quasi-identifiants apparaît au moins k fois
- Exemple : k=5, alors chaque combinaison [genre, tranche d'âge, 3 premiers chiffres du code postal] ≥ 5 personnes
- Outil : ARX Data Anonymization Tool

### 3. Consentement éclairé

**Consentement à l'utilisation des données** :
- Informer clairement de l'utilisation des données lors de la collecte
- Utilisation pour des recherches futures (consentement élargi requis)
- Partage (après anonymisation)
- Utilisation commerciale
- Droit de retrait : les participants peuvent retirer leurs données à tout moment

**Utilisation secondaire** :
- Au-delà du champ du consentement initial : obtenir un nouveau consentement
- Ou : utiliser des données entièrement anonymisées (ré-identification impossible)
- Ou : exemption du comité d'éthique (intérêt public)

### 4. Sécurité des données

**Sécurité lors du transfert** :
- Transfert chiffré : HTTPS, SFTP, VPN
- À éviter : envoi de données sensibles par e-mail non chiffré
- Fichiers volumineux : archive chiffrée + mot de passe envoyé séparément

**Sécurité du stockage** :
- Stockage chiffré : BitLocker (Windows), FileVault (Mac)
- Contrôle d'accès : principe du moindre privilège
- Journal d'audit : enregistrer qui a accédé à quelles données

**Destruction** :
- Après la fin de la recherche : destruction ou archivage selon l'accord
- Suppression sécurisée : destruction physique du disque dur, démagnétisation, écrasement multiple
- Données cloud : confirmer la suppression définitive (pas seulement « mettre à la corbeille »)

## Plan de gestion des données (PGD)

### 1. Qu'est-ce qu'un PGD ?
Le plan de gestion des données est un document établi avant le début de la recherche, décrivant comment les données seront collectées, gérées, stockées et partagées.

**Sources d'exigences** :
- Bailleurs de fonds : National Natural Science Foundation of China, National Social Science Fund, Horizon Europe de l'UE
- Revues : Nature, Science, PLOS exigent sa soumission lors de l'article
- Institutions : politiques de données des universités/instituts

### 2. Contenu du PGD

**1. Description des données** :
- Type de données : quantitatives, qualitatives, images, audio, vidéo
- Volume de données : nombre de fichiers estimé, taille totale
- Formats de données : CSV, JSON, MP3, MP4, etc.
- Source des données : collecte propre, données publiques, données de collaboration

**2. Documentation et métadonnées** :
- Normes de métadonnées : Dublin Core, DDI, ISO 19115
- Plan de documentation : README, dictionnaire de données, codebook
- Contrôle de qualité : validation des données, processus de nettoyage

**3. Stockage et sauvegarde** :
- Emplacement de stockage : local, serveur, cloud
- Stratégie de sauvegarde : fréquence, support, hors site
- Mesures de sécurité : chiffrement, contrôle d'accès

**4. Aspects juridiques et éthiques** :
- Propriété intellectuelle : attribution des données, accord de licence
- Protection de la vie privée : anonymisation, consentement éclairé
- Données sensibles : mesures de traitement spéciales

**5. Partage des données** :
- Plan de partage : quand, où, comment partager
- Conditions restrictives : embargo, contrôle d'accès
- Conservation à long terme : choix de l'entrepôt, migration de format

**6. Responsabilités et ressources** :
- Gestionnaire de données : nom, responsabilités
- Budget : frais de stockage, temps du personnel
- Formation : compétences en gestion des données

### 3. Outils de PGD

**Outils en ligne** :
- DMPonline (Royaume-Uni) : dmponline.dcc.ac.uk
- DMPTool (États-Unis) : dmptool.org
- Chine : certains institutions fournissent des modèles

**Ressources de modèles** :
- Académie des sciences de Chine : modèle de plan de gestion des données
- National Natural Science Foundation of China : exigences de gestion des données pour les projets
- Horizon Europe de l'UE : modèle de PGD (lisible par machine)

## Citation des données et association avec les publications

### 1. Format de citation des données

**Format standard** :
- Auteur. (Année). Titre du jeu de données [type de données]. Nom de l'entrepôt. Identifiant

**Exemples** :
- Smith, J., & Jones, M. (2023). Survey on Online Learning Behaviors [Dataset]. Zenodo. https://doi.org/10.5281/zenodo.1234567
- Académie des sciences de Chine. (2022). Jeu de données de puits de carbone des écosystèmes terrestres chinois [Data set]. Centre national de données scientifiques écologiques. http://www.nesdc.org.cn/

### 2. Déclaration de disponibilité des données dans l'article

**Emplacement** :
- Section méthodologie : « Les données ont été collectées de mars à juin 2022... »
- Déclaration de disponibilité (Availability Statement) :
  - Paragraphe indépendant (généralement à la fin de la méthodologie ou avant les références)
  - Ou : note de bas de page, annexe

**Modèle** :
`
Data Availability Statement:
The data that support the findings of this study are openly available in 
[Repository Name] at [DOI/URL], reference number [accession number].

The data are available on reasonable request from the corresponding author.
[Contact email] due to [ethical/commercial/privacy restrictions].

The data are not publicly available due to [reason]. 
Access can be requested through [process].
`

### 3. Article de données (Data Paper)

**Définition** :
- Article décrivant spécifiquement un jeu de données, sans analyser les données, uniquement les décrire
- Publié dans des revues de données (telles que Scientific Data, Data in Brief, China Scientific Data)

**Contenu** :
- Contexte et objectifs de la collecte de données
- Description des données (variables, échantillons, période, lieu)
- Qualité et validation des données
- Instructions d'utilisation des données
- Modalités d'accès aux données

**Avantages** :
- Obtenir une citation formelle et une reconnaissance académique
- Augmenter la visibilité des données
- Répondre aux exigences de partage de données des bailleurs de fonds
