# 研究計画書詳細ガイド

## 技術ロードマップ

### 1. 技術ロードマップとは？
技術ロードマップは、研究の問題から解決策に至る完全なパスを可視化するツールです。査読者が研究ロジックを素早く理解できるようにし、研究者自身の思考整理にも役立ちます。

### 2. 技術ロードマップのタイプ

**タイプ1：フローチャート式（実験/工学研究に適した）**
```
研究問題
    |
    v
文献綜述 → 理論枠組み
    |
    v
研究仮説
    |
    v
実験設計/データ収集
    |
    v
データ分析
    |
    v
結果検証
    |
    v
結論と提案
```

**タイプ2：タイムライン式（縦断的/発展的研究に適した）**
```
Phase 1 (月1-3)    Phase 2 (月4-6)    Phase 3 (月7-9)
    |                   |                   |
    v                   v                   v
文献調査               データ収集           論文執筆
理論構築               実験実施             修正・完成
```

**タイプ3：反復式（アクションリサーチ/設計研究に適した）**
```
       計画(Plan)
          |
          v
    実施(Do)
    /        \
検証(Check)  反省(Reflect)
    \        /
      調整(Adjust)
          |
          v
      新たな計画
```

**タイプ4：ツリー分岐式（多手法/多事例研究に適した）**
```
              コア問題
                 |
    +------------+------------+
    |            |            |
量的研究     質的研究     混合研究
    |            |            |
アンケート   深層インタビュー  三角測量
    |            |            |
統計分析     テーマ分析     統合分析
```

### 3. 技術ロードマップ作成ツール

**専門ツール**：
- Visio：最も包括的、複雑なフローに適した
- ProcessOn：オンライン、中国語対応、テンプレート豊富
- Draw.io（diagrams.net）：無料、高機能
- Lucidchart：オンラインコラボレーション、チーム向け

**汎用ツール**：
- PowerPoint：シンプルなフローに十分
- Word：SmartArt機能
- LaTeX：TikZパッケージ（学術組版向け）

**コードツール**：
- Python：matplotlib、graphviz
- R：DiagrammeR、ggplot2
- Mermaid：Markdownスタイル、ドキュメント埋め込み向け

### 4. 技術ロードマップ設計原則

**明確性**：
- 各ノードに明確なラベル（動詞+名詞）
- 矢印の方向を明確に（一方向、双方向、循環）
- 交差線を避ける（階層化や色分けを使用）

**完全性**：
- 問題から結論まで完全なチェーンを含む
- 重要なノード（マイルストーン）を明示
- 意思決定ポイントを明示（例：「仮説検証に成功したか？」）

**階層性**：
- メインフロー：太線、大きなノード
- サブフロー：細線、小さなノード
- 注記：破線、グレー

**美観**：
- 統一配色（3-5色）
- 整列（グリッド整列）
- 余白（混雑させない）

### 5. 例：量的研究技術ロードマップ

```
[研究背景]
オンライン教育は急速に発展しているが、学習効果にはばらつきがある
         |
         v

         |

H3: 相互作用の質はプラットフォーム機能と学習効果を媒介する
         |
         v
[研究設計]
  |
  +-- 実験群：新型相互作用プラットフォーム使用（n=150）
  |
  +-- 対照群：従来プラットフォーム使用（n=150）
  |
  +-- 事前テスト：学習動機、事前知識
  |
  +-- 事後テスト：学業成績、批判的思考、満足度
         |
         v
[データ収集]
  |

  |
  +-- アンケート調査：相互作用の質の認識、学習体験
  |
  +-- テスト成績：客観式+主観式問題
  |
  +-- インタビュー：メカニズムの深層理解（n=20）
         |
         v
[データ分析]
  |
  +-- 記述統計：サンプル特性、変数分布
  |
  +-- 推測統計：t検定、分散分析、回帰分析
  |
  +-- 媒介分析：ブートストラップ法
  |
  +-- 質的分析：テーマコーディング
         |
         v
[結果検証]
  |
  +-- 仮説検定：H1/H2/H3が成立するか
  |
  +-- 堅牢性検定：変数の置き換え、サブサンプル
  |
  +-- 三角測量：量的+質的結果の一致性
         |
         v
[結論と提案]
  |
  +-- 理論的貢献：オンライン学習相互作用理論の完善
  |
  +-- 実践的提案：プラットフォーム設計、教授戦略
  |
  +-- 限界と今後の研究
```

## 実現可能性分析

### 1. 研究実現可能性の次元

**理論的実現可能性**：
- 研究問題に理論的裏付けがあるか？
- 理論枠組みは成熟しているか？
- 研究仮説は導出可能か？

**方法的実現可能性**：
- 研究手法は研究問題に適しているか？
- データは入手可能か？
- 分析技術は習得しているか？

**資源的実現可能性**：
- 時間：研究期間は合理的か？
- 予算：追加資金は必要か？
- 設備：特殊な設備は必要か？
- 人員：共同研究者は必要か？
- データ：データ入手経路はあるか？

**個人的実現可能性**：
- 知識蓄積：関連する理論的基盤を有するか？
- スキル蓄積：研究手法を習得しているか？
- 指導教員のサポート：指導教員はその分野に精通しているか？
- 時間投入：十分な時間を確保できるか？

### 3. 実現可能性分析の例

**例：オンライン教育相互作用研究**

```
1. 理論的実現可能性
   - 理論基盤：社会構成主義（Vygotsky）と認知負荷理論（Sweller）
     は教育技術研究で広く応用されており、本研究に堅実な理論的裏付けを提供。
   - 研究ギャップ：既存研究は主にオンライン学習プラットフォームの機能設計に注目しているが、
     相互作用メカニズムが学習効果に与える影響の体系的研究が不足。
   - 実現可能性結論：理論枠組みは成熟し、研究仮説は導出可能、理論的に実現可能。

2. 方法的実現可能性
   - 研究手法：準実験設計（実験群vs対照群）は因果関係を検証する
     標準的手法であり、本研究問題に適している。
   - データ入手：XXオンライン教育プラットフォームと提携済み、学習ログデータを入手可能；
     アンケート調査はプラットフォーム経由で配布、回収率>70%を予測。
   - 分析技術：SPSSとMplusを習得済み、AMOS構造方程式モデルのトレーニングを計画中。
   - 実現可能性結論：手法は成熟し、データは入手可能、技術は習得可能、方法的に実現可能。

3. 資源的実現可能性
   - 時間：研究期間12ヶ月（2023.9-2024.8）、詳細なスケジュールを作成済み。
   - 予算：XX基金の助成を獲得（5万元）、アンケート、インタビュー、トレーニング費用をカバー。
   - 設備：パソコン、SPSSソフトウェアを保有済み、追加設備不要。
   - 人員：指導教員XX教授は教育技術の分野で知名な学者、
     関連論文を10本以上発表；XX大学教育学院との提携を連絡済み、相手は対照群クラスの提供に同意。
   - データ：プラットフォーム側とデータ使用契約を締結済み、倫理委員会の承認を取得済み。
   - 実現可能性結論：資源は十分、資源的に実現可能。

4. 個人的実現可能性
   - 知識蓄積：教育心理学、教育統計学、教育技術学を履修済み、
     堅実な理論的基盤を有する。
   - スキル蓄積：SPSS高度応用トレーニングを通過済み、記述統計、推測統計、
     回帰分析を習得；構造方程式モデルを学習中。
   - 指導教員のサポート：指導教員XX教授は教育技術分野の知名な学者、
     研究方向は本研究と高度に関連、指導に同意済み。
   - 時間投入：週20時間投入可能、詳細な時間管理計画を作成済み。
   - 実現可能性結論：個人的条件は研究要件を満たし、個人的に実現可能。

総合結論：本研究は理論、方法、資源、個人の4次元で実現可能性を有し、
計画通りに実施可能。
```

## リスク予防策

### 1. 一般的リスクの特定

**データリスク**：
- リスク：データ収集困難（回収率低下、サンプル不足）
- リスク：データ品質問題（欠損値多数、外れ値多数）
- リスク：データ入手権限の変更（提携先の撤回、プラットフォーム閉鎖）

**方法リスク**：
- リスク：手法不適用（仮説不成立、モデル適合不良）
- リスク：技術的課題（ソフトウェアエラー、分析失敗）
- リスク：時間不足（新手法の学習に時間がかかりすぎる）

**資源リスク**：
- リスク：予算不足（超過、追加費用）
- リスク：設備故障（パソコン故障、ソフトウェア期限切れ）
- リスク：人員変動（指導教員出張、共同研究者離脱）

**個人リスク**：
- リスク：健康問題（病気、疲労）
- リスク：時間的競合（授業、試験、実習）
- リスク：モチベーション低下（停滞期、先延ばし）

**外部リスク**：
- リスク：政策変更（学校要件変更、倫理新規則）
- リスク：突発的事象（パンデミック、自然災害）
- リスク：技術変革（プラットフォーム更新、データ形式変更）

### 2. リスク評価マトリクス

```
リスク評価マトリクス

リスク項目          確率(1-5)  影響(1-5)  リスクレベル  対応戦略
------------------------------------------------------------
データ回収率低下      3         4         高      多チャネル配布、インセンティブ
サンプル量不足        2         5         高      サンプリング範囲拡大、設計調整
手法不適用        2         4         中      代替手法、予備実験
予算超過          2         3         中      予算バッファ、追加申請
指導教員出張          3         2         低      オンラインコミュニケーション、事前調整
健康問題          2         3         中      健康管理、時間的余裕確保
政策変更          1         4         低      動向注視、柔軟な調整
```

### 3. リスク対応戦略

**予防戦略（確率低減）**：
- データ回収：事前テスト、多チャネル配布、リマインダー設定
- サンプル量：サンプリングフレーム拡大、最低サンプル基準設定
- 手法適用：文献検証、予備実験、専門家相談
- 予算：詳細予算、10-20%バッファ確保
- 健康：規則正しい生活、定期運動、時間的余裕確保

**緩和戦略（影響低減）**
- データ回収率低下：サンプル量増加、重み付け調整の使用
- 手法不適用：代替手法の準備、モデルの簡素化
- 予算超過：コア支出の優先保障、追加助成の模索
- 指導教員出張：オンライン会議、重要問題の事前討議
- 健康問題：段階的推進、同僚の協力依頼

**緊急戦略（リスク発生後）**：
- データ回収率<50%：サンプリング範囲拡大、質的研究への転換
- サンプル量不足：ブートストラップ、ベイズ手法の使用
- 手法完全失敗：記述的研究、ケーススタディへの転換
- 予算枯渇：緊急助成申請、指導教員のサポート依頼
- 長期病欠：延期申請、研究計画の調整

**移転戦略**：
- データ収集：専門機関への委託（予算必要）
- データ分析：統計コンサルティングの依頼（学校通常無料）
- 技術問題：技術サポートサービスの購入

### 4. リスク予防策の例

**例：データ回収率低下**

```
リスク：アンケート調査の回収率が予想を下回る（<50%）

予防措置：
- アンケート設計：10人で事前テスト、5分以内で完成を確保
- 配布チャネル：メール+WeChat+授業+プラットフォームプッシュ、多チャネルカバー
- インセンティブ：最初の100名の完了者にXX報酬（学習資料、小ギフトなど）
- リマインダーメカニズム：配布後3日、7日、14日にそれぞれリマインダー

緊急措置：
- 回収率40-50%：サンプルフレーム拡大、200人増加
- 回収率30-40%：インセンティブ増加、抽選に変更（100%当選）
- 回収率<30%：質的研究に変更（深層インタビュー20人）
- 回収率<20%：指導教員と討議、研究設計の調整

モニタリング指標：
- 日別回収数量
- 回収率トレンド
- サンプル代表性（全体との比較）
```

### 5. 研究計画書におけるリスク予防策の書き方

```
【リスク予防策】

本研究は以下の主要リスクを特定し、対応する予防策を策定する：

1. データ収集リスク
   リスク記述：アンケート調査の回収率が予想を下回る可能性。
   予防措置：多チャネル配布（メール+WeChat+授業）、リマインダー設定、インセンティブ提供。
   緊急措置：回収率<50%の場合、サンプルフレーム拡大またはインセンティブ増加；
             <30%の場合、質的研究（深層インタビュー）へ転換。

2. 手法適用リスク
   リスク記述：構造方程式モデルの適合が不良の可能性。
   予防措置：予備実験でモデル検証、統計専門家に相談。
   緊急措置：モデル適合不良の場合、代替手法（回帰分析、分散分析）
             またはモデルの簡素化。

3. 時間リスク
   リスク記述：データ収集が遅延し、後続分析に影響する可能性。
   予防措置：詳細なスケジュール作成、2ヶ月のバッファ時間確保。
   緊急措置：遅延>1ヶ月の場合、論文延期申請または分析の簡素化。

4. 資源リスク
   リスク記述：予算超過の可能性。
   予防措置：詳細予算、20%バッファ確保、コア支出の優先保障。
   緊急措置：超過の場合、追加助成申請または指導教員のサポート依頼。

上記の予防策により、本研究は潜在的リスクを効果的に対応し、研究の円滑な完了を確保する。
```

## 研究計画書構造テンプレート

### 完全な構造

```
1. 研究背景と意義
   1.1 現実的背景（問題の由来）
   1.2 理論的背景（学術的脈絡）
   1.3 研究意義（理論+実践）

2. 文献綜述
   2.1 コア概念の定義
   2.2 国内外の研究現状
   2.3 研究評価（ギャップ）

3. 研究目標と内容
   3.1 研究目標（具体的、測定可能）
   3.2 研究内容（逐条展開）
   3.3 研究仮説（該当する場合）

4. 研究方法と技術ロードマップ
   4.1 研究方法（方法論+具体的手法）
   4.2 技術ロードマップ（可視化）
   4.3 研究ツール（アンケート、尺度、設備）
   4.4 サンプリング方案（全体、サンプル、サンプリング方法）

5. 実現可能性分析
   5.1 理論的実現可能性
   5.2 方法的実現可能性
   5.3 資源的実現可能性
   5.4 個人的実現可能性

6. リスク予防策
   6.1 リスク特定
   6.2 リスク評価
   6.3 対応戦略

7. 研究計画とスケジュール
   7.1 段階区分
   7.2 マイルストーン
   7.3 ガントチャート

8. 期待される成果と革新点
   8.1 期待される成果（論文、特許、ソフトウェアなど）
   8.2 革新点（理論、方法、応用）

9. 参考文献
```

## よくある問題と解決策

### Q：技術ロードマップが簡単すぎる/複雑すぎる？
- 簡単すぎる：サブフロー、意思決定ポイント、循環フィードバックを追加
- 複雑すぎる：同類を統合、高レベルの抽象化、詳細は付録に移動

### Q：実現可能性分析が自慢のように見える？
- 客観的記述：「保有済み」「確認済み」と表現し、「私は優秀」とは書かない
- 限界の認容：「X方面の経験は不足しているが、Y方式で補完済み」
- 証拠の引用：コース成績、トレーニング証明書、指導教員の論文

### Q：リスク予防策が形式的？
- 具体化：「問題が発生する可能性がある」ではなく「回収率<50%の可能性」と書く
- 量化：確率、影響、閾値
- 実行可能：「管理を強化」ではなく「3日後にリマインダーメール送信」と書く

### Q：革新点が不足？
- 再定義：「完全に新しい」ではなく、「新しい組み合わせ」「新しい応用」「新しい視点」
- 対比説明：既存研究との具体的な差異
- 適度な表現：「試みる」「探索する」「完善する」と表現し、「初の」「覆す」とは書かない

# 論文修正・ブラッシュアップガイド

## 自己修正

### 1. 修正段階

**冷却期間（1-3日）**：
- 初稿完成后、1-3日放置してから修正
- 理由：距離が客観性を生み、問題を発見しやすくなる
- 活動：文献読解、データ処理、休息

**第一回目：構造修正（マクロ）**
- 論理チェーンの検査：序論→方法→結果→考察→結論
- 章節バランスの検査：各章の文字数は合理的か
- タイトル階層の検査：明確で一貫性があるか
- 遷移の検査：章と章、節と節の間は連続しているか

**第二回目：内容修正（メゾ）**
- 論点の検査：各段落に明確な論点があるか
- 論拠の検査：論拠は論点を裏付けているか
- 論証の検査：論理は厳密か
- 繰り返しの検査：冗長な内容はないか
- 漏れの検査：重要な内容の欠落はないか

**第三回目：言語修正（ミクロ）**
- 文法の検査：主語と述語の一致、時制、冠詞
- スペルの検査：誤字、専門用語
- 句読点の検査：中国語と英語の句読点の混用
- フォーマットの検査：フォント、文字サイズ、行間
- 引用の検査：形式統一、対応関係

**第四回目：詳細ブラッシュアップ（精緻化）**
- 図表の検査：番号、タイトル、鮮明さ
- データの検査：数字、単位、パーセンテージ
- 参考文献の検査：完全性、形式
- 付録の検査：番号、対応関係

### 2. 自己修正チェックリスト

**構造チェックリスト**：
- [ ] 要旨は研究目的、方法、結果、結論を網羅しているか？
- [ ] 序論はマクロからミクロへ、最後に研究問題を明確にしているか？
- [ ] 文献綜述は分類が明確で、評価と結合しているか？
- [ ] 方法部分は再現可能なほど詳細か？
- [ ] 結果部分は客観的に提示し、解釈を加えていないか？
- [ ] 考察部分は結果を解釈し、文献と比較し、限界を指摘しているか？
- [ ] 結論は研究問題に応答し、新しい内容を導入していないか？
- [ ] 各章の比率は合理的か（序論10%、文献20%、方法15%、結果20%、考察25%、結論10%）？

**内容チェックリスト**：
- [ ] 各段落にトピックセンテンスがあるか？
- [ ] 段落間に遷移があるか？
- [ ] 無関係な内容はないか？
- [ ] 繰り返しの内容はないか？
- [ ] 漏れた重要な文献はないか？
- [ ] データは最新か？
- [ ] 結論は過度な推論ではないか？

**言語チェックリスト**：
- [ ] 口語的な表現はないか？
- [ ] 曖昧な表現はないか？
- [ ] 絶対化の表現はないか？
- [ ] 長難文（>30字）はないか？
- [ ] 受動態の過度な使用はないか？
- [ ] 中国式英語はないか？
- [ ] 用語は統一されているか？

### 3. 音読法

**方法**：
- 論文全文を声を出して読む
- または：テキスト読み上げツールを使用（Word朗読、Edgeブラウザ）

**発見できる問題**：
- 口ごもる文：読み上げた時に流暢でない、書き直しが必要
- 繰り返し語彙：同じ語彙が連続出現、置き換えが必要
- 論理的飛躍：一段落読み終えても何のことかわからない
- 語気の問題：強すぎる、弱すぎる、客観的でない

### 4. 逆アウトライン法

**方法**：
- 一段落読み終えたら、一文で核心内容を要約
- 付箋やドキュメントの余白に書く
- 全部完成后、要約文だけを見る

**チェック**：
- 要約文は論理チェーンを形成しているか？
- 要約文とタイトルが一致しないものはないか？
- 連続する数段落の要約文が内容的に繰り返しているものはないか？
- 要約できない段落はないか（内容が雑多であることを示す）？

## 指導教員フィードバック処理

### 1. フィードバック受領の心構え

**正しい心構え**：
- 指導教員は助言者であり、批判者ではない
- フィードバックは無料の専門家コンサルティング
- すべての修正が論文品質を向上させる
- 指導教員の「わからない」は往往是読者の「わからない」

**避けるべき心構え**：
- 防御的：「私は間違っていない、指導教員が理解できなかっただけ」
- 抵抗的：「これだけ修正するなら、書き直した方がまし」
- 先延ばし：「後で考えよう」
- 選択的：「簡単なものだけ修正し、難しいものは無視」

### 2. フィードバックのタイプと対応

**タイプ1：方向性フィードバック**
- 特徴：「研究枠組みの調整を提案」「XX理論の補充を提案」
- 対応：指導教員と面談し、具体的な方向を確認、修正計画を策定
- 注意：大量の書き直しが必要になる可能性、早めに対処

**タイプ2：内容性フィードバック**
- 特徴：「ここは論拠が不足」「XXデータの補充を提案」
- 対応：文献、データ、事例を補充するか、その論点を削除
- 注意：データソースの確認が必要、信頼性を確保

**タイプ3：構造性フィードバック**
- 特徴：「第2、3章の統合を提案」「章節の順序調整を提案」
- 対応：構造調整方案を作成、指導教員の確認後に実行
- 注意：アウトラインビューを使用して操作、内容の紛失を回避

**タイプ4：言語性フィードバック**
- 特徴：「表現が不明確」「簡潔化を提案」「文法エラー」
- 対応：逐条修正、ネイティブスピーカーやブラッシュアップサービスの支援を依頼
- 注意：修正スタイルの統一、前後不一致を回避

**タイプ5：フォーマット性フィードバック**
- 特徴：「図表が不規範」「引用形式が間違い」
- 対応：学校テンプレートと照合、逐項修正
- 注意：スタイル機能を使用、手動調整を回避

### 3. フィードバック処理フロー

**ステップ1：フィードバックの整理**
- フィードバックを分類：方向/内容/構造/言語/フォーマット
- 優先度を标注：必ず修正/提案修正/任意修正
- 難易度を标注：簡単/中等/困難
- テーブル作成：フィードバック内容|タイプ|優先度|難易度|修正方案|状態

**ステップ2：計画策定**
- 優先度でソート：まず方向性を処理、次に内容性、最後にフォーマット性
- 難易度の搭配：簡単+困難を交互に、burnoutを回避
- 時間設定：各タイプのフィードバックに時間を確保
- バッファ確保：総時間の20%を予期せぬ事態に対応

**ステップ3：修正実行**
- 一つのタイプに集中：一度に一つのタイプのフィードバックのみ処理
- 完了マーク：修正後に「完了済み」を标注
- 問題記録：修正できない場合、理由を記録
- バージョン保持：各ラウンドの修正で新しいバージョンを保存

**ステップ4：再確認**
- フィードバックと照合：逐条修正したかを検査
- 交差検証：修正箇所が新しい問題を引き起こしていないか
- 全体検査：修正後の全文が連続しているか
- 指導教員に提出：修正説明を添付

## 同行レビュアー

### 1. レビュアーの選択

**基準**：
- 同分野：研究方向が近く、内容を理解できる
- 異なる視点：方法論、理論的志向が異なり、新しい視点を提供できる
- 経験あり：上級大学院生、博士研究員、若手教員
- 信頼できる：機密保持、建設的、剽窃しない

**チャネル**：
- 同門：先輩後輩、同期の学生
- 学術界：会議で知り合った人、ソーシャルメディア
- ライティンググループ：定期的に相互評価するグループメンバー
- 専門サービス：一部の学校がライティングセンターを提供

### 4. 同行レビュー意見の処理

**原則**：
- すべての意見は検討に値する、たとえ採用しなくても
- 多数の意見は採用すべき、特に複数人から指摘されたもの
- 掍用しない場合は十分な理由が必要、注記可能

**フロー**：
1. すべての意見を収集、分類整理
2. 出現頻度を标注（複数人が指摘=重要）
3. 修正計画を策定
4. 修正を実行
5. レビュアーにフィードバック（感謝+修正状況の説明）

## 言語ブラッシュアップ

### 1. 自己ブラッシュアップのテクニック

**簡潔化**：
- 冗長表現の削除："very" "quite" "rather" "really"
- フィラーの削除："it is important to note that" "there is no doubt that"
- 繰り返しの削除：同一節内で用語を繰り返し定義しない
- 口語表現の削除："get" "big" "good" "bad" "thing" "stuff"

**強化**：
- 動詞で名詞を代替："make an analysis" → "analyze"
- 能動態で受動態を代替（適度に）："It was found that" → "We found that"
- 具体的で抽象的を代替："good results" → "results improved by 25%"
- 強い形容詞で"very + 形容詞"を代替

**連貫性**：
- 遷移語の追加："Furthermore" "However" "Therefore" "In contrast"
- 指示語の追加："This finding" "These results" "That approach"
- まとめの追加：段落末のまとめ文、章末の遷移文

### 2. ツール支援

**文法チェック**：
- Grammarly：文法、スペル、スタイルを検出
- LanguageTool：オープンソース、中国語インターフェース対応
- Writefull：学術執筆専用、AIベース

**スタイルチェック**：
- Hemingway Editor：可読性を検出、長難文をマーク
- ProWritingAid：総合スタイル分析
- 中国語：秘塔写作猫、写作助手

**用語チェック**：
- 用語一貫性：検索と置き換え、統一を確保
- 用語正確性：権威ある文献と照合
- 用語の初出：正式名称+略語

### 3. 専門ブラッシュアップサービス

**適用場面**：
- 英語論文の国際ジャーナルへの投稿
- 言語問題が多く、自己修正では向上が困難
- 時間が差し迫り、迅速なブラッシュアップが必要

**サービスタイプ**：
- 言語ブラッシュアップ：文法、スペル、スタイル（$0.03-0.08/語）
- 深度ブラッシュアップ：言語+内容提案（$0.08-0.15/語）
- 科学ブラッシュアップ：言語+科学的正確性（$0.15-0.30/語）

**選択基準**：
- 編集者の資格：ネイティブスピーカー、学科バックグラウンド
- サービス保障：品質保証、アフターサービス修正
- 機密保持契約：NDA署名
- 時間コミットメント：納期通りに納品するか

**有名サービス**：
- Elsevier Language Services
- Springer Nature Author Services
- Wiley Editing Services
- 意得輯（Editage）
- 美捷登（Medjaden）
- 英论阁（Enago）

### 4. ブラッシュアップ後のチェック

**必ずチェックすべき**：
- 用語が間違って修正されていないか（専門用語が「正されて」一般的な語にされていないか）
- データが間違って修正されていないか（数字、単位、パーセンテージ）
- 引用が間違って修正されていないか（著者名、年、ページ番号）
- 論理が間違って修正されていないか（接続語の変更で論理が逆転していないか）
- フォーマットが間違って修正されていないか（図表の位置、番号）

**提案**：
- ブラッシュアップ後に自分で通読する

## よくある問題

### Q：修正するほど悪くなる？
- 原因：過度な修正、全体的な視点の喪失
- 解決：全文を印刷し、オフラインで読む；または全文を音読
- 予防：各ラウンドの修正で一つのタイプの問題に焦点

### Q：指導教員の意見が矛盾？
- 解決：指導教員とコミュニケーションし、優先順位を確認
- 戦略：自分の研究問題を基準に、選択を説明
- 注意：コミュニケーションの結果を記結果を記録し、繰り返し修正を回避

### Q：時間が足りず、十分に修正できない？
- 優先度：構造>内容>言語>フォーマット
- 戦略：まず致命的な問題（論理的欠陥、事実誤認）を修正し、次に軽微な問題（言語ブラッシュアップ）
- 支援依頼：同僚にフォーマット調整、言語チェックを依頼

### Q：何度も修正しても満足できない？
- 受容：完璧な論文はなく、十分に良いものがある
- 基準：卒業要件を満たし、答弁を通過すれば良い
- 将来：卒業後も改善を続け、投稿発表できる

# 論文執筆段階ガイド

## 段階1：テーマ選定診断

### テーマ選定原則
- **価値性**：学術的価値または実践的価値
- **革新性**：新しい視点、新しい方法、新しい材料、新しい結論
- **実現可能性**：時間、資源、能力のマッチ
- **明確性**：問題が具体的、境界が明確

### テーマ選定方法
1. **文献駆動**：ギャップ、矛盾、空白の発見
2. **問題駆動**：実践の中で遭遇した問題
3. **方法駆動**：新しい手法を古い問題に応用
4. **交差駆動**：学際的視点

### テーマ選定評価チェックリスト
- [ ] 研究問題を一文で明確に表現できるか？
- [ ] 関連文献の裏付けがあるか？
- [ ] データ/材料は入手可能か？
- [ ] 6-12ヶ月以内に完成できるか？
- [ ] 指導教員は承認しているか？
- [ ] 専門の育成方向に合致しているか？

## 段階2：研究計画書

### 標準構造
1. **研究背景**
   - マクロ背景（社会/学術）
   - ミクロ背景（具体的現象）
   - 問題提起（背景から問題へ）

2. **文献綜述**
   - 研究の脈絡（時間/テーマ/方法）
   - 主要な観点（分類整理）
   - 研究の不足（ギャップ分析）
   - 本研究の位置づけ（貢献声明）

3. **研究内容**
   - 研究目標（全体+具体）
   - 研究問題（3-5つの具体的問題）
   - 研究仮説（該当する場合）
   - 技術ロードマップ（フローチャート）

4. **研究方法**
   - 方法論（実証/規範/解釈）
   - 具体的手法（量的/質的/混合）
   - データソース
   - 分析ツール

5. **革新点**
   - 理論的革新
   - 方法的革新
   - 材料的革新
   - 観点的革新

6. **研究計画**
   - 時間ノード（ガントチャート）
   - 期待される成果
   - リスクと対応

### 研究計画書答弁準備
- 10-15分間の陳述
- 回答準備：なぜこのテーマを選んだか？なぜこの手法を使うか？実現可能性は？
- 審査員の意見を記録、会議後に修正

## 段階3：アウトライン構築

### アウトラインのタイプ
- **目次式**：章節タイトルの階層
- **論理式**：論点の漸進関係
- **カード式**：各段落の核心内容

### アウトライン要素
- 各章の核心論点
- 論拠/材料/データ
- 前後章との論理関係
- 推定文字数

### アウトラインチェック
- [ ] 論理は連続しているか？
- [ ] 階層は明確か？
- [ ] 比率は均衡しているか？
- [ ] 冗長なものはないか？
- [ ] すべての研究問題をカバーしているか？

## 段階4：章ごとの執筆

### 執筆順序の提案
1. **まず書く**：文献綜述、研究方法（比較的独立）
2. **次に書く**：データ分析、ケーススタディ（核心作業）
3. **後に書く**：序論、結論（全文の視点が必要）
4. **最後に**：要旨、キーワード

### 各章の構造
- **序論段落**：本章の目的、全文との関係、核心内容の予告
- **本文段落**：論点+論拠+分析（PEEL構造）
  - Point：論点
  - Evidence：証拠
  - Explanation：説明
  - Link：論点への復帰/次の論点への遷移
- **結論段落**：発見のまとめ、承上啟下

### 執筆テクニック
- **毎日定時**：固定時間で執筆、習慣化
- **まず完成、その後完璧**：初稿は完璧を求めず、まず書く
- **段落単位**：一度に一つの段落を書き、プレッシャーを軽減
- **TODOマーク**：不確実な箇所にTODOをマーク

## 段階5：修正・完成

### 自己チェックリスト
- [ ] 論点は明確か？
- [ ] 論拠は十分か？
- [ ] 論理は厳密か？
- [ ] 言語は正確か？
- [ ] フォーマットは規範的か？
- [ ] 引用は完全か？

### 修正レベル
1. **マクロ**：構造調整、章節の追加削除、論理再編
2. **メゾ**：段落再編、遷移最適化、論証強化
3. **ミクロ**：文のブラッシュアップ、句読点規範、フォーマット統一

### 指導教員フィードバック処理
- 「必ず修正」と「提案修正」を区別
- 理解できない点は積極的にコミュニケーション
- 修正後に変化を标注
- 修正記録を保持

## 段階6：フォーマット規範

### よくあるフォーマット要件
- **表紙**：学校統一フォーマット
- **要旨**：中国語と英語、300-500字
- **目次**：自動生成、3級タイトル
- **本文**：
  - フォント：宋体/Times New Roman
  - 文字サイズ：小四（12pt）
  - 行間：1.5倍または固定値20ポンド
  - 余白：上下2.54cm、左右3.17cm
- **図表**：
  - 図のタイトルは下、表のタイトルは上
  - 番号：図1-1、表2-1
  - ソース标注
- **参考文献**：
  - フォーマット：GB/T 7714-2015
  - タイプ：単行本[M]、雑誌[J]、学位論文[D]、会議[C]、電子文献[EB/OL]

### 組版ツール
- **Word**：スタイル機能、多段階リスト、題注
- **LaTeX**：Overleaf、テンプレート
- **参考文献**：EndNote、Zotero、NoteExpress

## 段階7：重複チェックと答弁

### 重複チェック準備
- **自己チェック**：知网、维普、万方（学校指定システム）
- **重複削減戦略**：
  - 同義置き換え（学術的正確性を保持）
  - 文再構成（能動態と受動態の転換）
  - 図表化（テキストを表/図に転換）
  - 引用規範（直接引用の标注）
- **注意事項**：
  - 専門用語は保留
  - 公式の記述は書き換え
  - 法条/古詩の原文はカウントしない（ただし标注）
  - 参考文献リストはカウントしない

### 答弁準備
- **PPT作成**：
  - 15-20枚
  - 研究問題、方法、発見、貢献
  - 図表为主、テキストは簡潔
  - 原稿準備（PPTを読むのではなく）

- **答弁問題**：
  - なぜこのテーマを選んだか？
  - 革新点はどこか？
  - 手法の限界は何か？
  - ある結果をどう解釈するか？
  - もう一度やるとしたらどう改善するか？

- **答弁マナー**：
  - 正装
  - 時間管理（陳述15-20分）
  - 批評には謙虚に対応
  - 修正意見を記録

### 答弁後
- 修正意見の整理
- 指導教員と修正範囲の確認
- 期限通りに修正稿を提出
- 最終フォーマットチェック
- 電子版と紙版の提出
