# 会员运营诊断与增长建议 · 成熟度评分细则

> 适用 skill：`lingyi-member-ops-diagnosis-growth`
> 作用：把"按 1–5 分打分"从主观感觉变成**可复现、可解释、跨模型一致**的判定。**评分前必须先读本文件**，保证不同诊断之间口径统一。

## 目录

- 0. 怎么用这份细则
- 1. 八维成熟度锚点（1.1–1.8，每维度 1–5 分）
- 2. 整体成熟度分段
- 3. 六类根因（把表层问题归类）
- 4. P0 / P1 / P2 优先级判定

## 0. 怎么用这份细则

1. 对每个维度，先从用户材料里找到**可观测证据**（数据、机制、动作、节奏），没有证据就标"依据不足"。
2. 对照该维度 1–5 的锚点描述，先定到某一档，再在该档内微调。
3. 必须写出**评分依据**：引用具体材料 / 数据 / 现象，禁止只写"较弱""一般""较好"等模糊词。
4. 缺数据时按"就低不就高、必须标注"处理：证据只能支撑到 N 分，就打 N 分，并在"依据"里写"暂估，需补充 XX 数据验证"。
5. 分数只是辅助，最终要落到六类根因和 P0/P1/P2 项目事项。

## 1. 八维成熟度锚点（每维度 1–5 分）

### 1.1 用户资产（会员是谁，价值如何分布）

| 分 | 锚点（满足即定档） |
|---:|---|
| 1 | 只有会员总人数，没有活跃/购买/流失/价值结构；不知道谁是高价值用户。 |
| 2 | 有基础会员库和注册量，但无分层、无标签，无法区分活跃与沉睡。 |
| 3 | 有 RFM 或简单分层（如新/老、高/低），但分层口径不固定、不更新。 |
| 4 | 有稳定分层（新客/活跃/潜力/高价值/沉睡/流失）+ 价值分布，定期更新。 |
| 5 | 分层动态流转（用户在层级间迁移可追踪），并能算出各层规模、价值、流失风险与迁移路径。 |

### 1.2 生命周期（用户处在什么阶段，如何推进）

| 分 | 锚点 |
|---:|---|
| 1 | 无阶段概念，所有人同一套触达和权益。 |
| 2 | 提过生命周期概念，但只停留在策略表达，未落到阶段定义。 |
| 3 | 定义了主要阶段（如新客/活跃/沉睡），但阶段转换条件模糊、内容权益无差异。 |
| 4 | 每个阶段有定义、可量化触发条件，且内容/权益/触达方式按阶段区分。 |
| 5 | 阶段转换由行为数据驱动，有完整旅程图并持续用真实数据校准。 |

### 1.3 权益体系（权益是否能改变行为）

| 分 | 锚点 |
|---:|---|
| 1 | 无会员权益，或仅有偶发优惠券。 |
| 2 | 有等级/积分/券，但兑换率低、感知弱，主要为装饰性机制。 |
| 3 | 权益覆盖消费/服务/身份中至少一类，有赚花规则，但缺少有效性评估。 |
| 4 | 权益绑定消费、服务、身份、内容、场景多类，定期评估兑换率与权益成本。 |
| 5 | 权益与复购/留存/升级强相关，积分从"兑换小礼品"升级为绑定成长的机制，能驱动行为改变。 |

### 1.4 触点链路（用户从哪来、到哪沉淀、如何转化）

| 分 | 锚点 |
|---:|---|
| 1 | 公域、私域、商城、社群各自为战，无承接关系。 |
| 2 | 有多个触点，但触点之间无承接，用户行为断层。 |
| 3 | 有基本承接路径（如公域→私域→商城），但断点未梳理、转化未追踪。 |
| 4 | 有完整触点地图和优先级，关键断点已识别并有承接动作。 |
| 5 | 触点间数据与身份打通，同一用户关系可跨触点延续，承接路径有转化数据闭环。 |

### 1.5 内容活动（用户为什么持续参与）

| 分 | 锚点 |
|---:|---|
| 1 | 无固定内容，活动靠临时策划。 |
| 2 | 仅在节日/大促做活动，日常内容弱、无节奏。 |
| 3 | 有月度内容排期，但内容栏目/任务/互动不成体系。 |
| 4 | 有内容栏目 + 用户任务 + 互动 + UGC，且有固定运营节奏。 |
| 5 | 内容活动与生命周期、权益、转化联动，能持续产生活跃且可衡量内容贡献。 |

### 1.6 转化复购（活跃如何变成复购和长期价值）

| 分 | 锚点 |
|---:|---|
| 1 | 无复购触发机制，靠自然复购或促销驱动。 |
| 2 | 活动热闹但购买/复购/续费弱，复购率无提升。 |
| 3 | 有首购/复购链路设计，但触发条件模糊、未按人群区分。 |
| 4 | 有按人群/周期的复购触发、沉睡召回、加购升级机制，且追踪复购率。 |
| 5 | 转化漏斗与复购模型清晰，能算 CLV，触达—转化—复购形成可优化的闭环。 |

### 1.7 数据标签（是否能持续判断健康度）

| 分 | 锚点 |
|---:|---|
| 1 | 无数据沉淀，只有零散活动记录。 |
| 2 | 只有活动复盘，无固定看板、无标签口径。 |
| 3 | 有部分指标但口径不统一、更新不固定。 |
| 4 | 有会员健康度看板，固定追踪活跃率/兑换率/复购率/沉睡率/触达转化率，有标签治理。 |
| 5 | 看板驱动运营决策，指标口径统一、可下钻，标签随业务迭代更新。 |

### 1.8 组织SOP（运营能否稳定执行和迭代）

| 分 | 锚点 |
|---:|---|
| 1 | 无角色分工，靠个人经验，无复盘。 |
| 2 | 有团队但分工不清，复盘不沉淀。 |
| 3 | 有角色分工和活动复盘，但无固定诊断与迭代节奏。 |
| 4 | 有角色分工 + 周期复盘 + 可复用 SOP/资产，经验能沉淀。 |
| 5 | 有固定诊断节奏，运营动作沉淀为资产并能复用/复用报价，组织与系统协同。 |

## 2. 整体成熟度分段

整体分数 = 八个维度分数的**简单平均**，保留 1 位小数。

| 平均分 | 阶段 | 一句话定性 |
|---:|---|---|
| 1.0–1.9 | 起步期 | 有渠道或活动，但无会员经营体系，主要靠人工临时动作。 |
| 2.0–2.9 | 成长期 | 已有基础设施（等级/积分/触点/活动），但缺少精细化运营闭环。 |
| 3.0–3.9 | 成熟期 | 有分层、权益、触点、看板和复盘，进入精细化运营，待协同提效。 |
| 4.0–5.0 | 卓越期 | 数据、权益、触点、内容、转化、组织形成自动化或半自动化闭环。 |

## 3. 六类根因（把表层问题归类）

把每个表层问题归入**最多两类**主根因（避免到处都是根因）。归类时写清"为什么归这一类"。

| 根因 | 含义 | 典型信号 |
|---|---|---|
| 策略 | 方向/分层/优先级不清 | 无分层、平均用力、目标与人群错配 |
| 系统 | 工具/数据/标签/打通缺失 | 看板缺失、身份未打通、字段不可导出 |
| 内容 | 内容/活动/任务缺节奏 | 只有大促、日常弱、无栏目无任务 |
| 转化 | 触发/漏斗/复购机制缺失 | 复购率不升、召回缺失、链路断层 |
| 数据 | 口径/指标/复盘缺失 | 口径不一、无健康度看板、不更新 |
| 执行 | 角色/SOP/节奏/资产缺失 | 依赖个人、复盘不沉淀、无迭代节奏 |

## 4. P0 / P1 / P2 优先级判定

按"影响 × 紧急 × 依赖成熟度"三因子判定，三选一，不允许多选或空缺。

| 优先级 | 判定条件（满足任一即归此档） |
|:---:|---|
| **P0** | 阻塞后续所有优化（如无分层、无数据口径）；或直接影响核心增长/复购；或 1–2 周内可启动且依赖极少。 |
| **P1** | 对活跃/转化有显著提升，但依赖 P0 事项先落地；或需 1–2 个月协调资源。 |
| **P2** | 长期能力建设（如组织 SOP、自动化闭环），3–6 个月推进，依赖前两类成果。 |

> **取舍原则**：P0 应是**真正阻塞后续优化或直接决定核心目标的事**。判断"有没有做取舍"的硬标准是：**当项目事项 ≥ 4 个时，不能全部是 P0——至少要把一项显式降级到 P1 或 P2**。若几乎所有事项都是 P0，说明没做取舍，需要重排。
>
> 注意：比例上限**不是**硬指标。低成熟度业务本来就可能有多个合理的 P0（分层、看板、权益等基础同时缺失），强行把真实 P0 降级到 P1 只会让报告失真。关键不是"P0 有几个"，而是"是否至少对一项次要事项做了显式降级"。

## 5. 评分示例（说明"可复现"的口径）

材料："会员规模较大，但近 90 天活跃下降；等级和积分已上线但兑换率低；社群和小程序都在运营，活动靠节日促销；复购率未提升；只有月度活动复盘，无健康度看板。"

- 权益体系 → **2 分**：等级/积分已上线（≥2），但"兑换率低、感知弱"匹配 2 分锚点，无有效性评估证据，不升到 3。依据：兑换率低（材料）。
- 转化复购 → **2 分**：复购率未提升、无复购触发机制，匹配 2 分。依据：复购率未提升（材料）。
- 数据标签 → **2 分**：只有月度复盘、无看板、无口径，匹配 2 分。依据：无健康度看板（材料）。

同样材料，不同诊断者按本细则应得到相同分数——这就是"可复现"的目标。

## 6. 从评分到增长杠杆（诊断→增长衔接）

评分不是终点，而是增长杠杆的入口。**低分维度 + 根因 → 对应一类增长杠杆**，保证增长建议由诊断推导而非空给。完整映射见 [growth-levers.md](growth-levers.md) §2，此处给速查：

| 低分维度 / 根因 | 衔接到的增长杠杆 |
|---|---|
| 用户资产 / 生命周期低分（策略根因） | 分层精准运营、生命周期跃迁 |
| 权益体系低分（转化/内容根因） | 权益体系优化 |
| 转化复购低分（转化根因） | 复购提升、召回与防流失 |
| 触点链路低分（系统根因） | 触点链路梳理 |
| 内容活动低分（内容根因） | 内容活动体系化 |
| 数据标签 / 组织SOP低分（数据/执行根因） | 数据基础建设（底座先行） |

> 衔接规则：①每条增长杠杆必须能追溯到某个低分维度或根因；②增长杠杆含五要素（杠杆/人群/预期方向/验证方式/依赖）；③预期给方向区间不给确定数字；④增长限存量会员（复购/留存/跃迁/召回），不含拉新。
>
> 特例：当诊断出"数据标签"或"组织SOP"极低分（无看板、无口径、无迭代节奏）时，增长第一步往往是"数据基础建设"——先有度量能力再谈增长，否则增长无法验证（见案例 2）。
