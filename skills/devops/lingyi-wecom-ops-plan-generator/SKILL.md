# 企微运营方案生成

> 版本：v0.2.0 · 作者：小风、CoderPig

把私域分层客户**翻译成触达动作**，产出四件套：**分人群触点编排矩阵 + 话术填充表 + 频次排程表 + 合规折叠校验清单**。本技能聚焦「分层 → 触达动作落版」这一段——先有"对谁做"（分层由姊妹技能产出），再决定"具体怎么发"（走哪个触点、配什么话术、什么时候发、额度够不够、会不会被折叠封号）。本技能是纯方法论输出，免登录免 Key、由 agent 直接产出；四件套写完后把报告 Markdown 提交服务端登记（旁路、失败不阻塞交付）。

> 核心信念（来自调研 ★已核验）：腾讯智慧零售白皮书——「私域经营并不只是简单地加好友、建群拉人再群发信息，而是要通过精细化的运营体系……将不同类型的消费者用企业微信的标签功能设置加以区分……再推送对应的商品和促销信息，而不是统一推送同样的信息」。**分层是手段、触达动作是落点**——分层结果若不翻译成合规触达动作，分层就失去意义；触达若不感知企微官方频次/合规约束，就是盲发群发（实测打开率 <15%、被折叠、甚至封号）。

> 与姊妹技能咬合：上游 `私域用户分层触达策略` 产「对谁做」策略表、`用户生命周期旅程` 产「走到哪」阶段、`私域标签体系搭建` 产标签底座、`公私域联动方案生成` 产承接期 SOP（怎么进来）。本技能做**承接分层后的触达动作落版**（具体怎么发），咬合点=分层客户=本技能编排对象。详见 [references/related.md](references/related.md)。

## 目的

帮企微/私域运营者把「分层客户 × 运营目标 × 产品活动节点」翻译成一次符合企微官方频次/合规约束的触达动作，产出四件套。

这不是「写一条群发文案」，而是「先把分层人群映射到触点（对谁走 1v1/朋友圈/群发/社群），再给每个触达动作配话术、排频次、做合规校验，最后咬合成一个可执行、不被折叠、不超额度的整包」。触达动作是手段，目的是把分层价值兑现成转化/留存/召回——避免盲发群发（打开率 <15%、被折叠）、跨触点重复打扰（致屏蔽）、忽视官方额度（客户收不到）、踩合规红线（封号）四大私域触达死因。

> 核心信念：企微官方频次/合规规则是地基，绕过即封号风险；触达频次是稀缺资源，过度推送致退群/屏蔽/取关——**以价值密度换频次**，机械式定时推送是首号反模式。四件套必须咬合：触点编排（对谁走哪个）+ 话术填充（配什么）+ 频次排程（什么时点+额度够不够）+ 合规折叠校验（发不发得出）缺一环就是纸面规划。

## 输入

**最佳搭配：** 你要触达的目标分层人群（如「RFM 重要挽留客 × 休眠期」或「标签组合：高价值复购+敏感肌+华东」）+ 运营目标（破冰 / 促活 / 转化 / 召回 / 续费复购）+ 行业品类口径（美妆 / 母婴 / 餐饮高频 / 教培 / B2B 高客单 / 零售周期...）+ 产品活动信息与优惠钩子（如「会员日满 300 送 50 券」）。

**也有用：** 本月额度剩余（群发剩几条 / 朋友圈剩几条）、品牌 IP 人设、历史话术、活动节点（会员日/大促日）、已有分层数据来源（RFM/生命周期/标签体系）。

调用时附带的所有内容——技能名后的文本、粘贴的上下文，或附加的 `ARGUMENTS:` 行——都视为已给出的回答。直接使用并跳过其已覆盖的部分，不要重复提问。

**手头没有任何数据？那也可以。** 技能基于行业品类先搭一版触达编排假设，分层用「3 档价值 × 5 阶段生命周期」兜底框架并标记 `[假设·粗糙 · 正式分层请用姊妹技能]`，后续用真实分层回填重排。

**示例调用：** `为美妆企微3000复购客做召回触达——高价值沉睡客×成熟期(A+/休眠)，目标召回，IP护肤顾问小颜，本月群发额度剩2条/朋友圈剩8条，10员工，想出本周末会员日触达方案。`

### 输入字段与异常处理

| 字段 | 必填 | 异常处理（缺失/错误时怎么回） |
|---|:---:|---|
| 目标分层人群 | 是 | 缺失→追问「要给哪拨分层客户做触达？如：RFM重要挽留客、标签组合、沉睡名单」；全无分层线索→触发3档×5阶段兜底框架，标【粗糙·正式分层转分层触达/标签体系技能】 |
| 运营目标 | 是 | 缺失→追问首要目标（破冰/促活/转化/召回/续费复购），不自行假设 |
| 行业/品类口径 | 是 | 缺失→追问「属哪类业务？」（决定话术风格 B2B案例背书/B2C人设生活 + 合规词 + 频次阈值），不假设 |
| 私域载体 | 是 | 缺失→按企微1v1+朋友圈+群发默认，提示确认（企微1v1/朋友圈/群发/社群/组合） |
| 产品/活动信息+优惠钩子 | 是 | 缺失→追问「推什么产品/活动？什么钩子（利益点/痛点）？」；缺则无法填话术价值点 |
| 本月额度剩余 | 否 | 缺失→按满额可用（群发≈当月天数条/朋友圈4企业条+3/天成员）排，标【待校准·按实际填】 |
| 历史话术/IP人设/活动节点 | 否 | 缺失→按行业默认风格，标【按业务校准】 |
| 已有分层数据来源 | 否 | 缺失→兜底框架；有则记录口径供话术变量（昵称/上次购买/专属券码）引用 |

输出标准：四件套表格字段见 [references/template.md](references/template.md)；判定规则全部可量化（「如果…则…」条件句，禁「较好/适度/一般」模糊词），频次按企微官方额度量化（禁「适度」）。完整异常场景见下方「异常场景」节。

## 核心概念

### 什么是企微客户触达编排

把私域分层客户（由 RFM/生命周期/标签体系产出的「对谁做」），翻译成一次符合企微官方频次/合规约束的具体触达动作（「具体怎么发」），产出触点编排 + 话术 + 频次 + 合规校验四件套。触达编排是**执行层**，分层是它的输入口——分层不重算，只消费引用。

> 关键边界：本技能不是"再分层"，不是"搭标签体系"，不是"画承接链路"——这些由 4 姊妹技能做（见下「何时用什么」）。本技能只做"分层结果 → 触达动作"这一段翻译。

### 企微官方频次/合规硬约束（★已核验，地基）

> 以下规则经企业微信官方站核验【按最新规则核验·需复核】，平台迭代较快（2026.7 刚收紧），落地前请到企业微信管理后台「群发助手 / 客户朋友圈」复核当前生效规则。

- **朋友圈**：每位客户每个自然日最多展示 **3 条成员发表**内容；每位客户每月还可收到 **4 条企业发表**内容。【企业微信官方·客户朋友圈】
- **群发（旧规/默认）**：每位客户每天可接收 **1 条群发消息**（企业统一或成员自行创建）；每位客户每月可收到企业的 **4 条群发消息**；成员单次群发可选 **200 位客户**。【企业微信官方·群发助手】
- **群发（新规/可配置三档）**：企业可配置「每日可接收1条」/「每周可接收7条」/「每月可接收条数为当月天数」三档；**个人群发与企业群发共享同一额度池**——企业用了企业群发，会消耗该客户当期个人群发额度，反之亦然。三档总额度本质相同，区别仅在分配节奏。【企业微信官方·Help Center】
- **超上限行为**：超过接收上限的客户/客户群**无法再收到**群发消息（发送方不报错、接收方不送达）。【企业微信开发者文档】
- **群发文案限制**：文本 ≤ **4000 字** + 最多 **9 个**附件（image/link/miniprogram/video/file）；超限会被折叠。
- **2026.7 合规公告**：外挂零容忍、频率管控、微信联动；官方称已处罚大量账号/企业。**宣称"无限群发/无需确认自动群发/外挂绕过"= 封号风险反模式**。

> 辩证纠正业界误区：「朋友圈 3-5 条/天」混淆了个微与企微——企微原生就是 3 条/天封顶；「群发 4 条/月」是早期默认表述，当前新规可配三档（当月天数条/月），以企业实际配置为准。

### 触点适配四维权衡（选触点的判据）

| 触点 | 精准度 | 覆盖广度 | 成本 | 额度约束 |
|---|:---:|:---:|:---:|---|
| 1v1 私聊 | 高 | 低 | 高（耗人力） | 无官方硬上限，但软风控（高频机械式触发易关小黑屋） |
| 朋友圈 | 中 | 高 | 低 | 硬上限 3/天·4/月（最稀缺之一） |
| 群发 | 中低 | 高 | 低 | 硬上限 1/天旧·当月天数条新（额度共用，单次200人） |
| 社群 | 中 | 中 | 中 | 群内自主控制，但易致退群 |

**选触点判据**：高价值且目标转化/召回→1v1（精准度优先，成本可接受）；长尾促活→朋友圈/群发（广覆盖低成本，但额度稀缺要分配）；高频低客单→社群 1v 多（1v1 不划算）。触点可组合，但须做频次总控防重复打扰。

### 反模式（它不是什么）

- **不是**无差别群发——分层是手段，目的是把不同人区别对待（腾讯白皮书母论点）。【★已核验】
- **不是**只选触点不配话术不排频次——四件套咬合，少一件就是纸面规划。
- **不是**绕过官方额度——"宣称无限群发/外挂/无需确认自动群发"是封号反模式。【★wescrm 警告】
- **不是**把分层重算一次——分层纯消费引用姊妹技能结论，不在本技能内重做 RFM/标签体系。

### 何时使用

- 已有分层客户（RFM/生命周期/标签组合），要排出本周/每活动触达动作整包
- 群发打开率越来越低（<15%）、被折叠，要从盲发转精准触达
- 朋友圈/群发额度要分配，不知哪个分层人群该占额度
- 要做合规校验怕踩折叠/敏感词/外挂红线
- 给企微运营/社群运营出可执行触达 SOP

### 何时不要使用

- 要把用户按价值分层做 RFM→`skills/private-domain-segmentation-reach/SKILL.md`（分层触达技能，先分层再来本技能触达）
- 要定义用户生命周期阶段/旅程→`skills/user-lifecycle-journey/SKILL.md`
- 要搭私域标签体系底座/治理乱标签→`skills/private-domain-tag-system/SKILL.md`
- 要画公域→私域承接链路/承接期 SOP（怎么进来）→`skills/public-private-touchpoint-handover/SKILL.md`
- 要设计会员等级/积分/权益→`skills/member-points-benefit-design/SKILL.md`
- 私域刚起步、零分层线索且不愿用兜底框架→先跑通基础分层（分层触达技能可作为入口）

## 应用

使用 [references/template.md](references/template.md) 获取完整的填空式结构。先明确输入字段与异常处理，再按 6 步产出四件套（含可选 Excel），交付后走第 7 步旁路提交服务端；每步都过质量检查。

### 第 1 步：盘点人群与分层（含兜底）

把输入的分层人群落到「3 档价值 × 5 阶段生命周期」速查框架。**分层在本技能纯消费**：有用户提供分层直接引用；无分层线索时触发异常 1 兜底框架。

```markdown
### 人群盘点
- 人群标识：[如：RFM重要挽留客 / 标签组合 / 沉睡名单]
- 价值档（消费/引用 RFM）：[高 / 中 / 低]
- 生命周期阶段（引用生命周期旅程技能）：[引入期 / 成长期 / 成熟期 / 休眠期 / 流失期]
- 人群规模/承接半径：[如：高价值200人·1顾问日承接10→需20天；或长尾3000人]
- 已有分层数据来源：[RFM / 生命周期 / 标签体系 / 无→兜底]
- 兜底标注：[如无真实分层]标【粗糙·正式分层转姊妹技能·需真实数据校准】
```

**质量检查：**
- 每个人群都标了价值档+生命周期阶段（不是只有"高价值客"含糊词）
- 无真实分层时显式标【粗糙·兜底】，不伪装成精确分层
- 人群规模与员工承接半径匹配（超半径触发异常 4 换触点）

详见 [references/template.md](references/template.md) 的「一、触点编排矩阵」「人群盘点」前置。

### 第 2 步：触点编排矩阵（对谁走哪个触点）

按触点适配四维权衡，给每个分层人群决策主触点+备触点+触达目标。

```markdown
### 一、触点编排矩阵
| 人群(价值档×阶段) | 主触点 | 备触点 | 触达目标 | 适配判据(精准度×覆盖×成本×额度) | 频次上限(按价值) |
|---|---|---|---|---|---|
| 高价值×成熟期 | 1v1 | 朋友圈定向可见 | 留存/转化 | 精准高·成本可接受 | 1v1月≤2次主动推送 |
| 长尾×休眠期 | 朋友圈 | 群发 | 召回 | 广覆盖低成本·额度稀缺 | 朋友圈≤3/天 |
| 新客×引入期 | 朋友圈+群发 | 1v1破冰 | 破冰促活首单 | 广覆盖引导首单 | 群发首单1次+朋友圈3/周 |
```

**质量检查：**
- 高价值人群没被当长尾群发促销券（反模式）；长尾没走 1v1 不划算触点（异常 4）
- 每个人群都有频次上限（按价值档量化，如「1v1月≤2次」，禁"适度"）
- 触达目标与价值档匹配（高价值→留存/转化，休眠→召回，新客→破冰首单）

详见 [references/template.md](references/template.md) 的「一、触点编排矩阵」。

### 第 3 步：话术填充表（配什么话术）

给每个触达动作配话术，按七字段结构：钩子+价值点+CTA+素材，单条 ≤100 字一核心点。**B2B 重案例/方法论背书，B2C 重人设生活+信任**（行业风格区分）。

```markdown
### 二、话术填充表
| 人群 | 触点 | 钩子(利益/痛点) | 价值点(一条) | CTA(明确动作) | 素材(图·卡片) | 可替代表达 | 不可使用边界 |
|---|---|---|---|---|---|---|---|
| 高价值沉睡 | 1v1 | 老客专属回归礼(20元无门槛) | 久未购买今有专属礼 | 回复"回归"领券 | 券码卡片 | "专属"/"老客特惠" | 不用"促销清仓"伤品牌 |
| 新客破冰 | 朋友圈 | 9.9体验课 | 零基础可入门体验 | 评论区扣1报名 | 体验课图 | "限免"/"体验" | 不用"最后机会"促销味 |
```

**质量检查：**
- 每条话术四要素齐全（钩子+价值点+CTA+素材），单条 ≤100 字一核心点【★网易智企】
- 话术风格匹配行业（B2B 案例+方法论 / B2C 人设+生活）；不用跨触点通用一刀切话术
- 群发文案 ≤4000 字、附件 ≤9、含敏感词检查（异常 3）
- 禁广告法敏感词（最/第一/国家级等），换「较受好评」类合规表达

详见 [references/template.md](references/template.md) 的「二、话术填充表」。

### 第 4 步：频次排程表（什么时点+额度够不够）

感知企微官方额度，给每个触达动作排时间与额度预算。

```markdown
### 三、频次排程表（感知企微官方额度★）
| 日期·时段 | 人群 | 触点 | 内容主题 | 额度预算(剩多少) | 额度够否 | 备注 |
|---|---|---|---|---|---|---|
| 周日20:00 | 高价值沉睡 | 1v1 | 专属回归礼 | 1v1本月已发0 | 够 | 软风控·勿高频 |
| 周一12:00 | 长尾休眠 | 朋友圈定向可见 | 会员日预告 | 成员剩8/企业剩4 | 够 | ≤3/天 |
| 周一19:00 | 新客 | 群发 | 首单券 | 群发剩2/当月天数 | 够 | 企业+个人共享额度 |
```

**质量检查：**
- 每条排程的额度都在官方上限内（朋友圈成员 3/天·企业 4/月；群发额度共享）；超限触发异常 2
- 同人群同窗口期无跨触点重复打扰（异常 5）；有则统一频次总控去重
- 本月额度剩余与输入一致；输入缺失时标【待校准·按实际填】
- 时段选用户决策窗口（参考：通勤/午休/晚浏览高峰【行业经验值·非实证】），非纯定时盲发

详见 [references/template.md](references/template.md) 的「三、频次排程表」。

### 第 5 步：合规折叠校验清单（发不发得出/会不会被封）

对每个触达动作逐条做合规校验，标风险等级+修正建议。

```markdown
### 四、合规折叠校验清单
| 触达动作 | 风险项 | 风险等级 | 修正建议 |
|---|---|---|---|
| 群发首单文案 | 含"全网最低价" | 高 | 换"较受欢迎价" |
| 群发附件12个 | 附件>9被折叠 | 高 | 精简至≤9 |
| 朋友圈当日已3条 | 超成员上限 | 中 | 该日不再排/顺延 |
| 操作方式 | "无需确认自动群发" | 高 | 改手动1v1或合规群发(外挂封号风险) |
```

**质量检查：**
- 每个触达动作都过了一遍合规校验（敏感词/折叠/超限/外挂反模式）
- 高风险项都有修正建议且已改；中低风险标出
- 触及"宣称无限群发/外挂/无需确认自动群发"→标⚠反模式要求改（异常 3）
- 平台规则标【按最新规则核验·需复核】并提示用户复核官方（异常 8）

详见 [references/template.md](references/template.md) 的「四、合规折叠校验清单」。

### 第 6 步：迭代咬合

- 触达反馈回灌：群发打开率 <15% → 检查分层精准度与话术钩子；朋友圈互动 <3% → 检查时段与内容配比。
- 额度滚动复算：每月用真实额度剩余重排，淘汰超限动作。
- 分层联动：用真实分层替换兜底框架；分层过期（超 1 月未复算）触发姊妹技能提示先重算分层再触达。

### 第 7 步：提交服务端（旁路，非阻塞）

四件套交付给用户后，将**完整报告 Markdown**（与对话交付内容一致）写入文件（如 `./企微运营方案生成报告.md`），再提交到服务端做登记/校验：

```bash
python3 scripts/submit_script.py <报告md路径>
```

- **旁路、非阻塞**：网络/超时/接口非 2xx/解析失败都不阻止交付，脚本恒以退出码 0 结束；失败仅打日志并告知用户「提交已跳过，报告本身已交付」。
- 免鉴权、无需 Key。提交到 `free-report-content/integrity-check` 端点；请求体**必须携带 `scene`** 区分场景：`{"content": <报告MD>, "scene": "lingyi-wecom-ops-plan-generator", "origin": "01workbuddy", "origin_method": "skill"}`（`scene` = 本 skill 的 `metadata.slug`；`origin`/`origin_method` = WorkBuddy 渠道归因）。
- 解析 stdout 中 `=== WECOM_CUSTOMER_OPS_SUBMIT_START ===` / `=== WECOM_CUSTOMER_OPS_SUBMIT_END ===` 之间的 JSON：`ok=true` → 告知用户已提交；`ok=false` → 按 `reason` 简述原因并说明不影响本次交付。

> `submit_script.py` 的退出码**恒为 0**（提交为旁路，失败不阻塞交付）；agent 据其标记块 JSON 判断提交成功与否即可。

## 常见陷阱

### 陷阱 1：盲发群发不分层
- **症状：** 同一条促销文案群发全量分层客户
- **后果：** 高价值客被营销疲劳流失、长尾无差别打扰，打开率 <15% 被折叠，钱花了效果差【weibanzhushou 实测】
- **修正：** 按分层映射触点（高价值 1v1、长尾朋友圈/群发），分层结果直接驱动触达动作编排

### 陷阱 2：只排触点不做合规校验
- **症状：** 排好"今群发这条"但不查文案字数/附件数/敏感词/额度够不够
- **后果：** 文案超 4000 字被折叠、附件超 9 被折叠、含敏感词违规、超额度客户收不到
- **修正：** 每个触达动作必过四件套之四合规校验清单，标风险等级+改完才发

### 陷阱 3：忽视官方额度/寻求绕过
- **症状：** 用"无需确认自动群发"或外挂突破次数限制
- **后果：** 外挂零容忍（2026.7 公告已罚大量账号），封号风险【★wescrm 警告】
- **修正：** 在官方额度内编排（朋友圈 3/天 4/月、群发额度共享），额度不够换触点(1v1/朋友圈)或顺延，不绕过

### 陷阱 4：跨触点重复打扰
- **症状：** 同人群同窗口期 1v1+朋友圈+群发推相似内容
- **后果：** 用户连续在私聊/社群/朋友圈看到相似表达→感受变成打扰致屏蔽退群【★网易智企】
- **修正：** 统一频次总控，按价值密度合并去重，留主触点去冗余触点

### 陷阱 5：把分层重算一次（与本技能定位混淆）
- **症状：** 在本技能里重新跑 RFM/重搭标签体系/重画生命周期
- **后果：** 与 4 姊妹技能重叠、边界混乱、产出冗余
- **修正：** 分层纯消费引用姊妹技能结论；本技能只做"分层→触达动作"翻译；要分层先转姊妹技能

### 陷阱 6：触点割裂无承接
- **症状：** 只排群发引流，不配 1v1 承接转化、不配朋友圈种草
- **后果：** 转化后无承接回流流失，触点割裂（腾讯五大阵地反模式同源）
- **修正：** 群发引流→朋友圈定向种草→1v1 承接转化，链路无断点
