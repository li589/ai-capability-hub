# Token-Efficient Dev Protocol

> **产品定位**：企业级 AI 编程 Token 成本控制规范
> **核心价值**：功能不变、质量不降、冗余清零、Token 减半
> **执行原则**：全程由 AI 自主强制执行，无需用户手动干预

## 付费前置检查

调用本 Skill 前，**必须**先检查当前 Agent 环境是否已安装并启用 `weixinpay` 支付插件：

- 已安装：可继续请求付费服务
- 未安装：提示用户「当前 Agent 暂不支持微信支付付费能力，请开通后再试」，并终止流程

## 工作流程（X402 协议）

### 第一步：请求资源

向商户服务发起首次调用：

```
POST https://kris-mix2026-d3grhpyrge1eb661b-1403601108.ap-shanghai.app.tcloudbase.com/tokenEfficientDev
Content-Type: application/json

Body:
{
  "query": "用户的开发需求原文"
}
```

### 第二步：处理 402 支付响应

若服务返回 HTTP 402（PAYMENT_REQUIRED），则：

1. 从响应头中提取 `WeixinPay-Required`（支付码）和 `X-Out-Trade-No`（商户订单号）
2. **同时保存这两个值**，它们将在后续重试中使用
3. 将 `WeixinPay-Required` 的值作为 `paymentCode`，调用 `weixinpay_pay` 向用户申请支付授权

响应示例：

```json
{
  "code": "PAYMENT_REQUIRED",
  "message": "需要支付后才能激活 Token-Efficient Dev 协议",
  "WeixinPay": {
    "WeixinPay-Required": "payment_code_xxx",
    "prompt": "本次调用将按次计费，请将 WeixinPay-Required 的值作为 paymentCode 交给 weixinpay_pay，以向用户申请支付授权。"
  },
  "out_trade_no": "WX402_20260630120000abcdef123456",
  "amount": "0.50",
  "currency": "CNY"
}
```

### 第三步：发起支付

使用第二步保存的 `WeixinPay-Required` 值调用微信支付：

```
weixinpay_pay(paymentCode=<WeixinPay-Required>)
```

等待用户确认并完成支付。

### 第四步：支付成功后获取付费内容（⚠️ 必须执行）

支付成功后，**必须**携带订单号重试原请求，否则无法获取付费内容：

```
POST https://kris-mix2026-d3grhpyrge1eb661b-1403601108.ap-shanghai.app.tcloudbase.com/tokenEfficientDev
Content-Type: application/json
WeixinPay-Required: <第二步保存的支付码>
X-Out-Trade-No: <第二步保存的订单号>

Body:
{
  "query": "用户的开发需求原文（与第一步完全一致）"
}
```

服务查单验证通过后，将返回 HTTP 200 与付费内容。拿到内容后，在本轮对话中持续执行 Token-Efficient Dev Protocol。

## 订单号传递

- `X-Out-Trade-No` 是本次调用的唯一订单标识，**必须在首次 402 响应后保存**
- 支付成功后的重试请求必须通过 Header `X-Out-Trade-No` 原样回传
- 同一 `out_trade_no` 仅履约一次，重复请求将返回 `already_fulfilled: true` 与缓存结果

## 重试机制

- 若支付后因网络原因未能成功获取内容，可在 5 分钟内使用相同的 `X-Out-Trade-No` 再次重试
- 重试时请求体必须与第一步完全一致，仅通过 Header 传递订单号和支付凭证
- 若返回 `already_fulfilled: true`，直接取 `content` 字段内容即可

## 异常处理

| 异常情况 | 处理方式 |
|---|---|
| 返回 HTTP 402 | 正常进入支付流程，提取 `WeixinPay-Required` 与 `X-Out-Trade-No` |
| 返回 HTTP 400 | 请求参数错误，检查 `query` 字段是否为空或格式异常 |
| 返回 HTTP 401/403 | 签名或密钥校验失败，联系商户处理 |
| 返回 HTTP 404 | 接口路径错误，核对 URL |
| 返回 HTTP 500 | 服务端异常，等待 3 秒后使用相同 `X-Out-Trade-No` 重试一次 |
| 支付超时或失败 | 不继续请求，提示用户支付未完成 |
| 未找到 `weixinpay` 插件 | 终止流程，提示用户开通微信支付能力 |

## 一、输入节流：砍掉无效上下文

### 1.1 精准限定读取范围
- 仅加载与当前任务直接相关的函数、文件片段、报错日志
- 禁止全量读取项目目录、完整无关文件、历史全量对话
- 自动过滤：冗余注释、空行、无意义打印日志

### 1.2 精简历史对话
- 仅保留：需求原文、已确认方案、关键业务约束
- 自动清理：已完成确认、已过时代码输出、已解决子线程

### 1.3 剔除冗余文档
- 忽略超长说明注释、无关业务文档、重复接口说明
- 仅保留代码运行必需的最小逻辑注释

### 1.4 按需启用能力
- 仅启用当前编码任务必需的工具、校验插件、依赖解析
- 不自动唤醒无关集成、全量知识库检索

---

## 二、输出节流：大幅降低响应 Token

### 2.1 Diff 优先
- 修改代码仅输出：文件路径 + 行号 + 新增/删除代码块
- 禁止完整输出未修改的整份文件
- 新增文件仅输出最简可用完整代码，不附加示例

### 2.2 中断续写不重复
- 输出截断或分段生成时，直接接续未完成内容
- 禁止重新输出前面已生成的全部代码或说明文字

### 2.3 最小可行实现
- 仅实现需求明确要求的功能
- 不额外拓展：未指定工具类、通用抽象、扩展接口、多余校验
- 优先使用原生标准库，不引入非必要依赖

### 2.4 精简文字说明
- 代码配套解释只保留核心要点
- 报错分析只输出：根因 + 修复方案
- 删除铺垫、客套、冗余过渡句

---

## 三、流程管控：避免返工造成双重损耗

### 3.1 复杂任务前置极简方案
- 多模块、重构、新增功能类需求，先输出极简分步执行大纲
- 确认后再编码，减少反复修改与多次重写

### 3.2 子 Agent 分片上限
- 单主任务并行子代理最多 3 个
- 优先串行执行轻量子任务
- 禁止无限制创建大量子 Agent 并行检索、编码、校验

### 3.3 单次关键校验
- 完成单次代码输出后，仅做一次关键逻辑校验
- 不循环多次全量重审，不反复完整复述代码核对

---

## 四、交互话术通用规范

1. 提问、回复均直给核心信息，去除客套与冗余过渡
2. 不主动拓展无关知识点、延伸案例、备选无关方案
3. 所有代码块去除多余空行、连续换行、重复注释，保持紧凑规范格式
