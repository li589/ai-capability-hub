# 七陌会话洞察复杂分析 Playbook

本文件用于复杂分析任务：大数据量采样、语义聚类、情绪/风险识别、客服表现归因、典型样本引用、图表和报告输出。简单计数、普通 Top N、单次查询不需要读取本文件。

## 目录

- 大数据量分析
- 聚类分析
- 情绪与风险识别
- 客服表现分析
- 典型会话引用
- 图表和表格
- 报告结构
- 业务建议
- 可信度说明

## 大数据量分析

当用户查询涉及大规模会话数据，且无法通过结构化字段直接聚合得到结果时，采用混合分析方式，避免一次性拉取全量数据导致 MCP 超时、结果超限或上下文溢出。

适用场景：

- 查询数据量较大，无法直接将原始数据全部交给 LLM 处理。
- 数据中缺少可直接聚合的标签字段，例如问题类型、重复咨询原因、解决状态。
- 分析目标依赖会话原文，需要理解用户问题、客服回复或完整对话内容。
- 单纯 SQL 聚合无法回答“为什么”“主要原因”“典型表现”。

处理原则：

1. 先评估数据规模：查询总会话数、消息数、时间分布、渠道/客服组/标签等维度分布。
2. 优先结构化聚合：已有字段可以直接支撑统计时，不拉取原文做低效分析。
3. 分层采样：按时间、业务线、渠道、机器人、客服组、产品、地区、风险等级等维度采样。
4. 局部扩展：一级采样发现整体趋势后，从中选择 5-6 个重点采样点拉取完整会话验证。
5. 分批沉淀：较大的任务可以把每批分析结果写入本地 Markdown 作为中间结果。
6. 明确边界：最终说明数据范围、采样方式、样本覆盖情况和可能误差。

表述要求：

- 采样分析结果说“样本中显示”“趋势上”“高频出现”。
- 不把采样归纳当作全量精确统计。
- 不只取最新 N 条或任意前 N 条作为代表样本。

## 聚类分析

用户提出“聚类分析”“高频问题”“主要咨询问题”“主题归类”“原因归纳”时：

1. 先查询表结构和列注释，确认是否存在问题类型、意图标签、业务分类、会话标签等结构化字段。
2. 如果存在可靠标签，优先基于结构化标签做 SQL 聚合，并结合时间、渠道、客服组等筛选条件完成统计。
3. 如果标签缺失、不可信或无法覆盖用户问题，再抽取完整会话内容做语义聚类。
4. 数据量较大时走分层采样，不要直接拉全量原文。
5. 每个主题输出：主题名、数量/样本占比、典型会话、关键原话、业务含义、建议处理方向。

关键词召回只能作为候选，不等于最终分类。最终主题必须基于上下文理解。

## 情绪与风险识别

用户问“负面情绪”“投诉”“升级”“流失风险”“高价值客户不满”“服务风险”时：

1. 用风险关键词、评价结果、评价标签、重复追问、等待过久、长会话等召回候选。
2. 按风险表达强度、重复追问次数、负面评价、等待时长等因素排序。
3. 查询完整会话上下文，判断是真风险还是普通咨询。
4. 输出风险等级、诱因、证据片段、建议跟进动作。

风险判断维度：

- 客户是否表达明确不满、投诉、退款、升级、流失意向。
- 客户是否多次重复同一问题。
- 客服是否未正面回应、答非所问、流程卡住。
- 是否存在高价值客户、关键订单、强时效诉求。
- 处理结果是否闭环。

不要仅凭“退款”“投诉”等单词判定高风险；必须结合客户态度、处理结果和上下文。

## 客服表现分析

用户问“响应慢”“客服组表现”“客服质量”“首次未解决”“重复追问”“解释不清”“服务风险”时：

1. 响应时效类：先用会话级指标聚合，按客服组、客服、渠道或平台来源排名。
2. 内容质量类：查访客重复追问、负面评价、长会话、高访客消息数、低坐席回复数等候选。
3. 查询典型完整会话，判断问题来自产品流程、知识库、排班、客服表达还是客户问题复杂度。
4. 输出指标排名、异常场景、样本证据和改进建议。

注意：

- 消息数量不直接等同于服务质量。
- 长会话可能是复杂问题，也可能是解释不清。
- 响应慢可能来自排班、系统、渠道异步、客户离线等原因，需要结合上下文。

## 典型会话引用

用户要求“每个主题给 2 条样本”“列出典型会话”“附关键原话”“给我案例”时：

1. 先明确主题或风险类别。如果用户没给主题，先做聚类或候选统计。
2. 每类抽取约2 个不同 `session_id`，优先选择内容完整、证据清晰、时间较近的会话。
3. 查询完整会话后，摘取 1-3 条关键原话片段。
4. 输出 `session_id`、时间、客服组/客服/渠道、样本摘要、关键原话、代表性理由。

样本引用应脱敏，只保留支撑结论的片段，避免整段会话堆叠。

## 图表和表格

图表服务于分析目标，不为画图而画图。简单问答不画图。

| 分析目标 | 推荐方式 |
|----------|----------|
| 看哪个最多 | 横向柱状图、Top N 表格 |
| 看占比结构 | 饼图/环形图，仅适合分类较少 |
| 看变化趋势 | 折线图 |
| 看增长最快 | 增长率排序表 + 趋势折线图 |
| 看渠道、客服组、问题类型对比 | 分组柱状图、堆叠柱状图、热力图 |
| 看风险会话或异常样本 | 明细表格、样本卡片 |
| 看原始证据 | 关键原话、会话摘要、判断依据 |

如果分类较多，不建议使用饼图；如果关注排序，优先柱状图；如果关注变化，优先折线图。

表格适合承载排名、指标、分类、样本和建议。字段不要过多；复杂信息拆多个表格。

## 报告结构

复杂分析可按需组合：

```markdown
### 分析范围
说明时间范围、数据来源、会话数量、过滤条件。

### 核心结论
用 2-5 条要点概括最重要发现。

### 关键指标
展示会话数、主题数、高风险数、负面占比、增长率等核心指标。

### 图表分析
根据分析目标展示排名、趋势、占比或对比结果。

### 明细表格
展示可复核的分类、指标、样本或异常明细。

### 典型样本
提供代表性会话摘要、关键原话和判断依据。

### 业务建议
给出处理优先级、责任方、建议动作和预期收益。

### 可信度说明
说明数据范围、字段限制和模型判断边界。
```

不要机械输出所有模块。比如“近 10 天有多少会话”只需要核心结论和分析范围。

## 业务建议

只有存在问题、风险或优化空间时才输出建议，不要每个问题都强行建议。

建议表可采用：

| 优先级 | 问题 | 责任方 | 建议动作 | 预期收益 |
|--------|------|--------|----------|----------|
| 高 | 高频且增长明显的问题 | 产品 / 运营 / 客服 | 优化页面说明、知识库、客服话术或处理流程 | 降低重复咨询、投诉或流失风险 |
| 中 | 局部影响的问题 | 对应业务团队 | 补充说明、抽样复核、专项培训 | 提升服务一致性 |
| 低 | 低频但可优化的问题 | 运营 / 客服 | 纳入后续优化项 | 减少简单咨询 |

建议应明确责任方、处理动作和优先级，避免泛泛而谈。

## 可信度说明

当分析依赖模型判断、样本量较小、字段不完整或分类边界不清晰时，应说明：

- 数据时间范围。
- 分析会话数量。
- 是否过滤无效会话。
- 是否存在字段缺失。
- 主题分类、情绪识别、风险判断可能存在的边界。
- 是否建议业务人员复核高风险或高价值样本。

示例：

> 本次分析基于指定时间范围内的会话数据生成。主题分类、情绪识别和风险判断由模型根据会话内容自动归纳，部分相近主题可能存在边界重叠。涉及投诉风险、高价值客户或重大业务决策的结论，建议结合原始会话样本进行人工复核。
