# DesignKit 爆款视频

通过简洁的对话流程生成或复刻营销短视频。默认使用简体中文。

## 默认方案

- 模式：`generate`；提供参考视频文件或分享链接时使用 `replica`
- 市场：美国
- 语言：英语
- 视频比例：9:16
- 视频时长：固定 15 秒，不可修改
- 视频类型：UGC 种草（`ugc`）
- 生成数量：1 条
- 模特与人设：默认不使用模特
- 内容：根据商品图和用户描述整理

用户提出相关需求时，再展开视频类型、数量、自定义脚本和 AI 模特选项。

## 渐进式首轮

先判断用户意图，不得把下面几种场景合并回答。

### 直接生成

用户说“做一条爆款视频”“帮我生成视频”但尚未上传商品图时，回复控制在约 120 个中文字内：

> 可以，直接上传商品图即可开始。
> 默认生成 1 条 15 秒英语 TikTok 竖屏 UGC 视频，不使用模特；时长固定不可修改。
> 想调整可回复“查看选项”，我会列出视频类型、语言、平台和模特的完整选项。要复刻已有视频，可同时提供参考视频。

不要在这一步附完整选项目录，但必须保留“查看选项”入口；不要提及接口、帮写开关或内部工作流。

### 询问怎么做

只说明三步，不展开参数：

使用下面的三步流程：

1. 上传商品图；要复刻现有视频时，再提供参考视频文件、直接视频链接或 TikTok/Reels 等平台分享链接。
2. 我会整理卖点和脚本，并按你的自然语言修改视频类型、市场、语言、画面比例、模特和数量。
3. 提交前先算价，只确认一次价格；确认后开始生成，通常需要 5-10 分钟。

用户没有素材时，最后只要求上传商品图。用户已经提供商品图时，立即整理当前草稿。

### 询问完整选项

只有用户明确询问“有哪些选项”“可以设置什么”时，才说明以下内容。

**必填内容**

- 生成爆款：至少 1 张商品图。商品卖点可由当前 Agent 根据图片和描述整理，因此不是用户必填项。
- 爆款复刻：至少 1 张商品图、1 个参考视频文件或分享链接，并在提交时确认拥有相应使用授权。

**可选配置与默认值**

- 模式：生成爆款、爆款复刻；默认生成爆款，提供参考视频时自动切换为复刻。
- 商品卖点：可填写或修改产品名称、关键卖点、使用方法、目标用户和使用场景；默认由当前 Agent 结合商品图与用户描述整理。
- 内容：由我根据商品图整理（默认）、使用用户提供的卖点、卖点优化。
- 视频组合：UGC 种草、产品口播、带货短剧、产品演示、开箱种草、痛点解决、反应展示、品牌广告（TVC），每种可生成 1-5 条；默认 `UGC 种草 × 1 条`。支持“做 2 条 UGC 加 1 条产品演示”。复刻模式只选择复刻数量。
- 脚本：自动脚本、自定义脚本；默认自动脚本，自定义脚本始终允许修改。
- 目标市场：北美、欧洲、中国、日本、韩国、东南亚、巴西、全球/其他；默认北美。
- 视频语言：英语、中文、日语、韩语、西班牙语、葡萄牙语、泰语、马来语、菲律宾语、印尼语、纯音乐无口播；默认英语。
- 发布平台与比例：TikTok/Reels 9:16、抖音 9:16、小红书 9:16、淘宝主图 1:1、YouTube 16:9、亚马逊 16:9；默认 TikTok/Reels 9:16。
- 模特：无模特、官方模特、定制 AI 模特；默认无模特。模特列表不可用时继续使用无模特配置。

用户选择定制 AI 模特时，转到[定制 AI 模特](../designkit-viral-video-model/SKILL.md)完成生成和图片确认，再将返回的模特配置用于当前视频草稿。

**固定项**

- 视频时长固定为 15 秒，不可修改。
- 正式生成前进行只读算价并请求一次价格确认；确认后生成通常需要 5-10 分钟。

用户追问某类“有哪些”时，只展开对应目录中的真实可选值。例如询问视频类型，只列出 8 种类型并各用一句短说明帮助选择；不要重新输出市场、语言、模特等无关配置。

在内部每轮对话最多调用一次 `init_cfg` 并复用结果，将返回内容转换为用户易懂的中文名称；接口返回的可见选项优先于上面的静态目录。调用失败时使用以上目录和默认值继续说明。不要向用户展示 `init_cfg`、字段名、枚举代码或命令。

需要页面示例时提供对应入口：[爆款生成](https://www.designkit.cn/viral-video/viral-generate)或[爆款复刻](https://www.designkit.cn/viral-video/viral-replicate)。已经判断出模式时只发送对应链接。

## 会话草稿

收到商品图后维护一份草稿。首次逐行展示当前值，并紧接着给出一次紧凑的修改目录：

> 当前方案
> 市场：美国
> 语言：英语
> 视频：UGC 种草 × 1 条
> 平台：TikTok 竖屏
> 模特：不使用
> 固定：时长 15 秒（不可修改）

> 可以修改，直接说即可：
> - 视频类型：UGC 种草、产品口播、带货短剧、产品演示、开箱种草、痛点解决、反应展示、品牌广告；可混搭，合计 1-5 条
> - 语言：英语、中文、日语、韩语、西班牙语、葡萄牙语、泰语、马来语、菲律宾语、印尼语、纯音乐无口播
> - 平台与画面：TikTok/Reels 9:16、抖音 9:16、小红书 9:16、淘宝主图 1:1、YouTube 16:9、亚马逊 16:9
> - 市场：北美、欧洲、中国、日本、韩国、东南亚、巴西、全球/其他
> - 内容：由我整理卖点、使用你的卖点、卖点优化，或使用自定义脚本
> - 模特：不使用、官方模特、定制 AI 模特
> 例如：`做 2 条 UGC 加 1 条产品演示，改成日语，使用官方模特。`

视频类型、语言、平台与画面的可选值必须完整展示，不得用“等”省略。这个修改目录只在收到素材后的首次草稿展示一次。用户补充信息时只更新变化项和仍缺少的必填内容，不重复完整说明。准备算价前再汇总一次最终草稿，之后只确认价格。

## 商品卖点确认

收到商品图后，根据图片和用户描述整理以下五项。价格确认前必须逐项展示真实内容，不能只写“商品素材”或省略整段：

> 商品卖点信息（可以修改）
> - 商品名称：便携蓝牙音箱
> - 核心卖点：IPX7 防水、长续航、便携设计
> - 使用方法：蓝牙连接手机后播放音乐
> - 目标用户：户外运动和旅行用户
> - 使用场景：露营、海边、居家聚会

图片足以判断时直接生成可编辑草稿；只有无法可靠判断商品类别或核心用途时才追问一个关键问题。用户修改任何一项后，更新同一份草稿。调用 `prepare` 时传入 `selling_points_profile`，并在最终方案中再次展示这五项和实际内容；卖点为空时不得算价或提交。

## 执行流程

1. 缺少商品图时，请用户提供一张或多张图片文件或 URL，并等待素材。
2. 围绕商品名称、关键卖点、使用方法、目标用户和使用场景整理可编辑内容。默认由当前 Agent 整理，不调用外部优化接口；用户明确选择“卖点优化”后才调用以下辅助动作。返回 `status=fallback_required` 或调用失败时，由当前 Agent 结合商品图和用户原文生成草稿，不中断流程。

```bash
python3 __SKILL_DIR__/../scripts/viral_video.py selling_points_help --input-json '<json>'
```

无论优化成功或降级，结果都只是可编辑草稿。用户可继续修改商品卖点，也可新增或修改自定义脚本；调用 `prepare` 前始终采用用户最后一次修改的内容。存在非空 `custom_script` 时使用自定义脚本和对应数量，不同时传入 `script_types`。

3. 根据素材推断模式：提供参考视频时使用 `replica`，其余情况使用 `generate`。参考视频文件、平台分享链接和直接视频链接统一执行素材准备：解析或读取视频、校验格式/时长/分辨率/音轨、上传稳定存储。参考视频上传策略固定使用 `app=xiuxiu-pro`、`type=ai_image_video`、对应视频后缀及 `count=1`，返回地址必须位于 `/ai_image_video/` 路径；失败时只给可执行建议，不把原始分享链接或错误桶地址直接提交。

```bash
python3 __SKILL_DIR__/../scripts/viral_video.py reference_video_prepare --input-json '<json>'
```
4. 使用 OpenClaw 对应的国内 DesignKit 配置。需要配置选项时，每轮对话最多获取一次 `init_cfg` 并复用结果。
5. 用户明确选择使用模特时，才按目标市场获取国内官方模特。首批展示 4-6 个候选并使用稳定编号；必须用返回的远程 URL 输出 Markdown 图片节点，不能输出图片 URL 列表。用户可以回复编号、“换一批”或“查看全部”：

```bash
python3 __SKILL_DIR__/../scripts/viral_video.py preset_model_list --input-json '{"count":6}'
```

每位候选使用两行展示：先输出独立的可复制编号，例如 `M535FA`，下一行输出 `![标签](URL)`，URL 使用对应的 `artifacts[].url`。图片节点不能放进 Markdown 表格或代码块，不能使用 `present_files` 处理远程 URL，不能只输出编号、裸 URL 或“预览不可见”，也不能让用户盲选。用户可以复制编号，或回复“换一批”“查看全部”。将选中编号对应 `models[].image_url` 作为 `custom_model_reference`，设置 `has_custom_model=true`，并传入 `model_type=my_model`。
返回 `status=unavailable`、`status=empty` 或调用失败时，不传模特相关参数，直接使用无模特的默认配置继续执行 `prepare`；不要要求用户重试，也不要中断流程。
6. 执行内部准备动作：

```bash
bash __SKILL_DIR__/../scripts/run_designkit_workflow.sh viral-video prepare --input-json '<json>'
```

7. `status=action_required` 时，展示 `user_hint` 和 `action_url`，并结束当前尝试。
8. `status=ready_for_confirmation` 时，展示 `pricing.user_hint`，说明视频生成通常需要 5-10 分钟，并请求一次价格确认。复刻模式在同一次确认中包含参考视频授权声明。
9. 用户确认后，使用 `confirmed=true` 调用 `execute`；复刻模式同时传入 `reference_authorized=true`：

```bash
bash __SKILL_DIR__/../scripts/run_designkit_workflow.sh viral-video execute --input-json '<json>'
```

10. `status=processing` 时，告知用户视频仍在生成，在内部保留 `task_ref`，并继续调用 `resume`。
11. `status=completed` 或 `completed_with_errors` 时，先执行下载上报，再对每个成功视频调用 `preview_url`，参数 `url` 使用对应的 `artifacts[].url`。随后在最终回复中逐条输出 `[播放视频 N](URL)`，并保留每个终态视频的 `task_ref`。不要使用 `present_files` 处理远程视频 URL；成功任务暂未返回 URL 时继续 `resume`。
12. 下载上报和 `preview_url` 都不得保存视频到用户本地。`preview_url` 完成后告诉用户“视频已在预览面板打开”，同时保留播放链接；不得声称已在对话框中内嵌播放器。如需保存到下载目录，提示用户可以说“下载全部”。
13. 用户明确要求下载或保存到本地时，携带原 `task_ref` 执行以下工作流动作。该动作查询对应的已生成视频并保存到本地，不重复上报：

```bash
bash __SKILL_DIR__/../scripts/run_designkit_workflow.sh viral-video download --input-json '<json>'
```

保存动作直接下载已展示的视频；本地保存失败只重试工作流 `download` 动作，不重新上报或生成视频。

## 单条重新生成

- 视频展示完成后主动提示：`如果某条效果不满意，可以说“重做第 2 条”。`
- 用户点名某条成功、失败或取消的视频时，找到对应 `task_ref`，执行 `regenerate`。一次只重新生成一条，不重新投递整批视频。
- 重新生成沿用原视频的商品素材、类型、脚本、市场、语言、比例和模特配置。
- 完成后用 `preview_url` 打开新视频并在回复中保留播放链接，继续提供单条重新生成入口。

```bash
bash __SKILL_DIR__/../scripts/run_designkit_workflow.sh viral-video regenerate --input-json '<json>'
```

## 内部输入

默认生成参数：

```json
{
  "product_images": ["/path/or/url.jpg"],
  "product_info": "便携蓝牙音箱，长续航、防水",
  "market": "US",
  "language": "English",
  "aspect_ratio": "9:16",
  "script_types": [{"type": "ugc", "count": 1}]
}
```

复刻模式可接收本地视频文件、平台分享链接或直接视频 URL，并先通过 `reference_video_prepare` 校验和转换为稳定视频地址。

配置、卖点优化、官方模特、上传签名、算价、任务提交、轮询、下载地址获取和失败重做等 DesignKit 服务接口统一携带公共 `channel`；运行时只读取 `DESIGNKIT_CHANNEL` 或公共默认常量，不能使用用户输入覆盖。对象存储上传和媒体文件下载使用服务端签发的原始地址，不修改签名 URL。

## 结果规则

- 以 `artifacts` 作为媒体交付协议，并使用其中整理后的字段构造用户输出。
- 下载上报、结果展示与用户保存是相互分离的动作。轮询完成后先执行 `report`，再使用上报结果构造 `artifacts[].url`；`local_path` 保持为空。
- Agent 必须用 `preview_url` 自动打开 `artifacts[].url`，并在对话正文提供可点击播放链接。WorkBuddy 不会把 `present_files` 中的 HTTP URL 转成对话媒体附件，`show_widget` 也不能加载非白名单 CDN，因此禁止用这两种方式宣称已内嵌视频。用户明确保存时才写入下载目录。
- 上报结果暂未返回可用 URL 时回退到查询结果中的 `res_video`；两者都不可用时继续 `resume`。
- 查询超时或结果暂不可读时保留原任务并继续 `resume`；用户保存时发生本地异常只重试工作流 `download` 动作，不得重新投递或提示退款。
- 只有服务端明确返回失败视频时才展示 `refund_hint`；本地保存失败不得阻断同批其他结果。
- 短暂网络传输失败自动重试一次；内容风控、参数、会员和余额问题返回对应处理建议。
- 本次任务只处理用户明确提供的商品图片和参考视频。
