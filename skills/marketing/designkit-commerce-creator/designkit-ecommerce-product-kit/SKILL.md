# DesignKit 商品套图

通过简洁的对话生成七张电商上架套图。默认使用简体中文。

## 默认方案

- 平台：Amazon
- 市场：美国
- 图片文字：英语
- 图片比例：1:1
- 视觉风格：自动匹配
- 输出数量：固定 7 张；具体图片类型和名称以生成结果标签为准

用户明确指定平台、市场、图片文字、比例、风格或商品卖点时，采用用户提供的内容。

## 渐进式首轮

先判断用户意图，不得把下面几种场景合并回答。

### 直接生成

用户说“帮我做商品套图”但尚未上传商品图时，回复控制在约 120 个中文字内：

> 可以，直接上传商品图即可开始。
> 默认生成 7 张 Amazon 美国站英语方图，视觉风格自动匹配。
> 想调整可回复“查看选项”；也可以直接说“做日本站日语 3:4 套图”。

不要在这一步展开完整参数，不追问平台、市场、语言或风格。

### 询问怎么做

只说明三步，不展开配置目录：

1. 上传一张或多张商品图。
2. 我会整理商品信息并给出推荐方案，你只需修改自己关心的内容。
3. 提交前先算价，只确认一次价格；确认后生成 7 张套图并直接展示，需要时再下载到本地。

用户没有素材时，最后只要求上传商品图。用户已经提供商品图时，立即整理当前草稿。

### 询问完整选项

只有用户询问“有哪些选项”“可以设置什么”或回复“查看选项”时，才展示以下内容。

**必须提供**

- 至少 1 张商品图。
- 商品名称和核心卖点需要在算价前明确；默认由当前 Agent 结合图片与用户描述整理，用户无需先填写表单。

**可以调整**

- 商品信息：商品名称、核心卖点、使用方法、目标用户、使用场景；默认由当前 Agent 整理，用户可以随时修改。
- 平台：Amazon、淘宝/天猫/1688、Temu、TikTok Shop、拼多多、抖音电商、OZON、独立站、Shopee、阿里巴巴国际站、速卖通、SHEIN、京东、美客多、Coupang、Wayfair；默认 Amazon。
- 市场：美国、欧洲、中国、俄罗斯、东南亚、西班牙、德国、日本、韩国、巴西、墨西哥；默认美国。
- 图片文字：英语、中文、俄语、西班牙语、德语、日语、韩语、葡萄牙语、印尼语、泰语、无文字；默认英语。
- 图片比例：1:1、3:4、9:16、16:9；默认 1:1。
- 视觉风格：自动匹配（默认），或查看四套候选风格后选择。风格选择属于高级选项，用户没有主动提出时不展开。

**固定内容**

- 每次生成 7 张商品套图，具体图片类型和名称以结果标签为准。
- 本能力处理商品套图；A+ 详情页、详情页长图和长图拼接不属于本能力。
- 正式生成前进行只读算价，只请求一次价格确认。

列出选项后提醒用户无需逐项填写，可以直接说：`做 TikTok Shop 日本站日语 3:4 套图，风格自动。`

需要页面示例时提供[商品套图页面](https://www.designkit.cn/product-kit)，让用户通过可视化界面理解选项。

## 会话草稿

收到商品图后，先分析图片与用户描述，再维护一份可持续修改的草稿。首次展示采用以下结构：

> 当前方案
> 平台：Amazon
> 市场：美国
> 图片文字：英语
> 图片比例：1:1
> 视觉风格：自动匹配
> 固定输出：7 张

> 商品信息（可以修改）
> - 商品名称：便携蓝牙音箱
> - 核心卖点：IPX7 防水、长续航、轻巧便携
> - 使用方法：蓝牙连接手机后播放音乐
> - 目标用户：户外运动和旅行用户
> - 使用场景：露营、海边、居家聚会

紧接着给出明确入口：

> 可以直接说要改什么，例如“改成 Temu 德国站、德语、3:4”。
> 回复“查看选项”可查看平台、市场、图片文字、比例和风格的完整可选项。

商品名称和核心卖点无法可靠判断时，只追问一个关键问题。其余字段可以根据图片合理整理为可编辑草稿。用户补充信息时只更新同一份草稿中变化的内容，不重复首轮说明或完整选项目录。

价格确认前再汇总一次最终方案和商品信息，之后只确认价格。不得只展示文件名或“商品素材”，也不得用“商品”作为占位卖点进入算价。

## 风格选择

普通用户直接使用自动风格。只有用户主动要求指定风格、查看风格候选或修改视觉方向时，才进入以下流程：

1. 使用第一张商品图、当前商品信息、平台和市场生成四套候选风格：

```bash
bash __SKILL_DIR__/../scripts/run_ecommerce_kit.sh style_create --input-json '<json>'
```

2. 使用返回的任务信息查询候选结果：

```bash
bash __SKILL_DIR__/../scripts/run_ecommerce_kit.sh style_poll --input-json '<json>'
```

3. 只展示接口返回的风格名称、选择理由和色彩方向，让用户回复编号或名称。选中后把对应完整对象作为 `brand_style` 放入当前草稿。
4. 候选风格获取失败时，提供“继续使用自动风格”或“稍后重试”两个明确动作；通用商品套图流程仍可使用自动风格继续。

不得自行编造四套风格，也不要让普通用户先等待风格生成再开始套图。

## 执行流程

1. 缺少商品图时，请用户上传一张或多张图片，并等待素材。
2. 根据图片和用户描述整理商品名称、核心卖点、使用方法、目标用户和使用场景，先向用户展示可编辑草稿。只有商品类别或核心用途无法判断时才追问一次。
3. 展示当前平台、市场、图片文字、比例、风格和固定输出数量，同时给出“查看选项”入口。用户未修改的内容采用默认方案。
4. 用户主动选择风格时完成候选风格流程；其余情况直接使用自动风格。
5. 执行内部准备动作：

```bash
bash __SKILL_DIR__/../scripts/run_designkit_workflow.sh product-kit prepare --input-json '<json>'
```

6. `status=action_required` 时，展示 `user_hint` 和 `action_url`，并结束当前尝试。
7. `status=ready_for_confirmation` 时，逐行汇总最终方案与商品信息，展示 `pricing.user_hint`，只请求一次价格确认。
8. 用户明确确认后，使用返回的 `config` 并增加 `confirmed=true` 调用：

```bash
bash __SKILL_DIR__/../scripts/run_designkit_workflow.sh product-kit execute --input-json '<json>'
```

9. `status=processing` 时，在内部保留 `task_ref`，向用户简要说明正在生成或确认状态，并使用 `resume` 续接任务。禁止重新提交付费任务，也禁止向用户展示 `task_ref`、`batch_id` 或其他内部标识。
10. `status=completed` 或 `completed_with_errors` 时，按 `artifacts` 的标签逐张展示成功图片；失败项说明会自动退还对应额度，并提供单张重试。最终回复中每张图片先输出标签，下一行输出 `![标签](URL)`，URL 使用对应的 `artifacts[].url`。图片节点必须一图一行，不能放进 Markdown 表格或代码块，不能使用 `present_files` 处理远程 URL，也不能只输出裸 URL 或普通链接。
11. 生成完成后先执行下载上报，再按上述 Markdown 图片节点逐张渲染；上报阶段不得保存到用户本地。只有实际输出完全部图片节点后，才能告诉用户“图片已展示，如需保存到下载目录可以说‘下载全部’”。
12. 用户明确要求下载或保存到本地时，携带原 `task_ref` 执行以下工作流动作。该动作使用已上报的 `res_img` 保存图片，不重复上报：

```bash
bash __SKILL_DIR__/../scripts/run_designkit_workflow.sh product-kit download --input-json '<json>'
```

保存完成后可展示保存结果和 `artifacts[].local_path`；对话中的图片仍使用 `artifacts[].url` 输出 Markdown 图片节点。

## 单张重新生成

- 套图展示完成后主动提示：`如果某张效果不满意，可以说“重做第 3 张”或直接说图片名称。`
- 用户按序号或结果标签点名时，在当前结果中找到对应 `artifact.task_ref`。
- 使用该图片的 `task_ref` 调用 `regenerate`，只重新生成这一张，不重新提交整套图片。成功图片和失败图片都支持。
- 重新生成完成后内嵌展示新图片，并保留原套图中其他结果；仍提示可以继续点名重做。

```bash
bash __SKILL_DIR__/../scripts/run_designkit_workflow.sh product-kit regenerate --input-json '<json>'
```

## 内部输入

优先传入结构化商品信息，工作流会同步生成服务端需要的 `product_info`：

```json
{
  "image_urls": ["/path/or/url.jpg"],
  "selling_points_profile": {
    "product_name": "便携蓝牙音箱",
    "key_selling_points": ["IPX7 防水", "长续航", "轻巧便携"],
    "usage": "蓝牙连接手机后播放音乐",
    "target_audience": "户外运动和旅行用户",
    "use_scenarios": ["露营", "海边", "居家聚会"]
  },
  "platform": "amazon",
  "market": "US",
  "language": "English",
  "aspect_ratio": "1:1"
}
```

本地图片会上传至 DesignKit 服务。只处理用户在当前任务中明确提供的图片。
算价、风格、上传签名、套图提交、轮询和单张重生成请求统一携带公共 `channel`；运行时只读取 `DESIGNKIT_CHANNEL` 或公共默认常量，不能使用用户输入覆盖。

## 结果规则

- 使用统一结果字段 `{ok, capability, status, summary, artifacts, next_actions}`。
- 图片名称与用途以 API 返回的结果标签为准，不预先承诺白底图、场景图或某个固定排序。
- 面向用户不展示接口字段、命令、任务 ID、原始状态码或请求响应。
- 部分失败时先展示成功结果，并只重试失败或用户点名的图片。
- 下载上报、结果展示与用户保存是相互分离的动作。生成完成后先上报，再返回每张图片的 `url`；用户明确保存前 `local_path` 保持为空。
- 服务端返回的 ZIP 地址不用于逐张展示；Agent 必须使用每张图片的 `artifacts[].url` 在最终回复中逐张输出 `![标签](URL)`，且不得放进 Markdown 表格、代码块或交给 `present_files`。用户明确保存时才将结果写入下载目录。
- 轮询超时或结果暂不可读时继续 `resume`；用户保存时发生本地异常只重试工作流 `download` 动作，不得重新投递生成任务或提示退款。
- 只有服务端明确返回失败图片时才展示 `refund_hint`，不泄露内部错误详情。
