# 用户画像与人群洞察 · 画像就绪度评分细则（persona-scorecard.md）

> 适用 skill：`lingyi-user-persona-and-crowd-insight`
> 作用：把"按 1–5 分打分"从主观感觉变成**可复现、可解释、跨模型一致**的判定。**评分前必须先读本文件**，保证不同画像方案之间口径统一。

## 目录

- 0. 怎么用这份细则
- 1. 六维画像成熟度锚点（1.1–1.6，每维度 1–5 分）
- 2. 就绪度分段
- 3. 应用优先级 P0 / P1 / P2 判定
- 4. 评分示例（可复现口径）

## 0. 怎么用这份细则

1. 对每个维度，先从用户材料里找到**可观测证据**（数据源、标签、分群、画像、应用、治理机制），没有证据就标"依据不足"。
2. 对照该维度 1–5 的锚点描述，先定到某一档，再在该档内微调。
3. 必须写出**评分依据**：引用具体材料 / 数据 / 现象，禁止只写"较弱""一般""较好"等模糊词。
4. 缺数据时按"就低不就高、必须标注"处理：证据只能支撑到 N 分，就打 N 分，并在依据里写"暂估，需补充 XX 数据验证"。
5. 分数只是辅助，最终要落到分群/标签/画像/应用的项目事项。

## 1. 六维画像成熟度锚点（每维度 1–5 分）

### 1.1 数据基础（有没有数据，能否打通）

| 分 | 锚点（满足即定档） |
|---:|---|
| 1 | 只有零散数据，各端身份未打通，无统一 ID。 |
| 2 | 有部分行为/交易数据，但分散在各系统，身份匹配率低。 |
| 3 | 主要数据源已接入，部分打通（如交易+行为），但仍有断点或字段不全。 |
| 4 | 行为/交易/属性/偏好多源打通，有统一 ID（OneID），数据字典清晰。 |
| 5 | 全域数据实时打通，身份匹配率高，外部/三方数据可按需引入，数据质量有监控。 |

### 1.2 标签体系（有没有分层标签，命名/口径是否统一）

| 分 | 锚点 |
|---:|---|
| 1 | 无标签，或仅有人口统计硬字段。 |
| 2 | 有零散标签，无分层、无命名规则、口径不一。 |
| 3 | 有分层标签（基础/行为/交易等），但覆盖不全、无治理。 |
| 4 | 标准六类标签（基础属性/行为/消费价值/生命周期/渠道来源/预测）基本齐备，有命名规则与口径，标签库可查。 |
| 5 | 标准六类标签齐全 + 治理（有效期/衰减/质量校验），标签可被业务自助取用。 |

### 1.3 分群建模（有没有 RFM/聚类模型）

| 分 | 锚点 |
|---:|---|
| 1 | 无分群，人群靠拍脑袋。 |
| 2 | 有简单分层（如新/老、高/低），但口径不固定、不更新。 |
| 3 | 有 RFM 或单一模型，但分群少、未按场景细分。 |
| 4 | 有 RFM + 行为/价值多模型，分群含量化规则与规模，按场景可组合。 |
| 5 | 分群模型持续迭代，有人群包管理与效果回收，模型可对比可下钻。 |

### 1.4 画像刻画（有没有鲜活的 persona）

| 分 | 锚点 |
|---:|---|
| 1 | 无画像，或只有人口统计罗列。 |
| 2 | 有粗略人群描述，但无需求/痛点/触点，业务难用。 |
| 3 | 有 2-3 个画像，但偏静态、不关联分群、不更新。 |
| 4 | 有 3-5 个鲜活 persona，含需求/痛点/触点/价值，关联分群。 |
| 5 | persona 由数据驱动刻画并持续校准，可按业务场景派生，被多团队复用。 |

### 1.5 应用落地（画像有没有被业务用）

| 分 | 锚点 |
|---:|---|
| 1 | 画像无人用，运营仍靠经验。 |
| 2 | 偶尔用于一次性营销，无常态化场景。 |
| 3 | 用于 1-2 个场景（如营销），但未对接推荐/内容/产品。 |
| 4 | 画像接入营销/推荐/内容/产品多场景，有应用指标。 |
| 5 | 画像驱动决策闭环，应用效果可衡量、可归因、可优化。 |

### 1.6 治理迭代（标签/画像有没有更新与质量校验）

| 分 | 锚点 |
|---:|---|
| 1 | 无治理，标签/画像一次性产出后不动。 |
| 2 | 偶尔更新，无质量校验、无衰减。 |
| 3 | 有更新节奏，但无标签有效期、无质量监控。 |
| 4 | 有标签有效期/衰减/质量校验，画像定期刷新。 |
| 5 | 治理自动化：标签质量监控、失效自动衰减、画像随业务迭代，有运营 SOP。 |

## 2. 就绪度分段

整体分数 = 六个维度分数的**简单平均**，保留 1 位小数。

| 平均分 | 阶段 | 一句话定性 |
|---:|---|---|
| 1.0–1.9 | 起步期 | 有零散数据，但未打通、无标签、无分群，人群靠经验。 |
| 2.0–2.9 | 成长期 | 已有部分标签/分群，但覆盖不全、应用不深、无治理。 |
| 3.0–3.9 | 成熟期 | 六类标签齐、分群有模型、画像鲜活、接入多场景，待治理提效。 |
| 4.0–5.0 | 卓越期 | 数据全域打通、标签治理、画像数据驱动、应用闭环、持续迭代。 |

## 3. 应用优先级 P0 / P1 / P2 判定

按"影响 × 紧急 × 依赖就绪度"三因子判定，三选一。

| 优先级 | 判定条件（满足任一即归此档） |
|:---:|---|
| **P0** | 阻塞后续画像建设（如数据未打通、无标签、无分群）；或直接决定核心场景效果（精准营销/推荐）；1–2 周内可启动且依赖极少。 |
| **P1** | 对画像刻画/应用有显著提升，但依赖 P0 先落地；或需 1–2 个月协调资源（标签平台/算法）。 |
| **P2** | 长期能力建设（标签治理、画像迭代 SOP、自动化），3–6 个月推进。 |

典型落位：**数据基础/标签体系/分群建模** 多为 P0（阻塞项）；**画像刻画/应用落地** 多为 P1（依赖前者）；**治理迭代** 多为 P2（长期）。

> **取舍原则**：项目事项 ≥4 个时，不能全部是 P0——至少把一项次要事项显式降级到 P1/P2。低就绪度业务本就可能有多项合理 P0（打通/标签/分群同时缺），关键不是"P0 有几个"，而是"是否至少对一项次要事项做了显式降级"。

## 4. 评分示例（说明"可复现"的口径）

材料："三端身份未打通、无统一标签、人群靠拍脑袋；有商城订单和部分行为埋点；刚做完生命周期六阶段分层；目标是精准营销和推荐优化。"

- 数据基础 → **2 分**：有部分行为/交易数据（≥2），但"三端身份未打通"匹配 2 分锚点，无统一 ID 不升到 3。依据：三端未打通（材料）。
- 标签体系 → **1 分**：无统一标签、无分层，匹配 1 分。依据：无标签（材料）。
- 分群建模 → **1 分**：人群靠拍脑袋、无分群，匹配 1 分。依据：靠拍脑袋（材料）。
- 画像刻画 → **2 分**：有生命周期分层但无 persona，偏 2 分。依据：仅有分层无画像（材料）。
- 应用落地 → **1 分**：画像无人用、运营靠经验，匹配 1 分。依据：靠经验（材料）。
- 治理迭代 → **2 分**：无治理但有生命周期更新意识，暂估 2 分，需补充验证。

整体均分 ≈ 1.5 → 起步期。同样材料，不同诊断者按本细则应得到接近的分数——这就是"可复现"的目标。
