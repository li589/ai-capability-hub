# 用户画像与人群洞察 · 标签体系规则（tagging-rules.md）

> 适用 skill：`lingyi-user-persona-and-crowd-insight`
> 作用：消除"标签怎么分、怎么命名、口径是什么"的歧义。设计标签体系时按本文件的**双轴分类 + 命名规则 + 口径/数据源 + 治理**执行。**对标 CDP/神策/袋鼠云等行业 SOP**。

## 使用约定

- 标签**双轴分类**：① 按计算方式（事实/规则/预测，CDP 经典分层）② 按业务域（基础属性/行为/消费价值/生命周期/渠道来源/预测）。两轴正交，每个标签同时属于一个计算方式 + 一个业务域。
- 标签**分层不堆砌**：按业务域组织，每类有口径与数据源。
- 标签**可量化/可计算**：写清取值口径（公式/规则/数据源）。
- 标签**有治理**：有效期、衰减、质量校验、上下限。
- **从应用场景反推**（神策原则）：标签优先级由应用场景与商业目的决定，不是先堆标签再找用途。
- 缺数据时给"建议口径 + 待补"，不臆造标签值。

## 一、轴 ①：按计算方式分层（CDP 经典三分）

每个标签按"怎么算出来"归入三类之一，对应数据从原始到智能的层级：

| 计算方式 | 又称 | 含义 | 典型 | 数据层级 |
|---|---|---|---|---|
| **事实标签** | 统计类 | 基于原始数据**直接统计**得出 | 注册时间、购买次数、累计消费、近 90 天活跃天数 | 原始数据 → 事实标签 |
| **规则标签** | 模型类 | 基于业务**规则定义**生成 | RFM 分层、会员等级、生命周期阶段、高价值标记 | 事实标签 → 规则标签 |
| **预测标签** | 算法类 | 基于算法**模型预测**生成 | 流失倾向、购买意向、升级潜力、价格敏感度 | 规则标签 → 预测标签 |

> 数据层级：**原始数据 → 事实标签 → 规则标签 → 预测标签**，越往后越智能、越依赖前层、建设成本越高。低就绪度业务先做事实+规则，预测类标"待补"。

## 二、轴 ②：按业务域分类（标准六类）

| 标签层(业务域) | 用途 | 典型标签 | 数据源 | 计算方式（轴①示例） |
|---|---|---|---|---|
| **基础属性** | 人口统计刻画 | 性别/年龄段/城市/设备/会员龄 | 注册/授权/设备 | 多为事实 |
| **行为** | 行为偏好刻画 | 浏览高频/互动活跃/内容偏好/活跃时段 | 埋点 | 事实为主，偏好可规则 |
| **消费价值** | 价值与复购刻画 | 客单带/复购频次/品类偏好/RFM 分层/CLV 段 | 订单 | 事实(金额频次)+规则(RFM)+预测(CLV) |
| **生命周期** | 阶段刻画 | 新客/活跃/潜力/高价值/沉睡/流失 | 行为+交易（可用用户已有分层口径） | 规则 |
| **渠道来源** | 来源与触点刻画 | 首次来源渠道/偏好渠道/线上线下偏好 | 来源埋点+交易 | 事实+规则 |
| **预测** | 意向/风险预测 | 购买意向/流失倾向/升级潜力/价格敏感度 | 模型分 | 预测 |

> 设计 tag_system.layers 时**六类业务域中至少覆盖 4 类**（schema 硬门）；价值/预测类是高阶，数据不足时先做基础/行为/消费价值/生命周期四类，预测标"待补"。

## 三、命名规则

统一命名：`<业务域>_<对象>_<取值>`（可附计算方式），便于检索防重复。

- 示例：`行为_浏览_高频`、`消费价值_RFM_高`、`生命周期_阶段_沉睡`、`预测_流失_高倾向`、`渠道来源_偏好_线下`。
- 取值用**枚举或区间**，不用自由文本（防"高频""比较高"口径漂移）。
- 同义标签合并：`浏览多` 与 `浏览高频` 统一为一个并写明口径。

## 四、画像建模（RFM + K-means 组合范式）

分群 = 一组标签的量化组合。行业标准范式（观远/腾讯云）：

1. **RFM 提特征**：算每个用户的 R/F/M（事实标签）。
2. **K-means 聚类**：对 RFM（归一化后）做 K-means；用**手肘法/轮廓系数**定 K。
3. **八分图打标**：各簇 RFM 均值 vs 总体均值，打"重要价值/重要保持/重要发展/重要挽留/一般价值/..."等价值标签（规则标签）。
4. **LTV 融入**：LTV 作各簇**评估指标**，或扩展为 **RFM-LTV** 第四维，兼顾历史行为与未来价值。

方法对比（选型用）：

| 维度 | RFM（规则） | K-means（聚类） |
|---|---|---|
| 分群依据 | 预设阈值业务规则 | 数据分布自动聚类 |
| 可解释性 | 高，业务直观 | 较低，需事后解释 |
| 灵活性 | 固定三维 | 可扩展多维 |
| 适用 | 客户成熟、规则明确 | 探索性、复杂行为画像 |

> 高客单/订阅可加**决策路径/续费周期**维度；内容类可用**行为聚类+内容偏好(LDA)**。segments.rule 必须含量化标记（schema 硬门）。

## 五、口径要点 / 常见陷阱

1. **时间窗必须显式**：标签带时间窗（近 30/90/180 天），不写"近期活跃"。
2. **分子分母对齐**：偏好类标签分母用同期同人群，不是全量。
3. **行为口径锁定**："活跃"先锁定定义（登录/浏览/下单/互动），固定不混用。
4. **交易去重**：订单标签剔除退款/异常大单；客单用有效订单。
5. **预测标签不臆造**：给口径与验证要求（正负样本、离线 AUC/召回、上线 AB），不输出模型代码或承诺指标。
6. **身份去重前提**：未做 OneID 时，规模/占比标签声明去重前提。

## 六、标签治理（防标签爆炸）

| 治理项 | 规则 |
|---|---|
| 有效期 | 行为/偏好类带有效期（如 90 天滚动），过期失效或降权。 |
| 衰减 | 长期未更新标签降权；价值/预测类按周期重算。 |
| 质量校验 | 覆盖率/填充率/分布监控；过低标签下线或补数据。 |
| 上下限 | 同对象同类标签数量有上限；新标签评审入库。 |
| 合规 | PII 类最小化采集、授权使用、脱敏存储；高敏行业以合规审核为准。 |

## 七、从标签到分群/画像（Profile + Persona）

- **Profile 侧**（全量、可圈选）：标签（原料）→ 分群（组合）→ 人群包（应用）。给系统/算法用。
- **Persona 侧**（代表性、定性）：分群 + 鲜活需求/痛点/触点 → 3-5 个 persona 卡。给团队/产品用。
- 顺序：先 Profile（标签→分群）再 Persona（基于分群刻画代表人物）→ 再应用（场景）。
