# 错误处理参考

执行购物动作出错时的排查指引。先判断错误类型，再按对应处理方式应对，必要时把简明原因和排查方向告诉用户，不要把原始报错堆给用户。

## 如何判断出错

- **CLI**：`status_code` 非 200，或业务数据 `messages[]` 中含 `type=error`
- **MCP**：工具调用返回 error，或业务数据含错误消息

排查时记下 `headers.X-Trace-Id`（TraceId），它能帮服务方定位问题。

---

## 常见错误对照

| HTTP / 错误码 | 含义 | 最可能的原因 | 处理方式 |
|---------------|------|--------------|----------|
| **401** Unauthorized | 鉴权失败 | 买家身份未绑定，或 session 过期 | 尝试 `utp link` 绑定身份后重试；session 过期则重新 discover |
| **403** Forbidden | 无权限 | 身份已鉴权但无权访问该资源 | 确认买家身份是否已 `link`；提示用户可能需要联系服务方开通权限 |
| **404** Not Found | 资源不存在 | host 地址错误，或商品/checkout id 失效 | 核对 host URL；id 失效则重新搜索/查询 |
| **500** Server Error | 服务端异常 | 服务方内部错误 | 提示用户稍后重试；附上 TraceId |
| session 不存在/过期 | 会话失效 | session 未建立或已过期 | 重新 discover 建立 session |
| `OFFER_IS_CHANGED` | 商品规格变更 | offer 已更新 | 建议重新搜索获取最新规格 |
| `ILLEGAL_OFFER` | 商品不可交易 | 商品不支持交易 | 建议用户联系卖家 |

---

## 401 专项排查

收到 **401**，通常是买家身份未绑定或 session 过期。

1. **MCP 模式**：下单/加购卡片会自动弹出扫码登录浮层（二维码 + 浏览器登录），用户在卡内完成后自动继续；用户主动要登录时调 `utp_login` 打开独立登录卡。无需去终端。

2. **CLI/兜底模式**：卡片环境不可用时，用 `utp link` 绑定买家身份，绑定后重试。

3. 确认 session 有效：重新执行 `utp discover <host>` 建立 session 后重试。

4. 若仍 401，可能是服务端鉴权配置问题。提示用户联系服务方（附上 TraceId）。

---

## 通用原则

- **不要把 401 当临时故障盲目重试**——鉴权类错误重试通常无效，先排查身份绑定和 session。
- 与鉴权无关的瞬时错误（500、网络超时）可提示用户稍后重试。
- 始终向用户说明**发生了什么**和**下一步怎么办**，并在涉及服务方排查时附上 TraceId。
