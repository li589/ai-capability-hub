# PatSeek 专利检索

## 核心原则

1. 先确定任务类型，再选择流程；不得用可专利性查新替代 FTO。
2. 把 PatSeek 作为专利文献召回工具，不把相似度、命中数或模型结论直接当作法律结论。
3. 报告所有数据库、市场、检索式、日期、限制和未覆盖来源，保证可复核。
4. 对未公开技术先提示保密：完整方案会发送到 PatSeek；使用 `--no-call-log` 可禁用本地调用统计，缓存仍可能保存 API 响应。
5. 费用以 API 返回的 `credits_charged` 为准，不用文档估算替代实际返回。
6. **API Key 失效时（401/402/403）必须停止检索并询问用户**，禁止自行转向 Google 或其他互联网引擎检索专利。引导用户到 **https://patseek.cn** 更新 Key 或充值积分。详见"API Key 失效处理协议"。

## 检索模式选择（必做）

确定任务类型后、开始任何付费检索前，**必须向用户呈现检索深度选项**；不得跳过分步直接按标准流程运行，也不得默认走快速模式。与"方案拆解"合并为一次确认，输出：

```
本次检索范围：[技术对象 × 核心机制 × 关键区别特征；库=cn/world；法域=...]
请选择检索深度：
  1. 快速摸底 —— 约 3-5 次 Bool + 详情 ≤2，3-6 分钟，4-7 积分
     适用：交底前摸底、初步筛查、时间紧、非正式了解
     产出：初步印象 + 候选列表 + 深入检索建议（不构成新颖性/创造性结论）
  2. 完整深度 —— 约 8-10 次 Bool + 详情核对 + 语义先行 1 次（+补漏 0-2 按需），15-35 分钟，15-20 积分
     适用：正式查新报告、申请前决策（方向已明确，想一次到位）
     产出：饱和检索 + 分层 X/Y 证据 + 可复核报告
```

**怎么选**：
- **方向已明**、要一次到位 → **完整深度**：少一次交互、更快
- **时间紧/想先摸底** → **快速摸底**：跑完会给出「深入检索建议」（未覆盖项+值得深入的方向+成本提示），由你决定是否继续
- 快速摸底只出初步印象（3-5 次 Bool），不构成新颖性/创造性结论

**边界（不提供快速选项）**：FTO/侵权、无效检索、正式申请决策 → 不提供"快速摸底"，直接走完整深度流程，并告知用户原因。

**默认规则**：用户未明确选择时默认完整流程；但必须已呈现选择，不能跳过分步。

**不触发场景**：简单直接检索（已知公开号/申请号、单一申请人盘点）、宏观态势统计；同一任务的后续轮次不重复询问。

### 语义先行（完整深度 · 用户已给详细方案时必做）

用户已提供完整方案描述（对象×机制×区别特征齐全）且选择**完整深度**时，进入 Bool 检索前**先执行 1 次语义检索**（+5 积分）：

1. 执行：`semantic "方案描述（去标识化）"` → 取结果集前 20 + **IPC 分布摘要**；
2. 用途：
   - **IPC 分布确认分类方向**——可纠正 Bool 预检的方向偏差（实测：固态电池热管理语义直接给 H01M 10/613/659/6568，Bool 预检却指向化学类 10/0525）；
   - **关键词扩展**——提取真实术语/同义词（如"角度可偏移""浮动块"），纳入 Bool 检索式；
   - **新候选人发现**——语义与 Bool 召回互补（实测互相漏掉对方 H 级），语义候选并入候选池；
3. 边界：
   - **不可只信 top-1**：新兴领域 top-1 可能是噪声（实测低空管控 top-1 为课桌 sim=10%），一律以整体结果集与 IPC 分布为准；
   - **不可替代 Bool**：语义先行后仍须跑完整 Bool 流程；
   - 语义相似度普遍偏低或 top-1 明显不相关（新兴领域）时，以 Bool 关键词为主，语义仅作 IPC 参考；
4. **快速摸底不做语义**（保持 3-5 Bool、4-7 积分）；简单直接检索/宏观统计不做。

## 运行与保密

使用当前 Skill 目录中的脚本：

```bash
python3 <skill-dir>/scripts/patseek_client.py --help
```

通过环境变量传 Key，避免把 Key 写进命令历史：

```bash
export PATSEEK_API_KEY=ps_你的Key
```

> **还没有 API Key？** 访问 **https://patseek.cn** 注册/登录 →「个人中心 → API Key 管理」→ 创建新 Key。Key 过期或积分不足时也到该网站更新或充值。

保密选项：

```bash
# 不写本地调用统计日志；公共参数可写在子命令之前或之后
python3 <skill-dir>/scripts/patseek_client.py bool "检索式" --no-call-log

# 完全禁用调用统计
export PATSEEK_DISABLE_CALL_LOG=1
```

脚本的调用日志只保存 Key 指纹、技术词摘要、页码和积分，不保存查询原文。结果缓存默认位于 `~/.cache/patseek/`；高度敏感任务结束后提醒用户自行清理缓存。不要在报告、终端输出或日志中回显 API Key。

## API Key 失效处理协议

当 API 调用返回 401（Key 缺失/无效）、402（积分不足）或 403（Key 已禁用）时，**必须立即停止检索流程，向用户报告并等待用户选择**，不得自行决定替代方案。

### 禁止行为

- **禁止**在 API Key 失效后自行转向 Google Patents、Espacenet、WIPO Patentscope 等互联网专利检索引擎
- **禁止**将互联网检索结果当作 PatSeek 检索结果直接写入报告，不标注数据来源差异
- **禁止**静默跳过专利检索步骤，只在报告中标注"未检索"
- **禁止**在未告知用户的情况下，用通用网页搜索替代专业专利数据库检索

PatSeek 与互联网引擎在数据覆盖、字段结构、检索精度和法律可复核性上存在实质差异。自行替换会导致检索质量下降、结论不可复核，严重影响 FTO、查新等任务的可靠性。

### 必须执行的流程

检测到 401/402/403 错误后，向用户输出以下信息并等待选择：

```
PatSeek API 调用失败：[错误码] [错误说明]

可能原因：
- 401：API Key 缺失、格式错误或已过期
- 402：积分余额不足
- 403：API Key 已被禁用

请选择如何继续：
1. 更新 API Key — 访问 https://patseek.cn 登录后，在「个人中心 → API Key 管理」
   创建或查看 Key，然后告诉我新的 Key（我会更新环境变量并重试检索）
2. 使用互联网引擎检索 — 我将改用 Google Patents / Espacenet 等公开来源，
   但数据完整性、字段结构和可复核性可能不如 PatSeek，报告会显著标注数据来源差异
3. 暂停任务 — 先处理 Key 问题，稍后再继续

请回复 1 / 2 / 3 或告诉我你的选择。
```

### 用户选择后的处理

| 用户选择 | 执行动作 |
|---|---|
| 1. 更新 Key | 引导用户到 https://patseek.cn 获取新 Key；用户提供后更新 `PATSEEK_API_KEY` 环境变量并重试原检索；重试仍失败时再次询问 |
| 2. 互联网引擎 | 明确告知用户互联网检索的局限性（引文表可能缺失、法律状态不可靠、字段不完整等）；在报告显著位置标注"因 PatSeek API 不可用，改用互联网公开来源，可复核性降低"；不得将互联网结果伪装为 PatSeek 结果 |
| 3. 暂停 | 保留已完成的部分结果，记录中断原因和待恢复的检索步骤 |

### 缓存命中不算失效

若 API Key 失效但本地缓存仍有有效结果（Bool 15 分钟、详情 12 小时、语义 60 分钟内），可使用缓存结果并标注"来自缓存，未实时验证"。但不得用缓存结果替代需要新检索的任务，也不得隐瞒 Key 已失效的事实——仍须告知用户 Key 状态并询问是否更新。

### 预防性检查

对长会话或多轮检索任务，首次调用前建议先执行 `key-info` 命令确认 Key 状态：

```bash
python3 <skill-dir>/scripts/patseek_client.py key-info
```

若返回 `active: false`、`expires_at` 已过或即将过期，提前告知用户并询问是否更新，避免检索中途失败。

## 执行前检查

| 检查项 | 必须确认的内容 |
|---|---|
| 任务 | 可专利性、FTO、调研或直接检索 |
| 使用者与决策 | 企业管理/市场/IP/研发、发明人、技术经理或高校团队；报告要支持什么决定 |
| 对象 | 产品/方法、必要技术特征、部件关系、参数和效果 |
| 日期 | 可专利性：目标申请日及最早优先权日；FTO：计划实施时间；技术调研：分析时间范围与数据截止日 |
| 地域 | CN 或 world；FTO 必须列明具体实施国家，`WO/EP` 不能直接代表可执行国家权利。涉及非中国专利时**必须先读** `references/world_search_reference.md` |
| 文献 | 专利文献是否足够；是否需要论文、标准、手册、网页或官方登记簿 |
| 保密 | 是否包含未申请的关键参数、配方、源代码或商业秘密 |
| 检索模式 | 已向用户呈现 快速摸底/完整深度 选择并确认（FTO/无效/正式决策除外） |

制药/化学/生物、通信标准或高校成果转化任务还必须读取`references/special_domain_gates.md`，执行结构/序列、参数、标准必要性和商业化边界检查。

## 关键词与分类构造

读取 `references/keyword_expansion.md`。对每个概念标注术语关系，禁止把相关概念伪装成同义词：

| 关系 | 用法 |
|---|---|
| 严格同义、缩写、拼写/旧称 | 可放入同一 OR 组 |
| 上位/下位概念 | 分别组成宽检索和窄检索，不默认混入同一组 |
| 功能、结构、应用、效果相关 | 作为独立 AND 块或补充检索切角 |
| 多语言术语 | 按目标库生成并回译核对；分类号作为跨语言补充 |

不要使用固定"最多8词"或未定义的"语义距离"。扩展多少由概念边界、结果抽样和验证集表现决定。记录每个扩展词的关系与来源。

**申请人检索注意**：企业/机构检索必须优先使用**全称**（如 `AP=(华为技术有限公司)`），简称（如 `AP=(华为)`）会产生大量个人申请人噪声（"张华为"等）。技术调研时优先用"全称+IPC"组合，精度最高。详见 `references/technology_research_workflow.md`"申请人检索策略"。

IPC 不一律截断到4位：先用准确下位组查准，再用上位组补召回。CN实测格式为子类与主组之间保留空格，如 `H01M 10/0525`；客户端会自动修复常见紧凑写法。复合检索前先单独预检IPC；若为0条，先修复格式或回退上位组，不得把错误分类与关键词叠加后的0条解释为无现有技术。不同市场需分别验证。完整语法见 `references/query_syntax.md`。

## 试验性检索策略

撰写报告或开始系统检索前，建议先做 1-2 次**试验性检索**掌握整体情况，再逐步使用精确检索式。适当增加 Bool 检索次数是正常的——一次完整查新或无效检索通常需要 **8-10 次 Bool 检索**（分 2-3 轮，每轮之间须执行"轮次引导"用户校准）。

### 试验性检索的目的

1. **确认术语有效性**：验证关键词在目标库中是否有命中，避免正式检索时因术语错误浪费时间
2. **评估结果规模**：了解宽检索的命中量，判断是否需要 IPC/CC/日期限定
3. **发现术语变体**：从试验性检索的前排结果中提取真实术语、IPC 分类和申请人名称
4. **确认申请人名称格式**：企业/机构检索前，先用简称试检索核对 `applicant` 字段的完整格式

### 推荐流程（完整深度：Bool 预算 8-10 次，分 2-3 轮）

```
第 1 轮（2-3 次 Bool）：
  → 试验性/QX 一式（对象×机制×关键特征，兼作术语与规模校准）
  → IPC 预检 1 次（按需；若已做语义先行，以其 IPC 分布为预检方向，避免方向偏差）
  → QY-Base 一式（对象×机制×技术问题/效果）
  → 抽样前 10 标 H/M/N/D，识别噪声与 H 级候选
  → 交给用户校准（见"轮次引导"）

第 2 轮（2-4 次 Bool，按第 1 轮结果与用户调整点构造）：
  → QY-Comp 一式（Y-Base 存在缺失区别特征时必做）
  → 收窄/扩展（按噪声收窄，按新术语/分类扩展）
  → 加 PD<关键日 / CC / 日期限定；CN + World 分库
  → 抽样核对，交给用户校准

第 3 轮（0-3 次 Bool，按需）：
  → 补充切角/多语言/换库验证，或针对残余缺失特征
  → 连续两轮无新线索即中止（预算内跑不满不算失败）

语义补漏（0-2 次，按需；计入积分，不计入 Bool 预算）：
  → 仅 Bool 多轮无 X 时启动，围绕不同技术问题
```

试验性检索的命中结果不直接进入候选池，但用于校准后续正式检索的术语和限定条件。

## 轮次引导（用户校准，完整深度必做）

完整深度分 2-3 轮执行；**每轮检索结束、抽样标注 H/M/N/D 后，必须向用户呈现结果并等待选择**，不得连续自行跑完所有预算：

```
本轮结果：H 级候选 N 篇（列出公开号）/ 主要噪声类型 / 新术语·新 IPC·新申请人线索
下一步：
  A. 调整检索重点 —— 换特征组合/换切角/收窄法域/改日期/换库或语言（用户给出重点，或确认我方建议）
  B. 继续当前方向 —— 进入下一轮（预算内）
  C. 提前收尾 —— 已满足决策需要，生成报告
```

- **下一轮按用户的调整点构造新检索式**，不得机械重复上一轮相同式；
- **预算**：完整深度 Bool 总预算 **8-10 次**；用户明确要求追加时，报告标注"超出预算 X 次"；
- 中止条件仍以"连续两轮/两页不再出现新关键分类、申请人、特征或引证线索"为准（见"候选池与证据核对"），预算内跑不满不算失败。

## 快速查新模式（由"检索模式选择"触发）

用户经"检索模式选择"选择**快速摸底**，或明确要求快速结果时，走**快速查新分支**，不执行完整流程。快速模式已包含试验性检索和 IPC 预检，不需要先跑"试验性检索策略"的完整 5 步。**未选择快速时默认完整流程**；任务将用于正式申请决策时仍必须走完整流程。

### 适用场景与禁止场景

| 场景 | 是否可用快速模式 |
|---|---|
| 交底前摸底、初步筛查、非正式了解 | ✅ 可用 |
| 时间紧迫且用户明确要求"先快速看看" | ✅ 可用 |
| 正式查新报告、申请前决策依据 | ❌ 必须完整流程 |
| 涉及 FTO/侵权结论 | ❌ 必须完整流程（FTO 见 `fto_workflow.md`） |

### 最小检索集（约 3-5 次 Bool，3-6 分钟）

快速模式固定执行以下步骤，**不跑语义、不执行 QY-Comp、不做扩展轮**（可按需做 1 次收窄/换切角）：

1. **QX 一式**（含试验性校准）：对象×机制×1-2 个高区分特征（加 `PD<关键日` 或 `CC=` 限定）；前排结果同时用于校准术语与规模，不再单列试验性检索；
2. **IPC 预检 1 次（按需 0-1）**：需用 IPC 限定时才单独验证（格式见"关键词与分类构造"），0 条先修格式；
3. **QY-Base 一式**：对象×机制×技术问题/效果；
4. **收窄/换切角 0-1 次（按需）**：QX/QY 噪声明显时，从 H/M 文献提取新术语换一个切角重检；
5. **详情核对 ≤2 篇**：只核对 H/M 前排候选。

每式仍须满足"Bool 检索式质量闸门"的三块结构；抽样前 10 标 H/M/N/D 并记录。

### 结论降级（强制）

快速模式**只输出"初步印象 + 候选列表"**，必须明确标注：

- "本结果来自快速查新模式，未做饱和检索，**不构成新颖性/创造性结论**"；
- 未覆盖项照常列出（仅按需收窄/换切角 0-1 次，未做扩展轮、未做语义补漏、未做 QY-Comp）；
- 候选列表中的每篇专利仍须提供附图与快速链接（见"重点专利的附图展示"与"专利快速链接"）。

禁止将快速模式结果套用完整流程的三种结论口径（如"发现可能破坏新颖性的文献"或"未发现单篇文献公开全部必要特征"）。快速模式的输出是**筛查结果**，不是法律结论。

### 深入检索建议（快速摸底收尾必给）

快速模式输出初步印象 + 候选列表后，**必须附"深入检索建议"**，供用户决定是否继续，但**不自动转入**深度检索：

- **指出未覆盖项**：未做扩展轮/语义补漏/QY-Comp、world 英文未覆盖切角等；
- **建议最值得深入的方向**：如已验证 IPC 收窄、参数专项、补 world 英文、语义补漏，或对 H/M 候选做全文比对；
- **提示成本**：转入完整深度约 +8-10 次 Bool、约 10-15 积分（快速轮已跑检索式可复用）；
- 由用户决定是否继续；若继续，进入完整深度流程（含轮次引导），快速轮的候选集/已验证 IPC 作为起点。

### 升级触发（硬约束）

快速模式中只要出现以下任一情况，**必须停止快速模式并转入完整流程**：

- 发现任何 H 级候选（覆盖≥70% 必要特征或命中核心关系）；
- 用户后续表示结果将用于正式决策。

**命中过宽的缓冲（不立即升级）**：QX/QY-Base 任一式命中 ≥5,000 条或触达 10,000 上限时，**先执行 1 次收窄/换切角**（用已验证 IPC、日期、CC= 或申请人限定；或从 H/M 前排提取新术语换切角），收窄后仍 ≥5,000 条/触达上限、或收窄后前排无质量提升，才升级到完整流程。该收窄即最小检索集第 4 步，不额外增加预算。

## Bool 检索式质量闸门

除专利号精确查询、单一申请人盘点或用户明确要求的宏观态势统计外，**不得只用技术对象+宽泛功能词执行 Bool 检索**。技术检索式通常必须包含三个相互独立的 AND 块：

1. **技术对象**：产品、部件、材料或方法场景；
2. **核心机制/技术问题**：方案如何工作或具体解决什么问题；
3. **关键区别特征**：结构关系、步骤关系、控制逻辑、特定部件、参数范围或特殊技术效果中的至少一项。

信息不足以构造三个块时，使用两个高置信概念块并增加已验证的准确 IPC 或关系词组，不要用“系统、装置、方法、设备、处理、控制”等通用词凑数。CN普通关键词不保证短语匹配，中文可能按单字分析；引号不能替代结果抽样和详情核对。优先加入能排除同领域噪声的特征，顺序通常为：**关键关系/机制 > 特定结构或步骤 > 参数 > 特殊效果 > 通用场景词**。

执行前用下表自检：

| 项目 | 通过标准 |
|---|---|
| 独立概念块 | 通常≥3；每块表达不同技术维度 |
| 关键特征 | 至少1个，不得全部是上位或通用词 |
| OR扩展 | 只扩展块内同一概念，不把不同特征用OR混成一个块 |
| 精确限定 | 至少考虑一个关系短语、下位IPC、参数、日期或申请人条件 |
| 可解释性 | 能说明新增特征将排除哪类噪声 |

命中后执行强制收窄规则：

| 命中数 | 动作 |
|---:|---|
| 0-20 | 检查是否过窄；保留用于高精度块，并用其他块补召回 |
| 21-500 | 适合逐篇或分批核对 |
| 501-4,999 | 抽样5-10篇；噪声较多时增加一个关键区别特征后重检 |
| ≥5,000 | 判定为过宽，不得直接进入候选池；必须增加关键特征、已验证IPC或日期后重检 |
| 10,000或显示上限 | 视为截断结果，当前命中数不可用于统计或法律分析；必须收窄 |

三块组合仍达 10000 上限时的收窄操作（按优先级）：
1. **加字段限定**：`CC=(目标国)`（world）、`AD>=年份`、已验证准确 IPC 下位组
2. **更换特征组合**：从 H/M 文献提取真实术语，换一个特征组合，而非在原式末尾继续叠加
3. **切换库/语言**：CN 切 world 英文，或 world 切 CN 中文；不同库前排结果不同
4. **分拆检索**：把宽检索拆成多个窄检索（如按 IPC 分拆、按申请人分拆），分批核对

收窄时先查看前5-10篇的噪声类型，一次性选择最有区分力的新增条件；不要机械堆叠多个低置信词。CN关键词块连续两轮仍显示上限或对象块未在前排原文出现时，不再追加中文词，改用已单独验证的IPC、关键日前公开日期、world/英文或语义召回。除宏观态势任务外，高精度块以可核对规模和前排质量为目标；显示10,000可能是计数上限，不能仅凭总量判断策略成败。

### 条件可观察性闸门

Bool请求成功或命中量下降，不证明新增AND块真正生效。每轮抽样前10篇，为每个对象、机制、区别特征及字段限定建立“条件—原文/字段证据”矩阵：

1. 只把题名、摘要、权利要求、说明书或对应结构化字段中可定位的原词、确认同义词或等价技术表达记为“可观察”；单字散落、模型联想和仅同领域不算命中该条件。
2. 任一必需条件在某篇中不可观察，该篇不得标为QX的H或FTO高覆盖候选；多篇结果不能拼成单篇覆盖。
3. 新增条件在前10中可观察率低于50%，或命中量下降但H率/H+M率未提高，判定该条件“检索约束无效”；不要继续沿同式加词，改用已验证IPC、字段过滤、英文/world、语义或另一特征组合。
4. `AP=`、`CC=`、日期和IPC等字段条件必须用返回的申请人、公开号、日期和分类字段逐篇反查。申请人统计同时要求“申请人命中”和“技术相关”两道门，不能因申请人正确就把无关专利计入竞品布局。
5. 高精度块即使命中少于5,000条，若前排必需条件可观察率或H率不合格，仍不得进入候选池或统计。反之，宏观调研的宽池必须拆成未截断分区并跨页分层抽样，不能只凭前10质量宣称可统计。

### 国际专利检索（market=world）

```bash
# 英文关键词 + 国家限定
python3 <skill-dir>/scripts/patseek_client.py bool "solid-state battery CC=(US OR EP)" --market world --page-size 20

# 申请人多语言检索（中文可命中日文申请人，英文可命中英文存储的申请人）
python3 <skill-dir>/scripts/patseek_client.py bool "AP=(丰田 OR Toyota OR トヨタ) battery" --market world --page-size 20

# IPC + 国家（world 库 IPC 用紧凑写法，如 H01M10/0525）
python3 <skill-dir>/scripts/patseek_client.py bool "IPC=(H01M) solid-state battery CC=(US OR JP)" --market world --page-size 20

# 三块组合 + 国家 + 日期
python3 <skill-dir>/scripts/patseek_client.py bool "(solid-state battery) (thermal management) (phase-change material OR cooling channel) CC=(US OR EP) AD>=2022" --market world --page-size 20

# 多语言关键词组合（中/英/日均有效）
python3 <skill-dir>/scripts/patseek_client.py bool "(固态电池 OR solid-state battery OR 全固体電池) CC=(US OR JP)" --market world --page-size 20

# 精确公开号查国际专利
python3 <skill-dir>/scripts/patseek_client.py bool "PID=(US10234567B2)" --market world --page-size 5
```

world 复合式返回 0 条时，不得直接判定无专利；必须执行四层探针（对象+CC / 机制+CC / IPC子类+CC / 准确IPC主组+CC），详见 `references/world_search_reference.md` 第 8 节。

### 语义检索

```bash
python3 <skill-dir>/scripts/patseek_client.py semantic '完整且去标识化的技术描述' --timeout 180 --no-call-log
```

语义检索面向中文技术描述（**语义先行**用法见"检索模式选择→语义先行"：完整深度且用户已给详细方案时，先做 1 次用于 IPC/术语确认）。**实测语义结果含国际公开号（US/WO/JP/EP/KR，约占 20-25%）**——"仅支持中国库"指查询须用中文描述，不表示结果仅 CN 公开号。只把它用于召回不同术语的候选，不把相似度当作新颖性、创造性或侵权判断。失败、取消或超时必须报告为失败，不能解释为0条结果。

语义任务不限总次数，但默认串行提交，相邻两次提交至少间隔60秒；不要并发批量提交。每次使用不同的技术角度，并记录新增术语、分类和高覆盖候选；连续两轮无新增时停止该角度。

批量语义检索逐任务流式保存结果，不要等整批结束后一次性写出。单个任务失败或服务端超时时，记录任务ID、失败状态和已接收数量，保留此前已完成结果并继续后续独立角度；失败任务不能当作0条，也不能让整批证据丢失。需要重试时使用更窄或不同机制的描述，并继续遵守60秒提交间隔。

两个以上语义角度优先使用断点脚本。任务文件为JSON数组或JSONL，每项包含`id`和`query`；检查点不保存查询原文和Key，完整结果逐任务原子写入输出目录：

```bash
python3 <skill-dir>/scripts/semantic_batch.py semantic_tasks.json \
  --checkpoint semantic_checkpoint.jsonl --output-dir semantic_results
```

重跑相同命令会跳过已成功保存的任务；失败项会再次执行。不要把检查点或结果目录放入公开仓库，高度敏感方案仍先去标识化。

### 缓存与重复调用

- 相同查询优先命中缓存：Bool 15分钟、详情12小时、语义60分钟。
- `--no-cache` 表示明确要求最新数据，并跳过近似拦截；它仍会更新缓存。
- `--force` 只跳过近似拦截；不要用于翻页。
- 公共参数可以放在子命令前或后。

### 无效检索 Goal Loop 控制器

`scripts/invalidity_goal.py`（不调用 API、不消耗积分），用于驱动无效检索的持续循环，全部子命令的 `case_dir` 为**位置参数**：

```bash
PY=/path/to/python; G=scripts/invalidity_goal.py
$PY $G init <case_dir> --target-patent CN1234567A --critical-date 2019-06-11 ...
$PY $G enqueue  <case_dir> actions/A01_qx_cn.json     # 入队一个动作
$PY $G next     <case_dir> --limit 3 --claim          # 按优先级认领待办
$PY $G record   <case_dir> A0001 results/A0001.result.json
$PY $G checkpoint <case_dir> --note "本轮结论"         # 结算增益、给出 recommendation
$PY $G status   <case_dir>
$PY $G complete <case_dir> --reason evidence_ready|saturated --note "..."
$PY $G suggest-diversity <case_dir> [--threshold 2]   # 未覆盖特征经≥2 Bool通道→建议语义B/C骨架
$PY $G export <case_dir> [--output evidence_skeleton.json]  # 导出 evidence.json 骨架
```

要点：

- `record` 会把结果里的 `followups` 自动入队并分配新动作号，无需手工 enqueue；检测到封顶（`total>=10000` 或 `truncated`）时输出 `narrowing_suggestions` 收窄建议（不自动入队）。
- `result.json` 的 `feature_coverage_delta` 必须是**数值**（float），填字典会抛 `TypeError`。
- `result.json` 新增结构化覆盖字段：`covered_features`（本动作确证覆盖的特征 ID 列表）和 `feature_gaps`（`[{"feature_id":"F7","reason":"..."}]` 缺口记录）。`checkpoint` 据此计算 `real_coverage_delta` 并强制饱和门第 4 条件（`all_features_covered_or_gapped`）。
- `result.json` 可选填 `credits_charged`/`credits_remaining`（从 API 回包取），`record` 累加进 `state.cost`，`status` 报累计消耗。
- 动作 JSON 可选填 `features`（特征 ID 列表），`suggest-diversity` 据此判断哪些特征已尝试过哪些 Bool 通道。
- `checkpoint` 维护**两级零增益计数**：`zero_gain_cycles`（宽松，任一正增益归零）和 `zero_decisive_cycles`（严格，仅决定性证据/高覆盖/真实覆盖增量归零）。饱和门用 `zero_decisive_cycles >= 3` 且 `all_features_covered_or_gapped` 才进 `saturation_review`；仍有特征未覆盖时即使 decisive 零增益也走 `plan_new_diverse_actions`（保护多样性续作）。
- `complete --reason evidence_ready` 在门未推荐 `saturation_review` 时**必须附 `--note`** 说明覆盖理由，否则拒绝执行；事件日志记 `override_gate=true`。
- `export` 从 goal_state 自动生成 evidence.json 骨架（searches/details/gate stub），`gate.status`/`limitations`/`conclusion` 需人工填写再交 `report_guard.py` 校验。
- `checkpoint` 的 `recommendation` 取值：`continue_required_lanes` / `continue_high_value_frontier` / `saturation_review` / `continue_frontier` / `plan_new_diverse_actions`。收到 `plan_new_diverse_actions` 意味着**必须换多样性轴**（语种、库、语义视角 A/B/C、相邻领域），而不是重跑同类检索。
- 目标专利若为授权 B 号且 PatSeek 未收录，改用同族 A 公开号做 `--target-patent`。

## 候选池与证据核对

查新时先读取 `references/adaptive_xy_search.md`，再读取 `references/evaluation_and_reporting.md`。执行以下硬约束：

1. 语义分只决定是否进入候选池；最终相关度以特征覆盖、关系、日期、证据位置和任务适格性为准。
2. 优先按同族聚合；若 API 只有同族数量而无成员清单，标注"无法完成同族去重"，不得假装已经完成。
3. 不固定只看 Top 20-30。至少覆盖各检索块结果并以"连续两轮/两页不再出现新关键分类、申请人、特征或引证线索"作为可解释的初步中止条件。
4. 每个要素记录：文献原文位置、权项/段落/附图、明确或隐含披露、日期角色、可信度。
5. 对新颖性，披露在权利要求、实施例或附图中并不形成机械强弱等级；判断是否由同一适格文献公开全部必要特征。
6. 对创造性，评价权利要求整体：最接近现有技术→区别特征及技术效果→实际技术问题→是否存在技术启示；禁止只给孤立特征评级。
7. 分别执行 QX、QY-Base；QY-Comp 在 Y-Base 存在缺失区别特征时**必须执行**，无缺失时记录"Y-Base 已覆盖全部必要特征"后跳过。不能用一条越来越窄的检索链同时替代 X 与 Y 文献检索。
8. 每轮抽样前10篇并记录 H/M/N/D、H率、H+M率、X/Y新增情况；下一式必须针对已观察到的噪声或缺失特征。

### 重点专利的附图展示

报告应尽量展示**重点专利**的附图，以辅助读者理解技术方案——附图比文字描述更直观，特别是涉及部件结构、方法步骤、电路连接时。

**何时展示附图**：
- **必须展示**：X 文献/Y 文献核心候选、目标专利（查新/FTO/无效场景）、技术路线代表专利
- **建议展示**：高被引专利、典型实施例相关专利
- **不必展示**：仅作背景参考的专利、低相关候选

**展示方法**：
1. 用 `patent <id> --figures-dir <目录>` 下载附图到本地（命令用法见"附图展示"章节）
2. 报告中插入图片：`![](figures/CN217874688U/01.png)`
3. 每张附图配简短说明（什么图、对应什么技术特征、为什么引用）
4. **优先展示剖视图/结构图**（展示部件关系）和**流程图**（展示方法步骤），其次电路图

**附图来源可靠性（已实测验证）**：来源 Google Patents，US/EP/JP/KR/WO 等主要专利局均覆盖，URL 长期有效。少数专利（较老或非主要国家）可能没有附图或不完整。详见 `evaluation_and_reporting.md` 第 6 节。

**重点专利快速链接（必须）**：所有进入候选池的重点专利**必须**提供快速阅读链接（格式与写法见"专利快速链接"章节），与附图配合使用——附图展示技术方案细节，快速链接提供全文阅读入口。报告交付前逐篇核对候选池每篇文献都有链接，缺链接视为报告不完整。走 `report_guard.py` 渲染的报告，其"候选证据"表会自动生成链接列（pid → xinxin.chat），无需手工填写。

路线比较、低密度机会、申请前查新、FTO预筛或合作对象筛选形成结构化证据后，使用`scripts/decision_gates.py evidence.json`执行结论闸门。world证据还必须输入逐件`CC`前缀核验率与IPC/语言预检状态。脚本只判断证据是否足以支持相应标签，不替代专利代理人、市场或合作尽调判断。

交付Markdown报告前，用`scripts/report_guard.py evidence.json --output report.md`检查范围、检索式、样本、闸门和限制是否齐全。缺少字段、未解释的0条结果、FTO非候选筛查闸门或保证性结论会拒绝渲染；详情没有权项/段落位置时自动标为文本或字段代理，不得伪装为权项映射。

**每份检索报告须含「双导读 + 双建议」**（顺序固定为先发明人后代理人）：前置·双导读（给发明人的导读 + 给代理人的导读，放在标题信息表之后、正文之前）与结尾·双建议（给发明人的建议 + 给代理人的建议，放在报告最后）。两段共享同一组证据、不重复检索、不额外耗积分；用词少新名词、结论纪律不软化。模板、各任务类型变体与 evidence.json 字段对应见 `references/dual_summary.md`；`report_guard.py` 校验四个字段（`inventor_briefing`/`agent_briefing`/`inventor_advice`/`agent_advice`）非空，缺则拒绝渲染。

## 外部核验与限制

PatSeek 不能覆盖全部非专利公开、同族成员、审查档案和各国官方法律状态。任务需要时：

- 用可用浏览/检索工具查询官方专利登记簿、WIPO、CNIPA、EPO、USPTO 等；
- 按领域补论文、标准、产品手册、会议资料、网页和序列/化学数据库；
- **`pdf_url` 为空时，可对已知公开号尝试外源 PDF 兜底**（如 freepatentsonline：详情页解析 iframe 的 S3 签名 URL 两步下载；**实测 EP/WO 稳定可用、US 部分覆盖，CN/JP/FR/DE/GB 等不可用**（无 iframe 即判不可用）；PDF 为扫描件无文本层。操作细节见 `api_reference.md` §2）。**CN 专利**：`pdf_url` 有值即 Google Patents 直链可直接下载（实测 5/5）；空值率约 50%，且 freepatentsonline 不覆盖 CN——空值时无自动化兜底，提示用户经 Google Patents 页面/CNIPA 人工获取。外源仅用于 **PDF 文件获取**，不得替代 PatSeek 检索；
- 在报告中逐项列明"已检索/未检索/无法访问"，并提供来源链接和检索日期。

没有外部工具或权限时继续完成 PatSeek 范围内工作，但必须显著保留：“未检索非专利文献/未核验官方法律状态/未完成同族成员分析”。

## 结论纪律

禁止输出“已经具备新颖性”“不存在侵权风险”“全球无人申请”等保证性结论。使用：

> 截至[日期]，在[数据库、国家、语言和文献类型]及所列检索式范围内，未发现一篇在关键日期前公开并披露全部必要技术特征的文献。本结果不排除未公开申请、数据库缺口、非专利公开或术语差异造成的漏检。

FTO 还必须补充：

> 本次结果仅为候选权利筛查。是否影响实施须结合目标国家、计划时间、有效授权权利要求、官方法律状态及具体实施方案作专项法律分析。
