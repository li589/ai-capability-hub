# PatSeek 检索式语法详细参考

> 本文档详细说明 PatSeek Bool 检索接口（`POST /v1/search`）支持的检索式语法。
> `market=cn`（中国专利，默认）和 `market=world`（国际/外文专利）接受相同的表面语法，但底层字段映射和分析器可能不同，不能假定同式具有相同召回率或精度。另有两点功能例外：
> - `AN=` 申请号检索：`world` 库的申请号字段暂无数据，查询会返回 0 条
> - `CC=` 国家/地区代码限定：仅 `world` 库支持，`cn` 库不支持也不需要（本身即单一国家库）
>
> **国际检索（`market=world`）请优先阅读 `world_search_reference.md`**，该文件集中了 world 库的字段对照表、可直接复制的示例、零结果四层探针和申请人多语言检索等核心内容。本文件提供通用语法规则，world 库的特定行为差异在各章节中以"world 库"标注。

## 布尔运算符

| 写法 | 含义 | 示例 |
|---|---|---|
| `A B`（空格） | AND，所有词都必须出现 | `固态电池 电解质` |
| `A AND B` | 显式 AND，效果相同 | `低空空域 AND 无人机` |
| `A OR B` | 任一出现即命中 | `人工智能 OR 机器学习` |
| `(A OR B) C` | 括号控制优先级 | `(固态 OR 全固态) 电池` |

## 字段前缀

| 前缀 | 字段 | 匹配方式 |
|---|---|---|
| `AP=(...)` | 申请人 | match_phrase |
| `IPC=(...)` | IPC 分类号 | match + and |
| `PID=(...)` | 公开号 | term 精确 |
| `AN=(...)` | 申请号 | match_phrase |
| `AD` | 申请日 | range |
| `PD` | 公开日 | range |
| `NOT=(...)` | 排除 | must_not |
| `CC=(...)` | 国家/地区代码（仅 world 库） | prefix |

前缀支持 `=` 和 `:` 两种写法，如 `AP=(华为)` 等同于 `AP:(华为)`。

## 各字段详细用法

### 申请人 AP=

```
AP=(华为技术有限公司)               # 全称（推荐，精度最高）
AP=(华为)                          # 简称（⚠️ 有噪声，见下方警告）
AP=(比亚迪)                        # 单个申请人
AP=(华为 OR 中兴)                  # 多个申请人用 OR 连接
AP=(上海市第一人民医院 OR 上海交通大学附属第一人民医院)
```

- 多个申请人用 `OR` 连接，不支持 `AND`
- 全称/简称均可尝试，取决于数据库存储
- match_phrase 匹配，名称须与数据库一致
- `AP=` 可匹配联合申请人中的任一申请人（如 `AP=(华为)` 可命中"华为技术有限公司;清华大学"）

> **⚠️ 申请人简称噪声警告（实测发现）**：简称是否产生噪声取决于**该简称是否容易作为人名的一部分出现**。
>
> - **高风险简称**：`AP=(华为)` 匹配到"张华为"、"陈华为"等个人申请人——"华为"可作人名用字，噪声严重
> - **低风险简称**：`AP=(大疆)` 全部命中"深圳市大疆创新科技有限公司"——"大疆"不易出现在人名中，简称安全
>
> **判断标准**：如果简称中的字常见于人名（如华/为/明/达/信/中等），简称检索可能命中个人申请人，必须用全称或加 IPC/技术关键词限定。如果简称不易出现在人名中（如大疆/腾讯/字节等），简称可以直接使用，但仍建议核对前 3 条的 applicant 字段确认。分别检索全称和简称后按 PID 合并去重。

> **⚠️ 外国公司中文名须核对 applicant 字段（实测发现）**：外国公司的中文译名**可能**匹配到无关的中国实体，但并非所有中文名都会命中错误实体。
>
> - **命中错误实体**：`AP=(英伟达)` 命中"英伟达(江苏)机床有限公司"（机床厂，不是 NVIDIA）
> - **命中正确实体**：`AP=(索尼)` 命中"索尼公司"3024 条（正确的索尼公司）
>
> **判断标准**：如果该中文名碰巧是一家中国公司的名称（如"英伟达"被机床公司注册），会命中错误实体。**用中文名检索外国公司时，必须核对前 3 条返回的 `applicant` 字段确认是否为目标实体**；如果命中错误实体，改用英文原名（如 `AP=(NVIDIA)`）。优先用英文原名，中文名作为补充。

> **⚠️ 外国公司在 CN 库和 world 库的名称格式可能不同（实测发现）**：同一公司在两库的存储名称可能完全不同。例如 NVIDIA 在 CN 库存为"NvidiaCorp"（无空格连写），在 world 库存为"Nvidia Corp"（有空格）。**简称与全称命中量可能差 20 倍**（NVIDIA 简称 10000 条 vs Nvidia Corporation 全称 485 条）。必须尝试所有名称变体（简称、全称、连写、缩写）后按 PID 合并去重，不得只用一种名称。

### IPC 分类号 IPC=

```
IPC=(H01M)                         # 单个 IPC 子类
IPC=(H01M OR H02J)                 # 多个 IPC 子类
IPC=(B60W OR G05D 1 OR G08G)       # 主组前保留空格
```

真实CN数据通常把子类与主组存成带空格格式，如 `H01M 10/0525`。紧凑写法 `H01M10/0525` 可能产生假0条；skill客户端只对CN自动规范化。**world库与CN相反——实测偏好紧凑写法**：`IPC=(H01M10/0525)` 有命中，`IPC=(H01M 10/0525)` 返回 0 条。world 库客户端不做自动规范化，紧凑写法是首选。不要一律只用前4位：先单独执行IPC预检，再把有命中的准确下位组加入复合式；0条时先核对格式并回退上位组。world 库 IPC 预检的具体命令和实测结论见 `world_search_reference.md` 第 4 节。

```
IPC=(H01M 10/0525) # 精确下位组，先单独验证
IPC=(H01M)         # 上位组补召回
```

常用 IPC 速查表：

| 领域 | 代码 | 领域 | 代码 |
|---|---|---|---|
| 电池 | H01M | 通信 | H04L, H04W |
| 储能/充电 | H02J | 生物医药 | A61K, A61P |
| 人工智能 | G06N | 机器人 | B25J |
| 图像处理（软件） | G06T, G06V | 光学 | G02B |
| 图像采集（硬件） | G03B, H04N23 | 半导体 | H01L |
| 自动驾驶 | B60W, G05D1 | | |

### 日期 AD= / PD=

`AD` = 申请日，`PD` = 公开日。

```
AD>=2020              # 2020 年及以后
AD>2019               # 同上（2019年底之后）
AD<2015               # 2015 年初之前
AD<=2015              # 2015 年底及以前
AD=2023               # 2023 整年
AD=202301             # 2023 年 1 月
AD=20230115           # 精确日期
AD=2020-2023          # 范围：2020 到 2023
AD=2020 to 2023       # 范围（to 写法）
```

日期格式支持：`YYYY`、`YYYYMM`、`YYYYMMDD`、`YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY.MM.DD`

### 公开号 PID=

```
PID=(CN101971633A)
PID=(CN101971633A OR CN222118806U)
```

- `pid` 是 keyword 类型，term 精确匹配，速度最快
- 大小写不敏感，系统自动匹配原样/大写/小写变体

### 申请号 AN=

```
AN=(CN200980108398)
AN=(CN200980108398 OR CN202110012345)
```

⚠️ 13 位申请号需去掉最后一位（校验位）：`2019205174826` → `201920517482`

### 排除 NOT=

```
固态电池 NOT=(液态)
图像识别 NOT=(医疗 OR 医学)
```

### 国家/地区代码 CC=（仅 world 库支持）

> world 库完整使用指引（含字段对照表、申请人多语言检索、零结果探针）见 `world_search_reference.md`。

```
CC=(US)                             # 只看美国专利
CC=(US OR EP)                       # 美国 + 欧洲专利
battery CC=(US) IPC=(H01M)          # 关键词 + 国家 + IPC 组合
```

- 基于公开号（`pid`）开头的两位国家代码做前缀匹配，大小写不敏感
- 常用代码：`US` 美国、`EP` 欧洲、`WO` PCT 国际申请、`JP` 日本、`KR` 韩国、`DE` 德国、`GB` 英国、`FR` 法国、`CA` 加拿大、`AU` 澳大利亚、`CN` 中国（但通常直接用 `market=cn` 库更合适）
- 仅在 `market=world` 时生效；`market=cn` 库本身就是单一国家库，不支持也不需要此前缀
- 多个国家用 `OR` 连接，不支持 `AND`（一件专利只有一个国家代码，`AND` 无意义）

### 专利号自动识别（无需前缀）

直接输入专利号，系统自动识别并同时检索 pid 和 appnum：

```
CN101971633A       # 中国专利（带后缀）
CN101971633        # 中国专利（无后缀）
101971633          # 纯数字，默认补 CN
201920517482       # 申请号（12位）
US10234567B2       # 美国专利
```

## 关键词全文检索

无字段前缀时，在以下字段全文检索（权重从高到低）：

```
title^3 > abstract^2 > claims > description > pid > appnum
```

匹配规则：所有分析后的关键词单元都必须出现（`operator:and`），不要求连续或顺序。CN中文可能被分析为单字；当前普通关键词路径不会因为加引号就切换为 `match_phrase`，因此不得把引号当作精确短语保证。

```
固态电池              # "固态" 和 "电池" 都必须出现
(固态电解质)           # 普通关键词；仍需核对原文是否连续出现
(固态 OR 全固态) 电池  # 括号分组 + OR 扩展
```

## 完整组合示例

```
# 关键词
固态电池 电解质

# 申请人限定
AP=(华为) 5G

# 多申请人
AP=(华为 OR 中兴 OR 爱立信) 通信

# IPC 领域
IPC=(H01M) 固态电池

# IPC 多领域
IPC=(H01M OR H02J) 储能

# 日期范围
飞行汽车 AD>=2020

# 日期区间
IPC=(H01M) AD=2018-2023

# 公开日
AP=(华为) PD>=2024

# 申请人 + IPC + 日期（三重限定）
AP=(比亚迪) IPC=(H01M) AD>=2020

# 精确专利号
PID=(CN101971633A)

# 多个专利号
PID=(CN101971633A OR CN222118806U OR CN115036562A)

# 申请号
AN=(CN200980108398)

# 国家限定（仅 world 库，需配合 market=world）
battery management CC=(US)

# 多国限定
battery management CC=(US OR EP OR JP)

# 关键词语义扩展（推荐写法）
(狗 OR 猫 OR 宠物) (清洗 OR 洗浴 OR 护理) (装置 OR 设备 OR 机器)

# 排除
(固态 OR 全固态) 电池 NOT=(液态 OR 液体)

# 组合
AP=(华为) IPC=(B60W OR G05D 1) AD>=2022 NOT=(仿真 OR 模拟)
```

## 注意事项

1. **发明人无专用前缀**：`inventors` 字段存在但没有 `IN=` 处理，只能通过关键词全文命中（精度有限）。
2. **IPC 分层使用**：CN主组前保留空格；先单独验证长分类号，再用于复合检索，前4位上位组用于补召回。
3. **申请人用短语匹配**：名称须与数据库一致，全称/简称效果可能不同。
4. **13 位申请号去末位**：校验位需手动去掉。
5. **page_size 上限 50**：单次最多返回 50 条（实测 51 起返回 422）。宽结果跨页翻页时用 `--page` 递增翻页，不要试图单次拉取超过 50 条。
6. **world零结果先探针**：`0条`不等于目标国家没有专利。先依次验证`对象词 + CC`、核心机制/关系词 + `CC`、IPC子类 + `CC`、准确IPC主组的紧凑/空格两种写法 + `CC`；只有各层均返回可核对样本后才组合。任一层为0时记录字段/语言/表达式待修复，禁止将复合式0条用于FTO排除、低密度或技术空白结论。完整探针命令见 `world_search_reference.md` 第 8 节。
7. **world 库申请人多语言**：world 库 `AP=` 支持中文、英文、当地语言检索同一申请人（如 `AP=(丰田)` 可命中日文"丰田自动车株式会社"）。竞品分析时须将同一主体的多种名称变体分别检索后按 PID 合并去重。详见 `world_search_reference.md` 第 6 节。
8. **不支持数值范围检索**：PatSeek 不支持数值范围查询（如 `0.5-2mm`、`温度>=80℃`）。参数只能作为详情核对时的验证条件，不能放入检索式。需要按参数筛选时，先用关键词/IPC 召回候选，再在详情中人工核对参数五元组（对象+性质+数值+单位+位置）。
9. **摘要截断不足以判断特征**：Bool 检索返回的摘要可能被截断（约 200 字符），不足以判断特征是否真正出现。标记 H/M 前若摘要无法确认特征覆盖，必须调详情核对权利要求和说明书原文，不得仅凭截断摘要标记。
10. **Bool 返回字段因查询类型和专利而异**：`description` 仅 PID 精确查返回，普通关键词和 world 库不返回。`figures` 和 `cited_cnt` 是否返回取决于该专利在数据库中是否有对应数据（API 不返回值为 null 的字段键）。客户端必须用 `dict.get(key)` 检查字段是否存在。详见 `api_reference.md` 接口 1。
