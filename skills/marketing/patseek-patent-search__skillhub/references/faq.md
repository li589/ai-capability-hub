# 常见问题速查（FAQ）

> 本文件由 SKILL.md 尾部「常见问题」外移而来：**仅在遇到下列异常现象或疑问时读取**，正常执行流程无需读取。所有内部引用已统一为 `references/` 前缀，可直接按路径读取。

## 检索疑问

**Q: 申请人用简称还是全称？**
A: 企业/机构必须用**全称**（如 `AP=(华为技术有限公司)`）。简称会产生噪声——`AP=(华为)` 会匹配到"张华为"等个人申请人。详见 `references/query_syntax.md` AP= 章节。

**Q: 外国公司用中文名还是英文名？**
A: 用**英文原名**。中文名可能命中错误实体——`AP=(英伟达)` 命中的是"英伟达(江苏)机床有限公司"，不是 NVIDIA。`AP=(NVIDIA)` 才是正确的。详见 `references/technology_research_workflow.md`"跨国公司全球专利检索策略"。

**Q: world 库用中文还是英文关键词？**
A: **优先英文**。world 库 title/abstract/description 100% 英文存储，英文覆盖所有国家；claims 保持当地语言（JP/KR/TW）。详见 `references/world_search_reference.md` 第 5 节。

**Q: IPC 用紧凑还是带空格写法？**
A: **CN 库带空格**（如 `H01M 10/0525`，客户端自动规范化），**world 库紧凑**（如 `H01M10/0525`，带空格实测返回 0 条）。详见 `references/world_search_reference.md` 第 4 节。

**Q: 命中 10000 条怎么办？**
A: 10000 是显示上限，不可用于统计。收窄方法见 SKILL.md「Bool 检索式质量闸门」命中后强制收窄规则。

**Q: 命中 0 条怎么办？**
A: 先检查：①IPC 格式（CN 带空格/world 紧凑）；②申请人名称（外国公司用英文，企业用全称）；③关键词拼写。world 库 0 条时执行四层探针（见 `references/world_search_reference.md` 第 8 节）。注意：0 结果仍扣 1 积分。

**Q: `AN=` 申请号检索在 world 库能用吗？**
A: 不能。world 库 `AN=` 无数据，返回 0 条。改用 `PID=` 公开号检索。

**Q: 某个特征多轮 Bool 都搜不到，是不是就没有在先技术？**
A: **不是，恰恰相反**——这通常是术语体系不匹配的信号，应立刻切到语义 B（去对象化关系）和 C（问题机制）视角。实测案例：某特征经 CN/world、中/英文四轮 Bool 全部零有效命中，最终由语义 C 以相似度 95 召回一篇德文术语体系的同构文献，与 Bool 词面完全不重叠。在 Bool 零命中后就断言"无披露"会得出相反结论。详见 `references/invalidity_search_workflow.md` 第 5.4 节。

**Q: 为什么有的国际专利没有 description（说明书全文）？**
A: ①Bool 检索命中 **≥10 条时不返回 description**（<10 条会返回，cn/world 一致，2026-08-09 后台更新后）；②即使命中 <10，个别无全文来源的专利（如 GB `D0` 检索报告类）仍缺或为空串。单篇全文首选 `bool "PID=(公开号)" --market world`（覆盖整个检索索引，含 DE/KR）。详见 `references/api_reference.md` §1/§2。

## 流程与积分

**Q: 一次查新大约消耗多少积分？**
A: 典型查新约 15-20 积分（完整深度：8-10 次 Bool + 详情核对 + 语义先行 1 次；语义补漏 0-2 次按需另计）。快速摸底约 4-7 积分（3-5 次 Bool，不做语义），跑完会给出深入检索建议。Bool 和详情各 1 积分/次，语义 5 积分/次。以 API 返回的 `credits_charged` 为准。

**Q: 时间紧，能不能快速查新？**
A: 可以走「快速查新模式」：QX 一式（含试验性校准）+ IPC 预检（按需）+ QY-Base 一式 + 收窄/换切角（按需）+ 详情 ≤2 篇，约 3-5 次 Bool（3-6 分钟）。但只输出"初步印象 + 候选列表"，**不构成新颖性/创造性结论**；跑完会给出**深入检索建议**（未覆盖项+值得深入的方向+成本），由你决定是否转入完整深度；发现 H 级候选、或收窄 1 次后仍 ≥5000 条/触达上限时必须转入完整流程。详见 SKILL.md「快速查新模式」。

**Q: 为什么先做语义检索（语义先行）？**
A: 完整深度且用户已给详细方案时，Bool 前先做 1 次语义（+5 积分），三案例实测收益：①**IPC 分布确认更准**（固态电池热管理直接给 H01M 10/613/659/6568，纠正 Bool 预检的化学类方向）；②**关键词扩展更精**（暴露"角度可偏移""浮动块"等 Bool 想不到的术语）；③**发现 Bool 漏掉的新申请人族**（华为系）。注意：不可只信 top-1（新兴领域 top-1 可能噪声）、不可替代 Bool（两路召回互补）。快速摸底不做语义。

**Q: 语义检索支持国际专利吗？**
A: 查询须用中文描述，但**实测语义结果含国际公开号**（US/WO/JP/EP/KR，约占 20-25%）——"仅支持 CN 库"指查询语言而非结果来源。需要国际语义召回时，仍可先用语义在 CN 召回术语，再用英文回到 world 库验证。

## 无效检索

**Q: 无效检索什么时候可以停？**
A: 不由感觉决定，由 Goal Loop 的饱和门决定。运行 `scripts/invalidity_goal.py checkpoint` 后看 `recommendation`：只要还是 `plan_new_diverse_actions` 或 `continue_*`，就必须继续换多样性轴检索；只有必经通道全部执行、每个特征都已建立证据或明确缺口（`all_features_covered_or_gapped`）、且 `zero_decisive_cycles >= 3`，才可 `complete --reason saturated`；若全部特征已建立证据对应、攻击路线成型，可提前 `complete --reason evidence_ready`，但门未推荐 `saturation_review` 时**必须附 `--note` 说明覆盖理由**，否则拒绝执行（事件日志记 `override_gate`）。卡在"还有特征未覆盖但不知怎么搜"时，运行 `suggest-diversity` 让控制器建议语义 B/C 骨架。

**Q: 无效检索和查新检索有什么区别？**
A: 查新是"我的方案能不能申请专利"（找关键日前文献），无效是"别人的专利能不能打掉"（已知目标专利，找破坏其新颖性/创造性的在先技术）。无效检索的核心策略是**分层 Bool**（QX完整层/QY-Base基础层/QY-Comp补充层）+ 关键日约束 + 语义补漏。详见 `references/invalidity_search_workflow.md`。

**Q: 无效检索为什么不能只做一次全特征检索？**
A: 实测验证：完整特征一次式检索找回 18.2% 已知证据，分层 Bool 后提升到 36.4%，最终决定路线从 1/7 提升到 5/7。旧文献未必用同一套术语，且创造性攻击通常是两篇文献组合——分层检索恰好对应"基础文献+补充文献"的攻击结构。详见 `references/invalidity_search_workflow.md`。

## API Key

**Q: API Key 过期/积分不足怎么办？**
A: **必须停止检索并询问用户**，不得自行转向 Google。引导用户到 https://patseek.cn 更新 Key 或充值。详见 SKILL.md「API Key 失效处理协议」。

## 报告展示

**Q: 报告中如何展示重点专利的附图？**
A: 用 `patent <id> --figures-dir <目录>` 下载附图。必须展示 X/Y 候选、目标专利、技术路线代表专利；优先剖视图和流程图。展示规范与来源可靠性详见 SKILL.md「候选池与证据核对」中的附图展示规范。

**Q: 报告中如何提供专利快速阅读链接？**
A: 用 `https://xinxin.chat/patent?pid=<公开号>` 生成单篇链接，`&pid2=<公开号>` 可多篇对比。格式与写法示例见 SKILL.md「专利快速链接」章节。所有候选池重点专利都应提供。
