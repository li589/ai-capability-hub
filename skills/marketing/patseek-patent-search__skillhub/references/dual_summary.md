# 双导读与双建议（报告前置 + 结尾）

每份检索报告须含四个面向不同读者的小节，**顺序固定为先发明人后代理人**：

- **前置·双导读**：标题信息表之后、正文之前
- **结尾·双建议**：报告最后

四节共享同一组证据（X/Y 状态、候选表、覆盖情况、成本日志），仅表述层不同，**不重复检索、不额外耗积分**。

## 通用规则

1. **短**：每节 ≤4 条，每条 1–2 句。
2. **少用新名词**：不使用 skill 内部操作词（X/Y、QX、QY-Base、QY-Comp、H 率、特征覆盖矩阵、饱和门、适格文献等）；专利词首次出现带白话括注。
3. **证据驱动**：每条由报告自身证据生成，不写与本次证据无关的通用套话。
4. **结论纪律不软化**：不出现"保证授权""可授权""无风险""全球无人申请"等保证性表述；结论须带"本次检索范围内 / 未见"限定。

## 前置·双导读

### 给发明人的导读（白话·主语"你/你的"）

1. **一句话结论**：有没有人做过跟你一样的；你最特别的点是什么。
2. **最接近的几个方案**：每篇一句话 + 它们差在哪。
3. **下一步**：该干嘛（交代理人 / 规避设计 / 补"会不会侵权"检索）。
4. **红线**：申请前勿公开发表、参展或销售（欧洲无宽限期）。

> 专利词首次出现括注，如"权利要求（界定你保护范围的法律条款）"。禁用自造或生僻洋词，改用日常说法。

### 给代理人的导读（专业·简）

1. **检索范围与结论**：库/法域/语言/关键日/检索次数/积分 + 新颖性结论口径。
2. **最接近现有技术与缺失特征**：公开号 + 公开内容 + 相对区别特征缺失。
3. **权利要求建议与争点**：区别特征作独立权项核心；创造性争点。
4. **待核验**：非专利文献、当地语言权利要求、法律状态/同族官核、FTO。

## 结尾·双建议

### 给发明人的建议（需进一步深挖）

性质："你去把方案补强"。内容方向：

- 把模糊点讲细（阈值、时序、隔离方式、恢复逻辑）；
- 补量化效果数据（故障注入下的对比数据，最能支撑创造性）；
- 想替代实施方式（扩大保护面，写进从属权利要求）。

### 给代理人的建议（需询问发明人的问题）

性质："你去把发明人问清楚"。内容：锁定权利要求所需的细节清单，每条标明关联特征与影响的权项层级；不代答、不写推测性结构。

## 各任务类型变体

| 任务 | 前置双导读侧重点 | 结尾双建议侧重点 |
|---|---|---|
| 查新 | 标准（见上） | 标准 |
| FTO | 发明人③变"能不能用/风险在哪国/规避方向"；代理人②变"有效权利要求清单+规避点"，④加"法律状态官核" | 发明人建议→规避设计/替代方案；代理人建议→问实施细节+目标国+上市时间 |
| 技术调研 | 两节③变"竞品在做什么/你的机会/研发启示"；发明人版去红线 | 双建议可省，或变"研发启示/进一步调研方向" |
| 无效 | 两节②变"证据对目标专利的威胁程度"（权利人视角） | 发明人建议→补强自家专利稳定性方向；代理人建议→问原始研发记录与时间线 |
| 快速摸底 | 两节各精简到 2 块（结论+下一步/待核验），保留"不构成结论"降级声明 | 双建议各精简到 2 条 |

## 与 report_guard 的对应

evidence.json 须含四个字段（`report_guard.py` 校验非空，缺则拒绝渲染）：

- `inventor_briefing`：给发明人的导读（markdown 字符串）
- `agent_briefing`：给代理人的导读（markdown 字符串）
- `inventor_advice`：给发明人的建议（markdown 字符串）
- `agent_advice`：给代理人的建议（markdown 字符串）

`report_guard.render()` 在"任务与范围"之后、"特征或实施要素"之前插入双导读；在"限定结论"之后插入双建议。手写报告（不经 render）同样须含这四个小节，遵循本文件的模板与用词规则。
