# 专利无效证据检索工作流

> 本流程用于在已知目标专利的情况下，检索可能破坏其新颖性或创造性的在先技术。核心策略：**关键日约束的分层 Bool 检索为主，语义检索为补，专利详情和特征比对为最终核验。**
>
> 本流程不替代专利代理人或律师的法律判断。PatSeek 是证据发现工具，不是无效决定工具。

## 1. 边界与输入

无效检索回答"能否找到破坏目标专利新颖性或创造性的在先技术"，不回答 FTO 或可专利性。

| 项目 | 必须确认 |
|---|---|
| 目标专利 | 公开号/申请号，需调详情获取权利要求全文 |
| 目标权利要求 | 逐项列出独立权利要求和拟攻击的从属权利要求的必要技术特征 |
| 关键日 | 通常是目标专利的优先权日或申请日；关键日前的公开文献才能作为在先技术 |
| 攻击类型 | 新颖性（单篇覆盖全部特征）或创造性（多篇组合 + 技术启示） |
| 数据范围 | CN/world、语言、专利/非专利来源 |

没有关键日的检索最多只能叫"技术相似性搜索"，不能直接用于判断在先技术。

## 2. 权利要求拆解

把目标权利要求整理为特征表，每个特征标注其在攻击中的角色：

| 特征ID | 特征内容 | 结构/步骤关系 | 技术效果 | 区分力 | 预检术语 |
|---|---|---|---|---|---|
| F1 | 核心对象/产品 | … | … | 高/中/低 | 同义/缩写/多语言 |
| F2 | 核心机制/结构 | … | … | … | … |
| F3 | 区别特征 | … | … | … | … |

拆解原则：
- 每个特征必须是权利要求中**独立可检索**的技术要素
- 区分力标注该特征能否有效排除同领域噪声（高=特定结构/参数，低=通用功能词）
- 预检术语包括严格同义、缩写、旧称和多语言变体

## 3. 分层 Bool 检索策略

**核心原则：不能只做一次"全特征检索"。** 目标专利的全部特征往往不会以同样的组合、同样的术语出现在旧文献中。特别是在创造性攻击中，无效决定常常是"基础文献 + 补充文献 + 普通技术知识"的组合。

### 3.1 三层检索式设计

每案至少准备三条 Bool 检索式，按角色分层：

| 层级 | 角色 | 检索式结构 | 目标 |
|---|---|---|---|
| QX | 完整层 | 核心对象 + 多个关键特征 + `PD<关键日` | 找可能一篇覆盖较多特征的文献 |
| QY-Base | 基础层 | 核心对象 + 核心机理/结构 + 解决的问题 + `PD<关键日` | 找最接近的基础文献（可能只覆盖部分特征） |
| QY-Comp | 补充层 | 残余特征 + 技术效果/部件关系 + 应用场景 + `PD<关键日` | 找补充基础文献缺失特征的文献 |

```
QX      = (对象词) (特征1 OR 同义1) (特征2 OR 同义2) PD<关键日
QYBase  = (对象词) (核心机理 OR 同义) (解决的问题) PD<关键日
QYComp  = (残余特征 OR 同义) (技术效果 OR 部件关系) PD<关键日
```

QY-Comp 具有严格的前置依赖：必须先对至少 1 篇 Y-Base 候选完成详情核验，并形成“目标特征—Y-Base 已公开特征—残余区别特征”矩阵，之后才能构造 QY-Comp。若尚未找到可用的 Y-Base，继续运行 QY-Base、语义 A 或 world 宽式寻找组合基础，不得直接从待挑战权利要求臆造“残余特征”并提前进入 QY-Comp。

### 3.2 为什么分层

历史回放曾显示分层 Bool 比单一“完整特征式”更容易找回基础文献和补充文献；这只是小样本设计依据，不是当前案件的效果承诺。每次回放仍须按第 9 节独立计算路线召回。

分层的原因：
- 旧文献未必用同一套术语；换成更基础的技术关系词更容易命中
- 创造性攻击通常是两篇文献组合，分层检索恰好对应"基础文献 + 补充文献"的攻击结构
- 一次式检索容易漏掉"只披露其中一半、但恰好适合组合"的旧文献

### 3.3 关键日约束

每条检索式必须加 `PD<关键日`（如 `PD<20200101`），把结果限定为关键日前公开的在先技术。

注意：
- `PD<关键日` 过滤公开日，不是申请日；关键日前申请但之后公开的文献可能是抵触申请，需另列检索
- CN 库 `PD<` 格式为 `PD<20200101`；world 库语法相同
- 关键日不明确时，先用目标专利的优先权日作为初始关键日，后续核实
- **热门领域预警（实测发现）**：`PD<关键日` 在热门领域（如负载平衡/故障转移、图像传感器等）可能仍达 10000 上限——这些领域在关键日之前已有大量专利。日期限定不是万能收窄手段，须配合 IPC、特征组合或 CC 限定

### 3.4 三层都达上限时的收窄策略

当 QX、QY-Base、QY-Comp 三层都达到 5000+ 或 10000 上限时（热门领域常见），按以下策略收窄：

1. **加 IPC 限定**：`AP=(申请人) IPC=(准确分类) PD<关键日` 或 `(关键词) IPC=(准确分类) PD<关键日`——IPC 是最有效的结构化收窄手段
2. **按覆盖证据加 CC 限定（world 库）**：先保留不带 `CC=` 的首轮路径；仅基于前排来源、申请人或同族线索选择 CC（如 `CC=(US OR JP)`），并记录排除前缀
3. **换更基础的术语**：旧文献可能用更基础的机械关系词（如"定位"代替"盲插"），换成更通用的表达
4. **拆分检索**：把宽检索按 IPC 子类或年份分拆（如 `AD=2005`、`AD=2006` 逐年检索）
5. **保留前 100 名观察窗**：即使达上限，前 100 名仍可能有高相关候选——抽样前 10 篇评估质量，如果 H 率 ≥30% 则保留该检索块，否则收窄后重检

封顶只会使结果总量、命中率和“未检出”推断失真，不会使已经返回的正向候选失效。Top 50/100 中日期合格且特征覆盖高的文献必须保留、重排并进入详情核验，可计为该路径的正向检出，但不得据此宣称已穷尽该路径。

不得因三层都达上限就放弃检索或宣称"未找到在先技术"。

### 3.5 对象块上位概念与通用工艺路径（防漏检硬规则，金标回放实测）

**对象块必须包含上位概念，IPC 收窄不得丢弃通用工艺路径。** 仅用目标领域对象词构造检索式会系统性漏检"通用设备领域的决定性证据"。

- **上位概念扩展**：特征拆解时，对象词必须扩展为上位/平行领域词。例：目标"端子压着机"→ 上位"冲压机/压力机/压装机"；目标"织物平幅洗涤机"→"织物处理机/水洗机"；目标"盲插连接器"→"连接器/流体接头"。
- **至少一条 QX/QY-Base 用上位对象词构造**：去掉目标领域词限定（如去掉"端子"），保留机制/结构块，如 `(冲压机 OR 压力机) (转盘 OR 多工位) (定位 OR 分度) PD<关键日`。
- **IPC 双路径并行**：收窄时保留两条路径——目标领域 IPC（如 H01R 43/048）+ 通用工艺 IPC 家族（如 B21D 22/02、B21D 37/xx、B30B 7/00）；不得只收窄到目标领域 IPC 而丢弃通用工艺分类。
- **收窄前验证**：命中 10000 上限需用 IPC/对象收窄时，先确认上位概念路径已被覆盖（即上位词检索已执行并保留结果），再收窄到目标领域词。

**金标回放实测（CN113013703A 无效检索，2026-08-10）**：决定性对比文件1 CN205869183U（多工位转盘冲压机，覆盖目标 F1-F5 直接）因对象块只有"端子压着/压着机"且 IPC 收窄到 H01R 43/048 被漏检——该文献名称不含"端子/压着"、分类在 B21D 22/02/B21D 37/06/B30B 7/00；若保留"冲压机/压力机"上位路径或 B21D/B30B 通用 IPC 路径即命中。金标回放召回率仅 1/9（9 篇对比文件命中 1 篇），且决定性证据漏检——此类案例说明：**检索封存后，若有已知决定书/审查历史/金标对比文件，必须做金标回放核对 recall，并以漏检根因反查检索式设计**。

## 4. CN + World 分库检索

CN 库和 world 库各做擅长的事，不得只检一个库：

| 库 | 擅长 | 检索要点 |
|---|---|---|
| CN | 中文术语、国内实用新型、中文表述差异 | 用中文关键词 + 中文 IPC |
| World | 英文技术术语、PCT/US/EP/JP 等国际来源 | **优先英文关键词**（title/abstract 100% 英文）；仅在结果规模需要控制时使用 CC 限定 |

world 库检索前必须读 `world_search_reference.md`，注意：
- world 库 IPC 偏好紧凑写法（如 `H01M10/0525`）
- world 库申请人用英文原名（如 `AP=(NVIDIA)`，不用中文名"英伟达"）
- world 库 QX 仅在首轮无 `CC=` 已执行且结果规模需要控制时，按第 4.1 节的覆盖依据加 `CC=` 收窄

### 4.1 world 法域覆盖闸门

无效证据检索的目标是发现全球在先公开，`CC=` 只能是结果规模控制工具，不能默认为“主要法域”筛选。执行以下规则：

1. 首轮 world QX 或 QY-Base 至少保留一条**不带 `CC=`**的日期限定检索；若需要 `CC=` 收窄，先记录不带 `CC=` 的命中规模和触发原因。
2. 使用 `CC=` 时，覆盖集必须由技术来源、申请人、已知同族或前排样本驱动；不得未经说明只写 `US OR EP OR WO OR JP OR KR`。台湾及其他可能来源须显式考虑，例如 `TW`。
3. 每轮记录实际 `CC` 集合及被排除的前缀；后验评测时计算“决定性证据前缀是否被检索范围覆盖”。
4. `CC=` 仅按公开号前缀筛选，不代表证据适格性、同族完整性或法律地域结论。

### 4.2 world 范围桥接

当 CN 路径不足、语义返回出现非 CN 前缀，或案件答案分布提示跨法域来源时，应将语义候选、分类号、家族和引证作为“桥”，而不是继续堆叠中文关键词：

1. 从高覆盖候选提取 IPC/CPC、关系词、部件词、申请人/发明人及家族信息；
2. 先运行 `IPC/对象 × 1 个关键关系` 的宽式，再按证据密度增加第 2 个关系或部件；
3. 按实际出现的 PID 前缀拆分检查结果，并追踪同族及引证；
4. 避免把所有语义词同时 AND 到一条 world 检索式中。

## 5. 语义检索：术语与关系发现闭环

语义检索不是无效证据的排序器，相似度也不等于证据强度。其有效产出有两类：

- **直接候选**：日期合格、对象未跑偏且覆盖关键结构/关系，可直接进入详情核验；
- **检索 pivot**：可回写 Bool、分类号、家族或引证路径的术语、关系和候选锚点。

Bool 复现用于验证表达式和扩展邻域，不是语义候选进入证据池的强制门槛。

### 5.1 先建立特征图，再写互不重复的语义任务

在首轮 QX/QY-Base 后，从特征表额外写出对象、可移除对象词、部件/步骤关系、机制和技术问题五栏。先用 A 做试探，再由试探结果决定是否触发 B/C：

| 任务 | 输入构造 | 用途 | 禁止项 |
|---|---|---|---|
| A 对象视角 | 对象 + 核心机制 + 一个关键关系 | 找同类产品的不同叫法 | 不得照抄完整权利要求 |
| B 去对象化关系视角 | 去掉产品名和目标部件名；仅写部件拓扑/步骤关系 + 作用机制 | 跨产品名称发现同一结构关系 | 不得出现目标产品、型号或独有命名 |
| C 问题/机制视角 | 技术问题 + 实现机制/效果，不写对象名 | 发现相邻领域的可迁移表达 | 不得把效果词单独当作方案 |

例如，"可拆卸扣件"不是把该词换成同义词。可先以“扣合件的闭合机制”（A）试探；若对象噪声高，再运行“两构件通过相对运动实现可释放连接”（B）；只有 Y-Base 已确认且残余问题明确时，才运行“减少重复装配操作的保持机构”（C）。已执行的 A/B/C 必须在记录中说明各自删除或保留了哪些特征，防止近义改写。

- A 完成资格过滤后，记录 `eligible_prekey_rate` 和 PID 前缀分布；若合格率低于 10%，或合格候选少于 5 篇，停止机械追加 B/C，转向 world Bool、IPC/CPC、家族和引证。
- B 仅在 A 的对象锚定不足、噪声明显，或需要验证已发现关系时触发。
- C 仅在至少 1 篇 Y-Base 已完成详情核验并形成真实残余特征/技术问题后触发。
- 语义接口的实际返回范围以响应中的 PID 前缀为准，必须记录前缀分布，不得预设为仅 CN；world 召回仍须由第 4 节的英文 Bool、家族和引证路径补足。
- 任务串行提交，相邻间隔至少 60 秒。
- 语义可在首轮 Bool 后开始，但不得替代 QX、QY-Base、QY-Comp 或 world 路径。

### 5.2 资格过滤与留痕（先过滤，后阅读）

对每个任务分别保存原始 PID 列表，并产出两张表：`semantic_eligible_prekey` 和 `semantic_excluded`。只有前者才可进入候选重排；后者仅可提供术语线索。

| 过滤项 | 合格条件 | 不合格记录原因 |
|---|---|---|
| 日期 | `pubdate < 关键日` | 关键日后 / 日期未知 |
| 自匹配 | 非目标 PID、申请号、可识别同族或后公开延续案 | 目标自身 / 同族 / 目标方案延续案 |
| 去重 | 同 PID 仅保留一条；可识别同族优先最早公开且文本完整者 | PID 重复 / 同族重复 |
| 可核验性 | 有 PID 与可核验日期字段 | 标识或日期无法核验 |

被过滤文献不得提高 H/M 比例、X/Y 候选数、详情优先级或路线召回率。报告分别给出原始数、合格数和各排除原因数；不得从原始 Top 结果直接挑选“最相似”的几篇。

不得只检查相似度 Top 10。应对全部日期合格结果进行轻量重排，至少考虑关键特征覆盖、稀有关系命中、时间余量、对象一致性及结果多样性。日期合格且覆盖至少 2 个高优先级特征，或命中 1 个决定性结构/功能关系的结果，可作为语义直接候选进入详情核验，即使其排名低于 50 或尚未被 Bool 复现。未经详情核验，不得直接标记为 X/Y 证据。

### 5.3 从合格语义结果生成 Bool 枢纽

只从 `semantic_eligible_prekey` 的标题、摘要、分类和详情抽样中提取下列枢纽：替代对象词、关系短语、机制词、下位/相邻 IPC、英文对应表达、申请人/引证/同族线索。每个枢纽须记录来源 PID、来源字段、对应特征和以下一项采纳依据：

1. 出现在至少两篇日期适格文献中；
2. 来自权利要求、IPC 定义、标准或其他可核验权威来源；
3. 经发明人或检索负责人确认。

单篇噪声文献的偶然用词不得直接加入核心式。对每个被采纳枢纽，按宽—中—窄三层构造新的 `PD<关键日` Bool：宽式为 `IPC/对象 × 1 个关键关系`；中式增加第 2 个关系或部件；窄式仅在宽式或中式已保留语义锚点后增加更多限制。中文枢纽回写 CN；有可靠英文对应或国际线索时，再回写一条不带默认 `CC=` 的 world 式。

每次改写都要保存 Top 50 和作为锚点的语义候选 PID。新 Bool 的 Top 50 至少应保留 1 篇高覆盖锚点；若全部丢失，说明查询过窄或关系组合错误，该查询不得替代语义直接候选或此前的宽式结果，应放松 AND 条件或回退一层。禁止把所有 pivot 一次性 AND 到单条查询中。

### 5.4 语义结果的用途边界

- 语义合格结果可沿“直接候选 → 详情核验”或“pivot → Bool/分类/家族扩展”两条路径进入候选池；Bool 重现不是直接候选的准入条件，但未经详情逐项核验不得晋级为 X、Y-Base 或 Y-Comp。
- 语义不能证明“未找到”；若 A/B/C 没有产生有效枢纽，应换入口维度（对象、关系、问题），而不是反复润色同一段描述。
- **某特征经多轮 Bool（跨库 + 跨语种）零命中或全噪声，是触发 B/C 的强信号，而不是"该特征无在先技术"的结论。** Bool 靠词面匹配，跨术语体系的同构方案必然漏检。实测案例 CN113039321B：F6（气动输送管道出口喷洗涤液）经 CN/world、中/英文四轮 Bool 全部零有效命中，最终由 C（问题机制视角）以 sim=95 召回 EP1526203A1——该文献用德文术语体系 `Venturi-Transportdüse`/`Spülflüssigkeit` 描述同一结构，与 Bool 词面零重叠。若在 Bool 零命中后即断言"该特征无披露"，结论将与事实相反。同理，F7 的跨领域证据分布在 F26B（干燥）、D21H（造纸）、B65H（片材输送）而非纺织分类下，只有 B（去对象化关系视角）能召回。
- 详情显示了同族、引证或相邻分类线索时，记录为“扩展线索”；仅对实际查询并返回的 PID 计入候选池，不能假定同族已被自动覆盖。
- 若候选依赖产品页面、使用手册、展会资料、销售记录或其他非专利公开，标记 `source_gap=non_patent`，单列来源计划；PatSeek 专利检索不得把此缺口写成零证据。

### 5.5 语义失败处理与效能指标

429、取消或异常返回均记为“任务未完成”，保留任务状态；60 秒后以**不同入口维度**重试，不能写成零命中。语义模块仅按以下指标评估，不按相似度或原始命中量评估：

| 指标 | 定义 |
|---|---|
| `eligible_prekey_rate` | 合格日期适格 PID / 语义原始 PID |
| `pollution_rate` | 自匹配、同族、关键日后或日期未知 PID / 语义原始 PID |
| `pivot_yield` | 通过采纳门的新增术语、关系、IPC 和国际线索数 |
| `semantic_direct_candidate_yield` | 语义合格池中满足直接详情晋级门的日期适格候选数 |
| `semantic_direct_route_recall@N` | 回放封存后，语义直接候选找回的决定性证据路线数 |
| `semantic_assisted_bool_yield` | 语义辅助 Bool Top 50 中新增的日期适格候选数 |
| `pivot_anchor_retention_rate` | 语义辅助 Bool Top 50 保留至少一个高覆盖语义锚点的查询比例 |
| `semantic_assisted_route_recall@50` | 回放封存后，语义辅助 Bool 找回的决定性证据路线数 |
| `semantic_combined_route_recall` | 语义直接候选与语义辅助 Bool 合并后的决定性证据路线召回 |
| `positive_yield_from_capped` | 封顶查询 Top 50/100 中晋级详情的日期适格高覆盖候选数 |
| `source_gap_detection_rate` | 正确标记为非专利或未覆盖来源的案件比例 |

## 6. 候选核验

对候选池中的每篇文献逐项核验：

| 核验项 | 方法 | 通过标准 |
|---|---|---|
| 公开日 | 检查 `pubdate` 字段 | `pubdate < 关键日`（普通现有技术） |
| 特征披露 | 调详情核对权利要求/说明书原文 | 每个必要特征有明确或隐含的原文位置 |
| 同族去重 | 按 PID 或同族标识合并 | 同族只保留最早公开文本 |
| 组合动机 | 若是多文献组合，检查结合理由 | 记录技术问题相同/功能关系/相邻领域迁移理由 |

### 6.1 前观察窗

Bool 检索取前 100 名作为固定观察窗（每页 50 条，取前两页）。如果检索返回 5,000 条以上或显示 10,000 条封顶，说明检索式过宽；此时不得把结果总量计入命中率，也不得作“未命中”或已穷尽结论，应增加结构词、IPC 或限定词收窄。同时，已返回 Top 50/100 中日期合格且覆盖度高的正向候选仍须进入候选池和详情核验；只计“封顶路径正向检出”，不宣称完整召回。

**保存与晋级规则**：每条 Bool 必须保存前 50 个 PID（结果少于 50 时保存全部）。前 10 篇用于人工质量抽样，但不得把“只看前 10”当作详情晋级门槛：在 Top 50 中，凡关键日前且标题、摘要或权利要求可观察到至少两个高优先级特征（对象、核心机制、关键关系）者，必须进入候选重排和详情候选队列，即使原始排序在 11–50 位。记录其原始排名、可观察特征和晋级理由。

详情核验出现同族或引证信息时，再检查是否有日期适格且不同文本版本值得检索；只有实际执行的扩展查询及其返回 PID 才构成“已覆盖”，避免把同族标签误作检索结果。

### 6.2 特征比对矩阵

对每篇候选建立特征比对表：

| 文献 | F1 | F2 | F3 | 原文位置 | 明确/隐含 | 组合角色 |
|---|---|---|---|---|---|---|
| CNxxx | ✅ | ✅ | ❌ | 权1/段[0032] | 明确 | 基础文献 |
| USxxx | ❌ | ❌ | ✅ | 段[0015] | 隐含 | 补充文献 |

- ✅ = 该特征在文献中有明确或隐含披露
- ❌ = 该特征在文献中未见
- 多篇结果不能拼成单篇覆盖；组合需要结合理由

## 7. 攻击路线构建

区分两种攻击路线：

### 7.1 单篇新颖性路线（X 文献）

**标准**：同一篇关键日前文献明确或隐含公开目标权利要求的**全部**必要特征及其必要关系，且公开达到可理解/可实施程度。

不得仅凭标题、摘要相似度或同词数量判定 X 文献。必须核对全文、关键日期和公开充分性。

### 7.2 多篇创造性路线（Y 文献组合）

**标准**：
1. Y-Base 文献：关键日前、领域/问题最接近，公开大部分必要特征和核心机制
2. Y-Comp 文献：关键日前，公开 Y-Base 缺失的关键区别特征
3. 组合动机：两篇之间存在需要复核的结合线索（相同技术问题、相同功能关系、相邻领域迁移理由、标准/公知常识证据）

没有结合理由时只能报告"特征分别已见"，不能直接标 Y 组合。

### 7.3 攻击路线图

输出一张证据路线图，清楚说明：
- 基础文献解决了什么问题、覆盖了哪些特征
- 补充文献补了什么缺失特征
- 哪些特征仍未被覆盖
- 组合动机是什么

## 8. 持续检索 Goal Loop 与中止

开始检索前必须读取 `invalidity_goal_loop.md`，为每件案例建立独立目录并运行 `scripts/invalidity_goal.py init`。控制器负责持久化目标、关键日、特征、动作前沿、PID 来源、候选、检查点和暂停状态；PatSeek 客户端仍只负责实际 API 调用。

无效检索不得以固定 Bool 次数、固定轮数或单轮命中下降为中止理由。每个循环都要：

1. 从 QX、QY-Base、QY-Comp、语义、world、IPC、家族/引证和详情前沿中选择最高价值动作；
2. 保存原始响应，以及 Bool Top 50 和语义全量 PID；
3. 更新日期适格候选、特征矩阵、Y-Base 残余矩阵、直接语义候选和 pivot；
4. 把新候选、IPC、家族、引证和关键特征披露转为后续动作；
5. 写入 checkpoint 并依据证据增益决定继续、暂停或进入饱和复核。

只有满足以下全部条件才可封存为饱和：

- QX、QY-Base、world、语义 A 和详情等必经通道已执行；必要的 QY-Comp 已在 Y-Base 残余矩阵形成后执行；
- 所有高优先级候选与前沿已完成核验或记录不处理原因；
- 连续至少 3 个完整 checkpoint 未产生新的日期适格候选、关键证据、pivot、IPC、家族/引证或特征覆盖；
- 每个必要特征均有已核验证据或独立检索缺口记录；
- 报告清楚列明未覆盖的库和非专利文献类型。

任一新候选、pivot、分类或家族线索都会重新打开相关路径并清零零增益计数。API 401/402/403、费用检查点或用户要求只能暂停并保存状态，不得伪装为完成。

## 9. 输出报告

报告至少分开记录四种数字：

| 数字类型 | 说明 |
|---|---|
| 候选数量 | 检索返回多少条，是否被截断 |
| 已知证据找回率 | 若有已知无效决定，决定书列出的实际证据有多少进入候选池 |
| 最终路线找回率 | 最终支撑结论的证据有多少被找回 |
| 法律可用性状态 | 公开日、特征披露和组合逻辑是否已核验 |

回放评测必须在检索封存后才加载决定书或金标，并额外报告：决定性证据 `recall@50`、被详情晋级率、X/Y 路线召回率、world 前缀覆盖缺口、封顶路径正向候选产出，以及第 5.5 节的语义直接召回、辅助 Bool 召回、合并召回和锚点保留率。不得以金标反向扩展同一题的检索式。

### 报告结构

1. 目标专利、权利要求拆解和关键日
2. 检索矩阵与执行记录（每条 Bool 式、语义 A/B/C 触发依据、原始/合格/排除数量、直接候选、枢纽和锚点保留路径、命中量、是否截断）
3. 候选特征比对矩阵
4. 攻击路线图（单篇新颖性路线 / 多篇创造性路线）
5. 逐篇证据核验表（公开日、原文位置、明确/隐含）
6. 未覆盖项、限制和下一步

用 `scripts/report_guard.py evidence.json --output report.md` 做发布前守卫校验。字段口径（实测）：

- `searches[].total` **必须可转 int**；命中封顶时填 `10000`，把"封顶截断、总量不可用于统计"写进同条的 `observability`，不要写进 `total`。
- `total` 为 0 时必须同时给 `zero_result_explained: true`，否则校验不通过。
- 必填字段：`title/role/decision/task_type/as_of/scope/features/searches/gate/limitations`；`gate.status` 不可为空。
- `conclusion` 命中禁用词（"不存在侵权风险""可自由实施""全球无人申请""保证新颖性""已经具备新颖性"）会直接拒绝渲染。
- 无效检索若未形成单篇 X 候选，`gate.status` 用 `no_x_candidate_in_scope`，守卫会自动附加"这不保证新颖性"的限定口径。

## 10. 结论纪律

- 一篇文献出现在前 100 名，只说明它值得阅读，不等于专利当然无效
- 不得输出"该专利无效""不存在在先技术"等保证性结论
- 不得把"技术上相似"误读成"已经证明无效"
- 无效分析还需要逐项核对：公开日、特征披露、组合动机、抵触申请、优先权、同族、程序和权利要求解释问题

推荐口径：

> 截至[日期]，在[数据库、国家、语言]及所列检索式范围内，[发现/未发现]可能影响目标专利新颖性或创造性的在先技术候选。候选文献的法律可用性须逐篇核验公开日、特征披露和组合逻辑后才能确定。本结果不替代专利代理人或律师的专业判断。
