# TikTok Shop商品视频制作

把商家授权的商品资料、产品图和目标市场，做成一份卖家或达人可以直接开拍的 TikTok Shop 商品
视频方案：一组由商品出发的开场钩子、一段口播脚本、镜头节拍、字幕提示，以及本地化的发布文案，
全部只写在商家提供的事实范围内。

## 适用范围与路线选择

本 Skill 用于为特定市场规划一条可带货的商品视频：商品展示、功能演示、开箱、测评、对比角度，
以及达人带货视频。它写方案和拍摄用的台词，不出片、不录旁白、不上架商品、不投放广告，也不承诺
销量或平台审核结果。

从单张商品图直接生成成片请使用 `product-video-studio`；需要 AI 达人出镜口播请使用
`douyin-ugc-ad-creator`；已有脚本需要旁白音频请使用 `short-form-voiceover-audio`；电商商品图集（主图、
卖点图、场景图）请使用 `ecommerce-listing-image-set`。

## 输入与默认值

硬性输入是目标市场和商家自己的商品事实。复用对话中已有的商品名称、类目、卖点、价格、受众、
达人口吻、发布位置和产品图。只追问会改变方案的那几项：目标市场、希望观众做的那一个动作、
事实来源，或者拍摄条件。

用目标市场的语言来写。面向美国或全球 TikTok Shop 受众默认用英语，面向日本受众默认用日语；
必须保留的品牌或商品措辞按原样照搬。

默认给出 3 个开场钩子、一段 20–45 秒的脚本、一个明确的商品记忆点、钩子→证明或演示→报价→行动
引导的结构、每一段口播对应一个镜头节拍，以及每个节拍一条字幕提示。交付本地化标题、话题标签，
以及一条商品页事实撑得住的行动引导。

价格、库存、物流、折扣、评分、评价、认证、奖项、排名、成分、功效和合规状态都只能来自商家。
产品图能说明画面里看得见什么，但它不是商家没说过的事实的依据。缺少某个证明点时，去问，而不是
用看起来合理的细节把它补上。

## 标准流程

1. 写商品简报：市场与语言、商品事实、受众、希望观众做的那一个动作、达人口吻、必须保留的措辞、
   可用产品图，以及拍摄条件。
2. 从商品真正的优势出发起草三个明显不同的开场，选定一个主开场，另外两个保留备用。
3. 逐句写出口播脚本、镜头与动作节拍、字幕提示、本地化标题、话题标签和行动引导。
4. 交付前先筛一遍措辞：每一个说法都能追回到商家提供的事实，不承诺结果，不用无法证实的绝对化
   表述，不做受监管的健康、医疗或功效宣称。命中意味着改写，而不是加一句免责。
5. 复查市场语言是否自然、能不能拍、时长是否合适、字幕是否读得清，以及与商品页是否一致。交付
   主脚本、两个未采用的开场，以及一份商家可以逐条确认的事实清单。

关于简报卡、时长计算、各市场语言注意事项、措辞筛查与修订规则，请阅读
[商品视频工作流](references/workflow.md)。

## 修订与更新

市场、商品、事实、受众、报价或希望观众做的动作发生变化，都算一份新的简报。保留已确认的事实，
只改动受影响的字段。本 Skill 属于不计费的方案工作：不创建生成任务，也不产生付费的
`client_request_id`。

远程操作只使用本 Skill 随包的 `scripts/mcp_client.py`；随包客户端会在首次使用时自己完成注册，
没有需要手动调用的注册子命令。不要配置或调用宿主 Beatra Connector，也不要使用 REST/OpenAPI
作为回退。注册链路需要排查时请阅读[随包 MCP Client 连接诊断](references/mcp-connection.md)，
移除本包时请阅读[卸载与断开连接](references/uninstall-and-disconnect.md)。

## 运行时与安全自动更新

随包客户端会在每个安装中静默检查更新，最多每 24 小时一次。发现更高版本时，
不另行确认地自动安装。它只从固定的 Beatra 官方发现地址与不可变 CDN 路径下载，
在替换之前校验压缩包、清单和每个随包文件，并且只替换本包拥有的文件。更新失败时不会中断：
当前安装仍可使用，原本请求的命令会继续执行。这个设置会在本安装中持续生效。详见
[自动更新与安全](references/automatic-updates-and-safety.md)。

```text
python3 scripts/mcp_client.py update --auto off
python3 scripts/mcp_client.py update --auto on
python3 scripts/mcp_client.py update --check
```
