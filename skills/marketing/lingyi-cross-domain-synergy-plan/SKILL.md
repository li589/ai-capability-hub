# 公私域联动方案生成

> 版本：v0.2.0 · 作者：小风、CoderPig

梳理公域/半私域/私域/线下触点角色分工，画出统一收口的承接链路，用 RICE 给渠道量化优先级，产出状态化承接期触达 SOP。本技能是纯方法论输出，免登录免 Key、由 agent 直接产出；四件套写完后把报告 Markdown 提交服务端登记（旁路、失败不阻塞交付）。

> 核心信念：私域承接是「首次获客付费、复购触达接近免费」的杠杆支点——把公域流量系统接进私域并完成首单，承接链路无断点，后面分层运营 / 会员成长才有意义。承接做不好，进来即流失（公转私沉淀率行业仅 5–15%），后面全白搭。

> 与姊妹技能咬合：本技能管「怎么进来」（承接期），`私域用户分层触达策略` 管「进来后怎么分群运营」（分层+全生命周期触达），两者在「承接进来的用户 = 分层对象」咬合。完整 SOP：会员运营诊断与增长建议 → 本技能承接规划 → 分层触达 → 会员积分体系。详见 [references/related.md](references/related.md)。

## 目的

帮运营者把「公域流量系统承接进私域并完成首单」跑通，产出**触点地图 + 承接链路图 + 渠道优先级 + 承接期触达 SOP** 四件套。

这不是「一套群发话术表」，而是「先盘清触点角色、画统一收口链路、给渠道量化优先级、写状态化承接 SOP」。承接是手段，目的是把用户从公域接进来、沉淀到企微/社群/小程序、完成首单——避免触点割裂（用户身份在不同触点跳来跳去）、进来即流失（7 天无互动变僵尸粉）、SOP 纸面化（30 天打开率<30%）三大私域死因。

> 核心信念：触点角色必须固定分工（公域入场 / 企微社群承接 / 小程序成交 / 公众号品牌内容 / 会员体系成长），承接链路必须统一收口无断点，SOP 必须按用户状态而非消息时间表触发——四者咬合才成承接体系，少一环就是纸面规划。

## 输入

**最佳搭配：** 你的业务模式（餐饮高频复购 / 零售客单周期 / 电商跨品类 / 服务预约 / 线下到店）+ 私域载体（企微 / 社群 / 小程序 / 公众号）+ 主要公域流量来源（抖音 / 小红书 / 视频号 / 朋友圈广告 / 搜一搜 / 电商店铺 / 门店）+ 首要运营目标（公转私沉淀 / 首购转化 / 复购提升 / 门店导流 / 会员成长）。

**也有用：** 现有触点清单（哪怕散乱的「有公众号 3 万粉、门店无码、无企微」）、预算/人力约束、现有数据源（订单 / 互动 / 社群活跃 / 门店 POS）。

调用时附带的所有内容——技能名后的文本、粘贴的上下文，或附加的 `ARGUMENTS:` 行——都视为已给出的回答。直接使用并跳过其已覆盖的部分，不要重复提问。

**手头没有任何信息？那也可以。** 技能基于业务描述先搭一版触点地图与承接链路假设，标 `[假设—需验证]`，后续用真实数据回填并滚动复算。

**示例调用：** `为茶饮连锁设计公私域承接链路——企微+小程序+社群，公域主要靠抖音种草和门店扫码，目标公转私沉淀和首购转化，3 万复购客。`

### 输入字段与异常处理

| 字段 | 必填 | 异常处理（缺失/错误时怎么回） |
|---|:---:|---|
| 业务模式 | 是 | 缺失→追问「业务属高频复购/客单周期/跨品类哪类？」不假设 |
| 私域载体 | 是 | 缺失→按企微+小程序默认，提示确认（企微/社群/小程序/公众号） |
| 主要公域流量来源 | 是 | 缺失→追问「公域流量主要从哪来？」全无→链路图「公域种草」阶段缺失，降级只产触点地图+渠道优先级（异常 3） |
| 运营目标 | 是 | 缺失→追问，多目标时要求排优先级 |
| 现有触点清单 | 否 | 缺失→继续，提示「有现有触点请提供，便于盘点去重」 |
| 预算/人力约束 | 否 | 缺失→提示「无约束信息则 RICE 的 Effort 按经验估，需复核」 |
| 现有数据源 | 否 | 缺失→提示「无数据则 KPI 基准用行业区间，标【待印证】」 |

## 核心概念

### 公私域怎么区分
公、私域区分的关键在于：企业与用户**连接关系的强弱**，商家是否直接拥有用户资产，能否对用户**重复触达**，以及触达用户需要付出多少成本。据此微信生态触点分四类：
- **公域**（付费/搜索/推荐）：朋友圈广告、视频号原生广告、搜一搜、抖音/小红书种草、电商平台——单向、按次付费、不直接拥有用户。
- **半私域**（品牌自有、单向广播）：公众号、视频号主页/直播间、搜一搜品牌官方区——品牌自有但以广播为主。
- **私域**（双向互动、可反复触达）：企微 1v1/朋友圈/社群、小程序、社群、会员系统——直接拥有、可反复触达、成本接近免费。
- **线下**：门店收银、POP/海报、导购码、包裹卡、线下活动——物理触点，承接靠扫码。

### 触点角色固定分工（腾讯五大阵地 2026）
微信生态五大阵地角色清晰分工，承接链路按此分工编排（【按 2026 规则核验·需复核】）：

| 阵地 | 角色分工 | 在链路中的位置 |
|---|---|---|
| 视频号 | 公域入口（获新） | 公域种草 / 活跃培育 |
| 搜一搜/广告 | 公域获客 | 公域种草 |
| 公众号 | 品牌阵地（内容种草） | 私域沉淀 / 活跃培育 |
| 企业微信 | 1V1 服务 + 社群 | 私域沉淀 / 活跃培育 |
| 小程序/微信小店 | 成交枢纽 / 私域阵地（深度会员运营） | 转化变现 / 会员成长 |

> 核心信念：「运营的核心不是把某个阵地做大，是让五个阵地协同转起来形成公私域联动飞轮——首次获客付费、复购触达接近免费。」渠道取舍以此飞轮为框架。

### 承接链路 vs 分流
| 承接链路（本技能做） | 分流（分群运营，姊妹技能做） |
|---|---|
| 画「公域→沉淀→培育→成交→成长→召回」整条路径 | 给已在私域的用户按 RFM 分价值分群 |
| 回答「用户从哪来、沉淀到哪、怎么持续触达」 | 回答「谁是谁、值多少、该怎么对待」 |
| 产出链路图 + 渠道优先级 + 承接期 SOP | 产出分层表 + 差异化触达策略 |

> 承接是「接进来 + 完成首单」，分流是「进来后分群运营」。本技能的承接期 SOP 止于首购后第 N 天的复购预埋；成熟期 / 沉睡召回的全生命周期分层触达归分层触达技能。

### SOP 是用户状态对应表，不是消息时间表
**私域 SOP 首要失败模式**：把 SOP 当「发消息的时间表」（以发送动作为中心），30 天后打开率<30%、互动率<10%（句子互动实战数据）。

正确做法——SOP 是「用户状态对应表」（以用户状态为中心）：
- 三维骨架：**时间轴**（破冰 Day1-3 / 培育 Day4-14 / 成熟 Day15+）× **用户标签**（来源渠道 / 浏览行为 / 互动记录）× **内容类型**（品牌背书 / 产品教育 / 利益驱动）。缺一维就只是纸面流程。
- 触发条件必须是用户状态事件：加好友通过→破冰 SOP、7 天未互动→培育 SOP、首购后第 3 天→复购预埋 SOP。纯定时（如"每天 8 点发"）=反模式。

### 反模式（它不是什么）
- 不是只盘点触点不画链路——触点清单无收口路径等于没承接。
- 不是 SOP 全生命周期大而全——本技能聚焦承接期，后面分流到姊妹技能。
- 不是抄同行链路——李宁「先直购后加粉」是单品牌个案【待印证】，要按自己业务反推链路类型。
- 不是把渠道优先级拍脑袋——必须 RICE 量化，禁「高/中/低」模糊词。

### 何时使用
- 新接手私域项目要盘触点、出可汇报承接方案
- 公域有流量但接不住、沉淀率低（5–15% 区间）
- 触点散乱角色不清，要画统一收口链路图
- 要给门店导购 / 社群运营出承接 SOP

### 何时不要使用
- 要把已有用户按 RFM 分层做差异化触达 → `skills/private-domain-segmentation-reach/SKILL.md`（分层触达技能）
- 要设计会员等级/积分/权益 → `skills/member-points-benefit-design/SKILL.md`
- 要诊断会员运营成熟度（含触点链路诊断）→ `skills/lingyi-member-ops-diagnosis-growth/SKILL.md`
- 要搭私域标签体系底座 → `skills/private-domain-tag-system/SKILL.md`
- 私域刚起步、无公域流量、零数据 → 先跑通基础承接，本技能可降级产触点地图+渠道优先级（异常 3）

## 应用

使用 [references/template.md](references/template.md) 获取完整的填空式结构。先明确输入字段与异常处理，再按 8 步产出四件套（含可选 Excel），交付后走第 9 步旁路提交服务端；每步过质量检查。

### 第 1 步：盘触点（触点地图）

把业务涉及的触点按公域/半私域/私域/线下四类盘点，每触点填 13 列。参考全枚举（按业务裁剪，不必全用）：

```markdown
### 一、触点地图（13 列盘点表）

| # | 触点名称 | 所属平台载体 | 触点类型 | 生命周期阶段 | 承接动作(用户侧+运营侧) | 沉淀位置 | 参考指标 | 负责人 | 优先级 | 触达频次上限 | 引流诱饵 | 转化目标 KPI | 关联触点 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

**触点全枚举（按业务裁剪）**：
- 公域：朋友圈广告 / 公众号文章广告 / 视频号原生广告 / 搜一搜(品牌专区/关键词) / 抖音·小红书种草 / 电商平台店铺包裹
- 半私域：公众号(关注自动回复/菜单栏/推文/模板消息) / 视频号(主页企微入口/直播间挂活码/评论区私信) / 搜一搜品牌官方区
- 私域：企微(1v1/朋友圈/社群/客服消息/活码) / 导购个微号 / 小程序(首页/详情页/支付成功页/订阅消息/支付凭证) / 社群(群公告/欢迎语/营销任务) / 会员系统(会员卡/积分商城)
- 线下：门店(收银台扫码/POP海报/导购码/试衣间码) / 包裹卡 / 线下活动·快闪 / 户外广告带码

**参考指标（区间，【按业务校准】）**：公众号图文阅读 6-10% / 菜单栏引流 2-3% / 模板消息 10-30% / 群分享转化 10-20% / 朋友圈 3-8% / 支付后关注 20-35% / 公转私沉淀率 5-15%
```

> **质量检查：** 核心触点四类（公域/半私域/私域/线下）每类≥1 个→通过；缺整类→不通过，追问该类是否有可用触点（异常 6）。触达频次上限用行业惯例值，标【待印证·按业务校准】。

### 第 2 步：定触点角色分工（五大阵地）

按腾讯五大阵地给第 1 步每个触点标角色：获新 / 沉淀 / 培育 / 成交 / 成长。避免触点割裂——单一触点（只开小程序不动其他）触发异常 6。

> **质量检查：** 成交阵地（小程序/微信小店）与承接阵地（企微/社群）必须同时存在；只有成交无承接=触点割裂。

### 第 3 步：画承接链路图（6 阶段收口）

把触点串成 6 阶段链路，每阶段填节点/用户动作/承接动作/沉淀位置/后续触达：

```markdown
### 二、承接链路图（6 阶段）

| 阶段 | 节点(触点) | 用户动作 | 承接动作 | 沉淀位置 | 后续触达 |
|---|---|---|---|---|---|
| 1.公域种草 | [抖音/小红书/视频号/广告] | 品牌建认知 | 渠道活码自动打标 | 待沉淀 | 引流至沉淀触点 |
| 2.私域沉淀 | [公众号菜单/包裹卡/门店码/支付页] | 关注/扫码/加好友 | 欢迎语+新人礼+标签 | 企微+社群+小程序会员 | 7 天新客 SOP |
| 3.活跃培育 | [企微1v1/社群/朋友圈/推文] | 阅读/互动/点击 | 内容种草+福利钩子 | 活跃用户 | 生命周期分层触达 |
| 4.转化变现 | [小程序商城/直播/社群秒杀] | 下单/支付 | 订单标签+复购券 | 成交会员 | 复购提醒+升单 |
| 5.会员成长 | [会员中心/积分商城] | 升级/兑换 | 等级权益匹配 | 高价值池 | 专属服务+裂变激励 |
| 6.流失召回 | [短信/AI外呼/企微1v1] | 唤醒/回流 | 召回券+调研 | 重新激活 | 二次培育 |
```

> **质量检查：** 6 阶段每阶段≥1 个触点节点 + 链路无断点（每节点「沉淀位置」=下阶段「入口」）→通过；断点→标红补承接动作（异常 8）。例如「公众号→沉淀公众号粉丝」后无入口到企微，补：公众号菜单栏设企微活码。

### 第 4 步：RICE 评分定渠道优先级

给候选渠道打 RICE 四维，公式 `Score=(R×I×C)÷E` 排序：

```markdown
### 三、渠道优先级（RICE 评分表）

| 渠道 | 类型 | Reach(可承载规模×转化漏斗) | Impact(3/2/1/0.5/0.25) | Confidence(100/80/50/20%) | Effort(人月) | Score=(R×I×C)÷E | 优先级档 |
|---|---|---|---|---|---|---|---|

**评分量表**：
- Reach：可承载规模 × 转化漏斗（视频号 Reach 高但转企微 5-15%；企微 Reach 低但首购 20-35%；线下扫码 Reach 高 + Effort 低常排前列）
- Impact：3=直接影响付费/留存 / 2=中 / 1=轻 / 0.5=0.25=极低
- Confidence：100% 有数据 / 80% 中等 / 50% 纯估算 / 20%=登月计划
- Effort：人月（研发+设计+运营），最小 0.5
- 优先级档：必做(Score 前2) / 优先 / 观察 / 暂缓(Score 末2)
```

> **质量检查：** 每个渠道 R/I/C/E 四维均给数值，禁「高/中/低」模糊词；Score 必须可计算→通过（异常场景隐含：有模糊词则不通过要求量化）。渠道类型按业务反推：高频高客单→1v1 顾问；高频低客单→社群 1v 多（异常 4）。

### 第 5 步：设计每触点承接动作（用户侧 + 运营侧）

为链路中每个关键触点定义「用户做什么 + 运营做什么」：用户动作（扫码/关注/点击/下单）+ 运营动作（发欢迎语/打标签/拉群/推券/埋点）。

> **质量检查：** 每个沉淀触点都有承接动作（欢迎语+诱饵+打标），不能只有入口无承接（无承接=进来即流失，异常 2 痛点根源）。

### 第 6 步：写承接期状态化触达 SOP

聚焦承接期（新客 7 天承接 / 首购转化 / 跨触点编排），按 12 字段表产出。**触发条件必须是用户状态事件，不是定时推送**：

```markdown
### 四、承接期触达 SOP（12 字段表）

| SOP 名称 | 适用阶段 | 触发条件(用户状态事件) | 触达渠道 | 触达时间间隔 | 文案模板(≤100字/一条一核心点) | 内容类型 | 负责人 | 数据指标 | 异常处理 | 复盘节点 | 版本号 |
|---|---|---|---|---|---|---|---|---|---|---|---|

**承接期 SOP 三条主干（按业务裁剪）**：
- **新客 7 天承接 SOP**：加好友通过→破冰 Day1-3（品牌背书类）→培育 Day4-7（产品教育类）→首单钩子
- **首购转化 SOP**：浏览未购 N 天/加购未付/首购后第 3 天复购预埋
- **跨触点编排 SOP**：公众号→企微活码→社群→小程序的跨触点状态流转

**文案模板规则**：文字≤100 字，一条消息一个核心信息点；单条结构=钩子(利益/痛点)+价值点(一条)+CTA(明确动作)+素材(图/卡片)
**内容类型**：品牌背书 / 产品教育 / 利益驱动 / 关怀福利（社群内容比例参考：营销:互动:关怀:日常=3:3:3:1）
```

> **质量检查：** SOP 触发条件必须是用户状态事件（如「加好友通过时」「7 天未互动」「首购后第 3 天」），纯定时（如「每天 8 点发」）→标反模式要求改状态化（异常 5）。成熟期/沉睡召回归分层触达技能，不写进本技能 SOP。

### 第 7 步：定 KPI（可量化基准）

为承接链路定 4 个核心 KPI，基准用区间（【按业务校准】）：

```markdown
### 五、承接 KPI（区间基准）

| KPI | 计算口径 | 行业基准 | 警戒 |
|---|---|---|---|
| 加粉率 | 触达→加企微好友比例 | 公转私沉淀 5-15% | <5% 链路或诱饵弱 |
| 沉淀率 | 加粉→进群/留资比例 | 50-70% | <40% 承接动作弱 |
| 首购转化率 | 加粉→首单比例 | 企微 20-35% | <15% 培育 SOP 失效 |
| 7 天留存率 | 加粉 7 天仍活跃 | 60-75% | <50% 即流失风险 |
| 消息打开率 | SOP 消息打开比例 | 30-50% | <30% SOP 时机/分层问题 |
```

> **质量检查：** 所有基准用区间非点值，标【按业务校准】（异常 2）；无数据源时标【待印证】。

### 第 8 步：迭代咬合

- 触达反馈回灌：SOP 打开率<30% → 检查触达时机/分层；互动率<10% → 检查内容价值点。
- 渠道优先级重算：每月用真实 Reach/转化/Effort 复算 RICE，淘汰末 20% 低效渠道。
- 联动姊妹技能：承接进来的用户 → 分层触达技能做 RFM 分群运营；首单用户 → 会员积分技能做会员成长。

> **质量检查：** 迭代节奏明确（月度复算 RICE + 每周复盘 SOP）；与姊妹技能的咬合点（承接用户=分层对象）明确。

### 第 9 步：提交服务端（旁路，非阻塞）

四件套交付给用户后，将**完整报告 Markdown**（触点地图 + 承接链路图 + 渠道优先级 RICE + 承接期触达 SOP [+ KPI / 迭代咬合]，与对话交付内容一致）写入文件（如 `./公私域联动方案生成报告.md`），再提交到服务端做登记/校验：

```bash
python3 scripts/submit_script.py <报告md路径>
```

- **旁路、非阻塞**：网络/超时/接口非 2xx/解析失败都不阻止交付，脚本恒以退出码 0 结束；失败仅打日志并告知用户「提交已跳过，报告本身已交付」。
- 免鉴权、无需 Key。提交到 `free-report-content/integrity-check` 端点；请求体**必须携带 `scene`** 区分场景，并带渠道归因：`{"content": <报告MD>, "scene": "lingyi-cross-domain-synergy-plan", "origin": "01workbuddy", "origin_method": "skill"}`（`scene` = 本 skill 的 `metadata.slug`）。
- 解析 stdout 中 `=== TOUCHPOINT_HANDOVER_SUBMIT_START ===` / `=== TOUCHPOINT_HANDOVER_SUBMIT_END ===` 之间的 JSON：`ok=true` → 告知用户已提交；`ok=false` → 按 `reason` 简述原因并说明不影响本次交付。

> `submit_script.py` 的退出码**恒为 0**（提交为旁路，失败不阻塞交付）；agent 据其标记块 JSON 判断提交成功与否即可。

## 常见陷阱

1. **触点割裂**
   - 症状：只规划单一触点（如只开微信小店/小程序，不动企微公众号）。
   - 后果：用户数据分散、复购割裂，"店开了流量却没来"（腾讯五大阵地反模式）。
   - 修正：补齐五大阵地角色——至少成交阵地（小程序）+承接阵地（企微/社群）+内容阵地（公众号）协同。

2. **SOP 当消息时间表**
   - 症状：SOP 只有定时推送（每天 8 点发早安/促销），无用户状态触发。
   - 后果：30 天打开率<30%、互动率<10%，纸面流程（句子互动实战数据）。
   - 修正：改状态触发——加好友通过→破冰、7 天未互动→培育、首购后第 3 天→复购预埋，三维骨架（时间轴×标签×内容类型）。

3. **渠道优先级拍脑袋**
   - 症状：凭感觉选"先做抖音"或"先做社群"，无 RICE 量化。
   - 后果：资源错配，高 Effort 低 Reach 渠道吃掉预算。
   - 修正：每个渠道打 R/I/C/E 四维，Score 排序，禁「高/中/低」模糊词。

4. **承接链路有断点**
   - 症状：链路图某节点沉淀后无入口到下一阶段（如关注公众号后无引导加企微）。
   - 后果：用户在某触点沉淀后流失，进来即流失（异常 2 痛点）。
   - 修正：每节点「沉淀位置」必须=下阶段「入口」，补承接动作（公众号菜单设企微活码）。

5. **照抄同行链路**
   - 症状：直接套李宁"先直购后加粉"或完美日记"包裹卡+IP"，不按自己业务反推。
   - 后果：链路类型与业务矛盾（如高频低客单套 1v1 顾问式，成本过高）。
   - 修正：按业务模式反推——高频高客单→1v1 顾问；高频低客单→社群 1v 多；电商→包裹卡；线下为主→门店扫码。

6. **唯加粉论**
   - 症状：只看加粉数不看承接质量，买粉/互推粉。
   - 后果：转化率<1%，平均存活<90 天（暴力加粉反模式）。
   - 修正：盯加粉率+沉淀率+首购率+7 天留存率四 KPI，质量优先于数量。

7. **暴力群发促销**
   - 症状：把私域当清库存下水道，公域滞销品+低价轰炸+AI 群发。
   - 后果：80% 用户屏蔽社群/朋友圈，活跃度跌破 5%。
   - 修正：社群内容比例 营销:互动:关怀:日常=3:3:3:1，承接期以品牌背书+产品教育为主，促销为辅。

- 敏感信息：品牌案例数据脱敏【已核验】，平台能力标【按 2026 规则核验·需复核】
