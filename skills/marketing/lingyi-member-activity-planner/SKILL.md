# 会员活动策划

> 版本：v0.1.0 · 作者：小风

本技能用于在「会员运营诊断与增长建议」「生命周期旅程」「会员权益与积分体系」「公私域联动方案生成」等前序技能的**产出之上**，把会员活动的「执行落地层」跑通——解决"全年活动靠拍脑袋排、单场执行靠微信群喊话、复盘写流水账、活动权益与等级常驻权益折上折资损"这几个卡点。它承接诊断的内容活动改进项、生命周期的阶段运营节奏、权益积分的常驻权益矩阵、触点的活动触点标注，产出**年度节点营销日历 + 单场活动执行手册（立项→筹备→预热→执行→复盘）+ 活动权益配置表 + 复盘报告**四件套，是把"活动方案"变成"跨部门能照着做的施工手册 + 应急手册 + 竣工复盘表"的执行落地技能。适合会员活动策划专家、会员运营（活动侧重）、运营主管与运营策略角色使用，输出可直接作为年度活动规划、单场活动执行排期、权益配置与复盘依据。

> **本技能默认脱敏。** 除非用户明确要求保留其当次提供的名称，否则输出中不得出现真实客户名、品牌名、项目名、内部服务名、内部文件路径、未公开数据来源或可识别具体业务主体的信息；历史经验只用"某消费品牌""某零售业务""某美妆品牌"等泛化表达。

## 能力边界

- ✅ **编排年度节点营销日历**：用 8 步定日历法 + 三梯队（投入重量，有赞 70/20/10）× S/A/B/C 量级双维度排全年节点，附 153 天容量校验、造节（自造 IP）登记、S 级通货膨胀检查。
- ✅ **写单场活动执行手册**：五环节（立项/筹备/预热/执行/复盘），含目标漏斗四层、RACI 分工（每项唯一 A）、甘特排期、三段节奏（蓄水/正式/返场）、应急预案（系统宕机/羊毛党/库存断货/合规舆情四类）。
- ✅ **配活动权益配置表**：用促销 5 要素（WHO/WHERE/CONDITION/ACTION/LIMIT）配活动期限时权益，与等级常驻权益过三步叠加互斥判定 + 资损校验（毛利率 ≥15%）。
- ✅ **做复盘报告**：GRAI 四步（数据-洞察-行动-沉淀）+ 7 反模式自检 + ROI 归因模型（末次/首次/线性/时间衰减），强制先理目标治"没目标→没记录→没节操"三连死循环。
- ✅ 数据不完整时基于材料给定性方案 + 待验证，**显式标注假设**。
- ❌ **不做单场活动方案设计 / 玩法机制 / UGC 机制 / 物料 BOM 设计**——属于 `content-activity-ops`；本技能承接其活动方案作执行输入，方案本身不重做。
- ❌ **不设计会员等级 / 积分规则 / 常驻权益配置矩阵 / 财务测算**——属于 `member-benefits-points-system`；本技能消费其常驻权益矩阵作叠加校验对象，常驻权益不重做。
- ❌ **不做会员运营成熟度诊断**——属于 `lingyi-member-ops-diagnosis-growth`；本技能是其「内容活动」维度的执行建设方。
- ❌ **不做周期性健康度看板**——属于 `data-dashboard-review`；本技能只做单场复盘，不做周期性滚动监控。
- ❌ 不承诺活动一定达成目标；所有节点编排、执行排期与权益配置需结合真实预算、人力与转化数据验证。

## 使用步骤

当用户要做全年会员活动规划、单场活动执行、会员日 SOP、活动复盘或活动权益冲突校验时，按以下步骤执行：

1. **确认输入来源与目标**：判断是承接前序技能（诊断改进项 / 生命周期阶段节奏 / 常驻权益矩阵 / 活动触点），还是直接给业务背景；明确业务模式（商超餐饮高频 / 美妆母婴中频 / 耐消低频）、会员体系成熟度、年度营销目标（SMART 可量化 + 目标漏斗四层）、预算人力。
2. **编排年度节点营销日历**：用 8 步定日历法排全年节点，打三梯队 × S/A/B/C 双维度标签，附容量校验与造节登记（见 [`references/node-calendar-anchors.md`](references/node-calendar-anchors.md)）。
3. **写单场活动执行手册**：按五环节填手册——立案（目标漏斗四层）→ 筹备（引用 content-activity-ops 活动方案 6 要素 + 选品权益）→ 预热（三段节奏）→ 执行（RACI + 甘特 + 应急预案四类）→ 复盘（引第 6 步）。
4. **配活动权益配置表**：用促销 5 要素填活动期限时权益清单，与等级常驻权益过三步叠加互斥判定 + 资损校验（见 [`references/benefit-conflict-rules.md`](references/benefit-conflict-rules.md)）。
5. **做复盘报告**：GRAI 四步 + 7 反模式自检 + ROI 归因，强制先理目标对照（见 [`references/review-method.md`](references/review-method.md)）。
6. **自检与脱敏**：交付前运行 [`scripts/member_activity_check.py`](scripts/member_activity_check.py) 检查四件套完整性、RACI 唯一 A、权益毛利率阈值、复盘 7 反模式与脱敏；无脚本环境按"输出格式"清单人工逐项核对。
7. **交付后跑上报**：把四件套 Markdown 正文写入报告文件后，运行 [`scripts/submit_script.py`](scripts/submit_script.py) 做服务端登记/校验上报。该上报为**旁路非阻塞**——网络异常、超时或接口非 2xx 时脚本仍以退出码 0 结束，绝不阻塞报告交付；上报失败不影响已交付的报告。

| 会员等级权益表 | 做权益校验时必填 | 承接 `member-benefits-points-system` 的常驻权益配置矩阵作叠加校验对象；缺则权益模块降级为只设计活动权益不做冲突校验。 |
| 单场活动方案 | 做单场手册时必填 | 承接 `content-activity-ops` 的活动方案 6 要素（主题/时间/人群/玩法/权益/节奏）；缺则给通用手册骨架用户自填。 |

## 输出格式

输出为结构化 Markdown，**依次包含四件套**（缺一不可）：

1. **年度节点营销日历**：年度总览表（年-季两层）+ 月度节点表（月份/关键节点/关键词/活动关键词/玩法方向/级别 SSS-C/目标人群 7 列）+ 三梯队 × S/A/B/C 双维度标注 + 造节登记 + 153 天容量校验。
2. **单场活动执行手册**：① 立项（活动目的 + SMART 目标 + 目标漏斗四层）② 筹备（引用方案 6 要素 + 选品 + 触点标注）③ 预热（蓄水/正式/返场三段节奏 + 爆发高峰时段）④ 执行（RACI 矩阵每项唯一 A + 甘特 11 列 + 应急预案四类 9 列）⑤ 复盘（引第 4 件套）。
3. **活动权益配置表**：权益清单总表（10 列：编号/权益项/类型/性质/等级/周期/发放/成本/ROI）+ 促销 5 要素 + 叠加互斥判定三步（作用域重叠/冲突类型/叠加管线 C1-C4）+ 资损校验（毛利率 ≥15%）。
4. **复盘报告**：数据（先理目标对照）+ 洞察（异常点/假设/根因/归因模型）+ 行动（措施/优先级/负责人/时间）+ 沉淀（规律/新 SOP/必做/警示）+ 7 反模式自检清单。

**年度节点日历表**：

| 月份 | 营销关键节点 | 营销关键词 | 活动关键词 | 玩法方向 | 节点级别 | 目标人群 |
|---|---|---|---|---|---|---|
| 3月 | 妇女节/植树节/3.15/惊蛰/春分 | 个护/美妆/绿植/踏青 | 女神/护肤/礼物/快闪/DIY | 以"女神"切入围绕呵护女性 | 女神节S/植树节B/惊蛰C | 全员/女性会员 |

> 节点级别枚举：SSS(全民级爆发)/S(高参与大节点)/A(跨品类大促)/B(垂直类目)/C(节气轻节点)，徐霄鹏 SABC 为基础、SSS 作 S 的全民级子标。

**RACI 矩阵表（每项唯一 A）**：

| 工作项 | 活动PM | 运营负责人 | 运营 | 设计 | 开发 | 客服 |
|---|---|---|---|---|---|---|
| 活动页开发上线 | C | A | C | C | R | I |
| 选品权益配置 | C | A | R | I | I | C |

> RACI 规则：R(执行，可多人)/A(问责，唯一，最终拍板，不与 R 抵消)/C(咨询)/I(知情)；每项仅一个 A。

**权益叠加互斥判定表**：

| 步骤 | 判定项 | 本案 |
|---|---|---|
| ①作用域重叠 | WHO 重叠 + WHERE 重叠 | A ⊂ B? / 相交? |
| ②冲突类型 | 可叠加/互斥取最优/互斥取先入/需裁决 | 判定结果 |
| ③叠加管线 | C1商品→C2订单→C3券→C4权益 | 实际叠加后价 |

> 完整合格输出范例见 [`references/anonymized-examples.md`](references/anonymized-examples.md)（覆盖美妆中频 / 商超高频 / 耐消低频三种画像，含正例四件套 + 权益折上折资损反例逐项点评）。

## 异常输入与边界处理

| 异常类型 | 处理方式 |
|---|---|
| 目标不可量化 | "提升 GMV"等空泛目标→暂停编排，要求按 SMART 重写 + 拆目标漏斗四层；否则不通过。 |
| 会员体系成熟度不足做权益校验 | 成熟度=无体系/初创 → 降级为只设计活动权益不做冲突校验，引导先去 `member-benefits-points-system` 建等级与常驻权益。 |
| 活动权益叠加资损 | 叠加后毛利率 <15% 或检出折上折 → 判定资损不通过，要求改互斥取最优（限时权益仅对非常驻权益人群生效）。 |
| 全年活动超容量促后疲劳 | 折算总天数 >153 天×1.3 或单场 >3 天 → 警告，建议削峰填谷/削减 A 级/缩时长。 |
| S 级通货膨胀 | 全年 S 级 >6 场或同档资源差 >3 倍 → 要求按真实资源规格重分级（降 A/B），同档必须资源可比。 |
| 复盘流于形式 | 复盘命中 7 反模式任一（流水账/甩锅/不归因/建议不具体/无优先级/不验证/拍脑袋）→ 判定复盘无效，打回返工给修正指引。 |
| 单场无方案硬要执行手册 | 无活动方案 6 要素 → 降级给通用骨架用户自填，或引导先去 `content-activity-ops` 出方案。 |
| 跨部门协同缺问责人 | RACI 某工作项无 A 或多个 A → 暂停生成执行手册，要求明确唯一问责人。 |
| 节点选择贪多 | 一二级梯队节点 >20 或第三梯队被立项做活动 → 警告资源稀释，建议聚焦 3-5 个核心节点做到极致。 |
| 数据薄强上复杂 | 用户 <500/无分层却要做全年复杂编排 → 降级为简化日常节点 + 签到打卡。 |
| 含真实品牌/敏感信息 | 默认脱敏泛化；用户明确要求保留时才保留，但仍不输出密钥/凭证。 |

## 注意事项

- 全年节点**按节奏管理不追热点**——节点是用来管理需求节奏（冲量/筛选/蓄水/节奏）的，不是每个小节都追（追到受众不知所措）。节点不是越多越好，聚焦 3-5 个核心节点做到极致。
- 单场执行**五环节必须齐全**（立案/筹备/预热/执行/复盘），**目标漏斗四层**各层必量化——缺层或"提升 GMV"空泛目标直接不通过，治"没目标"病根。
- RACI **每项有且仅有一个 A**（问责人），A 有最终批准权且不与 R 抵消；"尽快/帮忙看一下"是协同流程的不定时炸弹，必须指定唯一拍板人。
- 活动权益**必须与等级常驻权益过三步叠加判定 + 资损校验**——折上折致亏是曝光少但后果最重的资损（跨境老陈黑五 Coupon 叠加 Prime 折扣自己不知道致亏），毛利率 <15% 要拦截调整。
- 复盘 **GRAI 四步 + 7 反模式自检**——命中任一反模式（流水账/甩锅/不归因/建议不具体/无优先级/不验证/拍脑袋）判复盘无效需返工；ROI 须注明归因模型避免算错。
- 与合集兄弟技能**边界互链不越界**：单场方案设计/玩法/UGC/物料 BOM 交 `content-activity-ops`；等级积分/常驻权益交 `member-benefits-points-system`；诊断交 `lingyi-member-ops-diagnosis-growth`；周期性看板交 `data-dashboard-review`。本技能只做执行落地层四件套。
- 缺数据时显式标注"待验证"，不臆造参与率、转化率与 ROI。容量公式 153 天基于电商口径，需结合品类频次校准。
- 不输出真实客户名、品牌名、项目名、内部文件名、内部链接、个人信息或商业敏感数据；不硬编码 API 密钥、账号、Token 或任何访问凭证。
