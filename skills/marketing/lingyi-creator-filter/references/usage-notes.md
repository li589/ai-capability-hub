# 达人匹配 交互与口径说明

本文件补充 SKILL.md 里不便展开的交互约定与扣点口径，供助手核对。接口字段细节见 [api.md](api.md)。

## 核心定位

- **核心提示词在后端**，前端 skill 只做用户层引导与控制：初始引导 → 读配置 → 填参数发起任务 → 轮询 → 交付渲染好的 Markdown 报告。
- skill 侧**不做报告模板**，报告正文由后端渲染（`data.markdown`），助手只负责真正把它渲染给用户。

## 会话防中断：连续轮询循环

WorkBuddy / Web 端单轮对话有时长上限，达人匹配任务重、可能 5–10 分钟甚至更久。**禁止**一次性同步调脚本阻塞到完成（会被中断打断、用户拿不到报告）。也**禁止给一次进度就停下来**——用户会以为断了。固定走「创建 + 连续短轮询循环」：

1. `--estimate-only` 创建任务 → 立即拿 `CREATOR_MATCH_TASK_ID` + 预计扣点（退出码 0，不轮询）。
2. 用户确认后，立即开始连续轮询循环：跑 `--task-id <id>` → 给用户一句话进度 → 判断结果 → 非终态就**立即**再跑 `--task-id <id>` → 循环直到终态。
3. **绝对不许跑一次 `--task-id` 给一句进度就停下来**——那样用户会以为断了。每次非终态返回后，给一句简短进度就立刻再跑下一轮。
4. 轮询期间用户可随时插话，用最新一次轮询结果自然回应即可，回应后继续轮询循环不停。

## 扣点口径（三态贯穿）

达人匹配要研究**多个候选达人账号 × 多个达人视频**，点数消耗非常大且会浮动。整条链路对用户的扣点感知由助手贯穿：

- **执行前确认（必做，跳过不得）**：读配置、信息收集（达人数 1～10、产品名称和核心卖点必填）、账号名准确性确认、API Key 就绪后，先 `--estimate-only` 拿到 `CREATOR_MATCH_ESTIMATE_POINTS`（服务端返回用真实值，否则按 **198 × 候选达人数** 估算），再向用户发起确认话术——明确「需要逐个读取达人账号视频数据、平均每读取一个达人约 198 点、达人越多点数越巨大、会随达人视频数量浮动、任务已创建、确认后即继续扣点、最终以服务端实际扣点为准」。**等用户明确确认后再用 `--task-id` 轮询**；未确认、未回应、含糊或要求改主意时**不轮询**。
- **执行成功后回告实扣**：`completed` 后把 `CREATOR_MATCH_POINTS_USED` 非空时如实告知「本次实际扣除 N 点」；为空时回退预估口径「本次约扣 N 点（约 198 点 × 达人数），实际以服务端扣点为准，可在 01Claw 账户查看」。
- **执行失败/超时后告知返还**：任务已发起但未成功产出报告（`failed` / `timeout` / 网络 5xx），统一告知「因网络原因本次任务执行失败，相应点数已返还」并询问是否重试；`timeout` 附 `task_id` 可 `--task-id` 恢复。
- **任务未发起到位**（缺 key / 参数非法 / 余额不足）**不涉及扣点**，正常引导修正。

## 进度转述

- 状态 `pending`/`running` 时每轮把 stderr 进度行（状态/已等待时长/progress_message，无细节时每 30s 保活一行）用人话转述，例如「正在筛选，已等约 2 分钟，服务端处理中，稍候…」。**全程不沉默**。
- **核心铁律：非终态 = 立刻再跑一轮 `--task-id`，不许停。** 给一句进度后必须继续轮询，不能停下来等用户说话。
- 用户中途问进度，就现查 `--task-id` 转述后**立即续轮询**，不要停下等用户。**禁止**回复「查不了任务状态 / 没有 task_id」——创建后立刻有 task_id 与进度。

## 报告渲染（硬性交付要求）

针对「有时没渲染为 md」做三重保险：

1. **脚本侧**：优先取 `data.markdown`；缺失时对结构化结果兜底渲染；**三级落盘**（`--out` → 工作目录 → `/tmp`），`CREATOR_MATCH_REPORT_FILE` 非空即落盘成功。
2. **SKILL 侧硬性要求**：交付时**必须**截取 `=== CREATOR_MATCH_REPORT_START ===` 与 `=== CREATOR_MATCH_REPORT_END ===` **之间**的正文，**作为 Markdown 渲染到对话**——不包代码块、不只给路径、不用摘要替代全文、不贴 `===` 分隔符与 `*_=` 协议行。正文过长也至少完整渲染前 2–3 个二级标题并说明完整报告已落盘，能放下优先**完整渲染**。
3. **拆分轮询防会话中断**（见上），避免报告还没拿到会话就被打断。

> 报告正文由后端渲染，从 `# 达人匹配分析报告` 起步。助手直接渲染即可，不要二次加工、不要改写表格。

## API Key

取技能目录下 `config.json` 的 `LY_API_KEY`（回退环境变量 `LY_API_KEY`）。缺失引导用户前往 <https://claw.lingyishuke.com/webapps/01claw-auth/index.html?source=01workbuddy> 获取并写入；该文件已 `.gitignore` 忽略。鉴权失败（退出码 3）重新获取覆盖写 `config.json` 后重试。SSL 证书错误可设 `LY_SKIP_SSL_VERIFY=1`（临时、受控环境，有中间人风险）。
