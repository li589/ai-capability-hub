# 经营模式：结构与转化参考

经营模式决定用户要完成什么、需要哪些证据、页面范围和关键能力；行业还会改变哪些经营变量最值得先确认。先理解行业中的真实交易与履约，再决定页面结构。以下内容是**候选判断维度和路径，不是固定分类或菜谱**。

## 动态探索

不要依次问完一套问题。先从用户已提供的行业、主体、商品/服务和场景事实中形成 1–3 个候选经营假设，再选择一个最可能改变页面结构、主行动、导航或证据顺序的未知项追问。每次回答后重新判断；剩余不确定性不会改变当前页面决策时停止。

按行业动态选择判断维度，只使用会造成决策分叉的部分：

- **主体与经营拓扑**：单主体、单店、多店/连锁、多商户平台，或买卖双方等多角色；
- **渠道关系**：纯线上、线下为主、线上获客线下履约、到店+到家等混合关系；
- **履约与地域**：快递、即时配送、自提、到店、上门、预约、企业交付，以及位置是否改变库存、价格或服务；
- **交易目标**：立即购买、比较、预约、询价、订阅、申请加入、参团或寄售；
- **供给与风险证据**：库存、时效、人员、资质、地点、MOQ、批次、流程、佣金或结算。

这些维度不是必填字段，结果也非互斥。单店可以同时是线上预约+线下服务，连锁可以同时提供到店、自提和到家；某些 B2B 或平台业务中，角色、账期和交付能力比“有几家店”更先决定结构。

行业决定第一问。例如：

- 餐饮/零售若地点改变供给，先确认单店/多店以及到店、自提、配送关系；
- DTC 品牌若默认线上成交，先确认一次购买/订阅及是否存在影响履约的线下触点，不必先问门店数；
- 医疗、美业或教育服务先确认服务地点、人员/机构关系与预约闭环，不从购物车开始；
- B2B 批发先确认采购角色、MOQ/询价和交付范围，门店拓扑可能无需追问。

把结论写成带依据的当前假设，并保留会影响页面的未知项；不得把行业常识写成用户已确认事实。

## 结构选择原则

- 首页优先展示本模式最关键的用户动作和证据，不要求营销、商品、内容、会员全部出现。
- 页面数和导航项按任务决定；没有购物车的业务不放购物车，没有多店的业务不放门店切换。
- 模式名称只用于解释结构，不要求从下表选出唯一标签；组合业态可以同时引用多行，但必须说明主次关系。
- “核心能力”可以由内置组件、多个组件组合或局部 custom 表达，不因缺少某个组件名而改变业务结构。
- 数据必须具体可信：距离、时段、MOQ、箱规、税费、日期、佣金、服务量、结算节点等不能只写口号。

## 模式总览

| 模式 | 首页优先问题 | 关键证据/状态 | 常见主行动 |
| --- | --- | --- | --- |
| 纯线上网店 | 有什么值得买，如何找到 | 商品、价格、库存、物流、售后 | 浏览 / 加购 / 购买 |
| 连锁多门店 | 哪家店适合我 | 当前门店、距离、营业时间、库存或服务差异 | 选店 / 到店 / 下单 |
| 单店 | 今天是否值得来、怎么来 | 地址、营业时间、今日供应、环境或服务事实 | 导航 / 致电 / 预约 |
| O2O 到店+到家 | 现在能否送到或自提 | 定位、配送范围、时效、起送价、自提状态 | 到家 / 自提 / 到店 |
| 服务预约 | 谁来服务、何时可约、结果是否可信 | 服务项目、人员、资质、时段、案例、流程 | 预约 / 咨询 |
| 分销/加盟 | 值不值得加入、如何获益 | 佣金、门槛、政策、培训、结算、案例 | 申请加入 / 查看政策 |
| 社区团购 | 何时截单、哪里提货、是否成团 | 团长、自提点、成团门槛、到点、退款、核销 | 参团 / 选自提点 |
| B2B 批发 | 能否稳定供货、成本多少 | SKU、箱规、MOQ、阶梯价、库存、交期、账期、发票 | 询价 / 加采购单 |
| 跨境预售 | 什么时候到、总成本与风险 | 原产地、批次、截单、税费、定金尾款、清关、退款 | 付定金 / 订阅到货提醒 |
| 周期订阅 | 订什么频率、如何调整 | 方案、周期、首期/续期金额、下次扣款、暂停跳过 | 选择计划 / 开始订阅 |
| 鉴定寄售 | 如何鉴定、卖出后如何结算 | 鉴定报告、成色、瑕疵、进度、佣金、结算日 | 免费估价 / 提交寄售 |

## 1. 纯线上网店

**UX 核心**：让用户快速理解品牌主张、找到适合的商品并放心购买。

可选首页内容：品牌 campaign、搜索/分类、主推系列、新品或场景选购、商品比较、材质/配方、评价、物流售后、会员。高端品牌可以弱化优惠和商品密铺，综合商城可以强化搜索、分类和促销。

候选页面：home、category/search、detail、cart、me。只有业务需要时才全部创建。

避免：默认“大促 Hero + 四宫格 + 双商品组 + 会员卡”；把所有网店都做成同一促销商城。

## 2. 连锁多门店

**UX 核心**：尽早确认当前门店，并让用户理解门店之间的距离、库存、服务或活动差异。

可选首页内容：当前门店/切换入口、附近门店、门店专属供给、统一权益、到店/到家能力、门店活动。门店切换是否置顶取决于位置是否影响后续价格和库存。

候选能力：`wa-store-switch`、门店列表、定位、门店详情、统一会员。

避免：只有一句“全国 N 家门店”却没有选店路径；把连锁页做成无位置上下文的网店。

## 3. 单店

**UX 核心**：回答“今天有什么、在哪里、什么时候营业、值得不值得来”。

可选首页内容：门店身份、今日菜单/项目、地址与营业时间、空间/人物照片、招牌商品或服务、活动、导航、电话或预约。通常不需要复杂分类和多页商城。

候选页面：home + detail/booking + me，或仅单页落地。

避免：硬凑五页、购物车和门店切换；把地址、营业时间埋到页尾。

## 4. O2O 到店+到家

**UX 核心**：先确定地点和履约方式，再展示可售内容。

可选首页内容：定位、到店/到家/自提切换、预计送达、配送范围、当前门店、即时优惠、商品或菜单、购物车状态。

候选能力：`wa-take-away`、location、store、goods、cart/buy bar。

避免：不说明配送范围和时效；把到店与到家混成一个不明确的 CTA。

## 5. 服务预约

**UX 核心**：先建立专业信任，再降低选择人员、项目和时间的成本。

可选首页内容：服务结果与边界、项目/套餐、服务人员、可约时段、资质、过程、案例、评价、地点或上门范围、预约入口。服务图片、人员和空间图片在提供真实信任时应使用。

候选能力：`wa-service-reservation`、store/person list、calendar/time slot、location、case/testimonial custom。

避免：使用秒杀和购物车语言替代预约；只列价格，不解释人员、时长、流程和风险边界。

## 6. 分销/加盟

**UX 核心**：解释加入价值、门槛、收益计算和持续支持。

可选首页内容：项目定位、适合人群、收益模型、政策、培训、案例、分佣商品、申请流程、常见问题。面对加盟商和普通消费者时应拆分入口。

候选能力：`wa-distribution`、政策卡、收益示例、申请表。

避免：只写高佣金，不写成本、条件、结算与风险；消费者首页和招商首页混用同一主 CTA。

## 7. 社区团购

**UX 核心**：让买家理解成团与履约，让团长理解验货、核销和佣金职责。

可选首页内容：附近团、自提点、截单时间、成团门槛、到点时段、商品、退款说明、团长信息。团长中心应独立呈现订单、验货、核销、售后和结算。

候选能力：`wa-distribution-community-group`、时间线、自提点、提货码、团长中心。

避免：退化为普通“几人拼团”；不说明未成团退款、提货和核销。

## 8. B2B 批发

**UX 核心**：让采购者快速判断“有没有、多少钱、多少起订、何时到、能否长期稳定”。

可选首页内容：搜索、品类/SKU、箱规、MOQ、阶梯价、库存、交期、配送区域、履约指标、资质、客户案例、询价摘要。可以直接以工具式搜索和数据面板开场，不需要装饰性 Hero。

候选能力：goods/catalog、筛选、规格矩阵、采购单、询价表、履约看板。

避免：只显示零售价和普通购物车；大篇品牌叙事挤占采购关键信息。

## 9. 跨境预售

**UX 核心**：解释批次、时间、到手成本和异常处理。

可选首页内容：当前批次、原产地、截单/到仓时间线、含税价、定金尾款、实名清关、在途状态、到货通知、退款规则。

避免：只写“海外直邮”与低价；税费、日期和定金口径模糊。

## 10. 周期订阅

**UX 核心**：让用户比较方案、理解续费节奏，并相信可以控制订阅。

可选首页内容：订阅价值、适合人群、方案比较、内容/配方、配送周期、首期与续期金额、下次扣款、暂停/跳过/更换、评价、开始订阅。

候选页面：home、plans、detail、subscription-management、me。

避免：只说“更省心”，不展示频率、下一箱、金额和调整入口；用普通会员卡代替订阅管理。

## 11. 鉴定寄售

**UX 核心**：降低对真伪、估价、瑕疵披露、流转和结算的担忧。

可选首页内容：免费估价入口、支持品类、鉴定流程、真实报告样例、成交案例、佣金、寄售时效、进度状态、结算规则。买家侧与卖家侧可分入口。

候选能力：估价表、鉴定护照、成色/瑕疵报告、寄售时间线、结算中心。

避免：只有“正品保障”；不披露佣金、退回规则和结算节点。

## 交叉检查

完成结构后问：

- 删除行业名称后，这个页面是否仍能看出经营模式？
- 删除视觉样式后，信息顺序是否仍能完成主任务？
- 首页最显眼的能力是否真的是本模式的核心，而不是通用营销组件？
- 是否存在与业务无关的购物车、会员、门店或优惠模块？
