# 页面类型与模块候选

本文件帮助设计师和实施者检查页面职责，不提供固定组件序列。结合用户目标、经营模式和实时画布，从候选模块中选择真正服务当前任务的内容。**候选不是必选，顺序也不是默认顺序。**

## 起手选择

| 场景 | 建议起手 |
| --- | --- |
| 多页站点且有高度匹配的整站模板 | 读取资源 digest 作为共享设计起点；当前页仍按设计稿直接搭建 |
| 非首页且有匹配内置页 | 只试最匹配的一个 `manage_page(action=add, from=...)`，看真实画布后判断局部调整、保留任务结构整体换内容主题，或放弃并从零搭建 |
| 无匹配模板、品牌差异大或强叙事页面 | 从设计稿逐 section 映射 |
| 已有页面局部修改 | 保留画布，少量增删和 `update_component` |

模板只是起点。出现明显品牌、经营模式或内容差异时，允许大幅调整，不以保留模板结构为目标。

## 页面通用检查

每页先回答：

1. 用户为什么进入这页？
2. 页面结束时要完成什么动作？
3. 用户在行动前必须知道哪些事实？
4. 哪些内容适合文本、数据、图片、视频、列表或交互？
5. 哪些内容属于其他页面，不应在这里重复？

`wa-bottom-nav`、`wa-buy-bar`、`wa-fix-nav` 等单例和互斥关系以最新组件 instructions 为准。

## 1. 首页 / 品牌入口

### 核心职责

建立主体与价值，帮助用户进入最重要的路径。首页不等于“把所有功能都放一遍”。

### 候选模块

- 品牌论点或任务入口；
- 搜索、定位、门店切换、到店/到家切换；
- 主推商品、系列、服务、方案或 SKU；
- 分类、场景、问题或人群入口；
- 价格、优惠、会员或订阅价值；
- 人物、空间、过程、案例、评价或资质；
- 履约、物流、时效、售后和风险说明；
- 主 CTA、次 CTA、底部导航。

### 常见变体

- **品牌电商**：媒体与系列叙事优先，商品数量可少；
- **综合商城**：搜索、分类、活动和商品效率优先；
- **单店**：今日供应、地点和营业信息优先；
- **服务预约**：项目、人员、案例和时段优先；
- **B2B**：搜索、规格、供货和询价优先；
- **订阅**：方案比较、节奏和控制权优先。

### 反模式

固定渐变 Hero、信任四项、优惠券、四宫格、双商品组、会员卡和底部导航全部出现；为达到模块数复制商品区。

## 2. 列表 / 搜索 / 分类

### 核心职责

让用户缩小选择范围并保持上下文。

### 候选模块

搜索、面包屑/当前分类、筛选、排序、标签、商品/服务/SKU 列表、库存或距离、已选条件、空状态、加载状态、购物车/询价摘要。

### 设计判断

- 宽品类商城强调搜索和筛选；
- 高端品牌系列页可以用编辑式大卡和少量产品；
- B2B 列表要显示箱规、MOQ、含税价和库存；
- 服务列表要显示人员、时长、地点或可约状态；
- 门店列表要显示距离、营业和服务差异。

## 3. 商品 / 服务 / 方案详情

### 核心职责

完成比较、风险消除与行动。

### 候选模块

主媒体、标题与价格、规格/方案、关键利益、库存/时段、配方/材质、详情、案例/评价、履约与售后、相关内容、购买/预约/询价 CTA。

### 设计判断

- 商品详情可以使用 `wa-buy-bar`；服务详情可能需要预约或咨询固定栏；两者不必共用购物车语言。
- 订阅详情同时展示单次与周期金额、频率、下一次扣款和暂停规则。
- B2B 详情优先箱规、MOQ、阶梯价、交期和采购量，不以零售详情顺序为模板。
- 二手商品详情需要全貌、瑕疵、鉴定和附件证据。

## 4. 预约 / 询价 / 提交

### 核心职责

以尽量低的认知负担收集完成服务所需的信息。

### 候选模块

当前选择摘要、人员/门店/项目、日期和时段、数量/规格、联系人、地址、备注、费用说明、隐私说明、提交 CTA、成功/失败状态。

### 设计判断

先展示用户正在提交什么，再让用户填信息；字段按履约需要精简。复杂 B2B 询价可以分步，简单服务预约不必做长表单。

## 5. 营销活动 / Campaign / Landing

### 核心职责

围绕一个受众、一个主张和一个行动建立连贯论证。

### 候选模块

campaign 媒体、核心利益、产品/服务、机制、证据、使用场景、评价、规则、FAQ、主 CTA。可以没有底部导航。

### 设计判断

活动页不等于优惠券堆叠。品牌发布、招募加盟、订阅转化、门店开业和服务咨询可以有完全不同的叙事结构。

## 6. 个人中心 / 企业中心 / 团长中心

### 核心职责

让用户看见自己的身份、资产、订单、状态和下一步任务。

### 候选模块

账户身份、会员/企业资质、订单、预约、订阅、寄售、优惠、地址、收藏、客服、设置。多角色业务应为不同角色设计不同中心。

### 设计判断

- 消费者中心强调订单、权益和售后；
- 企业采购中心强调采购单、询价、合同、发票和账期；
- 团长中心强调验货、核销、售后和佣金；
- 寄售中心强调估价、鉴定、上架、售出和结算状态。

## 7. 订单 / 履约 / 状态页

### 核心职责

解释当前状态、下一节点、异常处理和可执行动作。

### 候选模块

状态标题、时间线、订单/服务摘要、金额、物流/预约/自提信息、联系人、凭证、取消/退款/改期、客服。

### 设计判断

状态必须使用具体日期、地点和动作；不要只写“处理中”。跨境、团购、订阅和寄售的时间线节点不同，应由经营模式决定。

## 结构自检

- 每个 section 是否解决一个明确问题？
- 是否把首页当成所有页面的拼盘？
- 页面是否在用户需要时才出现证据、价格和 CTA？
- 删除某个模块后，决策路径是否仍完整？若完整，该模块可能是填充。
- 页面之间是否各司其职，而不是重复相同商品和信任条？
