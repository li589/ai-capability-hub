# 演示设计技法：从 UX 到 UI

本文件提供判断框架，不提供可直接套用的成品页面。设计师应从 brief、真实品牌和内容资产建立系统，避免复制固定 Hero、卡片组合或“行业皮肤”。

## 一、先 UX 后 UI

### UX 画布

设计前用一句话回答每项：

- **核心用户**：谁在什么处境进入页面？
- **页面任务**：用户离开前应完成什么？
- **决策路径**：用户依次需要理解、比较和确认什么？
- **证据**：用户会怀疑什么，什么事实能消除疑虑？
- **行动**：主 CTA、次 CTA 和失败/退出路径是什么？
- **内容资产**：哪些事实、图片、数据和案例真实可用？
- **section 职责**：每个区块只负责一个主要问题。

不要先画模块，再为模块寻找内容。没有真实内容支撑的 section 应删除或改成更合适的表达。

### UX 自检

- 页面前两屏是否已经建立主体、价值和下一步？
- 用户产生疑虑前是否看到了证据？
- 主行动是否清晰，次行动是否抢夺注意力？
- 模块顺序是否符合当前用户，而不是参考案例？
- 是否存在只为增加“饱满度”而出现的模块？
- 是否根据经营模式展示了关键状态、时间、地点、价格和风险？

### 从主题世界取材

视觉身份来自主体自己的主题世界：真实材料、工具、空间、动作、包装、行业语言和用户习惯。配色、排版、媒体、结构与动效至少要能指向其中的具体依据，而不是先选一种流行风格再套行业文案。

如果 brief 尚未明确品牌、行业或经营模式，返回启动信息门槛补齐或可靠推导；不得为了具体化而编造品牌、行业或经营事实。可以提出有依据的设计假设，但必须与用户事实区分。

## 二、建立 UI 方向

### 方向依据

按以下顺序建立视觉：品牌资产 → 用户指定 → 产品/内容特征 → 经营模式 → 行业语境。行业只是最后的校准，不是第一张 moodboard。

在 manifest 中写清：

- `brandBasis`：用了哪些品牌线索；
- `mediaStrategy`：图片、数据、排版、图形各承担什么；
- `layoutConcept`：一句话说明版式逻辑；
- `typeRoles`：标题、正文、数据/标签如何区分；
- `tokens`：共享色、支持色、间距、圆角和阴影；
- `signature`：可选，为什么值得记住；
- `motion`：可选，动效反馈什么。

### 避免默认模板

除非有明确理由，不自动采用：

- 渐变背景 + 徽章 + 大标题 + 胶囊 CTA；
- 四项图标信任条；
- 四宫格分类；
- 连续两组相同商品卡；
- 深色会员卡作为“高级感”；
- 所有区块白卡 + 同一圆角 + 轻阴影；
- 暖奶油、近黑酸色、报刊细线等流行风格的无理由复刻。

### 明确视觉立场

- **Hero 是页面命题**：首屏用主题世界中最有代表性的内容说明“这是谁、为什么值得继续”，可以是标题、人物/商品、空间、数据或局部演示；不要默认使用大数字、统计卡和渐变点缀。
- **排版承担品牌个性**：Display、Body、Data/Utility 的字形气质、字重、字宽、行距和字距要形成有意的对比；字体选择必须可加载并有可靠回退。
- **结构装置必须编码真实信息**：眉题、编号、标签、分隔线和时间轴要表达类别、状态、层级或顺序。编号只用于真实顺序，不把 `01/02/03` 当作无意义装饰。
- **复杂度必须匹配视觉方向**：极简方向靠精确间距、排版和细节成立；丰富方向需要足够的层次与执行，不把两者折中成通用卡片页。
- 选择一项可解释的视觉冒险，并说明它如何强化 brief；只把大胆用在一个地方，其余元素保持克制，不以可读性、任务路径或移动端稳定性换取新奇。

在进入实现前做一次反模板检查：如果这套配色、排版、Hero、结构和签名选择在替换品牌和行业后仍然成立，修改至少一个关键选择，并记录新的主题依据。

## 三、媒体策略

### 何时使用真实图片

图片应承担至少一种不可替代的信息：

- 商品、材质、质地、细节；
- 品牌 campaign 或人物关系；
- 门店、空间、地点和环境；
- 服务人员、过程和案例；
- 生活方式、产地、制造或履约；
- 鉴定、瑕疵、成果与状态证据。

当图片只是在重复标题、填空或制造模糊氛围时，改用排版、数据、图形、色块或留白。

### 图片编排

- 先决定图片角色，再决定比例；不要把所有媒体裁成相同方形。
- Hero 媒体可以是全幅、分栏、局部裁切、序列或无图；由内容决定。
- 商品图保持比较一致；人物、空间和故事图可以使用不同节奏。
- 多张素材先统一展示逻辑，避免因原图比例不同造成跳动。

### 图片质量审查重点

Reviewer 只根据最终真实截图检查会影响销售演示的图片问题，只报告 blocker/major：

- **主体与业务文案**：主体的品类、年龄、性别、场景和用途必须与标题及卖点一致，不能用相近但错误的公共素材替代。
- **清晰度与压缩**：在 375px 视口检查模糊、像素化、明显压缩噪点、拉伸变形、坏图和水印；关键 Hero 或商品图出现这些问题至少记为 major。
- **裁切与构图**：不得裁掉人物脸部、关键商品、品牌识别或演示所需的界面区域；文字叠加区应有足够留白和对比。
- **跨图一致性**：同页或同一业务路径中的摄影风格、光线、背景、色温和比例不能明显冲突。
- **模板感与重复素材**：避免同一公共图片无意义重复，或使用过于通用、与品牌无关的图库图导致页面像占位模板。

每条结论必须包含具体页面、区域和截图证据，说明可见问题及其对演示的影响。整页概览只用于全局构图，图片细节必须在 `components.json` 绑定的完整顶层组件图中确认。若搜索得到的公共图片触发上述问题，且定向生成更可能得到匹配素材，标记“建议 AI 生图替换”；Reviewer 只报告，不自行生成或询问用户。

## 四、排版与层级

### 角色

至少建立三种角色，但不一定使用三种字体：

- **Display/标题**：品牌语气与主张；
- **Body/正文**：快速阅读与解释；
- **Data/价格/状态**：比较和扫描。

通过字号、字重、字宽、行距、字距和数字特性建立区分。不要仅靠颜色区分层级。

### 文案密度

- 品牌叙事可用短句和留白；
- 工具型/B2B 页面可以更密，但要通过栅格、对齐和标签提高扫描效率；
- 重要数字必须带单位和口径；
- 长段说明拆成问题、步骤或证据，不堆成小字号墙。

### 文案也是设计材料

- 从用户一侧命名对象和能力，使用用户认识的业务词，不暴露组件、字段或系统实现术语。
- 默认使用主动语态和具体动词；按钮直接说明结果，例如“保存修改”而不是“提交”。
- 同一个动作名称在整个流程中保持一致，按钮、反馈和后续状态使用同一词汇。
- 错误和空状态要说明发生了什么以及下一步怎么做，不用含糊道歉、情绪口号或无行动价值的占位文案。
- 每个元素只承担一个文案职责：标签负责命名，说明负责解释，示例负责示范。

## 五、布局与节奏

### 版式选择

- **编辑式**：媒体、留白、系列叙事；适合强品牌与内容；
- **任务式**：搜索、筛选、状态、表单；适合 O2O、B2B、账户；
- **比较式**：方案、价格、规格；适合订阅、服务、B2B；
- **空间式**：地点、环境、人物；适合门店、服务、文旅；
- **流式零售**：分类与商品效率；适合宽品类商城。

一页可以组合两种，但要有主导逻辑。

### section 节奏

- 不要求所有 section 都装进卡片；通栏、分栏、列表、表格、媒体、留白都可以成为结构。
- 连续内容通过背景、间距和对齐建立关系，不必机械插入分割线。
- 全宽区块的实现要先读取实际容器 padding，不写死 `-12px`；只有确需贴边时才撑出容器。
- 移动端优先保证触达、扫描和点击，不以桌面缩小版思考。

## 六、颜色、圆角与材质

### 色彩

`apply_style_theme` 提供 primary、accent、bg、text 四个共享角色。实际品牌可增加支持色、弱表面色、边框色和状态色，但要在 manifest 命名，不在 CSS 中散落无意义 hex。

检查：

- 正文与背景通常 ≥4.5:1；
- 主按钮、次按钮、价格和状态在各自背景上清晰；
- 强调色只用于真正重要的信息；
- 深色表面上的文字显式选择高对比色。

### 圆角

圆角是语义，不是统一开关。可以建立小规模层级：

- 0：通栏、表格、媒体边界或利落品牌；
- 基础圆角：卡片、输入和按钮；
- 更大圆角：强调容器；
- 999px：标签、胶囊和头像。

值的数量要少、关系清楚；不要求所有组件完全相同，也不允许每个模块任意选择。

### 阴影与边框

阴影用于层级和悬浮，不用于给每张白卡“加质感”。工具型页面常用边框与底色分层；品牌型页面可以用留白和媒体分层。

## 七、签名元素与动效

签名元素不是交付必选项。只有当一个图形、排版、交互或媒体处理能强化品牌记忆时才使用；不要为了通过检查发明装饰。

动效优先服务：

- 状态变化和操作反馈；
- 重要内容首次进入；
- 轻量品牌节奏。

规则：

- 不依赖动效才能理解内容；
- 循环动效极少使用；
- `@keyframes` 使用组件唯一前缀；
- 自定义脚本组件自包含；
- 提供 `@media (prefers-reduced-motion: reduce)` 关闭或简化；
- 编辑态和预览态分别验证。

## 八、实现友好的设计

- 设计 HTML 以语义 section 划分，不按 WAI 组件切碎视觉。
- 重复出现的内容模式应稳定，但不必全部做成相同卡片。
- 关键业务能力预留可映射的内容结构，如商品字段、门店信息、时段、规格和 CTA。
- 独特视觉可分布在任意数量的 custom section；按业务职责拆分并保持可编辑，而不是把整页绑成一块。
- 设计稿使用系统可用字体；确需外部字体时说明加载风险和回退。

## 九、UI 自检

- 不看文案，只看版式，是否能辨认主次和行动？
- 不看颜色，只看结构，是否仍符合经营模式？
- 媒体是否提供真实信息，还是装饰性填充？
- 品牌是否有辨识度，但没有依赖流行模板？
- 圆角、边框、阴影和间距是否形成系统？
- 页面是否既不过度空，也不靠重复模块制造密度？
- 以 375px 为主视口时是否成立，并在 360px 与 414px 下无横向溢出？关键触控目标通常是否至少 36px？内置组件内部的紧凑文字链接不参与点击区尺寸检查。
- 动效关闭后是否仍完整可用？
