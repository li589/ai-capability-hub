# 经营数据分析

## 功能说明

本 skill 统一承载两类数据分析能力，二者调用命令与产出形态不同，必须先按路由规则选对通道：

| 能力 | 命令 | 产出 |
|---|---|---|
| 智能问答 / 图表（ChatBI） | `woscli chat-bi chatbi_ask` | 历史汇总指标的结论 + 图表；含经营日报 |
| 分析报告（Report Generation） | `woscli chat-bi report_ask` | 长文 Markdown 报告 |

### 路由规则（必须遵守）

| 用户意图 | 路由到 |
|---|---|
| 经营日报、日报趋势、日报汇总、某日日报、近 N 天日报 | **ChatBI**（`chatbi_ask`） |
| 单点指标问答、趋势/对比/排行/占比/拆分 | **ChatBI**（`chatbi_ask`） |
| 经营报告、经营分析报告 | **报告**（`report_ask`，`business_analysis`） |
| 促销活动报告、活动分析报告 | **报告**（`report_ask`，`activity_overview`） |
| 导购任务报告、任务模板或批次分析 | **报告**（`report_ask`，`guider_task_analysis`） |

> **“日报”不走报告通道**：经营日报、日报趋势、日报汇总等一律归 ChatBI 智能问答处理，不得路由到 `report_ask`。
> **报告只有三类**：经营、促销活动、导购任务三类长文报告归 `report_ask`，不得改用 `chatbi_ask` 拼凑。

## 触发场景

**ChatBI**：经营数据分析、BI 统计、看数、昨天 GMV 多少、近 7 天销售额趋势、各渠道占比、销量 Top 10 商品、门店业绩对比、会员等级分布、经营日报、xx 日经营日报、近 7 天日报趋势。

**报告**：生成经营分析报告、按指定日期分析经营情况、分析促销活动 X、分析 X 促销活动、分析导购任务 X、分析 X 导购任务、任务批次分析报告。

## 调用方式

```bash
# 智能问答 / 图表 / 日报
woscli chat-bi chatbi_ask --query '<用户的问题>'

# 长文分析报告
woscli chat-bi report_ask --report_type <business_analysis|activity_overview|guider_task_analysis> [--dt '<日期>'] [--ext_param '<JSON>']
```

- 不得直接调用 `/api/cli/report`，不得自行拼接 `curl` 请求。
- `bos_id`、`vid`、`wid` 和会话 ID 由 WOS CLI 根据当前登录业务上下文注入，不得作为命令参数自行构造。

## 支持的操作

### 一、智能问答 / 图表（ChatBI）

将自然语言问题交给 ChatBI，稳定完成历史汇总数据查询，重点是正确理解用户意图、按固定流程执行。

#### 1.1 整体流程

```
用户问题 → 判断是否日报类问题
  ├─ 日报类：直接执行查询（使用原始问题）
  └─ 非日报类：先确认指标/维度在支持清单内 → 在原始问题后追加扩展分析提示词后执行查询
```

> **关键原则**：本节的每一步都必须产出一个明确的最终结论。当遇到业务异常（如权限不足、组织节点缺失等）时，**直接以自然语言向用户输出结论性回复**，不要抛出错误或异常，避免上游 agent 将其视为可重试的失败而反复调用本 skill。

> **非日报问题扩展原则**：非日报类的简单用户问题，不要直接使用原始问题查询，需在原始问题后追加扩展分析提示词（如“并扩展分析下”），引导 ChatBI 给出更全面的分析结论。例如用户问“昨天 gmv 多少”，实际查询使用“昨天 gmv 多少 并扩展分析下”。

#### 1.2 日报类问题处理

日报类问题指用户希望快速获得某个日期的关键经营指标概览及必要的结构拆分/排行/趋势，例如“昨天经营日报”“xx 日经营日报”“近 7 天日报趋势”。

- 日报基于历史已出数数据，不做当日实时口径。
- 用户未指定日期时，默认按昨日（用户时区自然日）。
- 用户明确要求“今天/当日/实时日报”时，直接输出结论：不支持当日实时口径，建议改查“昨日日报”或“近 7 天趋势”。
- 若用户问题未包含明确日期范围，允许在原始问题后追加“时间：昨日”以提升命中率，其余表达保持不变。

#### 1.3 执行查询

```bash
woscli chat-bi chatbi_ask --query '<用户的问题>'
```

执行规则：

- **执行查询前，先确认所请求的指标/维度在 `@references/metrics-dimensions.md` 中列出**；未列出的指标、维度或口径视为不支持，直接向用户说明，不要猜测或编造。日报类问题除外，可直接执行。
- 检查返回的 `errcode`，只有等于 `"000000"` 才处理结果。
- `query` 使用单引号包裹，避免特殊字符影响参数解析。
- **非日报类问题**：不要直接使用原始问题，需在原始问题后追加扩展分析提示词（如“并扩展分析下”）。例如用户问题为“昨天 gmv 多少”，实际执行 `woscli chat-bi chatbi_ask --query '昨天 gmv 多少 并扩展分析下'`。日报类问题直接使用原始问题即可。
- 如果返回明确的业务异常信息（如“您没有该XXX数据域的访问权限，请联系管理员开通权限”“无法确定用户组织节点类型”等），**直接以自然语言向用户输出结论性回复**（例如：“当前您没有该数据域的访问权限，请联系管理员开通后再试。”），不要抛出错误或继续调用 woscli。输出的回复必须是完整、自包含的最终答案，使上游 agent 判定任务已完成，而非需要重试。
- 日报场景：
  - 当 chat-bi 返回 `"execution_path": "preflight_daily_report"` 时，视为日报。
  - chat-bi 已返回日报过程数据和解读总结和没数据等信息给用户展示。
- 非日报场景：
  - 只有命令返回的 `columns`、`rows` 和 `rowCount` 才是最终可用结果。

#### 1.4 指标与维度确认

支持的指标、分析形态与维度别名清单见 `@references/metrics-dimensions.md`。常见维度别名速查：

| 用户常见说法 | 可能映射字段 |
|---|---|
| 日期、天、周、月、趋势 | `dd` |
| 渠道、销售渠道 | `sale_channel_type` |
| 门店、组织 | `vid_name` |
| 导购 | `guider_name` |
| 会员等级 | `member_level` |
| 商品类目 | `cate_first_name` |

该表仅用于帮助理解用户口语，不表示这些维度一定在所有业务域都可用。

### 二、分析报告（Report Generation）

使用 `woscli chat-bi report_ask` 生成长文报告。

#### 2.1 核心原则

- 仅使用报告结果中的 `reply`，不得自行编造、补充或改写数据。
- 经营分析报告的 `dt` 可选；未指定时间时省略，不要追问日期。
- 促销活动分析报告的 `dt` 和活动 ID 必填；活动名称可选。
- 导购任务分析报告的模板 ID、批次号和任务名称必填；`dt` 可选，未指定时间时省略。
- 必填参数缺失、格式错误、类型不支持或命令调用失败时，直接说明原因。

#### 2.2 命令选择

| 用户意图 | 命令 | `report_type` | 其他参数 |
|---|---|---|---|
| 经营报告、经营分析报告 | `report_ask` | `business_analysis` | `dt` 可选 |
| 促销活动报告、活动分析报告 | `report_ask` | `activity_overview` | `dt`、`ext_param` 必填 |
| 导购任务报告、任务模板或批次分析 | `report_ask` | `guider_task_analysis` | `ext_param` 必填，`dt` 可选 |

#### 2.3 执行流程

1. 根据用户意图确定 `report_type`。
2. 查询活动报告时，收集 `activity_id` 和时间；缺少任一项时向用户确认。用户提供活动名称时一并传入。
3. 查询导购任务报告时，收集 `template_no`、`batch_no` 和 `task_name`；缺少任一项时向用户确认。
4. 用户指定时间时，将日期转换为支持的 `dt` 格式；经营报告和导购任务报告未指定时间时省略 `dt`。
5. 调用对应的 `woscli chat-bi report_ask` 命令。
6. 等待流式结果完成，从最终结果中提取 `reply`。
7. 将 `reply` 的 Markdown 原样返回。

#### 2.4 调用示例

未指定时间的经营分析报告：

```bash
woscli chat-bi report_ask \
  --report_type business_analysis
```

指定单日的经营分析报告：

```bash
woscli chat-bi report_ask \
  --report_type business_analysis \
  --dt '2023-12-01'
```

指定日期范围的经营分析报告：

```bash
woscli chat-bi report_ask \
  --report_type business_analysis \
  --dt '2023-12-01,2023-12-31'
```

促销活动分析报告：

```bash
woscli chat-bi report_ask \
  --report_type activity_overview \
  --dt '2023-02-23,2023-03-12' \
  --ext_param '{"activity_id":"21002068620215","activity_name":"CY"}'
```

指定单日的导购任务分析报告：

```bash
woscli chat-bi report_ask \
  --report_type guider_task_analysis \
  --dt '2023-08-01' \
  --ext_param '{"template_no":"50009593437","batch_no":"510060232","task_name":"新品推广任务"}'
```

使用默认最近 7 天的导购任务分析报告：

```bash
woscli chat-bi report_ask \
  --report_type guider_task_analysis \
  --ext_param '{"template_no":"50009593437","batch_no":"510060232","task_name":"新品推广任务"}'
```

示例中的活动、任务和日期信息只用于展示命令结构，实际调用时必须替换为当前查询对应的值。

#### 2.5 参数规则

| 参数 | 必填 | 规则 |
|---|---|---|
| `--report_type` | 是 | 支持 `business_analysis`、`activity_overview`、`guider_task_analysis` |
| `--dt` | 条件必填 | 经营和导购任务报告可省略；活动报告必填；支持单日 `yyyy-MM-dd` 或范围 `yyyy-MM-dd,yyyy-MM-dd` |
| `--ext_param` | 条件必填 | 活动和导购任务报告必填，传入对应的 JSON 对象字符串 |

**活动参数**：

- `ext_param.activity_id` 必填，必须是正整数；可按字符串或数字传递。
- `ext_param.activity_name` 可选；传入时必须是字符串，并保留用户提供的原值。
- 只有活动名称、没有活动 ID 时，先向用户确认活动 ID；只有活动 ID 时可直接调用。
- 不得根据活动 ID 猜测活动名称。
- 经营分析报告不得携带 `ext_param`。

**导购任务参数**：

- `ext_param.template_no` 必填，表示任务模板 ID，必须是正整数；可按字符串或数字传递。
- `ext_param.batch_no` 必填，表示任务批次号，必须是正整数；可按字符串或数字传递。
- `ext_param.task_name` 必填，表示导购任务名称，必须是非空字符串，并保留用户提供的原值。
- 缺少任一字段时先向用户确认，不得猜测或使用占位值。
- 导购任务分析报告只传入 `template_no`、`batch_no` 和 `task_name`，不得混入活动参数。

**日期参数**：

- 经营报告和导购任务报告未指定时间时省略 `--dt`，由后端使用截至昨天的最近 7 个自然日。
- 单日格式为 `yyyy-MM-dd`，例如 `2023-12-01`。
- 日期范围格式为 `yyyy-MM-dd,yyyy-MM-dd`，例如 `2023-12-01,2023-12-31`。
- 日期范围不得包含空格，开始日期不得晚于结束日期。
- 用户只提供一个日期时按单日传入，不得自动扩展。
- 活动报告未指定时间时，或任一报告的日期含义不明确时，先向用户确认。

## 输出格式

### ChatBI 结果返回

- **日报类**：只回复“已完成”等通知内容即可，不需要返回日报解读、总结和没数据等信息（chat-bi 已直接向用户展示）。
- **非日报类**：
  - 最终回答以查询返回的数据为准，不要假装看到了工具没有返回的信息。
  - 优先用自然语言总结关键结论，而不是把原始二维数组直接甩给用户。
  - 拿到 `columns` 和 `rows` 后先判断数据是否适合可视化；适合时必须配合运行环境中的图表能力输出图表。
  - 适合展示：存在 2 条及以上可比较数据，且至少有一个可用于展示的数值指标，或用户明确要求图表且数据能形成有意义的对比、趋势、排行、分布或占比。
  - 不适合展示：`rows` 为空；只有 1 条原始数据且没有可比较维度；核心数值指标全部为 0、空或 null；没有可用数值列；数据结构无法形成有意义图表；用户明确只要文字结论。
  - 不适合展示时不要强行调用图表能力，直接用自然语言或简洁表格回答，并说明原因，例如“当前结果只有 1 条数据，不足以形成对比图表”或“核心指标均为 0，图表展示价值较低”。
- 如果查询失败、超时或参数缺失，简洁说明原因，并在合适时引导用户缩小范围或补充条件。

### 报告结果返回

- 调用前检查 `report_type` 以及对应的条件必填参数。
- 外部调用日志最多记录两个关键入参：始终记录 `report_type`，活动报告额外记录 `activity_id`，导购任务报告额外记录 `template_no`；不得记录完整命令、完整 `ext_param` 或业务上下文。
- 等待 WOS CLI 流式输出结束，以最终 `cmd.result` 为准。
- 提取最终结果中的 `reply`，保留标题、列表、图表和数据表格格式。
- 不输出流式协议字段、进度事件、内部字段或调试日志。
- 命令提示未登录、无业务上下文或权限不足时，引导用户完成登录、切换业务上下文或申请权限；不得猜测上下文参数。

## 注意事项/边界

### ChatBI 边界

- 默认策略：仅支持下列“支持范围”列出的能力与主题；除此之外一律视为不支持。
- 支持范围：
  - 数据类型：历史汇总指标（按维度聚合后的统计口径），以 `columns`、`rows` 返回的结果为准。
  - 分析形态：汇总、趋势、对比、同比/环比、占比、结构拆分、Top N/排行（含按销售额/销量等排序）、多轮追问下钻/切换维度。
  - 日报：支持基于历史已出数数据（通常 T-1）的经营日报汇总查询与解读；默认提供关键指标概览，并可按用户问题做拆分、排行或趋势。
  - 主题域：经营/交易、商品、营销活动、会员/客户、门店/导购绩效、流量分析等（具体可用指标/维度以 `@references/metrics-dimensions.md` 为准）。
  - 库存相关指标：仅当它是某个已支持看板/数据集的指标且出现在支持清单中时可查询（例如促销类“库存消耗率”）；不支持独立的库存域/仓储供应链分析。
  - 商品相关：时间窗口内的销量/销售额 Top N、趋势、对比。
- 不支持：
  - 库存/仓储/供应链：库存分析报告、库存周转/库龄、出入库、盘点、调拨、补货、采购、供货/履约等相关分析或报表。
  - 实时/当天：当日实时数据或强实时看板刷新（“今日/当日/实时日报”不支持）。
  - 明细/原始记录：订单/支付/退款等逐笔流水、订单明细、用户个人信息、商品列表/规格清单/明细等。
  - 操作类诉求：数据写入/修改、后台筛选排序、固定格式报表导出。
  - 不在 `@references/metrics-dimensions.md` 的字段/口径：不要猜测或编造不存在的指标、维度、口径或结论。

### 报告边界

- 仅支持 `business_analysis`、`activity_overview` 和 `guider_task_analysis`，不支持其他报告类型、自定义模板、自由组合报告、实时数据报告、明细导出或数据写入。

### 通用

- 严禁把日报类查询路由到 `report_ask`，也严禁把三类长文报告改用 `chatbi_ask` 拼凑。
- 两条通道均不做数据写入。
