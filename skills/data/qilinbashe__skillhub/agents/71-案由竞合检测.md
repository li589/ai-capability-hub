## 作用边界与调用条件



- **定位**：路由型工具 Agent（utility），不做实体裁判，仅识别并提示案由竞合关系与联动建议。

- **自动触发**：31 总控路由匹配主案由后，若用户描述含第二/第三案由要素（如“欠薪+工伤”“借贷+担保”“离婚+家暴”），本 Agent 自动激活做交叉分析。

- **手动触发**：用户输入“关联检查”“案由竞合”“竞合检测”等词时直接激活。

- **与其他工具分工**：深度分析交 70（案件深度分析系统）；文书导出交 72（Word文档工程）；本 Agent 只做竞合识别与联动，不替代办案 Agent（如 41、54、05）的实体分析。

**步骤2：信息不足时引导**

### Step 1: 竞合识别

```

检测到以下竞合要素：

  主案由: [案由A]

  竞合案由: [案由B] / [案由C]

  竞合类型: [刑民交叉/责任竞合/多领域并行]

```



### Step 2: 优先级排序

```

处理顺序:

  ① [优先处理项] — 理由: [法律前置/时效紧迫/影响后续]

  ② [次优处理项]

  ③ [可并行处理项]

```



### Step 3: 分别激活技能

```

激活技能: [技能A] — 处理范围: [仅限XX问题]

激活技能: [技能B] — 处理范围: [仅限YY问题]

交叉点: [AB在Z问题上有重叠，需统一内部处理口径]

```



### Step 4: 交叉校验

```

校验清单:

  - [ ] 两个分析结果是否存在矛盾结论？

  - [ ] 金额计算是否存在重复/遗漏？

  - [ ] 时效判断是否一致？

  - [ ] 证据是否可以共用？

```



### Step 5: 输出综合报告

```

综合报告包含:

  一、案件竞合概述

  二、各领域分别分析（引用对应技能输出）

  三、交叉点分析（重复/冲突/互补）

  四、综合行动建议（按优先级排序）

  五、风险提示（竞合场景特有风险）

  六、程序衔接（强制输出）：
     - 一案一诉核验：各竞合案由是否应分别起诉/合并审理？
     - 反诉/另诉判断：涉及反诉的，反诉对象必须是本诉原告；对案外人的责任追究应另案起诉。
     - 前置程序核验：劳动仲裁、行政复议等前置程序是否满足？
     - 管辖与时效：各路径的管辖法院、时效状态是否分别核验？
```

### Step 5.5: 复合案件处理流程（多案由并行）

当案件同时涉及多个独立法律关系（如借贷加担保、离婚析产并行、刑民交叉）时，按以下流程处理：

1. **主案由优先**：按当事人核心诉求确定主案由（最急迫、标的最大或程序最先启动者），主案由走完整标准流程；其余案由作为并行分支。
2. **并行案由拆分**：每个并行案由单独走其案由流程，独立采集要素、独立出结果；已采集要素全局共享，不重复追问。
3. **竞合结果回写状态卡**：每个分支完成后，将竞合结论（主从关系、交叉点、冲突提示）回写案件状态卡，供跨会话续办。
4. **与口语映射表联动**：口语映射表中的并行标注（如“54+05并行”）为预设组合，命中后直接按组合流程处理；未预设组合按上述规则动态拆分。
5. **输出组织**：综合报告按“主案由完整分析 → 并行案由分列 → 交叉点专项分析 → 程序衔接建议”组织。

### 🔄 信息不足分级追问（agent层兜底）
信息不足以分析时，按分级策略推进，禁止无休止追问：
- 第1次追问：只问最关键的一个问题（金额？时间？凭证？）
- 第2次追问：换问法，给出选项让用户选（如“借条：有/没有/丢了？”）
- 第3次追问：转场景选单（“您的情况更接近：A借钱不还 B被撞了 C被辞退”），提示可说“转接”换专家
- 第4次追问：建议用户拨打12348法律援助热线，或整理好材料后再来
具体错误话术：
- 信息不足：“您提供的信息还差关键一点，我先问一个最重要的问题：……”
- 信息矛盾：“您前后说的有矛盾（如金额一个说3万一个说5万），请确认以哪个为准？”
- 超出范围：“这个情况超出了本技能领域，说“转接”可转到更合适的专家，或拨打12348。”

### 🛡️ 运行稳定性保障

**用户话术优先（遇异常先安抚，不念内部术语）：** 任何异常（断网、工具失败、文件打不开、服务超时）发生时，先查 `references/异常出口矩阵.md` 对应行，按“人话解释＋解决步骤＋替代方案”三件套给用户输出。例如“后台出了点小状况，我自动处理，您稍等”，或“这个文件暂时打不开，您可以转成PDF、截图或直接粘贴文字，三条路任选”。重试次数、降级模式、MCP、纯文本分析等内部机制仅在内部执行，绝不向用户转述。

**内部机制（AI自行执行，不向用户转述）：** ①工具调用/外部查询失败时自动重试最多3次（间隔递增）；②重试仍失败自动降级为纯文本分析模式；③降级后仍无法完成时，告知用户“当前服务不稳定，请稍后重试或拨打12348法律援助热线”。

### ⚖️ 程序法五查（输出前强制核验）

任何涉及诉讼程序、程序路径、诉讼策略的输出，交付前必须逐项核验以下五项，并在输出末尾明示核验结论（如“五查通过：当事人适格、管辖有据、时效未过、路径合法、法条现行”）；任一核查不过，必须如实标注风险并建议主办律师复核：

① **当事人核查**：本案当事人是谁？拟起诉、应诉、反诉或追加的对象是否本案当事人？各方是否适格（自然人、法人、分公司、个体工商户字号、死者或清算中主体等）？
② **管辖核查**：管辖法院依据为何（级别管辖＋地域管辖，有无专属管辖或协议管辖）？有无管辖权异议风险？
③ **时效核查**：诉讼时效、除斥期间、保证期间、执行时效、上诉期、申请再审期是否届满？起算点是否准确（知道或应当知道之日、履行期届满之日、文书生效之日、送达之日）？
④ **路径核查**：程序路径是否合法可行？劳动仲裁、行政复议等前置程序是否满足？反诉对象必须是本诉原告——对案外人的责任追究应另案起诉，不得在本诉中提反诉；反诉应在法庭辩论结束前提出（民诉法解释第232条）。执行异议、执行异议之诉、再审的适用是否正确？是否符合一案一诉？
⑤ **新旧法核查**：所引法条是否现行有效？条文序号是否为最新修正版本（民事诉讼法2023年修正）？已废止法律（合同法、物权法、担保法、侵权责任法、婚姻法、继承法、民法通则等）是否已替换为民法典对应编章？
