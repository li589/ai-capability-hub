# 法条交叉核验引擎（96）

> **定位**：全技能包“引用法条”动作的**强制前置关卡**。任何 Agent 在输出法条号 + 条文内容前，必须先经本引擎做多源交叉比对。**严禁仅凭模型内部知识生成法条号与条文**——这是“仲裁法第43条乌龙”类错误的根因。

---

## 一、为什么必须有这一步

法律近年密集修订（仲裁法 2025、公司法 2023、刑法修正案十二 2024、刑诉法 2018 修正〔配套 2021 最高法刑诉法解释〕……）。模型训练数据存在截止期，**“法条号 → 条文内容”的对应关系可能已漂移**：

- **反面案例（固化）**：2025 修订前《仲裁法》第 43 条为“证据规则”；修订后第 43 条变更为“仲裁庭组成”规定，证据调取规则移至**第 55 条**。若仅凭旧知识输出“仲裁法第43条=证据规则”，即构成引用乌龙。
- **法源基准两层口径**：`law_baseline_global = 2026-07-01`（实体法全局基线，全包统一）；`law_baseline_special = 2026-08-10`（程序法专项复核基准）——《民事诉讼法》现行有效版本为**2023 年修正版**（2024-01-01 施行），截至 2026-08-10 全国人大法律法规数据库未收录新修正案；引用前先确认“现行 = 哪年修正版”，同理引用其他法律前先确认“现行 = 哪年修正版”。
- 因此必须按“**法条号 + 时间戳**”双索引核验，而非凭记忆。

---

## 二、调用顺序（强哥指定优先级 · 运行时必须真的发起工具调用）

> 🔴 **运行时铁律**：本引擎不是“声明已核验”，而是**必须真实发起 MCP 工具调用**拿到条文原文，才算核验通过。凡下列源已连接，就**先调工具、后出结论**；**禁止**仅凭模型内部知识写“已核验”，也禁止在没调用工具的情况下把模型自产条文标成“已核验”。

| 序 | 源 | 工具命名空间（运行时真实调用，非口头声明） | 用途 |
|----|----|----------|------|
| 1 | **华宇元典** | `mcp__yuandian__*`（法条检索 / 法条向量 / 案例向量 / 案例详情 / 幻觉检测 等） | 权威法条 + 案例 + 企业信息 |
| 2 | **北大法宝** | `mcp__pkulaw__*`（法条语义 / 按条号取法条 / 法规列表 / 案例语义 / 案例列表 等） | 法规 + 裁判文书 + 专题 |
| 3 | **IMA 知识库** | `mcp__ima-mcp__*`（笔记 / 知识库检索） | 内部沉淀的法规摘录与办案笔记 |
| 4 | **中国裁判文书网** | 公开检索（网传接口 / 网页抓取） | 案例与裁判规则兜底 |

> ✅ 源 1/2 已在客户端连接华宇元典（yuandian）、北大法宝（pkulaw）连接器并填入鉴权，**直接调用其工具即可**；若某环境未连接，则**跳到源 3/4，并诚实标注“未接入权威库”**——此时本条输出只能标“🔴 未核验·模型生成”，不得混标“已核验”。

## 三、核验流程（每次引用必走）

1. **提取待引用法条**：法名 + 条号（精确到条、款、项）。
2. **依次调用** 上述源，获取该条“最新有效条文 + 生效日期 + 修订记录”。
3. **三源比对**：条文号 ↔ 内容 ↔ 生效状态 是否一致。
4. **输出核验结论**（见下格式）。

---

## 四、输出格式（诚实两态标注 · 强制）

> 所有法条 / 案例引用必须落到一个**明确的状态标签**上，来源写清楚。绝不允许“未标注 / 含糊带过”。

| 状态 | 含义 | 触发条件 | 视觉 |
|------|------|----------|------|
| ✅ **已核验(MCP)** | 实际调用了北大法宝 / 华宇元典其一或二者，取回条文原文并比对一致 | 源 1/2 任一工具成功返回且与引用一致 | 绿色 |
| 🔴 **未核验·模型生成** | 未实际调用任何 MCP 源（离线 / 源不可达 / 模型自产） | 源 1/2/3 均不可用，或模型直接凭记忆输出 | **红色高亮** |

- ✅ 已核验时**必须写明来源**：`已核验(MCP: 北大法宝)` / `已核验(MCP: 华宇元典)` / `已核验(MCP: 北大法宝+华宇元典)`（单源即标单源，不冒充双源）。
- 🔴 未核验时**必须红色高亮**并附固定提示：“🔴 本条未经实时核验，为模型生成，仅供初步参考，须以国家法律法规数据库 flk.npc.gov.cn 官方文本为准，并由主办律师复核”。
- ❌ 禁止把“未核验·模型生成”伪装成“已核验”或用“离线待核”柔化带过——降级透明是底线。

## 四-A、自动标注规则（在现有规则基础上追加）

当任一核验步骤出现以下情况时，必须在输出中显式标注：

1. **离线模式**：法条来自离线法条精华 → 标注“🔶 离线模式，未联网核验最新版本”
2. **时效超1年**：引用的法条/司法解释距今天超过1年未确认修订 → 标注“⚠️ 引用法条距今>1年，请确认无修订”
3. **单源核验**：仅一个MCP源可用（沿用现有⚠️标签）→ 标注“⚠️ 单源核验，建议人工复核”
4. **无案例支撑**：未找到类似判例 → 标注“💡 本案无直接类案参考，裁判可能受法官自由裁量影响”

## 四-B、MCP降级提示规则

- MCP全部不可达（离线模式）→ 输出末尾追加：“🔴 未核验·模型生成：本次未连接 北大法宝 / 华宇元典，法条输出未经实时核验，仅供参考”
- 仅单源可用 → 输出末尾追加：“✅ 已核验(MCP: 仅X可用)，建议人工复核。如需多源核验，请配置第二个MCP数据源”
- MCP正常、多源核验通过 → 内联“已核验(MCP: 北大法宝+华宇元典)”，**不追加冗长提示**，避免干扰正常使用

### 🔄 信息不足分级追问（agent层兜底）

- 第1次追问：只问最关键的一个问题（金额？时间？凭证？）
- 第2次追问：换问法，给出选项让用户选（如“借条：有/没有/丢了？”）

- 信息不足：“您提供的信息还差关键一点，我先问一个最重要的问题：……”
- 信息矛盾：“您前后说的有矛盾（如金额一个说3万一个说5万），请确认以哪个为准？”
- 超出范围：“这个情况超出了本技能领域，说“转接”可转到更合适的专家，或拨打12348。”
