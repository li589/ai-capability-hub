# PTG 面板图读图模板（沉淀版）

> 一份"读图模板手册"，让 562 张面板的录入从"每张人生第一次"变成"按模板填空"。
> 适用对象：批次 2/3/4 的大模型视觉录入流程；后续 PaddleOCR 模板化裁切。

---

## 0. 总览

- **来源**：腾讯文档 xlsx 导出的 PTG 球员信息面板弹窗截图
- **总量**：562 张
- **尺寸**：实际范围 1146~1175 × 776~796（共 100+ 种），**集中在 1158~1162 × 781~785**
- **结论**：**绝对像素不可硬编码，但比例坐标稳定**（差异 ±0.5%）
- **板式**：弹窗白底 + 左半身资料卡 + 右半位置能力表

```
+-------------------------------------------------------------+
|  球员信息                                               ×    |  ← 顶栏 (Y: 0~7%)
+--------------------------+---------- +---------------------+
| 左半：基础信息卡         | 头像     | 右半：能力数值表    |
|  - PTG徽章+姓名+俱乐部   |          |  - tab: 总/位置1/位置2/所有位置
|  - 主位置+OVR (红/绿/紫) |          |  - 当前tab高亮OVR    |
|  - 俱乐部 国籍国旗       |          |  - 12项分位置数值    |
|  - 工资 身高cm 体重kg 体型|         |    (每项左中文 右数字)|
|  - 6维 (速射传盘防强)    |          |                      |
|  - tab: 特征/价格/经历   |          |                      |
|  - 生日                  |          |                      |
|  - 花式技巧 ★★★★★        |          |                      |
|  - 名声                  |          |                      |
|  - 持有特性 (3-6个图标)  |          |                      |
|  - 训练助教追加特性      |          |                      |
|  - 获得特性              |          |                      |
|  - 是否可产出            |          |                      |
+--------------------------+----------+----------------------+
```

### 1.2 主位置 + OVR（左半第二行）

| 字段 | 位置 | 说明 |
|---|---|---|
| **主位置 + OVR** | (7, 17, 35, 7) | 例 "中锋 135"、"中场 133 后腰 133"（双位置）|

**颜色码**：
- 红色 (`#E51A4C`) = 攻击型位置（前锋/边锋/前腰）

- 紫色 = PTG 强化值（右侧能力数值区，区别于普通卡的青色）

### 1.5 6 维能力条（左半中部，灰色背景）

> **统一顺序**：速度 / 射门 / 传球 / 盘带 / 防守 / 强壮（场上球员）

| 字段 | 位置 | 说明 |
|---|---|---|
| 6 个维度名 | y=33~36% | 第一行，灰底白字 |
| **6 个数值** | y=37~42% | 第二行，紫色加粗大字 |

每个数值的 X 中心点（场上球员）：
- 速度: 11% | 射门: 23% | 传球: 35% | 盘带: 47% | 防守: 59% | 强壮: 71%

### 1.6 tab 切换（左半下部）

| 字段 | 位置 | 说明 |
|---|---|---|
| 特征 (黑底白字 = 当前激活) | (7, 44, 12, 5) | 我们要读的内容 |
| 价格 / 现实加成 / 俱乐部经历 | 后续 tab | 不读 |

### 1.7 特征详情（左半下半部）

| 字段 | 位置 | 说明 |
|---|---|---|
| **生日** | (50, 50, 15, 5) | 右对齐，例 "1993.7.28" |
| **花式技巧 ★** | (50, 56, 22, 5) | 5 颗星，亮黄色为已点亮 |
| **名声** | (50, 62, 18, 5) | "传奇球员/世界级球员/顶级球员/知名球员/一般球员" |
| **持有特性** (3-6 个图标) | (35, 67, 30, 8) | 六边形深灰图标，**仅图标无法 OCR 名字 → traits 留空** |
| 训练助教追加特性 | (35, 73, 30, 5) | 通常为空 |
| 获得特性 | (35, 79, 30, 5) | 通常为空 |

### 1.8 右半：能力详情表

| 字段 | 位置 | 说明 |
|---|---|---|
| **当前 tab** | (52, 16, 35, 4) | 例 "总能力值 / 中锋 / 后腰 / 所有位置" |
| **当前位置 OVR** | (52, 21, 38, 6) | 左中文位置 + 右大数字（紫色 PTG 色）|
| **12 项分位置能力** | y=27~78%, 行高约 4.2% | 共 12 行，左中文（白色）右数字（紫色，加粗）|

每行 ROI：
- 名称 (52, 27 + i*4.2, 30, 4)
- 数值 (85, 27 + i*4.2, 8, 4)
- i ∈ [0, 12)

### 1.9 双位置卡：副位置

部分球员主位置后跟 `副位置 OVR`，例如：
- 奥利塞: `前腰 133  右边锋 133`
- 埃基蒂克: `中锋 128  左边锋 126`
- 里斯·詹姆斯: `右后卫 131  左后卫 131`

→ 右侧 tab 栏会多出一个 tab（鼠标可切换），但**面板截图只能定格在一个 tab**。
副位置 OVR 记录到 `alt_positions: [(位置名, OVR)]`，分位置详情默认主位置。

## 3. 录入决策树（让大模型读图变快）

每张图按这个顺序识别，**只看必要 ROI**，不全图扫：

```
Step 1  读左上角主位置色块 → 判断位置族（GK/CB/SB/CM/CAM/W/ST）
Step 2  按位置族查"2. 字段表"知道要读哪 12 项
Step 3  读左半 6 维（同位置同顺序）
Step 4  读右半 12 项（同位置同字段，从上往下）
Step 5  读左半身体条（身高/体重/体型/弱足/花式）
Step 6  读左半下半部（生日/名声）
Step 7  traits 字段统一留空（图标无文本）
```

**对应阵型槽位简记**：
| 主位置 (面板) | 阵型 role |
|---|---|
| 门将 | GK |
| 中后卫 | CB |
| 左后卫 | LB |
| 右后卫 | RB |
| 后腰 | CDM |
| 中场 | CM |
| 前腰 | CAM |
| 左边锋 | LW |
| 右边锋 | RW |
| 中锋 / 影锋 | ST |

## 5. 批量入库流程（固化）

每个国家走 4 步：

```bash
# Step 1: 反查主库取 top11 spid（避免凭面板猜 spid 写错）
python3 -c "
import json
db = json.load(open('data/player_ptg_cache.json'))
top = sorted([(s,p) for s,p in db.items() if p.get('nationality')=='<国家>'], 
             key=lambda x: -x[1].get('ovr',0))[:11]
for s, p in top: print(s, p['name_cn'], 'OVR'+str(p['ovr']))
"

# Step 2: 按 spid 列表读 11 张面板图（大模型视觉）
#   - 按位置族决定读哪些字段（查 §2 字段表）
#   - 按 §1 ROI 只看关键区域，不全图扫描

# Step 3: 写 /tmp/append_batch2_<country>.py（用 §4 模板填值）

# Step 4: 执行入库脚本（脚本内置 spid 主库校验 + 重复跳过 + 姓名匹配 warn）
python3 /tmp/append_batch2_<country>.py
```

## 6. 踩坑记录（持续累积）

### 6.1 spid 不能凭面板图编
**错误**：第一版法国脚本里我把 863202126 写成"奥利塞"，主库其实是英格兰哈里·凯恩。
**正确**：始终先反查主库 `player_ptg_cache.json[nationality==<国家>]` 取真实 spid，**只把面板图的能力数值填进去**。

### 6.2 特性图标无法识别名字
面板中的"持有特性"是 32×32 六边形图标，**没有文字**，大模型只能描述形状不能识别名字。
**决策**：traits 字段统一留空，先把所有数字字段录满；后续 P1 阶段人工配 25 条 trait_catalog 标签。

### 6.3 门将板式与场上不同
门将的左半"6 维"实际是 6 项门将能力（扑救/门将手控球/门将开大脚/门将反应/门将速度/门将站位），不是速射传盘防强。
**决策**：用 `six_dims_gk` 字段区分，渲染层（render_html.py）按是否有 `six_dims_gk` 走门将雷达图。

### 6.4 双位置卡的副位置 OVR 在标题区
副位置 OVR 不是次要信息——里斯·詹姆斯左/右后卫都是 131，玩家选他时可能两个都看。
**决策**：用 `alt_positions: [(位置名, OVR)]` 单独存。

### 6.5 面板图尺寸不一致
562 张实际有 100+ 种尺寸，**不能硬编码绝对像素**。但比例稳定。
**决策**：模板用百分比定义 ROI（§1）；如未来做 PaddleOCR 模板裁切，需先 resize 到标准 1160×783。

### 6.6 反应字段在多个位置族都有
反应在中后卫/边后卫/中场/前腰/边锋/中锋的 12 项里都是最后一项；门将的反应是单独一项放第 6 位。
**决策**：按字段表照搬，不要因为"看起来重复"漏读。

### 6.7 体型描述带"(专属)" 后缀
"瘦弱(专属)/一般(专属)"是 PTG 强化卡的特有体型，**必须完整保留括号**，影响数据真实性。

## 7. 对外汇报口径（重要）

**SPID 是内部信息，对外（含对话呈现）一律不显示。**
对外汇报用：**姓名 + OVR + 位置**，例如：
- ✅ 奥利塞 OVR133 前腰 已入库
- ❌ 863247827 奥利塞 OVR133 已入库

只有在 README 类工程文档（如本文）和入库脚本日志中可保留 spid，用于调试。
