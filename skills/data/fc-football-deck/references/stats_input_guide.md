# 球员能力数据录入指南（v5.1 修订）

## 一、定位修正（v5.1）

v5.0 错误地把"放弃 OCR"理解成"完全不做 OCR"。**v5.1 修正**：

> **OCR 是"一次性离线录入工具"，不是"运行时依赖"。**

- 一次性把 562 张球员信息面板图通过 OCR + 人工复核 → 固化到 `data/player_ptg_stats.json`
- 录入完成后，OCR 工具可以**完全丢弃**
- Skill 运行时只读 JSON，不再做任何识别
- 这样才彻底实现"用户使用 Skill 时不再实时 OCR 读取原表"

**v5.1 总目标**：完成 562 名球员全量录入，做到"表内有 = 数据库有 = 用户可用"。

---

## 二、录入路径（按推荐度）

### 方案 A：大模型视觉逐张读图（推荐 ⭐⭐⭐⭐⭐）

把信息面板图（`assets/panels/{spid}.png`）交给 LLM Vision，让它一次性输出该球员的完整 JSON。

**优势**：
- 准确率最高（≈100%）
- 不依赖任何 OCR 部署环境
- 无环境兼容性问题（没有 numpy 签名冲突这类坑）
- 直接产出结构化 JSON

**劣势**：
- 每张约 4-5 秒
- 562 张需要分多轮会话拆批

**当前进度**：批次 1（4 人）已用此方法录入成功验证。

### 方案 B：PaddleOCR / RapidOCR 跑批 + 人工复核

**优势**：可批量、速度快
**劣势**：
- 沙箱内 numpy 签名冲突，部署不稳
- 特性图标识别约 85-92% 准确率，仍需人工复核
- PaddleOCR 完整安装 500MB+

**用法**：在非沙箱机器上跑批，把结果导入 `player_ptg_stats.json` 后再人工抽样校验，跑完即丢。

### 方案 C：完全人工看图录入

**适用**：少量精校（如顶级球星 OVR≥132）
**不适用**：562 全量录入（工作量太大）

## 四、字段说明

### 核心字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | 字符串 | ✅ | 球员中文名（与 `player_ptg_cache.json` 的 name_cn 一致） |
| `ovr` | 整数 | ✅ | 8 强强化总评（115-135） |
| `salary` | 整数 | ✅ | 工资（19-31） |
| `primary_position` | 字符串 | ✅ | 主位置中文名 |
| `secondary_positions` | 数组 | 可选 | 副位置中文名 |
| `six_dims` | 对象 | ✅ | 六维基础能力 |
| `position_stats` | 对象 | ✅ | 至少录入主位置的 12 项分位置能力 |
| `traits` | 数组 | ✅ | 持有/金特性列表 |
| `body` | 对象 | ✅ | 身高/体重/模型类型 |
| `weak_foot` | 整数 | ✅ | 弱足星级 1-5 |
| `skill_moves` | 整数 | ✅ | 花式技巧星级 1-5 |
| `reputation` | 字符串 | 可选 | 名声 |
| `birthday` | 字符串 | 可选 | 生日 yyyy.m.d |

### six_dims 六维（必须六个全填）

```json
{"速度": 129, "射门": 134, "传球": 131, "盘带": 136, "防守": 67, "强壮": 112}
```

取值范围通常 60-145。**直接看面板原图右上角的六个圆形数值。**

### position_stats 12 项分位置能力

每个位置下 12 项细分能力（前场/中场通用 12 项 / 门将另一套）。**至少录入 `primary_position` 的 12 项。**

### traits 特性

`type` 取 `"持有"` 或 `"金特性"`，金特性是面板图中带金色边框的图标。

### body 身体数据

`model` 取值：`"瘦弱(专属)"` / `"一般(专属)"` / `"普通"` / `"魁梧(专属)"` 等。

## 六、验证脚本

`scripts/validate_ptg_stats.py`（待开发）会做以下校验：
- JSON 格式合法性
- 必填字段完整
- 六维各项在 [50, 150] 区间
- 12 项分位置数值在 [50, 150] 区间
- 弱足/花式星级在 [1, 5]
- 特性中文名是否在 `trait_catalog.md` 中存在
- 主位置在合法位置列表中

## 七、录入完成后的运营流程

- OCR 工具与录入脚本**完全丢弃**
- Skill 安装包**不包含任何 OCR 依赖**
- 后续 PTG 改版时，重跑一次离线 OCR + 人工复核即可，Skill 主体不动
- 数据补丁通过 PR / commit `data/player_ptg_stats.json` 即可，无需重新部署 Skill
