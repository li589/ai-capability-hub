# 球员与球队实体映射规则

## 球员映射优先级

1. **alias 精确匹配**：用户输入归一化（去空格、转小写）后查 `data/player_alias_map.json` 的 `alias_to_name`
2. **name_cn 精确匹配**：在 `data/player_ptg_cache.json` 中按 `name_cn` 字段精确匹配
3. **包含匹配**：用户输入是 name_cn 的子串，或 name_cn 是用户输入的子串（处理"罗德里戈" vs "罗德里戈·戈伊斯"等）
4. **国籍 + 关键字组合**：当用户带上下文（如"法国 罗梅罗"），先按国籍过滤再做关键字匹配
5. **无法匹配**：返回 `未匹配` 标记，**不得静默丢弃**

## 球队（国家队）映射

球队名直接用中文标准化形态，参考 `data/national_teams_2026_groups.json` 的 `all_nations`。

常见简写归一化（在 Skill Runtime 中预处理用户输入时做）：
- 葡国 → 葡萄牙
- 法兰西 → 法国
- 桑巴 → 巴西
- 三狮 → 英格兰
- 潘帕斯 → 阿根廷
- 战车 → 德国
- 斗牛士 → 西班牙
- 橙衣军 → 荷兰
- 维京 → 挪威

## 未匹配球员的展示规则

当某球员在 PTG 数据库中没有卡片时，**在阵容图中用灰色卡 + 球员名字展示**，注明：

> 该球员暂无 FC Online PTG 数据，本场分析不含此球员的具体能力数值。

**绝不**假装该球员存在或编造数据。

## 冷门球队（PTG 卡 < 11）处理

当国家队 PTG 卡数不足 11 张：

1. **不**强行展示前 N 张卡的细节
2. 用 `safety_policy.md` 中的兜底话术
3. 通用结论用 "FC Online 近千场后台模拟比赛预估，分析可能是……"
4. 公开数据补充：FIFA 排名、近期热身赛、关键球员现实角色（来自 WebSearch）

**当前 PTG 卡 < 11 的球队**（来自 `national_teams_2026_groups.json` 的 `no_or_low_ptg`）：

约旦(1)、伊朗(2)、南非(3)、乌兹别克斯坦(4)、伊拉克(5)、埃及(5)、巴拿马(5)、库拉索(6)、佛得角(7)、澳大利亚(7)、突尼斯(8)、巴拉圭(8)、海地(9)、厄瓜多尔(9)、新西兰(10)、乌拉圭(10)、加拿大(11)、阿尔及利亚(11)、加纳(11)。

> **注**：上述清单基于当前 PTG 数据快照。Skill 运行时以 `query.py nation_stats --nation X` 的实际返回为准。

## 同名/重名消歧

PTG 数据库可能出现同名球员（不同国籍）。消歧策略：
1. 用户输入若带国籍上下文 → 直接按国籍过滤
2. 否则取 OVR 最高的命中
3. 必要时在回复中显式提示："您指的是 [国籍] 的 [球员]，对吗？"

## alias_map 维护流程（运营）

1. 发现用户高频输入但匹配失败的简称 → 加入 `data/player_alias_map.json`
2. 加入前必须通过 `query.py player --name <候选标准名>` 验证能命中
3. 热门 8 队（葡萄牙/法国/英格兰/阿根廷/巴西/德国/西班牙/荷兰）主力球员的 alias 必须人工 100% 复核
