# Skill 回复模板（Markdown 形态，供龙虾客户端渲染）

## 通用规则

1. 球星卡卡面图必须用本地 file:// 路径以原图呈现：
   ```
   ![C罗](file:///Users/.../assets/cards/863020801.png)
   ```
2. **关键球员要附卡面图，不要光出文字**。每个被点名分析的球星（前场/中场/后防核心、对位关键人、连线两端）都要带卡面图，让用户能"看到"球员，而不是只看一行文字。
3. 标题层级用 `##`、`###`，不要用 `#`（避免抢喧场）
4. 每条回复末尾固定附上「数据来源说明 + 推荐追问」两个板块
5. 当 `query.py` 返回 `fallback_required: true`，必须按 safety_policy.md 第 5 节走兜底话术
6. 用户追问倾向来源时，固定回答："来自公开赛前预测的综合信号"

### 禁止写法（用户体验红线）

- ❌ **不要**单独出现"PTG 赛季映射"「映射状态」「11 人匹配 X 人」「卡数不足」「PTG 数据库覆盖」等技术性、内部口径表述——这些是数据生产环节的内部状态，用户不关心。需要兜底时直接走通用话术即可，不解释为什么走兜底。
- ❌ **不要**说"不展开 FC 数据细节"这种自报缺陷的话——直接给该出的内容，没法给的就走兜底话术，不告诉用户"我没数据"。
- ❌ **不要**输出"未匹配球员"清单。除非用户特别问，否则在正文里悄悄按 PTG 命中的球员展开分析就够了。

1. `query.py match --home X --away Y` 拿 FC 数据维度倾向 + `suggested_score`
