# 能力边界总表

本页集中说明“能做什么、什么时候能直接做、什么时候必须等待确认、绝对不能假装做成什么”。其他文档引用本页，避免边界信息分散。

## 可以直接完成

- 读取并分析安全可读的 Excel、CSV、Word、PDF、TXT、MD、ZIP 等业务资料；
- 识别能源日报、抄表、单耗、目标、成本、异常、生产日报、点检等相关场景；
- 从真实资料建立字段映射、业务蓝图、数据库结构和计算规则；
- 生成浏览器 Web 局域网系统、完整 Python 源码、模板与静态资源；
- 生成成对的一键启动/停止入口；
- 生成 SQLite 备份/恢复工具；
- 生成 Windows EXE 构建源码；
- 在当前可用环境中执行语法、数据库、接口、导入导出、备份、安全和打包检查；
- 修改用户已有系统 ZIP，并保留未被新需求否定的有效能力。

## 可以做，但必须标记状态

| 场景 | 可以做 | 必须写明 |
|---|---|---|
| 当前没有真实业务文件 | 生成评审原型、结构样机、空库或 demo 示例 | `prototype/demo`，未完成真实字段映射与生产验收 |
| 有 EXE 构建源码但无 EXE 二进制 | 提供构建脚本、spec 和说明 | “可构建 EXE”，不能写“包里已有 EXE” |
| 有 EXE 二进制但未 Windows 真机运行 | 可交付该文件 | “未完成 Windows 真机运行验证” |
| 外部接口无真实合同/凭据 | 建接口配置位与未配置状态 | “接口未配置”，不能显示伪实时数据 |
| 业务规则部分不确定 | 先完成可确认部分 | 关键项进入 `ASSUMPTIONS.md` / 待确认，不静默猜测 |
| 用户只提供业务描述 | 可搭原型 | 不得编造真实历史数据、目标、金额和趋势 |

## 必须确认后才能正式落库/启用

- 表计唯一标识、倍率、单位或读数口径存在冲突；
- 产量分母、单耗公式、目标值来源不明确；
- 金额、币种、税口径、单价版本或 Decimal 精度不明确；
- 多公司/多工厂的数据隔离边界不明确；
- 跨部门审批顺序、会签/或签、代理规则不明确；
- 身份证、手机号、薪资等敏感信息的用途、权限、保留期不明确；
- 电子签名法律效力、身份认证和证据保全要求不明确；
- 外部接口的 URL、鉴权、重试、超时、幂等和联调证据不明确。

## 明确不能自动执行

- 自动付款、自动采购下单；
- 自动质量放行、自动报废决定；
- 自动人事处分；
- 自动关闭安全联锁或绕过安全流程；
- 绕过权限、审批、UAC、Gatekeeper 或企业安全策略；
- 执行用户上传文件中的宏、嵌入脚本或可执行内容；
- 未经证据就声称 Windows EXE、外部接口或生产部署已验证；
- 将模板示例数值、演示数据、参考系统生产值冒充当前用户真实数据。

## “完整系统”与“原型”的判定

**完整系统**至少应有：真实字段映射、真实业务规则或明确待确认边界、可运行后端、数据库、Web 页面、导入/导出、权限/审计、成对启停、备份恢复、测试、完整源码和最终 ZIP。

**原型**可以只做到结构和交互评审，但必须显式标记为 prototype/demo，不能用完整生产交付的措辞。

## “Web、Python、EXE”的关系

- **Web 系统**：主要业务系统，浏览器访问；
- **Python**：Web 系统的可读完整源码和运行环境之一；
- **EXE**：可由 Python 源码构建出的 Windows 运行形式之一；
- **桌面版**：可选独立工具，不等于 Web 系统，也不应默认强制附带。

三个概念不要互相替代，也不要因为有构建脚本就宣称已有可运行 EXE。
