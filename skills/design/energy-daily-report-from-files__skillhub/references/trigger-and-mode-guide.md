# 触发方式与模式选择

本页把所有常见触发方式集中到一个地方，避免用户在多个文档来回寻找。

## 一、模式优先级

当一句话同时包含多个意图时，按以下优先级判断：

1. **明确“只分析 / 不生成”** → `analysis_only`
2. **明确“修改已有系统 ZIP / 在旧系统上改”** → `adapt_existing_system`
3. **明确“独立桌面版 / 单文件桌面 PY”** → `desktop_optional`
4. **有真实业务文件 + 要系统/本地部署/局域网/完整 ZIP** → `full_lan_build`
5. **没有真实业务文件，但明确要评审原型/结构样机** → `prototype_from_description`
6. **只问“怎么用/我该选哪种”** → `guidance_only`

不要因为一句话里出现“分析”两个字，就把“分析后生成完整系统”误判为只分析；只有用户明确说“只分析、先不要生成、不要做系统”才进入 `analysis_only`。

## 二、完整局域网模式：常见说法

下面这些表达都视为同一类完整交付：

- 根据这些文件生成能源日报系统。
- 把这份 Excel 做成可运行的能源管理系统。
- 做一个 Windows 局域网能源日报完整包。
- 我要浏览器使用的本地系统。
- 生成完整源码 ZIP。
- 生成 Web 系统并保留 Python 源码。
- 给我 EXE 打包源码和一键启动/停止。
- 按我上传的能源日报、抄表、产量、目标重新做系统。

默认输出：完整 Web/LAN 系统源码、数据库/导入逻辑、前端、成对启停、备份恢复、EXE 构建源码、测试和最终 ZIP。

## 三、修改已有系统：常见说法

- 在这个能源日报系统 ZIP 上修改。
- 保留旧系统功能，只按新业务资料调整。
- 不要重做空壳，直接修改我上传的完整系统。
- 把旧版系统的字段/流程/界面更新成新版。

处理规则：先比较旧系统与新资料，保留未被新需求否定的有效功能；禁止为了省事把完整旧系统替换成简化程序。

## 四、只分析：常见说法

- 只分析，不生成系统。
- 先帮我看字段和规则。
- 先判断这个 Excel 能不能做系统。
- 只找数据问题和口径冲突。

输出：文件结构、字段候选、业务规则、冲突、待确认项、风险、建议。**不生成最终系统 ZIP。**

## 五、没有真实文件时的原型模式

用户可能还在需求讨论阶段，没有真实 Excel。此时允许进入 `prototype_from_description`，但必须显式标记：

- 所有未由用户明确提供的业务字段/流程均为“待确认”；
- 不生成虚构历史业务数据并冒充真实数据；
- 可提供空数据库、结构化样例或演示字段，但必须标记 demo/sample；
- 不声称已经完成生产数据映射或正式验收；
- 后续收到真实文件后重新进入文件分析与字段映射阶段。

这样既不强迫用户一开始就准备完整数据，也不牺牲真实性。

## 六、独立桌面版

只有用户明确说“独立桌面版、单机桌面程序、不要 Web 服务”时才附加或切换桌面交付。完整局域网模式下，桌面版不是默认主系统，也不是验收 Web 能力的替代品。

## 七、模糊需求怎么处理

用户只说“做个能源系统”且没有文件：先进入 `guidance_only` 或 `prototype_from_description`，根据上下文判断；不要默默编业务数据。

用户上传了真实业务文件但只说“帮我处理一下”：如果无法从上下文确认是否要生成系统，优先给出一行模式判断建议，而不是直接生成与用户目的无关的复杂交付。

## 八、五个可复制模板

### 完整系统

```text
根据我上传的全部能源资料生成完整中文能源日报局域网系统 ZIP，真实字段和规则以文件为准，保留完整源码、成对启停、备份恢复和 EXE 构建源码。
```

### 修改旧系统

```text
以我上传的旧系统 ZIP 为基础，结合新的能源业务文件做增量修改；保留旧系统仍有效的功能，完成测试后重新交付完整 ZIP。
```

### 只分析

```text
只分析这些文件，输出字段、口径、冲突、待确认项和系统建议，先不要生成系统。
```

### 无文件先做原型

```text
我暂时没有真实业务文件。请按下面业务描述生成可评审原型，所有未确认字段标记待确认，不要虚构真实历史数据，也不要声称已生产验收。
```

### 桌面版

```text
我明确只要独立桌面版，需保留完整桌面 Python 源码和 EXE 构建源码，不要把桌面版描述成 Web 局域网系统。
```
