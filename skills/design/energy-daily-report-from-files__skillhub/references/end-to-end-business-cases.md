# 端到端业务案例

这些案例不是伪造的验收数据，而是说明“用户怎么说 → 技能怎么处理 → 最终得到什么”。案例中的数值仅作为叙述示意，不能复制成真实用户数据。

## 案例 1：单工厂能源日报从 Excel 到局域网系统

### 用户输入

上传：月度能源日报.xlsx、表计清单.xlsx、产量日报.xlsx、年度单耗目标.xlsx。

提示词：

```text
根据这些资料生成完整能源日报局域网系统，电、水、天然气都要按日记录，能看实际单耗和目标差异。
```

### 技能处理

1. 只读检查文件结构与安全；
2. 识别日期、工厂/车间、表计、能源类型、期初/期末、倍率、产量、目标；
3. 将单位、倍率、分母、目标版本映射到业务蓝图；
4. 发现两个表中“产量”口径不同，则进入待确认，不静默合并；
5. 展开完整 Web 基线并按真实字段改造；
6. 导入已确认历史数据；
7. 校验单耗、目标偏差、权限、导入幂等、备份恢复；
8. 打包最终 ZIP。

### 最终用户看到

- 浏览器首页：今日消耗、单耗、目标偏差、异常；
- 日报录入与导入；
- 按能源/车间/日期查询；
- 目标达成与异常闭环；
- Excel 导出；
- Windows 一键启动/停止；
- 完整 Python 源码和 EXE 构建源码；
- `ASSUMPTIONS.md` 只保留尚未确认的关键口径。

## 案例 2：在已有系统 ZIP 上增量修改

### 用户输入

上传旧版能源系统 ZIP + 新版能源日报 Excel，并说明“新增蒸汽能源，取消多人审批，保留现有备份和局域网启动方式”。

### 技能处理

- 先检查旧系统目录、数据结构、已有字段和有效功能；
- 做“保留 / 修改 / 新增 / 删除”差异表；
- 不用简化程序替换完整旧系统；
- 新增蒸汽字段和计算；
- 将审批流按用户要求调整，保留审计；
- 保留并复测备份、一键启停、端口、Web 入口；
- 做迁移兼容检查后重新打 ZIP。

### 增值输出

除新系统外，额外生成一份变更摘要：哪些模块没动、哪些字段迁移、哪些规则废止、历史数据是否需要重算。这样用户可以直接拿去做验收或版本评审。

## 案例 3：用户只想先分析

### 用户输入

```text
先帮我分析这几份能源文件，不要生成系统。我想知道字段是否够用、单耗口径有没有冲突。
```

### 技能处理

只输出：

- 文件清单与可读性；
- 字段字典；
- 同义字段与冲突；
- 单耗分子/分母候选；
- 目标来源与版本；
- 数据质量问题；
- 如果未来要做系统，还缺哪些关键信息。

不会因为技能默认能力很强就强行生成 ZIP。

## 案例 4：还没有真实业务文件，先做评审原型

### 用户输入

```text
我还没有整理好 Excel。先做一个电、水、天然气日报原型，角色是填报员和能源管理员，后续我再补真实数据。
```

### 技能处理

可生成结构原型，但所有未确认内容写成 `candidate` / `demo` / `待确认`：

- 空数据库或明确标记的 demo 记录；
- 录入页、列表、趋势页、权限结构；
- 不写死真实目标、真实价格、真实历史趋势；
- `DELIVERY_STATUS` 明确“原型，未完成真实业务文件映射”；
- 后续收到真实文件后重新分析映射，再升级为正式版本。

### 为什么这样做

用户不必因为暂时没有整理好数据就无法体验流程，同时技能也不会为了“看起来完整”而制造虚构业务事实。

## 案例 5：EXE 需求容易被误解

### 用户输入

```text
给我一个 EXE。
```

### 技能处理

如果当前环境不能 Windows 真机构建，则交付：完整 Web 源码 + EXE 构建入口 + spec + 构建说明，并明确当前状态是“可构建，未包含已验证 EXE”。如果用户随后在 Windows 上构建并提供结果，再把真机证据写入交付状态。

不会把“存在 build 脚本”写成“EXE 已经验证可用”。
