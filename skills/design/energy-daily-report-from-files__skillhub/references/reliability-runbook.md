# 可靠性运行手册

目标：把“能生成”提升为“出问题时知道在哪一步、不会误删数据、能安全继续”。

## 生成前四项只读检查

1. 检查内置完整局域网基线：

```text
python scripts/ensure_full_lan_energy_system.py --check-only
```

2. 检查用户输入文件是否安全可读：

```text
python scripts/inspect_business_files.py <输入文件或目录>
```

3. 检查运行环境和空间：

```text
python scripts/preflight_check.py <项目目录>
```

4. 检查业务场景：

```text
python scripts/classify_scenario.py "业务描述"
```

## 为什么先做基线健康检查

完整 Web 系统使用内置参考架构作为代码基线。健康检查会在写入业务项目之前验证：

- ZIP 能正常打开；
- CRC 无损坏；
- 没有绝对路径或 `..` 路径穿越；
- 核心 Web/数据库/导入/备份/启停/EXE 构建源码齐全；
- 基线 SHA-256 可记录。

实际展开先进入临时 staging 目录，只有验证完成才复制到目标项目，避免“压缩包坏到一半才发现”并把半成品混进项目。

## 运行稳定性检查顺序

生成完整系统后至少按顺序检查：

1. Python 语法；
2. SQLite `integrity_check`；
3. 核心路由/API；
4. 业务主键和重复导入；
5. 目标/单耗/成本抽样计算；
6. Excel 导入与导出回读；
7. 权限、403、409、审计；
8. 备份 → 校验 → 恢复自检；
9. 启动/停止必须是同一项目 PID 和端口；
10. 最终 ZIP 独立解包复测。

## 常见运行故障与处理

| 现象 | 先检查 | 不要做 |
|---|---|---|
| 双击启动没反应 | Python 前置条件、日志、`quick_check.py` | 不要关闭系统安全策略 |
| 浏览器本机能开，其他电脑打不开 | 服务监听地址、Windows 防火墙、同网段、端口 | 不要用“关闭全部防火墙”解决 |
| 端口被占 | 当前端口配置与 PID 文件 | 不要结束所有 Python 进程 |
| 数据库锁住 | 是否有另一个服务实例/WPS/同步程序占用 | 不要强制删除数据库 |
| 导入重复 | 文件 SHA-256、业务主键、导入批次 | 不要直接清空历史数据重导 |
| EXE 构建成功但运行失败 | templates/static/vendor/data 是否被打包、工作目录 | 不要把“构建成功”写成“运行已验证” |
| 恢复备份失败 | 是否先停服、备份完整性、目标路径 | 不要覆盖唯一数据库副本 |

## 中断恢复

固定阶段：

`ANALYZED → MAPPED → SCAFFOLDED → IMPLEMENTED → IMPORTED → TESTED → PACKAGED`

运行：

```text
python scripts/diagnose_and_resume.py <项目目录>
```

它只读诊断并给出 `resume_from`。恢复原则：

- 已完成产物不删除；
- 已成功导入批次不重复导入；
- 输入指纹变化则回到分析；
- 业务蓝图变化则重新验证受影响阶段；
- 数据库完整性失败立即停止写入并从已验证备份恢复。

## Windows EXE 的证据等级

从低到高：

1. `build_exe_windows.py` 存在 → **可构建**；
2. 当前 ZIP 实际带 `.exe` → **已包含构建产物**；
3. Windows 真机构建退出码 0 → **已构建验证**；
4. Windows 真机启动、登录、读写、停止均通过 → **运行验证通过**。

只允许按当前达到的等级描述，不得跳级。
