# FAQ 与故障处理

先按症状找答案，不需要从头读完整文档。更系统的恢复流程见 `reliability-runbook.md`，稳定错误码见 `error-catalog-and-recovery.md`。

## 1. 我第一次用，不知道说什么

上传真实能源资料后直接说：

```text
根据我上传的文件生成完整能源日报本地部署 ZIP，保留完整源码、成对启停、备份恢复和 EXE 构建源码。
```

如果只是想先看看资料，说：

```text
只分析这些文件，先不要生成系统。
```

完整模式选择见 `trigger-and-mode-guide.md`。

## 2. 我没有真实业务文件，还能用吗？

可以做**评审原型**，但不能冒充正式生产系统。可以先按业务描述搭页面、字段结构、权限和空数据库；所有未确认内容标记 `candidate/demo/待确认`。等真实 Excel 到位后重新做字段映射和正式验收。

## 3. 必须上传参考模板吗？

不需要用户额外上传技能内置参考模板。技能包自身已经带完整局域网代码基线。用户只需要上传自己的业务资料或已有系统 ZIP。

正式生成前可以只读检查内置基线是否完整：

```text
python scripts/ensure_full_lan_energy_system.py --check-only
```

## 4. 为什么技能包里有一个参考 ZIP？会不会照抄别人的业务数据？

参考 ZIP 只提供完整 Web/LAN 代码架构。当前用户的系统名、组织、产线、能源类型、目标、价格、公式和历史数据必须来自当前用户资料。参考系统中的业务值不得机械复制。

## 5. 文件很多，我到底只看哪几个？

最终系统 ZIP 中，普通用户只看：

- `00_请先看_交付导航.md`
- 一键启动
- 一键停止

`vendor/` 是第三方离线依赖，普通用户不用阅读。按角色文件地图见 `delivery-file-map.md`。

## 6. Web 系统和 EXE 有什么区别？

Web 系统是主要业务系统，浏览器访问；Python 是完整源码；EXE 是 Windows 上的一种运行形式。`build_exe_windows.py` 存在只代表“可构建 EXE”，不代表压缩包里已经有 EXE，更不代表 Windows 真机运行验证通过。

## 7. 为什么默认不是桌面软件？

局域网多人使用更适合浏览器 Web 系统：服务器只需在一台电脑启动，其他电脑用浏览器访问。独立桌面版仍保留，但只有用户明确要求时才附加，避免与主 Web 系统混淆。

## 8. Windows 双击启动没有反应怎么办？

按顺序检查：

1. 是否已有符合要求的 Python，或交付包是否实际包含已验证 EXE；
2. 查看启动窗口或日志提示；
3. 运行 `python scripts/quick_check.py .`；
4. 仍无法判断时运行 `python scripts/diagnose_and_resume.py .`。

不要通过关闭系统安全策略、隐藏错误窗口或全局结束 Python 进程来“解决”。

## 9. 本机能打开，其他局域网电脑打不开怎么办？

检查服务是否监听局域网地址、访问电脑是否同网段、端口是否被防火墙规则允许、服务器 IP 是否变化。允许按企业 IT 规则开放**当前项目所需端口**，不要建议关闭整个防火墙。

## 10. 端口被占用了怎么办？

系统应优先探测可用端口，启动和停止使用同一端口/PID 状态。也可设置项目支持的端口环境变量或按交付说明修改端口配置。停止脚本只允许停止本项目服务，不能结束所有 Python 进程。

## 11. 文件被 Excel/WPS 占用怎么办？

对可重试的文件锁错误会有限次重试。仍失败时关闭占用文件的软件，再从当前阶段继续，不需要重做整个项目。

## 12. 上传文件损坏了怎么办？

损坏、加密、CRC 失败或结构异常不能盲目重试。系统应返回稳定错误码和中文修复方式。优先从原始来源重新导出，不要求用户提供文档密码。

## 13. 多个 Excel 字段名字不一样能合并吗？

可以做候选映射，但关键字段不会静默合并。比如“产量”“入库量”“合格产量”可能代表不同分母，必须保留来源证据；影响单耗、金额、权限和审批的冲突应进入待确认。

## 14. 同一个文件导入两次会重复吗？

正式系统应按文件指纹、业务主键和导入批次做幂等。成功行不应因中断恢复而重复写入；文件或蓝图变化时重新进入相应阶段。

## 15. 产量为 0 时单耗怎么算？

不能显示虚假的 0 或 100%。分母为 0 时应显示“—/不可计算”，并保留原始消耗与产量供追溯。

## 16. 电价、蒸汽价格、目标值不确定怎么办？

不写死。可先配置为待确认或带来源版本的候选值。金额和目标进入正式计算前，应确认来源、有效期、单位和精度。

## 17. 没有网络能运行吗？

目标是局域网/离线可运行。若依赖已随交付包完整提供，就不需要外网。缺失依赖时不得静默联网下载；应明确告诉用户需要 IT 提供匹配 Python/系统架构且带 SHA-256 清单的离线包。

## 18. Python 没装怎么办？

如果最终 ZIP 没有已验证 EXE，就需要安装符合要求的 Python。安装流程由用户或 IT 在标准系统界面中执行；技能脚本不得自行提权、绕过安全策略或静默下载安装器。

## 19. 有 build_exe_windows.py 就等于已有 EXE 吗？

不等于。证据等级是：可构建源码 → 实际带 EXE → Windows 真机构建通过 → Windows 真机运行通过。只能按真实达到的等级描述。

## 20. EXE 构建成功但运行失败怎么办？

优先检查 `templates/`、`static/`、`vendor/`、seed/config、数据目录是否正确纳入打包，以及运行时数据是否写到 EXE 同级持久化 `data/`。构建成功与运行验证必须分开记录。

## 21. Web 系统怎么备份？

完整系统必须带 `backup_restore.py` 或等价工具。备份使用 SQLite 安全备份接口并校验完整性；恢复前先停服，覆盖前保留当前数据库回滚副本。

## 22. 数据库损坏怎么办？

立即停止写入，不要删除唯一数据库文件。保留故障副本，从最近一次**已校验**备份恢复，再做完整性检查。

## 23. 生成到一半失败，会不会从头重来？

不应无条件重来。构建状态按 `ANALYZED → MAPPED → SCAFFOLDED → IMPLEMENTED → IMPORTED → TESTED → PACKAGED` 记录。`diagnose_and_resume.py` 给出 `resume_from`，已完成且仍有效的产物应保留。

## 24. 内置参考基线坏了怎么办？

`--check-only` 会在真正生成前发现，并返回 `LAN_REFERENCE_*` 错误。此时不要继续向业务项目写半成品；重新校验 `FILES_SHA256.txt`、重新获取完整技能包并解压。

## 25. 能否修改我已有的系统，而不是重做？

可以。上传旧系统 ZIP 和新资料后明确说“在旧系统上增量修改”。技能应先做差异分析，保留仍有效的功能、数据结构和启停/备份能力，不得用一个简化程序替换原完整系统。

## 26. 可以去掉审批吗？

可以按真实业务要求调整。审批不是固定模板。即使取消多人审批，仍建议保留必要的状态、修改记录和审计追溯。工作流必须按用户业务蓝图验收，而不是套固定“管理员审核”模板。

## 27. 可以接实时电表/ERP/MES 吗？

可以预留接口和配置，但只有用户提供真实接口合同、鉴权方式和联调证据后，才能声称已接通。未配置时必须显示“未配置”，不能生成伪实时数字。

## 28. 可以自动付款、自动采购或自动质量放行吗？

不做高风险自动决策。可做记录、计算、预警、建议、人工审批和审计，但自动付款、自动采购下单、自动质量放行/报废、自动人事处分、安全联锁关闭等必须排除。

## 29. 怎样判断交付是真的完整，不是空壳？

查看：完整后端源码、数据库逻辑、真实字段映射、Web 模板/JS/CSS、导入导出、权限/审计、成对启停、备份恢复、EXE 构建源码、测试证据和最终 ZIP。只给 HTML、代码片段、伪数据或启动壳都不算完整。

## 30. 我只想知道接下来该做什么

运行：

```text
python scripts/quick_check.py .
```

如果项目中断或错误更复杂，再运行：

```text
python scripts/diagnose_and_resume.py .
```

它们应优先给中文结论和下一步，不让普通用户先看 Traceback。
