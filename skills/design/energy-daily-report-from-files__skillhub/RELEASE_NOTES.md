# V1.7.0 Release Notes

本次发布针对平台评测中分数最低的十项进行定向补强，重点解决“怎么触发、从哪里开始、边界散落、案例不足、文件多难理解、原型门槛、异常恢复和基线稳定性”。

## 用户体验与文档

- `START_HERE.md` 改为“30 秒选模式”，普通用户无需先理解 Web、Python、EXE。
- 新增 `trigger-and-mode-guide.md`，统一完整系统、旧系统增量修改、只分析、评审原型、独立桌面和指导六种模式及优先级。
- 新增 `capability-boundaries.md`，集中定义可直接做、需确认、只能标记状态和禁止自动执行的边界。
- 新增 `delivery-file-map.md`，按普通用户 / IT / 开发 / 审计四层解释文件，明确 `vendor/` 不需要普通用户阅读。
- 新增 `end-to-end-business-cases.md`，增加真实使用流程案例，而不是只展示零散输出片段。
- 重写 FAQ，覆盖无真实文件、旧系统修改、启动、局域网访问、端口、EXE、备份、导入幂等、数据库损坏等高频问题。
- 修正文档中 Web 主交付与可选桌面版的历史冲突；独立桌面版不再被默认 Web 验收器强制要求。

## 可靠性与异常处理

- `ensure_full_lan_energy_system.py` 新增 `--check-only` 只读基线健康检查。
- 展开完整局域网基线前检查 ZIP 可读性、CRC、安全路径、重复规范化路径、符号链接样式成员和核心文件。
- 实际展开先进入临时 staging 目录，验证完整后再复制到业务项目，减少基线损坏造成半成品写入。
- `FULL_LAN_SOURCE_MANIFEST.json` 记录参考基线 SHA-256、健康检查项目及“展开前已验证”状态。
- 新增 `reliability-runbook.md`，把启动、局域网访问、数据锁、备份恢复、中断续跑和 EXE 证据等级集中说明。

## 适用性与增值

- 新增“无真实文件的评审原型模式”：降低首次使用门槛，但所有未确认内容必须标记 demo/待确认，不得伪造真实业务数据。
- 强化“已有系统增量修改模式”：先做保留/修改/新增/删除差异，再修改完整系统并给出迁移/变更摘要。
- 工作流验收改为按真实业务蓝图；用户明确不需要多人审批时，不再因缺固定审批模板判为不完整。

## 发布验证

发布前应通过：版本一致性、安全策略、完整测试集、局域网基线只读健康检查、完整基线展开、备份恢复自检、完整交付校验和 ZIP 独立解包复测。
