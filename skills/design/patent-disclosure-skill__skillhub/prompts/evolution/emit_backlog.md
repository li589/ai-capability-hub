# 技能进化旁路 · 输出进化清单

前置：已按 `research.md` 完成检索与抓取。

## 落盘

路径：`outputs/evolution/EVOL-YYYYMMDD-HHMM.md`（创建目录若不存在）。  
可用 Write 工具写入；**这是旁路唯一默认可写的产物路径**（另见用户确认后的 `docs/evolution/` 复制）。

合同字段见 `references/schemas/evolution_backlog.schema.yaml`（Markdown 实现时按下列结构即可）。

## 文档结构（必须）

```markdown
# 技能进化清单 EVOL-YYYYMMDD-HHMM

- **生成时间**：…
- **时间窗**：…
- **关注范围**：…
- **状态**：草案 · 待确认（未改技能）
- **原则**：半自动；人审闸门见文末

## 1. 观点 ↔ 信源（主表，必填）

| 编号 | 轨道 | 观点摘要（可核验） | 证据 | 发布/施行 | 信源标题 | 信源 URL |
|------|------|-------------------|------|-----------|----------|----------|
| S1 | 审查工具 / 申请客体 / 程序通识 | … | A/B/C | YYYY-MM-DD | … | https://… |

规则：
- **一行一个观点**；一个 URL 可支撑多行（观点不同则多行，URL 可重复）。
- URL 必须是抓取时使用的 **最终可打开地址**（勿用搜索页、勿用缺 host 的相对路径）。
- 观点摘要用中性表述，引用关键措辞可加引号；禁止无来源发挥。

## 2. 对技能的候选影响（待勾选）

| 编号 | 依赖信源 | 建议动作 | 可能改动的文件 | 风险/备注 | 建议 |
|------|----------|----------|----------------|-----------|------|
| E1 | S1,S2 | … | `prompts/…` | … | 采纳/搁置 |

- 仅证据 A/B 的 S* 可进入本表作为「建议改技能」依据。
- C 级只可出现在 §1 或「背景」，不可单独支撑 E*。

## 3. 明确不建议做的项（可选）

## 4. 人审闸门

```

## 质量自检（写完前勾选）

- [ ] §1 每行均有完整 `https://` URL  
- [ ] 无「据悉/网传」而无 URL 的行  
- [ ] 时间窗内或已注明仍有效的规范  
- [ ] 未改任何 `prompts/**` / `SKILL.md`（除非用户已确认且走 apply）  
- [ ] 回复用户时用简短说明 + 指出清单路径；完整表以文件为准，聊天里可摘主表
