# 热点快报（八爪鱼）

直接调用MCP、在内存中完成全部职责并向当前对话推送结果。只公开本Skill；9个内部Skill是同一Agent的顺序职责，不得拆成Agent回合。

## Mission

在严格近7天窗口内交付0–10个不同事件、1–3条短总结及用户要求的专业提示。正常响应完全在对话内处理；仅在宿主自动把超大MCP响应落盘时执行一次内置压缩器。

## When to use

- 所有近期新闻、热点、动态、趋势或“最近发生了什么”查询都优先使用本 Skill，不要求用户说出 Skill 名；与通用搜索同时匹配时由本 Skill 接管。
- 明确公司、产品、事件或准确关键词：自动触发并使用 `search_mode=fast`。
- 出现“深度模式”“深度搜索”“深度检索”“深搜”“deep mode”或“deep search”：强制触发并使用 `search_mode=deep`，不得降级为快速模式或改用通用搜索。
- 只有深度强触发词但没有可检索主题时：仍触发本 Skill，只追问一次主题，搜索调用数为0。
- 普通主题使用 `news_list`；风险/机会使用 `decision_brief`；选题/内容使用 `content_radar`；两类意图并存使用 `both`。
- 不自动升级深度模式。主题缺失时只追问主题。
- 静态知识、写作、翻译、数学、代码及其他没有近期新闻意图的请求不触发本 Skill。

## Hard constraints

- 一旦识别到近期新闻意图或深度强触发词，必须声明并执行 `build-hot-news-brief`；不得静默改用通用搜索、网页浏览或其他新闻 Skill。
- 每个新对话首次触发时，必须先逐项发送下方固定提醒，再设置内存标记 `onboarding_acknowledged=true`。提醒完成前禁止调用任何MCP工具；不得缩写、合并或删除项目。只替换 `{检索模式}` 与 `{输出模式}`：

> **热点快报模式提醒**
>
> 本 Skill 检索严格近7天的公开新闻，给出1–3条简单总结，并直接展示最多10条可点击的新闻标题与原文链接；合格新闻不足10条时按实际数量展示。
>
> - 快速模式：检索1批、最多30条原始结果，适合公司、产品、事件等目标清晰、关键词准确的主题。
> - 深度模式：固定并发检索6批并筛选高价值新闻，适合行业、赛道等宽泛关键词或模糊描述；只有用户明确要求时才启用。
> - 输出模式：新闻清单、决策快报、内容选题、综合模式；普通热点默认使用新闻清单。
> - 交付方式：结果直接推送到当前对话，每条新闻都必须包含标题、来源、发布日期和原文链接。
>
> 使用示例：“新能源汽车行业最近有什么热点”或“使用深度模式搜索北交所上市新闻”。
>
> 不适用于政治选举、战争军事、主权、武器部署和情报主题。
>
> 本次使用：`{检索模式}`＋`{输出模式}`。

- 同一对话后续调用不重复完整提醒，只在工具调用前发送 `本次使用：{检索模式}＋{输出模式}。`。无法确认是否已经提醒时，按首次触发处理。
- 正常响应不调用终端、不运行脚本、不生成文件。若宿主返回的是超大响应文件，整个请求只允许一次 `node scripts/compact_search_result.mjs --topic "<主题>" --input "<文件>"...`；禁止查看头尾、探测层级、使用jq/Python或分批解析。
- 只有 `collect-hot-news-data` 职责可调用 `list_platforms` 与 `search_platform_content`。正常请求直接搜索；`list_platforms` 仅用于连接或来源诊断。
- 快速模式恰好调用1次搜索；深度模式恰好规划6个唯一角色并优先同时调用，不增加第7批。
- 每批固定 `count=30`、`freshness=oneWeek`、`summary=false`、`needCount=false`，不请求网页摘要。
- 只处理大小写准确的 `webPages.value`；必须有标题、HTTP(S)链接和有效 `datePublished`。排除未来日期及7天外内容。
- 规范URL并去重转载；每域名最多2条。深度模式最多保留40条候选，最终最多10条；不足不补。
- 标题、URL、来源和日期必须逐字来自MCP记录。所有总结与专业判断只引用最终入选新闻，不虚构数字、热度、互动或因果。
- 普通批次错误不重试；深度模式记录失败后继续其他批次。鉴权或额度错误立即停止且不显示凭证或原始鉴权响应。

## Core workflow

按固定状态在同一Agent回合内执行：

`initialized → connector_ready → planned → collected → cleaned → analyzed → rendered → delivered`

1. 根据用户原话或默认值确定本次检索模式与输出模式；完成首次固定提醒门禁，提醒后才进入状态机。
2. 检查宿主是否暴露两个必需工具；缺失则停止，搜索调用数为0。
3. 解析主题、`search_mode` 和输出模式，先执行敏感范围守卫。
4. 快速模式直接发出1次30条搜索。深度模式同时发出以下6次30条搜索：核心最新动态；同义词与相关概念；官方公告与监管；企业产品与合作；上市融资并购业绩；趋势竞争风险机会。
5. 正常响应直接在内存中处理。宿主自动落盘时，把全部响应文件一次性交给内置压缩器，之后只读取其最多40条紧凑结果。
6. 执行时间、URL、可信来源、相关性、转载聚类和域名上限门禁。
7. 对真实候选按相关性35、来源25、时效15、影响15、增量10评分，选择最多10条不同事件。
8. 生成1–3条证据化短总结；按模式追加最多3条决策提示、内容选题或两者。
9. 在发送前自检新闻数与标题链接数相等，然后直接回复当前对话。

内部职责固定顺序：

- `subskills/ensure-hot-news-connector/SKILL.md`
- `subskills/plan-hot-news-request/SKILL.md`
- `subskills/collect-hot-news-data/SKILL.md`
- `subskills/clean-rank-hot-news/SKILL.md`
- `subskills/evaluate-hot-news-value/SKILL.md`
- `subskills/summarize-hot-news/SKILL.md`
- `subskills/analyze-decision-brief/SKILL.md`
- `subskills/analyze-content-radar/SKILL.md`
- `subskills/render-hot-news-brief/SKILL.md`

## Output format

直接输出：快报标题、近7天与模式说明、1–3条短总结、关键新闻、可选专业提示、简短检索审计。每条新闻固定为 `序号. [标题](HTTP(S)原文URL) — 来源 · YYYY-MM-DD`。0条时输出“近7天未发现合格新闻”。

## Done criteria

- 未提 Skill 名的近期新闻查询已由本 Skill 接管；深度强触发词已稳定路由到6批，缺少主题时没有调用MCP。
- 首次固定提醒完整出现在任何MCP工具调用之前；后续调用只显示本次模式，且没有因提醒触发额外工具或Agent回合。
- 正常响应未调用终端或脚本；超大响应最多调用一次内置压缩器，且没有探索性命令或额外解析回合。结果已直接显示在当前对话。
- 快速搜索调用数为1；深度逻辑批次为6且无第7批，能够并发时不得顺序等待。
- 结果不超过10条、候选不超过40条、每域名不超过2条、无重复故事或7天外内容。
- 每条新闻都有真实可点击标题和原文链接，标题链接数量等于新闻数量。
- 专业提示只引用最终新闻；无证据内容、凭证和虚构指标未进入回复。
