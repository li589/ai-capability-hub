# 热点快报对话输出契约

## 首次模式提醒

每个新对话首次触发时，先逐项发送主 `SKILL.md` 中唯一的固定“热点快报模式提醒”，再调用任何MCP工具。只替换检索模式和输出模式；不得缩写、合并或删项。发送后在当前对话内记录 `onboarding_acknowledged=true`。同一对话后续调用只发送本次检索模式与输出模式；无法确认提醒状态时按首次触发处理。

## 运行接口

`topic` 必填。`search_mode` 为 `fast` 或 `deep`；默认 `fast`。`mode` 为 `auto`、`news_list`、`decision_brief`、`content_radar` 或 `both`；普通主题默认 `news_list`。固定近7天、中文可信信源优先、最终最多10条。

每批搜索固定 `count=30`、`freshness=oneWeek`、`summary=false`、`needCount=false`。快速模式1批；深度模式6批并发优先。

## 大响应处理

正常MCP响应直接在内存中处理。宿主自动将超大响应落盘时，整个请求只执行一次：

```text
node scripts/compact_search_result.mjs --topic "<主题>" --input "<响应文件1>" --input "<响应文件2>" ...
```

压缩器一次读取全部文件，只输出标题、URL、域名、来源、发布日期、截断snippet和相关性，最多40条。禁止查看文件头尾、逐层探测字段、使用jq/Python或逐批运行解析命令。

## 快速总结

所有模式生成0–3条事实短句，每条不超过80个中文字符。总结只引用最终入选新闻，不写无证据数字、热度、因果或长篇背景。

## 新闻条目

每条固定输出为：

```text
序号. [标题](HTTP(S)原文URL) — 来源 · YYYY-MM-DD
```

标题、URL、来源和日期必须来自同一MCP记录。最终最多10条、每域名最多2条、同一故事只保留1条；不足不补。0条时输出“近7天未发现合格新闻”。

## 专业输出

- `decision_brief`：最多3条变化、影响对象、机会或风险及建议动作。
- `content_radar`：最多3个选题角度、受众、建议标题和内容切口。
- `both`：两类输出共用同一最终新闻集合。

所有专业内容必须绑定最终新闻证据。证据不足时减少项目，不虚构热度、指标、市场份额或确定性预测。

## 完成门禁

- 结果直接发送到当前对话，不回复报告路径。
- 快速搜索数为1；深度逻辑批次为6且无第7批。
- 正常路径没有终端和文件操作；超大响应压缩器调用数不超过1。
- 新闻数等于可点击标题链接数，且所有内容严格位于近7天。
