# 信息收集与交付约定

## 待检字段

| 字段 | 必填 | 示例 | CLI |
|------|------|------|-----|
| 产品或话题 | 是 | 「怡宝本优矿泉水」（≤30 字） | `--text` |
| 核心卖点（1–3） | 是 | 「深岩矿泉水源」「清甜顺滑」 | `--selling-points`（可多次） |
| 目标平台 | 是 | 小红书/公众号等（需 `--fetch-config` 拉实时枚举 value） | `--target-platform` |
| 种草正文结构型 | 是 | AIDA 型/痛点型/干货型等（需 `--fetch-config`） | `--seeding-structure` |
| 品牌调性 | 是 | 高级/专业等（需 `--fetch-config`） | `--brand-tone` |
| 参考文案 | 否 | 「偏小红书真人分享语气，不要硬广」（≤500 字） | `--reference-text` |
| 是否实际生图 | 否 | 不传=只产方案+生图 Prompt；传=实际生图 | `--generate-images` |
| 文字画进图 | 否 | 允许把文字画进图；仅生图时有意义 | `--render-text-on-image` |
| 封面张数 | 否 | 1（0–3） | `--cover-count` |
| 配图张数 | 否 | 1（0–8） | `--image-count` |
| 参考图（≤3） | 否 | 本地图片路径（png/jpg/jpeg/webp/gif/bmp，单张 ≤10MB） | `--ref-image`（可多次） |
| 参考图提示词 | 否 | 「白底正面 45 度」（≤100 字，仅在 `--ref-image` 有时写入） | `--ref-image-desc` |
| 调用来源 / 方式 | 否 | 默认 `01workbuddy` / `skill`（埋点） | `--origin` / `--origin-method` |

> 五项必填缺一创建会被 422/400 拦截；可选字段「可引导但不强制、缺省不传」走后端默认。**禁止夹带未声明字段**（如 `account_id`），夹带会被服务端 422——脚本不会构造这些。

## 收集流程

1. 触发 skill 后先拉一次 `--fetch-config` 拿三组枚举（target_platform / seeding_structure / brand_tone），同时判断五项必填是否齐全。
2. **必填齐全** → 直接执行（默认参数；可选缺省走后端默认）。
3. **有缺失** → 一次性追问缺失项（只问 1 轮），并把三组枚举用自然语言列给用户选。话术示例：
   > 技能已就绪 ✅ 帮你生成种草图文方案。方便补我几条信息就能开始：
   > 1. **产品或话题**——要种草什么（≤30 字，如「怡宝本优矿泉水」）
   > 2. **1–3 条核心卖点**——亮点是什么
   > 3. **目标平台**——（实时枚举：小红书 / 公众号 …）
   > 4. **种草正文结构型**——（AIDA 型 / 痛点型 / 干货型 / 情绪型 / 清单型 / 对比型 …）
   > 5. **品牌调性**——（高级 / 活泼 / 专业 …）
   > 不给参考文案/生图开关/张数也行，我用默认（只产方案+生图 Prompt、1 封面 1 配图）。
4. **仍不给** → 五项必填无法用默认兜底（都必填）；可选项缺失用默认继续，不阻塞。
5. 用户用自然语言选定枚举后，你回查 `--fetch-config` 拉到的对应 `value` 传入 CLI（如用户说「小红书 + 痛点型 + 高级」→ `--target-platform xhs --seeding-structure pain --brand-tone premium`）。

要点：一次问清，不挤牙膏；不展示技术字段名（如不出现 `xhs`/`aida`/`premium` 给用户，用「小红书」「AIDA 型」「高级」等自然语言）。**严禁硬编码文档示例值**——枚举一律靠 `--fetch-config` 实时拉，后端可能随运营配置变化。

## 参考图上传（可选）

- 用户有参考图（产品实拍、风格图等）想辅助生成时，用 `--ref-image PATH` 传入本地图片路径，可多次（最多 3 张，png/jpg/jpeg/webp/gif/bmp，单张 ≤10MB）。
- 脚本在创建任务**之前**自动完成三步上传（取预签名 → PUT 二进制 → 确认换 image_id），再把 image_id 写入创建请求 `reference_images`。无需手动调上传接口。
- 可附 `--ref-image-desc` 给参考图加提示词（≤100 字，如「白底、正面 45 度、晨光」），仅在传了 `--ref-image` 时写入。
- **大小控制**：单张参考图上限 10MB，超限脚本在**上传前**本地拒绝（退码 3，不发起上传、不扣点），提示「图太大，请压缩后重试」。这是脚本侧约定（API 文档未明示该上限），目的是避免大图直传 OSS 超时或被后端拒绝、浪费上传。
- 上传发生在创建任务之前：任一步上传失败任务未发起、未扣点（脚本按性质归入退出码 3/8/10/11，stderr 会注明「任务未发起、未扣点」）。
- 引导上传用中性文案：「把参考图发我，或给我图片路径。」不要侦测客户端环境。图太大我会提示你压缩。

## 调用与重试

- **主路径（异步）**：`POST /api/v1/content/seeding-article-generation` 立即拿 `task_id` → `GET /{id}` 轮询 → `completed` 交付 `data.markdown`。
- **拆分轮询（WorkBuddy/Web 防会话中断，推荐）**：
  - 创建：`python3 scripts/seeding_article.py --text "<产品或话题>" --target-platform <v> --seeding-structure <v> --brand-tone <v> --selling-points "卖点1" --selling-points "卖点2" --only-create`（退出码 0，拿 task_id；有参考图先上传内置在这步）
  - 轮询：`python3 scripts/seeding_article.py --poll-task <task_id> --text "<同上>" --out ...`（退出码 13 仍运行，再跑一次；退出码 0 交付报告）
  - ⚠️ `--poll-task` 必须带 `--text`（与创建时相同），否则报告标题退化为「任务 xxx」。
- **取枚举前置**：`python3 scripts/seeding_article.py --fetch-config` 拉取三组实时枚举展示，选定后用 `--target-platform`/`--seeding-structure`/`--brand-tone` 传入创建。`--fetch-config` 不创建任务、不扣点。
- **默认报告文件**：未传 `--out` 时，脚本自动写当前目录的 `种草图文方案-<task_id>.md`。
- **实扣字段**：`data.total_points`（整数，终态 `completed` 后返回）。
- **进度**：脚本 stderr 周期输出，用户中途问「跑到哪了」时读 stderr 最新行转述（status / progress_message / current_stage / 已用时 / task_id），不要说「查不了」。
- **失败重试（偏差）**：本 API **无 `/retry` 接口**。若输出含 `SEEDING_ARTICLE_TASK_ID` 或 stderr 含 `task_id=`，用户同意后用 `--retry-task <旧id> --text <产品或话题> <业务参数> --out ...`——脚本会用相同参数**重新创建新任务**（新 task_id、**独立扣费**）。须重供 `--text` 与全部业务参数以重建请求体。如实告知用户「重新提交会再计费」。
- **无幂等（偏差）**：本 API 无幂等机制（文档无 `idempotency` 字段，§4.3 禁未声明字段），脚本不发幂等头、不注入 body、无 `--idempotency-key`。**重复提交会新建任务、独立计费**——故同一意图不要重复点「再提交」，需重新生成时再调用创建；用户说「刚才那次再提交」时先确认是否真的要新建一次（会再扣费）。

## 交互节奏

- **收集**：最多 1 轮追问，之后用默认继续，不让用户反复等待。
- **扣点确认（硬性，跳过不得）**：跑脚本**前**必须告知「本次任务预计扣点约 100 点起步（账户需 ≥100 点门槛，不足创建前会被 402 拦截），实际扣点以最终完成任务时的实际点数为准，是否继续？」，用户**明确确认**后才跑脚本。重试时如实说明「重新提交会再计费」。
- **速度差异**：说明本次大约耗时（如「只产方案约 1–3 分钟；开启生图约 5–15 分钟，期间 stderr 会有进度」）。用户问进度时转述 stderr，勿空等不回。
- **交付**：报告 MD 一次性渲染给用户（务必把分隔符之间的 Markdown 真正渲染出来，不能只甩文件路径或贴带 `\n` 的原始文本）。后端渲染的钩子标题/正文文案/生图方案与 Prompt 原样呈现，**不要本地改写、总结或重排**；后端 `markdown` 已自带一级标题，脚本不再重复加标题，你也不用补。
- **成功后**：告知实际扣除点数（如「本次实际扣除 12 点」）+ 报告查看方式（已渲染在上方 + 已存为 MD 文件）。
- **失败后**：告知「因网络原因本次任务执行失败，相应点数已返还」；有 task_id 时询问是否用 `--retry-task` 重新创建（独立扣费）。**注**：若失败发生在参考图上传阶段，任务未发起、未扣点（stderr 会注明）。
- **交付后**：主动询问是否需要后续动作（如「换个种草结构再生一版」「某条卖点再强化」「开启实际生图再生一版」「生成公众号版本」）。

生成的种草图文由模型依据产品话题、卖点与创作参数产出，封面图与配图（开启 `generate_images` 时）均为 AI 生成，文案可能存在事实偏差或不符合品牌调性；正式发布前请人工复核信息准确性、合规性与品牌一致性。
