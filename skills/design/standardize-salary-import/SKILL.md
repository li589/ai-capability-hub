# 正常工资薪金导入表生成

把用户主动上传的 Excel 工资表或工资表图片整理为可继续导入的“正常工资薪金导入”Excel。以 `assets/normal-salary-import-template.xlsx` 为唯一输出模板，保持原工作表、两行复合表头、列顺序、合并单元格、数据验证和减免事项清单不变。只转换和校验来源数据，不重新计算工资、社保、公积金或个人所得税。

## 能力边界

- 处理 `.xlsx`、`.xls`、`.png`、`.jpg`、`.jpeg`；同一任务可接收多个文件或多张连续图片。
- 使用当前环境自带的电子表格读取能力处理 Excel，使用内置视觉能力读取图片。不得调用外部 OCR、外部 API 或把工资数据上传到第三方服务。
- 仅写入模板已有的 21 个明细列。不得新增、删除、重命名或调换工作表与列，不得修改 `Sheet2` 的减免事项清单。
- 用户提供某字段时原样或按明确格式规则规范化后写入；用户未提供时保持空白，不以零、默认值、身份证件类型或计算结果补齐。
- 对写入模板的证件号码、手机号码、工资及其他受约束字段执行确定性格式校验。格式错误时保留来源值、将对应输出单元格标为黄色，并在交付摘要中说明；不得静默修正或删除。
- 必须扫描每个非空工作表。主工资表之外的加班、补贴等工资构成表属于补充来源；其中非零工资性记录不得因人员未出现在主表而被遗漏。
- 不把“实发工资”“到手工资”“银行代发金额”映射为模板的“工资”，不把个人所得税写入任意扣除列，不把社保合计拆分为养老、医疗、失业和大病医疗。
- 不代替个税申报，不判断免税资格，不修改源文件，不写入个税、银行、ERP 或财务系统。

## 输入与前置条件

至少需要一个用户上传的工资表文件或工资表图片。先确认文件可访问、未加密且包含可识别的人员明细。图片必须完整覆盖表头和数据行；内置视觉能力不可用、图片模糊、被遮挡或缺页时，说明无法可靠提取，并请用户补充清晰图片或 Excel。

每次执行都先阅读 [模板字段与格式](references/template-schema.md) 和 [字段映射规则](references/field-mapping.md)。输入包含图片时，再阅读 [图片提取规则](references/image-extraction.md)。开发或回归验证时阅读 [测试案例](references/test-cases.md)；典型用法见 [Playbook 案例](references/playbook-example.md)。

## 执行步骤

1. **清点输入。** 枚举每个文件的全部非空工作表，不得在找到第一个人员表后停止。列出工作表或图片顺序，识别主工资表、加班/补贴等补充工资构成表、表头、人员行、合计行、重复表头和备注区。姓名或首个文本字段为“合计”“总计”“小计”“本页合计”“本月合计”“累计”等汇总标签，且证件标识为空的行必须排除，即使该行包含工资或扣除金额；不得把它计入人员数。多个公司、多个工资期间或多个互不相干的表格必须分开处理，不得合并为同一人员清单。
2. **提取原始数据。** Excel 只读取单元格值和必要格式，不执行宏、不刷新外部链接。图片只使用内置视觉能力逐行读取；看不清的单元格保持空白并记录来源位置，不猜测姓名、证件号码、日期或金额。
3. **建立字段映射。** 按字段语义而非列位置映射到 21 个模板明细列。对同名、近义和高风险字段严格执行 [字段映射规则](references/field-mapping.md)。明确属于工资性报酬的“加班工资”“加班费”“加班补贴”映射到“工资”；加班天数、基本工资和计算说明不映射。未映射字段不写入模板，但必须在交付摘要中列出，不得静默丢弃。
4. **形成来源覆盖清单和规范 JSON。** 先按“文件 + 公司/主体 + 工资期间 + 工作表 + 来源行”建立覆盖清单，至少记录人员标识、是否为补充表、非零工资性金额及处理结果；再将每名应输出人员整理为 `scripts/validate_payroll_json.py` 接受的规范字段对象。同一公司、同一工资期间的补充表中，人员不在主工资表、但有非零加班工资或其他明确工资性金额时，必须在该期间的输出中新增一名人员，将该金额写入“工资”，其余未提供字段保持空白并报告必填项缺失。补充表属于另一工资期间时，为该期间建立独立输出，不得并入主表期间，也不得遗漏。补充表中只有零金额的人员不单独创建工资记录；若该人员已由其他来源纳入，保留其明确提供的零值。来源未提供的键可以省略或写为 `null`/空字符串；不得以零代替缺失金额。
5. **运行确定性校验。** 执行 `python scripts/validate_payroll_json.py <input.json>`。读取标准输出中的 `normalized_rows`、`issues` 和 `status`。脚本只校验和规范化，不写文件；各字段必须独立校验，不得因同一行其他字段错误而跳过。出现 `missing_required`、无效枚举、无法确认的证件号码、无效居民身份证号码、无效手机号码、无效日期、无效/负数/超限金额、重复人员或公式式文本时，保留用户提供的原值并在交付摘要中提示。证件类型缺失或无效但证件号码非空时，C、D 两列分别产生错误并分别标黄；已明确为合法的其他证件类型时，不套用居民身份证 18 位规则。
6. **生成工作簿并标记格式错误。** 复制 `assets/normal-salary-import-template.xlsx` 为新文件，从 `Sheet1` 第 3 行开始写入人员数据。可解析金额写为数值；校验失败的金额保留来源文本。证件号码和手机号码写为文本，能确认的任职受雇从业日期写为有效日期并显示为 `yyyy/mm/dd`；无效日期保留来源文本。对校验结果中 `level=error` 且带有 `field` 的项目，按 [模板字段与格式](references/template-schema.md) 将对应输出单元格填充为浅黄色 `#FFF2CC`；例如证件号码错误标黄 D 列、手机号码错误标黄 E 列、工资错误标黄 G 列。只标记错误单元格，不标记整行，不更改 `Sheet2`，也不新增问题工作表。超过模板预留行数时，只复制第 3 行的数据格式和数据验证到新增行；不得改变前两行表头、合并区域或 `Sheet2`。
7. **复核输出。** 检查人员行数与规范 JSON 一致，并逐项核对来源覆盖清单：每条非零工资性来源记录必须已写入对应公司和工资期间的输出，或已因明确重复/归属歧义列入待确认项，不得静默消失。主工资表标题或字段明确写明“含加班”，且同一期间、同一人员已在主表出现时，只用加班表做覆盖核验，不得再次累计；若无法可靠匹配人员，则保留为独立收入行并提示，不得丢弃。确认所有 `level=error` 且可定位到模板列的单元格均为浅黄色 `#FFF2CC`，且黄色单元格均有相应错误说明。继续检查必填字段缺失均已报告；金额未因文本转换、千分位或科学计数法改变；证件号码和手机号未丢失前导零；所有未提供字段仍为空；无额外工作表、列或公式错误。对工作簿执行一次视觉检查，确认黄色标记、表头、数据和列宽可读。
8. **交付结果。** 单一公司、单一工资期间时，默认命名为 `<用户上传文件基础名>-标准工资表.xlsx`，例如 `工资表2.xlsx` 输出为 `工资表2-标准工资表.xlsx`；若基础名已以 `-标准工资表` 结尾则不重复追加。一个源文件包含多个公司或工资期间且必须拆分时，分别命名为 `<基础名>-<公司或工资期间>-标准工资表.xlsx`，避免覆盖并在交付摘要中说明拆分原因。多个互不相干的源文件分别输出。交付时简要说明写入人数、缺失必填项、未映射字段、图片疑似识别项和其他校验问题；对格式错误按“输出行号 + 模板列名 + 原因”逐项说明，例如“第 3 行，证件号码：居民身份证号码必须为 18 位，末位为数字或大写 X；对应单元格已标黄”。存在问题仍可交付待确认稿，但不得称为“已可直接申报”或“税务认定无误”。

## 需要确认或警示的情形

- 姓名、证件类型或证件号码缺失时保持空白，并明确提示该行不满足模板必填要求。
- 来源只有“应发工资”“税前工资”而未明确其是否等于模板“工资”时，请用户确认；来源只有实发金额时不得写入“工资”。
- 来源只有社保合计、五险一金合计或其他合并金额时，不拆分、不分摊，相关明细列保持空白。
- 免税收入大于零但减免事项缺失，或减免事项不在 `Sheet2!A2:A25` 中时，保留已提供内容并提示可能无法导入。
- 图片关键字符存在 `0/O`、`1/I`、`5/S`、小数点、负号或行列错位歧义时，对该单元格留空并列出待确认位置。
- 证件类型为“居民身份证”且证件号码不是 18 位，或前 17 位含非数字、末位不是数字或大写 `X` 时，保留原值、标黄 D 列并报告；其他证件类型不套用居民身份证号码规则。
- 手机号码非空但不是 11 位数字时，保留原值、标黄 E 列并报告。
- 工资无法解析为有限非负数字或超过模板上限时，保留原值、标黄 G 列并报告。
- 发现同一“姓名 + 证件类型 + 证件号码”重复时保留各行，不自动合并或删除。
- 跨工作表匹配人员时，优先使用“证件类型 + 证件号码”；缺少证件信息时，仅当同一公司、同一工资期间内姓名唯一且完全一致才按姓名匹配。重名或归属不明时保留独立行并提示，不得猜测合并。

## 权限与安全

本技能仅读取用户指定的本地附件，并在用户可访问的位置创建一个新的 Excel 文件；不覆盖源文件、不删除文件、不联网、不调用外部 OCR 或外部 API、不改变外部系统状态。校验脚本仅读取一个本地 JSON 文件并向标准输出返回 JSON，不写文件。工资、证件号码和手机号码属于敏感个人信息，不得写入日志、参考资料、示例或公共目录；测试只能使用虚构数据。任何未来的外部传输、系统导入或覆盖写入都必须另行说明目标和影响，并在执行前取得用户确认。
