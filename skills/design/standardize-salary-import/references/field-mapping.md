# 字段映射规则

## 映射顺序

1. 优先使用与模板完全一致的表头。
2. 再使用本文件列出的明确同义词。
3. 同一来源字段存在两个合理目标时停止映射，保持目标为空并提示用户确认。
4. 模板没有对应列的字段不得挤入相近列或备注列；在交付摘要中列为“未映射字段”。

## 可直接映射的常见同义词

| 来源字段 | 模板字段 |
| --- | --- |
| 员工姓名、职工姓名、人员姓名 | 姓名 |
| 身份证件类型、证件类别 | 证件类型 |
| 身份证件号码、证件号、身份证号 | 证件号码 |
| 手机号、联系电话、手机 | 手机号码 |
| 入职日期、任职日期、受雇日期 | 任职受雇从业日期 |
| 工资薪金、工资薪金收入、本期工资 | 工资 |
| 加班工资、加班费、加班补贴（明确为工资性报酬） | 工资 |
| 免税工资、免税金额 | 免税收入 |
| 养老个人、个人养老、养老保险个人部分 | 养老保险 |
| 医疗个人、个人医疗、医疗保险个人部分 | 医疗保险 |
| 失业个人、个人失业、失业保险个人部分 | 失业保险 |
| 大病医疗个人部分 | 大病医疗 |
| 公积金个人、个人公积金、住房公积金个人部分 | 代扣公积金 |
| 企业年金、职业年金、年金个人部分 | 企业(职业)年金 |

## 必须确认或禁止映射

- `应发工资`、`税前工资`、`应付工资`：只有来源说明其等于本次正常工资薪金收入时才能写入“工资”；否则询问用户。
- `实发工资`、`到手工资`、`银行代发金额`：永远不得写入“工资”。模板没有实发工资列，将其列为未映射字段。
- `个人所得税`、`代扣个税`：模板没有对应列，不得写入“其他税后扣除”。
- `社保合计`、`个人社保合计`、`五险合计`：不得按比例拆分为养老、医疗、失业和大病医疗。
- `五险一金合计`：不得拆分为社保和公积金。
- `公司承担社保`、`单位养老`、`单位公积金`：不得写入个人代扣列。
- `大病医疗专项附加扣除`：不得写入“代扣社保 / 大病医疗”。
- `专项附加扣除`、`子女教育`、`住房贷款利息`等：模板没有对应列，不得写入“其他扣除”。
- `加班天数`、`基本工资`、`加班计算公式/说明`：不得作为另一笔工资写入；只映射来源明确给出的加班工资、加班费或加班补贴金额。
- `部门`、`岗位`、`工号`、`出勤天数`、`奖金`等：模板没有对应列，不得新增列。
- 只有证件号码但没有证件类型：证件类型留空，不根据号码格式推断。

## 数值与空值

- 空单元格、`null`、空字符串、“未提供”均按缺失处理并保持空白。
- 只有来源明确写出 `0`、`0.00` 或等价数值时才输出零。
- 去除金额文本中的人民币符号、普通千分位和首尾空格后转为数值；括号负数、红字负数或带减号金额保留负值并报错，不自动改为正数。
- 不从应发、扣除、实发之间反推任何缺失金额。

## 写入前格式校验与标记

- 仅当证件类型为“居民身份证”时，证件号码必须匹配 `^\d{17}[\dX]$`：共 18 位，前 17 位为数字，末位为数字或大写 `X`。不自动把小写 `x` 改为大写；不匹配时保留原值、标黄模板 D 列并报告 `invalid_resident_id_number`。
- 各字段独立校验：不得因 C 列证件类型错误而跳过 D 列。证件类型缺失或不在模板枚举中、但证件号码非空时，C 列按缺失或枚举错误标黄，D 列同时报告 `unverifiable_id_number` 并标黄，说明因证件类型无效而无法确认号码格式。已明确为合法护照等其他证件类型时，不套用居民身份证 18 位规则。
- 手机号码非空时必须匹配 `^\d{11}$`。不匹配时保留原值、标黄模板 E 列并报告 `invalid_mobile`。
- 工资必须能解析为 0 至 99,999,999.99 的有限数字。非数字、负数或超限时保留原值、标黄模板 G 列并报告对应金额错误。
- 所有带 `field` 的 `level=error` 都标黄其对应模板单元格，颜色为浅黄色 `#FFF2CC`；交付摘要同时列出输出行号、模板列名和错误原因。

## 多表与重复行

- 必须枚举源工作簿全部非空工作表；不得只读取第一个工作表或第一个识别到的人员表。
- 先区分公司/主体、工资期间、主工资表与加班、补贴等补充工资构成表，再建立“文件 + 公司/主体 + 工资期间 + 工作表 + 来源行 + 人员标识 + 非零工资性金额 + 处理结果”的来源覆盖清单。
- 同一公司、同一工资期间的补充表中存在非零加班工资等明确工资性金额、但人员不在主表时，新增人员行并将该金额映射为“工资”；其余未提供字段留空。补充表属于不同工资期间时，为其建立独立输出，不得并入其他期间。补充表中的零金额本身不创建新人员，但已由其他来源纳入的人员应保留明确提供的零值。
- 同一工资期间内，主表标题或工资字段明确说明“含加班”，且补充表人员可可靠匹配到主表时，不得把补充表金额再次加到工资中。主表未说明是否包含该项时，不自动相加；保留独立记录并提示用户确认。
- 跨工作表优先按“证件类型 + 证件号码”匹配；缺少证件信息时，仅在同一公司、同一工资期间内姓名唯一且完全一致时按姓名匹配。重名或归属不明时不得猜测合并。
- 分页重复表头不作为人员行。
- 姓名或首个文本字段为“合计”“总计”“小计”“本页合计”“本月合计”“当月合计”“累计”等汇总标签，且证件类型、证件号码为空的行，必须作为汇总行排除；即使该行的工资、社保、公积金或个税有值，也不得计入人员数或写入模板。
- 汇总标签旁带有冒号、空格或“（人）”等说明时，先去除这些非姓名说明再判断。无法确定是人员还是汇总时，保持该行不写入并提示用户确认。
- 多张图片拼接时，以表头和连续行号判断顺序；无法确认顺序时分别处理。
- 使用“姓名 + 证件类型 + 证件号码”检查完全重复。发现重复时保留各行并提示，不自动合并。
