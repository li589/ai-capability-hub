# 图片提取规则

## 能力与隐私边界

只使用当前环境内置的图片理解能力读取工资表图片，不调用外部 OCR、网络接口或第三方文件服务。内置视觉能力不可用时，不能处理图片；请用户提供 Excel 或可复制文本。不得在日志或示例中复述完整证件号码、手机号码和工资数据。

## 提取步骤

1. 确认图片方向、清晰度、表格边界、表头和最后一行是否完整。
2. 多张图片先判断是否为同一表的连续页，检查重复表头、重复人员和缺页。
3. 先读取表头，再按视觉行逐行读取；不得先抄全部数字再猜测所属列。
4. 为每个关键值保留图片编号、视觉行和来源列，以便发现错位时回查。
5. 将看清的值写入规范 JSON。未显示的字段与看不清的字段都留空，但在问题摘要中区分“来源未提供”和“图片无法确认”。
6. 按字段类型复核：证件号码和手机号按文本；日期按年月日；金额检查小数点、千分位和负号。

## 必须标记为无法确认的情形

- 字符可能是 `0/O`、`1/I/l`、`2/Z`、`5/S`、`6/G`、`8/B`。
- 小数点、逗号、负号或括号被网格线遮挡。
- 证件号码、手机号码或金额被截断、打码、反光覆盖或跨页。
- 合并表头导致同一数值可能属于两个字段。
- 行距过小、网格倾斜或图片拼接导致人员与金额可能错行。

遇到以上情形时，目标单元格保持空白并列出待确认位置。不得选择“看起来最像”的字符，也不得利用合计数反推个人金额。

## 视觉复核

- 对姓名、证件号码、工资和各扣除金额执行第二次独立逐行查看。
- 若图片包含合计行，只用于发现可能漏行或错位；不得用合计差额补齐个人数据。
- 图片提取结果必须经过 `scripts/validate_payroll_json.py` 校验后才能写入模板。
