## Phase 0：输入验证 + 生成范围确认（IG-A门控）

**风险等级**：L1

### 0.1 输入验证

1. 检查 `company_type` 非空且为合法枚举值（V1规则）
2. 检查 `business_model` 非空（V2规则）
3. 检查 `operating_regions` 非空且≥1个地域（V3规则）
4. 检查 `company_size` 非空且为合法枚举值（V4规则）
5. 检查 `generation_scope`（如提供）为合法枚举值（V5规则）
6. 检查 `operating_regions`国家可识别性（V6规则）
7. 检查 `business_model`是否包含政府客户描述（V7规则）

### 0.2 生成范围确认（IG-A交互门控）🔴

**触发条件**：用户未在输入中手动指定 `generation_scope`

**禁止行为**：智能体不得代用户决定生成范围——必须展示推荐模式并等待用户确认

**交互话术模板**：

```
## 生成范围推荐

根据企业规模（{company_size}），推荐生成范围：**{recommended_scope}** 模式

| 选项 | 模式 | 产物范围 | 文件数 |
|------|------|---------|--------|
| A | full（完整版） | 合规手册+8套SOP+8份表格+角色矩阵+违规流程，每类文件独立输出（DOCX+XLSX） | 19个 |
| B | standard（标准版） | 合规手册+5套SOP+5份表格+角色矩阵，违规流程内联合规手册 | 12个 |
| C | compact（精简版） | 合规手册（精简版，含核心SOP+表格内联） | 1个 |

请选择（输入A/B/C），或直接回复"确认"使用推荐模式。
```

**用户响应处理**：
- 选择A/B/C → 设置 `generation_scope` 为对应模式
- 回复"确认" → 使用推荐模式（按 `company_size` 映射规则）
- 用户手动指定了 `generation_scope` → 跳过此门控直接使用

### 0.3 上下游衔接确认

1. 如用户提供 `existing_host_country_law` → Phase 1/2/3/4中采用"引用模式"（标注引用上游技能成果）
2. 如用户提供 `existing_risk_assessment` → Phase 1企业画像中引用风险等级
3. 如未提供 → 采用"独立生成模式"（标注"建议配合对应技能使用"）

### Phase 0 产出

- 验证通过/失败状态
- `generation_scope` 确认值（full/standard/compact）
- 上下游衔接策略（引用 vs 独立生成）

## Phase 1：企业画像构建 + 法规适用分析

**风险等级**：L2

### 1.1 企业画像构建

根据输入参数构建企业反贿赂合规画像：

| 画像维度 | 推断规则 | 影响 |
|---------|---------|------|
| 企业规模 | company_size参数 | 组织架构复杂度 + 生成范围 |
| 行业风险等级 | industry_sector映射（制药/能源/基建/国防→高/金融/贸易→中/科技/服务→中低） | 合规手册重点章节+SOP管控严格程度 |
| 运营地域风险 | operating_regions × TI CPI指数推断 | 第三方尽调增强级别+政治捐赠管控必要性 |
| 政府业务风险 | business_model中政府客户占比推断 | 政治捐赠/慈善捐赠SOP必要性 |
| 法规适用 | operating_regions → FCPA适用对象判定+UKBA §7"密切联系"判定 | 合规手册法规范围声明 |
| 上下游衔接 | 是否有上游技能成果 | 引用vs独立生成策略 |

### 1.2 法规适用分析

**FCPA适用对象判定**（三选一）：
- 发行人(issuer)：在美国证券交易所上市的美国或外国公司→FCPA全面适用
- 国内企业(domestic concern)：注册于美国/主要营业地在美国的公司、合伙人、个人→FCPA全面适用
- 在美国境内行为的外国主体(territorial jurisdiction)：在美国境内从事促进贿赂的行为→FCPA反贿赂条款适用

**UKBA §7适用性判定**：
- 商业组织在英国成立或开展业务（或在英国的任何部分开展业务）→UKBA §7适用
- §7"未能防止关联人贿赂"——与英国有"密切联系"(close connection)的企业→UKBA可能适用
- 唯一抗辩：企业已建立"充分预防程序"(adequate procedures)

**中国法适用性判定**：
- 中国企业→《反不正当竞争法》第7条+《刑法》第163/164条适用
- 中央企业/国企→《中央企业合规管理办法》第22条适用

**东道国法适用性**：
- 如提供 `existing_host_country_law` → 引用上游技能成果
- 如未提供 → 使用ISO 37001通用框架，标注"[需检索东道国反贿赂法规]"

### 1.3 FCPA vs UKBA 加速费差异分析（关键法域差异）

| 维度 | FCPA | UKBA 2010 |
|------|------|-----------|
| 加速费例外 | 15 U.S.C. §78dd-1(b) 狭义例外——仅限加快政府例行非自由裁量行政行为 | 无任何加速费例外——任何以获取商业优势为目的的支付均违法 |
| 适用条件 | 支付目的仅为加快护照签发/许可证处理/警方保护/信件递送等例行行政行为 | 不适用 |
| 建议策略 | 即使FCPA适用，建议零容忍政策（多数跨国企业已放弃加速费例外）+ UKBA管辖下强制执行零容忍 |

### Phase 1 产出

- 企业反贿赂合规画像
- 法规适用分析报告（FCPA/UKBA/中国法/东道国法适用性判定）
- FCPA vs UKBA加速费差异标注（供SOP-05使用）
- 生成策略确认

## Phase 2：合规手册14章生成

**风险等级**：L2

### 2.1 第一章：合规政策声明与领导层承诺

1. 生成合规政策声明——明确企业对反商业贿赂的零容忍承诺
2. 政策声明要素：
   - 适用法规范围（FCPA+UKBA+中国法+东道国法+ISO 37001）
   - 合规承诺（零容忍贿赂行为/主动披露违规/持续改进合规体系）
   - 适用人员范围（全体员工+董事会+第三方代理+合资伙伴）
   - UKBA §7"充分预防程序"声明——企业已建立adequate procedures
   - 领导层承诺（CEO/董事会签署）
   - 修订机制（年度审查+法规变更触发修订）
3. **full模式**：含CEO签署模板 + 董事会决议模板

### 2.2 第二章：贿赂风险评估

1. 按运营地域/业务模式/行业领域/政府业务占比四维度评估贿赂风险等级
2. 风险评估要素：
   - 地域维度：按TI CPI指数映射风险（CPI<30→极高风险/30-50→高风险/50-70→中风险/>70→低风险）
   - 业务模式维度：政府招标→高/代理商分销→中/直销→低
   - 行业维度：制药/能源/基建/国防→高/金融/贸易→中/科技/服务→中低
   - 政府业务占比：>30%→高/10-30%→中/<10%→低
3. 风险等级输出：
   - 🔴高风险 → 强化管控措施（增强尽调+多层审批+定期审计）
   - 🟡中风险 → 标准管控措施（标准尽调+二级审批+年度审计）
   - 🟢低风险 → 基础管控措施（基础尽调+一级审批+定期抽查）
4. 风险评估更新触发条件（法规变更/新市场进入/业务模式变化/合规事件发生）
5. 风险评估结果对SOP管控严格程度的映射关系

### 2.3 第三章：合规组织架构与职责

1. 根据企业规模和generation_scope生成组织架构：
   - full模式（大型企业）：首席合规官→合规部门（反贿赂专项组）→区域合规专员→部门合规接口人→业务操作员
   - standard模式（中型企业）：合规官→关键部门接口人→业务操作员
   - compact模式（小型企业）：合规负责人（高管兼任）→业务操作员
2. 各层级职责定义（含独立性和报告线要求）
3. **full模式**：合规委员会设置+外部合规顾问角色+独立审计职能

### 2.4 第四章：ISO 37001 反贿赂管理体系适配

1. ISO 37001:2016 十大要素与本合规手册14章的映射关系表
2. 管理体系文件结构（手册→程序文件→作业指导书→记录四级体系）
3. ISO 37001 认证路径与准备（可选，full模式提供）

### 2.5 第五章：第三方商业关系管理

1. 第三方分类与风险分级：
   - 高风险第三方：政府合同代理商/中介机构/咨询顾问/高风险国家代理商
   - 中风险第三方：一般代理商/分销商/合资伙伴
   - 低风险第三方：标准供应商/服务提供商
2. 第三方尽职调查流程（引用SOP-01）
3. 第三方合同中的反贿赂条款模板
4. 第三方持续监控与年度复审机制

### 2.6 第六章：礼品、招待与差旅管控

1. 礼品分类标准（促销礼品/商务礼品/特殊礼品→逐级审批）
2. 招待分类标准（商务餐饮/活动邀请/差旅安排→限额+审批+记录）
3. 禁止行为：
   - 向政府官员提供任何形式的贵重礼品
   - 在合同谈判/招标期间向交易对方提供招待
   - 以现金或现金等价物形式提供礼品
4. 审批层级与限额标准：[需结合企业行业惯例和当地市场标准确定]
5. 引用SOP-02礼品招待审批流程

### 2.7 第七章：捐赠与赞助管控

1. 政治捐赠管控：
   - 政策原则：禁止或严格限制企业直接/间接政治捐赠（full/standard模式）
   - 如企业所在地法律允许政治捐赠：须经合规委员会审批+公开披露
   - FCPA风险：政治捐赠不得用于换取政府业务或政策优惠
2. 慈善捐赠审批：
   - 实质审查——捐赠对象不得与政府官员或其亲属有关联
   - 关联性判断——捐赠不得与任何正在进行的政府业务/招标相关
3. 赞助活动审批：
   - 实质审查——赞助活动须有合法商业目的
   - 禁止向政府官员直接或间接支付赞助费用

### 2.8 第八章：利益冲突管理

1. 利益冲突类型定义：
   - 经济利益冲突（在合作企业/竞争对手持有股份或权益）
   - 雇佣关系冲突（亲属在合作企业/政府机构任职）
   - 外部职务冲突（在合作企业担任董事/顾问/合伙人）
   - 礼品招待引发的潜在利益冲突
2. 申报义务：年度全面申报+重大事项即时申报
3. 处理方式矩阵：回避/限制/剥离/附条件批准
4. 引用SOP-06利益冲突申报标准操作程序

### 2.9 第九章：财务与非财务控制

1. 财务控制措施：
   - 支付审批分级（金额分级+支出类型分级+地域分级）
   - 现金支付限制（禁止大额现金支付/鼓励银行转账/现金支付须有合法理由和完整记录）
   - 佣金合理性审查（佣金比例须与市场可比+须有实际交付物证明）
   - 账簿记录准确性（确保账目准确反映交易实质/FCPA会计条款§78m(b)要求）
2. 非财务控制措施：
   - 合同审批与签署控制
   - 供应商/代理商准入控制
   - 举报热线设置与保护（匿名举报/反报复保护）
3. 引用SOP-05加速费管控 + SOP-07现金支付管控

### 2.10 第十章：培训与沟通

1. 培训体系设计：
   - 入职培训（全体员工——FCPA/UKBA/中国法/企业政策基础）
   - 定期培训（年度——法规更新/案例分析/情景模拟）
   - 专项培训（针对高风险岗位——销售/采购/政府关系/代理商管理）
   - 高管培训（反腐败合规责任+领导层承诺）
2. 培训内容矩阵（按岗位×培训类型）
3. 培训效果评估与记录保存
4. 沟通机制：政策传达/定期通讯/举报渠道宣传

### 2.11 第十一章：监控与审计（含违规上报）

1. 内部审计制度设计：
   - 审计频率（年度全面审计+季度专项审计）
   - 审计范围（第三方尽调/礼品招待记录/捐赠审批/利益冲突申报/支付合规/培训完成率）
   - 审计流程（计划→执行→报告→跟踪→关闭）
2. 持续监控机制：
   - 交易监控（异常支付模式/异常佣金比例检测）
   - 数据分析和趋势报告
3. 违规上报机制（引用O5违规上报流程——full模式；内联——standard/compact模式）
4. 外部审计安排（full模式）

### 2.12 第十二章：违规调查与纠正措施

1. 违规发现与上报渠道（引用O5流程）
2. 内部调查程序：
   - 初步评估（事实收集→风险范围评估→调查计划）
   - 正式调查（访谈/文件审查/电子数据取证/第三方核实）
   - 事实确认（调查结论→根本原因分析）
3. 处置措施分类：
   - 内部纪律处分（警告/降职/解雇/奖金追回）
   - 业务调整（终止代理关系/修订流程/SOP更新）
   - 外部报告（DOJ自愿披露/UK SFO自我报告/当地监管报告）
4. FCPA自愿披露路径：
   - DOJ FCPA Corporate Enforcement Policy：自愿披露+完全合作+及时适当补救→推定不起诉
5. UKBA自我报告路径：
   - SFO Guidance on Corporate Prosecutions：自我报告+合作是重要减轻因素
6. 纠正措施（Corrective Actions）：
   - 违规调查根本原因分析（系统性缺陷vs个人失误）
   - 流程变更（根据根本原因修订相关SOP/流程）
   - 全员再培训（涉及修改的流程对相关岗位重新培训）

### 2.13 第十三章：记录保存与文件化信息

1. 记录保存范围（尽调记录/礼品招待记录/捐赠审批记录/利益冲突申报/培训记录/审计报告/违规调查记录）
2. 保存期限：
   - FCPA会计条款：账簿记录保存5年（15 U.S.C. §78m(b)）
   - UKBA §7"充分预防程序"证据保存：建议6年
   - ISO 37001要求：保留必要文件化信息以证明体系有效性
3. 文档分类与归档
4. 记录检索与审计支持
5. 记录销毁规则与保密要求

### 2.14 第十四章：制度修订与持续改进

1. 法规变更监测机制（DOJ FCPA Opinion Procedure Releases/SFO Guidance更新/东道国法修订/ISO标准更新）
2. 制度修订触发条件（法规变更/业务模式变化/合规事件/审计发现/管理评审）
3. 修订流程与审批
4. 持续改进机制（PDCA循环——Plan计划/Do执行/Check检查/Act改进）
5. ISO 37001 管理评审（年度管理评审输入/输出要求）

- 每章包含政策声明+操作流程+法律依据引用+ISO 37001映射

### 3.1 SOP-01：第三方尽职调查

   - 标准尽调（L1）：适用于低风险第三方——基础信息核实+制裁清单筛查+公开信息检索

5. 政府官员特别规定（零奢侈礼品/严格限额/不得在合同谈判期间提供招待）

### 3.3 SOP-03：政治捐赠管控（full）

1. 政治捐赠定义（向政党/政治候选人/政治行动委员会/政治相关组织提供资金或实物支持）
2. 管控原则：禁止或严格审批（取决于企业所在地法律）
3. 捐赠审批流程：申请→合规审查（关联性判断/政府合同冲突检查）→合规委员会审批→记录→年度公开披露
4. FCPA风险：政治捐赠不得被用于换取政府业务或政策优惠

### 3.4 SOP-04：慈善捐赠审批（full）

1. 慈善捐赠定义（向慈善机构/非营利组织/社区项目提供资金或实物支持）
2. 审批流程：申请→实质审查（受赠方背景/与政府官员关联性/与当前业务的关联性）→合规官审批→记录
3. 拒绝条件：受赠方与政府决策者或亲属有关联/捐赠发生在政府合同审批期间/受赠方无合法注册

### 3.5 SOP-05：加速费/疏通费管控

1. 🔴 **FCPA vs UKBA 法域差异明确标注**：
   - FCPA 15 U.S.C. §78dd-1(b)：加速费狭义例外——仅限加快政府例行非自由裁量行政行为（如护照签发/许可证处理/警方保护/信件递送/水电服务开通等）
   - UKBA 2010：无任何例外——任何以获取或保留商业优势为目的的支付均违法
   - 建议策略：FCPA适用企业建议零容忍政策（多数跨国企业已放弃加速费例外），UKBA管辖下强制执行零容忍
2. 加速费识别标准（政府官员主动索要/支付目的仅为加快例行行为/金额不大/非自由裁量行为）
3. 遇索要加速费的应对流程：拒绝支付→记录→上报合规官→评估是否需要自愿披露
4. 记录要求：所有加速费索要事件（无论是否支付）均须完整记录

### 3.6 SOP-06：利益冲突申报

1. 申报类型：年度全面申报+重大事项即时申报（入职/岗位变动/家庭关系变化/外部投资变化）
2. 利益冲突评估标准
3. 处理流程：申报→合规官初步评估→利益冲突程度分级→回避/限制/剥离/附条件批准→跟踪复审
4. 保密要求与申报记录保存

### 3.7 SOP-07：现金支付管控

1. 现金支付定义与范围（纸币/硬币/现金等价物如旅行支票/预付卡）
2. 管控措施：
   - 禁止大额现金支付（建议限额[需结合企业实际情况和当地市场标准确定]）
   - 鼓励银行转账并保留完整银行记录
   - 小额现金支付须有合法商业理由+完整记录+事前审批
3. 高风险国家特殊管控（TI CPI<30国家→现金支付禁令+事后审计）
4. 记录要求与审计

### 3.8 SOP-08：赞助活动审批（full）

1. 赞助活动定义（企业赞助商业会议/行业论坛/文化活动/体育赛事等）
2. 审批流程：申请→实质审查（受赞助方背景/政府官员关联/活动商业目的合理性）→合规官审批→记录
3. 禁止行为：直接向政府官员或决策者提供赞助名额/赞助费用实际被用于个人消费
4. 记录要求：赞助协议+活动参与人员名单+费用明细

### Phase 3 产出

- SOP文件集（3-8套，按generation_scope）
- 每套SOP标注"须结合企业实际情况调整"
- SOP-05（如生成）明确标注FCPA vs UKBA法域差异

### 5.2a 格式合规验证（生成后必检）

**每个文件生成后立即验证**（不等到全部生成完），验证不通过则重新生成该文件：

**DOCX格式验证（每文件逐一执行）**：

| # | 检查项 | 验证方法 | 不通过动作 |
|---|--------|---------|-----------|
| DF-01 | 页面尺寸为A4纵向 | 读取doc.sections[0].page_width/height | 重新设置页面后保存 |
| DF-02 | 页边距为上2.5cm/下2.0cm/左2.8cm/右2.6cm | 读取doc.sections[0].top_margin等 | 重新设置页边距 |
| DF-03 | 正文为宋体12pt | 读取第一个正文段落的runs[0].font | 重新设置字体 |
| DF-04 | 一级标题为黑体18pt加粗居中（小二号） | 读取Heading 1样式 | 重新设置标题样式 |
| DF-05 | 封面存在且含"内部底稿" | 搜索文档前5段落 | 重新生成封面 |
| DF-06 | 页眉含文件标题+版本号 | 读取doc.sections[0].header | 重新设置页眉 |
| DF-07 | 页脚含页码 | 读取doc.sections[0].footer | 重新设置页脚 |
| DF-08 | 合规手册须有TOC（目录） | 检查是否存在目录段落 | 插入TOC（合规手册专用） |
| DF-09 | SOP须有文件头表格 | 检查第一个表格为非空 | 重新生成文件头（SOP专用） |

**XLSX格式验证（每文件逐一执行）**：

| # | 检查项 | 验证方法 | 不通过动作 |
|---|--------|---------|-----------|
| XF-01 | 含2个Sheet（填写区+填写说明） | 读取wb.sheetnames长度≥2 | 重新创建工作表 |
| XF-02 | Sheet 1 首行冻结 | 读取ws.freeze_panes不为None | 重新设置冻结窗格 |
| XF-03 | 表头行为深蓝底色+白字 | 读取A1.fill.start_color.rgb | 重新应用表头样式 |
| XF-04 | 必填字段有浅黄底色 | 扫描所有行检查标记字段的fill | 重新标记必填字段 |
| XF-05 | 签字区存在合并单元格 | 读取ws.merged_cells.ranges不为空 | 重新添加签字区 |
| XF-06 | 角色矩阵有颜色区分（权限层级） | 扫描角色矩阵表检查权限分级行颜色 | 重新应用颜色 |

**重新生成规则**：
- 单项DF/XF检查不通过 → 修复该单项后重新保存（不重新生成整个文件）
- 2项以上不通过 → 重新生成整个文件
- 重新生成后再次验证，最多重试2次。2次后仍不通过 → 标注"[格式存疑]"+继续下一文件
