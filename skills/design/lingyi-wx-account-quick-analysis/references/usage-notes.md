# 信息收集与交付约定

## 待检字段

| 字段 | 必填 | 示例 | 说明 |
|------|------|------|------|
| `account_name`（账号名称） | 是 | 央视新闻、papi酱 | 视频号账号名称（昵称）。**建议从微信视频号里复制准确昵称再发**，避免手打出错。错一个字就可能拆到别的账号或拆不出来 |
| `platform`（平台） | 否 | — | 可不传；本期固定按微信视频号处理。**可引导但不强制、缺省不传**，走后端默认 |

## 收集流程

1. 触发 skill 后先判断必填输入是否齐全。
2. **账号名称准确性提醒**：拿到账号名后先简短复述确认「我将拆解账号【<名称>】的……，对吗？」；名称含错别字、歧义或为简称时主动核对完整昵称；建议用户从微信视频号里复制准确昵称。
3. **有缺失** → 一次性追问缺失项（只问 1 轮）。话术示例：
   > 技能已就绪 ✅ 帮你把一个视频号账号「快拆」出一份报告：账号总览、受众画像、内容矩阵、爆款公式、对标竞品、运营建议，照着抄他的爆款路径。把视频号的**账号名称**（昵称）发我就行，比如「央视新闻」「papi酱」。
   >
   > 拿到账号名后我会先跟你确认账号名准确、再告知扣点成本，**你确认后**才提交，通常几分钟出报告。
4. **给的不是账号名称**（链接 / 视频文件）→ 引导改发账号昵称：本技能是按账号名称定位拆解的，暂时没法学直接吃链接或视频文件，把账号昵称发我即可。
5. **仍不给** → 用默认继续，不阻塞（但账号名为必填，缺失则不发起）。

要点：一次问清，不挤牙膏；不向用户展示技术字段名（如内部枚举值）。

## 调用与重试

- **主路径（异步）**：`POST` 创建（`account_name`）立即拿 `task_id` → `GET` 轮询 → 终态交付。`task_id` 与全量「账号拆解」接口凭证**互不通用**。
- **拆分轮询（WorkBuddy/Web 防会话中断，推荐）**：
  - 创建：`python3 scripts/quick_analysis.py --account-name "央视新闻" --only-create`（退出码 0，拿 task_id + 初始进度）
  - 轮询：`python3 scripts/quick_analysis.py --poll-task <task_id> --account-name "央视新闻" --out ...`（退出码 13 仍运行，再跑一次；退出码 0 交付报告）
  - ⚠️ `--poll-task` 建议带 `--account-name`（与创建时相同），否则报告标题退化为「任务 xxx」。
- **默认报告文件**：未传 `--out` 时，脚本自动写当前目录的 `账号快拆报告-<task_id>.md`。
- **实扣字段**：`data.total_points`（number，仅完成且有扣点时返回；否则为 null）。
- **进度**：脚本 stderr 周期输出，用户中途问「跑到哪了」时读 stderr 最新行转述（status / 当前阶段 / 进度文案 / 已用时 / task_id），不要说「查不了」。
- **失败重试**：本接口**无重试端点**。任务失败（退出码 12）时，用户同意后用原账号名重新 `--only-create` 发起新任务（重新计费）；不要用失败任务的 `task_id` 去 `--poll-task`（已终态，再查无意义）。
- **幂等**：同一次用户意图的重复提交尽量用同一 `--idempotency-key`；用户说「刚才那次再提交」且你持有上次 key 时复用。

## 交互节奏

- **收集**：最多 1 轮追问，之后用默认继续，不让用户反复等待。
- **扣点确认（硬性，跳过不得）**：跑脚本**前**必须告知「本次任务预计扣点约 120 点，实际扣点视任务复杂程度而定、以最终完成任务时的实际点数为准，是否继续？」，用户**明确确认**后才跑脚本。
- **速度差异**：说明本次大约耗时（如「约 1–2 分钟，期间 stderr 会有进度」）。用户问进度时转述 stderr，勿空等不回。
- **交付**：报告 MD 一次性渲染给用户（务必把分隔符之间的 Markdown 真正渲染出来，不能只甩文件路径或贴带 `\n` 的原始文本）。报告由后端预渲染、自带一级标题，助手原样渲染全文即可。
- **成功后**：告知实际扣除点数 + 报告查看方式（已渲染在上方 + 已存为 MD 文件）。
- **失败后**：告知「点数已返还」；本接口无重试端点，询问是否用原账号名重新发起。
- **交付后**：主动询问是否需要后续动作（如「就某个维度再展开」）。

## 免责声明（交付报告时按需附一句）

账号快拆基于服务端远端分析，结果为模拟参考性质的拆解，不承诺精确到每一条数据；重大运营决策建议结合账号实际数据人工复核。
