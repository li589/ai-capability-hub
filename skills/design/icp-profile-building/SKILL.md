# ICP画像构建

## 目标与边界

定位：把已确认的产品应用、成交案例和采购角色结构化为可执行ICP及细分画像。边界：不生成真实客户名单，不使用未经授权的CRM隐私数据，画像需保留验证条件。

## 输入要求

- 用户目标与使用场景
- 产品/品牌/案例等事实资料
- 目标市场、受众、渠道与语言
- 输出格式和必须遵守的企业规则

## 工作流程

1. 确认用户目标、目标市场/受众、输出语言和交付格式。
2. 整理用户提供的产品、品牌、案例和渠道资料，区分事实、推断和缺失项。
3. 按ICP画像构建的方法生成结构化初稿。
4. 检查技术参数、案例、认证、价格、版权和商业承诺是否有依据。
5. 输出可直接修改的结果、待确认项和发布/执行前检查清单。

## 输出要求

- 结构化分析或内容草稿
- 事实依据与假设
- 待企业确认项
- 发布或执行前检查清单

## 固定口径与输出模板

- 分析单位为企业账户，不把单个联系人等同于客户企业。
- 固定维度：地区/行业/规模、应用场景、产品匹配、采购角色、采购触发、主要异议、排除条件、可验证信号。
- 证据分为“已确认事实、样本推断、待验证假设”；样本不足或集中于单一市场时必须标注偏差。
- 输出表：细分画像｜已确认事实｜推断｜待验证条件｜决策链｜触达切入点｜排除条件。

## 实战使用卡

### 可直接复制的任务示例

> 产品为304不锈钢保温杯，目标德国礼品批发商；已确认样本为18家成交客户，其中12家员工50–200人；输出英文ICP表，区分事实、推断和待验证条件。

### 最小任务卡

用户信息不完整时，只补问会阻塞执行的项目；其余内容先按已知事实交付草稿。

- 业务目标
- 已确认的产品/企业事实
- 目标市场、受众与渠道
- 语言、格式和必须保留的条件

### 默认交付顺序

1. 可直接使用或修改的第一版成品
2. 事实/来源与推断分栏
3. 仅保留真正阻塞执行的待确认项
4. 发布、发送或执行前检查清单

### 完成标准

- 结果可被业务人员直接复制、筛选、修改或提交复核，不只给方法论。
- 每个关键结论能追溯到输入、CRM字段、消息原文或明确标注的推断。
- 缺失信息用占位符或缺口清单表达，不因缺一个非关键字段而停止全部工作。
- 涉及发送、发布、投放或CRM写入时，停在明确的确认点。

## 询盘云API接入

- 本Skill不读取或写入实时CRM。若用户提出CRM操作，说明超出本Skill边界并转交已配置的CRM能力；禁止索取任何密钥。

## 禁止事项

- 不编造客户、公司、产品、价格、认证、案例、实时数据或商业承诺。
- 不把推断写成事实；资料不足时明确列出待确认项。
- 不执行本Skill边界外的发送、发布、删除、批量修改或系统写入。
- 涉及CRM写入时，不得跳过字段发现、目标查询、变更预览、明确确认和执行回查。
- 不得把 client_id、client_secret 或 access_token 写入SKILL.md、参考资料、工作簿、对话或日志。
