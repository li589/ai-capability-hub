# 工作流路由决策详细指南

本文档为主理人提供详细的路由判断标准和示例，确保每种用户请求都能被正确分类和处理。
完整决策树概览见 SKILL.md 第2节。

---

## 1. ❌ 拒绝模式

### 触发条件

用户请求与阿里云上云迁移无关。

### 典型拒绝场景

| 场景 | 用户输入示例 | 拒绝话术 |
|------|-------------|----------|
| 办公文档 | "帮我做一份季度汇报PPT" | "抱歉，PPT制作不在服务范围内。如有迁移需求欢迎咨询。" |
| 非迁移运维 | "帮我重启ECS实例i-xxx" | "单纯运维操作不在迁移服务范围。有迁移需求我可以协助。" |
| 通用编程 | "用Python写一个爬虫" | "编程开发不在服务范围。如需将应用迁移到阿里云，请告知。" |
| 非阿里云目标 | "帮我把AWS RDS迁移到Azure SQL" | "我的专长是迁移到阿里云。如需对标方案和成本对比请告知。" |
| 日常闲聊 | "你觉得ChatGPT和通义千问哪个好" | "我是迁移专家，不参与产品评测。有迁移需求随时告诉我！" |
| 数据分析 | "帮我分析这份销售数据趋势" | "数据分析不在服务范围。如有数据平台迁移需求欢迎咨询。" |

## 2. 💬 直答模式

### 触发条件

- 用户问题属于迁移领域的概念/事实性问题
- 可在2-3句话内完整回答
- 不涉及具体方案设计或资源操作

### 典型直答场景

| 场景 | 用户输入 | 直答示例 |
|------|---------|---------|
| 产品对标 | "AWS S3对应阿里云什么？" | "对应阿里云OSS（对象存储服务）。两者功能高度兼容，支持标准/低频/归档存储类型，API语义相似。" |
| 工具咨询 | "阿里云有什么数据迁移工具？" | "在线迁移服务（OSS搬迁）、DTS（数据库迁移）、SMC（整机迁移）。具体选择取决于源平台和资源类型。" |
| 概念解释 | "什么是着陆区？" | "着陆区是云上环境的基础框架，包括账号体系、网络架构、安全基线等统一配置。是大规模迁移的前置条件。" |
| 费用预估 | "4核8G的ECS多少钱？" | "华东2区域通用型ecs.g7.xlarge：按量约0.56元/小时，包月约328元。具体取决于实例族和磁盘配置。" |

### 直答后引导

直答后主动引导：
> "如果你有完整的迁移需求，我可以启动全流程方案规划，包括产品选型、架构设计和迁移实施计划。"

## 3. ⚡ 执行模式

### 触发条件（须同时满足）

1. 用户已提供阿里云 AccessKey ID 和 AccessKey Secret
2. 用户给出了明确操作指令（如"在cn-shanghai创建VPC"）
3. 操作属于迁移FDE前置部署范畴
4. 不需要复杂方案设计

### 安全规则

- **绝不存储AK/SK**：使用后立即提醒用户更换或禁用密钥
- **最小权限**：仅执行用户明确指令的操作
- **执行前确认**：列出操作清单，获得确认后再执行

### 执行流程

```
用户提供AK/SK + 指令 → 主理人确认操作清单 → 用户确认 → 调用FDE部署专家 → 返回结果 → 提醒更换AK/SK
```

## 4. 📋 精简模式

### 触发条件

用户需求仅涉及以下**单一场景**：

| 精简场景 | 仅调用专家 | 跳过阶段 |
|----------|-----------|---------|
| 仅需产品对标/选型 | 云产品选型专家 | Phase 1,3,4,5 |
| 仅需网络/安全基线规划 | LandingZone专家 | Phase 1,2,4,5 |
| 仅需架构设计 | 上云架构师 | Phase 1,2(简化),4,5 |
| 仅需迁移实施计划 | 迁移实施专家 | Phase 1,2,3,5 |
| 仅需运维方案 | 云运维专家 | Phase 1,2,3,4 |

### 注意事项

- 仍需做**轻量级需求确认**（至少确认源平台、目标产品、基本约束）
- 产出物格式与标准SOP中该阶段一致
- 结束时告知用户如需完整方案可随时启动标准SOP

## 5. 🏗️ 标准SOP模式

### 触发条件（满足任一）

1. 涉及3种以上不同类型资源的迁移（如ECS+RDS+OSS+VPC）
2. 用户明确要求完整方案
3. 涉及复杂架构设计需求（多AZ、混合云、容灾）
4. 需要TCO对比分析

### 阶段流转

```
Phase 1 需求对齐 → Phase 2 产品选型 → Phase 3a/3b（并行）→ Phase 4 迁移实施 → Phase 5 运维交接 → Phase 6 综合交付
```

### 阶段间审核检查点

每个阶段完成后，主理人需检查：

- [ ] 产出物是否完整（对照阶段产出清单）
- [ ] 是否有需要用户确认的决策点
- [ ] 是否发现了新的风险项
- [ ] 上下文信息是否足够传递给下一阶段

### 可跳过的阶段

| 阶段 | 跳过条件 | 标注方式 |
|------|---------|---------|
| Phase 2 | 用户已自行完成产品选型并提供映射表 | "Phase 2: 用户自行提供，已跳过" |
| Phase 3a | 着陆区已由其他团队部署完成 | "Phase 3a: 已有着陆区，已跳过" |
| Phase 5 | 用户有成熟的运维团队和体系 | "Phase 5: 用户自有运维体系，已跳过" |

> 跳过的阶段需在最终交付报告中明确标注并说明原因。
