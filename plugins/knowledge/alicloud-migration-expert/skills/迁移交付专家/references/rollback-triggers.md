# 回滚触发条件详细手册

> 本文档为迁移交付专家的补充参考，定义完整的回滚触发条件、严重级别、监控命令和决策流程。

---

## 1. 严重级别定义

| 级别 | 名称 | 响应时间 | 决策人 | 典型场景 |
|------|------|----------|--------|----------|
| P1 | 严重 | 立即 | 技术负责人+项目经理 | 数据不一致、核心服务不可用 |
| P2 | 警告 | 5min内 | 迁移工程师 | 性能下降、非核心异常 |
| P3 | 观察 | 30min内 | 值班工程师 | 指标轻微波动 |

## 2. 技术指标类触发条件

### 2.1 数据同步类

| 编号 | 指标 | 警告阈值(P2) | 严重阈值(P1) | 监控命令/工具 | 观察窗口 |
|------|------|--------------|--------------|---------------|----------|
| T-01 | DTS同步延迟 | >10s | >30s且无收敛趋势 | DTS控制台 / `DescribeMigrationJobs` API | 持续2min |
| T-02 | DTS同步状态 | 状态波动 | 状态变为Error | DTS控制台事件 | 即时 |
| T-03 | 数据行数差异 | 差异<100行（可解释） | 差异>0且无法解释 | `pt-table-checksum` / 自研校验脚本 | 校验周期内 |
| T-04 | Checksum不一致 | - | 任意表checksum不一致 | `pt-table-checksum --replicate` | 即时 |

**DTS延迟监控命令示例：**

```bash
# 查询DTS同步延迟（阿里云CLI）
aliyun dts DescribeMigrationJobStatus \
  --MigrationJobId <job-id> \
  --region cn-hangzhou

# 关注字段：
# - Delay: 同步延迟（秒）
# - Status: Running/Migrating/Error
```

## 3. 业务指标类触发条件

| 编号 | 指标 | 警告阈值(P2) | 严重阈值(P1) | 监控方式 | 观察窗口 |
|------|------|--------------|--------------|----------|----------|
| B-01 | 核心转化率（支付/下单） | 下跌>3% | 下跌>5%持续3min | 业务监控大盘 | 持续3min |
| B-02 | 客服投诉量 | 突增>100% | 突增>200% | 客服系统统计 | 30min窗口 |
| B-03 | 登录成功率 | 下降>2% | 批量报错或超时 | 应用日志监控 | 持续2min |
| B-04 | 结算成功率 | 下降>1% | 批量报错或超时 | 交易监控 | 持续2min |
| B-05 | 订单创建量 | 下降>10% | 下降>30% | 业务监控 | 持续5min |

> **注意**：业务指标阈值需根据客户历史基线定制，以上为通用参考值。建议在割接前1周采集业务指标基线。

## 4. 时间窗口类触发条件（硬规则）

时间窗口类为**硬规则**，触发后无讨论空间，必须执行预定义动作。

| 编号 | 条件 | 强制动作 | 判断依据 |
|------|------|----------|----------|
| W-01 | 割接窗口剩余≤20%，问题未解决 | **强制回滚** | 计划窗口时间 vs 当前时间 |
| W-02 | 单环节超时 > 2×预估时间 | **暂停评估** | 步骤预估时间 vs 实际耗时 |
| W-03 | 凌晨窗口结束（如06:00） | **必须回滚至已知稳态** | 当前时间 |
| W-04 | 割接总耗时超出窗口 | **立即停止，评估回滚** | 累计耗时 vs 计划窗口 |

**时间窗口计算示例：**

```
计划窗口: 02:00 - 06:00 (4小时 = 240分钟)
20%剩余阈值: 240 × 0.2 = 48分钟 → 05:12为强制回滚决策点
单环节超时示例: 数据校验预估10min → 实际超过20min即暂停
```

## 5. 外部依赖类触发条件

| 编号 | 条件 | 影响评估 | 建议动作 |
|------|------|----------|----------|
| E-01 | 上游调用失败 | 评估影响范围（核心/非核心） | 核心→回滚；非核心→降级 |
| E-02 | SSL证书/域名异常 | 全站不可用 | **立即回滚** |
| E-03 | 专线延迟突增 | 数据同步可能中断 | 评估是否影响增量同步 |
| E-04 | 第三方SDK鉴权失败 | 部分功能不可用 | 评估降级方案，必要时回滚 |
| E-05 | CDN节点异常 | 静态资源访问异常 | 切换CDN域名或回滚 |
| E-06 | DNS服务商故障 | 域名解析失败 | 切换DNS服务商或回滚 |

## 6. 回滚决策流程图

```
触发条件命中？
├── P1严重 → 立即通知决策人 → 评估局部回滚可行性
│   ├── 可局部回滚 → 执行局部回滚 → 验证 → 继续/全量回滚
│   └── 需全量回滚 → 执行全量回滚 → 验证 → 复盘
├── P2警告 → 5min内评估
│   ├── 指标自行恢复 → 继续观察
│   └── 持续恶化 → 升级为P1 → 走P1流程
├── P3观察 → 记录日志 → 下次巡检评估
└── 时间窗口硬规则 → 无讨论，直接执行预定义动作
```

## 7. 回滚步骤模板

### 7.1 数据库层回滚

```
1. 停止目标端写入（应用层切只读）
2. 切换连接串回源端（修改应用配置）
3. 确认源端数据完整（行数+checksum快速校验）
4. 灰度流量切回源端（10% → 50% → 100%）
5. 验证核心业务指标恢复正常
6. 记录回滚时间线和原因
```

### 7.2 网络层回滚

```
1. DNS记录切回源端SLB（TTL已预设为60s）
2. 等待DNS生效（dig/nslookup验证）
3. 确认源端SLB健康检查全部通过
4. 监控流量恢复正常
```

### 7.3 应用层回滚

```
1. 停止目标端应用实例
2. 启动源端应用实例（确认配置未变）
3. 连接串/配置回滚到源端
4. 健康检查确认源端服务正常
5. 灰度流量导入源端验证
```
