# HA/DR决策框架（High Availability / Disaster Recovery Framework）

## 文档说明

本文档提供阿里云产品级别的HA/DR决策数据，包含各产品的RPO/RTO实测值、实施模式、成本影响和适用场景。架构设计时应根据业务等级从本文档中选择匹配的HA/DR模式。

---

## 三级模型总览

| 等级 | 业务类型 | SLA目标 | RPO | RTO | 架构模式 | 成本倍数 |
|------|----------|---------|-----|-----|----------|----------|
| L1-核心 | 交易/支付/核心API | ≥99.99% | 0 | <1分钟 | 跨Region两地三中心 | 2.0-2.5x |
| L2-重要 | 用户/商品/内部效率 | ≥99.95% | <15分钟 | <30分钟 | 同城多AZ双活 | 1.3-1.5x |
| L3-一般 | 报表/后台/测试 | ≥99.9% | <1小时 | <4小时 | 单AZ+备份恢复 | 1.0x（基线） |

---

## L1-核心：跨Region容灾详细方案

### 架构组成

```
┌─────────────────────────────────────────────────┐
│                 主Region（如杭州）                  │
│  ┌──────────┐  ┌──────────┐                     │
│  │   AZ-H   │  │   AZ-I   │  ← 双AZ同时提供服务   │
│  │  ECS×N   │  │  ECS×N   │  ← 每AZ至少2个实例    │
│  │  RDS主   │  │  RDS备   │  ← 三节点强同步       │
│  │ Redis主  │  │ Redis备  │  ← 跨AZ主备           │
│  └────┬─────┘  └────┬─────┘                     │
│       └──────┬───────┘                           │
│           ALB/SLB                                 │
└──────────────┬──────────────────────────────────┘
               │ DTS实时同步 / Redis跨Region复制
               │
┌──────────────┴──────────────────────────────────┐
│               灾备Region（如上海）                  │
│  ┌──────────────────────────────┐                │
│  │  热备ECS×N（50%容量）          │  ← 故障时扩容   │
│  │  RDS灾备实例                   │  ← DTS实时同步  │
│  │  Redis灾备实例                  │  ← 异步复制    │
│  └──────────────────────────────┘                │
└─────────────────────────────────────────────────┘
               │
         GTM全局流量管理（DNS级切换）
```

### 产品级RPO/RTO数据

| 产品 | 部署方式 | RPO | RTO | 同步方式 | 延迟影响 |
|------|----------|-----|-----|----------|----------|
| RDS MySQL三节点 | 主Region双AZ+灾备Region | 0（主Region）/<5s（跨Region） | ≤30s（主Region）/≤5min（跨Region） | 强同步+DTS增量 | 跨Region同步延迟1-5秒 |
| PolarDB MySQL | 主Region+跨Region集群 | 0（主Region）/<5s（跨Region） | ≤30s（主Region）/≤3min（跨Region） | 共享存储+物理复制 | 跨Region延迟20-30ms |
| Redis集群版 | 跨Region数据复制 | <5秒 | ≤30s | 异步复制 | 网络延迟+复制延迟 |
| ALB/SLB | 每Region独立部署 | 0 | <1min | 独立，DNS切换 | 无 |
| ECS | 每Region独立部署 | N/A | <10min | ESS在灾备Region扩容 | ESS扩容约5-10分钟 |
| OSS | 跨区域复制 | 分钟级 | ≈0 | 异步复制 | 复制延迟分钟级 |

### 故障切换流程

1. **故障检测**（<30秒）：云监控+ARMS检测到主Region不可用
2. **DNS切换**（<1分钟）：GTM将流量从主Region切换到灾备Region
3. **数据层提升**（<3分钟）：灾备RDS提升为可读写主实例
4. **计算层扩容**（<10分钟）：ESS在灾备Region扩容ECS至满配
5. **服务恢复**（<15分钟）：全量流量由灾备Region承接

### 成本明细（以中型交易系统为例）

| 资源项 | 主Region（月费） | 灾备Region（月费） | 合计 |
|--------|-----------------|-------------------|------|
| ECS（应用） | ¥15,000 | ¥7,500（50%热备） | ¥22,500 |
| RDS三节点 | ¥8,000 | ¥4,000（灾备实例） | ¥12,000 |
| Redis集群 | ¥5,000 | ¥2,500（灾备实例） | ¥7,500 |
| DTS同步 | - | ¥2,000（同步链路） | ¥2,000 |
| GTM | ¥500 | - | ¥500 |
| CEN跨Region带宽 | ¥3,000 | - | ¥3,000 |
| **合计** | | | **≈¥47,500/月** |

## L2-重要：同城多AZ双活详细方案

### 架构组成

```
┌──────────────────────────────────────────┐
│            单Region（如杭州）               │
│  ┌──────────┐    ┌──────────┐            │
│  │   AZ-H   │    │   AZ-I   │            │
│  │  ECS×2+  │    │  ECS×2+  │ ← 双AZ对等  │
│  │  RDS主   │    │  RDS备   │ ← 三节点     │
│  │ Redis主  │    │ Redis备  │ ← 跨AZ主备   │
│  └────┬─────┘    └────┬─────┘            │
│       └───────┬────────┘                  │
│           SLB/ALB                          │
└──────────────────────────────────────────┘
```

### 产品级RPO/RTO数据

| 产品 | 部署方式 | RPO | RTO | 同步方式 |
|------|----------|-----|-----|----------|
| RDS MySQL三节点 | 跨AZ强同步 | 0 | ≤30秒 | 强同步（Paxos） |
| RDS MySQL高可用版 | 跨AZ半同步 | <1秒 | ≤30秒 | 半同步复制 |
| PolarDB MySQL | 跨AZ多副本 | 0 | ≤30秒 | 共享存储三副本 |
| Redis集群版 | 跨AZ主备 | <5分钟 | ≤30秒 | 自动主备切换 |
| SLB/ALB | 跨AZ部署 | 0 | <1分钟 | 健康检查+自动摘除 |
| ESS | 跨AZ伸缩 | N/A | <5分钟 | 自动在新AZ创建实例 |

### 故障切换流程

1. **故障检测**（<10秒）：SLB健康检查检测到AZ内实例异常
2. **流量切换**（<30秒）：SLB自动将流量路由到健康AZ
3. **数据层切换**（<30秒）：RDS自动主备切换，Redis自动切换
4. **计算补充**（<5分钟）：ESS在健康AZ补充实例

### 成本影响

相比单AZ部署，双AZ部署的额外成本主要来自：
- ECS：无额外成本（总实例数不变，分布在两个AZ）
- RDS三节点：比高可用版多约30%费用
- Redis跨AZ：无额外费用（集群版原生支持）
- SLB跨AZ：无额外费用

**总成本增量**：约30-50%（主要来自RDS三节点升级）

## L3-一般：单AZ + 备份恢复详细方案

### 架构组成

```
┌──────────────────────────────────┐
│        单Region（单AZ）            │
│  ┌─────────────────────┐         │
│  │       单AZ           │         │
│  │  ECS×1+  (ESS弹性)   │         │
│  │  RDS高可用版          │         │
│  │  Redis标准版          │         │
│  └──────────┬──────────┘         │
│             │                     │
│         SLB/ALB                   │
│             │                     │
│     ┌───────┴───────┐            │
│     │  备份存储(OSS) │            │
│     │  快照+备份策略  │            │
│     └───────────────┘            │
└──────────────────────────────────┘
```

### 备份策略

| 数据类型 | 备份方式 | 备份频率 | 保留周期 | RPO |
|----------|----------|----------|----------|-----|
| RDS数据库 | 自动全量+binlog | 每日全量 | 7-30天 | <1小时 |
| ECS云盘 | ESSD快照 | 每日 | 7天 | <24小时 |
| OSS数据 | 版本控制+跨区域复制 | 实时 | 按需 | ≈0 |
| 配置文件 | Git版本管理 | 每次变更 | 永久 | ≈0 |

### 故障恢复流程

1. **故障确认**（<30分钟）：运维确认故障范围和预计恢复时间
2. **计算恢复**（<15分钟）：ESS在其他AZ自动创建实例
3. **数据恢复**（<2小时）：RDS从备份克隆恢复
4. **配置恢复**（<30分钟）：从Git拉取最新配置
5. **服务恢复**（<4小时）：全量服务在新AZ恢复

## 跨等级通用建议

### 数据同步策略选择

| 同步方式 | RPO | 适用产品 | 成本 | 适用等级 |
|----------|-----|----------|------|----------|
| 强同步（Paxos） | 0 | RDS三节点 | 高 | L1/L2 |
| 半同步复制 | <1秒 | RDS高可用版 | 中 | L2/L3 |
| 异步复制 | 秒级 | DTS/Redis复制 | 中 | L1灾备/L2 |
| 定时快照 | 小时级 | ESSD快照 | 低 | L3 |
| 跨区域复制 | 分钟级 | OSS/表格存储 | 低 | L1/L2 |

### 监控与告警体系

| 层级 | 监控工具 | 关键指标 | 告警阈值 |
|------|----------|----------|----------|
| 基础设施 | 云监控 | CPU/内存/磁盘/网络 | CPU>80%持续5分钟 |
| 应用层 | ARMS | QPS/延迟/错误率 | P99延迟>2秒 |
| 数据层 | DMS/云监控 | 连接数/QPS/复制延迟 | 复制延迟>10秒 |
| 业务层 | 自定义 | 订单量/成功率 | 成功率<99% |

### 灾备演练计划

| 演练类型 | 频率 | 范围 | 目标 |
|----------|------|------|------|
| 桌面推演 | 每月 | 全团队 | 验证流程完整性 |
| AZ故障模拟 | 每季度 | 单AZ | 验证自动切换能力 |
| Region级容灾切换 | 每半年 | 全Region | 验证跨Region恢复能力 |
| 全链路压测 | 每年 | 全链路 | 验证容量和性能 |

## 决策流程图

```
业务系统 → 确定业务等级
  │
  ├─ L1-核心 → SLA≥99.99%？
  │    ├─ 是 → 跨Region两地三中心（L1方案）
  │    └─ 否 → 降级到L2方案
  │
  ├─ L2-重要 → SLA≥99.95%？
  │    ├─ 是 → 同城多AZ双活（L2方案）
  │    └─ 否 → 降级到L3方案
  │
  └─ L3-一般 → 单AZ+备份恢复（L3方案）
```

每个决策点需要记录一条ADR，说明选择理由、成本影响和遗留风险。
