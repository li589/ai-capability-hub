# 架构决策记录模板（Architecture Decision Record Template）

## 文档说明

本文档提供架构决策记录（ADR）的标准模板和使用示例。每个ADR记录一个关键架构决策的背景、选项分析、最终决策和遗留风险。

---

## ADR模板

```markdown
# ADR-{编号}: {决策标题}

## 状态
{已采纳 | 已废弃 | 已取代（被ADR-XXX取代）}

## 日期
{YYYY-MM-DD}

## 背景
{描述促成这个决策的业务和技术背景}

## 决策
{描述做出的决策}

## 选项分析

### 选项A: {选项名称}
- 优势: {列出优势}
- 劣势: {列出劣势}
- 成本: {成本估算}

### 选项B: {选项名称}
- 优势: {列出优势}
- 劣势: {列出劣势}
- 成本: {成本估算}

## 选择理由
{说明为什么选择当前方案，关键的权衡取舍是什么}

## 后果
### 正面影响
- {正面影响}
### 负面影响与遗留风险
- {风险}: {缓解措施}

## 关联
- 业务等级: {L1/L2/L3}
- 涉及产品: {阿里云产品}
- 成本影响: {月度成本变化}
```

## ADR示例

### ADR-001: 核心交易系统计算形态选择

**状态**: 已采纳 | **日期**: 2024-03-15

**背景**: 核心交易系统当前部署在IDC物理机上（16C64G×8台），日均QPS约5,000，峰值QPS约15,000。上云后需要选择合适的计算形态。

**决策**: 选择 ACK托管版 + ECS节点池 的混合部署方案。

**选项分析**:
- 选项A（纯ECS）：迁移成本低但弹性伸缩慢（分钟级），¥12,000/月
- 选项B（ACK+ECS混合）：容器弹性秒级，资源利用率提升30%，¥10,000/月，需2周改造
- 选项C（函数计算FC）：成本最优但冷启动100ms-1s不可接受，¥8,000/月

**选择理由**: 选项B在弹性和运维效率间取得最佳平衡，容器化改造成本可控。

**遗留风险**: K8s运维复杂度 → 通过ACK托管版降低；容器化回归 → 灰度发布+全链路压测

**关联**: L1-核心 | ACK/ECS/ESS/ALB | 节省¥2,000/月

## ADR编号规范

- 格式：ADR-{三位数字}，按创建时间顺序编号
- 已废弃的ADR保留编号，状态标注为"已废弃"
- 一个ADR对应一个独立决策，不混合多个决策
- 决策做出后立即记录，经架构评审会议讨论后采纳
