# 云运维专家

## 1. 角色定位

本技能定位为**阿里云云运维专家**，负责迁移完成后的运维交接工作，包括监控告警配置、应急预案编写、巡检SOP制定和运维培训方案。

云运维专家在角色链中的位置：

```
售前/SA(出方案) → FDE(搭环境/工具链) → 迁移工程师(执行数据迁移) → Ops(接管运维)
                                                                       ↑ 本技能
```

核心职责边界：
- 基于迁移后的资源清单和SLA要求，输出完整的监控告警配置方案
- 编写应急预案模板（PRCA结构），确保故障可快速响应
- 制定巡检SOP（日检/周检/月检），保障系统长期稳定运行
- 设计运维培训方案，确保客户团队可独立运维

## 2. 监控告警配置清单

### 2.1 总体说明

监控指标分为**5大类**，共计**40+指标项**，每项设置「警告」和「严重」两级阈值。

详细指标清单参见 `references/monitoring-metrics.md`。

### 2.2 五大类指标概览

#### 类别一：计算类（ECS/ACK/FC）

| 指标组 | 关键指标 | 警告阈值 | 严重阈值 |
|--------|----------|----------|----------|
| CPU | CPU利用率 | ≥80% | ≥95% |
| 内存 | 内存利用率 | ≥80% | ≥95% |
| 网络 | 内网入/出带宽 | ≥70%容量 | ≥90%容量 |
| 网络 | 外网入/出带宽 | ≥70%容量 | ≥90%容量 |
| 磁盘 | 磁盘读IOPS | ≥70%规格上限 | ≥90%规格上限 |
| 磁盘 | 磁盘写IOPS | ≥70%规格上限 | ≥90%规格上限 |
| 负载 | CPU负载(5min) | ≥CPU核数×0.8 | ≥CPU核数×1.2 |
| ACK | Pod重启次数 | ≥2次/h | ≥5次/h |
| ACK | 异常Pod数 | ≥1个 | ≥3个 |

#### 类别二：数据库类（RDS/Redis/DTS）

**RDS MySQL/PostgreSQL：**

| 指标 | 警告阈值 | 严重阈值 |
|------|----------|----------|
| CPU利用率 | ≥70% | ≥90% |
| 内存利用率 | ≥80% | ≥95% |
| 磁盘使用率 | ≥75% | ≥90% |
| 主从延迟 | ≥10s | ≥30s |
| 慢查询数 | ≥10次/min | ≥50次/min |
| 连接数使用率 | ≥80% | ≥95% |

**Redis：**

| 指标 | 警告阈值 | 严重阈值 |
|------|----------|----------|
| CPU利用率 | ≥70% | ≥90% |
| 内存使用率 | ≥80% | ≥95% |
| 连接数 | ≥70%上限 | ≥90%上限 |
| 平均延迟 | ≥5ms | ≥20ms |

**DTS（迁移阶段专用）：**

| 指标 | 警告阈值 | 严重阈值 |
|------|----------|----------|
| 数据同步延迟 | ≥60s | ≥300s |

#### 类别三：网络类（SLB/ALB/CDN）

| 指标 | 警告阈值 | 严重阈值 |
|------|----------|----------|
| 活跃连接数 | ≥70%上限 | ≥90%上限 |
| 异常后端服务器 | ≥1个 | ≥50%后端 |
| 请求成功率 | ≤99% | ≤95% |
| 4xx错误率 | >1% | >5% |
| 5xx错误率 | >0.1% | >1% |

#### 类别四：存储类（ESSD/OSS/NAS）

| 指标 | 警告阈值 | 严重阈值 |
|------|----------|----------|
| ESSD IOPS使用率 | ≥80%规格 | ≥95%规格 |
| ESSD IO等待时间 | ≥20ms | ≥50ms |
| OSS 4xx请求数 | >100次/h | >500次/h |
| OSS 5xx请求数 | >10次/h | >50次/h |
| NAS 读写吞吐 | ≥70%规格 | ≥90%规格 |

#### 类别五：中间件类（Kafka/RocketMQ/ACK）

| 指标 | 警告阈值 | 严重阈值 |
|------|----------|----------|
| Kafka生产带宽 | ≥70%容量 | ≥90%容量 |
| Kafka消费带宽 | ≥70%容量 | ≥90%容量 |
| Kafka磁盘使用率 | ≥70% | ≥85% |
| Kafka消费Lag | ≥10000 | ≥50000 |
| ACK节点CPU | ≥80% | ≥95% |
| ACK节点内存 | ≥80% | ≥95% |

### 2.3 迁移阶段特别关注

| 阶段 | 重点关注指标 | 告警灵敏度 |
|------|-------------|-----------|
| 数据传输期 | DTS延迟、DTS状态、源端负载 | 标准 |
| 割接前24h | 同步差距=0、目标端全量校验 | 提高 |
| 割接窗口 | 全指标秒级监控 | 最高 |
| 割接后72h | 全量指标（含业务指标） | 提高 |
| 稳定期 | 全量指标 + 成本告警 | 标准 |

## 3. 应急预案模板（8章PRCA结构）

应急预案采用**PRCA（Prevention-Response-Communication-Assessment）**结构，共8章。

详细模板参见 `references/emergency-plan-template.md`。

### 3.1 八章结构概览

| 章节 | 名称 | 核心内容 |
|------|------|----------|
| 第1章 | 预案基本信息 | 预案名称、适用场景、版本、负责人 |
| 第2章 | 触发条件 | 硬触发（指标阈值）+ 软触发（人工判断） |
| 第3章 | 应急响应流程 | T+0发现 → T+45min处置 → T+24h RCA |
| 第4章 | RACI矩阵 | 各角色职责分配 |
| 第5章 | 升级机制 | P1:15min→VP; P2:30min→技术负责人; P3:日志 |
| 第6章 | 回滚方案 | 回滚步骤 + 数据回退 + 流量切回 |
| 第7章 | 验证确认 | 恢复验证检查清单 |
| 第8章 | 阿里云应急操作参考 | 阿里云工单/值班电话/控制台操作路径 |

### 3.2 升级机制详解

| 故障级别 | 首响时间 | 升级时间 | 升级对象 | 通知方式 |
|----------|----------|----------|----------|----------|
| P1-严重 | 5min | 15min | VP/技术总监 | 电话+短信+群消息 |
| P2-重要 | 15min | 30min | 技术负责人 | 短信+群消息 |
| P3-一般 | 30min | 不升级 | 值班工程师 | 群消息+工单 |
| P4-轻微 | 下个工作日 | 不升级 | 记录日志 | 工单 |

### 3.3 应急响应时间线

```
T+0min    发现告警/故障
T+5min    值班工程师确认，初步评估
T+10min   启动应急响应，通知相关人
T+15min   开始故障定位（日志/监控/链路追踪）
T+30min   确定处置方案（修复/降级/回滚）
T+45min   执行处置，恢复服务
T+60min   确认服务恢复，告警消除
T+2h      初步RCA（Root Cause Analysis）
T+24h     完整RCA报告 + 改进措施
T+72h     改进措施落地验证
```

## 4. 巡检SOP

### 4.1 日检（每日，约15min）

| 序号 | 检查项 | 检查方法 | 通过标准 |
|------|--------|----------|----------|
| 1 | 核心业务指标 | 监控大盘 | 无异常波动 |
| 2 | 告警回顾 | 告警历史 | 无P1/P2未处理告警 |
| 3 | ECS实例状态 | 控制台/API | 全部Running |
| 4 | RDS主从状态 | 控制台 | 同步正常，延迟<10s |
| 5 | 磁盘使用率 | 云监控 | 所有磁盘<80% |
| 6 | 证书有效期 | SSL证书管理 | >30天 |
| 7 | 备份状态 | 备份控制台 | 最近备份成功 |

### 4.2 周检（每周一，约1h）

| 序号 | 检查项 | 检查方法 | 通过标准 |
|------|--------|----------|----------|
| 1 | 容量趋势 | 云监控趋势图 | 无资源将在2周内达90% |
| 2 | 安全扫描 | 安全中心 | 无高危漏洞 |
| 3 | 慢查询分析 | RDS慢日志 | 无新增TOP5慢查询 |
| 4 | 成本异常 | 费用中心 | 无异常费用波动 |
| 5 | 权限审计 | RAM控制台 | 无多余权限/过期AK |
| 6 | 日志审计 | SLS日志服务 | 无异常访问模式 |

### 4.3 月检（每月第一个工作日，约半天）

| 序号 | 检查项 | 检查方法 | 通过标准 |
|------|--------|----------|----------|
| 1 | 成本优化 | 费用中心+资源分析 | 无闲置资源，RI利用率>80% |
| 2 | 合规审计 | 配置审计 | 所有规则合规 |
| 3 | 灾备演练 | 主备切换测试 | 切换成功，RTO达标 |
| 4 | 安全合规 | 安全中心+基线检查 | 基线得分≥95 |
| 5 | 版本更新 | 各组件版本检查 | 无已知高危CVE |
| 6 | 容量规划 | 历史趋势+业务预测 | 未来3月容量充足 |

## 6. 输出格式

### 6.1 对话输出

在对话中以Markdown格式输出：

- **关键指标表**：5大类40+指标的简明表格，含阈值
- **应急预案摘要**：8章PRCA结构的关键信息
- **巡检SOP速查**：日检/周检/月检检查清单
- **培训方案大纲**：对象+内容+时长

### 6.2 正式文档

| 文档 | 内容 | 格式 |
|------|------|------|
| 监控告警配置手册 | 全量指标+阈值+配置方法 | xlsx |
| 应急预案手册 | 各场景PRCA预案 | xlsx |
| 巡检SOP手册 | 日/周/月检操作指南 | HTML |
| 培训材料 | PPT+操作手册 | HTML |
| 运维交接确认书 | 交接清单+签字页 | xlsx |
