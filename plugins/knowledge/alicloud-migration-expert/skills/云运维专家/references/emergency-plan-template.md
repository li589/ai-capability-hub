## 第3章：应急响应流程

### 3.1 T+0 发现阶段

```
1. 告警触发 → 值班工程师收到通知
2. 确认告警真实性（排除误报）
3. 评估影响范围（受影响业务/用户量）
4. 判定故障级别（P1/P2/P3/P4）
5. 在应急群发布故障通报：
   格式：[级别][系统]故障描述 | 影响范围 | 当前状态
```

### 3.2 T+5min 响应阶段

```
1. 值班工程师开始故障定位
2. 检查项：
   - 云监控：各资源指标状态
   - 应用日志：错误日志/异常堆栈
   - 链路追踪(ARMS)：调用链路耗时分析
   - 数据库：慢查询/锁等待/连接数
3. 如需协助，@相关技术专家
```

### 3.3 T+15min 定位阶段

```
1. 确定根因或缩小范围
2. 制定处置方案：
   方案A: 快速修复（配置变更/重启/扩容）
   方案B: 降级处理（限流/熔断/关闭非核心功能）
   方案C: 回滚操作（切回源端/恢复快照）
3. 评估各方案风险与耗时
4. 选择最优方案，通知决策人确认
```

### 3.4 T+30min 处置阶段

```
1. 执行处置方案
2. 逐步验证恢复状态
3. 如处置失败，切换到备选方案
4. 持续在应急群更新进展（每5min一次）
```

### 3.5 T+45min 恢复阶段

```
1. 确认服务完全恢复
2. 验证核心业务功能正常
3. 消除告警
4. 在应急群发布恢复通报：
   格式：[恢复][系统]已恢复 | 故障时长 | 影响范围 | 初步原因
```

### 3.6 T+24h RCA阶段

```
1. 收集完整时间线
2. 执行5 Whys根因分析
3. 制定改进措施（短期+长期）
4. 编写RCA报告
5. 安排RCA评审会议
```

## 第6章：回滚方案

### 6.1 回滚决策标准

- 处置方案A/B在T+30min内未恢复服务 → 启动回滚
- 故障级别为P1且影响核心业务 → 直接启动回滚评估
- 时间窗口硬规则触发 → 强制回滚

### 6.2 回滚步骤

```
步骤1: [具体操作，例：停止目标端应用写入]
步骤2: [具体操作，例：切换数据库连接串至源端]
步骤3: [具体操作，例：DNS解析切回源端SLB]
步骤4: [具体操作，例：灰度验证源端服务正常]
步骤5: [具体操作，例：全量流量切回源端]
步骤6: [具体操作，例：确认业务指标恢复正常]
```

### 6.3 回滚验证清单

- [ ] 源端服务健康检查通过
- [ ] 核心业务功能验证通过
- [ ] 数据一致性确认
- [ ] 监控指标恢复正常
- [ ] 告警消除
