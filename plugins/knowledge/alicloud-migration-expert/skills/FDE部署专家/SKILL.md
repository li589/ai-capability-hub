# FDE部署专家（FDE Pre-deployment）

## 1. 角色定位

本技能定位为**FDE（Field Deployment Engineer，现场部署工程师）**，负责迁移前的环境搭建、工具链准备和连通性验证，让后续迁移角色有可用的环境。

FDE在角色链中的位置：

```
售前/SA(出方案) → FDE(搭环境/工具链) → 迁移工程师(执行数据迁移) → Ops(接管运维)
                    ↑ 本技能
```

### 1.1 FDE的核心使命

- **让迁移能开始**：没有FDE搭建的环境和工具链，迁移工程师无法执行数据迁移
- **让后续角色有环境可用**：FDE的交付物是"可用的迁移基础设施"
- **降低迁移执行风险**：通过充分的连通性验证和环境自检，提前发现问题

### 1.2 FDE vs 迁移工程师 vs Ops 职责边界

| 工作项 | FDE做 | 迁移工程师做 | Ops做 |
|--------|-------|-------------|-------|
| 搭建迁移集群 | ✅ | - | - |
| 配置源端访问凭据 | ✅ | - | - |
| DTS/SMC任务初始化 | ✅ | 执行迁移 | - |
| 临时网络通道搭建 | ✅ | - | - |
| 连通性验证 | ✅ | - | - |
| 数据迁移执行 | - | ✅ | - |
| 割接执行 | - | ✅ | 配合值守 |
| 变更流程与审批 | - | - | ✅ |
| 监控大盘与告警升级 | 基础告警初始化 | - | ✅ |
| 数据库定期巡检 | - | - | ✅ |
| 故障响应On-Call | - | - | ✅ |
| 容量规划 | - | - | ✅ |
| 安全合规审计 | - | - | ✅ |

**交接点说明：**
- FDE → 迁移工程师：割接前完成环境移交，输出「FDE前置部署完成报告」
- 迁移工程师 → Ops：割接后由Ops接管，FDE/Ops双方在割接阶段配合值守

## 2. FDE前置部署组件清单

### 2.1 网络互通

**目标**：建立源端与阿里云目标端之间的稳定网络通道。

| 组件 | 配置项 | 验收标准 |
|------|--------|----------|
| 专线连接 | 物理专线/CEN云企业网 | 延迟<5ms，丢包率=0，带宽达标 |
| VPN通道 | IPSec VPN | 延迟<20ms，丢包率<0.1% |
| 安全组 | 迁移端口放通 | 迁移所需端口全部放通 |
| 防火墙 | 白名单配置 | 源端IP加入目标端白名单 |
| 路由表 | 跨VPC/跨地域路由 | 路由可达，无黑洞 |

**网络方案选择决策树：**

```
源端与阿里云是否在同一机房？
├── 是 → 物理专线（最优）
│   └── 带宽需求>1Gbps？
│       ├── 是 → 多条专线冗余
│       └── 否 → 单条专线 + VPN备份
└── 否 → 评估网络条件
    ├── 有MPLS/MPLS-VPN → CEN云企业网接入
    ├── 公网可达 → IPSec VPN
    └── 仅内网 → 通过跳板机 + VPN
```

**迁移必需端口清单：**

| 端口 | 用途 | 协议 |
|------|------|------|
| 22 | SSH（Linux ECS迁移） | TCP |
| 3389 | RDP（Windows ECS迁移） | TCP |
| 3306 | MySQL迁移(DTS) | TCP |
| 5432 | PostgreSQL迁移(DTS) | TCP |
| 6379 | Redis迁移(DTS) | TCP |
| 27017 | MongoDB迁移(DTS) | TCP |
| 9092 | Kafka迁移 | TCP |
| 873 | rsync数据传输 | TCP |
| 443 | 阿里云API/控制台 | TCP |

### 2.2 目标端基础资源

**目标**：在阿里云预创建所有目标资源实例。

| 资源类型 | 配置项 | 验收标准 |
|----------|--------|----------|
| VPC/子网 | 网段规划（与源端不冲突） | 网段无重叠，路由可达 |
| ECS实例 | 规格/系统盘/数据盘/镜像 | 实例Running，可SSH登录 |
| RDS实例 | 引擎版本/规格/存储/参数组 | 实例Running，可连接 |
| Redis实例 | 版本/规格/架构(标准/集群) | 实例Running，可连接 |
| MongoDB实例 | 版本/规格/副本集配置 | 实例Running，可连接 |
| OSS Bucket | 地域/存储类型/加密 | Bucket创建成功，可读写 |
| NAS文件系统 | 协议类型/存储类型 | 文件系统可用，可挂载 |
| SLB/ALB | 规格/监听/健康检查 | 实例Running，监听配置完成 |

**资源预创建顺序：**

```
1. VPC/交换机/路由表（网络底座）
2. 安全组（安全策略）
3. ECS/RDS/Redis/MongoDB（计算+数据库）
4. OSS/NAS（存储）
5. SLB/ALB（负载均衡）
6. 中间件实例（Kafka/RocketMQ/ES等）
```

### 2.3 迁移工具链

**目标**：搭建并验证所有迁移工具，确保迁移可以启动。

| 工具 | 用途 | 配置验收 |
|------|------|----------|
| SMC(服务器迁移中心) | ECS整机迁移 | Agent安装成功，任务可创建 |
| DTS(数据传输服务) | 数据库迁移/同步 | 连通性预检通过，任务可创建 |
| ossimport/ossutil | OSS数据迁移 | 工具安装成功，可读写Bucket |
| rsync | 文件/NAS同步 | 工具安装成功，源端可达 |
| DataWorks | 大数据迁移 | 工作空间就绪，数据源注册 |

**DTS连通性预检清单：**

```
1. 源端数据库白名单是否放通DTS服务器IP段
2. 源端数据库账号权限是否满足（读+REPLICATION权限）
3. 目标端数据库白名单是否放通DTS服务器IP段
4. 源端到DTS服务器的网络连通性（telnet 源端IP 端口）
5. DTS到目标端的网络连通性（telnet 目标端IP 端口）
6. 源端数据库binlog是否开启（MySQL要求ROW格式）
7. 源端数据库server_id是否唯一（不与目标端冲突）
```

### 2.4 账号与权限

**目标**：配置迁移所需的RAM账号和访问凭据。

| 配置项 | 说明 | 安全要求 |
|--------|------|----------|
| RAM子账号 | 迁移专用子账号 | 最小权限原则 |
| RAM策略 | DTS/SMC/OSS/RDS等权限 | 仅授权迁移相关API |
| 源端凭据 | 源端数据库/服务器访问凭据 | **不留存，仅在DTS/SMC中配置** |
| AK/SK | 阿里云API调用 | 使用RAM子账号AK，非主账号 |

**安全红线：**
- ❌ 不在任何文档/脚本中明文记录源端密码
- ❌ 不使用主账号AK/SK
- ❌ 不将凭据发送到非安全通道
- ✅ 源端凭据仅在DTS/SMC控制台配置
- ✅ 迁移完成后轮换/删除临时凭据
- ✅ 所有操作记录到操作审计(ActionTrail)

### 2.5 监控基线

**目标**：初始化迁移阶段的基础告警策略。

| 告警项 | 配置说明 |
|--------|----------|
| ECS CPU/内存 | 基础阈值告警（80%/95%） |
| DTS同步延迟 | 延迟>60s告警 |
| DTS任务状态 | 状态变更告警 |
| 网络连通性 | 专线/VPN状态告警 |
| 磁盘使用率 | 使用率>85%告警 |

> 注：FDE仅配置迁移阶段基础告警。完整的运维监控体系由Ops技能在运维交接阶段配置。

### 2.6 文档输出

FDE完成后需输出以下文档：

| 文档 | 内容 | 接收方 |
|------|------|--------|
| FDE前置部署完成报告 | 所有组件状态汇总 | 迁移工程师 + 项目经理 |
| 环境自检清单 | 各项检查结果（通过/不通过） | 迁移工程师 |
| 网络连通测试结果 | 各通道延迟/丢包/带宽测试 | 迁移工程师 |
| 移交checklist | FDE→迁移工程师的交接清单 | 迁移工程师 |
| 资源清单 | 目标端所有资源ID/IP/规格 | 迁移工程师 + Ops |

## 3. 环境自检清单

FDE完成部署后，需逐项执行环境自检。详细自检清单参见 `references/environment-checklist.md`。

### 3.1 自检分类概览

| 类别 | 检查项数 | 关键检查项 |
|------|----------|------------|
| 网络连通性 | 8项 | 专线/VPN延迟、端口可达、DNS解析 |
| 安全组规则 | 5项 | 迁移端口放通、白名单配置 |
| 存储权限 | 4项 | OSS读写、NAS挂载、ESSD挂载 |
| 迁移工具 | 6项 | SMC/DTS/ossimport版本与状态 |
| 凭据有效性 | 4项 | RAM权限、源端连接、AK有效性 |
| 资源状态 | 6项 | 实例状态、规格确认、版本匹配 |

### 3.2 自检流程

```
1. 执行自动化检查脚本（如有）
2. 手动执行网络连通性测试
3. 验证各迁移工具状态
4. 测试DTS/SMC任务创建（dry-run）
5. 记录所有检查结果
6. 不通过项立即修复
7. 全部通过后输出自检报告
```

## 5. 实操建议

### 5.1 部署顺序

1. **先网络后资源**：VPC/子网/安全组必须先于所有计算和存储资源
2. **先基础后应用**：ECS/RDS等基础资源先于中间件
3. **先配置后验证**：所有资源创建完成后统一做连通性验证
4. **先测试后移交**：DTS/SMC做dry-run测试通过后再移交

### 5.2 常见问题预防

| 常见问题 | 预防措施 |
|----------|----------|
| 网段冲突 | 提前获取源端网段，目标端使用不同网段 |
| 安全组遗漏 | 使用安全组规则模板，覆盖所有迁移端口 |
| DTS连通性失败 | 先手动telnet验证，再创建DTS任务 |
| 权限不足 | 使用RAM策略模拟器(Policy Simulator)预检 |
| 跨地域延迟高 | 提前做带宽测试，必要时升级专线带宽 |
| 镜像不兼容 | 提前测试自定义镜像在目标端的启动情况 |
