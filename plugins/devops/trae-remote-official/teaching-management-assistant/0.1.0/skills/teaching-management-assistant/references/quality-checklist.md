# 质量自检清单

交付前逐项核对。

## 1. 数据质量

- [ ] 输入文件可追溯（记录了来源）
- [ ] 字段映射有记录，关键歧义已确认
- [ ] 特殊状态（缺考/免考/作弊）与分数分离，未当 0 分
- [ ] 汇总行/表头噪声已剔除
- [ ] 多表关联覆盖率已检查并可见
- [ ] 原始文件未被修改

## 2. 计算质量

- [ ] 批量指标由落盘代码/脚本计算，非心算
- [ ] 关键指标可重新计算复现
- [ ] 分层各档人数之和 = 总有效人数
- [ ] 各比率（优秀/及格/低分）口径一致、分母明确
- [ ] 逐题得分之和与整卷总分一致（试卷分析）
- [ ] 图表数据与结果表一致
- [ ] 无 NaN / Infinity / 公式错误(`#REF!`/`#DIV/0!`/`#VALUE!`) / 空图表

## 3. 方法与结论质量

- [ ] 每个分析说明了方法与适用条件
- [ ] 差异/关联报告了效应量或不确定性，不只给 p 值
- [ ] 数据事实与推断可区分；解释性假设/建议已给出（鼓励），报告级统一标注"供参考"即可，不必逐句加"待验证"
- [ ] 不把相关性断言为因果；未做能力边界外的内容生成/决策
- [ ] 建议与发现对应、具体可落地
- [ ] 小样本/数据不足已提示局限
- [ ] 内容完整多视角：重点关注名单列全（预警/临界/偏科/拔尖带原因）、有性别/偏科/分数段等下钻；全体明细仅在内部使用、人数较少且用户明确要求时附
- [ ] 试卷分析指标深度与分析目的匹配（有逐题数据时）：日常够用难度 P+高低分组 D+缺陷题；命题复盘才展开 r_pb/分半/偏度峰度/多指标下钻——按需，不为专业感堆砌
- [ ] 场景要点严格按 query 触发：query 未提家长会/教研会/汇报等场景，报告里就没有对应发言/汇报要点（不默认套用、不沿用历史偏好）

## 4. 隐私与合规

- [ ] 非必要不展示学生身份信息，个体结果优先用学号/脱敏标识
- [ ] 无"差生"等标签化措辞
- [ ] 面向个体输出不非必要暴露横向排名
- [ ] 遵循平台数据处理与留存规则

## 5. 文件与交付

- [ ] 结果写入独立输出目录
- [ ] 长报告（>5 节）便于阅读：分节用规范 h2/h3、有顶部目录锚点；涉及专业指标的报告末尾有"方法与判别标准"附录（含通俗解释）
- [ ] 分层/帮扶/名单类任务：HTML 已列全重点名单及原因；只有用户明确要求可筛选/下发时才附多 sheet Excel
- [ ] HTML 末尾没有 Sources 区块，正文没有 `[1]` 等编号引用标记
- [ ] 最终交付的是完整报告目录（主 HTML + `_shared/` + `assets/`），没有只交付依赖缺失的单个 HTML
- [ ] 帮扶/冲刺类建议带了"动态进出（活水）"机制，而非一份静态死名单
- [ ] 给出处理摘要 + 文件路径（如有影响结论的重要局限，就地一句话提示，不单列长章节）
- [ ] 报告末尾标注"AI 辅助分析，请结合教学实际判断"
