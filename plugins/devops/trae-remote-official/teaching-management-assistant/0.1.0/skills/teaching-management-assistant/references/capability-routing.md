# 能力路由

按现有数据条件自动启用能力，可组合。用户无需选择"模式"。

## 两层能力

### P0 成绩分析（基于成绩总分表，最常见）

只要有"学生 + 分数"就能做：

- 成绩单清洗与口径统一
- 均分、中位数、分数分布
- 优秀率、及格率、低分率
- 学生与群体分层
- 班级、专业、年级、科目对比
- 异常学生与异常群体识别（单次横向）
- 教学问题诊断与改进建议
- 可视化报告

### P1 试卷和课程分析（需额外数据）

| 能力 | 触发数据 |
|------|---------|
| 试卷难度、区分度 | 逐题得分 |
| 题目得分率 | 逐题得分 |
| 整卷信度 | 逐题得分 |
| 错题识别与错因分析 | 试卷图片/作答 或 逐题得分 |
| 知识点掌握 | 题目-知识点映射 |
| 多次考试趋势与纵向异常 | 多次考试数据 |
| 课程目标达成 | 课程目标-考核项映射 + 权重 |

## 路由判断顺序

1. 先看用户**目标**：分析单班 / 对比多班 / 看试卷 / 查需关注学生 / 出报告
2. 再看**数据条件**：有没有逐题、有没有多次、有没有映射
3. 目标 × 数据 → 启用能力集合
4. 数据不足以支持用户目标时，先做能覆盖的部分，并说明缺什么

## 混合任务处理

一次请求常包含多条路径，例如"分析这次月考各班情况，顺便看看试卷难不难"：

- 并行启用：群体对比（P0）+ 试卷分析（P1）
- 分节输出，不混为一谈
- 各路径的样本范围和方法独立说明

## 常见误判提醒

- "多个班在同一张表" → 是分组对比，不是多文件合并
- "总分列已给" 但仍有逐题列 → 同时支持 P0 和 P1
- "只给了一列分数没给学号" → 仍可做分布/分层，但无法定位到个人
- 用户要"回填模板/写公式" → 属通用文件操作，正常执行，不要拒绝
