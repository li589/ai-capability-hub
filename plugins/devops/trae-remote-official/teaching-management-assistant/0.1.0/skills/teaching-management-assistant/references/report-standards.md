# 报告与输出规范

## 主交付物：HTML 报告（html-report 渲染）

**默认且首选的交付物是一份 HTML 报告**：叙事结论、关键指标、图表、明细表全部汇总进一份报告。**渲染委托平台 `html-report` skill**（它有成熟的设计系统、ECharts 图表规范、分层配色、响应式与移动适配），本 skill 负责提供内容（数据结论、图表数据、章节结构、教学语言）。

硬性要求：

- **委托 html-report 渲染**：调用 `html-report` skill 生成报告（`<name>.html` + `_shared/js/` + `assets/charts.js`）；不要自己手写整套 HTML/CSS，复用其专业设计系统。
- **报告目录即为最终交付物**：主 HTML 依赖同目录的 `_shared/` 和 `assets/`，整目录可离线打开；不要把主 HTML 描述为单文件。
- **不生成 Sources**：调用 html-report 时明确要求最终 HTML 不包含底部 Sources 区块和编号引用标记。
- **信息完整**：报告本身即完整交付，不需要再配 Markdown。

生成方式：

```bash
# 委托 html-report skill 渲染报告（内容由本 skill 提供）
```

> `scripts/chart_render.py` 为轻量后备（无法调用 html-report、或只要单图/极简报告时用），不是默认路径。
> Markdown 仅在用户明确只要文字、或需要可复制文本片段时作为附带产物；不作为主交付物。

## 报告结构参考（按场景灵活组织，非强制）

下面是一个**常见结构参考，不是必守模板**。报告结构应**按实际场景灵活组织**——家长会、教研会、命题质量分析、个体学情报告等场景的合理结构差异很大，模型应据用户目标、数据形态和受众自行裁剪、增删、重排章节，怎么讲清楚怎么来。以下仅供起手参考：

```
一、核心结论（2-3 条关键发现）
二、数据范围与质量（人数、清洗动作、缺考/异常处理、评分阈值/权重）
三、关键指标（均分/及格率/低分率等 KPI）
四、成绩/试卷/课程分析（分布、分层、群体对比含显著性与效应量、难度区分度/知识点/课程目标）
五、多视角下钻（性别对比、偏科识别、分数段分布等，有数据且与目标相关时做）
六、需关注对象与问题（重点关注名单：预警/临界/偏科/拔尖，带原因+维度、教学问题诊断）
七、改进建议（可操作建议；**仅当 query 涉及家长会/教研会/汇报等场景时**才补对应发言/汇报要点，否则不加）
```

> 章节顺序、命名、取舍都可调；不必凑齐八节，也可新增更贴合场景的章节。**核心结论放最前面**、**关键发现不遗漏**、**重点关注名单和多视角别省**这三条是目的，章节形式是手段。
> **报告分节要用规范标题层级（h2/h3），不要用无语义的 div 平铺堆叠**——章节结构要在 DOM 上清晰可辨。
> **报告 >5 节时，在顶部加"报告目录"**：列出各章节名 + 可点击锚点（`<a href="#节id">`），方便教师快速定位。长报告（试卷质量、学期复盘、年级对比等）尤其受益；短报告不必强加。
> **不铺全体学生的完整排名流水表**（完整成绩老师本就有）；报告只给决策所需的聚合与重点名单。完整排名仅在内部使用、人数较少且用户明确要求时附。

> **正文不插长篇"方法/假设/局限"打断阅读**。分析方法和统计口径就近写在对应结论旁（一句话即可，如"两班差异经 t 检验显著 p<0.05, d=0.6"）。仅当存在**影响结论可信度的重要局限**（如小样本、缺考比例高、口径不明、单次考试推断趋势）时，才用一句话或小 callout 就地提示。
> **但允许（且推荐）在报告末尾放一个"分析方法与判别标准"附录节**——尤其试卷/命题质量、课程目标达成等涉及专业指标的报告。附录集中列出用到的指标口径与判别阈值（难度理想区间、区分度分级、信度标准、显著性口径等），供教师复核。正文先呈现结论，方法细则收进末尾附录。附录用规范标题、纳入顶部目录锚点。

### 内容完整度要求（重要，不要偏保守）

报告要**信息充分、多视角**，宁全勿缺。除非用户明确只要快速摘要：

- **重点关注名单要给全，但不抄全体明细**：需关注/预警/临界/偏科/拔尖等**决策对象名单，列出全部符合条件的学生**（不截断、带原因），这才是报告价值所在。但**不要在报告里铺全体学生的完整排名明细表**——完整成绩老师手里本就有，报告再抄一遍 N 行是冗余、撑大体积、还增加转发泄露面。仅当教师内部使用、单班人数较少（约 ≤50 人）且用户明确要求时，才附完整排名；外部传播报告不附身份明细。
- **多视角下钻**：只要数据支持，就从多个角度切入——性别对比、偏科识别（到具体学生）、分数段分布、各科强弱、群体分层，不要只算一遍均分就收尾。
- **需关注对象带"原因"**：每个需关注学生标注为何被列入（几科不及格 / 偏科 / 临界 / 大幅退步）。
- **分层/帮扶/名单类任务：HTML 默认给完整重点名单；用户明确要求可筛选或下发时，再附分组 Excel**：
  - 一个「总表」sheet + 每个层级/组别各一个 sheet（如①一本冲刺/②本科冲刺/③单科挖潜/④全科补弱）
  - 列尽量给全、可直接筛选执行：学号、姓名、班级、各科分、总分、距线分数、帮扶类型（单科突破/均衡薄弱）、主攻科目、该科得分、提分潜力、预测提分后总分、一句话帮扶建议
  - 生成 Excel 时，HTML 可放聚合视图、重点名单概览和决策结论，并注明"完整可筛选名单见 xxx.xlsx"
- **帮扶/冲刺类建议默认给"动态进出（活水）机制"**：名单不是一次性静态的。补一句可操作机制——如"每周/双周小测后更新临界名单，连续两次过线转'巩固'、名额让给下一拨临界生，保持帮扶名单的动态活水"。让建议贴合冲刺阶段实战，而非只给一份定死的名单。
- **场景化要点（严格条件触发，不要默认加）**：**仅当用户 query 明确提到"家长会/教研会/汇报/发言"等特定场景时**，才补对应的发言/汇报要点。**query 未提场景就不要加**——不要给每份报告都套一个"家长会发言要点"当收尾。例如"帮我做临界生分层帮扶"是教师内部规划，就不该出现家长会内容。判断依据是 query 原文，不是揣测、不是沿用历史偏好。
- **敢给推断和建议**：见 `diagnostic-guidelines.md`，鼓励解释性假设和可落地建议（学习方法、假期安排、教学重点），报告级统一标注"供参考"即可。（面向家长的建议同样仅在 query 涉及家长场景时给。）

按用户目标裁剪：快速需求可只给"核心结论 + 关键指标 + 1 张图"；但**默认（教学复盘/质量分析）应输出多视角、决策导向的报告**（聚合 + 重点名单，而非全体流水明细）。最终交付为可离线打开的 HTML 报告目录。

## 语言规范（分角色）

| 面向 | 风格 | 示例 |
|------|------|------|
| 教研/管理 | 专业、精炼、数据支撑 | "A班均分较B班高5.2分(p<0.05, d=0.43)，差异具统计学意义" |
| 任课教师 | 直观、建议导向 | "A班整体好于B班，差距主要在函数应用题，建议B班加强该模块" |
| 面向个体/家长 | 通俗、正面 | "本次数学进步3分，函数掌握良好，立体几何可加强" |

统一用教学语言而非统计术语面向一线教师；关键统计概念附一句解释。

## 可视化规范

图表选型：

- 分布 → 直方图、箱线图
- 群体对比 → 柱状图、箱线图、点图
- 趋势 → 折线图
- 题目分析 → 难度-区分度散点图、题目得分率条形图
- 课程目标 → 达成度条形图或矩阵
- 多维画像 → 谨慎用雷达图，不用它替代精确比较

**可视化按内容需要，不凑数也不偏少**：有几个值得可视化的角度就画几张（各科对比、分布/分层、多视角下钻如性别/分数段/箱线）；有多个角度却只放一张是偏少，硬凑无信息量的图是浪费。图表须与文字结论一致、直接标注关键值。

工具型审美（沿用 P0 插件规范）：

- 高数据密度、低视觉干扰；不用装饰性渐变/发光/大阴影/入场动画/emoji
- ECharts 默认配色，语义色仅用于告警（预警/未达标）；分层/强弱可用配色或行高亮增强可读性
- 图表直接标注关键值
- 看板：来源可追溯、支持按班级/科目筛选、可看明细

## 文件输出规范

| 格式 | 规范 |
|------|------|
| HTML（主交付） | html-report 渲染目录（主 HTML + `_shared/` + `assets/`），整目录离线可开 |
| Excel 分组名单（分层/帮扶/名单类任务的配套交付） | openpyxl，`index=False`；「总表」+ 各层级/组别分 sheet，列给全可筛选（学号/姓名/班级/各科分/总分/距线/帮扶类型/主攻科目/提分潜力/预测总分/建议）|
| CSV | `utf-8-sig`，`index=False` |
| Excel | openpyxl 引擎，`index=False` |
| JSON | `ensure_ascii=False`，`indent=2` |

- HTML 报告默认走 html-report 渲染，不生成底部 Sources；报告目录即最终交付物（后备可用 `chart_render.py --report`）
- 输出写入独立目录，不覆盖原始文件
- 命名清晰（如 `教学质量分析报告.html`、`成绩标准化.xlsx`）
- 每次给出处理摘要：做了什么、影响多少行、输出路径
