# 复杂任务完整性

适用于公共科研数据库、论文结果复现、多模态或多阶段分析、预测/解码，以及同时生成多类产物的任务。目标是让分析范围、定义和数据关系清楚，不设置验收门或完成门禁。

## 1. 明确范围与数据适配性

- 说明研究问题、数据模态、分析单位、时间点、结局、特征粒度和实际可完成范围。
- 数据只覆盖部分对象时，仅分析被数据支持的部分，不用无关代理数据补齐范围。
- 多数据集只有在人群、时间、结局和特征定义可比时才合并；无法个体级连接的数据用于跨队列比较或互证。

## 2. 锁定复现口径

论文或既定流程复现时记录：

```yaml
reference_version:
feature_identity_and_granularity:
sample_and_analysis_unit:
filter_order:
strand_and_orientation:
numerator:
denominator:
normalization_unit:
zero_and_tie_handling:
aggregation_rule:
contrast_and_threshold:
reported_benchmark:
```

- 参考版本、过滤顺序、链方向、分母和特征粒度变化时，说明与原流程的差异。
- 用户要求序列、转录本或异构体粒度时，以该粒度作为主结果；需要与基因级文献结果比较时另行汇总。
- 文献样本数、目标集合或性能只作为外部参照，不作为调参目标。

## 3. 防止层级泄漏

- 先声明独立分析单位；患者、动物、中心、session、probe insertion 或批次是独立单位时，下层记录不得跨训练和验证边界。
- 同一患者、动物或 session 的相关记录进入同一数据划分。
- 缺失处理、标准化、残差化、特征选择、降维、阈值选择和调参在训练数据中学习，再应用于验证数据。
- 内部交叉验证与独立外部验证分开表述。

## 4. 稳健性与结果解释

- 依据研究问题选择患者/动物/批次级重采样、负对照、标签置换、敏感性规格、多重校正、校准或外部验证。
- 数值、集合和性能差异作为分析结果解释，不转化为交付门禁。
- 区分 `直接观测`、`计算推断`、`外部证据` 和 `机制假设`；探索性信号不写成已验证机制或个体医疗结论。

## 5. 复现记录与交付

按任务需要保留输入来源和版本、代码或计算记录、参数、参考资源、分析 ID 和输出路径。主报告陈述实际分析范围、主要发现和局限，不嵌入内部台账或产物清单。

按用户要求直接生成产物。产物及其本地资源写出后不再读取、解析、检查、验证、lint、渲染、运行、截图或预览。
