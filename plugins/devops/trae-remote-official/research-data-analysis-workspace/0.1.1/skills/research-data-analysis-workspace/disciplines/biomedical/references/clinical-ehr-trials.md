# 临床、EHR 与试验数据

## 数据层级与时间

先建立受试者、就诊、医嘱、给药、检验、诊断、结局、标本和中心之间的关系。不得把事件表行数当作患者数。

- 主键和连接基数必须显式检查；多对多连接先说明预期膨胀；
- 区分记录时间、采集时间、发生时间、入库时间与修订时间；
- 统一单位、参考范围、时区和编码版本，保留原值；
- 确认 index time 前后信息边界，避免把未来信息用于基线或预测；
- 重复值需按临床语义定义聚合，不默认取最近值或均值。

字段名只能支持候选解释。没有方案、数据字典或用户说明时，不自动定义 `index_date`、暴露策略、随访起点、洗脱期或纳排规则；先完成不依赖这些定义的盘点，将设计选项保留为待确认项。

医院队列质控不得因以下信息缺失而停在中间：`index_date` 的业务定义、既往结局是否允许、随访截止日期、暴露缺失来源、ICD 体系/版本、主键冲突的源系统优先级。分别按下列保守口径完成本轮交付：

- 只描述记录中的 `index_date` 及其与其他日期的关系，不擅自赋予入组、治疗或随访起点语义；
- 既往结局只标记时间逻辑关系，不自动删除、置空或改成删失；没有随访截止时，不把无事件记录认定为完整随访；
- 暴露缺失保留为未知，ICD 只给不覆盖原值的候选列；
- 主键冲突无优先级时保留冲突组，必要时补充整组排除的条件性计数，不选择首行/末行；
- 最终报告直接回答队列在数据质控层面是否可用、哪些分析当前可做、哪些结论受限。上述信息只作为提高确定性的后续补充，不得写成继续分析或交付文件的前置确认。

## 编码与表型映射

- 对 ICD、药品、检验、手术或不良事件编码，先记录 `coding_system`、版本、地区/扩展、来源字典和映射日期。
- 仅大小写、首尾空格或已由来源规范明确证明的标点差异可作为确定性格式统一。可能改变临床含义或粒度的折叠、截断、跨版本/跨体系映射，必须有版本化字典或用户提供的映射表支持。
- 来源或版本未知时，保留原编码；可另给 `candidate_code_normalized`、`mapping_status=unverified` 和候选依据，但不得把候选值当成已验证编码用于主队列纳入、分组或聚合。把不确定性写进报告不能替代证据门槛。
- 未实际核验官方字典时，不在主报告断言某形式属于 WHO、ICD-10-CM 或本地扩展；标注 `unverified` 不能抵消未经核验的事实陈述。
- 编码频数表从原始数据自动生成，覆盖每个已观察类别及缺失；非零类别不得显示为“—”。没有编码体系与版本证据时，不使用“标准/非标准编码”措辞。

## EHR/真实世界数据审查

- 诊断码不自动等于确诊；说明表型算法、证据窗口和验证状态；
- “未记录”不自动等于“未发生”；评估医疗利用、失访和跨机构缺失；
- 暴露缺失不等于未暴露或 `none`；`Unknown` 只能作为缺失标记，不能未经假设和敏感性设计直接成为分析暴露水平；
- 药品处方、发药、给药和依从性是不同事件；
- 检验缺失可能由病情和医嘱共同驱动，不能视为随机空白；
- 医疗流程变化、系统迁移、科室/中心差异可能形成批次或时间偏倚；
- 同一患者跨表、跨院或去标识后的链接不确定性必须量化或标记。
- 结局早于时间零点先标为时间逻辑不一致或既往事件候选；只有设计确实形成必须存活/无结局才能进入暴露组的时间段时，才称为 immortal-time bias。
- `event=0` 且结局日期缺失只能说明当前没有事件日期；只有存在明确随访截止/末次接触时间并满足删失定义时，才能称为正常删失。否则标记为结构性不适用或随访信息不足，不并入异常总数。
- 不把时间零点机械平移一天，不把 index 前结局日期置空后当作删失。依据估计目标、事件是否允许既往发生、时间粒度和同日事件顺序，决定排除、重定义时间零点、修正数据或单列既往事件；同日事件也不得在缺乏顺序证据时机械排除。
- 不因当前样本最小年龄、`encounter_count=0` 或字段非空就发明纳入排除阈值；阈值须来自方案、数据字典或明确研究目标。
- 同一患者记录冲突且无法判真时，不默认保留首行。整组保留或隔离，并在每个状态重新计算记录数、唯一患者数、时间异常和缺失；唯一患者数必须从当前数据 `nunique`，不能按移除行数递减。
- 可精确计算的状态计数不得写“约”。仍有影响队列定义的未决事项时使用“待裁定数据集”，不用“分析就绪集”。

## 临床试验审查

优先读取方案、统计分析计划、随机化说明、盲态规则、病例报告表字典和数据库锁定记录。

检查：

- 随机化序列、分层/区组变量、实际治疗与分配治疗的一致性；
- 入组、随机、首次用药、访视、停药、结局和退出时间顺序；
- 分析集定义及其一致性；
- 方案偏离、救援治疗、交叉、失访和 intercurrent event；
- 主要/次要终点、访视窗、多重性和中期分析控制；
- 中心效应、盲态维护、不良事件编码版本和暴露时间；
- 数据清理查询、锁库前后变更和解盲权限。

数据库尚未锁定时，用于正式验证性结论前应说明版本状态；若版本持续变化且无法追溯，需明确标注该局限。

## 缺失与样本流

样本流至少覆盖：筛选、纳入、分组/暴露、随访、结局可评估、各分析集和主要分析有效样本。报告每个终点实际分母。

缺失处理应匹配其来源和估计目标。单次填补或“缺失即正常/无事件”不得作为无说明默认。比较不同合理假设时，将其作为预设敏感性分析而非显著性搜索。

二分类终点先声明事件含义、参考组和效应方向，并在内部结果对象中统一生成 `n/N`、RD、RR、OR、区间及正文。若 `primary_endpoint=1` 表示应答，治疗组应答率更低时，治疗/对照的 RR 与 OR 也应小于 1；不得在 JSON、表格与正文中混用倒数方向。随机分组全体属于 ITT 原则，但仅对非缺失终点做完整案例比较并不自动成为完整 ITT 估计，需报告缺失假设和相应敏感性分析。

时间到事件分析中，观察到的 `time_to_event` 同时受事件和删失影响，不用普通 t 检验、秩和检验或中位数比较把它解释为随访更充分或治疗延长生存。随访充分性优先用反向 KM 等方法；疗效由与删失机制相匹配的生存估计回答。

## 最低交付

- 数据来源、快照和编码版本；
- 分析单位、事件时间轴与连接关系；
- 队列/分析集构建规则和样本流；
- 数据质量问题、查询与决策；
- 主要分析、偏离、敏感性与适用范围；
- 不可共享字段及受控访问说明。
