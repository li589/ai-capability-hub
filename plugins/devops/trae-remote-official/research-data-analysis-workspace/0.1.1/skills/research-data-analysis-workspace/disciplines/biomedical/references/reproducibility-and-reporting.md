# 复现与报告

## 复现单元

每项正式结果必须关联一个分析 ID，并能定位：

```yaml
analysis_id:
generated_at:
source_snapshots:
data_lineage:
code_or_computation_record:
parameters:
software_and_dependencies:
outputs:
known_limitations:
```

无法保存受限输入时，至少保存来源、版本、访问方式、结构说明、生成步骤和可公开的合成测试数据。

## 输出分层

严格区分三层，不把内部工作记录堆入用户产物：

1. **内部分析记录**：数据字典、样本流、派生口径、分析代码、参数、环境和方法说明。
2. **用户主报告**：结论摘要、关键质量事实、对分析的影响、待确认决策、核心局限和必要下一步。
3. **条件性附件**：用户明确要求时，单独提供数据、代码、审计或完整复现包。

格式不能改变分层。主报告通常不超过 5 个一级章节、6 张表；不展示规则 ID/矩阵、逐条异常、台账或严重度汇总、哈希/环境、验证断言和文件枚举。不能用“质控规则”“技术说明”“版本追溯”等改名后继续承载内部内容。记录级示例最多 5 条；附件只需说明“另附”，不要在正文重复清单。

## 直接交付

依据当前分析结果直接生成用户要求的格式，不建立要求矩阵、机器断言、发布前检查或完成门禁。

任何格式的产物及其本地资源写出后直接交付：不读取、解析、检查、验证、lint、渲染、运行或修改；不调用内置 checker/validator、`node --check` 或其他检查器；不启动本地服务器，不打开浏览器，不截图，也不创建运行时预览。

## 领域报告要点

- 临床/EHR：队列定义、时间零点、编码算法、医疗利用与结局可得性；
- 试验：分析集、方案偏离、盲态、缺失、intercurrent event 与多重性；
- 因果：目标估计量、识别假设、平衡/overlap、未测量混杂敏感性；
- 生存：事件、删失、竞争风险、风险集、随访和绝对风险；
- 诊断/预测：目标人群、参考标准/标签、拆分、校准、阈值和外部验证；
- 组学：参考版本、QC、设计矩阵、批次、多重检验和背景集；
- 流式/成像/湿实验：实验单位、重复层级、对照、门控/分割、板批次和原始材料。

## 表图规则

- 图、表、正文来自同一分析 ID；
- 同时交付 HTML、JSON、CSV 或文本摘要时，从同一结构化结果对象生成；机器可读结果与主报告不得使用相反效应方向、不同分母或不同变量变换。
- 标明样本量/事件数、单位、分母、区间、模型和校正；
- 从状态清单指定的 `report_state` 生成全部表图和正文数字；不手工重抄；
- 正式图按需记录 `figure_id`、源数据/代码、最终尺寸、视觉编码和 Take-Home；这些信息默认不堆入主报告；
- 不截断或选择坐标范围来夸大差异；
- 正式图保留源数据或确定性生成记录，并提供可访问的替代文本。
