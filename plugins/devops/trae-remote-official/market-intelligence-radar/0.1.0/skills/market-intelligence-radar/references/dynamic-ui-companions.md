# Dynamic UI companion layer

Use this layer only after the HTML style has been selected uniformly at random and the built-in
`dynamic-ui` skill has routed the focal relationship to a scene and ready material. The companion
layer adapts composition and identity; it never replaces the runtime material.

## Authority boundary

The built-in Dynamic UI runtime owns:

- whether a compact widget is appropriate;
- scene and ready-material selection;
- `widget_code`, required root attributes, fallback content, and initialization;
- CSS token names, typography, spacing, radius mechanics, and host-theme support;
- chart libraries, tooltips, keyboard behavior, focus, tap, and useful click binding.

The Radar companion owns only:

- the selected companion identity from the same random receipt as HTML;
- the relative focal slot, support slot, alignment, asymmetry, and whitespace rhythm;
- the selected style's brand values, optional accent, ink-family direction, and geometry personality;
- one shared interaction state and the focal signal already established by the report.

Do not copy a companion SVG into `widget_code`. Do not create a second widget template library,
alternate token family, page shell, navigation, report header, source ledger, or dashboard frame.

## Uniform route

Run `scripts/select_visual_style.py` exactly once. It validates both six-item manifests and returns
the selected HTML style plus its one-to-one `dynamic_ui_companion`. Each pair has exact probability
`1/6`.

Never select, filter, weight, reroll, or substitute a companion from keywords, report type, evidence
shape, signal count, brand, previous output, or preference. Do not draw again for Dynamic UI.

Read only:

1. the selected companion entry in `assets/radar-visual-kit/dynamic-ui-companions/manifest.json`;
2. its selected SVG guide for composition proportions;
3. the built-in Dynamic UI scene, material manifest, selected material instructions, and visual
   tokens required by that runtime.

## Adaptation sequence

1. Let Dynamic UI choose the scene and material from the factual relationship.
2. Preserve that material's data shape, fallback, tooltip, interaction, and acceptance limits.
3. Arrange the material inside the companion's focal and support slots. A support slot may contain
   only a legend, exact readout, selector, trigger, or short non-analytical note.
4. Map the companion's `brand` and `chart_series_1` values onto the runtime's existing token names.
   Use `optional_accent` only for one genuinely distinct secondary category. When it is `null`, do
   not invent a pop color.
5. Derive `--surface`, `--surface-muted`, `--text`, `--text-muted`, and `--border` from one neutral
   ink family while retaining the runtime's light-default and dark-override structure.
6. Keep ordinary peer series on the runtime's `--chart-series-1` through `--chart-series-4` scale.
   Do not use the optional accent or semantic colors as an ordinary series palette.
7. Keep one focal relationship and at most one support slot. If the chosen material cannot fit,
   simplify the companion composition; never weaken the runtime material contract.

The SVG is a proportion guide, not a source of literal pixels. Use runtime spacing and radius tokens;
preserve only the guide's geometry personality and relative visual weight.

## Six distinct companions

| Random style | Companion | Composition signature |
|---|---|---|
| `verdict-sheet` | `verdict-gate` | 72/28 focal field and verdict gate with one trigger line |
| `evidence-object` | `evidence-lens` | large evidence object, numbered anchors, compact inspection rail |
| `swiss-trace` | `trace-index` | strict coordinate field, direct labels, narrow source index |
| `decision-mosaic` | `decision-prism` | dominant plane with one bifurcated evidence rail |
| `signal-stage` | `signal-theatre` | luminous focal stage with a narrow three-cue rail |
| `alert-cut` | `response-cut` | diagonal response-window measure and one exact evidence line |

These identities modify composition, never the factual chart type. For example, a built-in
`line-trend` may become a verdict-gate trace, an evidence-lens object, a Swiss trace field, a prism
zone, a signal stage, or a response cut without changing the line-trend data and interaction rules.

## Hard visual limits

- No colored edge strip, colored partial border, accent border, or colored inset edge on cards,
  cells, rails, headers, navigation, tables, sections, or headings.
- Keep card and panel surfaces neutral. Put color in data marks, direct labels, badges, or a true
  full-field focal mark—not in decorative card fills.
- Use at most three chromatic colors across HTML and Dynamic UI: primary, secondary, optional pop.
- Derive every neutral from one ink family.
- No gradients, glow, decorative orbs, emoji, illustration, page background shell, or app chrome.
- Preserve readable light and dark pairs. Never place dark chromatic text on a dark surface.
- Never expose, embed, trace, or ship the internal guide SVGs.
