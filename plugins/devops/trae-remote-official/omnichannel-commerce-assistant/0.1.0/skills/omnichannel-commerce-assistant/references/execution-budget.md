# Execution depth and stop conditions

| Mode | Use when | Default work |
|---|---|---|
| Focus | category, platform/site, or period is incomplete | select and state one narrow working focus; ask only if ambiguity remains genuinely blocking |
| Quick | narrow question; no current external facts required | answer or calculate directly |
| Standard | defined diagnosis, review, or plan | inspect supplied data; research only critical gaps |
| Deep | user explicitly requests current market/competitor research and scope is clear | bounded evidence plan and sourced synthesis |

Do not escalate because the user uses broad words such as report, latest, cross-border, or complete. Depth follows the decision and uncertainty.

## Limits

- Inspect user files before browsing.
- Keep one primary capability and at most two supporting capabilities.
- For Standard work, verify only the current claims that could change the recommendation.
- Compare at most two platforms/sites in the first pass unless the user explicitly defines a broader study.
- Avoid connector setup when a one-off export solves the task faster.
- Do not create artifacts before scope is stable; a stated working focus with labeled assumptions counts as stable and does not require user confirmation.
- Do not use mock data as a shortcut around available public research or missing real store evidence.

## Stop

Stop research when evidence converges, further sources repeat the same point, an internal metric becomes the bottleneck, access is blocked but an export is available, or remaining uncertainty can be represented as a scenario or test.

Do not research to fill sections, add decorative charts, or justify a predetermined answer.
