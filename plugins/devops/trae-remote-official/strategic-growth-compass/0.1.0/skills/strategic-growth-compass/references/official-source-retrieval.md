# 官方与权威来源深挖方法

当战略判断需要外部公司、产品、价格、技术、经营、政策或竞争事实时读取本文件。`WebSearch` 用于聚焦发现来源、事实和外部信号，`WebFetch` 用于深读优先页面、核对关键表述与口径。官方原文具有更高证据权重，但有分析价值的媒体报道、转载和行业观察也可以作为次级资料。

## 1. 流程输入

开始检索前，把战略问题转成会影响选择的事实缺口，例如：

- 公司与产品的正式定位、版本、发布时间和可用范围。
- 技术规格、模型卡、API、价格、服务条款和许可证。
- 产品组合、商业模式、经营数据、融资或交易状态。
- 政策、监管、标准和正式合作关系。
- 实际采用、市场反应或外部争议中确实会改变推荐的部分。

每个事实缺口同时写明目标主体、产品或版本、时间边界和最匹配的来源类型。后续所有搜索、抓取和筛选都围绕这些缺口进行。

## 2. 工具职责与使用方式

通常按以下方式协作；根据主张重要性决定深读程度，不机械要求每条信息都经过完整漏斗：

```text
WebSearch(query=聚焦的事实与来源查询) -> source_map + candidate_signals
WebFetch(url=优先官方原文或高价值第三方页面) -> priority_pages
筛选(source_map, priority_pages, 事实缺口) -> evidence_package
```

### `WebSearch`：聚焦发现与初步扫描

- 围绕主体、产品、时间和事实缺口设计聚焦查询，优先找到官网、官方文档、IR、监管、交易所和官方仓库。
- 同时保留与问题直接相关的媒体报道、采访、内容平台转载、行业观察和市场信号，形成来源地图与候选事实。
- 搜索摘要适合快速判断相关性和发现线索；涉及精确数字、限定条件、原始引语或会显著改变建议的主张时，继续使用 `WebFetch` 阅读完整页面。
- 不因来源来自头条、CSDN、网易号、搜狐号或其他内容平台就自动丢弃；判断其是否写明主体、时间、原始出处，是否提供可核对细节，以及是否对本次分析确有增量价值。

### `WebFetch`：重点页面深读

- 优先深读与关键主张直接匹配的官方发布页、文档、价格页、报告、监管披露、模型卡和许可证。
- 对采访、独立研究、融资报道、市场反应或高信息密度转载，也可使用 `WebFetch` 获取完整上下文和原始链接。
- 沿已获取页面中的官方或原始链接继续抓取，以减少转述误差；不需要把所有搜索结果逐页打开。
- 页面无法获取时，可以保留相关的第三方信息作为次级参考，但应降低结论强度、保留来源属性；只有信息不足以可靠判断时才标为未知。

工具选择由主张重要性决定：关键数字和核心结论优先深读原文，背景、行业反应和弱信号可以由相关搜索结果或转载提供参考。不要为了形式完整抓取大量不会改变判断的页面。

## 3. 第一步：WebSearch 建立来源地图

### 目标

第一步的目标是快速建立与事实缺口相关的来源地图：既找到可靠的官方入口，也识别值得进一步核验或用于理解外部反应的第三方资料。阶段产物可以包含候选事实和信号，但要保留来源类型，避免把线索直接写成确定结论。

### 执行方式

围绕主体名称、产品名称和正式资料类型进行聚焦查询，优先发现：

- 公司主站、新闻室、官方博客、开发者平台和文档站。
- 官方价格、条款、状态页、模型或代码托管组织。
- 投资者关系、年报、招股书、监管或交易所披露入口。
- 政府、法院、标准组织、原始论文和正式数据平台。

注意公司改名、产品独立域名、平台迁移、新旧域名并存和不同地域站点。二手结果如果暴露官方或原始链接，应优先追溯；若转载本身包含采访、市场反应、行业解释或官方未披露的信息，也可作为次级资料保留。查询围绕明确事实缺口收敛，不继续累积无法改变判断的泛化结果。

### 域名验证

优先通过以下方式确认归属：

- 公司主站对文档、开发者、IR、GitHub 或 Hugging Face 组织的正式链接。
- 官方页面之间的互相链接、页脚主体、域名归属和一致的品牌身份。
- 监管、交易所、政府和标准组织控制的正式域名。
- 官方仓库、模型卡或论文中指向公司站点的可验证关系。

### 输出

形成来源地图：

| 主体 | 域名/页面 | 来源类型 | 归属或出处 | 候选事实/信号 | 对应事实缺口 |
|---|---|---|---|---|---|

来源地图以官方和原始资料为优先，同时保留确有增量价值的第三方页面。搜索聚合、重复转载和没有具体出处或分析价值的内容不必保留。

## 4. 第二步：WebFetch 深读重点页面

### 目标

根据第一步的来源地图选择重点页面执行 `WebFetch`。优先级通常是：支撑关键事实的官方原文、会改变建议的原始披露或独立资料、包含重要上下文的高价值转载。此阶段追求信息增量，不追求抓取数量。

### 获取顺序

对每个已验证域名按事实缺口选择入口：

1. 访问官网首页、产品页、新闻室、文档首页或 IR/监管入口，确认页面可用和站点结构。
2. 探测 `/llms.txt`、`/docs/llms.txt`、`/sitemap.xml`、`/sitemap_index.xml`、`/robots.txt` 等索引。
3. 查看文档目录、API Reference、博客/新闻归档、报告与 Filing 目录、GitHub Releases、README 和模型卡。
4. 沿已抓取页面中的官方链接继续调用 `WebFetch`，访问与事实缺口直接相关的具体页面或文件。

### 获取记录

| 域名 | 页面/文件 | 页面类型 | 发布或生效时间 | 产品/版本 | 对应事实缺口 | 可用状态 |
|---|---|---|---|---|---|---|

如果页面不可访问、域名已迁移或内容过时，先寻找同主体的其他官方入口或原始出处；仍不可得时，可保留相关转载作为次级证据，并在需要时说明其未经官方确认。

## 5. 第三步：筛选信息并形成资料包

### 目标

结合来源地图和重点页面，筛选真正能回答事实缺口的内容。来源层级会影响证据权重，但更重要的是它是否与具体主张直接匹配。

### 筛选方式

- 将每个页面映射到一个或多个事实缺口，删除无关背景和重复页面。
- 对关键数字核对实体、产品、版本、单位、币种、期间、地域、分母和生效时间。
- 保留“已发布、计划、测试中、寻求、目标、据报道”等原始状态。
- 规格用对应技术文档或模型卡，价格用价格页，许可证用许可证原文，财务与交易用 IR、监管或交易所披露，不用一个发布博客替代所有资料类型。
- 同一主体的官方页面发生冲突时，检查版本和时间；无法解释的冲突保留为未知，不自行选择有利数字。

### 输出

形成紧凑资料包：

| 事实缺口 | 筛选后的事实或数字 | 版本/日期/口径 | 原始 URL | 状态与限制 | 对战略判断的作用 |
|---|---|---|---|---|---|

资料包只保留直接支持战略分析的官方原文、高价值第三方资料、必要反证和无法确认项。候选 URL、无关页面、重复转载和未采用材料不进入后续上下文。

## 6. 来源层级与使用边界

| 层级 | 来源 | 主要用途 |
|---|---|---|
| P0 | 公司官网与文档、IR/监管/交易所文件、政府文件、原始论文 | 确认发布、规格、价格、条款、财务和监管事实 |
| P1 | 可确认归属的官方仓库、模型卡、正式社交账号 | 确认开放资产、版本变化和官方表态 |
| P2 | 具备编辑审查、直接采访或透明研究方法的独立媒体与机构 | 补充未公开交易、实际采用、市场效果和外部反应 |
| P3 | 聚合转载、内容平台、社区讨论和个人分析 | 补充行业解释、市场情绪、弱信号和原始线索；按来源质量谨慎使用 |

官方资料能够确认发布方披露了什么，但不能独自证明市场成功。实际采用、客户反应、独立性能、未公开交易和行业评价通常需要 P2/P3 资料补充。无论层级，都应判断来源是否与具体主张匹配，并保留必要的证据状态。

## 7. 官方来源主体要求

- 关键事实优先由 P0/P1 原文建立底座；P2/P3 可补充外部效果、行业反应、采访信息、未公开事项和分析视角。
- 产品规格、版本、价格、许可证、正式财务数据和交易状态存在原文时，以原文为主；第三方转述可以补充解释，但不应覆盖或曲解原始口径。
- “官方为主”按证据权重和关键事实优先级判断，不按链接数量机械判断。高价值转载可以进入正文和来源清单，但应保留第三方属性。
- 如果关键主张暂时只有第三方支持，先判断是否值得继续追溯。找不到官方原文时，可以以“据报道”或条件判断使用，不必一律视为取证失败。
- 只有任务本身以舆情、用户评价或市场反应为主要对象时，独立资料可以占较大比重；仍需以官方资料界定基础事实。
- 最终来源清单只保留直接支持正文或提供重要分析背景的页面，不堆积重复或无关资料。

## 8. 不同问题的优先入口

| 研究问题 | 优先深挖的入口 |
|---|---|
| 技术产品或模型 | 发布页、Docs、模型卡、论文、官方仓库、版本日志 |
| 公司与商业模式 | 官网产品组合、IR、年报、招股书、正式管理层材料 |
| API 与平台比较 | API Docs、Pricing、Terms、Changelog、Status Page |
| 开源策略 | 官方仓库、权重页、LICENSE、Release、贡献记录 |
| 政策与监管 | 政府、监管、法院、交易所、标准组织和法规原文 |
| 市场采用与外部效果 | 正式客户案例、透明独立研究、直接采访和可追溯经营披露 |

## 9. 停止与回退判断

- 当关键事实已有与主张直接匹配的原文，不再为同一事实收集大量重复转载；有独立分析价值的第三方内容仍可保留。
- 只有单一官方来源时保留其真实状态和限制，不为了凑数量重复搜索。
- 找不到原文时先检查域名迁移、站点索引、官方仓库、IR/监管和同主体其他入口；仍无法确认时，根据第三方资料质量选择标为“据报道”、条件判断或未知。
- 当事实缺口已被直接证据覆盖，剩余未知不改变选择，或新增抓取不再提高判断质量时结束取证，进入战略分析。
