# 战略交付结构指南

本文件用于把分析结果组织成管理层可读的战略产物。以下是内容覆盖与组合方法，不是固定目录或字段清单。

## 目录

1. 编辑原则
2. 交付深度
3. 可组合的战略模块
4. 按咨询问题组合
5. 正文与底稿的边界
6. 管理层表达

## 1. 编辑原则

- 先回答用户的核心问题或需要做出的决定，再补充支持判断的事实与机制。
- 用户数据、定义、范围和约束构成基准；外部资料用于核验或补充，不静默替换。
- 只呈现会改变选择、优先级、投入或风险判断的内容。
- 推荐应体现关键取舍；只有决策复杂度需要时，才展开替代方案、维持现状、机会成本和明确不做事项。
- 客户表达、实际行为、商业承诺和经营结果存在差异时，呈现会改变选择的冲突，不以单一信号代表需求。
- 责任主体、目标和时间若尚未批准，写成建议的牵头职能、目标或时间窗口。
- 事实、估算、推断、情景与未知保持可区分，但不必把证据治理过程做成正文栏目。
- 来源就近支持关键事实；长检索记录、候选资料和内部编号留在底稿。
- 最终引用以官网、官方文档、监管、交易所和其他原始权威资料为事实底座；有分析价值的媒体报道、转载和行业观察可以补充外部效果、未公开事项、市场反应和解释视角，但需保留第三方属性。

## 2. 交付深度

### 精要（默认）

适用于首轮判断、单一战略问题、竞品事件响应和管理层预读。它首先是一份分析参考，通常围绕三个核心部分组织：

1. **关键事实与变化**：发生了什么，哪些信息真正影响判断。
2. **战略分析与含义**：这些变化对公司、产品、客户或竞争位置意味着什么。
3. **结论与建议**：建议如何理解和应对，近期最值得关注什么。

只有问题涉及明确决策、资源承诺或路线规划时，才展开选项取舍、Must / Should / Could、责任主体、风险或反转信号。章节可以合并或省略，不把内部分析框架变成固定报告模板。

### 标准

适用于多产品线、多议题或正式战略讨论。在精要层基础上，根据问题有选择地展开：

- 公司定位、生态位与关键控制点。
- 客户与经营信号，以及它们对外部判断的支持或反证。
- 客户和市场选择。
- 商业模式、收入引擎、成本驱动与经济性。
- 竞品战略、传导机制和跨产品线影响。
- 战略选项的系统比较。
- 产品组合、能力和资源取舍。
- 一个规划周期内的路线、指标、治理、依赖、风险和复盘节点。

标准稿需要提供足够的分析依据和清晰结论，但不要求把每个框架、备选项、治理字段或研究过程都展示出来。

### 深度

适用于董事会、投委会、重大投入、市场进入或退出、组合重构和尽调式研究。在标准层基础上按需增加：

- 同口径的公司、市场、区域或产品组合比较。
- 收入、成本、单位经济、情景与敏感性分析。
- 资源承诺、能力获取、治理与跨团队依赖。
- 自建、采购、合作、投资、并购、整合或退出等公司级发展方式。
- 资本配置、组织与经营机制，以及业务组合的母合优势。
- 替代解释、证据冲突和完整验证计划。
- 必要时提供证据附录或详细模型。

深度来自决策问题和分析严谨度，不来自章节数量。

## 3. 可组合的战略模块

### 核心判断

- 建议选择什么，为什么现在。
- 在哪里竞争，依靠什么取胜。
- 最大取舍和明确不做。
- 需要决策者现在批准、否决或继续验证什么。

### 公司概览与生态位

- 核心客户与任务。
- 产品组合和价值链位置。
- 稀缺资产、控制点与关键依赖。
- 利润池、议价权和生态关系的变化。

### 客户与经营信号

- 目标客户说了什么、实际做了什么、是否付费和留存。
- 趋势、分群、漏斗或商业承诺中哪些信号支持战略命题。
- 客户表达、产品行为和经营结果之间是否存在冲突。
- 哪些内部数据尚缺，缺口是否会改变建议。

### 商业模式与经济性

- 用户、客户和付费方是谁。
- 价值如何创造、交付与获取。
- 收入来源、定价单位和增长驱动。
- 固定与变动成本、规模效应和单位经济。
- 交叉补贴、现金消耗、扩张约束与待验证数据。

### 竞争与跨产品线影响

- 竞品改变了能力基线、价格锚点、分发、生态还是客户预期。
- 变化通过什么客户任务和业务机制传导。
- 哪些产品线受到直接影响，哪些受到二阶影响。
- 影响的方向、强度、时间窗口与观察信号。
- 最小充分响应是什么，哪些反应属于过度跟随。

### 战略选项与取舍

为每个真实选项比较：

- 客户与战略价值。
- 收入、成本和资源含义。
- 差异化、生态杠杆和防御性。
- 能力缺口、依赖、可逆性与失败代价。
- 成立条件及会让选择反转的信号。

维持现状作为基线保留，避免只比较主动方案。

### 产品组合与资源配置

- 各产品线承担增长、防御、变现、控制点或能力期权中的什么角色。
- 产品之间如何协同、复用或相互蚕食。
- 哪些方向应加码、维持、验证、收缩或退出。
- 资源选择的机会成本和重新分配条件。

### 公司级发展方式

- 关键能力适合自建、采购、合作、投资还是并购获得。
- 纵向整合、联盟或组合协同如何创造额外价值。
- 资本、组织复杂度、控制权和可逆性的取舍。
- 维持、整合、收缩或退出的客户与经济影响。

### 战略路线

用以下逻辑组织：

`战略主题 → 目标结果 → Must / Should / Could → 关键依赖 → 观察信号 → 决策节点`

路线保持在战略结果、能力和资源层面。没有可靠基线时，先安排基线校准或验证，不为完整表格制造目标数字。

### 指标与治理

- 战略命题如何连接业务结果、领先指标、驱动指标和护栏指标。
- 谁拥有决策权，谁负责执行和取数，哪些结果需要跨团队共同承担。
- 关键假设、复盘节奏、升级条件和下一决策节点。
- 路线发生变化时，说明触发证据、取舍和资源重新配置。

## 4. 按咨询问题组合

### 公司或产品定位

优先组合：核心判断、客户任务、生态位、控制点、差异化、市场选择和明确不做。

### 商业模式诊断

优先组合：价值交换、收入引擎、成本驱动、单位经济、扩张约束、关键敏感变量和验证计划。

### 竞品事件响应

优先组合：事件事实、竞品意图与机制、产品线影响、分析结论和应对建议。只有需要立即决策时，才展开替代方案、近期动作和反转信号。避免演变成竞品功能清单或资讯汇总。

### 季度战略与产品路线

优先组合：本周期核心矛盾、战略主题、Must / Should / Could、产品组合角色、能力与依赖、停止或转向条件和下一次决策节点。

### 组合与资源重构

优先组合：产品线角色、经济性、协同与蚕食、战略选项、资源机会成本、阶段性承诺和退出条件。

### 公司级增长、合作或并购

优先组合：战略目标、能力缺口、自建/采购/合作/投资/并购比较、控制权与经济性、整合前提、资本边界、阶段性承诺和退出安排。

## 5. 正文与底稿的边界

正文通常展示：

- 与问题直接相关的关键事实、分析与结论。
- 对公司、产品、客户、商业模式或竞争位置的主要影响。
- 用户需要时才展开的选项、取舍、路线、风险和治理安排。
- 精简且有用的来源。

底稿通常保留：

- 来源地图、完整证据记录和检索过程。
- 来源等级、候选链接、未采用材料和详细冲突排查。
- 完整框架推演、长归因链、计算过程和内部编号。

只有用户明确要求审计、尽调或方法附录时，才把相应底稿内容整理进交付产物。

## 6. 管理层表达

- 标题直接表达结论或问题，不使用空泛的章节名。
- 一段只推进一个判断；事实之后说明它为什么改变选择。
- 表格用于比较，图表用于揭示关系，短段落用于解释取舍。
- 避免整页背景、重复摘要、框架展示和没有决策含义的数据陈列。
- 结尾给出清晰结论或下一步关注事项；只有决策型任务才要求明确批准事项、验证动作和复盘时间。
- 决策者关注选择、业务影响、资源和风险；产品负责人关注客户、组合和验证；执行团队关注控制边界、依赖和指标。根据主要读者调整信息深度，但保持同一战略结论。
