# 战略选择、路线与治理

当需要形成推荐、比较公司级发展方式、配置资源、制定季度路线、建立指标与阶段门或设计复盘治理时读取本文件。

## 1. 战略层级与选择内核

根据任务连接不同时间层级：

`长期方向与优势 → 中期战略主题与关键能力 → 当前周期的赌注、验证和资源选择`

不要求固定年限，但季度动作应能回到更长期的取胜逻辑。用以下内核检查战略是否完整：

1. **诊断**：最需要解决的核心矛盾是什么。
2. **指导方针**：选择在哪里竞争、依靠什么取胜。
3. **协调动作**：能力、资源、组织和市场动作是否相互强化。
4. **明确放弃**：哪些市场、投入和机会暂不追求。

若建议只是互不关联的机会清单，重新收敛为一组有共同逻辑的选择。

## 2. 战略选项

形成少量真实选项，并保留维持现状作为基线。可根据问题比较聚焦/扩张、平台/垂直应用、开放/封闭、高端/大众、产品化/服务化、国内/海外等方向。

对每个选项回答：

- 成功定义和目标客户。
- 在哪里竞争，如何取胜。
- 需要哪些能力与经营机制。
- 收入成本、资本和时间窗口含义。
- 关键依赖、风险、可逆性和失败代价。
- 明确不做和成立条件。

多个可同时执行的小动作应作为同一战略组合，不包装成伪互斥选项。

## 3. 公司级发展方式

公司级问题按需比较：

- **自建**：能力是否构成长期控制点，能否在窗口期内建设。
- **采购**：能力是否标准化，采购能否降低时间和执行风险。
- **合作或联盟**：双方资产是否互补，价值、数据、客户和决策权如何分配。
- **投资或并购**：是否需要获得难以内部建设的能力、客户、渠道、人才或控制权。
- **纵向整合**：整合是否改善供应、质量、利润或战略自主，是否增加资本和组织复杂度。
- **整合、收缩或退出**：释放资源是否高于客户迁移、收入损失和能力断层风险。

对多业务公司检查“母合优势”：公司总部是否能通过资本、品牌、渠道、数据、人才或治理让业务组合比独立经营更有价值。没有明确协同机制时，不以“战略协同”替代证据。

## 4. 选项评估与情景

比较客户与战略价值、经济性、防御性与生态、能力与执行、时间窗口、可逆性、关键风险和证据置信度。权重由决策目标和约束决定，不使用通用固定权重。

改变最不确定的关键假设，检查推荐是否反转。高影响、高不确定变量需要情景时，说明：

- 假设及依据。
- 对客户、行业、经济性和产品组合的影响。
- 当前建议是否仍成立。
- 可观察信号和触发后的加码、暂停、转向或退出。

## 5. 资源与能力

先明确可用资源或资本边界、既有承诺和不可逆投入，再确定优先级。新增重大投入时说明被推迟、收缩或停止的事项。

区分：

- 已有且可复用的能力。
- 能在窗口期内建设的能力。
- 更适合采购、合作、投资或并购获得的能力。
- 只能观察或依赖的外部条件。

每项关键能力说明其支撑的选择、当前差距、获取方式、关键依赖和继续或停止建设的判断条件。

标记控制边界：`direct / influence / external`。团队可控结果、跨团队共同结果和公司级滞后结果分别表达，避免把收入、融资、资本开支或终端增长错误分配给单一团队。

## 6. 路线与验证

用以下逻辑组织路线：

`战略主题 → 目标结果 → Must / Should / Could → 关键依赖 → 指标 → 决策节点`

- **Must**：本周期不完成就无法验证或实现战略命题。
- **Should**：在 Must 取得进展后提高胜率。
- **Could**：低成本保留未来选择。

按情景还可区分无悔动作、核心赌注、保留选项和停止/退出。未知成本或必要性的重大建设不自动属于无悔动作。

验证优先采用低成本、快反馈和可逆的顺序：确认商业事实与预算归属，取得接近交易的承诺，评估最小范围与成本，开展有限试点，再决定规模化投入。若必须先提供最小能力才能验证，说明原因并控制承诺规模。

时间可使用季度或 Now/Next/Later；没有真实外部窗口或已批准承诺时，不制造精确日期。路线保持在战略结果、能力和资源层面，不进入功能 backlog。

## 7. 战略指标树

将推荐连接到可学习的度量系统：

`战略命题 → 业务结果 → 领先指标 → 驱动指标 → 护栏指标`

- **业务结果**：战略最终希望改善的客户、收入、成本、利润或竞争结果。
- **领先指标**：在结果出现前反映方向是否成立的信号。
- **驱动指标**：团队能够影响的产品、渠道、交付或能力变量。
- **护栏指标**：防止用短期增长换取不可接受的质量、成本、风险或客户损失。

指标需要说明定义、分群、基线、数据来源、观察窗口和负责取数的职能。趋势、队列、漏斗、贡献和异常分析按 `customer-business-signals.md` 执行。

## 8. 阶段门

阶段门连接关键不确定性、可观测证据和明确动作：

- 有用户确认目标、历史基线、单位经济或资源约束时，可以设阈值并说明依据。
- 没有可靠依据时，先定义需要观察什么、什么状态支持继续、什么状态要求调整；不制造精确数字。
- 企业业务同时考虑预算或合同价值、席位/用量、采购时间、合规条件、交付成本和样本代表性，不只计算客户家数。
- 弱来源只能支持条件情景或验证，不单独支撑难以逆转的 Must。

阶段门触发继续、加码、停止或转向，但不替代管理层判断。

## 9. 治理与变更

为重要战略建立轻量运行机制：

- **决策权**：谁批准方向和资源，谁提出建议，谁负责执行，谁提供关键输入。
- **假设清单**：当前推荐依赖什么，证据状态和下一验证是什么。
- **复盘节奏**：按信号变化速度和投入可逆性设置，不机械采用统一周期。
- **决策日志**：记录选择、理由、证据和当时未知项。
- **变更记录**：说明什么变化触发了路线调整，以及资源从哪里释放、重新投入到哪里。
- **升级机制**：哪些依赖、风险或指标偏离需要跨团队或管理层决定。

复盘不是更新项目进度，而是判断战略命题、优先级和资源承诺是否仍然成立。

## 10. 边界与误区

- 不同时填满所有框架；选择不能改变结论的方法可以省略。
- 不用任意评分、权重和阈值制造精确排序。
- 不把招聘、合作或短期趋势直接写成既定战略与长期因果。
- 不把市场增长或空白象限自动视为公司机会。
- 不把未知投入包装成无悔动作。
- 不为验证支付意愿先建设完整产品。
- 不把路线图写成用户故事、验收标准、Sprint 或研发估时。
- 不用外部竞品事件单独决定退出内部产品。
