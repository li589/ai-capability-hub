# 研究报告撰写内部步骤

本步骤由主 Agent 直接执行，不创建内部任务。先由脚本把专题稿完整组装为 `draft.md`，再提取紧凑编辑上下文，只一次写出核心结论、行业概览和结论与展望。六章专题正文、引用和图表声明由前序步骤负责，本步骤不重新阅读专题或完整草稿、不重写整篇报告，也不负责最终发布。

完成前不发送自然语言，不打开脚本、模板、CSS 或 JavaScript 源码，不调用 `LS`、`SearchReplace`，也不创建临时脚本。

## 一次组装

下文 `<SKILL_ROOT>` 和 `<WORK_DIR>` 分别取主流程已经解析的真实绝对路径。调用前替换路径占位符。

完整研究只运行一次：

```bash
python3 "<SKILL_ROOT>/scripts/assemble.py" \
  --work-dir "<WORK_DIR>" \
  --output "<WORK_DIR>/draft.md" \
  --title "<报告标题>" \
  --require-full
```

定向研究去掉 `--require-full`。程序负责按报告顺序复制已有研究维度，合并引用并按 URL 去重、统一编号，保留 `chart` 和 `visual`、资料不足章节和统一参考资料。`--require-full` 要求六份专题文件存在，但不要求每章都达到完整 L2 门槛。

`<报告标题>` 必须包含 `plan.md` 中用户实际研究的对象以及必要的地域或细分范围，形式为“<研究对象与范围>研究报告”；不得只写“行业研究报告”。终检程序将直接使用该一级标题生成 Markdown 和 HTML 文件名。

组装时会移除专题稿内部的“核心判断”“核心结论”“正文”等包装标题，保留其中内容和有业务含义的小节，避免目录出现重复通用节点。局部资料不足不能阻止草稿生成；缺失文件、弱来源、断裂引用、异常重复内容或无法解析的专题仍返回错误。

组装程序返回非零时立即结束：下一步必须直接返回失败摘要，不得再调用读取、编辑、命令或其他工具；不得读取专题后手工编写 `draft.md`、猜参数、修改专题、创建修复脚本或重跑。

## 紧凑编辑上下文

组装成功后只运行一次：

```bash
python3 "<SKILL_ROOT>/scripts/extract_context.py" \
  --work-dir "<WORK_DIR>" \
  --mode editorial \
  --output "<WORK_DIR>/editorial-context.md"
```

程序只从已组装草稿提取各章首要判断、必要口径、引用和展望，不改变草稿。提取失败时保留可用 `draft.md` 并直接进入关键事实与引用核查，不读取完整草稿补救、不重试。

提取成功后只读取一次 `<WORK_DIR>/editorial-context.md`，不得读取包含未核实发现线索的 `research-card.md`。读取结果返回后，下一条回复的第一个且唯一内容必须是一次 `Write`，写入 `<WORK_DIR>/editorial.md`；不得读取完整 `draft.md`，也不得先在主对话输出分析、提纲、草稿、自检或解释。

完整研究的 `editorial.md` 必须严格按以下顺序只包含三个二级章节；定向研究没有行业概览时只保留首尾两个章节：

```markdown
## 核心结论
...

## 行业概览
...

## 结论与展望
...
```

- **核心结论**：只保留彼此独立、会影响用户判断的短结论。每项采用“结论 + 一个关键证据 + 业务含义”，删除重复主题、过程标签和详细计算。
- **行业概览**：作为整篇报告的行业仪表盘。先用一段话说明研究边界、所处阶段和行业的核心结构；再从现有材料中选择真正影响判断的内容，说明最近发生了什么变化、关键价值或瓶颈位于哪里、企业主要靠什么拉开差距。三类问题只选证据足够且有解释力的内容，不要求全部覆盖，不使用固定小标题，也不按行业名称套模板；详细政策、规模推导和企业逐项资料留在后文。定向报告不新增行业概览。
- **可选行业速览**：只有紧凑上下文中已有 2—5 项彼此不同、可以直接引用的关键事实时，才在行业概览首段之后加入一个 `snapshot`；可以是数值，也可以是明确的阶段、结构、瓶颈或里程碑判断。每项写“简短名称｜数值或状态｜业务含义”，并在该项自身附已有引用；`source` 汇总这些引用。不得为了凑卡片增加事实、补搜数据、固定指标菜单或使用“指标、信息、业务含义”等占位内容。条件不满足时直接使用正文，不输出空卡片或普通信息卡。

```visual
type: snapshot
title: <根据实际内容命名>
source: [n] [m]
item: <简短名称> | <数值或状态> | <业务含义及直接引用 [n]>
item: <简短名称> | <数值或状态> | <业务含义及直接引用 [m]>
```
- **结论与展望**：只保留未来判断、成立条件、观察信号和会改变判断的因素，不复述六章内容。

局部编辑只能压缩、选择、分组和改写紧凑上下文中的已有材料。不得增加事实、数字、计算、URL、来源、企业、产品、政策或预测，不得改变结论方向；所有引用编号必须已存在于紧凑上下文的参考资料中。`editorial.md` 不得包含六章正文、参考资料、一级标题或其他二级标题。

写入 `editorial.md` 后立即结束，不运行合并、审计、引用整理或 HTML 预检。下一阶段的唯一确定性命令会把局部编辑安全合并到草稿，并一次完成引用整理、正式报告和 HTML 生成。`editorial.md` 缺失或不能安全合并时保留 `assemble.py` 已生成的可用草稿，不在本步骤修补、重试或全文重写。

## 报告结构与视觉

完整研究固定输出：

```markdown
# {行业}研究报告

## 核心结论
## 行业概览
## 市场规模
## 产业链与关键瓶颈
## 竞争格局
## 重点企业
## 宏观与政策环境
## 趋势、机会与风险
## 结论与展望
## 参考资料
```

报告不设置“研究说明”或其他报告级限制提示。某项资料限制只保留在受影响的章节和对应事实附近；研究范围、地域与资料截止时间作为正常元信息呈现，不写成免责声明。

行业概览是六个研究维度的综合阅读入口，不是第七个研究任务；宏观与政策环境放在重点企业之后、趋势之前。定向研究仍只组装用户要求的专题。

多对象、多字段横向比较、`chart` 和 `visual` 已由专题稿及组装程序保留。发布程序根据数据用途和数据形态生成相应图表或 HTML/CSS 结构组件；没有可靠数据或结构时使用正文，不画图、不补数、不使用 Mermaid。本步骤不改变六章正文的信息载体，也不在草稿阶段运行 HTML 预检。

完成后只返回两到三句话，说明报告实际包含的方面、总体判断、图表和关键资料限制，以及下一步将核查什么；不计算字符数，不给路径、命令、工具或写作过程。
