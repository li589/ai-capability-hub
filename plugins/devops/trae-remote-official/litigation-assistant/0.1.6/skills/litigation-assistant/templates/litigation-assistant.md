# 诉讼案件支持模板

## 质量约束

1. **法条强制 MCP**：涉及法律依据的分析必须通过 pkulaw skill 获取原文，禁止凭记忆引用。
2. **立场锁定**：首次交互必须确认用户是原告/被告/第三人，后续所有分析基于该立场展开。
3. **对抗性思维**：每个我方论点必须预判对方反驳并给出应对，不做单边乐观分析。
4. **零确认直执行**：意图明确后直接进入对应 Phase，禁止二次确认话术。
5. **结论先行**：每个 Phase 输出以一句话结论/胜算评估开头。

---

## 子场景分流表

| 用户表述 | 进入 | 必备信息 | 缺失处理 |
|---------|------|---------|---------|
| 案件分析/起诉/打官司/诉讼策略/帮我分析这个案件 | Phase 1 | 案件基本事实描述 | [必须问] 一次问全 |
| 证据梳理/时间线/整理证据 | Phase 2 | Phase 1 已完成 或 用户直接提供事件列表 | 有事件即推进 |
| 争议焦点/索赔图/对方会怎么辩/胜算分析 | Phase 3 | 案件事实 + 诉讼请求 | 未做 Phase 1 则先触发 |
| 质证准备/交叉盘问/证人询问 | Phase 4 | 证人身份 + 待证事实 | [必须问] |
| 起诉状/答辩状/代理词/律师函 | Phase 5 | 透传前序上下文 | 跳转 `legal-document.md` |
| 截止日期/排期/诉讼时效计算 | Phase 6 | 案件关键时间节点 | 有即推进 |

多意图按业务先后串联执行。首次进入且用户未提供任何信息时，用一条编号列表一次问全 Phase 1 必备信息。

## Phase 1: 案件梳理（Matter Intake）

**必备信息**（缺失一次问全）：
- 案件类型（合同纠纷/侵权/劳动争议/知产/行政/刑事/其他）
- 用户立场（原告/被告/第三人）
- 核心事实概述（发生了什么）
- 对方信息（对方是谁）
- 期望结果（要什么赔偿/达到什么目的）

**执行步骤**：
1. 根据案件类型并行调用 MCP 预加载核心法条
2. 识别法律关系类型 + 请求权基础（合同之诉/侵权之诉/不当得利等）
3. 逐一分析请求权构成要件是否满足
4. 初步胜算评估 + 关键风险点

**输出格式**：

```
[案件定性 + 初步胜算判断]
风险等级: [高风险/中风险/低风险]

案件基本信息:
- 案件类型 / 案由 / 当事人地位 / 标的金额 / 管辖法院 / 诉讼时效

| 请求权类型 | 法律依据 | 构成要件 | 是否满足 | 说明 |
|-----------|----------|---------|---------|------|

关键风险点（≤5条，按影响降序）:
1. ...

初步策略建议:
- 推荐方案 + 替代方案简述
- 诉讼成本效益初判

> 下一步：a. 整理证据时间线  b. 分析争议焦点  c. 起草起诉状/答辩状  d. 查同类判例  e. 计算诉讼时效
```

---

## Phase 2: 证据时间线（Evidence Chronology）

**触发条件**：Phase 1 完成后用户选择，或用户直接提供事件/证据清单。

**执行步骤**：
1. 按时间排列所有已知事件
2. 为每个事件标注对应证据、证据类型及证明力
3. 识别证据缺口（哪些关键事实缺少证据支撑）
4. 标注举证责任分配（谁来证明什么）
5. 给出证据保全建议（如有紧急性）

**输出格式**：

```
[证据充分度评估，如"核心待证事实5项中3项有强证据"]

| 日期 | 事件 | 证据名称 | 证据类型 | 证明目的 | 证明力 | 举证方 |
|------|------|---------|---------|---------|--------|--------|

证据缺口:
| 待证事实 | 取证方式建议 | 紧急程度 | 难度 |
|---------|-------------|---------|------|

证据保全建议（如需）:
- ...

举证责任分配要点:
- 我方需证明：...
- 对方需证明：...（利用举证不能）

> 下一步：a. 制作争议焦点图表  b. 准备质证大纲  c. 导出证据清单(docx)  d. 补充案件分析
```

用户要求"导出"时，联合 docx skill 生成证据清单文档。

---

## Phase 3: 争议焦点与索赔图表（Issue / Claim Charts）

**执行步骤**：
1. 从案件事实中提炼争议焦点（通常 2-5 个）
2. 每个焦点展开双方攻防：我方主张 + 法律依据 → 对方可能反驳 → 我方应对
3. 逐焦点胜算评估
4. 知产/专利案件附加索赔对比图表（权利要求 vs 侵权行为逐项对比）

**输出格式**：

```
[焦点数量 + 优劣势分布，如"3个焦点中2个我方占优"]

| 焦点 | 我方主张 | 法律依据 | 对方可能主张 | 我方应对 | 胜算 |
|------|---------|---------|-------------|---------|------|

综合胜诉概率: [X%-Y%]
- 有利因素：...
- 不利因素：...

（知产案件）索赔对比图表:
| 权利要求/条款 | 具体内容 | 侵权对应行为 | 匹配度 |
|-------------|---------|-------------|--------|

> 下一步：a. 准备质证大纲  b. 起草代理词  c. 制定和解方案  d. 查询同类判例  e. 导出焦点分析(docx)
```

---

## Phase 4: 质证准备（Cross-Examination Prep）

**必备信息**（缺失一次问全）：
- 证人身份/角色（对方当事人/对方证人/鉴定人/我方证人）
- 待证事实（该证人的证言试图证明什么）
- 已知陈述（对方证据材料中的相关内容，如有）

**执行步骤**：
1. 确定质证目的（肯定己方事实 / 动摇对方证据可信度 / 证明证人不可信）
2. 设计问题清单（从无争议事实 → 逐步引入矛盾点 → 封闭式关键问题）
3. 预判回答路径 + 追问策略（对方如果这样答/那样答，如何追问）
4. 标注禁止问题（可能适得其反或打开对方辩解空间的问题）

**输出格式**：

```
[质证目标，如"动摇对方关键证人关于交货时间的陈述可信度"]

质证目的: ...
质证策略: ...（总体路线）

| 序号 | 问题 | 目的 | 预期回答 | 若对方否认→追问 |
|------|------|------|---------|----------------|

[注意] 禁止问题（避免适得其反）:
- ...

证据弹劾点（如有矛盾陈述）:
- 证人在X处说"..."，但在Y处说"..."，二者矛盾

> 下一步：a. 准备另一位证人质证  b. 出质证意见书(docx)  c. 回到争议焦点  d. 补充证据时间线
```

用户要求"出质证意见书"时，联合 docx skill 生成正式质证意见文书。

---

## Phase 5: 文书草稿准备（桥接层）

本 Phase 将前序分析上下文透传给 `templates/legal-document.md`，不重复文书结构规范。

**透传字段**（自动从 Phase 1-4 收集，补全 legal-document.md 所需信息）：
- 原告/被告主体信息
- 案由
- 诉讼请求（金额 + 具体请求项）
- 事实与理由（来自 Phase 1 案件梳理 + Phase 3 争议焦点）
- 证据清单（来自 Phase 2）
- 适用法条（来自 MCP 检索结果）
- 管辖法院

**产物**：必须联合 docx skill 生成 .docx 文件。正文仅输出简要总结。

---

## Phase 6: 截止日期与行动计划（Deadline Tracker）

**执行步骤**：
1. 根据案件类型和当前阶段，列出所有法定期限
2. 结合用户提供的实际日期计算截止日
3. 按紧急程度排序
4. 给出优先级行动建议

**常见法定期限参考**：
- 诉讼时效：普通 3 年（民法典 188 条）
- 答辩期：收到起诉状副本 15 日内
- 举证期限：法院指定或协商（不少于 15 日）
- 上诉期：判决书 15 日 / 裁定书 10 日
- 财产保全：裁定后 30 日内起诉
- 劳动仲裁时效：1 年

**输出格式**：

```
[最紧急事项提示，如"答辩期仅剩5天"]

| 事项 | 法律依据 | 起算日 | 截止日 | 剩余天数 | 紧急程度 | 行动建议 |
|------|---------|--------|--------|---------|---------|---------|

优先行动清单:
1. [高风险/紧急] ...
2. [中风险] ...
3. [低风险] ...

> 下一步：a. 回到案件分析  b. 准备对应文书  c. 查询诉讼时效法条  d. 证据保全（如临近举证期限）
```

## 串联路径

```
Phase 1(案件梳理) → Phase 2(证据) / Phase 3(焦点) / Phase 5(文书) / Phase 6(排期) / case-search.md(判例)
Phase 2(证据) → Phase 3(焦点) / Phase 4(质证)
Phase 3(焦点) → Phase 4(质证) / Phase 5(文书) / 法条检索(MCP)
Phase 4(质证) → Phase 5(文书)
Phase 6(排期) → 任意 Phase
```

## 上下文透传字段

一经确认，跨 Phase 不重复询问：
- 案件类型、案由
- 用户立场（原告/被告/第三人）
- 双方当事人信息
- 核心事实
- 诉讼请求
- 管辖法院
