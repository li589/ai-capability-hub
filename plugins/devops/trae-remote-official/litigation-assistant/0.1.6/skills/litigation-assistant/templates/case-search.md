## 一、查询工具与方法

### 1.1 检索优先级

- **首选**：pkulaw skill（案例语义检索 + 案例列表深度检索）
- **补充**：WebSearch 检索裁判文书网等官方渠道（pkulaw 结果不足时使用，须标注来源）

### 1.2 查询策略

根据用户需求选择查询策略：

| 查询目的 | 推荐方式 | 查询关键字设计 |
|----------|----------|---------------|
| 同类案件判例 | pkulaw | 案由+关键事实描述 |
| 法官裁判倾向 | pkulaw | 法院名称+案由 |
| 企业涉诉风险 | pkulaw + WebSearch 补充 | 企业全称 |
| 个人信用调查 | WebSearch（执行信息网） | 姓名+身份证号 |
| 交易对手尽调 | pkulaw + WebSearch 交叉验证 | 企业全称，关注合同纠纷类 |
| 特定案件进展 | WebSearch（诉讼服务网） | 案号（格式：(2024)京01民初123号） |

### 1.3 补充检索渠道

pkulaw 检索结果不足时，可通过 WebSearch 补充检索以下官方渠道：

| 平台 | 网址 | 查询内容 | 数据范围 |
|------|------|----------|----------|
| 中国裁判文书网 | wenshu.court.gov.cn | 裁判文书全文 | 2014年至今公开文书 |
| 中国执行信息公开网 | zxgk.court.gov.cn | 被执行人/失信信息/限高 | 全国法院执行案件 |
| 国家企业信用信息公示系统 | gsxt.gov.cn | 企业基本信息/行政处罚 | 全国企业 |

## 三、判例检索

### 3.1 检索策略

根据用户法律问题设计判例检索方案：

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 确定案由 | 按照最高院《民事案件案由规定》确定精确案由 |
| 2 | 提取关键事实 | 从用户描述中提取与裁判相关的核心事实要素 |
| 3 | pkulaw 语义检索 | 用自然语言描述案情进行语义检索 |
| 4 | pkulaw 深度检索 | 按关键词检索获取完整判决要素 |
| 5 | 筛选排序 | 指导案例 > 公报案例 > 普通案例；近年 > 远年 |

### 3.2 判例报告格式

## 四、案号格式说明

中国法院案号格式：`(年份)法院简称+案件类型+编号`

| 案件类型代字 | 含义 | 示例 |
|-------------|------|------|
| 民初 | 一审民事 | (2024)京0105民初12345号 |
| 民终 | 二审民事 | (2024)京01民终6789号 |
| 民再 | 再审民事 | (2024)最高法民再123号 |
| 刑初 | 一审刑事 | (2024)京0105刑初456号 |
| 行初 | 一审行政 | (2024)京0105行初78号 |
| 执 | 执行 | (2024)京0105执12345号 |
| 执异 | 执行异议 | (2024)京0105执异67号 |
| 破 | 破产 | (2024)京0105破1号 |
| 知民初 | 知产一审 | (2024)京73知民初890号 |

法院简称规则：
- 最高法：最高法
- 高级法院：省简称 + 无区号，如"京"、"沪"、"粤"
- 中级法院：省简称 + 01/02…，如"京01"（北京一中院）
- 基层法院：省简称 + 4位区划码，如"京0105"（朝阳法院）

## 五、数据时效性提示

查询结果输出时必须包含以下提示：

```
[数据时效提示]
- 北大法宝实时同步主库，法规/案例时效性较高
- 裁判文书网数据通常滞后3-6个月（法院上传周期）
- 执行信息更新较实时（通常1-7天）
- 部分案件因涉密/未成年人/调解结案等原因不公开
```

## 六、合规与隐私注意事项

1. **个人信息保护**：查询个人信息时提醒用户注意《个人信息保护法》相关规定
2. **合法用途**：确认查询用于合法目的（尽调/风控/诉讼准备）
3. **数据来源标注**：所有查询结果必须标注数据来源渠道
4. **脱敏处理**：输出中对身份证号、银行账号等敏感信息做脱敏处理
5. **不做最终判断**：查询结果不能替代正式的法律尽调报告
