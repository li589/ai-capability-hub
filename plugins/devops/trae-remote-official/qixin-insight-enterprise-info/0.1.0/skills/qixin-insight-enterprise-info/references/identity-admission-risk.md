# 主体核验、准入与合作风险

## 主体核验

适用请求：

- 确认合同相对方是不是目标企业。
- 排除重名主体、分支/总公司混淆、旧名旧址、迁址误判、品牌混淆或疑似蹭名。
- 用户提供简称、曾用名、统一社会信用代码、注册号、法定代表人、地址、电话、邮箱、官网域名、园区、开发区或分公司名称。

流程：

1. 先整理用户线索，不把内部对象展示给用户。
2. 用 `qixin_insight_enterprise_resolve` 建候选集。
3. 按最强线索选择核验接口：三码、工商照面、历史名称、变更记录、分支归属、联系方式、备案域名、园区/开发区。
4. 输出 `确认匹配`、`基本匹配但签约前需补一个强标识`、`不匹配`、`存在多个候选暂不能确认`。
5. 若证据仍不足，给一个可复制的补充线索模板，优先要统一社会信用代码、注册号、完整企业名称、法定代表人、注册地址、官网域名或分支名称。

不要把“山寨”“仿冒”写成已确认事实；使用“名称/品牌混淆风险”或“疑似仿冒待进一步核验”。

## 前置准入核验

适用请求：

- 开户、商户入驻、供应商接入、授信前置筛查、内部资料校验。
- 用户想判断主体是否真实存续、是否明确、字段是否与库内一致、是否可继续收件、补正、人工复核、升级风控或法务、暂缓接入。

模式：

- `profile only`：只给企业线索，先确认主体、照面和快速结论。
- `generic compare`：用户给少量字段，只比对用户提供的字段。
- `custom compare`：用户给内部清单，按清单顺序逐项核验。

常见字段比对标签：

- `一致`
- `基本一致`
- `不一致`
- `用户未提供，无法比对`
- `库内当前未见，待人工核`

准入建议只使用过程性标签：

- `通过前置核验`
- `可继续收件但需补正`
- `需人工复核`
- `建议升级风控或法务`
- `暂缓接入`
- `不通过前置核验`

## 客户准入风险筛查

适用于银行客户准入、普通公司客户引入、合作准入、交易前置筛查。重点识别：

- 主体歧义、注销、吊销、清算。
- 失信、限高、被执行、终本。
- 经营异常、严重违法、行政处罚、税务异常。
- 股权冻结、资产负担等可能影响普通客户准入的事项。

执行顺序：

1. 主体唯一性确认。
2. 工商照面和关键风险明细预筛。
3. 仅对命中信号钻取代表性明细。
4. 聚合接口只有在用户明确要求或明细无法满足时豁免使用。

输出可用建议：

- `建议进入准入下一步`
- `建议补充材料后进入下一步`
- `建议升级人工审查`
- `建议暂缓准入`
- `不建议进入准入流程`

## 公司合作风险速查

适用于采购、法务、商务、供应商引入、签约前评审、客户合作前快速判断。默认覆盖：

- 工商状态。
- 经营异常、严重违法。
- 被执行、失信、限高。
- 行政处罚。

条件触发补查：

- 欠税、重大税收违法、非正常户。
- 股权冻结、股权出质、动产抵押。
- 立案、开庭、终本。

合作建议只在关键查询完成后输出：

- `可进入合作评审`
- `可推进但需补核`
- `建议法务或风控复核`
- `建议审慎推进`
- `建议先完成专项核验`

司法记录不要自动升档。先判断企业身份、案由、金额、时间、状态、集中度和与当前合作场景的相关性。
