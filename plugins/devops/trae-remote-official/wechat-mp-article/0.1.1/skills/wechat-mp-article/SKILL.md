# 微信公众号推文创作专家

把写好的公众号推文内容注入到 HTML 模板，交付真机风格预览：

```
new-article.sh 建目录 → 写 body.html → inject-content.sh 注入 → 交付 index.html
```

**决策次序：先内容、后工程**。不要一上来就跑脚本，先按 §1 挑对内容方法论、把正文打磨到位，再走 §2 机械注入。

> 🚫 **顶层禁令：`./scripts/` 和 `./templates/` 目录下的文件（脚本、模板 HTML）严禁读取。** 它们是纯执行件，用法已在 §2 写全，照命令调用即可。读它们不会让你写得更好，只会白烧 token——任何情况下都不要打开、不要预览、不要"确认一下内容"。

## 0. 铁律：样式内联 + 结构扁平（最优先，贯穿全程）

微信公众号后台会**剥离 `<style>` 标签、class 选择器、嵌套容器**，只保留标签自身的行内 `style=""`。写 `body.html` 必须遵守：

**可靠属性**：`color / font-size / font-weight / background / border / border-radius / box-shadow / padding / margin / line-height / text-align / max-width / width / overflow-x / float / display:inline-block`，单位优先 `px`。

**禁用**：class、`<style>` 块、外链 CSS、`var()`、`display:flex`、`position`、`@media`、伪类、`@keyframes`、外链字体、JS。

### 0.1 粘贴兼容四条死规则

1. **禁用 `<h1>`–`<h6>`**：公众号对语义标签强制覆盖样式（蓝色、左对齐），行内 style 无法覆盖。所有标题用 `<p style="...">`。
2. **禁止依赖继承**：公众号给 `<p>` 默认 `text-align:left`，覆盖父级。每个元素必须自身写全所有需要的样式。
3. **结构必须扁平**：嵌套 `<div>` 会被剥离/打平。每个可见元素都是独立顶层 `<p>`，自带全套 style，不依赖父容器。
4. **每个 `<p>` 是孤儿**：没有父亲、没有继承、没有语义标签特权——所有样式自己带齐，才能在粘贴后活下来。

```html
<!-- ✗ 嵌套容器 → 粘贴后丢样式 -->
<div style="text-align:center;margin:54px 0 28px;">
  <div style="...">— 01 —</div>
  <p style="...">章节标题</p>
</div>

<!-- ✓ 扁平独立 → 粘贴后保留 -->
<p style="text-align:center;margin:54px 0 0;font-size:13px;letter-spacing:5px;color:#9a8c6a;">— 01 —</p>
<p style="text-align:center;font-size:20px;font-weight:bold;color:#2b2b2b;margin:12px 0 28px;">章节标题</p>
```

### 0.2 内联款式示例

以下是行内 `style=""` 的技术写法参考。用哪些、用几个，以品类 reference 审美为准——不堆装饰填版面，也不输出纯 markdown 光板稿。

- **局部高亮**：关键术语/数字一个底色 + 变色，一屏一两处
- **加粗 / 变色加粗**：分量最重的一两句，深色或品牌色加粗
- **单句成段大字**：一句狠话独立成段、居中放大，靠留白做重音
- **引用块**：金句/原话，左边框或浅底色抬起来
- **数据卡片**：`inline-block` + 定宽做并排多卡（父容器 `font-size:0` 消间隙，不用 flex）
- **对比表格**：每个 `td`/`th` 单独写行内 style
- **横向滑动**：外层 `overflow-x:scroll` + 超宽容器 + 每卡 `float:left`

### 0.3 强制不要（全局审美底线）

- **为装饰而装饰**：与内容无关的彩色分割线、角标徽章、纯凑数的小图标——拿掉不影响阅读的，就是废件。
- **同质化套模板**：标题每章都套同一款、配色每篇都用同一个蓝、排版每次都一个数字一行字。看着均匀整齐的，恰恰是最重的 AI 味。
- **强调泛滥**：同一屏多种强调色混用；给普通陈述句、术语、数据无差别加底色高亮。高亮是重音，不是背景色。（注意：这条防的是"乱强调"，不是"不强调"——正文通篇零强调是废稿，见 §1.5。）
- **卡片 / 边框堆砌**：把一段本可以好好说的话硬塞进卡片、边框、底色块，靠"框"假装精致——文字本身立得住时，什么框都不要加。
- **无意义 AI 插图**：文生图生的氛围图拿掉后上下文毫无影响，纯粹占位——宁可不放图也不放废图。

### 0.4 章节标题 / 序号：三个原则 + 六款灵感

**别让标题退化成纯黑加粗大字——但也别死套某一款模板。** 核心三原则：

1. **序号要有一个视觉载体**——从文字流里跳出来。载体可以是实心色块、描边方框、圆/菱形、两侧短横线、竖色条、超大裸数字……形式不限，能让序号"被托住"就行。
2. **序号与标题之间要有层级差**——尺寸差、粗细差、颜色差，三者占一即可。
3. **一篇文章只能用一种标题样式，全篇统一。** 不同章节之间换样式、混搭多款是明确禁止的。

品类倾向：人物/文化/情感偏文艺居中；科技/财经/干货偏硬朗大数字；资讯/活动偏清爽紧凑。鼓励基于示例改参数、创造新款——但同一篇内只用一款。

**A · 色块数字徽章**（左对齐，最通用；资讯 / 活动首选）
```html
<p style="margin:46px 0 0;"><span style="display:inline-block;background:#0a84ff;color:#fff;font-size:19px;font-weight:bold;padding:3px 15px;border-radius:8px;">1</span></p>
<p style="font-size:20px;font-weight:bold;color:#0a84ff;margin:14px 0 22px;border-bottom:3px solid #0a84ff;padding-bottom:9px;">章节标题</p>
```

**B · 大数字压顶 + 居中标题**（科技 / 干货 / 盘点首选）
```html
<p style="text-align:center;font-size:52px;font-weight:900;color:#1a1a1a;letter-spacing:3px;line-height:1;margin:50px 0 0;">01</p>
<p style="text-align:center;font-size:21px;font-weight:bold;color:#333;margin:10px 0 26px;">章节标题</p>
```

**C · 双线夹数字 + 居中标题**（人物 / 文化 / 生活首选）
```html
<p style="text-align:center;font-size:24px;font-weight:bold;color:#1a1a1a;letter-spacing:2px;margin:50px 0 0;">—&nbsp;&nbsp;01&nbsp;&nbsp;—</p>
<p style="text-align:center;font-size:19px;font-weight:bold;color:#333;margin:8px 0 26px;">章节标题</p>
```

**D · 几何框数字 + 撞色偏移块**（科技 / 潮酷）
```html
<p style="text-align:center;margin:50px 0 0;"><span style="display:inline-block;border:2px solid #1a1a1a;color:#1a1a1a;font-size:19px;font-weight:bold;width:42px;height:42px;line-height:42px;box-shadow:6px 6px 0 #0a84ff;">1</span></p>
<p style="text-align:center;font-size:19px;font-weight:bold;color:#0a84ff;margin:18px 0 26px;">章节标题</p>
```

**E · 双色竖块夹标题**（居中；财经 / 观点 / 重头小标题）
```html
<p style="text-align:center;font-size:19px;font-weight:bold;color:#1a1a1a;margin:46px 0 22px;line-height:1.4;"><span style="display:inline-block;width:5px;height:19px;background:#8b4a2b;vertical-align:-2px;margin-right:12px;"></span>章节标题<span style="display:inline-block;width:5px;height:19px;background:#8b4a2b;vertical-align:-2px;margin-left:12px;"></span></p>
```

**F · 反白色块标签**（活动 / 资讯 / 模块分区）
```html
<p style="display:inline-block;background:#f5c518;color:#fff;font-size:16px;font-weight:bold;padding:8px 20px;border-radius:4px;margin:46px 0 20px;">章节标题</p>
```

### 1.2 先定位「谁在说话」

**动笔前先回答一个问题：这篇文章，是谁在说话。** 没有主体人格的文章，写得再对也只是一份合格的信息汇总，成不了爆款。

**一、个人号 —— 作者始终在场，只分真诚还是表演**

个人号的核心竞争力是**作者这个人本身**，所以作者必须在场：第一人称、亲身经历、真实态度都该有。**作者一隐身、把稿子写成纯客观陈述，立刻掉进通稿和营销稿的冷面孔里**——这是个人号最大的坑，比「我我我」更致命。

真正要控制的不是「作者出不出场」，而是「出场时真诚还是表演」。看两个开头就懂区别：

- ✅ **在场且真诚**：「昨天看到一篇论文，特别有意思，让我连夜读完了。」——第一人称、带情绪，但不夸张、不逼问。
- ❌ **在场且表演**：「我删掉了写了两天的稿子！你敢信？」——全是作者的激动，事实还没出场。

动笔前先拨两个档：

- **人设锚点**：犀利、老练、温柔、理性冷静……选一种贯穿全篇，不要每篇换脸。
- **情绪强度（默认低强度着色，不表态）**：真人最常用的是轻轻带一句情绪色彩——「挺有意思」「有点反常」「有点意外」，而不是「太棒了」「太炸裂了」「颠覆行业」那种夸张表态。有情绪、有态度，只是不喊、不 hedging。
- **共鸣优先于正确**，允许态度和一点不完美的真实。
- 参考标准：卡兹克、半佛仙人、刘润、卢克文。他们的共同点是**第一人称在场 + 真诚不表演 + 局部锋利**——不是靠作者隐身，也不是靠「你想想、你算算」硬撑。

**二、官号 —— 要匹配品牌的调性**

官号的人格是**品牌调性**，不是某个人：

- 新闻资讯类：权威、克制、事实与判断分离，个人色彩要收。
- 学院 / 机构类：专业、有厚度、可信赖，可以有观点但要稳。
- 产品 / 消费品牌类：贴合品牌性格（年轻潮酷 / 高级克制 / 亲切接地气）。
- 政务类：严谨、规范、有分寸。

**怎么落地**：先判定官号还是个人号、锁定人格锚点，再进入品类方法论。**如果一篇稿子谁来写都一样，那就是还没写到位。**

### 1.3 去AI味（默认执行）

**AI味的本质：每句话都正确、完整、圆滑、有逻辑缝合。** 真人会跳跃、省略、句子有长有短。每段都"总分总"、每句都主谓宾齐全、每两句之间都有过渡词——那就是AI。

去AI味靠的是**把事实讲透、把废话删掉**，而不是把作者藏起来写成冷稿。作者的第一人称该在场，只是别堆成"我我我"的表演。以下默认执行（官号/政务号按品牌调性可放宽）：

**① 长短交错，一个意思就断段**：禁止连续5句以上都是20-30字的中等句。穿插极短句做停顿、拉长句做信息（长句内部也用逗号切出节奏）。**排版上默认一到两句一段，想到一句发一句，严禁三四句焊成一大坨**——大段密排是最典型的 AI 稿长相。

**② 禁止完美过渡**：杀掉"与此同时""不仅如此""值得注意的是""在了解了X之后，让我们来看看Y"这类缝合语。段落之间直接跳，读者跟得上。

**③ 事实密度优先，人称自然在场**：对冲AI味最有效的办法是信息本身够硬、够具体——精确的数字、机制、来龙去脉。把一件事讲透，比甩十句"你想想""你算算"更像真人。**第一人称该用就用**（"我看到""我一直在想""我想跟你聊聊"），它让作者在场、稿子有人味；要防的是"我觉得我认为"密到每段都有的表演腔，也别用"你想想、你算算"这类逼问句凑人味。人称是自然在场，不是刷存在感。

**④ 允许不完整**：省略主语、半截句、偶尔没有中心句的段落。真人不板正。但这是自然发生的，不是刻意制造的口头禅。

**⑤ 观点少而准、尽量后置**：不hedging（"在一定程度上""或许可以认为"），但也不是段段下判断。先陈述事实，观点压在段末或全篇靠后，一次说到位。反例❌"这个领域前景值得关注"（空）；反例❌ 每段结尾都甩一句狠话逼你往下看（表演）；正例✅ 事实铺够后轻点一句判断，让读者自己已经信了。

### 1.4 图文穿插是硬底线

**没有一条只有文字、没有任何视觉素材的公众号推文是成立的。** 图片、图表、流程图、时间线、GIF，都是承担论据和节奏的素材，不是装饰。

**开篇首图几乎是标配**：人物稿的首图**必须是人物本人的真实照片**，不是概念图垫底。

**素材分级**：

- **A 类 · 承载论据（首选）**：真人/实物照片、数据图表（matplotlib/SVG/ECharts，中文字体设 `Noto Sans CJK SC`）、流程图/时间线/思维导图（内联 SVG 或 mermaid）、对比表格。**只要文中出现"演变/步骤/因果/对比/层级"，就该画一张。**
- **B 类 · 承载情绪（有 A 类之后再考虑）**：氛围插画（AI 生图）、梗图。B 类数量不能超过 A 类。

判断标准：一张图拿掉后上下文若毫无损失，就是废图，直接删。

**真人图硬规则**（人物/事件稿）：

1. 必须联网搜真实公开图（官方发布/主流新闻/人物公开社交）
2. 不允许用 AI 生图假冒人物肖像
3. 图注必须写清来源
4. 未成年子女、遗容/病榻画面一律不用

**结构化图硬规则**：

- 时间跨度 ≥ 3 个节点 → 时间线
- 3 个及以上分支或步骤 → 流程图/树状图
- 概念有层级或包含关系 → 思维导图/框架图
- 多对象多维度对比 → 横评表

**放置节奏**：跟着内容起伏走，别把"每隔 N 字插图"当指标。素材统一落到 `<slug>/assets/`。

### 1.5 重点句子要做强调（硬底线）

**没有一篇正文通篇平铺、零强调是成立的——这和 §1.4「必须有图」同级。** 每篇稿子里真正有分量的句子，必须从平铺的段落里跳出来。这里说的是**正文段落内部的强调**，章节标题和表格表头不算数。

哪些句子必须挑出来强调：能被截图转发的金句、最锋利的观点判断、反直觉结论、承担全篇重量的那句话。一篇稿子里这样的句子不会只有一句，找出来，让它们跳出来。

手段（灵活混用，别只会加粗）：

- **加粗**：`<strong>` 包裹
- **变色加粗**：分量最重的一两句，用强调色加粗（深红、品牌主色）
- **单独成段**：一句狠话独立成短段落，靠留白做重音
- **引用块**：`blockquote` 抬起来
- **大字/短句切割**：几个字一句连续甩出，用节奏本身做强调

实现上都要写行内 `style=""`（见 §0.2）。

**先做到"有"，再谈"别过头"。** 强调是重音不是荧光笔，同一屏别堆三四处、别给普通陈述句无差别上色。但要记住：这条节制针对的是"已经强调够了、别再加"的情况；如果你正文一处强调都没有，那不是克制，是漏了硬底线。

## 2. 模板注入步骤

> ⚠️ 直接执行脚本，**不需要读取或理解脚本、模板 HTML 内容**。

### Step 1: 创建目录

```bash
bash <skill-dir>/scripts/new-article.sh <slug> <work-dir>
```

- `<skill-dir>`：本 skill 所在目录（`.trae/skills/wechat-mp-article`）
- `<slug>`：推文 slug（小写英文/数字/连字符，例：`fake-intelligence-2026`）
- `<work-dir>`：工作目录（**始终用 `/workspace`**）

生成后的推文目录：

```
<work-dir>/<slug>/
├── index.html      ← 公众号推文预览（浏览器直接打开）
└── assets/         ← 所有图片/视频（可选）
```

### Step 2: 准备资源

- 图片/视频复制到 `<work-dir>/<slug>/assets/`
- **正文写成 `<work-dir>/<slug>/body.html`**：公众号正文本质是 HTML，脚本会原样注入模板
- 正文中的图片路径写成 `assets/xxx.jpg`
- **样式一律写行内 `style=""`，不靠 class**（§0）

### Step 3: 注入内容

```bash
bash <skill-dir>/scripts/inject-content.sh <work-dir>/<slug> \
  --title "推文标题" \
  --body-file <work-dir>/<slug>/body.html
```

### Step 4: 交付

- **不启动本地服务器、不截图验证、不打开浏览器**
- 交付物就是 HTML 文件本身

### Step 5: 引导发布到公众号

交付后，主动告知用户三种发布路径，让用户挑一种：

- **路径 A · 一键复制**（默认推荐，人人可用）：让用户在浏览器打开 `index.html`，点预览底部的【一键复制】按钮，粘贴到 mp.weixin.qq.com 后台图文编辑器；封面与正文图片在 `<work-dir>/<slug>/assets/` 目录下，用户自行上传。
- **路径 B · 导出 Word 一键导入**：告知用户可将本文导出为 `.docx`，导入公众号后台一键成文。
- **路径 C · API 直发**（需认证服务号）：用户提供 `AppID` + `AppSecret`，并把当前运行环境出口 IP 加入公众号「基本配置 → IP 白名单」，即可脚本直接建草稿 / 发布。个人订阅号仅支持到草稿一步。
