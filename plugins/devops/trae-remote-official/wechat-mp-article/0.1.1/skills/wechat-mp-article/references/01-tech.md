# 科技数码公众号爆款 · Reference

## 0. 一句话总纲

> **好选题 × 事实讲透 × 作者在场却不表演的克制文风 × 会说话的图 = 科技数码公众号的最大公约数。**

**本品类默认温度：真诚在场，克制不表演。** 科技/数码稿靠信息密度和判断力立住，但作者要在场——对标卡兹克那种「昨天看到个东西，挺有意思，跟你说说」的亲切自述，而不是藏起作者写成客观陈述。基调是「第一人称在场 + 冷静事实打底 + 局部锋利」：先把机制、数字、来龙去脉讲清楚，重判断压在后面，但可以随时轻轻带一句低强度的情绪着色（「挺有意思」「有点反常」）。下面 §3 的钩子等是**可选招式，慎用**，别把短视频式的「制造欲望」当成必答题。

## 0.1 教材级参考账号

这一套方法论是通用打法。如果需要更直观的对照，下列账号在**科技数码类**长期是行业公认的头部标杆，可以作为学习和拆解范本：

- **团队媒体式**：机器之心、量子位、新智元
- **个人博主式**：数字生命卡兹克、硅星人
- **商业思辨式**：虎嗅 APP、极客公园
- **快讯资讯式**：IT 之家


## 1. 选题（Topic Selection）

### 1.1 时间窗口公式

科技类内容的价值随时间指数衰减。所有选题必须踩中以下三个窗口之一：

| 窗口   | 时间          | 内容类型              | 典型风格          |
| ---- | ----------- | ----------------- | ------------- |
| 快讯窗口 | 发布后 0–24 小时 | 首发解读 / 快速评测       | 个人博主式、快讯资讯式   |
| 实测窗口 | 发布后 3–7 天   | 我用了 / 深度实测 / 对比横评 | 个人博主式、团队媒体式   |
| 思辨窗口 | 发布后 14–30 天 | 趋势 / 商业推演 / 行业分析  | 商业思辨式、团队媒体式   |

**判定规则：** 三个窗口都没踩到 → 必须给出独立选题理由（例如反热点、独家采访、稀缺一手数据），否则舍弃。

### 1.2 增量视角公式

`好选题 = 你的专业领域 × 读者普遍兴趣 × 当下时间节点`

只踩热点不够，必须给出别人没有的**增量视角**。四选一，缺一不可：

- **实测型**：我亲自用了，附截图 / 视频 / 数据
- **数据型**：我扒到了官方没披露的 Benchmark / 时间线 / 财报数字
- **观点型**：我下判断，敢用"我觉得""我认为"
- **推演型**：我给出行业 / 商业 / 生态层面的第二层解读

### 1.3 选题黑名单

- 把已发布的中文报道再翻译一遍
- 官方 PR 稿改一个标题就发
- 空喊"重大突破""颠覆行业"没有具体证据
- 没有个人视角的"综合整理"

## 2. 文风（Voice & Tone）

### 2.1 定位一句话

> **"有见识的普通人在认真聊一件打动他的事。"** ——from 卡兹克开源 skill

科技越硬，文风越要"活人感"。这是头部账号最反直觉、也最难被 AI 模仿的地方。

### 2.2 核心原则：文学性 × 数据性的微妙平衡（重要）

人的表达之所以比 AI 高级，是因为它有**很强的文学性、很强的情感性**。

如果一篇稿子通篇都是硬邦邦的数字、专业术语和冷冰冰的判断，读者会立刻产生距离感。这不是"专业"，这是另一种 AI 味。

正确的姿势是——

- 需要**证据、说服力、判断力**的地方，用明确的数据论据；
- 需要**引起共鸣、传达关怀、抒发观点**的地方，用文学化、情绪化、生活化的语言。

这两者不是非 A 即 B，而是一个**动态切换的呼吸节奏**：

| 场景 | 该用什么 | 例子 |
|---|---|---|
| 立论 / 反驳 / 下判断 | 具体数字 + 硬指标 | "MATH-500 从 78.2% 提到 97.3%" |
| 引入 / 铺垫 / 描述场景 | 画面感、细节、氛围 | "凌晨 4 点，办公室只剩显示器蓝光。" |
| 表达观点 / 情绪 | "我觉得""我一开始以为""我发现" | "我一开始以为这是巧合，后来才知道不是。" |
| 关怀 / 共情 / 收束 | 生活语言，允许留白 | "他不是天赋型选手，是苦力型选手。" |

**一段稿子里数据密度不宜超过 40%。**超过这个比例，就要主动切一段人话、切一段场景、切一段观点回来。

**判断方法**：把稿子念出声。如果每一段听起来都像财报、像 Benchmark 表、像行业报告，就说明失衡了。好的科技类稿子，念出来是"讲道理里带着人味"，不是"数字连珠炮"。

### 2.3 三条价值观

1. **永远对世界保持好奇**：不是先问"我会被取代吗"，而是"我能用它玩点什么有意思的"
2. **讲人话，像个活人**：允许使用"我觉得""我认为""说实话"；分享真实经历、踩过的坑
3. **真诚是唯一的捷径**：产品有缺点就直接说；不懂就大方承认；不追违背价值观的流量

### 2.4 节奏规则

- 句子**时长时短**，段落之间跳跃自然
- 信息密集段用**短句切割**（3–8 字一句），情绪段用**长句铺开**
- 一句话可以**自成一段**制造重量感
- 好的节奏像波动，不是匀速

### 2.5 语言硬规则（可直接写进 System Prompt）

```
✅ 允许：
- 用逗号或句号替代冒号
- 用「」替代 ""
- 英文产品名首次出现后保持英文，不翻译（如 Sora、Claude、GPT-4o）
- 直接下判断："我觉得""我认为"

❌ 禁止：
- 冒号（除时间与比分外）
- 破折号
- 感叹号（除非引用原话）
- 人名加书名号或引号
```

### 2.6 AI 味禁区

| 类别     | 关键词                       |
| ------ | ------------------------- |
| 起承转合套话 | 首先、其次、最后、综上所述、值得注意的是、总而言之 |
| 商业黑话   | 赋能、抓手、闭环、颗粒度、心智、势能、生态位    |
| 教科书开头  | "在当今 AI 快速发展的时代……"        |
| 高频踩雷词  | 说白了、意味着什么？、本质上、毫无疑问、众所周知  |
| 数字堆砌   | 一段里塞 4 个以上百分比 / 时间戳 / 万级数 |
| 术语砖墙   | 连续三句话全是专有名词，没有一句生活语言       |

## 3. 内容结构

### 3.1 四段黄金结构

```
① 开头（讲清真问题 / 一个具体切口进入，别写成新闻导语）
     ↓
② 层层剥开（现象→表面解释→深层追问→核心洞察）
     ↓
③ 论据支撑（事实为主，该用数据用数据，场景引语佐证）
     ↓
④ 结尾升维（连回更大的文化 / 哲学 / 历史 / 人性参照物）
```

### 3.2 开头：作者在场，讲清真问题，别做导语也别表演

**好开头让读者知道"这篇要回答什么、往下读能得到什么"，同时让作者自然地在场。** 默认是作者以第一人称把读者带进来，而不是藏起作者甩一段客观信息。

区分四种开头：

- ❌ **导语式**：*"2026 年 7 月 16 日晚 9 点。距 WAIC 开幕不到 24 小时。Kimi 发布 K3。2.8 万亿参数。100 万 token。开源。"* —— 这是简报，信息平铺、没有切口，也没有人。
- ❌ **表演式**：*"我删掉了写了两天的稿子！你敢信？"* —— 全是作者的激动，事实还没出场，读者只看到"我"在夸张。
- ✅ **亲切自述式（默认首选）**：*"昨天看到一篇关于 Kimi 的分析，特别有意思，让我连夜把它的技术报告翻完了。我想跟你聊聊这家公司现在到底在赌什么。"* —— 第一人称在场、带一句低强度情绪（"特别有意思"），自然引出全篇要讲的事。这是卡兹克式开法。
- ✅ **冷切口式（可选，适合硬核推演稿）**：*"K3 最反常的地方，不是 2.8 万亿参数，是它一边开源、一边把 API 价格抬了四倍。"* —— 一个具体反差带出全篇问题。作者退后，判断藏在事实里；适合纯推演稿，但不是默认，用它时也建议在开头一两句里让作者露个面。

**默认走亲切自述式**：作者以"我最近看到 / 我一直在想 / 我想跟你聊聊"这类自然的第一人称把读者带进来，配一句不夸张的情绪着色。冷切口只在题材特别硬、作者视角确实不必要时才用。

### 3.2.1 开头的两条底线

开头把真问题讲清楚就够了，不必刻意"制造欲望"。两条底线：

1. **别写成新闻导语的碎片**。开头要么给一个具体的切入点（一个事实、一个反差、一个场景），要么直接抛出这篇要回答的真问题，让读者知道往下读能得到什么。
2. **有判断，但不用喊**。全篇要有自己的立场，但不必在前 200 字就急着甩重结论、更不用靠"我不敢信"这类煽情。事实铺够了，判断自然立得住。作者默认在场——用第一人称把读者带进来是常态，别把"我"藏起来写成冷稿。

### 3.3 段落推进

段落靠事实和逻辑往前推，不必每段结尾都刻意留钩子——那是短视频式的表演，堆多了就是"登味"。

- 禁止"接下来我们看……""下面讲一下……"这种明说型缝合语。
- 也不要段段都用"你敢信？""问题来了。"逼读者往下看。真正的钩子是**上一段的事实自然引出下一段的疑问**，读者自己会想知道后面。
- 留白和平淡的过渡是允许的。真人讲事情，本来就有不精彩的衔接。

### 3.4 论据支撑：数据 × 故事 × 引语的三线交织

"该用数字的地方用数字"是原则，"通篇用数字"是灾难。

在一篇 3000 字的科技类稿件里，论据大致应遵循以下配比（科技类默认事实主导）：

| 论据类型 | 建议占比 | 用途 |
|---|---|---|
| 数据 / Benchmark / 机制 / 事实 | 45–55% | 立论的地基；量化对比；把来龙去脉讲透 |
| 场景 / 细节 / 引语 | 20–30% | 建立画面感；替读者代入；佐证判断 |
| 判断 / 观点 | 15–25% | 表明立场，少而准、尽量后置 |
| 白话过渡 | 5–15% | 换气、衔接，允许平淡 |

**数据用法的正反面**：

- ✅ "MATH-500 从 78.2% 提到 97.3%"——用在"证明 R1 推理能力质变"的立论处。
- ❌ 一段之内把 6 个 Benchmark 数字全甩出来，读者会觉得像 Excel 表格。
- ✅ 数据前给一句轻铺垫点明它意味着什么，再让数字自己说话。
- ❌ 光秃秃丢一句"MATH-500 97.3%"，然后马上下重判断。

**节奏**：一段事实/数字 → 一段解读 → 偶尔一段场景或引语 → 再回到事实。不要连续两段纯数据，也不要靠"我"的情绪来串场。

### 3.5 结尾升维准则

不要停在"这个模型很强"，一定要升一层：

- 技术升到哲学："学习被重新定义"
- 产品升到人性："人类的角色变成了裁判"
- 事件升到时代："这可能是内容平权的分水岭"

如果升不上去，就干脆用一句白话收束；但是升上去了，整个推文的档次会高很多。

**升维的关键**：结尾往往是文学性最重的地方，允许写得慢一点、软一点、留白一点。数字在这里通常不必再出现。

## 4. 排版（Layout）

### 4.1 微信公众号硬规则

| 项目   | 参数                   |
| ---- | -------------------- |
| 正文字号 | 15–16 px             |
| 行距   | 1.7–1.9              |
| 段落长度 | **默认一到两句一段，一个意思就断段**；严禁 4 句以上焊成一坨 |
| 段间距  | 单空行，多留白            |
| 首行缩进 | 不缩进                  |
| 对齐   | 左对齐（禁止两端对齐）          |

**断段是真实感的关键一环。** 真人写公众号是想到一句发一句，不是把一段话写满再换行。宁可段落多、留白多，也不要把三四句逻辑句缝进一个段落——后者一眼就是批量生产的 AI 稿。长句内部也多用逗号切成小节奏，别一句到底。

### 4.2 视觉锚点

科技类长文正文**不用副标题**，改用以下方式做导航：

- **加粗关键词** 承担"章节标题"功能
- **单句成段** 制造重音
- **图 / GIF** 每 800–1200 字插入一张做节奏

### 4.3 三段流水线

```
狠开头 —— 一个故事 / 一个反差 / 一个数字
实中间 —— 3 个论点，每个论点配 1 组证据
稳结尾 —— 一个升维 + 一句白话收束
```

### 4.4 差异化选择

| 风格    | 段落           | 加粗  | 图              |
| ----- | ------------ | --- | -------------- |
| 团队媒体式 | 中等长段 + 分级小标题 | 中密度 | 官方图 + 表格       |
| 个人博主式 | 极碎 + 单句成段    | 高密度 | 截图 + GIF + 表情包 |
| 商业思辨式 | 长段 + 引用块     | 低密度 | 少量氛围图 + 数据图    |
| 快讯资讯式 | 短段 + 参数表     | 中密度 | 官方渲染图          |

选一种，坚持一种。**不要混用**。

## 5. 图文（Image & Media）

### 5.1 三类合法图片

科技类文章的图只能是以下三类之一，其他一律不放：

1. **产品截图 / 官方 PPT 截图** —— 承担"证据"功能
2. **对比图 / 数据图 / Benchmark 表** —— 承担"下判断"功能
3. **GIF / 表情包 / 手绘草图** —— 承担"节奏调剂"功能

### 5.2 图片规则

> **每一张图都要能独立说话。**
>
> 判定方法：把这张图去掉，读者是否还能读懂上下文？如果能，说明这张图无效可以删掉。

- 禁止图库氛围图（除非确有必要且承担明确信息量）
- 禁止 AI 生成"配图性质"的插画
- 每张图配 1–2 行说明文字（既解释图，也承担正文过渡）
- 对比图必须并列放，不能上下切割

### 5.3 GIF 使用频率

- 极碎风格（个人博主式）：每 800–1200 字一个 GIF
- 团队媒体风格：可不用 GIF，改用信息图
- 位置：段落之间，用来"松一口气"
