# 专利申请文件撰写模板

## 适用场景
用户提供技术方案（技术交底书、产品描述、技术文档），需要撰写专利申请文件。

## 必要输入信息

| 字段 | 说明 | 是否必须 |
|------|------|---------|
| 技术方案描述 | 发明的具体技术实现 | 必须 |
| 要解决的技术问题 | 现有技术的缺陷 | 必须 |
| 专利类型 | 发明 / 实用新型 / 外观设计 | 可默认推进（默认：发明） |
| 现有技术参考 | 最接近的现有技术文献 | 建议提供 |
| 申请人信息 | 企业名称/个人姓名 | 可后补 |

## 输出结构

### 一、权利要求书

**独立权利要求：**
- 前序部分：与最接近现有技术共有的必要技术特征
- 特征部分（"其特征在于"之后）：区别技术特征

**从属权利要求：**
- 引用关系清晰（引用在前的权利要求）
- 附加技术特征层层递进
- 建议至少 5-10 项从属权利要求形成保护梯度

### 二、说明书

按以下顺序组织：
1. 技术领域
2. 背景技术（现有技术缺陷，不得贬低具体产品）
3. 发明内容（技术问题 + 技术方案 + 有益效果）
4. 附图说明（如有附图）
5. 具体实施方式（至少一个完整实施例）

### 三、摘要

- 说明书摘要：不超过 300 字，概括技术方案要点
- 摘要附图：选取最能说明技术方案的一幅

## 撰写规范

- 权利要求用语：使用"包括""设置于""连接"等专利惯用表达
- 避免功能性限定（除非无法用结构描述）
- 数值范围使用"X-Y"格式，优选值单独写从属权利要求
- 方法权利要求使用步骤编号"S1、S2..."
- 产品权利要求和方法权利要求分别撰写独权

## 检索支撑

撰写前应检索：
- `get_article`：专利法第26条（说明书充分公开）、第64条（保护范围解释）
- `get_article`：专利法实施细则第17-23条（申请文件形式要求）
- `search_article`：相关技术领域审查标准（如适用）
