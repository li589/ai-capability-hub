# 经营分析

面向运营分析师、业务分析师、策略分析师及需要定期复盘业务的负责人，从原始经营数据出发，完成从数据理解到可交付汇报的全链路分析。

## 目标用户画像

- 运营分析师、业务分析师、策略分析师
- 需要定期复盘业务的运营负责人、业务负责人
- 需要定期解释业务表现并支持经营决策的人

## 能力项与子场景

| 能力 | 说明 | Reference |
|---|---|---|
| 同比与环比分析 | 时间序列趋势、拐点识别、YoY/MoM/MTD/YTD | [trend-analysis.md](references/trend-analysis.md) |
| 业务结构拆解 + 目标完成度 | 占比分解、贡献归因、达成率、缺口量化 | [structure-analysis.md](references/structure-analysis.md) |
| 关键问题识别 | 异常检测、风险分级、问题归因 | [anomaly-identification.md](references/anomaly-identification.md) |
| 经营汇报 + 复盘 + 行动建议 | 多视角合成、四层 insight、格式交付 | [report-synthesis.md](references/report-synthesis.md) |

## 标准工作流

```
1. 数据理解
   └─ 确认时间粒度、核心指标、可拆维度、是否有目标/预算数据

2. 趋势分析 → trend-analysis.md
   └─ 产出：各指标趋势方向 + 拐点 + 同比/环比变化幅度

3. 结构拆解 → structure-analysis.md
   └─ 产出：维度占比 + 贡献排名 + 目标达成率 + 集中度风险

4. 异常识别 → anomaly-identification.md
   └─ 产出：分级问题清单（CRITICAL/WARN/INFO）+ 归因假设

5. 合成报告 → report-synthesis.md
   └─ 产出：经营汇报文档（Executive Summary → 详细分析 → 行动建议）

6. 交付渲染（当需要 HTML 产物时）
   └─ 调用 html-report skill，将步骤 5 的结构化内容作为输入
```

每步产出喂入下一步；步骤 2-4 可并行执行后在步骤 5 合成。

## HTML 交付规则

当用户要求生成可视化报告、HTML 报告、经营看板等需要渲染为 HTML 的交付物时，**必须调用 `html-report` skill** 完成最终渲染，不要自行编写 HTML。本 skill 负责分析内容的生产，`html-report` 负责格式与视觉呈现。

### 模板选择规则

根据数据特征和用户诉求自动匹配：

| 数据/诉求特征 | 选择模板 | 原因 |
|---|---|---|
| 指标多（≥5个KPI）、有 cohort/漏斗、用户说"看板/dashboard" | **cockpit** | 高信息密度，KPI卡片+多图网格 |
| 叙事性强、需要详细归因推导、用户说"报告/复盘/汇报" | **editorial** | 长文叙事+图表穿插，层次递进 |
| 数据维度多但单个指标为主、简洁风格 | **folio** | 传统单栏，中等信息密度 |

### 主题选择规则

根据行业/场景自动匹配明亮色系主题：

| 行业/场景 | 选择主题 | 色彩特点 |
|---|---|---|
| SaaS/互联网/科技产品 | **ocean-depths** | 深海蓝绿 `#2D8B8B` + 淡绿底，专业清爽 |
| 消费品/电商/零售/美妆 | **botanical-garden** | 森林绿 `#4A7C59` + 暖白底，自然清新 |
| 金融/咨询/B2B/企业服务 | **modern-minimalist** | 灰阶 + 黑白线条，克制专业 |
| 文化/教育/生活方式 | **golden-hour** | 琥珀金 `#D4910A` + 暖白底，温暖典雅 |
| 通用/无明确行业 | **soft-morandi** | 灰绿 `#7C9A92` + 奶油底，低饱和优雅 |

### 调用 html-report 时的传参要求

在 `plan.md` 中必须显式声明选择的模板和主题，示例：

```
## Theme
- **Name**: ocean-depths
- **Template**: cockpit
- **选择依据**: SaaS 业务数据，5+ KPI 指标，含 cohort 热力图和漏斗，适合高密度看板展示
```

### 图表类型映射

经营分析常见数据结构到 ECharts 图表的映射：

| 数据结构 | 推荐图表 | ECharts 类型 |
|---|---|---|
| 时间序列趋势（MoM/YoY） | 多轴折线图 | line + multi yAxis |
| 维度占比/结构 | 环形图或堆叠柱图 | pie (donut) / bar (stack) |
| 目标达成率 | 仪表盘 | gauge |
| Cohort 留存矩阵 | 热力图 | heatmap |
| 漏斗转化 | 漏斗图 | funnel |
| 增量归因（瀑布） | 瀑布图 | bar (waterfall pattern) |
| 多维对比 | 雷达图 | radar |
| 投入产出（ROI） | 气泡散点图 | scatter (bubble) |
| 渠道/品类月度趋势 | 堆叠面积图 | line (areaStyle + stack) |

## 分析置信度框架

所有结论必须标注置信度：

| 置信度 | 条件 | 标注方式 |
|---|---|---|
| **高** | 多视角交叉印证 + 数据充分 | 直接陈述 |
| **中** | 单一视角 + 数据充分，或多视角 + 数据有限 | 标注"[中置信度]" |
| **低** | 单一视角 + 数据不足 | 标注"[待验证]" |

## 约束

- 不编造数据，无法判断的标注"待确认"
- 可视化优先：能用图表说清楚的不堆文字
- 每个分析环节给出"建议下一步"，不只罗列发现
- 明确区分"数据事实"与"分析推断"
- 所有百分比变化同时给出绝对值，避免误导
- 时间口径必须显式声明（MTD/YTD/全年/自定义区间）
