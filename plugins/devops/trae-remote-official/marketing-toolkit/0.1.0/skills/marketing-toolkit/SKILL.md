# 营销活动策划

> **[!IMPORTANT] 产出格式规则 — 按产出体量分流，重交付物渲染，轻量文本直接给。**
>
> 本技能只负责营销内容的**策划与准备**（策略、文案、框架、数据），**不负责排版渲染**。当任务产生最终交付物时，先判断产出体量，再决定是否渲染：
>
> 0. **轻量产出豁免（先判断这一条）**：当产出是**一屏对话内可读完的轻量文本**——如单条或少量 slogan、标题、文案片段、评论/私信回复话术、UTM 链接、一段话诊断或建议——**直接在对话中输出，不调用任何渲染 skill**，避免小需求被过度包装。判断口径：用户没有要"报告/方案/文档/复盘"这类结构化交付物，且内容不需要排版结构，就直接给。
>
> 当产出是**需要排版结构的结构化交付物**（活动方案、投放复盘、月报、竞品分析、落地页全文、内容日历、长文案集等）时，执行以下规则：
>
> 1. **默认格式为 HTML**：必须调用 `html-report` skill 生成 HTML 报告。不要手写 HTML、不要在对话中直接输出纯 Markdown 作为最终交付物。
>    - **卡片样式规则**：卡片有圆角时不用左侧色条强调（border-left），圆角和左色条组合视觉不协调。无圆角时可以使用左色条。调用 `html-report` 时需将此规则传递给渲染环节。
>    - **视觉风格规则**：单篇报告强调色不超过 3 种（品牌色 + 2 种语义色），组件类型不超过 5 种。保持营销氛围但不堆砌——必要的视觉装饰让报告有质感，但不同组件要承载不同信息层级，读者扫一眼能抓住视觉重点，不是眼花缭乱。
> 2. **用户自然语言指定其他格式时遵从用户**：用户明确要求 PDF → 调用 `pdf` skill；要求 DOCX → 调用 `docx` skill；要求 PPTX → 调用 `pptx` skill；要求飞书文档 → 调用飞书相关 skill。用户未指定格式时，一律走 `html-report`。
> 3. **本技能的 reference 文件仅供内容准备阶段使用**，不作为最终产物输出。
> 4. **视觉素材生图规则**：当任务涉及社媒配图、落地页 hero 图、广告素材图、封面图等视觉资产时，调用 `GenerateImage` 生成图片。生图后对照 `brand-guardrails.md` 校验尺寸与配色。根据交付物类型分两种情况：
>    - **有报告交付物时**（HTML / PDF / DOCX 等）：先调用 `GenerateImage` 生成图片并保存到项目文件夹，再将图片插入报告对应位置，最终在产物中直接展示图片（非占位符）。同时在对话回复中用 `computer://` 链接单独返回每张图片，方便用户独立取用。
>    - **无报告交付物时**（用户只要求出图）：调用 `GenerateImage` 生成图片并保存到项目文件夹，在对话中用 `computer://` 链接返回给用户，无需额外包装为报告。

本技能提供营销全链路知识库，按需加载对应 reference 文件获取详细框架、模板和最佳实践。

## UTM 追踪链接

多渠道投放时直接在对话中生成 UTM 追踪链接，无需外部脚本。三个必填参数：

| 参数 | 含义 | 示例 |
|------|------|------|
| `utm_source` | 流量来源 | email / google / xiaohongshu |
| `utm_medium` | 媒介类型 | newsletter / cpc / social |
| `utm_campaign` | 活动名称 | 618_promo / spring_launch |

可选项：`utm_content`（区分素材，如 hero_img vs button_v1）、`utm_term`（付费关键词）。

命名规则：全小写、用下划线、不含空格。

## 产出视觉规范

**反模式（禁止出现）**：
- **文字墙**：连续 5 段以上纯文字无视觉打断（表格/卡片/图表/分隔线）
- **表格墙**：连续 3 个以上表格无文字或组件间隔

**配色语义**（全篇一致，同一颜色在不同位置含义相同）：
- 绿色 = 推荐 / 正面 / 达标
- 黄色 = 警告 / 待关注
- 红色 = 危险 / 负面 / 不达标
- 品牌色 / 中性色 = 强调

## 执行原则

- **先对齐目标**：开工前确认 SMART 目标，不盲目产出
- **受众深挖**：追问行为特征和痛点场景，不停留在人口标签
- **渠道差异化**：同一卖点在不同平台需要不同表达方式
- **合规底线**：规避广告法极限词（"最/第一/国家级"），邮件营销遵守 GDPR / 个人信息保护法
- **数据归因**：多渠道投放时用 UTM 参数隔离效果
- **品牌优先**：不为短期流量牺牲品牌一致性，内容产出后对照 voice-and-compliance.md 校验

## 写作纪律

产出营销内容时遵守以下语言规范：

**禁用空洞词**：不写"赋能/闭环/抓手/打通/心智"等空话，替换为具体表述（"赋能" → "让用户自己就能完成 X"）。

**禁用空泛最高级**：不写"world-class / cutting-edge / revolutionary / 领先 / 最佳"除非有具体数据支撑。

**禁用元叙事**：不写"下面我们来看…"/"接下来将详细分析…"，直接给结论。

**禁用标题复述**：段落第一句不复述标题，直接给事实、数据或判断。

**标题要有网感**：报告大标题保持专业性，清晰说明报告主题和范围。每个章节标题不只是说明章节内容，还要顺带点出结论或判断，用营销人熟悉的场景词增加吸引力，让读者扫一眼标题就能抓住核心观点。例：章节标题"首屏 3 秒定生死：标题收益导向，点击率翻倍"而非"首屏优化建议"。

**正文重点高亮**：正文段落中的关键数据和核心判断用**加粗 + 品牌色**标注，让读者扫读时一眼抓住重点。每段高亮不超过 2 处，避免满篇加粗等于没加粗。

**调研结论表达**：引用外部方法论或权威数据时，标注来源让用户可溯源，同时用营销人的语言把数据翻译成判断和经验，不照搬原文堆砌数字。例："据巨量引擎权威信息，货品结构上，引流款占四成做流量开口，爆款和利润款各三成分别扛转化和收入，稀缺战略款控制在一成以内造氛围——这是大场直播跑通的基本盘"而非"巨量引擎官方大场方法论建议引流款40%+爆款30%+利润款30%+稀缺战略款<10%"。

**收益先于功能**：先说用户能得到什么结果，再说产品功能怎么实现。"节省 3 小时"先于"自动化报表功能"。

**术语首次解释**：行业术语（ROAS / LTV / CAC / JTBD 等）首次出现时附简短释义，全文只注一次。

**证据标注（仅限内部自检，绝不写入正文）**：每个量化声明在自检时判定其来源类型——数据支撑 / 行业基准 / 假设 / 待确认。这些标签仅供内部判断该数据是否可用，**绝对不能出现在产出正文中**。正文中数据应自然引用来源（如"据艾瑞咨询 2025 年报告"），假设性数据用"预计""预估"等措辞体现。禁止编造社会认同、指标、案例结果。

## 产出质检清单

每份产出交付前逐项检查，不通过则修正后再交付：

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1 | 开篇开门见山 | 报告开头用可视化方式（卡片/图表/组件等）呈现核心结论，杜绝大段文字堆砌——开篇不能是连续段落，必须是可扫读的视觉组件。如涉及多个营销模块，可选用简明示意展示模块关系——层级要粗、关系要简单，不画复杂流程图 |
| 2 | 每个数字有出处 | 可追溯到数据源或标注为假设；无裸数字 |
| 3 | 无空洞表述 | 无"赋能/闭环/抓手"等空话；最高级有数据支撑 |
| 4 | 渠道差异化 | 同一卖点在不同平台有不同表达，未一键分发 |
| 5 | 品牌一致性 | 语气、用词、视觉描述符合 voice-and-compliance.md 规范 |
| 6 | 合规无红线 | 无广告法极限词；邮件含退订链接；隐私合规 |
| 7 | 收尾有行动 | 最后一段是"下一步行动"而非总结复述 |
| 8 | 无内部标签泄漏 | 产出中不出现 reference 文件名、技能内部术语、证据标注标签 |
| 9 | 方案含成本估算 | 仅对活动/上线类结构化方案生效（轻量产出豁免）：凡涉及预算投入的活动方案必须有预算分项 + ROI 测算，覆盖显性与隐性成本；缺失则补齐再交付 |
