# 营销模板库

以下模板以**结构指引表**形式呈现，描述每个组成部分的目标和写法要点，而非固定词句填空。使用时根据实际产品和受众灵活调整。

## 客户访谈 / 案例研究

适用场景: 采访客户撰写成功故事 / 案例研究时使用，确保信息收集完整。
使用要点: 按现状→选择→落地→成效四阶段推进；成效部分必须量化；最后确认授权范围。

| 访谈阶段 | 目标 | 关键问题 |
|---------|------|---------|
| 现状 | 还原使用前的真实工作场景 | 那时候这个流程是怎么跑的？最头疼的是哪个环节？试过哪些替代方案，为什么不满意？ |
| 选择 | 还原决策过程 | 最初是怎么知道我们的？评估了哪些选项？最后打动你的那一点是什么？ |
| 落地 | 了解实施过程和支持需求 | 上线花了多长时间？中间卡在哪里了？我们这边谁帮了你最多？ |
| 成效 | 拿到可量化的对比数据 | 如果用之前和之后的数字对比，变化最大的是什么？多久感受到这个变化的？ |
| 证言 | 获取一句话推荐 | 如果要向同行推荐我们，你会怎么说？ |
| 授权确认 | 确认使用范围 | 这个案例可以对外公开吗？公司名和 Logo 可以用吗？引述需要你审核吗？ |

## 表单最佳实践

适用场景: 落地页 / 官网线索收集表单的字段设计参考。
使用要点: 表单每多一个字段，转化率就掉一截——这不是直觉，是被反复验证的规律。根据线索获取阶段选择表单长度。渐进式收集（Progressive Profiling）是折中方案：首次只收邮箱，后续逐步补充。

### 按场景选择表单长度

表单长度本质是"你要求用户付出多少信息"和"你给用户多少价值"之间的交换。价值越高（如白皮书下载），用户愿意填的字段越多。

| 表单场景 | 适用时机 | 收集字段 | 转化率参考 |
|---------|---------|---------|-----------|
| 短表单 | 首次触达 / 内容下载 / 订阅 | 邮箱（必填）+ 昵称（选填） | 高（15-25%） |
| 中等表单 | Demo 申请 / 试用注册 | 邮箱 + 公司名 + 职位 + 需求场景（下拉） | 中（5-10%） |
| 长表单 | 企业咨询 / 定制方案 | 邮箱 + 手机 + 公司名 + 职位 + 团队规模 + 预算区间 + 决策时间线 | 低（1-3%） |

### 表单设计规则

- 必填项用红色 `*` 标注，让用户一眼知道哪些不能跳过
- 电话号码只在必须时才问——每多一个字段转化率下降约 5-7%
- 选项题用下拉菜单或单选按钮，不要让用户自由输入——自由文本无法用于分群
- 利用条件逻辑：根据前一个回答决定是否显示后续问题（如选"个人用户"则不显示"公司规模"）
- 首次接触只收最少信息，后续通过邮件跟进逐步补全画像（渐进式收集）
- 每个字段都要有 label 标签——placeholder 在输入时会消失，不能替代 label
- 提交按钮要够大够醒目：字号 ≥ 18px，点击区域 ≥ 44×44px（移动端触控标准）
- 超过 5 个字段的表单显示进度条（"第 1 步，共 3 步"），让用户有完成预期

### 提交后处理

- 提交后立即展示感谢页，同时告知"接下来会发生什么"（如"24 小时内会有顾问联系你"）
- 自动触发确认邮件，交付承诺的引流诱饵（白皮书 / 模板 / 试用链接）
- 如果承诺了跟进，务必在承诺时间内联系——响应速度越快转化率越高，5 分钟内首次响应的转化率远超 30 分钟后响应
- 线索信息同步到 CRM，触发分群规则和培育序列——手动录入会丢失最佳跟进窗口

## 落地页结构

**产品功能落地页**

适用场景: 付费广告或邮件 CTA 指向的转化页面，目标是驱动注册 / 试用 / 咨询。
使用要点: 落地页不是组件的上下堆叠，而是访客在页面里经历的一场"心理闯关"——从"要不要停下来"到"值不值得试"再到"要不要现在就动手"。把板块按访客当下要回答的问题归入三个闯关阶段来搭建，比逐块套模板更能保证动线不断裂。每个板块有且只有一个目标，删掉任何一个不服务转化的板块。

**第一关·让访客停下来（首屏 3 秒定生死）**

访客滑进页面的头 3 秒只问一件事——"这跟我有没有关系"。答不上来，后面写得再好也白搭。

| 板块 | 访客心理 | 写法要点 | 失败信号 |
|---------|------|---------|---------|
| Hero 首屏 | "这是什么？跟我有关系吗？" | 标题写收益而非产品名；配产品截图 / 视频；CTA 按钮明确 | 标题只有产品名没有收益 |

**第二关·让访客信服（中段建立"值得试"的确信）**

停下来之后，访客会依次冒出四个疑问：是不是说我、难不难用、别人用得好不好、我还有什么不放心。中段的四个板块就是逐个拆掉这些顾虑，顺序不能乱——先共鸣痛点，才谈得上后面的信任。

| 板块 | 访客心理 | 写法要点 | 失败信号 |
|---------|------|---------|---------|
| 问题放大区 | "这说的就是我" | 用数据放大痛点；3-5 个收益分点 + 产品使用场景图 | 只列功能不翻译成收益 |
| 上手演示区 | "难不难用？" | 3 步流程图：每步一个动作 + 一个结果 | 步骤超过 5 步显得复杂 |
| 信任背书区 | "别人用了吗？靠谱吗？" | 5-8 个客户 Logo 或 2-3 条真实证言 + 量化结果 | 证言没有具体数字 |
| 异议处理区 | "还有什么顾虑？" | 3 个最常见疑虑：和现有方案比强在哪 / 多久能看到效果 / 不合适能不能退 | FAQ 回答模糊 |

**第三关·让访客现在就动手（收口 + 合规兜底）**

信任建立之后，最后一步是把"以后再说"逼成"现在就点"，同时用合规底栏兜住法律底线。

| 板块 | 访客心理 | 写法要点 | 失败信号 |
|---------|------|---------|---------|
| CTA 收尾 | "该不该现在行动？" | 主按钮（动词+收益）+ 次要 CTA（"先看看案例"）+ 风险逆转（"不满意全额退"） | 只有一个 CTA 且门槛过高 |
| 信息底栏 | "合规 + 导航" | 退订链接、公司信息、隐私政策 | 缺少物理地址（CAN-SPAM / 个保法合规） |

## 付费广告结构

适用场景: 搜索广告 / 社交信息流广告 付费广告的文案结构参考。
使用要点: 每个平台字数限制不同，使用时需查阅最新广告政策；建议每活动准备 3-5 组素材变体做 A/B 测试。

### 抖音 / 小红书 信息流广告

| 组成部分 | 写法要点 |
|---------|---------|
| 前 3 秒 | 痛点放大或反转，决定完播率 |
| 正文 15-30 秒 | 单一卖点讲透，信息密度高 |
| 结尾 CTA | 软性引导，不要太硬 |
| 文案风格 | 口语化、接地气、有网感，不用官方腔 |

### 搜索类广告

搜索广告的逻辑：用户主动表达了意图，你的文案要接住这个意图并给出行动理由。

| 层级 | 字数限制 | 目标 | 写法要点 |
|------|---------|------|---------|
| 意图匹配层 | 标题 ≤ 30 字符 × 2-3 条 | 让用户确认"这就是我要找的" | 标题含搜索关键词 + 核心收益承诺 |
| 差异化层 | 描述 ≤ 90 字符 × 1-2 条 | 让用户觉得"这个比别的更值得点" | 独特卖点 + 社会认同（客户数 / 评分 / 案例） |
| 行动层 | 描述续写或附加信息 | 给用户一个"现在就点"的理由 | 限时优惠 / 免费试用 / 无需信用卡 |

### 社交信息流广告

信息流广告和用户的内容流混在一起，被划过的概率远大于被点击的概率。每个组成部分的任务就是降低跳过率。

| 组成部分 | 它的任务 | 写法要点 |
|---------|---------|---------|
| 标题 | 让拇指停下来 | 收益前置或制造信息缺口——"90% 的人不知道"比"产品介绍"更能让拇指暂停 |
| 描述 | 让眼睛看下去 | 用"痛点→转折→结果"三段式，不超过两行，第二行给数字 |
| 配图 | 让大脑相信 | 真实截图优于设计图，有人脸的图点击率比纯产品图高 30%+ |
| CTA | 让手指点下去 | 动词+收益组合——"免费试用 14 天"优于"了解更多" |

**朋友圈 / 公众号广告**

| 组成部分 | 写法要点 |
|---------|---------|
| 开头 Hook | 像朋友说话，不像广告 |
| 痛点 + 方案 | 场景化描述 + 一句话价值 |
| CTA | 低门槛引导 |
| 配图风格 | 生活化、不像硬广 |

### 月度主题轮换

三周一个循环，按"给价值 → 给方案 → 给信任"递进，确保受众不会连看三周广告而疲劳。

## 邮件模板

按"培育 / 拉新 / 召回"三类组织，覆盖用户生命周期各阶段。

### 培育类

**模板: 线索培育邮件**

适用场景: Nurture 序列中的一封，用数据驱动方式教育线索，推动向购买靠近。
使用要点: 开篇抛出常见错误制造紧迫感；用数据增加可信度；3 步行动指南可直接执行。

| 组件 | 写法要点 |
|---------|---------|
| 主题行 | "XX 类团队如何实现 XX"——收益导向 + 受众点名 |
| 开场 | 用"最大的误区是"制造紧迫，抛出常见错误 |
| 数据支撑 | "我们分析了 N+ 账号发现"——增强可信度 |
| 行动步骤 | 3 步可执行指南，每步：做什么 + 为什么有效 |
| 预期结果 | 给出时间框架和具体改善幅度 |
| CTA | 白皮书 / 基准报告 / 完整指南 |

### 拉新类

**模板: 产品上线公告邮件**

适用场景: 新产品 / 新功能正式发布，向已有用户列表发送公告。
使用要点: 标题制造期待感；正文先说收益再说功能；附 demo 链接降低了解门槛；P.S. 制造稀缺性。

| 组件 | 写法要点 |
|---------|---------|
| 主题行 | 50字符内；用"终于来了" / "全新上线"制造期待 + 点出核心收益 |
| 发件人 | 用人名而非公司名；团队负责人最佳 |
| 开场 | 2 句内抓住注意力——先说收益，不说功能 |
| 价值分点 | 每个收益一句话描述；用具体数字；3 个核心收益清晰可扫 |
| 社会认同 | 嵌入真实客户引言 + 姓名 + 公司 |
| CTA | 动词开头 + 具体收益；降低门槛 |
| P.S. | 限时福利 / 早鸟名额——制造紧迫感 |

**模板: 产品演示 / 在线研讨会后续跟进邮件**

适用场景: 客户参加产品演示或在线研讨会后 24 小时内发送。
使用要点: 个性化提及对方在活动中说过的话；附上资源链接；给出 2 个具体时间段邀约通话。

| 组件 | 写法要点 |
|---------|---------|
| 主题行 | 用"刚才提到的" / "您要的资料"——提及活动 + 提供价值 |
| 开场 | 回顾活动 + 提及对方在活动中说的具体内容 |
| 资源交付 | 列 2-3 个资源链接 + 简短说明——兑现活动中的承诺 |
| 关联痛点 | 不硬推产品，说"这正是 XX 解决的场景"——将对方痛点与产品价值对接 |
| 邀约 | 给 2 个具体时间段——不用开放式"您什么时候方便" |
| P.S. | 推荐相关资源——附加价值 |

### 召回类

**模板: 召回邮件（Win Back）**

适用场景: 对超过一定时间未活跃的用户发送，尝试重新激活或确认是否清洗。
使用要点: 语气轻松不施压；列出产品新变化勾起兴趣；给退出口降低抵触感。

| 组件 | 写法要点 |
|---------|---------|
| 主题行 | 用"想你" / "好久不见"——轻松 + 情感触发，不用官方腔 |
| 开场 | 不施压，用"注意到你最近没来"——轻松提及沉默事实 |
| 新变化 | 聚焦对方可能关心的功能——列 2-3 个产品更新 |
| 重新体验 | 一键查看新功能，不需重新注册——降低回归门槛 |
| 退出口 | "不合适也可以反馈"——尊重对方选择 |
| P.S. | 让老用户也能享受新用户福利——做吸引 |

## 上线前检查清单

任何营销活动上线前的最终自检。按"素材就绪"和"流程就绪"两组组织，每项以自检问句呈现。

### 素材就绪

**内容与技术**
- [ ] 文案有没有错别字——换一个人交叉校对，自己看容易跳过
- [ ] 所有链接都点过一遍了吗——404 是最低级的错误
- [ ] 图片是否压缩到 200KB 以内——大图拖慢加载速度，移动端尤甚
- [ ] 品牌一致性是否对照过 voice-and-compliance.md——语气、用词、视觉风格
- [ ] CTA 是否是一个具体动作——"免费试用 14 天"而非"了解更多"
- [ ] 所有链接是否都打了 UTM 参数——没打 UTM 的流量无法归因
- [ ] 转化追踪代码在最近一次改版后还生效吗——80% 的追踪失效发生在改版之后
- [ ] 邮件在 Outlook / Gmail / Apple Mail 中渲染是否正常——不同客户端 CSS 差异大
- [ ] 落地页在手机上能否正常使用——移动端流量占比超 60%
- [ ] 表单提交后是否跳转到正确页面——提交失败是最容易被忽略的转化杀手

### 流程就绪

**合规与规划**
- [ ] 隐私政策链接是否可正常访问
- [ ] 邮件退订功能是否实测可用——坏了的退订链接 = 用户点"举报垃圾邮件"
- [ ] 是否满足 CAN-SPAM / 个保法要求——Footer 含物理地址、退订入口、隐私链接
- [ ] 文案中是否有无证据的功能声明——"行业领先"需有数据支撑
- [ ] 是否含广告法极限词——"最 / 第一 / 唯一 / 国家级"在任何对外文案中禁止
- [ ] 预算是否已审批——未经审批的投放不发出
- [ ] 各环节时间节点是否已确认——含缓冲时间
- [ ] 每个任务是否都有明确的负责人——"大家一起做"等于没人做
- [ ] 成功指标是否已定义且有基线——没有基线就无法判断"好还是不好"
- [ ] 相关方是否已收到通知——销售、客服、技术支持需提前知情
