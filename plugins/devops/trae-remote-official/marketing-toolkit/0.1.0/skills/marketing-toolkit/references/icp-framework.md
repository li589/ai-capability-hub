# 理想客户画像框架

所有营销活动的前提是知道在跟谁说话。画像不是人口统计的填空题，而是回答"谁最容易买、为什么买、怎么买到"。

## B2B 与 B2C 的画像差异

两种业务的画像维度完全不同，不要混用。

### B2B 画像

| 维度 | 要回答的问题 |
|------|------------|
| 企业特征 | 行业、规模、融资阶段、地域 |
| 技术栈 | 现在用什么方案、技术成熟度如何 |
| 触发事件 | 什么事发生时他们会开始找你（融资/扩张/换高管/合同到期） |
| 购买角色 | 谁是决策者、谁是使用者、谁是把关者 |
| 资质条件 | 必须满足什么条件才值得跟（必备），满足什么更好（加分），什么情况直接排除（不合格） |

### B2C 画像

| 维度 | 要回答的问题 |
|------|------------|
| 人口属性 | 年龄、性别、收入、地域 |
| 心理特征 | 价值观、身份认同、向往什么、受谁影响 |
| 行为特征 | 在哪获取信息、怎么消费内容、购买决策习惯 |
| 场景触发 | 什么生活事件或情境会触发需求 |

## 痛点结构化

不要只写"效率低"这种废话。每个痛点按以下结构描述：

| 字段 | 说明 | 示例 |
|------|------|------|
| 严重程度 | 1-10 分 | 8 分 |
| 发生频率 | 多久遇到一次 | 每周 |
| 当前替代方案 | 现在怎么凑合的 | 手动用 Excel 拼 |
| 不解决的代价 | 不解决这个问题会怎样 | 每周浪费 3 小时，团队拿不到实时数据 |
| 情绪影响 | 用户的感受 | 烦躁、觉得自己在做无意义的事 |

痛点可按以下自定义框架分 5 类，按优先级排序：功能性痛点（做不到）> 财务痛点（太贵）> 流程痛点（太慢）> 社交痛点（被质疑）> 情绪痛点（焦虑）。

## 信息获取方法

画像不是拍脑袋写的。按以下方法获取，按可信度排序：

| 方法 | 可信度 | 怎么做 |
|------|--------|--------|
| 客户访谈 | 最高 | 问 10-15 人：现有客户 5-7、流失客户 2-3、潜在客户 3-5 |
| 调研问卷 | 高 | 10-15 题，5 分钟填完，通过社媒和邮件分发 |
| 销售对话记录 | 中高 | 从销售/客服的对话记录中提取高频问题和异议 |
| 数据分析 | 中 | 后台数据看谁付费、谁留存、谁流失 |
| 竞品评论 | 中 | 看竞品的用户评论，提取痛点和需求 |
| 行业报告 | 低 | 行业白皮书和报告，做背景参考 |

## 访谈框架

访谈是画像的核心。按以下 4 阶段提问，不要引导用户说你想听的话：

**背景**：你在这个岗位多久了？团队多大？日常工作是什么样的？

**问题**：最近一次遇到 [问题场景] 是什么时候？当时怎么处理的？花了多长时间？事后感受如何？

**方案**：你有没有找过解决方案？看了哪些？为什么没选？如果有一个工具能做到 XX，你会愿意试吗？

**购买**：你们买工具的流程是什么样的？谁拍板？一般预算审批要多久？

**关键原则**：问具体事件，不问观点。"上次遇到这个问题怎么处理的"比"你觉得这个问题重要吗"有效 10 倍。

## Persona Card

把调研结果浓缩成一张卡片，团队任何人看一眼就知道在跟谁说话：

| 字段 | 内容 |
|------|------|
| 角色名 | 画像代号（如"效率主管小王"） |
| 一句话描述 | 30 字以内的身份+诉求 |
| 目标 | 他想达成什么（1 个主目标 + 2 个次目标） |
| 痛点 | 最痛的 2-3 个 |
| 信息渠道 | 他在哪里获取信息 |
| 购买风格 | 比价型 / 冲动型 / 审批型 |
| 文案注意 | 对他说话要怎么说 / 不能怎么说 |
| 核心异议 | 他最可能拒绝你的理由 + 你的回应 |
| 一句原话 | 访谈中听到的最有代表性的一句话 |

## 验证与更新

画像会过时。每季度检查一次：

- 最近 10 个成交客户是否匹配画像？如果不匹配，是画像错了还是市场变了
- 流失客户的原因是否和画像中预判的痛点一致
- 销售团队是否在实际使用这个画像？如果不用，说明画像不够好用

画像不是文档，是工具。没人用的画像等于没有。
